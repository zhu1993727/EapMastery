# W02 · Day05 答案与参考实现

## 一、自测题标准答案
1. **T6 vs T8**：T6 是**单次控制事务**等应答的超时（"我发了 Select/Linktest.req，你在 T6 内必须回"），对应"握手没人理"；T8 是**链路空闲**阈值（SELECTED 下多久没看到任何报文就主动探活），对应"链路悄悄死"。关系：T8 触发发 Linktest，**再由 T6 判定这次探活有没有应答**。
2. **为何等 T5**：防止对端短暂不可用/正在重启时 Active 死循环狂连，打爆 CPU、端口和对端；T5 给网络与对端恢复留出固定间隔，也用于错开双 Active 冲突。
3. **回数据但不回 Linktest.rsp 算活还是死**：数据消息证明物理链路活着（会刷新 lastRxAt），但**本次 Linktest 控制事务仍在 T6 内等它自己的 rsp**；T6 到点没收到 Linktest.rsp，该控制事务判失败。严谨实现：连续一次/按厂规若干次 Linktest 失败才判死链（避免一次抖动误杀），判死后才 Separate+重连。
4. **T3 vs T6**：对象不同——T3 管**数据消息(SxFy)** primary 等 reply（业务事务，较长，~45s）；T6 管**控制消息** Select/Linktest/Deselect 的应答（连接维护，较短，~5s）。两者都靠 SystemBytes 配对，但分属不同事务类型与超时表。
5. **Active 不发 Select，Passive 怎么办**：用 **T7**，TCP 建立后 T7（~10s）内没完成选通，Passive 主动关闭这条 TCP，回收资源，等 Active 重新连。
6. **死链→重新 SELECTED 全步骤**：T8 到点发 Linktest.req（记 T6）→ T6 无 Linktest.rsp（按策略累计失败）→ 判死链，状态机 SELECTED→NOT CONNECTED、关 socket、通知上层不可用、未决数据事务按失败处理 → **等 T5** → TCP Connect（成功进 NOT SELECTED，Passive 侧同时起 T7）→ 发 Select.req（记 T6）→ 收到 Select.rsp status=0 → 进 SELECTED、重启 T8、通知上层可用。

## 二、参考实现

### HsmsTimers.cs（集中配置，典型值，现场以规范为准）
```csharp
public sealed class HsmsTimers
{
    public TimeSpan T3 { get; init; } = TimeSpan.FromSeconds(45); // 数据回复
    public TimeSpan T5 { get; init; } = TimeSpan.FromSeconds(10); // 连接间隔
    public TimeSpan T6 { get; init; } = TimeSpan.FromSeconds(5);  // 控制事务
    public TimeSpan T7 { get; init; } = TimeSpan.FromSeconds(10); // 选通时限
    public TimeSpan T8 { get; init; } = TimeSpan.FromSeconds(10); // 网络空闲
    public TimeSpan Tick { get; init; } = TimeSpan.FromMilliseconds(250);
}
```

### 统一超时扫描器（一个 Tick 管全部，不产生状态，只抛事件）
```csharp
public sealed class TimeoutScanner
{
    private readonly HsmsTimers _t; private readonly PendingTransactions _pend;
    private readonly Func<HsmsCtrlState> _state;
    public DateTime LastRxAt { get; set; } = DateTime.UtcNow;
    public event Action<Pending>? OnControlTimeout;   // T6
    public event Action? OnLinktestDue;               // T8 到点
    public event Action? OnSelectDueExpired;          // T7
    public DateTime? TcpOpenedAt { get; set; }
    private bool _selectedOnce;

    public TimeoutScanner(HsmsTimers t, PendingTransactions p, Func<HsmsCtrlState> state)
    { _t = t; _pend = p; _state = state; }

    public void MarkSelected() { _selectedOnce = true; LastRxAt = DateTime.UtcNow; }

    public void Scan()
    {
        var now = DateTime.UtcNow;
        // T6：扫描超时未应答的控制事务
        foreach (var p in _pend.Expired(_t.T6, now)) OnControlTimeout?.Invoke(p);

        if (_state() == HsmsCtrlState.Selected)
        {   // T8：SELECTED 空闲到点 → 发起 Linktest
            if (now - LastRxAt >= _t.T8) { LastRxAt = now; OnLinktestDue?.Invoke(); }
        }
        else if (_state() == HsmsCtrlState.NotSelected && TcpOpenedAt is { } op)
        {   // T7：连上后迟迟不选通
            if (!_selectedOnce && now - op >= _t.T7) OnSelectDueExpired?.Invoke();
        }
    }
}
```

### Active 重连循环（T5 退避）
```csharp
public async Task RunActiveLoopAsync(string host, int port, CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        try
        {
            await ConnectAndSelectAsync(host, port, ct);   // 内含 Select/T6/T8
        }
        catch (Exception ex) { _log.Log(LogDir.ERR, "链路异常:" + ex.Message); }
        finally { SafeClose(); _sm.OnTcpClosed(); }
        _log.Log(LogDir.EVT, $"等待 T5 {_t.T5.TotalSeconds}s 后重连");
        await Task.Delay(_t.T5, ct);                        // T5 连接分离
    }
}
```

## 三、故障演练判定标准
1. 不回 Select.rsp：T6 到点日志、状态回 NOT CONNECTED、随后 T5 重连。
2. 静默死链：T8 到点发出 Linktest.req；T6 无 rsp 判死并拆除重连。
3. 断线重连：对端关闭后 Active 精确等待 T5（不是立即），重连并重新 Select 到 SELECTED。

## 四、易错点
1. 每个事务开独立 Task.Delay，难取消难统计（应统一 Tick 扫描）。
2. T8 只看"有没有收到 Linktest.rsp"，忽略数据消息也能刷新活动时间。
3. 一次 Linktest 失败就立刻判死（建议按厂规容错，避免抖动误杀）。
4. 重连不等 T5，疯狂重连打爆对端。
5. 用本地时间受系统时钟跳变影响（应统一 UTC）。
