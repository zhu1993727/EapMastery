## 二、背景知识（先读，25 分钟）

### 1. T 参数总表（必背）
| 参数 | 名称 | 管什么 | 触发后动作 | 典型值(以标准/配置为准) |
|---|---|---|---|---|
| T3 | Reply Timeout | 数据消息 primary 等 reply | 判该事务失败，上层重试/报错 | ~45s |
| T5 | Connect Separation | 两次 TCP 连接尝试最小间隔 | Active 必须等待后再重连，防狂连 | ~10s |
| T6 | Control Transaction | Select/Linktest/Deselect 等控制应答 | 判控制事务失败，拆除/重连 | ~5s |
| T7 | Time to Select | TCP 建立后允许完成 Select 的时限 | 超时未选通则关闭连接 | ~10s |
| T8 | Network Inter-message | SELECTED 下相邻报文最大间隔 | 到点发 Linktest，再无应答判死链 | ~5~10s |

### 2. T8 保活循环（重点）
- SELECTED 后维护 lastRxAt；一个周期定时器检查：`now - lastRxAt >= T8` → 发 Linktest.req（登记 T6）；
- 收到**任何**报文都刷新 lastRxAt；
- Linktest.req 后在 T6 内没收到 Linktest.rsp → 判链路失效 → Separate/关闭 → Active 走 T5 重连。

### 3. Active 重连状态循环
```
断链 → Close → 等 T5 → TCP Connect(T7计时) → 发 Select(T6计时)
      → 成功进 SELECTED / 任一失败 → Close → 回到"等 T5"
```
- 重连必须"退避、有节奏"，不能死循环占满 CPU/打爆对端。

### 4. 双 Active 连接冲突（T5 相关）
两端都主动 Connect 会同时出现两条 TCP；HSMS 规定检测到冲突时按规则分离（保留一条、Separate 另一条），靠 T5 错开重连，避免反复撞车。一条链路务必固定一 Active 一 Passive。

### 5. 定时器工程要点
- 用一个统一的周期 Tick（如 250ms）扫描所有计时器，避免为每个事务开 Task.Delay 难管理；
- 时间用 UTC；超时只产生"事件"，由状态机决定动作，计时器本身不改状态。
