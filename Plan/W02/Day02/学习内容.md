## 二、背景知识（先读，20 分钟）

### 1. HSMS 帧总体
```
┌──────────────┬────────────────────────────────────────────┐
│ Length (4B)  │ Message：10B Header + 可选 Message Text/Data │
│ 大端,无符号  │ Length 的值 = 其后全部字节数(含这10B头)        │
└──────────────┴────────────────────────────────────────────┘
```

### 2. 10 字节消息头布局（必背，能手画）
| 字节偏移 | 长度 | 数据消息(SType=0) | 控制消息(SType=1~9) |
|---|---|---|---|
| 0-1 | 2B | Session/Device ID（大端）| Select 时=SessionID；Linktest/Separate=0xFFFF |
| 2 | 1B | **W-bit(bit7) + Stream(bit0-6)** | 固定 0 |
| 3 | 1B | Function | 固定 0 |
| 4 | 1B | PType（表示层类型，SECS-II=0）| 同（=0）|
| 5 | 1B | **SType（会话类型，数据消息=0）**| 1..7、9 |
| 6-9 | 4B | System Bytes（大端，事务号）| req 生成、rsp 原样复制 |

- **W-bit**：仅数据消息用，bit7=1 表示要求回复；Stream 取低 7 位（如 S6=0x06，要求回复则字节2=0x86）。
- **PType**：Presentation Type，SECS-II 编码固定为 0。
- **SType**：区分控制消息类型，数据消息必须为 0。
- **System Bytes**：4 字节事务标识，控制事务 req/rsp 用它配对（和数据消息同一规则）。

### 3. 控制消息 SType 表（必背）
| SType | 消息 | 方向 | 有无 Data |
|---|---|---|---|
| 1 | Select.req | Active→Passive | 无 |
| 2 | Select.rsp | Passive→Active | 1B SelectStatus |
| 3 | Deselect.req | 任一方 | 无 |
| 4 | Deselect.rsp | 对方 | 1B DeselectStatus |
| 5 | Linktest.req | 任一方 | 无 |
| 6 | Linktest.rsp | 对方 | 无 |
| 7 | Reject.req | 对方 | 1B RejectReason |
| 9 | Separate.req | 任一方 | 无（无 rsp，直接拆）|

> SType=8 保留未用；没有 Separate.rsp。

### 4. SelectStatus（Select.rsp 的 1 字节，常见值）
0=接受/通信建立；1=被选方已是 Active；2=Not Ready 未就绪；3=本地资源耗尽；4=备用连接/另一地址；5=SessionID 不识别；6=该会话已被选通。非 0 即拒绝，选通失败。

### 5. RejectReason（Reject.req 的 1 字节）
0=不识别的控制消息；1=状态下不该出现的控制消息（如 NOT SELECTED 收到 Linktest）；2=数据长度对不齐（Misaligned）；3=System Bytes 非法/不可用。
