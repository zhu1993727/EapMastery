## 二、背景知识（先读，15 分钟）

### 1. 协议栈定位
```
应用(GEM/GEM300) → SECS-II(E5,消息内容) → HSMS(E37,会话/传输控制) → TCP → IP
```
- E4 SECS-I 用 RS-232 串行，老旧、慢；E37 HSMS 用 TCP/IP 以太网，是当前 FAB 绝对主流。
- TCP 只保证"两个网络进程可靠有序传字节"，但半导体通信还需要：**确认对方是 HSMS 实体、会话选通与排他、心跳保活、统一事务超时、控制/数据消息区分、断线重连节奏**——这些就是 E37 的职责。

### 2. HSMS-SS vs HSMS-GS
- **HSMS-SS（Single Session，单会话）**：一条 TCP 连接承载一个会话，Host 与 Equipment 点对点。**FAB 99% 用 SS**，本计划只实现 SS。
- HSMS-GS（General Session，一般会话）：一条 TCP 复用多个会话，复杂、少见，了解即可。

### 3. Active / Passive 角色
- **Passive（通常设备）**：Bind/Listen/Accept，被动等连接，收到 Select.req 后回 Select.rsp。
- **Active（通常 Host）**：主动 Connect，连接建立后由它发 Select.req 发起选通；断线后由它按 T5 节奏重连。
- 角色可配置，但一条链路必须一 Active 一 Passive；双 Active 同时连会触发 T5 连接冲突分离。

### 4. 两个交互阶段、两类消息
- **阶段一：连接/选通控制阶段**（TCP 建立 → Select 选通 → SELECTED）。
- **阶段二：数据传输阶段**（SELECTED 后双向传 SECS-II 数据消息）。
- **控制消息（Control Message）**：管理连接本身——Select/Deselect/Linktest/Reject/Separate（SType 1~7、9）。
- **数据消息（Data Message）**：承载 SECS-II（SType=0），即 W3 起的 SxFy。

### 5. HSMS 控制状态机总览（今天先眼熟，Day03 闭卷画）
`NOT CONNECTED ──TCP建立──► CONNECTED/NOT SELECTED ──Select成功──► SELECTED`；SELECTED 经 Separate/Deselect/断链回退。
