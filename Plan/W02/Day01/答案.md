# W02 · Day01 答案与标准参考

## 一、自测题标准答案

### 题1：TCP 可靠，为何还要 HSMS（≥4 点）
1. **实体与会话确认**：TCP 只知道"连上了某进程"，不知道对方是不是 HSMS 设备、是不是目标会话；Select 用于确认 HSMS 实体、协商/确认 SessionID，并做**单会话排他**（已被选通则拒绝后来者）。
2. **连接生命周期状态机**：明确 NOT CONNECTED / NOT SELECTED / SELECTED 的合法迁移，避免"TCP 通了但业务没就绪"时误发数据。
3. **保活与半开检测**：对端断电/拔线不发 FIN，TCP 无感知；HSMS 用 T8 + Linktest 主动探测静默死亡。
4. **统一事务/控制超时**：T3 数据回复超时、T6 控制事务超时等，让"没回应"有确定的判定与处置时间。
5. **控制与数据分离**：把"管理连接的消息"（Select/Linktest/Separate）和"业务数据消息(SxFy)"分开，连接维护不干扰业务。
6. **重连节奏控制**：T5 连接分离时间防止 Active 方疯狂重连打爆对端；双 Active 冲突有确定分离规则。

### 题2：TCP 建立 ≠ 可发 SxFy
- 不等于。TCP 建立后处于 **CONNECTED / NOT SELECTED**，必须再经 **Select.req → Select.rsp(SelectStatus=0 接受)** 进入 **SELECTED**，才允许双向收发 SECS-II 数据消息。NOT SELECTED 状态只允许 Select 相关控制消息，发数据/Linktest 都属非法（会被 Reject，Reason=Unexpected Control/Data Message）。

### 题3：Active/Passive 分工
| 动作 | Active（常为 Host） | Passive（常为设备） |
|---|---|---|
| TCP | 主动 Connect | Listen/Accept |
| Select | 发 Select.req | 收 req、回 Select.rsp（带 SelectStatus）|
| 重连 | 断链后等 T5 再重连 | 继续监听等待 |
| Linktest | SELECTED 后双方都可发（谁的 T8 先到谁发）| 同左 |

### 题4：控制 vs 数据消息
- **控制消息**：管理连接，SType=1~7、9（1 Select.req/2 Select.rsp/3 Deselect.req/4 Deselect.rsp/5 Linktest.req/6 Linktest.rsp/7 Reject.req/9 Separate.req），无 SECS-II 体（Select.rsp/Reject 带 1 字节状态/原因）。**Linktest 是控制消息（SType 5/6）**。
- **数据消息**：承载 SECS-II，**SType=0**，头第 2/3 字节是 W-bit+Stream、Function。

### 题5：为何主流 SS
- 一台设备对一个 Host 的点对点模型最简单、确定性强、易排障、单会话无并发会话竞争；GS 的多会话复用增加状态与调度复杂度，而 FAB 现场没有这个需求，故 SS 成为绝对主流。

## 二、HSMS 总体交互时序（参考，先眼熟，Day03/04 闭卷）
```
Active(Host)                              Passive(Equipment)
   │── TCP SYN/SYN-ACK/ACK 建立 ─────────────►│  状态: NOT CONNECTED→NOT SELECTED
   │── Select.req (SType=1, SessionID) ──────►│
   │◄─ Select.rsp (SType=2, Status=0 接受) ───│  状态: NOT SELECTED→SELECTED
   │                                          │
   │   ════════ SELECTED：可双向传 SxFy ════════
   │◄─ Linktest.req / ─Linktest.rsp─►（T8 周期，双向可发）
   │── SxFy 数据消息 (SType=0) ──────────────►│
   │◄─ SxFy reply ───────────────────────────│
   │                                          │
   │── Separate.req (SType=9, 无rsp) ────────►│  状态: SELECTED→NOT CONNECTED，TCP 关闭
```

## 三、今日易错点
1. 把"TCP 连通"当"HSMS 选通"（中间差 Select）。
2. 以为 Linktest 是数据消息（它是控制消息 SType 5/6）。
3. 以为只能 Host 发 Linktest（SELECTED 后双方都可发，谁 T8 先到谁发）。
4. 忽略 SS 单会话排他：第二个 Host 来 Select 会被拒。
5. 双 Active 同时连接不知如何处理（T5 连接冲突分离，Day05 细讲）。

## 四、今日结论（一句话记住）
**HSMS = 在 TCP 之上加"选通(Select) + 保活(Linktest) + 状态机 + 超时(T3/5/6/7/8) + 有序拆除(Separate)"的会话控制层；只有 SELECTED 才能跑 SxFy。**
