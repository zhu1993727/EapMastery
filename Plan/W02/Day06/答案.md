# W02 · Day06 答案与整合参考

## 一、自测题标准答案
1. **为何"先过闸门、唯一入口"**：这样所有连接行为都收敛到一张状态机、一套合法边。排障时只要看 EVT 状态迁移日志，就能定位"在错误状态发了错误消息"；多线程/多回调下也不会出现状态被绕过、重复选通、半选通等幽灵问题。它是确定性和可复现的前提。
2. **报文处理链路（网卡→处理）**：Socket Receive → FrameReader 累积切帧（4B 长度）→ HsmsHeader.Decode（10B 头）→ 状态机 IsMessageAllowed 闸门 → 按 SType 分流（控制事务配对/应答；SType=0 触发 OnDataMessage 事件，W3 接 SECS-II）→ 刷新 lastRxAt → 写 RX 日志。
3. **发送为何串行化**：Socket 不是线程安全的，多个线程同时写会把两条帧的字节交错（帧撕裂），对端切帧直接失败。用一把发送锁或单一发送队列/Channel，保证"一条帧原子写完再写下一条"。
4. **抓包区分 Select/Linktest**：看 10B 头第 6 字节（SType，整帧偏移 4+5=第 9、10 字节附近）——Select.req=0x01、Select.rsp=0x02、Linktest.req=0x05、Linktest.rsp=0x06、Separate=0x09；再看头前两字节 SessionID：Linktest/Separate=FF FF，Select 是具体会话号。
5. **缺哪层**：缺 **SECS-II（E5）数据编码/解码层**——现在 SType=0 的 data 还是不透明字节，W3 学格式字节、数据项类型与嵌套 List，把 SxFy 的 body 解析成数据树，W4 再做完整事务与通信。

## 二、整合参考骨架（HsmsConnection.cs）
```csharp
public sealed class HsmsConnection
{
    private readonly Role _role; private readonly HsmsTimers _t = new();
    private readonly HsmsControlStateMachine _sm;
    private readonly PendingTransactions _pend = new();
    private readonly SysGenerator _sys = new();
    private readonly TimeoutScanner _scanner;
    private readonly SemaphoreSlim _sendLock = new(1,1);   // 发送串行化
    private NetworkStream? _stream; private readonly FrameReader _fr = new();
    public event Action? OnSelected;
    public event Action? OnBroken;
    public event Action<HsmsHeader, byte[]>? OnDataMessage; // W3 接 SECS-II

    public HsmsConnection(Role role, ILogSink log)
    {
        _role = role;
        _sm = new HsmsControlStateMachine(role, log);
        _scanner = new TimeoutScanner(_t, _pend, () => _sm.Current);
        _scanner.OnLinktestDue += () => Linktest();
        _scanner.OnControlTimeout += p => Break("T6 timeout " + p.Type);
        _scanner.OnSelectDueExpired += () => Break("T7 select timeout");
    }

    private async void Send(byte[] frame)
    {
        if (_stream is null) return;
        await _sendLock.WaitAsync();
        try { await _stream.WriteAsync(frame); } finally { _sendLock.Release(); }
    }

    private async Task ReceiveLoopAsync()
    {
        var buf = new byte[64 * 1024];
        while (true)
        {
            int n;
            try { n = await _stream!.ReadAsync(buf); } catch { Break("read error"); return; }
            if (n == 0) { Break("peer closed"); return; }      // 对端关 TCP
            foreach (var payload in _fr.Push(buf, n))
            {
                var h = HsmsHeader.Decode(payload.AsSpan(0, HsmsHeader.HeaderLen));
                var data = payload.Length > 10
                    ? payload[10..] : Array.Empty<byte>();
                await DispatchAsync(h, data);
                _scanner.LastRxAt = DateTime.UtcNow;
            }
        }
    }

    private Task DispatchAsync(HsmsHeader h, byte[] data)
    {
        if (!_sm.IsMessageAllowed(h.SType)) { Reject(h, 1); return Task.CompletedTask; }
        switch (h.SType)
        {
            case HsmsSType.Data: OnDataMessage?.Invoke(h, data); break;   // W3 接管
            case HsmsSType.SelectReq:
                byte st = _sm.OnSelectOk() ? (byte)0 : (byte)6;
                Send(HsmsControl.Build(HsmsSType.SelectRsp, h.SystemBytes, h.SessionId, st));
                if (st == 0) Selected();
                break;
            case HsmsSType.LinktestReq:
                Send(HsmsControl.Build(HsmsSType.LinktestRsp, h.SystemBytes)); break;
            case HsmsSType.SeparateReq: Break("peer separate"); break;
            case HsmsSType.SelectRsp: case HsmsSType.LinktestRsp: case HsmsSType.DeselectRsp:
                _pend.TryResolve(h.SystemBytes, data, out _);
                if (h.SType == HsmsSType.SelectRsp && data.Length > 0 && data[0] == 0) Selected();
                break;
            default: Reject(h, 0); break;
        }
        return Task.CompletedTask;
    }

    private void Selected() { _scanner.MarkSelected(); OnSelected?.Invoke(); }
    private void Reject(HsmsHeader h, byte reason)
        => Send(HsmsControl.Build(HsmsSType.RejectReq, h.SystemBytes, 0xFFFF, reason));
    private void Linktest() => Send(HsmsControl.Build(HsmsSType.LinktestReq, _sys.Next()));
    private void Break(string why) { try { _sm.OnSeparate(); } catch { } SafeClose(); OnBroken?.Invoke(); }
    private void SafeClose() { try { _stream?.Close(); } catch { } _stream = null; }
}
```
> 这是"骨架级"实现，重点看清编排关系；Active 的 Connect/Select/T5 重连接 Day05 的 RunActiveLoopAsync 接上即可。

## 三、抓包识别速查（整帧 = 4B长度 + 10B头 + data）
| 消息 | 长度 | 头关键字节（SType 位于整帧第 10 字节）|
|---|---|---|
| Select.req | 00 00 00 0A | …SType=01，SessionID 非 FFFF |
| Select.rsp(接受) | 00 00 00 0B | …SType=02，data=00 |
| Linktest.req | 00 00 00 0A | 头前两字节 FF FF，SType=05 |
| Linktest.rsp | 00 00 00 0A | FF FF … SType=06 |
| Separate.req | 00 00 00 0A | FF FF … SType=09 |

## 四、今日验收（DoD）
- 双端自动完成 Connect→Select(SELECTED)→周期 Linktest→数据计数→Separate；拔线/关端能 T5 自动重连。
- 异常矩阵 6 例全部得到预期状态变化与日志。
- 抓包能不看注释认出三类控制消息。
- HSMS 模块分层结构图能脱稿讲清每个组件职责与数据流。

## 五、易错点
1. 多线程并发写 socket 导致帧撕裂（务必发送锁/队列）。
2. Read=0（对端正常关闭）没当成断链处理。
3. 控制事务和数据消息共用一套超时（应 T6/T3 分开）。
4. 整合后绕过状态机直接发消息（回到 Day03 的纪律）。
