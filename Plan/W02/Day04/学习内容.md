## 二、背景知识（先读，20 分钟）

### 1. 各控制事务行为表（必背）
| 事务 | 发起方/状态 | 应答 | 成功后动作 |
|---|---|---|---|
| Select | Active 在 NOT SELECTED 发 req | Passive 回 rsp(SelectStatus) | Status=0：双方进 SELECTED |
| Linktest | 任一方在 SELECTED、T8 到点发 req | 对方立即回 rsp（无 data）| 刷新网络活动计时 |
| Separate | 任一方发 req（无 rsp）| 无 | 双方回 NOT CONNECTED、关 TCP |
| Deselect | SELECTED 发 req | 对方回 rsp | 回 NOT SELECTED，保留 TCP |
| Reject | 收到非法/无法处理的控制消息时回 | 无 | 带 ReasonCode，不改变自身状态（严重时断开）|

### 2. SystemBytes 配对规则
- req 发起方生成唯一 4 字节事务号（通常递增，线程安全）；rsp **原样复制** req 的 SystemBytes。
- 发送 req 后在"未决事务表"登记 `sys → (类型, 发出时刻, 超时T, 回调)`；收到 rsp 按 sys 匹配并移除，触发回调；超时未匹配由 T6 处理（Day05）。
- Linktest 也走这张表，但它的作用是探活，不承载业务。

### 3. 接收处理管线（顺序很重要）
切出一帧 → 解 HsmsHeader → 过"状态×消息闸门"（非法→Reject）→ 分流：
- SType=0 数据消息：交给 SECS-II（W3，本周先计数/打印）；
- Select.req：回 Select.rsp(状态机判定能否选通)；
- Select.rsp/Deselect.rsp/Linktest.rsp：按 sys 匹配未决事务；
- Linktest.req：立即回 Linktest.rsp；
- Separate.req：状态机回 NOT CONNECTED、关 socket；
- 不识别/错位：回 Reject.req(Reason)。

### 4. Linktest 触发逻辑
SELECTED 后维护"最后收到任何报文的时间"；定时检查，空闲达到 T8 就发 Linktest.req；**收到任何报文（含数据消息）都重置该计时**，避免无谓心跳。
