# W02 · Day04 答案与参考实现

## 一、自测题标准答案
1. **为何复制 SystemBytes / 并发如何区分**：HSMS 全双工、可同时有多个在途事务，rsp 不带"请求序号"就无法和请求对应，SystemBytes 是唯一配对凭据，所以必须原样回填。并发时每个 req 用不同 sys，接收端靠 sys 在未决事务表里精确匹配，类似请求 ID。
2. **Passive 如何定 SelectStatus**：0=当前 NOT SELECTED、资源就绪、SessionID 合法 → 接受；6=已经 SELECTED（已有 Host，SS 排他）；2=自身未就绪（初始化未完成/资源不可用）；5=SessionID 不识别；3=资源耗尽。依据就是 Day03 状态机当前态 + 资源/Session 校验。
3. **收到数据消息能否当活证据 / Linktest.rsp 还要吗**：**能**——任何报文到达都证明链路活着，应重置 T8 空闲计时；但**已经发出的 Linktest.req 仍要等 Linktest.rsp**，因为它是一次独立控制事务（在未决事务表里，靠 T6 判定），数据消息不能替代它的应答，否则该事务会 T6 超时误判。
4. **Separate 为何不等应答**：语义是立即单向拆除，发出即关 TCP，连接都要没了，没有可靠通道等 rsp；需要可确认的"只解除选通"用 Deselect（有 rsp）。
5. **收到 Reject 改不改状态**：**Reject 本身不要求改变本端状态**，它只是被告知"你那条控制消息有问题"。是否断开取决于问题性质：Reason=1 状态错位往往说明本端状态机 bug，要记日志/告警并核对状态；只有在无法恢复时才主动 Separate。
6. **选通→心跳→拆除时序**
```
Active(Host)                         Passive(设备)                 状态
 Select.req(SType1,sys=1) ───────► NotSelected
 ◄─────── Select.rsp(SType2,sys=1,status=0)        双方→Selected
   (T8 到点) Linktest.req(5,sys=2) ─► Selected
 ◄──────── Linktest.rsp(6,sys=2)
   S6F11 数据(SType0) ◄────────────► （任意报文都重置T8）
 Separate.req(SType9) ────────────► 双方→NotConnected，关TCP
```

## 二、参考实现

### SystemBytesGenerator + 未决事务表
```csharp
using System.Collections.Concurrent;
public sealed class SysGenerator { private uint _v; public uint Next() => Interlocked.Increment(ref _v); }

public sealed record Pending(uint Sys, HsmsSType Type, DateTime SentAt, TaskCompletionSource<byte[]> Tcs);

public sealed class PendingTransactions
{
    private readonly ConcurrentDictionary<uint, Pending> _map = new();
    public void Add(Pending p) => _map[p.Sys] = p;
    public bool TryResolve(uint sys, byte[] data, out Pending? p)
    {
        if (_map.TryRemove(sys, out p)) { p.Tcs.TrySetResult(data); return true; }
        p = null; return false;
    }
    public IEnumerable<Pending> Expired(TimeSpan t6, DateTime now)
        => _map.Values.Where(p => now - p.SentAt > t6).ToList();
    public void Remove(uint sys) => _map.TryRemove(sys, out _);
}
```

### 控制事务接收管线（Passive 侧关键分支）
```csharp
async Task HandleFrame(HsmsHeader h, byte[] data)
{
    if (!_sm.IsMessageAllowed(h.SType))                       // 状态×消息闸门
    {
        Send(HsmsControl.Build(HsmsSType.RejectReq, h.SystemBytes, 0xFFFF, (byte)1)); // Reason=1
        _log.Log(LogDir.ERR, $"状态{_sm.Current}下非法消息 {h.SType}");
        return;
    }
    switch (h.SType)
    {
        case HsmsSType.Data: await OnDataMessage(h, data); break;       // W3 接 SECS-II
        case HsmsSType.SelectReq:
            byte status = _sm.OnSelectOk() ? (byte)0 : (byte)6;        // 已选通→6
            Send(HsmsControl.Build(HsmsSType.SelectRsp, h.SystemBytes, h.SessionId, status));
            break;
        case HsmsSType.SelectRsp:
        case HsmsSType.DeselectRsp:
        case HsmsSType.LinktestRsp:
            if (!_pending.TryResolve(h.SystemBytes, data, out _))
                _log.Log(LogDir.ERR, $"收到匹配不上的 rsp sys={h.SystemBytes}");
            break;
        case HsmsSType.LinktestReq:
            Send(HsmsControl.Build(HsmsSType.LinktestRsp, h.SystemBytes));
            break;
        case HsmsSType.SeparateReq:
            _sm.OnSeparate(); await CloseAsync(); break;
        default:
            Send(HsmsControl.Build(HsmsSType.RejectReq, h.SystemBytes, 0xFFFF, (byte)0)); // 不识别
            break;
    }
    _lastRxAt = DateTime.UtcNow;   // 任何报文都算网络活动
}
```

### Active 侧发起选通/心跳
```csharp
public async Task<bool> SelectAsync(TimeSpan t6)
{
    var sys = _sys.Next();
    var tcs = new TaskCompletionSource<byte[]>();
    _pending.Add(new Pending(sys, HsmsSType.SelectReq, DateTime.UtcNow, tcs));
    Send(HsmsControl.Build(HsmsSType.SelectReq, sys, session: 0));
    var completed = await Task.WhenAny(tcs.Task, Task.Delay(t6));
    if (completed != tcs.Task) { _pending.Remove(sys); return false; } // T6 超时
    var status = tcs.Task.Result[0];
    if (status == 0) { _sm.OnSelectOk(); return true; }
    return false; // 非0拒绝
}
public void Linktest() => Send(HsmsControl.Build(HsmsSType.LinktestReq, _sys.Next()));
public void Separate() { Send(HsmsControl.Build(HsmsSType.SeparateReq, _sys.Next())); /*发完即关*/ }
```

## 三、今日验收
- 双端日志能看到：Select 选通进 SELECTED → 两次 Linktest req/rsp → Separate 回 NOT CONNECTED。
- 未选通发 Linktest 收到 Reject(Reason=1)；不识别 SType 收到 Reject(Reason=0)。
- 能解释"数据消息能重置 T8，但不能顶替 Linktest.rsp"。

## 四、易错点
1. rsp 没回填原 sys，导致未决事务永远 T6 超时。
2. 不做状态闸门，未选通也响应数据/心跳。
3. 用数据消息顶替 Linktest.rsp（事务对不上）。
4. Separate 还在等 rsp（应发完即关）。
5. 收到 Reject 就盲目断链（应先判 Reason、查本端状态机）。
