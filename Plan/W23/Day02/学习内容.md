# W23 · Day02（周二）优先级、老化防饥饿与可解释调度

> 建议时长：90 分钟。多 CJ 就绪集合里先做谁？今天建立可解释的调度优先级体系：静态优先级 + 就绪时间 FIFO + 老化提升 + 工艺切换代价，并保证低优先级任务不被无限推迟（无饥饿），每个排序结果都能给出理由。

## 一、今日目标
1. 实现调度优先级模型：批次优先级、就绪时间、老化（aging）、亲和/切换代价的综合排序键。
2. 掌握饥饿成因与防饥饿机制：老化提升、最大等待保证、公平性指标。
3. 识别并避免优先级反转（高优先级等待被低优先级占有的资源）。
4. 实现可解释调度：每次选择输出"为什么是它、被谁挡住、预计何时开始"。
5. xUnit 覆盖优先级抢占顺序、老化反超、无饥饿、解释生成。

## 二、背景知识（先读，30 分钟）

### 1. 为什么不能只看静态优先级
- 只按 Host 给的固定优先级，低优先级批次在持续到来的高优先级流面前可能永远排不上（饥饿）。
- 只按 FIFO 又无法响应紧急批次（hot lot/工程批）。
- 需要"优先级为主、等待时间老化为辅、确定性 tie-break 兜底"的组合。

### 2. 综合排序键（effective priority）
- 有效分 = 静态优先级 + 老化增益（等待越久增益越大），再用就绪时间、切换代价、固定 ID 做次级排序。
- 老化增益示例：aging(wait)=floor(wait/agingInterval)，每等一个区间 +1 级，封顶。
- 排序：有效分降序 → 就绪时间升序（先来先服务）→ 配方/腔体亲和（减少切换）→ CjId/PjId 字典序（确定性）。

### 3. 防饥饿保证
- 饥饿：某任务就绪后无限期得不到资源。
- 老化保证：等待足够久后有效分必然超过任何静态优先级（老化增益无上封顶或封顶高于最大静态优先级差），从而一定被调度。
- 可设最大等待时限 maxWait，超时产生告警/强制提权，供调度看板与 Host 监控。
- 公平性指标：每个任务"等待时长/加工时长"、最大等待，用来验证无饥饿。

### 4. 优先级反转与治理
- 反转：高优先级 H 需要某资源，却被持有它的低优先级 L 占着，而 L 又被中优先级 M 长期插队 → H 被 M 间接挡住。
- 设备调度治理：①资源一旦分配不可被抢占（非抢占式，工艺不可中途让腔），因此靠"让持有者尽快跑完释放"（不被无关中优先级再插队占用其后续所需资源）——即优先级继承思想：持有高优先级任务所需资源的作业，在持有期间按该高优先级对待；②或在预留阶段就按有效优先级排序资源分配，减少低优先级占住关键资源。
- 本设备场景以非抢占+优先级继承/有序预留为主，不做工艺中途抢占（会报废在制品）。

### 5. 工艺切换代价与亲和
- 连续两批在同腔用不同 recipe 有切换（换气/清腔/调参）时间；排序时在不违背优先级/公平的前提下，倾向同 recipe 连做（batching/亲和），但亲和不得导致饥饿（受老化约束）。
- 亲和是次级优化，永远让位于有效优先级与防饥饿。

### 6. 可解释调度（专家现场必备）
- 每次决策输出决策记录 DecisionRecord：被选任务、有效分构成、同时刻竞争者、未选原因（等哪个资源/被谁占/预计可用时刻）、预计开始/结束。
- 现场工程师/Host 问"为什么这批还没做"，能直接从记录回答，而不是黑盒。
