# W23 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何重叠 / 前提**：若等前批完全下料再上后批，LoadPort 交接、AMHS 送取盒、读盒建基线的时间设备都在空等，成为产能损失。重叠让空闲口提前完成后批上料，前批加工一结束就能立刻接着做，隐藏物流时间、提升口周转与设备利用率。不乱的前提：各 LoadPort 状态独立推进（一个口的上/下料不等另一个口）、共用的机械手/EFEM/锁进设备级全局资源日历统一仲裁（Day01）、片以全局 ID 带批次归属（今天的台账）、后批是否开工由统一调度按依赖/资源决定而非"上了就做"。
2. **三种口重叠期用法**：Input 口只负责进原料，前批加工时可在后 Input 口 Deposit/Load 后批原料并建基线、排队就绪；Output 口只出成品，前批成品陆续装入，盒满或批完成后 Unload 等 AMHS 取走，取走前该口被占用、不能安排别的盒；InOut 口兼用，必须串行复用——先作为输出把前批成品 Unload、被取走、口清空，才能再作为输入 Deposit 后批原料，同一时刻只承担一个方向。多口并行 + InOut 串行，使物流与加工最大重叠又不撞口。
3. **为何以全局片 ID 为主键**：多盒并存且会跨盒交叉取片（W15），按盒各记各的无法回答"这片现在到底在哪个盒、属于哪批"，跨盒转移时两本账容易不同步、混片。以全局唯一 SubstrateId 为主键，每片只有一条全局记录（含来源/当前位置/目标/所属批），盒只是片当前所在的容器属性；无论片怎么在盒间、设备内移动，都更新同一条记录，天然支持跨盒追踪与全局唯一位置，避免多本账漂移。
4. **两级守恒 / 同时成立的含义**：全局守恒=所有在口载具内片 + 设备内（臂/锁/腔/Buffer）片的 ID 集合 == 全部已上料且未下料片的总集合（跨盒总量不变、无中生有/丢失）；分批守恒=每个 CJ/Lot 自己的片集合在任意时刻守恒（该批片分布在哪些载具/设备位置的并集恒等于该批基线集合），且不同 CJ 的片集合交集为空。两者同时成立说明：总量没丢没多（全局），且每一批自己的片没少、批与批之间没串片（分批），是多批并存不混账的数学保证。
5. **后批状态 / 谁决定开工**：后批可以完成 Installed→Loaded→E90 基线注册，但其 ControlJob 创建后处于 Queued（就绪等待）状态：它的 PJ 虽可能 CJ 内依赖就绪，但要等统一调度器（Day01/02）依据全局资源日历（腔/臂/锁何时空）、优先级/老化、以及前批占用情况排到时间窗才真正 Start。即"上料就绪"与"开工执行"分离，能不能提前上料看口，什么时候开工由设备级 GlobalScheduler 统一裁决，后批不会因载具已 Loaded 就抢前批资源。
6. **InOut 先卸后上 / 违反后果**：InOut 同一物理口既要出前批成品又要进后批原料，物理上同一时刻只能有一个盒、一套 E84 握手。必须先让前批输出盒 Unload、AMHS Pickup 取走、口回到空，再 Deposit 后批输入盒。违反（没取走就放新盒/同时握手）会造成两盒在同一口冲突、E84 握手错乱、机械手取放目标不明，甚至撞盒、把成品盒当原料盒、混批。因此 InOut 口状态机把"卸→取空→上"严格串行。
7. **防 A 批片进 B 批输出盒的机制**：①片记录带 CjId/Lot 归属与该 CJ 定义的目标输出载具/槽；②每次 Place 到输出盒前，按片 ID 查其归属，校验目标载具正是该片所属 CJ 的声明输出、目标槽与 ResultMap 一致，不匹配直接拒绝（禁止"按最近空槽"跨批放置）；③分批守恒实时校验，A 批片一旦出现在 B 批输出集合即报警封锁；④跨批移动/分档合批必须显式授权（Day04）。用"片身份→归属→合法目标"的强校验替代就近放置，从机制上杜绝混批。

## 二、参考实现（net8.0）

### 多盒全局台账
```csharp
namespace EapLab.E94.Ledger;
public sealed class WaferLedgerEntry
{ public string Id="",LotId="",CjId="",SrcCarrier="";public int SrcSlot;
  public string Location="",DstCarrier="";public int DstSlot;public bool Done; }

public sealed class MultiCarrierLedger
{
    private readonly Dictionary<string,WaferLedgerEntry> _w=new();   // 全局片ID主键
    private readonly HashSet<string> _onboardCarriers=new();
    public void CarrierLoaded(string carrier){_onboardCarriers.Add(carrier);}
    public void Register(string id,string lot,string cj,string carrier,int slot,string loc)
    { if(_w.ContainsKey(id))throw new InvalidOperationException("片ID重复");
      _w[id]=new(){Id=id,LotId=lot,CjId=cj,SrcCarrier=carrier,SrcSlot=slot,Location=loc}; }
    public void Move(string id,string loc){_w[id].Location=loc;}
    public void AssignOutput(string id,string carrier,int slot){_w[id].DstCarrier=carrier;_w[id].DstSlot=slot;}

    // 放置前防混批校验
    public bool CanPlaceToOutput(string id,string carrier,int slot,out string why)
    { var e=_w[id]; why="";
      if(e.DstCarrier!="" && e.DstCarrier!=carrier){why=$"片{id}属{e.CjId},目标{e.DstCarrier},拒绝放{carrier}";return false;}
      if(_w.Values.Any(x=>x!=e && x.DstCarrier==carrier && x.DstSlot==slot)){why="目标槽已占";return false;}
      return true; }
    public void PlaceToOutput(string id,string carrier,int slot)
    { if(!CanPlaceToOutput(id,carrier,slot,out var w))throw new InvalidOperationException(w);
      _w[id].DstCarrier=carrier;_w[id].DstSlot=slot;_w[id].Location=$"{carrier}:{slot}";_w[id].Done=true; }

    public HashSet<string> GlobalSet=>new(_w.Keys);
    public HashSet<string> SetOfCj(string cj)=>new(_w.Values.Where(x=>x.CjId==cj).Select(x=>x.Id));
    public bool GlobalConserved(HashSet<string> loadedBaseline)=>new HashSet<string>(_w.Keys).SetEquals(loadedBaseline);
    public bool NoMixAcrossCj() // 不同CJ片不落在对方声明输出
    =>_w.Values.All(e=>e.DstCarrier=="" || OutputBelongsToCj(e.DstCarrier,e.CjId));
    Dictionary<string,string> _outOwner=new();
    public void DeclareOutput(string carrier,string cj){_outOwner[carrier]=cj;}
    bool OutputBelongsToCj(string carrier,string cj)=>!_outOwner.ContainsKey(carrier)||_outOwner[carrier]==cj;
}
```

### 端口监督（多口并行/InOut 串行）
```csharp
public enum PortRole{Input,Output,InOut}
public enum PortPhase{Empty,Depositing,Loaded,ProcessingBound,Unloading,Picked}
public sealed class PortSupervisor
{
    private readonly Dictionary<string,(PortRole role,PortPhase phase)> _p=new();
    public void Declare(string port,PortRole r){_p[port]=(r,PortPhase.Empty);}
    public (bool ok,string why) CanDeposit(string port)
    { if(!_p.ContainsKey(port))return(false,"未知口");
      var(role,phase)=_p[port];
      if(role==PortRole.InOut && phase is not (PortPhase.Empty or PortPhase.Picked))
        return(false,"InOut须先卸空取走才能再上");
      if(phase!=PortPhase.Empty && phase!=PortPhase.Picked)return(false,"口占用中");
      return(true,""); }
    public void Set(string port,PortPhase ph){var(r,_)=_p[port];_p[port]=(r,ph);}
}
```

## 三、多载具重叠（手绘参考）
```
LP1(Input CJ2): 前批加工中 → 可Deposit→Loaded→基线 → CJ2 Queued等全局调度
LP2(Input ...): 独立并行
OUT(Output CJ1): 成品陆续装入 → 满/批完 → Unload → AMHS取走前占用
InOut: 出前批(Unload→Pickup取空) ⇄ 上后批(Deposit), 严格串行不撞口
台账: 全局片ID主键(归属Lot/Cj + 源 + 当前位置 + 声明目标)
 全局守恒: 在口载具∪设备内 == 已上料总集合
 分批守恒: 每CJ集合守恒; 不同CJ交集为空
防混批: Place前 片ID→归属→声明输出校验, 拒绝跨批就近放置; 跨批移动需授权
共用机械手/EFEM/锁 → 全局资源日历仲裁; 开工时机由GlobalScheduler定, 与是否已Loaded分离
```

## 四、今日易错点
1. 前批下料完才上后批（物流时间变空闲，应多口重叠、统一调度）。
2. 按盒各建台账、跨盒转移两本账不同步（全局片 ID 唯一主键）。
3. 只做全局守恒不做分批守恒（总量对但批间串片）。
4. 以为载具 Loaded 就该开工（上料就绪与开工分离，调度器定时间窗）。
5. InOut 没取空前盒就放后盒（口冲突/E84 错乱/混批，必须先卸后上）。
6. 按"最近空槽"放输出导致跨批混盒（按片归属+声明输出强校验）。
7. 输出盒未取走还往该口安排新盒（占用冲突要挡）。
8. 设备端去指挥 AMHS 派车（设备只暴露口状态，派车是上层物流决策）。
