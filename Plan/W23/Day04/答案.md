# W23 · Day04 答案与参考实现

## 一、自测题标准答案
1. **四形态定义/场景**：Merge 合批——多个来源盒/批次的片汇入同一后续工艺或载具（如不同盒同配方片合进同一炉管批次），要保留每片原始谱系；Split 拆批——一批按确定规则拆向不同后续路线/载具（如同批片一部分走刻蚀 A、一部分走刻蚀 B）；Binning 分档——量测/检测后按结果把片分到 Good/NG/复测/不同性能档，各档对应不同输出盒或路线（如电学测试后分速度档）；Rework 回流——检测不合格的片返回某道工序重做（如膜厚不达标回沉积）。前三者改变片的分组/流向，Rework 改变片经过工序的次数。
2. **为何不用逐盒守恒而用全局 ID 集合**：逐盒守恒要求"一个盒进多少出多少"，但 Merge 是多盒进一盒/一路、Split/Binning 是一盒进多盒、Rework 片会在工序间往返，逐盒数量必然不守恒，硬套会把正常变换误判为丢片。全局以唯一 SubstrateId 集合为准：不管片怎么合、拆、分、回流，变换前所有片 ID 集合与变换后完全相等（SetEquals），只改变片的分组、位置、路线、轮次，不增不减，这才是这些形态下正确的守恒口径。
3. **Split/Merge 集合关系**：Split：原集合 S 拆为若干去向子集 S1..Sk，要求子集并集=S（全覆盖、无丢失）且两两交集为空（每片唯一去向、不重复分配）。Merge：多个来源集合 A、B 合并为 M，要求 M=A∪B 且来源之间交集为空（同一片不能从两个来源重复合入），并保留每片来自哪个源。两者本质都是"并集等于全体、互斥不重不漏"，只是方向相反。
4. **为何显式授权 / 设备能否自定去向**：合/拆/分档改变了片的预期工艺流向与最终归属，属于工艺/生产决策（哪片合炉、走哪条线、判成哪一档、进哪个盒），必须由 Host 的工艺令/配方规则明确授权（MergeSplitAuthorized，含来源、去向、规则、谱系要求）。设备不能自行决定，因为设备不掌握批次工艺意图与质量判定规则，自定流向会造成错工艺、混档、谱系断裂；设备只按授权规则执行量测结果到档位的映射并全程留痕，规则外情况安全保持上报。
5. **分档时机 / 档满**：必须在量测拿到结果之后、Place 到输出之前定档——先依据结果确定档位与该档目标盒/槽，再执行放置；若先放置再改档，片已在错误盒里、要二次搬运且可能已污染账目。某档输出盒满时，片不能硬塞也不能改投别的档盒，应停在 Buffer/交接安全位（有确定位置、计入守恒），向 FAB 请求更换该档空盒，换好并绑定后再放置，等待期间不丢片、不串档。
6. **回流为何用新实例+轮次而非 DAG 成环**：若让片在同一张控制图里沿边回到已执行过的 PJ，DAG 出现环，调度器无法判定先后（死循环、无法收敛、完成条件无法定义）。正确建模是为该片创建该 PJ 的一个**新执行实例**（或新返工 CJ），在实例序列上线性推进，并带 reworkCount 轮次、最大次数 N、退出条件（合格或达上限）。这样控制依赖始终是无环 DAG（新实例排在后面），同时准确表达"同一片又做了一遍"，可统计轮次、可在超次时退出到报废/人工。
7. **回流两次的片数/加工次数**：片总数不变（仍是那片，ID 已在全局基线，回流只改位置与轮次、不新增片）；加工次数增加——这片在被回流的工序上累计加工 3 次（首次+两次返工），若该 CJ 有 6 片且只有这一片回流两次，该工序的加工工作量是 8 片次但在制/完成片数仍按唯一 ID 计为 6（W20 唯一片计数：加工次数可累加，片数不翻倍）。完成以该片最终合格到达 CJ 输出为准，谱系记录三次加工与两次回流原因。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.E94.Flow;
public enum BinGrade{Good,Retest,NG,Scrap}
public sealed class FlowAuth
{ public bool MergeSplitAuthorized; public Dictionary<string,BinGrade> BinRule=new();
  public Dictionary<string,string> BinOutput=new(); public int MaxRework=2; }

public sealed class MergeSplitPlanner
{
    // Split: 一片一去向, 互斥且并集=原集
    public (Dictionary<string,List<string>> go,List<string> prob)
        Split(HashSet<string> src,Func<string,string> routeOf)
    { var go=new Dictionary<string,List<string>>(); var prob=new List<string>();
      foreach(var w in src){var r=routeOf(w);if(r==null){prob.Add($"{w}无去向");continue;}
        if(!go.ContainsKey(r))go[r]=new();go[r].Add(w);}
      var union=new HashSet<string>(go.Values.SelectMany(x=>x));
      if(!union.SetEquals(src))prob.Add("拆分未全覆盖");
      return(go,prob); }

    // Merge: 多源并集, 来源不重叠
    public (List<string> merged,List<string> prob) Merge(params HashSet<string>[] sources)
    { var merged=new List<string>(); var seen=new HashSet<string>(); var prob=new List<string>();
      foreach(var s in sources)foreach(var w in s)
        if(!seen.Add(w))prob.Add($"{w}在多源重复");else merged.Add(w);
      return(merged,prob); }

    // Binning: 量测后放置前定档
    public (Dictionary<BinGrade,List<string>> bins,List<string> prob)
        Bin(HashSet<string> wafers,Func<string,BinGrade> measure,FlowAuth auth,Func<BinGrade,bool> binFull)
    { if(!auth.MergeSplitAuthorized)throw new InvalidOperationException("未授权分档");
      var bins=Enum.GetValues<BinGrade>().ToDictionary(g=>g,_=>new List<string>()); var prob=new List<string>();
      foreach(var w in wafers)
      { var g=measure(w);
        if(binFull(g)){prob.Add($"{w} 档{g}盒满,安全等待换盒");continue;} // 不硬塞/不串档
        bins[g].Add(w); }
      return(bins,prob); }
}
```

### Rework 回流（新实例+轮次+上限）
```csharp
public sealed class ReworkLoop
{
    private readonly FlowAuth _auth; public ReworkLoop(FlowAuth a){_auth=a;}
    public sealed class ReworkInstance{public string Wafer="";public int Round;public bool Passed;}
    public List<ReworkInstance> History{get;}=new();
    public record Step(ReworkInstance Inst,bool NeedRework,BinGrade? Exit);
    public Step Process(string wafer,int currentRound,bool measurePass)
    { History.Add(new ReworkInstance{Wafer=wafer,Round=currentRound});
      if(measurePass)return new(new(wafer,currentRound,true),false,BinGrade.Good);
      if(currentRound>=_auth.MaxRework)return new(new(wafer,currentRound,false),false,BinGrade.Scrap); // 超次退出
      return new(new(wafer,currentRound,false),true,null); } // 生成下一(新)实例, DAG无环
}
```

## 三、复杂片流（手绘参考）
```
Merge: 源A∪源B(互斥) → 同后续PJ, 保留每片源谱系(多源栅栏等齐)
Split: 源S → 子集S1..Sk(并集=S, 两两交集空) → 不同路线
Binning: 量测 →(放置前)定档 → 档盒(Good/Retest/NG/Scrap); 档满→Buffer安全等换盒
Rework: 检测不过 → 同PJ"新实例"(线性DAG不成环) + reworkCount, ≤MaxRework, 合格/超次退出
统一口径: 全局SubstrateId集合 Before==After(SetEquals); 合/拆/分档需显式授权;
         片数按唯一ID不增, 加工/回流次数可累加; 全程谱系genealogy
衔接: Merge等多源到齐; Split支/新实例进全局调度; 档盒进多盒台账
```

## 四、今日易错点
1. 对 Merge/Split 套逐盒守恒（误判正常变换为丢片，要用全局 ID 集合）。
2. Split 子集不互斥（一片两个去向）或不全覆盖（漏片）。
3. Merge 来源有重叠片（重复合入）。
4. 未经授权自行合/拆/分档（流向是工艺决策，必须授权+留痕）。
5. 先 Place 再定档（污染账目，应量测后放置前定目标）。
6. 档满硬塞或改投别档盒（安全等待换盒、不串档）。
7. Rework 让 DAG 成环（用新实例+轮次，控制图始终无环）。
8. 回流新增片 ID/片数翻倍（片不增，只累加加工次数，完成以到输出为准）。
9. 回流不设最大次数（死循环，要 MaxRework + 超次转报废/人工）。
10. 不记谱系，合批/回流后无法追溯原批次与每次结果。
