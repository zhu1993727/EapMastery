# W23 · Day05（周五）组合故障注入：多 CJ 并发下的叠加异常

> 建议时长：100 分钟。真实现场异常往往同时来：一个腔故障时恰好 HSMS 断线、某载具又被 Hold。今天专门训练多 CJ 并发场景下的**叠加异常**：异常正交分解、影响域隔离、组合无未定义分支、恢复顺序与不串批，做到越乱越稳。

## 一、今日目标
1. 建立叠加异常模型：异常按维度正交分类（资源/通信/质量授权/片/作业），组合而非嵌套乱处理。
2. 实现 CompoundFaultResolver：多异常同时存在时逐维判定、求最严安全态、确定恢复顺序。
3. 保证多 CJ 并发下一个 CJ 的故障不污染其他 CJ（影响域按依赖图+资源占用圈定）。
4. 掌握恢复顺序：先安全、再通信/对账、后作业续跑，且每批各自恢复不串批。
5. xUnit 覆盖"腔故障+断线+Hold"三叠加、故障恢复期间新批到达、恢复顺序幂等。

## 二、背景知识（先读，30 分钟）

### 1. 叠加异常为什么难
- 单一异常有确定剧本（W21/W22）；叠加时若按"谁先触发走谁的流程"写 if-else，会出现处理互相覆盖（断线重连流程把腔故障状态冲掉）、状态抖动、未定义分支。
- 正确思路：异常不是先后故事，而是**当前同时存在的一组条件**，要按维度独立判定、合成一个总体安全态与恢复计划。

### 2. 异常五维正交分类
- 资源维：腔/臂/锁故障或不可用（影响占用该资源的所有 CJ 的相关 PJ）。
- 通信维：HSMS 断线（影响上报与命令，不影响本地安全执行）。
- 授权/质量维：Equipment/Carrier/Lot Hold（影响对应范围向前推进）。
- 片维：Missing/Double/Misplaced/读码失败（影响该片/该区域搬运）。
- 作业维：PJ/CJ 故障、Abort（按 W21 级联）。
- 每维独立给出"影响集合 + 要求的安全态"，互不覆盖。

### 3. 合成规则：求最严安全态（meet-lattice）
- 各维要求的动作严格程度排序：Continue < Degraded < Hold(到安全点停) < Stop(级联停) < SafeStop(全线安全保持人工)。
- 总体态=所有现存异常要求态的**最严者**（如腔故障要求某 CJ Stop、断线只要求本地继续+缓存、Hold 要求另一批 Hold，则相关 CJ 各取所需、整机不因断线而停、但被 Hold 批不动）。
- 影响域按 CJ 分开圈定：A 批资源故障不必然停 B 批，除非共用故障资源/安全系统。

### 4. 恢复顺序（叠加解除）
1. 安全优先：先保证所有片在安全位、危险动作停（无论通信是否恢复）。
2. 通信恢复：HSMS 重连、控制态回 ONLINE REMOTE。
3. 逐层对账：E87→E90→各 CJ 的 PJ（按身份分别重建，不串批，W22/W23 Day03）。
4. 条件解除：资源恢复/故障排除、Hold 授权解除（谁设谁解、设备不自解）。
5. 续跑调度：对账权威状态后，Spool 补发上报，调度器重新评估就绪 PJ（受剩余异常约束，如 Hold 批仍不启动）。
- 每一步幂等：重复收到"恢复"不产生副作用（如已 ONLINE 不再重复建链）。

### 5. 恢复期间的新事件
- 故障/断线期间又有新 CJ 上料到达：允许完成物理上料与本地建账，但作业是否启动受当前合成安全态约束（该启动才排队、否则就绪挂起）。
- 恢复后这些新批与存量批一起进入统一调度，按优先级/老化公平排（Day02）。

### 6. 兜底原则（不变）
- 任意组合都必须有定义分支；无法归类/多解/身份存疑→fail-safe 安全保持转 ManualInterventionRequired，绝不猜、绝不假恢复。
- 全程 E90 三不变式与分批守恒红线不破。
