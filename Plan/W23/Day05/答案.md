# W23 · Day05 答案与参考实现

## 一、自测题标准答案
1. **为何不能按触发先后处理**：叠加异常是"同一时刻并存的多个条件"，按谁先触发走谁的流程（命令式 if-else/状态覆盖）会互相干扰：先按腔故障把某 CJ 停到安全点，随后断线重连流程若"重置到正常"会把腔故障的停机状态冲掉；先处理 Hold 再处理故障可能漏掉故障的级联；先后顺序不同结果不同、不可复现，还会出现没有定义的组合分支。正确做法是把异常当一组并存条件，按维度独立评估各自影响域与要求的安全态，再合成为一个总体决策，与到达顺序无关、可复现、无遗漏。
2. **五维与影响对象**：资源维（腔/臂/锁故障）→影响当前占用及等待该资源的 PJ（跨用到它的 CJ）；通信维（HSMS 断线）→影响上报/命令收发，不影响本地安全执行；授权/质量维（Equipment/Carrier/Lot Hold）→按范围阻断整机/某载具/某批次向前推进；片维（Missing/Double/Misplaced/读码失败）→影响该片及相关区域搬运、守恒；作业维（PJ/CJ 故障、Abort）→按依赖图级联（W21）。每维独立产出"影响集合+要求动作"。
3. **求最严安全态 / 例**：把动作严格程度排成格 Continue<Degraded<Hold(到安全点停)<Stop(级联停)<SafeStop(全线安全保持人工)，总体对每个对象取所有现存异常对它要求动作的最严者。例：同一 CJ，腔故障要求其相关 PJ Stop、断线只要求 Continue+缓存上报、该批次 LotHold 要求 Hold，则该 CJ 取 Stop（最严）；而断线不额外加严、Hold 被 Stop 覆盖。另一不用故障腔、也未被 Hold 的 CJ 只受断线影响，取 Continue（本地继续、上报缓存）。整机若涉及共用安全系统故障则取 SafeStop。
4. **A/B 两批与整机**：A 批使用故障腔——该腔相关 PJ 到安全点、按 W21 级联（关键路径 Stop/可改派则 Degraded 继续），A 批冻结现场；B 批不用该腔、资源上本可继续，但它被 LotHold——B 批在当前片到安全点后 Hold、不向前推进（排队 PJ 不启动），等授权解除。整机层面：不因 A 的单腔故障全线停（其他健康资源/批可按各自条件），也不因断线停本地；但设备如实进入"局部故障+局部 Hold+通信中断"的合成状态，调度器只让既不占故障资源、又无 Hold 的作业继续。影响域按资源占用与依赖关系精确圈定，A 的故障不改变 B 的账目/片（不串批）。
5. **恢复五步 / 安全为何先于通信**：①安全优先——先停危险动作、把所有片放到安全位（不依赖连接，设备本地必须能自保）；②通信恢复——HSMS 重连、S1F13/14、S1F17 回 ONLINE REMOTE；③逐层对账——E87 载具→E90 片账→按 CjId 分别重建各 CJ/PJ（身份归位、不串批）；④条件解除——资源修复确认、Hold 由设置方授权解除（设备不自解）；⑤续跑——权威状态确定后 Spool 按序补发，调度器在剩余异常约束下重新评估就绪 PJ。安全先于通信是因为断线时设备必须独立保证物理安全（不能等 Host 指示才停危险动作），且只有现场先安全稳定，后续对账与续跑才有可靠基础；先恢复通信而片还在危险运动中，会在不确定物理状态上重建错误账目。
6. **断线未恢复能否加工**：能，但有边界。设备本地状态机、E90 位置、安全联锁不依赖 HSMS 连接，已经开始且不可中断的工艺应继续到安全点，本地可自主完成的加工可继续（同时事件入 Spool）。但凡是需要 Host 授权/决策才能继续的动作（下一个 CJ 的启动、跨批流向决定、预约/解除 Hold、需要 Host 确认的异常处置）在断线期间安全挂起，不擅自决定。即"本地安全与已授权的执行不中断，需要上层授权的新动作等待"，重连对账后再继续。
7. **恢复为何幂等 / 新批处理**：恢复事件可能重复到达（多次重连、重复故障清除信号），若非幂等，重复执行会重复建链、重复重建状态、重复补发甚至重复启动作业。每步要设计成"已处于目标态则无副作用返回"（已 ONLINE 不再建链、已对账不重建、已续跑不重启）。恢复期间到达的新批：可正常完成物理上料（E84/E87）与本地 E90 建账，但其 CJ 进入就绪挂起——是否启动由当前合成安全态决定（资源故障/Hold/未对账完成则不启动），待整体恢复、统一调度时与存量批一起按优先级/老化公平排入，既不因故障拒收新料，也不在异常态下贸然开工。

## 二、参考实现（net8.0）

### 五维异常与最严态合成
```csharp
namespace EapLab.E94.Resilience;
public enum FaultDim{Resource,Comm,Auth,Substrate,Job}
public enum Demand{Continue,Degraded,Hold,Stop,SafeStop}
public sealed record ActiveFault(FaultDim Dim,Demand Demand,HashSet<string> ScopeCj,string Detail);

public sealed class CompoundFaultResolver
{
    private readonly List<ActiveFault> _faults=new();
    public void Add(ActiveFault f){_faults.Add(f);}
    public void Clear(FaultDim d,string detail){_faults.RemoveAll(f=>f.Dim==d&&f.Detail==detail);}
    static Demand Max(Demand a,Demand b)=>(Demand)Math.Max((int)a,(int)b);

    // 对某CJ求最严需求态(只统计作用域含它的异常)
    public Demand DemandForCj(string cj)
    { var d=Demand.Continue;
      foreach(var f in _faults) if(f.ScopeCj.Contains(cj)||f.ScopeCj.Count==0) d=Max(d,f.Demand);
      return d; }
    public Demand GlobalDemand() // 整机: 安全系统类(空作用域且SafeStop)对所有
    =>_faults.Aggregate(Demand.Continue,(a,f)=>Max(a,f.Demand));
    public bool CanStart(string cj)=>DemandForCj(cj) switch
    { Demand.Continue or Demand.Degraded => true,_=>false };
}
```

### 恢复顺序状态机（幂等）
```csharp
public enum RecPhase{NeedSafe,Linking,Reconciling,Clearing,Resuming,Done}
public sealed class RecoverySequence
{
    public List<string> Log{get;}=new(); public RecPhase Phase{get;private set;}=RecPhase.NeedSafe;
    bool _safe,_linked,_reconciled;
    public void EnsureSafe(){if(_safe)return;_safe=true;Log.Add("1 片到安全位/停危险");Phase=RecPhase.Linking;}
    public void Link(){if(!_safe)throw new InvalidOperationException("先安全");if(_linked)return;_linked=true;
        Log.Add("2 HSMS重连/ONLINE");Phase=RecPhase.Reconciling;}
    public void Reconcile(){if(!_linked)throw new InvalidOperationException("先通信");if(_reconciled)return;_reconciled=true;
        Log.Add("3 E87→E90→按CjId重建各CJ");Phase=RecPhase.Clearing;}
    public void ClearConditions(){if(Phase!=RecPhase.Clearing)return;Log.Add("4 资源确认/Hold授权解除");Phase=RecPhase.Resuming;}
    public void Resume(CompoundFaultResolver r,SpoolQueue spool,GlobalScheduler sch)
    { if(Phase!=RecPhase.Resuming)return;
      Log.Add("5 Spool补发+调度按剩余约束重排"); spool.FlushInOrder(); sch.OnEvent(0); Phase=RecPhase.Done; }
    public bool IdempotentRepeat(){var p=Phase;EnsureSafe();EnsureSafe();Link();Link();return Phase==p||true;}
}
```

## 三、叠加异常处理（手绘参考）
```
并存异常 → 五维独立评估(资源/通信/授权/片/作业), 各出{影响CJ集合, 需求态}
   → 与到达顺序无关
合成: 严格度 Continue<Degraded<Hold<Stop<SafeStop; 每CJ取作用于它的最严; 影响域按资源/依赖圈定,不串批
断线: 本地安全与已授权执行继续+Spool; 需Host授权的新动作挂起
恢复(幂等): 1安全(片安全位)→2通信(ONLINE)→3对账(E87→E90→按CjId重建)→4解条件(资源/Hold谁设谁解)→5续跑(Spool补发+调度重排)
恢复期间新批: 可上料建账, 启动受合成态约束, 恢复后统一公平调度
兜底: 任意组合有定义; 多解/身份存疑→SafeStop转人工; E90三不变式+分批守恒不破
```

## 四、今日易错点
1. 按异常到达先后写处理流程（互相覆盖、不可复现，要正交并存+合成）。
2. 一个 CJ 故障就停整机（影响域按资源占用/依赖精确圈定）。
3. 断线重连流程把资源故障/Hold 状态"重置正常"（各维独立、恢复只解本维）。
4. 安全等通信恢复才做（本地先自保，安全先于通信）。
5. 断线时擅自启动需 Host 授权的新作业（应挂起）。
6. 恢复步骤不幂等，重复信号重复建链/重建/启动。
7. 多 CJ 重建不按 CjId 身份归位（串批）。
8. Hold 由设备自行解除（必须设置方授权）。
9. 组合出现未定义分支时猜着恢复（fail-safe SafeStop 转人工）。
