# W23 · Day01（周一）多 CJ 全局资源日历与统一调度器

> 建议时长：95 分钟。W22 跑通单批主链，本周进入真实 FAB 场景：多个 ControlJob 同时存在、共享设备的腔/臂/锁/LoadPort。今天建立设备级唯一的全局资源日历与统一调度器，让多 CJ 的 PJ 在同一时间轴上互不冲突地排布。

## 一、今日目标
1. 建立设备级 GlobalResourceCalendar：所有 CJ 的资源占用统一登记、区间互斥/容量。
2. 实现统一 GlobalScheduler：从多 CJ 收集就绪 PJ，按资源日历排到最早空隙。
3. 复用 W18 防死锁（资源全序申请、all-or-nothing 预留）并扩展到跨 CJ。
4. 区分 CJ 内依赖（DAG）与 CJ 间资源竞争两套关系。
5. xUnit 覆盖两 CJ 争腔、串行排布、跨 CJ 不冲突、Makespan 计算。

## 二、背景知识（先读，30 分钟）

### 1. 为什么必须设备级统一调度
- W18 的资源日历只在一个 PJ/CJ 内；真实设备上前一批没下、后一批已上，多个 CJ 的 PJ 会同时争用同一批物理资源（同一腔、唯一机械手、LoadLock）。
- 若每个 CJ 各排各的，会在同一时刻把同一资源分给两个 PJ（双占），或各自持有部分资源等对方（跨 CJ 死锁）。必须有一个设备级、跨所有 CJ 的唯一资源日历作为仲裁。

### 2. 全局资源日历模型（复用并放大 W18）
- 资源：腔（容量1）、机械手/臂（容量1）、LoadLock（容量1/门互斥）、Aligner、Buffer 槽位、LoadPort。
- 登记：占用区间 [start,end) + 资源 + 所属 CjId/PjId + 片 ID；容量 c 的资源允许 c 个区间重叠，否则冲突。
- 查询 earliestSlot(resource,dur,after)：在时间轴上找最早不冲突空隙。
- 预留 all-or-nothing：一个 PJ 需要多个资源（腔+锁+臂）时，要么全部在一致时段预留成功，要么一个都不占（不持有部分资源等其余，避免死锁）。

### 3. 统一调度循环
```
每个事件点(片完成/资源释放/新CJ到达/上料完成):
 1 从所有CJ收集"就绪PJ": CJ内依赖满足(DAG) + 输入片就位 + 无Hold
 2 对就绪PJ按调度策略排序(Day02细化优先级/老化)
 3 逐个尝试: 为其所需资源在全局日历找一致最早空隙
    成功→预留→到点启动; 失败(资源不足)→进等待队列, 不持有部分资源
 4 推进逻辑时钟到下一事件, 释放/占用, 重复
```

### 4. CJ 内依赖 vs CJ 间竞争
- CJ 内：DAG 控制依赖/片流依赖决定"同一批内谁先谁后、谁给谁片"（W20）。
- CJ 间：通常没有片流关系，只有**资源竞争**（以及 Host 给的批次优先级）。调度器把两类关系分开：先按 CJ 内 DAG 判断就绪，再在跨 CJ 的就绪集合里按资源/优先级排时间。

### 5. 关键指标（今天先算 Makespan/利用率）
- Makespan=一批/一组 CJ 从第一个动作到最后完成的总时长；瓶颈资源利用率=占用时长/总时长。
- 首片时间+（n-1）×节拍（W18）在多 CJ 下仍成立，但节拍由全局瓶颈决定。

### 6. 确定性与可复现
- 用逻辑时钟（事件点按时间全序），相同输入产出相同排程；同优先级 tie-break 用固定规则（CjId/PjId 字典序），避免随机导致不可复现的排程差异。
