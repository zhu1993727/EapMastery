# W23 · Day01 答案与参考实现

## 一、自测题标准答案
1. **各排各的问题 / 例子**：每个 CJ 只看自己的资源需求、看不到对方，就会在同一物理资源上重复安排。双占例子：CJ1 的 PJ_A 和 CJ2 的 PJ_X 都认为某刻 CH1 空闲，同时把片送进 CH1，机械/工艺冲突撞片。跨 CJ 死锁例子：CJ1 已预留 CH1 等 LoadLock，CJ2 已预留 LoadLock 等 CH1，两者各持一部分资源互等，全机卡死。根因是缺一个设备级、跨所有 CJ 的唯一资源仲裁者，局部最优导致全局冲突。
2. **冲突判定 / 容量 c**：日历为每个资源保存一串占用区间 [start,end)。新申请区间与该资源已有区间比较：时间重叠的占用数若达到该资源容量 c 即冲突。绝大多数资源（单腔、单臂、单锁）c=1，任何时间重叠都冲突；少数可并行资源（Buffer 多槽、多工位）c>1，允许至多 c 个区间同时重叠。判定即"重叠区间计数 < c"。
3. **earliestSlot 作用 / 输出**：给定资源、需要时长 dur、不早于 after，在该资源已有占用时间轴上找最早一段长度≥dur 的空闲空隙，返回这段空隙的开始时刻（以及结束=开始+dur）。它把"资源什么时候能用"量化，调度器据此把任务排到确定时间，而不是盲目"现在就上"。多个资源时要找让所有资源同时空闲的一致最早时刻。
4. **all-or-nothing 预留 / 防跨 CJ 死锁**：一个 PJ 常需同时占用多个资源（如 CH1+LoadLock+机械手）。all-or-nothing 指：只在能把这些资源在一致时间段**全部**预留成功时才一次性占用，任何一个拿不到就全部不占、进入等待（绝不先持有 CH1 再去等 LoadLock）。这样消除了"持有部分资源、等待被别人占用的其余资源"这一死锁必要条件（占有并等待），配合资源全序申请（永远按固定资源 ID 顺序申请），跨 CJ 也不会形成循环等待，从而避免死锁。
5. **CJ 内依赖 vs CJ 间竞争 / 分别处理**：CJ 内是 DAG 控制/片流依赖——决定同一批里 PJ 启动先后与片的流向（前驱不完后继不能就绪），是"能不能就绪"的问题；不同 CJ 之间一般没有片流关系，只有对共享物理资源的竞争和 Host 赋予的批次优先级，是"就绪了谁先用资源、排什么时候"的问题。调度器分两步：先在每个 CJ 内按 DAG+片就位判定哪些 PJ 就绪，再把所有 CJ 的就绪 PJ 放进同一个跨 CJ 集合，按资源日历与优先级统一排时间，两类关系不混为一谈。
6. **统一调度循环四步**：①收集——在每个事件点（片完成、资源释放、新 CJ 到达、上料完成）从所有 CJ 收集就绪 PJ（CJ 内依赖满足、输入片就位、无 Hold）；②排序——对就绪集合按调度策略排序（Day02 的优先级/老化，同级固定 tie-break）；③预留——逐个为 PJ 所需多资源在全局日历找一致最早空隙，成功则一次性预留、到点启动，失败则进等待队列且不持有部分资源；④推进——逻辑时钟走到下一事件，释放到期资源、执行占用，回到①。
7. **确定性原因 / tie-break**：生产排程必须可复现、可审计、可与 Host 核对——同样的输入（CJ、工艺时长、到达时刻）无论跑几遍、在谁的机器上都应得到相同排程，否则现场无法复现问题、无法解释"为什么先做它"。因此用逻辑时钟、不依赖随机/线程调度时序；当多个就绪 PJ 优先级相同、时间也相同时，用固定的全序 tie-break（如先比 CjId 再比 PjId 的字典序）决定先后，保证唯一确定结果。

## 二、参考实现（net8.0）

### 全局资源日历
```csharp
namespace EapLab.E94.Sched;
public sealed record ResId(string Kind,string Name){public override string ToString()=>$"{Kind}/{Name}";}
public sealed record Interval(double Start,double End,string CjId,string PjId)
{ public bool Overlap(double s,double e)=>s<End && Start<e; }

public sealed class GlobalResourceCalendar
{
    private readonly Dictionary<ResId,List<Interval>> _book=new();
    private readonly Dictionary<ResId,int> _cap=new();
    public void Declare(ResId r,int capacity=1){_book[r]=new();_cap[r]=capacity;}

    public bool Overlaps(ResId r,double s,double e)
    { var list=_book.GetValueOrDefault(r); if(list==null)throw new ArgumentException(r.ToString());
      return list.Count(x=>x.Overlap(s,e))>=_cap[r]; }

    public double EarliestSlot(ResId r,double dur,double after)
    { var list=_book.GetValueOrDefault(r,new()).OrderBy(x=>x.Start).ToList();
      double t=after;
      foreach(var iv in list)
      { if(iv.End<=t)continue; if(iv.Start>=t+dur)return t; if(iv.End>t)t=iv.End; }
      return t; }

    // 多资源一致最早时刻(all-or-nothing)
    public double? EarliestCommon(IEnumerable<ResId> rs,double dur,double after)
    { double t=after; bool moved;
      do{ moved=false; foreach(var r in rs)
        { var e=EarliestSlot(r,dur,t); if(e>t){t=e;moved=true;} } }while(moved);
      return t; }

    public bool TryReserve(IEnumerable<ResId> rs,double s,double dur,string cj,string pj)
    { var set=rs.ToList(); double e=s+dur;
      if(set.Any(r=>Overlaps(r,s,e)))return false;             // 有冲突, 一个都不占
      foreach(var r in set)_book[r].Add(new Interval(s,e,cj,pj));
      return true; }
    public double Utilization(ResId r,double horizon)
    =>_book[r].Sum(x=>Math.Min(x.End,horizon)-x.Start)/horizon;
}
```

### 统一调度器
```csharp
public sealed record ReadyPj(string CjId,string PjId,ResId[] Res,double Dur,double ReadyAt,int Prio,long Seq);
public sealed class GlobalScheduler
{
    private readonly GlobalResourceCalendar _cal; private double _now;
    private readonly List<ReadyPj> _waiting=new();
    public List<(double t,ReadyPj pj)> Plan{get;}=new();
    public GlobalScheduler(GlobalResourceCalendar cal,double now=0){_cal=cal;_now=now;}

    public void Admit(IEnumerable<ReadyPj> pjs)
    { _waiting.AddRange(pjs); Schedule(); }
    public void OnEvent(double at){_now=at;Schedule();}

    void Schedule()
    { var ordered=_waiting.OrderByDescending(x=>x.Prio).ThenBy(x=>x.ReadyAt).ThenBy(x=>x.CjId).ThenBy(x=>x.PjId).ToList();
      foreach(var p in ordered.ToList())
      { // 资源全序申请(按ResId排序), all-or-nothing
        var res=p.Res.OrderBy(r=>r.ToString()).ToArray();
        var start=_cal.EarliestCommon(res,p.Dur,Math.Max(_now,p.ReadyAt))!.Value;
        if(_cal.TryReserve(res,start,p.Dur,p.CjId,p.PjId))
        { Plan.Add((start,p)); _waiting.Remove(p); } } }
}
```

## 三、全局调度结构（手绘参考）
```
多CJ ──各自DAG判就绪(依赖+片就位+无Hold)──► 跨CJ就绪集合
        │
   排序(优先级/就绪时间/固定tie-break)
        │
   逐个: 资源按ID全序 → EarliestCommon找一致最早空隙
        → all-or-nothing预留(拿不齐一个不占,进等待) → 到点启动
        │
   逻辑时钟推进 → 释放/占用 → 重排
全局唯一日历: 区间[start,end)+资源+CJ/PJ/片; 容量c; 重叠计数<c不冲突
关系分离: CJ内=DAG片流(能否就绪); CJ间=资源竞争+优先级(何时用)
指标: Makespan; 瓶颈利用率; 确定性可复现
```

## 四、今日易错点
1. 每个 CJ 各排各（双占/跨 CJ 死锁，必须设备级唯一日历）。
2. 多资源先占一个再等其余（持有并等待→死锁，要 all-or-nothing）。
3. 申请资源不按固定全序（循环等待风险，按 ResId 排序申请）。
4. 混淆 CJ 内 DAG 依赖与 CJ 间资源竞争（先判就绪、再排时间）。
5. 容量一律当 1（Buffer 等可 c>1，重叠计数<c 即可）。
6. EarliestCommon 只看单资源（多资源要找共同空闲、迭代收敛）。
7. 排程依赖随机/线程时序（要逻辑时钟+固定 tie-break，可复现可审计）。
8. 等待中的 PJ 持有部分资源（拿不齐必须全部释放、纯等待）。
