# W23 · Day06 答案与参考实现

## 一、自测题标准答案
1. **为何只在事件点改状态 / 好处**：离散事件系统在两个相邻事件之间没有任何状态变化（没有任务到达、没有资源释放、没有片完成），连续推进时间没有意义。只在事件点改状态，用逻辑时钟跳到下一事件，仿真不必逐秒空转、效率高；且状态变化都由确定事件触发、事件按时间戳+固定 tie-break 全序处理，相同输入必然得到相同结果（可复现、可回归、好调试），也便于精确统计每段忙碌/等待时长。
2. **指标与口径**：Makespan=首个事件到最后一片下料的总时长；节拍 beat=稳态相邻成品产出间隔（≈瓶颈工序时长/该工序并行度）；WPH=3600×成品数/有效生产时长；资源利用率=该资源累计忙碌时长/仿真时长（分别统计腔/臂/锁/口，最高者为瓶颈）；WIP=任一时刻在设备内+在口未下料的片数（统计平均与峰值）；等待时长=每个 PJ 从就绪到实际开工的间隔（平均/最大，验证有界无饥饿）；守恒终验=结束时片全部成品下料或显式 Scrap/Partial、设备内空、全局 ID 集合守恒、分批不混。
3. **非瓶颈为何决定不了节拍 / 对比证明**：系统产出被瓶颈（利用率最高、处理最慢、排队堆积的资源）限制，非瓶颈本来就有空闲，给它提速只会增加它的空闲、不会让成品更快（产品在瓶颈前照样排队）。对比实验：保持其他不变，仅把某非瓶颈腔速度提高 20%，Makespan/WPH 应几乎不变；把瓶颈腔提速 20%（或增加其并行度），Makespan 明显下降、WPH 上升。两组对比即证明"只有瓶颈决定系统节拍"（TOC 约束理论），优化要投在约束资源上。
4. **hot lot 会否被普通批反超**：在老化机制下，hot lot 静态优先级远高于普通批，刚到达时老化都≈0，有效分=静态分，hot lot 必然排在普通批前先调度；普通批要靠等待累积老化增益，需要足够长时间才能把有效分追上来，而 hot lot 通常很快被调度完成、几乎不等待，因此不会被后来的普通批反超。老化只保证"等得足够久的低优任务最终被调度"，不会让刚到的普通批立刻压过高优急件——紧急度（静态）与公平（老化）通过有效分同时体现。
5. **故障在瓶颈 vs 非瓶颈对 WPH 影响**：瓶颈本就满负荷、没有富余产能，它故障的每分钟都直接减少整机产出（没有其他资源能补回），并让上游堆积、下游断供，WPH 近似按故障时长线性损失；非瓶颈资源有空闲余量，故障期间原本就排不满，可由同型资源/恢复后追赶消化，对系统产出影响小甚至为零。所以设备可靠性/冗余/快速恢复应优先保障瓶颈资源，故障排程也要优先把瓶颈上的任务改派出去。
6. **结束守恒终验项**：①全局集合守恒——所有上料片 ID=已下料成品 ∪ 显式 Scrap/Partial（带明细），无不明去向；②设备清空——臂/锁/腔/Buffer/交接位无 LeftInside；③载具——在口载具状态与台账一致、无未闭合交接；④分批不混——每个 CJ 片集合守恒、不同 CJ 无交叉错放、谱系完整；⑤任务闭环——所有 PJ/CJ 到终态（Completed/Aborted 且有续跑闭环），无悬挂在 Executing/Pausing 的作业；⑥账目——SourceMap 对 ResultMap、分档/回流数量与记录一致。
7. **最大等待无界说明什么 / 怎么修**：说明存在饥饿——某些任务因持续被高优任务插队或资源被长期占用，等待时间可无限增长，调度不公平、可能导致批次超时报废。修法：①引入/调强老化（等待按区间提升有效分，且老化增益最终可超过任意静态优先级，保证等待有上界）；②设 maxWait 阈值，超时强制提权并告警；③检查并消除优先级反转（优先级继承，Day02）；④审视瓶颈容量（饥饿常因瓶颈长期拥塞，提升瓶颈/增加并行度/改派）；⑤用最大等待指标做回归门禁，超过设计上界即判调度不合格。

```csharp
namespace EapLab.E94.Sim;
public sealed class SimEvent: IComparable<SimEvent>
{ public double At;public long Seq;public Action Run=()=>{};
  public int CompareTo(SimEvent? o)=>o is null?1:At!=o.At?At.CompareTo(o.At):Seq.CompareTo(o.Seq); }

public sealed class DiscreteEventSim
{
    private readonly PriorityQueue<SimEvent,SimEvent> _q=new(); long _seq; public double Now;
    public void Schedule(double at,Action run){var e=new SimEvent{At=at,Seq=++_seq,Run=run};_q.Enqueue(e,e);}
    public void RunUntil(double horizon)
    { while(_q.Count>0){_q.TryPeek(out var e,out _); if(e.At>horizon)break;
        _q.Dequeue();Now=e.At;e.Run();} Now=horizon; }
}

public sealed class PerfMetrics
{
    private readonly Dictionary<string,double> _busy=new();
    public List<double> CompletionTimes{get;}=new(); public List<double> Waits{get;}=new();
    private readonly List<(double t,int wip)> _wipSamples=new();
    public void AddBusy(string res,double sec){_busy[res]=_busy.GetValueOrDefault(res)+sec;}
    public void Complete(double t)=>CompletionTimes.Add(t);
    public void Wait(double w)=>Waits.Add(w);
    public void SampleWip(double t,int wip)=>_wipSamples.Add((t,wip));
    public double Makespan=>CompletionTimes.Max();
    public double Beat=>CompletionTimes.Count<2?0:
        (CompletionTimes[^1]-CompletionTimes[0])/(CompletionTimes.Count-1);
    public double Wph(double horizon)=>3600.0*CompletionTimes.Count/horizon;
    public double Util(string res,double horizon)=>_busy.GetValueOrDefault(res)/horizon;
    public string Bottleneck(double horizon)=>_busy.MaxBy(kv=>kv.Value).Key;
    public double MaxWait=>Waits.DefaultIfEmpty().Max();public double AvgWait=>Waits.DefaultIfEmpty().Average();
    public double AvgWip=>_wipSamples.Average(x=>x.wip);public int PeakWip=>_wipSamples.Max(x=>x.wip);
    public bool NoStarvation(double bound)=>MaxWait<=bound;
}
```

```csharp
public sealed class FabShiftSim
{
    public const double H=28800;
    public static (PerfMetrics m,List<string> log) Run()
    {
        var sim=new DiscreteEventSim(); var cal=BuildCalendar(); var sched=new GlobalScheduler(cal);
        var led=new MultiCarrierLedger(); var m=new PerfMetrics(); var log=new List<string>();
        // 普通批到达(每1800s), hot lot, rework批, 分档批 —— 教学用循环示意
        for(double t=0;t<H;t+=1800) sim.Schedule(t,()=>ArriveNormal(sched,led,sim,m));
        sim.Schedule(9000,()=>ArriveHot(sched,sim,m));
        sim.Schedule(7000,()=>FaultChamber(7000,600,sim,log));
        sim.Schedule(15000,()=>HsmsDown(15000,300,sim,log));
        sim.Schedule(20000,()=>LotHold(20000,240,sim,log));
        sim.RunUntil(H); FinalConservation(led,log);
        return(m,log);
    }
    static void ArriveNormal(GlobalScheduler s,MultiCarrierLedger l,DiscreteEventSim sim,PerfMetrics m){/*建CJ/就绪入调度*/}
    static void ArriveHot(GlobalScheduler s,DiscreteEventSim sim,PerfMetrics m){/*高优Prio*/}
    static void FaultChamber(double at,double dur,DiscreteEventSim sim,List<string>log)
    =>log.Add($"{at}: 腔故障,改派; {at+dur}:恢复");

    =>log.Add($"{at}:断线,本地继续+Spool;{at+dur}:重连对账");

    =>log.Add($"{at}:LotHold到安全点;{at+dur}:授权解除续跑");
    static GlobalResourceCalendar BuildCalendar(){/*声明3腔/双臂/2锁/口*/return new();}
    static void FinalConservation(MultiCarrierLedger l,List<string>log)
    =>log.Add("终验: 全局守恒/设备空/分批不混/PJ-CJ终态闭环");
```

## 四、8h 剖面流程（手绘参考）
```
事件队列(时间戳+Seq全序) → 弹事件改状态 → 统一调度(全局日历+老化) → 排新事件
上料重叠(多口) → 多腔并发(瓶颈节拍) → Merge/Split/Bin/Rework → 跨PJ/CJ交接 → 下料
中途: 腔故障(改派)/断线(本地继续+Spool,重连对账)/Hold(到安全点,解后续)
统计: Makespan/beat/WPH/利用率(找瓶颈)/WIP/等待(无饥饿)/守恒终验
对比: 只提速瓶颈才提升产出(TOC); 老化保证最大等待有界; 结果确定可复现
```

## 五、今日易错点
1. 用墙钟/逐秒推进（应用逻辑时钟事件驱动，可复现高效）。
2. 同刻事件无 tie-break（结果随机不可复现）。
3. 指标口径混乱（beat≠Makespan、WPH 分母用错、利用率不按资源分）。
4. 优化非瓶颈还期待提升产出（只有瓶颈决定节拍，要做对比验证）。
5. hot lot 被老化的普通批反超（静态优先级设计要保证急件先做）。
6. 故障不区分瓶颈/非瓶颈，平均用力（保障与改派优先瓶颈）。
7. 仿真结束不做守恒终验、设备内残留片无人查。
8. 最大等待无界还认为正常（饥饿，要老化+maxWait+瓶颈治理）。
9. 分档/回流片在指标里重复计数（片按唯一 ID，加工次数另计）。
