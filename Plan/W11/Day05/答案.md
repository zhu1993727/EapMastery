# W11 · Day05 答案

## 一、自测题标准答案
1. **五个超时定时器 / 为何 T_compt 最保守**：T_req（就绪后等请求）、T_es（请求后等许可 ES）、T_busy（许可后等 BUSY）、T_compt（BUSY 后等完成 COMPT）、T_reset（完成后等信号逐级复位），另有 T_valid（等 VALID 稳定有效）。T_compt 最保守是因为它处在**物理动作正在进行**的阶段：BUSY 已置说明小车正在下放或抓取 FOUP，此时迟迟不 COMPT 意味着盒可能处于半空、半夹、半放的最危险中间位置，任何贸然撤销信号、重试或复位都可能导致掉盒/碰撞，所以不能像空闲侧超时那样回 Idle 重来，必须立即停止、保持夹持、报警并由人工到场确认盒的真实位置后再处理。越靠近"盒被双方交接、归属不确定"的时刻，处置越保守。

2. **异常状态机 / 三态区别**：正常路径 Idle→WaitGrant(等ES)→WaitBusy(等BUSY)→Transferring(执行中)→WaitComplete(等COMPT/复位)→Idle。异常态：
   - **AbortSafe（安全中止）**：由握手逻辑矛盾或执行前/执行中的超时触发（如许可超时、方向矛盾、T_compt），主动中止流程、停止运动、保持夹持，回到需要确认的安全态；侧重"流程无法继续，有序中止"。
   - **SafeFreeze（安全冻结）**：由 VALID 丢失、信号闪断、线缆/电源瞬时问题触发，信号变得不可信，立即冻结一切动作和握手推进、维持当前机械姿态，等信号恢复后评估；侧重"输入不可信，原地冻住"。
   - **EStopHold（急停保持）**：由 ESTOP 安全回路触发，最高优先级，立即断电级停止所有轴、失电夹紧/制动，必须人工物理复位急停才能退出；侧重"安全回路动作，最高等级保持"。
   三者共同点是停止+保持+报警，区别在触发源（流程异常/信号不可信/安全回路）和恢复门槛（逻辑确认/信号恢复评估/人工急停复位），EStopHold 门槛最高。

3. **COMPT 到了但传感器不符为何不能推进**：COMPT 是小车单方声明"我完成了"，而设备自己的在位/坐实传感器是独立的客观事实来源。两者不一致说明出现了未预期情况：小车以为放稳了但设备没检测到盒在位（可能放偏/滑落/没放到位），或小车以为取走了但盒还在口上（可能没夹紧、盒卡住）。此时 FOUP 的真实归属和位置不确定，是最危险的状态。若继续推进（撤信号、机构回 Home、关门、E87 迁移状态），可能挤压、刮擦、掉盒，或让 MES 账目与实物不符。正确做法是保持当前安全姿态、不推进不复位、记录信号快照、立即报警，由人工确认盒到底在哪、被谁持有，再决定补救。原则：单方声明与独立事实冲突时，以安全保守为准，绝不"将错就错"。

4. **ESTOP 流程 / 为何不自动续接**：流程见学习内容（触发→安全回路动作、停轴、失电夹持制动→状态机进 EStopHold 冻结握手、记录信号快照→声光报警并经 SECS 上报 Host→人工到场确认盒位置与夹持、排除原因、复位急停→人工选择继续/手动取下/回退，确认后回 Idle）。复位后不自动续接是因为：急停时物理动作被瞬间打断，FOUP 可能停在任意中间位置、夹持状态未知、引起急停的根因（人/障碍/故障）未必已消除，软件无法可靠判断当前物理态势是否安全；自动续接可能在盒半悬、有人介入、机构未复位的情况下继续动作，极危险。必须由人现场确认物理世界安全后，再显式决定如何恢复，这是功能安全的基本要求。

5. **BYPS 时自动握手工作吗 / 为何同步 E87**：Bypass 旁路期间自动四相握手**不工作**——自动交接逻辑被禁用，Load Port 改由现场人工操作放/取 FOUP（检修、调试或自动系统故障时用）。手动放/取后必须同步 E87 的原因：Host/MES 的载具账目（哪个口有哪个盒、什么状态、属于哪个 Lot）是靠 E87 状态迁移和 SECS 上报维护的，旁路只绕过了 E84 自动物理握手，并不会自动更新这套逻辑账目；若人工实际放/取了盒而 E87 不同步，就会出现"现场有盒、系统显示空口"或反之的账实不符，后续派工、取片、下料全部错乱（混批、丢批）。因此旁路状态要显著上报 Host，手动操作后人工或半自动把 CarrierID、载具状态、SlotMap 同步进 E87，退出旁路前还要核对物理与逻辑一致。

6. **三类可恢复性 / 禁止自动重试判据**：
   - 可自动重试：尚未发生实质物理交接、处于空闲侧的超时（T_req/T_es/T_busy），信号撤干净回 Idle 即可重新发起，但限次（≤2 次），超限升级人工，防死循环。
   - 需人工确认恢复：动作进行中被打断（T_compt、VALID 闪断、瞬时掉电），盒可能在中间位，软件给出当前状态和建议，由人确认后续接或回退。
   - 不可自动恢复：硬件机构故障、传感器矛盾、急停，锁定报修，人工维修复位后解锁。
   - **禁止自动重试通用判据：凡是无法确定 FOUP 当前被谁持有、处于什么物理位置/夹持状态的时刻（归属不确定），一律安全保持并交人工，禁止自动重试或自动复位。** 因为自动重试的前提是"物理状态已知且可安全回到确定起点"，归属不确定时这个前提不成立，重试可能掉盒。

7. **VALID 闪断 200ms 恢复能否当没发生**：不能。VALID 无效期间总线上的信号组合被定义为不可信，即使 200ms 后恢复，这期间对方可能正处在信号切换瞬态、受干扰毛刺或线缆接触不良的窗口，设备无法确认在闪断瞬间物理动作推进到了哪一步、对方状态机走到了哪一拍。正确处理：VALID 一丢失立即 SafeFreeze 冻结动作和握手推进、保持当前姿态并计时/记录；恢复后不自动续拍，而是重新做信号一致性核对（双方当前信号/状态是否仍匹配、盒位置传感器是否正常、处于握手哪一拍），若能确认仍停在某个明确的安全拍且双方一致，可在严格条件下从该拍续接，否则按"归属不确定"交人工确认。短暂不等于无害，安全接口对信号有效性采取"宁可信其有问题"的保守策略。

## 三、两个场景推演（参考答案）
### 场景1：BUSY 后 30 秒无 COMPT（T_compt 超时）
1. BUSY 已置、小车正在下放/抓取，T_compt 计时到点未收到 COMPT。
2. 立即：停止一切可停运动、夹持/制动保持（绝不能松爪），状态机转 AbortSafe/EStopHold 级，冻结握手不复位。
3. 记录快照：时刻、TR_REQ/ES/BUSY/COMPT/VALID 电平、在位/坐实传感器值、小车位置反馈。
4. 高级声光报警，经 SECS 向 Host 上报交接故障事件，禁止该口再接新任务（置不可用）。
5. 不自动重试、不自动复位——此时盒可能半悬/半夹，归属不确定。
6. 人工到场确认 FOUP 位置和夹持，安全取出或辅助完成，排除卡滞原因、复位机构后手动置回 Idle 并解锁。
### 场景2：交接中 VALID 闪断 200ms 又恢复
1. VALID 下降沿瞬间：不解读任何信号，立即 SafeFreeze，停止推进、保持当前机械姿态和夹持，启动记录。
2. 200ms 后 VALID 恢复：不自动继续，进入"一致性重核对"。
3. 核对：当前处于哪一拍、双方现有信号是否仍匹配该拍、盒在位/位置传感器是否稳定正常、闪断期间有无信号非法跳变。
4. 若确认双方都停在同一明确安全拍、盒位置确定且无动作发生：可在人工/上位确认后从该拍续接（教学上保守起见仍建议人工确认一次）。
5. 若核对发现拍不一致、信号有非法跳变、或盒位置不确定：按归属不确定处理，安全保持+人工到场。
6. 记录闪断次数，频繁闪断说明线缆/接插件/干扰有隐患，应安排检修，不能因每次都"自己恢复"而忽视根因。

## 五、今日易错点
1. 所有超时都一律回 Idle 重试（动作中超时最危险，必须保持+人工）。
2. COMPT 与传感器矛盾时信 COMPT（必须以独立传感器客观事实为准，安全保守）。
3. ESTOP 复位后自动接着干（物理态势未知，必须人工确认）。
4. 以为 Bypass 只是物理手动、不影响系统账目（必须同步 E87，防账实不符）。
5. VALID 闪断时间短就忽略（不可信窗口内状态不明，必须冻结+重核对）。
6. 自动重试不限次（会死循环抖动，应限次并升级）。
7. 区分不清 AbortSafe/SafeFreeze/EStopHold（触发源和恢复门槛不同）。
8. 忘记在异常时记录信号快照（没有快照无法复盘盒在交接哪一步出问题）。
9. 归属不确定时还尝试自动复位/重试（最高危，禁止）。
