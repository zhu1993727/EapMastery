## 四、W12 预热：E87 Carrier Management（30 分钟）

### 1. E87 是什么 / 解决什么问题
- E87 = SEMI E87 **CMS Carrier Management Standard（载具管理标准，CMSD Carrier Management System）**，通过 SECS-II（GEM/OSS）管理载具（FOUP/Reticle Pod）在设备上的**逻辑生命周期**：载具预约、安装/就位、装载确认、卸载、移除的全过程状态，以及 CarrierID 与 Load Port、Slot Map、批次（Lot）的绑定校验。
- E84 管"盒子物理怎么被天车放上来/取走"（硬线），E87 管"这个盒子在系统里是什么状态、是谁、能不能加工、能不能走"（SECS 软件）。E84 完成是 E87 状态迁移的物理触发源。

### 2. E87 的核心管理对象
- **Carrier（载具/FOUP）**：载具对象，有 CarrierID、所在 LoadPort、状态、载具类型。
- **Load Port（装载口）**：载具工位，一个设备多个口，每个口有自己的状态。
- **CarrierID（载具标识）**：通过 RFID/条码/人工读取，是绑定 Lot、配方、槽位的关键。
- **Slot Map（槽位图，E90 紧密配合，W14 详讲）**：载具内 25 槽哪些有基板。
- **Reservation（预约/保留）**：Host 预先指定某个 Load Port 预期要上某个 CarrierID，上料时校验，防上错料。

### 3. Carrier 状态机全貌（先建立框架，W12 逐态精讲）
E87 用一组并行/关联状态描述载具，最核心的是 **Carrier 状态迁移**（教学主线，精确状态名以 E87 原文为准）：
```
(载具不在口) NOT_INSTALLED/ABSENT
   │ 天车 E84 Deposit 放盒、口检测到就位
   ▼
INSTALLED（已安装/已就位，读到物理在位，尚未确认ID/授权）
   │ 读到 CarrierID、Host 校验预约/授权
   ▼
LOADED（已装载/已确认，可以被访问/加工，门可开、可取片）
   │ 加工完成、准备下料
   ▼
UNLOADED（已卸载/准备移除，加工访问结束，等待取走）
   │ 天车 E84 Pickup 取走、在位传感器变空
   ▼
(移除) NOT_INSTALLED/ABSENT
```
- 还有几条横切状态/标志：**Reservation 预约状态**（该口是否被 Host 预约、预期哪个 ID）、**Verification 校验结果**（实际上料 ID 与预约 ID 是否一致，上错料要 Hold/拒绝）、Load Port 自身可用性状态。
- 异常分支：ID 读不到、ID 与预约不符、载具被 Hold、口故障等，都有对应拒绝/挂起迁移（W12 Day04/05 讲）。

### 4. E87 用哪些 SECS 消息（先混脸熟，W12 细讲）
- 主要走 E39 OSS 对象服务（S14/S15/S16）操作 Carrier/LoadPort 对象（这也是为什么 W09/W10 先学 OSS），也可用传统 GEM 事件/远程命令。
- 典型交互：设备检测就位→发对象事件/CE 报告"Carrier Installed"+CarrierID→Host 校验并下"装载授权/预约确认"→设备迁 LOADED 并上报；下料时 Host 下发卸载指令→设备迁 UNLOADED→配合 E84 取走→上报移除。
- 关键：**状态迁移由物理事件 + Host 授权共同驱动，不是设备单方面说了算**（和 E84 双边互锁思想一脉相承，只是搬到软件层）。

### 5. E84/E87/E90 三层再确认
```
E84 物理层：硬线握手放/取 FOUP（动作安全）
E87 逻辑层：Carrier 状态机 + ID 绑定 + 预约校验 + Host 授权（账本/准入）
E90 位置层：SlotMap/基板位置跟踪（盒里货）
W12 学 E87，W13 做 E84+E87 自动上料综合，W14/W15 学 E90。
```
