# W11 · Day07 答案

## 一、W11 自测题（10 题）标准答案

### 1. 为何用硬线不用 TCP / 故障安全
物理交接是硬实时、不可逆动作，要求延迟确定（微秒~毫秒）、不依赖操作系统调度和网络、断电死机也安全。TCP 报文有调度/拥塞/重传不确定性，软件栈可能崩溃，无法承担安全互锁；并行硬线电平直达安全回路，配合光耦隔离、失电夹紧/制动、VALID 门控，在断线/掉电/死机时自动回到"停止并保持夹持"的安全态（fail-safe），动作必须双方信号持续满足才进行。一句话：动作安全靠硬线确定与故障安全，信息管理才走网络。

### 2. 三组信号方向
- 设备→小车：CS（系统就绪）、ES（本拍交接许可）、HO0/HO1（握手节拍位）。
- 小车→设备：SS（搬运系统就绪）、VR（小车就绪）、TR_REQ（交接请求）、BUSY（执行中）、COMPT（完成）、CONT（继续）。
- 共用：VALID（信号有效）、ESTOP（急停）、BYPS（旁路手动）。

### 3. CS vs ES / 三信号顺序
CS 是系统级长期就绪（这个口能不能用，故障/离线则 OFF），ES 是本次交接本拍的动态许可（机构到位才 ON），CS 是 ES 的前提。顺序：TR_REQ（请求）→设备置 ES（许可）→BUSY（执行中）→COMPT（完成）→逐级复位。

### 4. 四相握手 / HO 位
四相握手=请求→应答→执行→完成→复位的异步互锁节拍，每拍都"看到对方信号稳定再推进自己信号"，双方速度不同也不丢拍。HO0/HO1 是握手编码/翻转位，用来标记"这是新的一拍"、区分上一拍残留信号，保证严格交替、防抢拍丢拍。

### 5. Deposit 六阶段与三个互锁点
空闲→①小车就位发 TR_REQ→②设备确认空位置 ES 许可→③小车 BUSY 下放→④COMPT 放稳、设备传感器确认坐实→⑤逐级复位、设备承接→⑥E87 转 LOADED。三个关键互锁点：①小车没看到 ES 绝不下放（防掉盒）；②BUSY 期间设备锁定机构不动（防碰撞）；④COMPT 后必须设备自身在位/坐实传感器确认才承接（防没放稳）。

### 6. Pickup 最大不同 / 逻辑先于物理
最大不同在阶段2：Deposit 设备空口承接基本不动，Pickup 设备必须先主动把盒松夹/下降/开门送到交接位才置 ES（备货方是设备）；COMPT 后 Deposit 确认在位 ON、Pickup 确认在位 OFF。下料"逻辑先于物理"：上料是盒子先物理来再建逻辑身份（物理→逻辑），下料必须先有 E87/Host 下料许可（加工完成、未 Hold、有搬运任务）才允许物理交出，否则在制盒被误取会账实不符。

### 7. 五个超时 / T_compt 最保守原因
T_req 等请求、T_es 等许可、T_busy 等 BUSY、T_compt 等完成、T_reset 等复位（另 T_valid）。T_compt 处于 BUSY 物理动作进行中，盒可能半悬半夹、归属不确定，贸然撤信号/重试会掉盒，故直接安全保持+人工，不自动重试；越靠近空闲侧的超时越轻（回 Idle 即可）。

### 8. COMPT 与传感器不符
COMPT 是小车单方声明，设备在位传感器是独立客观事实，两者不一致说明盒真实位置/归属不明（放偏、滑落、没夹紧、卡住）。必须保持当前姿态、不推进不复位、记录信号快照、报警交人工，绝不能将错就错关门/回 Home/迁移 E87，避免挤压掉盒和账实不符。

### 9. ESTOP vs BYPS / 恢复区别
ESTOP 是异常紧急停止：安全回路动作、立即停轴、失电夹持、进 EStopHold，必须人工到场排除原因并物理复位急停、确认盒安全后才恢复，不自动续接。BYPS 是有意切手动/检修：自动握手禁用、人工操作，退出时要机构回 Home、核对物理与 E87 账目一致（手动放/取也要同步载具状态），才回 Idle 恢复自动。

### 10. 唯一写者 / 步进时钟
唯一写者：每根物理信号线只有一个驱动源，代码强制所有者可写对方只读，防止自己给自己发信号的假握手、职责与真实 I/O 点表一致、异常可唯一定位。步进时钟：用逻辑时间手动 Tick 代替真实线程/Delay，消除调度竞态，使握手时序确定、可复现、可单步、可精确触发超时，xUnit 不需真实等待，这是协议/PLC 逻辑仿真的标准做法。

## 三、E87 预热补充（为 W12 打底）
1. **E87 定位**：载具管理标准（CMS），用 SECS（多走 E39 OSS 的 S14/S15/S16）管理 FOUP 的逻辑生命周期与准入，是 E84 物理交接之后的"账本和门卫"。
2. **四态主线**：NOT_INSTALLED(不在口)→INSTALLED(物理就位待确认)→LOADED(确认授权可加工)→UNLOADED(加工完待移除)→取走回 NOT_INSTALLED；迁移由物理事件+Host 授权共同驱动。
3. **预约防错料**：Host 先预约某口预期 CarrierID，上料读到实际 ID 要比对，不符则 Hold/拒绝，防止上错 FOUP 造成混批——这是先进 FAB 防错的关键。
4. **和 E90 分工**：E87 管"盒子"整体状态和准入，E90 管盒内每片基板的槽位位置（SlotMap），W14/W15 学。
5. **和 W09/W10 衔接**：Carrier/LoadPort 就是 OSS 对象类型，状态迁移用 W10 的通用状态机框架实现，事件走 S16F1，命令走 S15F9，W12 Day06 直接复用 OSS 代码资产。
6. **关键认知**：E84 是双边硬互锁，E87 是双边软件协同（设备报事件、Host 授权、设备再迁移），都不是单方面说了算，安全与一致思想一脉相承。

## 四、W11 全周易错点汇总
1. 把 E84 当成又一种 SECS 消息（实为并行硬线，不走 TCP/编码）。
2. 混淆 CS/ES、Deposit/Pickup 方向、在位 ON/OFF 完成判据。
3. TR_REQ 当直接动作（必须等 ES 许可）；BUSY 期间设备动机构。
4. 只信 COMPT 不看自己传感器；信号同时全撤不走四相握手。
5. VALID 无效/闪断仍读信号动作；不去抖采信毛刺。
6. 动作中超时想自动重试（归属不确定必须安全保持+人工）。
7. ESTOP 后自动续接；BYPS 手动后不同步 E87 账目。
8. 下料不看 Host 许可就交盒（逻辑先于物理）。
9. 信号总线多个写者；用真实线程导致时序不可复现。
10. 把 E84 完成等同 E87 LOADED（物理就位≠逻辑状态，需读 ID+授权）。
