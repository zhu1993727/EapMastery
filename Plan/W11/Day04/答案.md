# W11 · Day04 答案

> 时序为教学推演，精确时序以 SEMI E84 原文和设备 I/O 时序表为准。

## 一、自测题标准答案
1. **Pickup 六阶段 / 与 Deposit 最大不同**：
   - 阶段0 空闲：口上有盒待取，CS/SS 就绪。
   - 阶段1 请求：空车到位→VR=ON→TR_REQ=ON（请求 Pickup，HO 位标记新拍）；设备检查口上有盒、E87 逻辑允许下料、无异常。
   - 阶段2 备货并许可：**设备先动作**——把 FOUP 松夹/下降/开门送到可取交接位，再 ES=ON 许可。
   - 阶段3 执行：小车 BUSY=ON，伸爪抓取、夹紧、上提；BUSY 期间设备锁定保持交接位。
   - 阶段4 完成：小车夹紧提离→COMPT=ON；设备确认在位传感器 OFF（口空）、盒确实离开。
   - 阶段5 复位：设备确认口空后撤 ES、机构回 Home/关门，小车撤 COMPT/BUSY/TR_REQ（HO 翻转），带盒离开。
   - 阶段6 转软件：E87 转 UNLOADED/移除并上报 Host，Host 更新载具位置/任务。
   - **最大不同在阶段2**：Deposit 时设备基本只需"空口承接"（自己不动），等小车来放；Pickup 时设备必须在给许可前**主动先把盒送到可被取走的交接位**（备货方是设备），方向相反导致"谁先做机构动作"对调。

2. **为什么 Pickup 要先送盒到位再 ES**：ES 的语义是"我这边已具备执行本拍的条件，你可以动作"。取货时小车要抓取，前提是 FOUP 必须处于机械爪可达、可夹取的确定位置（正确高度、夹持已松开、门已让开）；如果设备还夹着盒、盒还锁在工位/未下降到交接位就点亮 ES，小车伸爪会抓空、抓偏或与设备夹持/门机构碰撞，甚至硬拉扯损坏 FOUP 和机构。因此设备必须先完成"松夹→下降/让位→到位确认"，把盒准备到可取状态，才用 ES=ON 告诉小车"现在可以取了"。这体现"许可信号必须在己方条件真正具备后才置位"的互锁原则。

3. **COMPT 后为何确认在位传感器 OFF**：COMPT 是小车单方声明"我已取走"，设备不能只凭对方声明就认定口空——必须用自己的在位/落座传感器确认 FOUP 确实离开了 Load Port（在位信号由 ON 变 OFF 并稳定去抖）。原因：①防止小车抓取失败/打滑/没夹紧，盒其实还在口上，设备却误以为取空而回 Home/关门，造成挤压；②防止半取半卡（盒卡在中途）的危险状态被漏掉；③保证账实一致——只有物理确认口空，才允许 E87 迁移到 UNLOADED、Host 才会认为载具已离开。这和 Deposit 时"COMPT 后确认在位 ON（坐实）"正好相反，方向相反则完成判据相反。

4. **Pickup 逻辑前提 / 逻辑先于物理**：逻辑前提是该 FOUP 已加工完成、E87 载具状态允许下料（例如已到可卸载态、没有被 Hold、没有未完成任务），且 Host/MES 已通过 AMHS 调度下发了来取的搬运任务。下料是"逻辑先于物理"：Deposit 是盒子先被物理放上来、系统随后才建立它的逻辑身份和状态（物理→逻辑）；而 Pickup 必须先在逻辑层确认"这个盒确实该走、可以走、由谁取、取到哪"，才允许物理上把它交出去（逻辑→物理）。若没有下料许可，哪怕空车已到、TR_REQ 已发，设备也不能松夹送盒，否则在制载具可能被误取走、物料流和 MES 账目不一致，造成丢批/混批。这是 E84（物理）服从 E87/MES（逻辑）调度的协同约束。

5. **同口能否同时交接 / 互斥保证**：不能。一个 Load Port 同一时刻只能进行一个交接（要么放、要么取，要么空闲），物理机构只有一套，同时放取必然碰撞。交接状态机用互斥状态保证：设 Idle/Deposit 中/Pickup 中/异常等状态，Idle 才能接受新 TR_REQ 并根据方向转入 Deposit 或 Pickup；一旦进入某交接流程，状态非 Idle，再来任何 TR_REQ 都拒绝/排队，必须等当前交接走完、信号复位、回到 Idle 才接受下一个。软件和 PLC 都以该状态为权威，配合硬件互锁，杜绝同口并发交接。

6. **方向与物理状态矛盾如何处理**：设备在阶段1先判定本次交接方向，再与口当前物理状态（在位传感器有无盒）和逻辑状态比对，矛盾一律拒绝并告警、不进入执行：
   - 空车对**空口**发 Pickup（要取却没盒）：无货可取，设备不置 ES、保持空闲，返回/置异常指示并上报告警（可能是调度错误或小车跑错位），让小车离开、AMHS 重新调度。
   - **有盒口**收到 Deposit 请求（要放却已有盒）：没有空位承接，设备拒绝、不置 ES，告警防止双盒碰撞。
   - 方向编码不明：无法判定放/取，拒绝并告警。
   - 有盒且请求 Pickup 但 E87 无下料许可：物理状态匹配但逻辑不允许，仍拒绝（逻辑先于物理）。
   原则：方向、物理状态、逻辑许可三者一致才许可，任一不符就安全拒绝并上报，绝不"将错就错"动作。

7. **Deposit/Pickup 后 E87 迁移与 Host 动作**：
   - Deposit 完成后：设备读 CarrierID，E87 Carrier 状态迁移到 **LOADED（已装载）**，经 SECS 上报 Host（对象事件/S6F11）；随后 E90 读 SlotMap，Host 校验载具/批次、预约关系，创建 ProcessJob/ControlJob 安排加工。
   - Pickup 完成后：设备确认口空，E87 Carrier 状态迁移到 **UNLOADED/移除（已卸载）**，经 SECS 上报 Host；Host 更新该载具位置（已离设备、在 AMHS 上）、关闭/归档本设备上的载具记录，并由 MES/AMHS 调度把 FOUP 送往下一工序设备或 Stocker 仓储。
   两者方向相反：上料后 Host"开始对这个盒负责并派工"，下料后 Host"结束在本设备的负责并更新流向"。

## 四、两个异常拒绝推演（参考答案）
### 异常1：空车对空口发 Pickup
- 阶段1 设备检查：在位传感器=OFF（口空），与"取货"方向矛盾，无货可取。
- 处理：不置 ES、不做任何机构动作，保持 Idle；置异常/拒绝指示（按标准应答信号），向 Host/AMHS 上报告警"空口取货请求、调度或到位错误"；通知小车离开，由 AMHS 重新核对任务与目标口。防止小车空抓、浪费节拍、误判取走。
### 异常2：无 E87 下料许可小车就来取
- 阶段1 设备检查：物理上口有盒（方向匹配），但查 E87/Host 状态——载具未到可卸载态/被 Hold/无对应搬运任务，逻辑不许可。
- 处理：物理状态虽匹配仍拒绝，不松夹、不送盒、不置 ES；上报告警"未授权下料"，等待 Host 明确许可或取消；保证在制载具不被误取走、账实一致。体现"逻辑先于物理、E84 服从 E87/MES 调度"。

## 五、今日易错点
1. 以为 Pickup 和 Deposit 完全对称只是方向反（阶段2 设备要先备货送盒，是实质区别）。
2. 设备没把盒送到交接位就置 ES（小车抓空/碰撞）。
3. COMPT 后不确认在位 OFF 就复位关门（抓取失败/半卡会挤压）。
4. 忽略下料的逻辑许可，空车来就给盒（在制盒被误取、账实不符）。
5. 同一 Load Port 允许并发交接（必须 Idle 才接新请求，状态机互斥）。
6. 方向与物理状态矛盾还将错就错（空口取/有盒放必须拒绝告警）。
7. 把 Deposit 的"物理→逻辑"和 Pickup 的"逻辑→物理"搞反。
8. 复位不按握手逆序、不翻转 HO 位（残留信号影响下一次交接）。
