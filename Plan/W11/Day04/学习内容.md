## 二、背景知识（先读，25 分钟）

### 1. Pickup 前置条件
- 逻辑前提（软件层，E87）：FOUP 加工完成、载具状态允许下料（如已 UNLOAD 准备、Host 已请求 AMHS 来取），不是想取就能取。
- 设备侧：CS=ON、Load Port 上有 FOUP、设备已把 FOUP 送到可被取走的交接位（下降/松夹/开门到位，具体机构顺序以设备为准）。
- 小车侧：SS=ON、VR=ON、小车**空载**（有空间接收 FOUP）、到达对接位；VALID 有效。

### 2. Pickup 标准节拍（教学时序）
```
阶段0 空闲：口上有盒待取，双方就绪 CS/SS
阶段1 小车就位、请求取货：
   空车到位 → VR=ON → TR_REQ=ON（请求 Pickup，HO 位标记新拍）
   设备采样：口上确实有盒?逻辑允许下料(E87)?CS/无急停非旁路?
阶段2 设备备货并许可（关键：这次是设备先做动作）：
   设备把 FOUP 送到交接位（松开夹持/下降到取货高度/开门让位）
   准备好被取走 → ES=ON（允许小车来取）
   小车采样到 ES=ON，确认盒已在可取位置
阶段3 小车执行取货：
   小车 BUSY=ON → 伸爪/下降抓取/夹紧 FOUP/上提
   BUSY 期间设备机构锁定、保持交接位不动
阶段4 取走完成：
   小车确认已夹紧并把 FOUP 提离 Load Port → COMPT=ON（取走完成）
   设备确认在位传感器 OFF（口已空）、FOUP 确实离开
阶段5 复位：
   设备确认口空 → 按握手顺序撤 ES、机构回 Home/关门
   小车撤 COMPT/BUSY/TR_REQ（HO 位翻转回空闲），带盒离开
阶段6 转软件流程（E87/E90）：
   Load Port 检测口空 → E87 Carrier 状态迁移到 UNLOADED/移除，上报 Host
   → Host 更新载具位置/任务，AMHS 把盒送往下一工位/Stocker
```

### 3. Pickup 与 Deposit 的对调点（核心）
| 环节 | Deposit（放/上料） | Pickup（取/下料） |
|---|---|---|
| 小车带盒? | 带盒来 | 空车来 |
| TR_REQ 后谁先做机构动作 | 设备只需确认空位（基本不动） | **设备先把盒送到交接位** |
| ES 许可前设备状态 | 口空、Home、准备承接 | 盒已在可取位、松夹/下降到位 |
| BUSY 动作 | 小车下放、松开 | 小车抓取、夹紧、上提 |
| COMPT 后传感器确认 | 在位 ON（确认坐实） | 在位 OFF（确认口空） |
| COMPT 后设备动作 | 夹持/上升/关门承接 | 机构回 Home/关门复位 |
| E87 状态迁移 | →LOADED | →UNLOADED/移除 |

### 4. 同口互斥与交接方向判定
- 一个 Load Port 同一时刻只能进行一个交接（不能一边放一边取），交接状态机用"空闲/Deposit 中/Pickup 中"互斥状态保证。
- 交接方向（这次 TR_REQ 是放还是取）由 AMHS 调度指令和约定信号/编码确定，设备在阶段1就要明确本次方向，按对应流程走；方向不明或与口当前物理状态矛盾（空口却请求取货、有盒却请求放货）必须拒绝并告警。

### 5. 下料的"逻辑先于物理"原则
- Deposit 是"先有物理盒来，再产生逻辑载具"（物理→逻辑）；Pickup 相反，"先有逻辑下料许可，才允许物理取走"（逻辑→物理）。
- 没有 Host/E87 的下料许可，即使空车来了发 TR_REQ，设备也不应把盒送出去（防止在制盒被误取走、账实不符）。这是 E84 与 E87 协同的重要一致性约束。
