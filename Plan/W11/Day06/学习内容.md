# W11 · Day06（周六，整块 3h）LPT 信号模拟器 + Deposit/Pickup 握手状态机代码

> 今天用 C# 把本周学的 E84 落地：先建并行信号位模型（一束信号的电平集合 + VALID 门控 + 去抖），再分别实现设备侧（Load Port）和小车侧（AMHS）的交接状态机，用"两个状态机互喂信号"的方式在内存里完整跑通 Deposit 和 Pickup，并注入异常（超时/VALID 闪断/方向矛盾/ESTOP）验证处置。不接真实硬件，纯逻辑模拟，便于单测和讲解。

## 一、今日目标

6. 闭卷画出"两状态机+信号总线"的协作图。

## 二、设计（先读，20 分钟）

### 1. 信号位模型
- 用枚举 `LptSignal` 列出全部信号（CS/ES/HO0/HO1/SS/VR/TR_REQ/BUSY/COMPT/VALID/ESTOP/BYPS）。
- `LptSignalBus`：内部 `Dictionary<LptSignal,bool>` 表示电平；分设备输出/小车输出方向，只有所有者能写自己的信号，对方只读（防越权写）。
- **VALID 门控**：`TryRead(signal)` 仅在 VALID 有效且信号稳定时返回真实值，否则返回"不可信"，模拟并口"VALID 无效不解读"。
- **去抖**：置位后需连续稳定 N ms 才被 `Stable(signal)` 采信（模拟器用步进时钟，不真睡）。
- **快照**：`Snapshot()` 返回当前所有信号电平，异常时记录。

### 2. 时钟与互喂（不用真实线程）
- 用一个可手动步进的逻辑时钟 `Tick(ms)`，两个状态机每次 Tick 各自采样总线、按状态推进、写自己的输出信号。这样时序完全确定、可单测、可复现，避免多线程时序不确定性。
- 一个 `HandshakeSimulator` 持有 bus + 两个 FSM，`Step()` 一次同时让两侧各 `Tick` 一次，直到交接完成或进入安全保持/超时。

### 3. 设备侧状态机（LoadPortFsm）
状态：Idle、WaitVehicle（就绪等请求）、GrantDeposit/GrantPickup（置 ES 许可）、WaitBusy、TransferObserve（BUSY 中观察）、WaitComplete、Closing（承接/复位）、SafeHold、EStopHold、ManualBypass。
- 收到 TR_REQ：先判方向与口物理状态/逻辑许可，矛盾→拒绝回 Idle+告警；一致→做己方准备（Pickup 要先送盒到位）→置 ES。
- 观察 BUSY→COMPT：Deposit 要求 COMPT 后在位传感器 ON；Pickup 要求在位 OFF，不符→SafeHold。
- 每等待态挂超时定时器，到点按 Day05 矩阵处置。
- ESTOP 任意态→EStopHold；BYPS→ManualBypass；VALID 丢→SafeFreeze。

### 4. 小车侧状态机（VehicleFsm）
状态：Idle、Approach（到位置 SS/VR）、Requesting（置 TR_REQ 等 ES）、Placing/Retrieving（置 BUSY 执行，完成置 COMPT）、Withdraw（撤信号离开）。
- 必须采样到 ES 稳定才进 BUSY（没许可不动）。
- 可注入故障：不置 COMPT（制造 T_compt）、提前动作（验证设备不响应）。

### 5. 物理传感器与逻辑许可的模拟接口
- `IPortPhysical`：`bool HasCarrier()`（在位传感器）、`void Dock/Undock()`、`bool LogicPermitsPickup()`（E87 下料许可）。用内存假实现，让设备状态机能判断"空口/有盒/逻辑许可"。
