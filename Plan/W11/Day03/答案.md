# W11 · Day03 答案

> 时序为教学推演，精确信号名称/维持时间/超时参数以 SEMI E84 原文和设备 I/O 时序表为准。

## 一、自测题标准答案
1. **Deposit 六阶段与关键信号变化**：
   - 阶段0 空闲：业务信号全 OFF，设备 CS=ON（口可用）、小车 SS=ON（系统可用）。
   - 阶段1 请求：小车移动到位→VR=ON→TR_REQ=ON（配合 HO 位标记新拍，请求 Deposit）；设备采样后检查口空、CS、无 ESTOP/非 BYPS。
   - 阶段2 许可：设备确认空位、机构 Home、具备承接条件→ES=ON；小车采样到 ES 才继续。
   - 阶段3 执行：小车 BUSY=ON，下放 FOUP 到承接面；BUSY 期间设备锁定机构保持承接条件。
   - 阶段4 完成：FOUP 坐实、小车松开→COMPT=ON；设备确认在位传感器、坐实、夹持到位。
   - 阶段5 复位：设备确认承接后按序撤 ES，小车按序撤 COMPT/BUSY/TR_REQ（HO 位翻转回空闲），设备回空闲，小车离开。
   - 阶段6 转软件：Load Port 检测就位→读 CarrierID→E87 转 LOADED 并 SECS 上报→E90 读 SlotMap→Host 建 PJ。

2. **为什么等 ES 才能下放 / 提前下放风险**：ES=ON 是设备明确告知"我这一侧已具备承接条件（口是空的、机构在 Home、承接面就位、无故障）"。小车没看到 ES 就下放，等于在设备没准备好时把 FOUP 往下放：可能 Load Port 上还有另一个盒（双盒碰撞）、机构没到位/门没开、承接面没升到位，结果 FOUP 放偏、悬空、滑落甚至坠落，整盒晶圆报废、损坏硬件。互锁原则就是"对方没明确许可，物理动作绝不开始"，用确定的电平信号而不是时间猜测来保证安全。

3. **BUSY=ON 期间设备约束**：BUSY 表示小车正在执行物理放置动作，此期间设备必须：①锁定 Load Port 相关机构，不做升降、开关门、移动、夹持切换等任何可能与小车动作冲突的运动；②保持承接条件稳定（承接面位置、避让姿态不变）；③持续监控在位/坐实传感器和安全信号；④不得撤销 ES、不得改变 CS/VALID。直到 COMPT 且按握手复位后，设备才进入自己的承接动作（夹持/上升等）。本质是"一方运动时另一方静止配合"，避免两机构同时动作造成碰撞。

4. **凭什么判断可靠承接 / 承接前能撤 ES 吗**：设备依据硬件传感器的组合判断可靠承接——FOUP 在位传感器（在口检测）、坐实/落座检测（重量/到位开关）、夹持/定位销到位等信号都确认，且在 COMPT 后稳定去抖，才判定 FOUP 被可靠承接。承接确认前**不能撤 ES**：ES 是本次交接的许可/互锁，若盒子还没坐实就撤，小车侧可能误判交接状态、提前松爪或离开，而设备又未确认承接，盒子处于"双方都没确认持有"的危险窗口。必须"传感器确认坐实→进入承接→按握手顺序"才撤销许可信号。

5. **复位顺序原则 / 为何不能同时全撤**：复位遵循四相握手的对称收尾——后提出请求的一方、或先完成确认的一方按"完成→许可→请求"的逆序逐级撤销，每撤一个信号都等对方相应信号也变化（HO 握手位翻转标记拍结束），双方确认回到同一拍后再撤下一个，最后全部回空闲。不能同时全撤的原因：并行信号不可能物理上严格同时变化，同时撤销会产生不确定的中间组合，双方可能对"交接到底结束没有"判断不一致（一方以为结束、另一方还在等完成），导致丢拍、重复动作或下一次交接无法启动（残留信号被当成新请求）。逐级、带握手位翻转的复位保证双方状态机严格同步、干净回到空闲，为下一次交接做好准备。

6. **E84 完成 vs E87 LOADED / 如何衔接**：不是一回事，属于不同通道不同标准。E84 Deposit 完成是**物理层**结果——FOUP 通过硬线握手被可靠放置在 Load Port、信号复位、小车离开，只证明"盒子物理上在口上了"，不含盒子身份/内容/逻辑状态。E87 LOADED 是**逻辑层**状态——设备软件检测到 FOUP 就位后读取 CarrierID、做预约/校验，把 Carrier 对象状态机迁移到 LOADED，并通过 SECS（S16 对象事件或 S6F11）上报 Host。衔接：E84 完成产生的"FOUP 就位"硬件事件是 E87 状态迁移的物理触发源（PLC 把就位信号给设备软件），设备软件再走 E87/E90 流程；E84 不传 CarrierID/SlotMap 这些信息。顺序上一定是先 E84 物理交接成功，才可能有 E87 LOADED。

7. **Deposit 中 ESTOP 的状态**：ESTOP 触发瞬间，双方立即停止一切运动并进入安全保持：小车停止下放/夹持保持（失电制动/夹紧，防止掉盒），设备立即锁定 Load Port 机构、保持当前承接姿态；交接状态机挂起到"异常中止"态，TR_REQ/ES/BUSY 等按安全逻辑处理（通常停止推进、保持必要互锁而非正常复位），VALID 与安全回路进入安全态；现场必须人工介入——确认 FOUP 当前位置和夹持是否安全、排除急停原因、人工复位 ESTOP，之后根据盒子实际状态决定是重新继续交接、手动取下还是回退，不能自动恢复。核心是故障安全：急停时"停住并夹住"，绝不允许在未确认安全时继续动作或松脱。

## 三、Deposit 逐拍讲解脚本（参考答案，5 分钟）
1. "天车带着 FOUP 到达目标 Load Port 上方，搬运系统就绪 SS、本车就绪 VR 先亮；设备这边系统就绪 CS 一直亮着，表示这个口可用、没故障。"
2. "小车发起上料请求 TR_REQ，同时握手位翻转表示这是一次新交接。设备收到请求先自检：口是不是空的、机构是不是在 Home、有没有急停或旁路，都没问题才继续。"
3. "设备确认能接收，点亮 ES，意思是'我准备好了，你可以放'。小车必须看到 ES 才动作，没看到就一直等——这是防掉盒的关键互锁。"
4. "小车点亮 BUSY 开始下放 FOUP。BUSY 期间设备机构锁死不动，只保持承接姿态，避免两边同时动。"
5. "FOUP 落到承接面、小车松开，点亮 COMPT 表示放完了。设备不靠 COMPT 单方面判断，还要自己的在位、坐实、夹持传感器都确认盒子确实坐稳了。"
6. "确认承接可靠后，双方按四相握手逆序逐级撤信号：设备撤 ES，小车撤 COMPT、BUSY、TR_REQ，握手位翻回空闲，小车离开，设备这才做夹持/上升/关门。"
7. "到这里 E84 物理交接结束。接着设备软件读 CarrierID，E87 把载具状态转成 LOADED 并通过 SECS 上报 Host，E90 读槽位图，Host 才去建加工任务——硬线管'放稳'，软件管'登记和干活'。"

## 四、Deposit 检查清单（参考答案）
- 前置：CS=ON、SS/VR=ON、口空、机构 Home、门闭、无 ESTOP、非 BYPS、VALID 有效。
- 拍1 请求：TR_REQ 置位前小车到位；设备自检通过。
- 拍2 许可：ES 置位前确认承接条件；小车等 ES 才动作。
- 拍3 执行：BUSY 期间设备锁定、小车平稳放置。
- 拍4 完成：COMPT + 在位/坐实/夹持传感器全部确认。
- 拍5 复位：按握手逆序逐级撤、HO 位翻转、无残留信号。
- 完成判据：FOUP 物理坐实、双方回空闲、小车离开、口占用传感器 ON。
- 转 E87 触发：就位硬件事件→读 CarrierID→E87 LOADED 上报→E90 SlotMap。
- 安全：每拍有超时；ESTOP 即停并保持夹持，人工复位。

## 五、今日易错点
1. 把 TR_REQ 当成"直接开始放"（它只是请求，必须等 ES 许可）。
2. 小车没等 ES 就下放（掉盒/碰撞风险，硬互锁不允许）。
3. BUSY 期间设备动 Load Port 机构（一方动另一方必须静止配合）。
4. 只看 COMPT 就认为承接可靠（必须叠加设备自身在位/坐实/夹持传感器确认）。
5. 信号同时全部复位（应按握手逆序逐级撤、HO 位翻转，防丢拍/残留）。
6. 把 E84 完成等同于 E87 LOADED（物理就位≠逻辑状态，E84 不传 ID/槽位）。
7. 忽略 VALID/去抖，信号一跳变就动作（要稳定有效才采信）。
8. ESTOP 后想自动续接（必须人工确认安全后处理，故障安全优先）。
