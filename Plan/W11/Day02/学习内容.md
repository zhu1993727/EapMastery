## 二、背景知识（先读，30 分钟）

### 1. 信号方向总览
E84 是一束双向并行信号，按数据流方向分三组：
```
┌─────────────┐   设备→搬运(E→A 输出)     ┌─────────────┐
│             │ ───────────────────────► │             │
│  设备        │   CS/ES/HO_0/HO_1/...    │  AMHS 天车   │
│ Load Port   │ ◄─────────────────────── │  (小车)      │
└─────────────┘   搬运→设备(A→E 输入)     └─────────────┘
                  SS/VR/TR_REQ/BUSY/COMPT/...
        共用安全/控制：VALID、ESTOP、BYPS（双方都要监控）
```
- 设备侧程序：输出信号由设备 PLC/控制器置位，输入信号由设备采样读取。
- 信号必须配合 VALID（有效指示）才有意义；ESTOP/BYPS 是全局安全状态。

### 2. 设备→搬运（E→A）核心信号（设备输出）
> 名称为业界通用缩写，精确语义以 E84 原文为准。
- **CS（Carrier/Equipment System Ready，系统就绪）**：设备侧整体就绪、可以参与交接的总状态。ON=设备在线、该 Load Port 可用、无故障；OFF=设备不可用（故障/离线/维护），小车不应来交接。
- **ES（Equipment Ready to Transfer，设备交接就绪）**：针对本次具体交接，设备 Load Port 已准备好执行放/取动作（机构到位、门/台状态正确）。ON=可以进行这一步物理动作；是对搬运请求的"许可/应答"类信号。
- **HO_0 / HO_1（Hand-off bit 0/1，交接握手位）**：一对用于**四相握手（four-cycle handshake）**的编码/翻转信号，配合对方信号逐拍推进交接阶段（请求→应答→执行→完成），用两位状态翻转保证每一步都被双方确认，防止丢拍/抢拍。
- 部分实现还有：TR_READY/READY 类"可以传送"指示、位置/夹持状态信号等（以点表为准）。

### 3. 搬运→设备（A→E）核心信号（设备输入）
- **SS（Storage/System Ready，搬运系统就绪）**：AMHS 系统级就绪、可调度交接。ON=搬运系统正常可用。
- **VR（Vehicle Ready，小车就绪）**：到达 Load Port 的这台小车自身就绪（已到位、机构正常、有货/可收货）。
- **TR_REQ（Transfer Request，交接请求）**：小车发起本次交接请求（要 Deposit 放货 或 Pickup 取货，方向由交接类型/其他信号区分）。这是握手的起点。
- **BUSY（交接执行中）**：小车正在执行物理动作（移动/放/取），ON 期间设备不得改变相关机构状态。
- **COMPT（Transfer Complete，交接完成）**：小车完成本次物理动作（货已放稳/已取走），通知设备可以进入下一步（如 Load Port 上升、夹持、关门）。
- **CONT（Continue，继续）**：多拍交手中允许进入下一阶段的推进信号（具体用途以时序为准）。

### 4. 双方共用的安全/控制信号
- **VALID（信号有效）**：表示当前并行总线上的信号组合是有效、可信的。任何一方在 VALID 无效时不得解读其他信号、不得动作；信号切换时先改变数据信号、稳定后再置 VALID，类似"数据有效时钟"。这是抗干扰、防误读的关键。
- **ESTOP（Emergency Stop，急停）**：急停状态指示，任一方向触发立即中止交接、进入安全保持。故障安全：异常时导向停止。
- **BYPS（Bypass，旁路/手动模式）**：自动交接被旁路（手动/维护模式），自动握手流程不执行，用于人工操作或检修；正常自动生产时 BYPS 必须处于非旁路态。

### 5. 四相握手思想（HO 位 + 请求/应答/完成）
并行交接采用"请求—应答—执行—完成—复位"的互锁节拍，本质是四相握手：
```
①请求方置请求(如 TR_REQ)并翻转/置位握手位
②应答方确认条件满足，置就绪/应答(如 ES)，双方都确认对方信号
③请求方见应答后开始执行(BUSY)，执行物理动作
④执行完置 COMPT，双方依次复位信号，回到空闲，准备下一拍
```
- 每一拍都要求"看到对方信号稳定→再推进自己的信号"，任何一方没到位就等待（进入超时处理，Day05 讲）。
- HO_0/HO_1 的翻转编码让双方能区分"新的一拍"和"上一拍残留信号"，避免重复动作。

### 6. Deposit 与 Pickup 的信号差异（先建立，Day03/04 细讲）
- Deposit（上料/放盒）：小车带盒来，TR_REQ 请求放→设备 ES 允许并准备接收→小车放下（BUSY）→COMPT 放稳→设备 Load Port 承接（上升/夹持/读 ID）→复位。
- Pickup（下料/取盒）：设备有盒待取，小车空车来，TR_REQ 请求取→设备 ES 允许、Load Port 把盒送到交接位→小车取走（BUSY）→COMPT 取走完成→设备机构复位。
- 方向相反，信号节拍框架相同，但"谁准备货、谁承接"相反。
