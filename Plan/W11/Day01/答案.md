# W11 · Day01 答案

## 一、自测题标准答案
1. **E84 LPT 是什么 / 作用**：E84 是 SEMI 标准定义的本地并行传输接口（Local Parallel Transfer Interface），是设备 Load Port 与 AMHS 搬运小车（OHT/AGV）之间的一束**并行数字 I/O 硬线**接口。作用：在 FOUP 自动放置（Deposit 上料）和取走（Pickup 下料）的物理过程中，双方通过固定信号的电平 ON/OFF 按严格时序握手和安全互锁——确认彼此就绪、允许动作、同步放/取、确认完成，任何一步条件不满足或异常都立即停止，防止碰撞、掉盒、损坏晶圆和伤人。它管的是"物理交接动作"，不是信息管理。

2. **五维对比**：
   - 介质：E84 是多芯信号电缆+光耦 I/O（并行电平）；HSMS/SECS 是以太网 TCP/IP（串行报文）。
   - 实时性：E84 微秒~毫秒、确定；SECS 毫秒~秒、受操作系统调度/网络拥塞/TCP 重传影响，不确定。
   - 安全：E84 直达安全互锁回路、故障安全；SECS 依赖软件栈和网络，非功能安全级。
   - 失效行为：E84 断线/掉电/死机自动回安全态（停、保持夹持）；SECS 断连靠超时和软件恢复，期间无法保证物理动作安全。
   - 用途：E84 只做物理交接硬握手/互锁；SECS 做信息交换、状态管理、任务下发、数据采集等丰富业务。

3. **为什么不能依赖 TCP / 网络抖动事故推演**：物理交接是硬实时、不可逆动作。推演：天车正把 FOUP 往 Load Port 放，需要"Load Port 已就位、可以松开夹爪"的确认；若这确认走 TCP，恰好网络拥塞/交换机抖动/协议栈卡顿 200ms，天车可能在没收到确认时按超时策略误判、或确认迟到时夹爪已在错误时机松开，FOUP 跌落，一盒 25 片晶圆报废，甚至砸坏设备。反过来，若"立即停止"指令走网络，软件崩溃或网线松动时指令根本到不了，机械继续动作。硬线信号是电平直达安全回路，微秒级、不经过操作系统和网络协议栈，掉电即回安全态，只有它能承担这种不可逆动作的互锁。原则：涉及人身/设备/物料安全的实时互锁，必须用确定性硬线，不能用尽力而为的网络。

4. **光耦隔离 / 为何两侧隔离**：光耦隔离是两侧电路不直接电气相连，信号通过"电→光→电"耦合传递（发光侧点亮 LED，接收侧光敏器件导通），中间没有金属导线直连。E84 两侧隔离的原因：①设备和天车是两套独立系统，各自电源/地电位不同，直连会产生地环流，干扰信号甚至烧毁 I/O 端口；②工业现场电机、变频器电磁干扰强，隔离阻断共模干扰串入；③一侧发生过压/短路/浪涌时，光耦保护另一侧不被高压串入损坏，提升安全和可靠性；④避免两侧故障互相传导。这是工业数字接口抗干扰和安全的标准做法。

5. **Source/Sink 不匹配后果 / 怎么确认**：Source（源型）输出端向外提供电流、Sink（漏型/灌电流）输入端向内吸收电流，电流必须从一个 Source 流出、经信号线流入一个 Sink 形成闭合回路。两侧类型不匹配（都是 Source 或都是 Sink）时电流无法形成回路，信号永远无效（I/O 点不亮/读不到 ON），交接握手卡死。工程确认：①查双方 I/O 模块手册的接线类型（PNP/NPN、Source/Sink、源型/漏型）；②按"输出类型与输入类型互补"原则接线，必要时加中间继电器/中继模块转换；③上电后用万用表量信号线对公共端电压、看 PLC I/O 指示灯，逐点验证每个信号 ON/OFF 都能被对端正确读到；④做信号回路测试（一侧强制 ON，另一侧监控），不要只看接线图就认为通。

6. **故障安全 / E84 怎么保证**：故障安全（Fail-safe）指系统在发生故障（断电、断线、信号丢失、死机）时自动进入对人和设备最安全的状态，而不是误动作。E84 的保证：①关键互锁信号采用特定有效逻辑，使得线缆断开、触点接触不良、失电时信号落到"不允许动作"的安全侧（如夹持/制动保持、运动停止），而非"允许动作"侧；②VALID 有效信号指示整束信号可信，VALID 无效（抖动/掉电）时双方都不执行任何交接动作；③握手要求信号稳定维持（去抖）才采信，瞬时干扰不会触发动作；④每个动作都需要双方信号同时满足（双边互锁），单边故障无法让动作继续；⑤机械上夹爪/制动器设计为失电保持（断电夹紧/制动），防止掉盒。核心思想：把"故障"导向"停止并保持安全"，把"动作"设计成需要持续满足条件才能进行。

7. **一次自动上料中各标准分工**：①**E84**——物理层硬握手：天车与 Load Port 通过并口信号完成 FOUP 的 Deposit 放置（就绪/允许/放/完成/互锁），保证物理动作安全；②**E87**——逻辑层载具管理：FOUP 就位后载具状态机迁移到 LOADED、绑定 CarrierID、预约/上料状态通过 SECS 上报 Host（对象事件/S6F11）；③**E90**——位置层基板跟踪：读取该 FOUP 的 SlotMap，知道 25 个槽位哪些有晶圆、每片基板 ID 和来源/目标槽；④**E40/E94**——任务层：Host 依据载具和槽位信息创建 ProcessJob（加工任务，指定配方/取放片槽位）、ControlJob（编排多个 PJ），驱动设备加工。比喻：E84 是"手"（安全搬放），E87 是"账"（盒子状态登记），E90 是"货"（盒里晶圆位置），E40/E94 是"活"（干什么加工）。

## 四、电气基础卡片（参考答案）
| 卡片 | 一句话 | 工程坑 |
|---|---|---|
| 24V 电平 | ON=有源导通、OFF=断开，每信号一根线+公共回线 | 公共端接错/虚接导致整组信号异常 |
| 光耦隔离 | 电-光-电传递，两侧无金属直连 | 以为隔离就不用共地测试，实际仍要逐点验证 |
| Source/Sink | 源型输出电流、漏型吸收电流，必须互补成回路 | 两侧同型导致信号永远不通，查 PNP/NPN |
| VALID | 指示整束信号有效，无效不得动作 | VALID 没建立就握手，动作被拒且难排查 |
| Fail-safe | 故障导向停止/保持，动作需持续满足条件 | 把安全信号设计成"得电才安全"，掉电误动作 |
| 去抖/稳定时间 | 信号稳定维持一定时间才采信 | 触点抖动被当多次触发，握手时序错乱 |

## 五、今日易错点
1. 把 E84 当成又一种 SECS 消息（它是并行硬线 I/O，不走 TCP、不走 SECS-II 编码）。
2. 以为 FOUP 交接靠 Host 发报文控制（物理互锁在设备和天车之间硬线完成，Host 只做逻辑管理）。
3. 混淆 Deposit（放到设备=上料）和 Pickup（从设备取走=下料）方向。
4. 忽视 Source/Sink 匹配，上电后信号不通找不到原因。
5. 认为故障安全靠软件兜底（真正的安全靠硬线失电安全态，软件不可信）。
6. 把 E87 载具状态和 E84 硬线信号混为一谈（E84 是电平动作，E87 是走 SECS 的逻辑状态机）。
7. 忽略 VALID 信号和去抖稳定时间，导致误触发或握手失败。
8. 记成 FOUP 有 25 片晶圆（FOUP 有 25 个 Slot 槽位，是否有片由 SlotMap 决定，不一定满）。
