# W31 · Day07 答案

## 一、综合自测卷（7 题）参考答案
1. **闭环 run 时序**：MES 给目标 T/规格→设备以"recipe 主档基线+本腔 overlay"加工 run（run 内设定稳定，EDA 上高频过程特征、GEM 上作业事件）→run/片结束得量测（inline 实测优先，否则高置信 VM，带腔/Lot/片/当时 u/时间戳）→按片→腔归属、对回当时 u 算残差→EWMA/dEWMA 更新漂移状态→控制律 u_next=(T-a)/b→死区/步长限幅/控制限→生成带作用域/版本/ReqId 的 overlay→RMS 校验（主档不变、knob 范围、版本匹配）→EAP 经 GEM S2F41 在安全点下发→S2F42 受理（≠生效）→装载并回读实际值一致→S6F11 生效（以此为成功判据，才开下一 run）→审计逐 run 留痕。通道：上行 EDA/GEM，下行只走 GEM；FDC 在 run 中独立保安全。
2. **手算示例**：取 T=100、b=1、λ=0.5、初始 u0=100。run1：y1=106，残差 e1=y1-b·u1=106-100=6，a1=0.5·6+0.5·6=6（首值即残差），u2=(100-6)/1=94。run2：用 u2=94 加工，y2=95，e2=95-94=1，a2=0.5·1+0.5·6=3.5，u3=100-3.5=96.5。可见输出偏高→设定下调，随 EWMA 平滑逐步拉回；λ 越大每步跟得越猛。
3. **不改主档/元数据**：主档是验证/审批/版本化的法定基线，直接改会导致同名配方漂移、跨腔 Lot 污染、无法追溯回滚；故只叠加受控、可撤销的 overlay。overlay 元数据：唯一 ReqId（幂等）、来源控制器与算法版本、基线 recipe 版本、作用域（设备/腔/Lot/片/run/有效期）、各 knob 的 Δ/目标值与单位、依据量测（run/值/来源实测或 VM）、生成时间、批准状态、优先级。
4. **四种量测情况**：延迟——按 run 序号归位、取当时 u 算残差按序重放，工况已变则只记录；缺失——不更新状态、hold-last-good 保持上一安全设定，连续 N 次停自动；异常（超物理界/与 VM 背离）——判可疑不直接更新，交叉验证/复测，确认坏剔除并记数据质量事件；VM 低置信——不单独用于控制（或大幅降权），回退等实测。统一原则：无有效观测不调节，实测优先于高置信 VM。
5. **握手/受理与生效/超时**：Idle→Sent→Accepted（S2F42 ACKC10=0，仅语法/前置通过、收到）→Loaded（安全点合成装载）→Effective（回读实际值=期望，S6F11 回告，才是真生效、才开下一 run）；失败→Rejected/Failed 全量回滚。Accepted 只代表收到，参数尚未装载、run 不会用；Effective 才闭环成功。超时未到 Effective：按同一 ReqId 幂等重发（设备识别重复、不重复叠加 Δ），多次失败转人工、不开工。
6. **多腔独立/C2C-C2O/归属**：各腔偏置与漂移速率不同，统一 overlay 会补一腔带偏另一腔，故共享主档/目标/算法，每腔独立 EWMA 状态与 overlay（作用域到腔）。C2O=各腔各自对最优目标 T；C2C=先消除腔间相对差对齐，常结合（独立 EWMA+共同目标既对齐又达标）。量测归属：依 E90 SlotMap 与 E40/E94 作业谱系确定片在哪个腔加工，取该腔当时生效 u 算残差，只更新该腔；归错腔会双向越调越乱。
7. **停自动条件（≥5）**：①连续 N run 无有效量测/VM 低置信、处于开环；②估计/残差发散、输出多 run 拉不回目标；③补偿量撞控制限或连续打满步长（硬件/模型问题）；④FDC 严重故障、设备 Hold/报警联锁、工况不稳；⑤recipe/产品/工况切换或主档版本升级（模型/基线不匹配，需重初始化）；⑥SPC 判异（Δu 单调累积、非随机趋势、超控制限）；⑦某腔保养换件未重建基线。触发即保持安全设定、停该控制器（或该腔）、报警转人工并留痕。

## 二、费曼三问参考
- **批间调且不改配方**：工艺漂移是慢变的，run 内要稳定才能保证一片内一致，所以等一个 run 量完、在下一 run 前微调；又因为配方是经过验证的法定基线不能乱动，所以不动主档，只盖一层可撤销、有作用域的"修正贴"（overlay），实际参数=基线+修正，随时能撕掉回滚，既自动优化又不破坏验证与追溯。
- **EWMA 抗漂移防发散**：EWMA 用"最新量测一点+历史估计一大部分"平滑地估设备当前漂移，既跟得上慢变化又不被单次噪声带着跳；再用步长限幅防止一步过冲、死区防止目标附近乱抖、控制限守住工艺边界，坏量测不更新、延迟量测对回当时设定、连续没把握就停自动转人工——让控制器"稳、慢、有边界、知进退"。
- **多腔不能一刀切**：每个腔像性格不同的工人，偏置和老化速度不同，用同一道修正指令会让本来准的腔被改错；所以标准配方大家共用（统一标准），但给每个腔配各自的"小账本"（独立状态和补偿），量测结果先查清是哪个腔干的再只调那个腔；一个腔出问题只停它，别的腔继续，最终所有腔产出都对齐到同一目标且每片可追溯。

## 四、W31 全周易错点总清单
1. 把 R2R 当 run 内实时控制（批间、run 内稳定）。
2. 反馈/前馈混淆；用本 run 结果调本 run（应下一 run）。
3. EWMA 残差不扣 b·u，把自身调节当漂移。
4. λ 不匹配噪声/漂移；线性漂移不知用 dEWMA。
5. 无限幅/死区/控制限，过冲振荡或推出工艺窗口。
6. 延迟量测对新设定、缺测插值硬调、坏量测照样更新。
7. 直接改 recipe 主档；overlay 无作用域/版本/ReqId。
8. 对 locked 参数半推半就（应整份 all-or-nothing 拒绝）。
9. 多层 overlay 无全序优先级，合成结果不确定。
10. 把 S2F42 受理当生效；不回读实际值；失败不回滚。
11. 重发无幂等把 Δ 叠加两次；加工中/Hold 期仍下发。
12. 多腔用统一 overlay；量测不按片→腔归属；一腔故障停全部。
13. 保养换件不重置该腔状态；腔间差撞限还想靠补偿（应保养）。
14. 不监控 Δu/残差序列，控制器失配仍盲目补偿；无逐 run 审计谱系。
