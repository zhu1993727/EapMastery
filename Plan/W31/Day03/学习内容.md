## 二、背景知识（先读，40 分钟）

### 1. Recipe 主档是什么
- 一个 recipe 含若干 Step，每步一组工艺参数（温度、压力、功率、气体流量、时间…），是经工艺验证、审批、版本化的**法定基线**；RMS 统一存储、版本、下发、校验（W33 系统讲 RMS）。
- 主档对某产品/工艺固定，不能因为 R2R 逐批微调就直接改写——否则同一 recipe 名在不同时间内容不同，验证基线、良率追溯、跨腔一致性全部失效。

### 2. Overlay 补偿模型
- overlay 是一份**增量参数集**（只含被调参数的 Δ 或目标微调值），不复制整个 recipe；实际生效设定 `effective = baseline ⊕ overlay`（逐参数：未被覆盖用基线，被覆盖=基线+Δ 或=目标值）。
- **作用域 scope**：补偿只对指定范围有效——哪个设备/腔（C2C 腔间补偿不同）、哪个 Lot/产品、哪片或哪几个 run、以及有效期（过期自动失效回到基线）。离开作用域绝不影响其他生产。
- overlay 带元数据：来源（R2R 控制器 id/算法版本）、依据（量测 run/值）、生成时间、批准状态、唯一版本号，形成可追溯链。

### 3. 可调 vs 锁定参数
- **control knob（可调）**：工艺确认允许 R2R 在给定范围内小幅调整的参数（如曝光剂量/焦距微调、CMP 时间/压力、刻蚀时间、气体流量小补偿），每个 knob 有 min/max、步长、单位。
- **locked（锁定）**：涉及安全、关键质量、不可在线微调的参数（气体种类、步骤顺序、硬联锁阈值等），R2R 无权动，变更必须改 recipe 走 ECN 审批。
- 设备端只接受对 knob、且在其界限内的 overlay；对 locked 参数的修改请求直接拒绝并告警。

### 4. 叠加优先级与合成规则
- 多层 overlay 可能同时存在（设备级长期补偿 + Lot 级 + 片级），需定义优先级（通常：片级 > Lot 级 > 腔/设备级 > 基线），同参数高优先级覆盖低优先级，合成结果唯一确定。
- 合成后对每个 knob 做范围校验（基线+总补偿仍在 [min,max]）、步长校验（相对上次变化不超限），任一不过则整份 overlay 拒绝（all-or-nothing，不半生效），回退基线/上一有效 overlay。

### 5. 版本一致、审计与回滚
- overlay 必须声明它基于哪个 recipe 版本；若主档版本已变（换 recipe/ECN 升级），旧 overlay 自动失效，需 R2R 基于新基线重算，防止把旧工艺补偿错套到新配方。
- 全程审计：谁/哪个控制器、何时、对哪个腔/Lot/片、把哪个参数从多少改成多少、依据量测、是否生效；与 MES 谱系关联（W35）。
- 回滚：overlay 导致异常（FDC/SPC 报警）可一键撤销回上一有效设定或基线，并可阻止该控制器继续自动下发。

### 6. 设备端落地（与你已有知识衔接）
- overlay 下发仍走 GEM：远程命令/参数下发（S2F41/配方参数选择，部分场景 S7 选 recipe + 参数块），设备 FSM 只在合适状态（未加工/片间安全点）接受，受理≠生效，以状态/事件确认实际生效值；EDA 只读、绝不用于写 overlay。
