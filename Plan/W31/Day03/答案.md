# W31 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何不改主档/overlay 替代**：recipe 主档是经工艺验证、审批、版本化的法定基线，同一名字必须代表同一被验证内容；若 R2R 逐批直接改写，同名 recipe 随时间漂移，验证基线失效、跨腔/Lot 互相污染、出问题无法追溯"当时到底用了什么参数"，也无法回滚。替代方式是保持主档不变，另出一份只含被调参数增量的 overlay，运行时把基线与补偿**叠加合成**为实际生效设定（effective=baseline⊕overlay），补偿带作用域与有效期、可随时撤销，主档始终干净可追溯。
2. **合成式**：逐参数合成——对每个工艺参数 p，若 overlay 未覆盖则 effective[p]=baseline[p]；若覆盖，增量式 effective[p]=baseline[p]+Δp（或目标式 effective[p]=overlayTarget[p]）。多层时按优先级从基线起逐层叠加，高优先级覆盖低优先级对同一参数的补偿，最终得到唯一的一份 effective recipe 下发执行；合成后逐参数做范围/步长校验。
3. **作用域/离开处理**：作用域维度包括设备/腔（不同腔补偿不同，C2C）、产品/Recipe、Lot、Wafer/run、时间有效期（可能还有控制器/算法版本）。一份 overlay 只在其作用域内生效：指定腔只影响该腔、指定 Lot/片加工完即失效、超过有效期自动作废回到基线；绝不能让针对某腔/Lot 的补偿泄漏到其他生产。作用域结束后合成器不再叠加它，相关参数自动回到基线或上一层值。
4. **knob/locked/收到 locked 修改**：control knob 是工艺确认允许 R2R 在给定 min/max、步长内在线微调的参数（剂量/焦距/时间/压力/小流量补偿等）；locked 是涉及安全、关键质量、步骤结构、联锁的参数（气体种类、步骤顺序、硬阈值），R2R 无权动，变更必须改 recipe 走 ECN。设备端收到包含 locked 参数的 overlay，应整份拒绝（all-or-nothing，不部分应用）、回非 0 原因并告警/审计，绝不静默忽略其中 locked 项而应用其余（那样下发方以为全生效，实际不一致）。
5. **多层优先级/唯一**：常见优先级 Wafer/片级 > Lot 级 > 腔/设备级 > 基线（越具体、越临时优先级越高）。合成时固定一个全序、同参数取最高优先级层的值（或按规定增量叠加规则），并规定同层不允许两个来源写同一参数（否则冲突报错），这样无论 overlay 集合如何，合成结果唯一确定、可复现；冲突无法裁决时拒绝下发并提示，而不是随机取一个。
6. **绑定版本/升级处理**：overlay 的补偿是相对"某一具体 recipe 版本基线"算出来的（基线值、增益、可调范围都与版本相关），必须声明基线版本号。主档一旦因换 recipe/ECN 升级，基线参数/工艺窗口可能改变，旧 overlay 若继续叠加会错配（补偿方向/幅度不再适用）。因此主档版本变化时，旧 overlay 一律自动失效、清除并要求 R2R 基于新基线重新初始化/重算补偿，确认 knob 与范围后再生成新 overlay；版本不匹配的 overlay 设备端拒绝应用。
7. **通道/时机/生效确认**：通道只走控制面——经 RMS 校验授权、EAP/Host 通过 GEM 远程命令/参数选择下发（S2F41 或 S7 选配方+参数块），EDA 只读绝不用来写。时机必须在未加工的安全点（run 开始前或片间），加工进行中不改设定（保证 run 内一致、避免状态机非法迁移）。生效确认遵循"受理≠生效"：S2F42 ACKC10=0 仅受理，要等设备完成参数装载并以 S6F11/状态变量回告实际生效值，R2R/EAP 比对回告值=合成期望值后才确认；不一致/超时则不开始加工、回滚到上一有效 overlay 或基线并告警。

## 二、参考实现（net8.0）：基线 + overlay 合成器

```csharp
namespace EapLab.R2r.Recipe;
public enum ScopeLevel{ Equipment,Chamber,Lot,Wafer }
public sealed record KnobSpec(double Min,double Max,double MaxStep,bool Locked);
public sealed class RecipeBaseline
{ public string Version{get;}Dictionary<string,double> Params{get;}=new();HashSet<string> Locked{get;}=new();
    public RecipeBaseline(string v){Version=v;} }
public sealed class OverlaySet
{ public string BaselineVersion{get;}public ScopeLevel Scope{get;}public int Priority=(int)ScopeLevel.Wafer;
    public Dictionary<string,double> Delta{get;}=new();public string Source{get;}public bool Valid=true;
    public OverlaySet(string baseVer,ScopeLevel scope,string src){BaselineVersion=baseVer;Scope=scope;Source=src;Priority=(int)scope;} }

public sealed class EffectiveRecipeResolver
{ readonly Dictionary<string,KnobSpec> _knobs;public EffectiveRecipeResolver(Dictionary<string,KnobSpec> knobs){_knobs=knobs;}
    public record Audit(string Param,double From,double To,string Src);
    public (bool ok,Dictionary<string,double>? eff,List<string> errs,List<Audit> trail)
        Resolve(RecipeBaseline b,IEnumerable<OverlaySet> overlays,double[]? prevEff=null)
    { var errs=new List<string>();var trail=new List<Audit>();
        // 版本不匹配的overlay直接剔除(失效)
        var valid=overlays.Where(o=>o.Valid&&o.BaselineVersion==b.Version)
                          .OrderBy(o=>o.Priority).ToList();
        var eff=new Dictionary<string,double>(b.Params);
        foreach(var o in valid)foreach(var(kv in o.Delta)
        { if(b.Locked.Contains(kv.Key)||(_knobs.TryGetValue(kv.Key,out var sp)&&sp.Locked))
            {errs.Add($"{kv.Key} locked");continue;}
          var from=eff[kv.Key];var to=from+kv.Value;
          if(_knobs.TryGetValue(kv.Key,out var spec))
          { if(to<spec.Min||to>spec.Max){errs.Add($"{kv.Key} out of range");continue;}
            if(prevEff is not null&&Math.Abs(to-prevP(Eff(prevEff,kv.Key,from))>spec.MaxStep)){errs.Add($"{kv.Key} step over");continue;} }
          eff[kv.Key]=to;trail.Add(new Audit(kv.Key,from,to,o.Source)); }
        if(errs.Count>0)return(false,null,errs,trail);   // all-or-nothing
        return(true,eff,errs,trail); }
    static double PrevEff(double[]? prev,string k,double d)=>d; // 教学: 实际按参数索引取上次生效值
}
```

### xUnit
```csharp
public class ResolverTests
{
    static (RecipeBaseline,Dictionary<string,KnobSpec>) Base()
    { var b=new RecipeBaseline("RC-v3");b.Params["Time"]=60;b.Params["Power"]=1000;b.Params["GasKind"]=1;b.Locked.Add("GasKind");
      var k=new Dictionary<string,KnobSpec>{["Time"]=new(40,90,5,false),["Power"]=new(800,1200,50,false)};return(b,k); }
    [Fact] public void 基线叠加overlay得生效值()
    { var(b,k)=Base();var r=new EffectiveRecipeResolver(k);
      var ov=new OverlaySet("RC-v3",ScopeLevel.Lot,"R2R");ov.Delta["Time"]=2;
      var(ok,eff,_,_)=r.Resolve(b,new[]{ov});Assert.True(ok);Assert.Equal(62,eff!["Time"]); }
    [Fact] public void locked参数被拒_整份不生效()
    { var(b,k)=Base();var r=new EffectiveRecipeResolver(k);
      var ov=new OverlaySet("RC-v3",ScopeLevel.Lot,"R2R");ov.Delta["GasKind"]=1;
      var(ok,_,errs,_)=r.Resolve(b,new[]{ov});Assert.False(ok);Assert.Contains(errs,e=>e.Contains("locked")); }
    [Fact] public void 越界拒绝()
    { var(b,k)=Base();var r=new EffectiveRecipeResolver(k);
      var ov=new OverlaySet("RC-v3",ScopeLevel.Lot,"R2R");ov.Delta["Time"]=40; // 60+40=100>90
      Assert.False(r.Resolve(b,new[]{ov}).ok); }
    [Fact] public void 版本不匹配overlay失效_回基线()
    { var(b,k)=Base();var r=new EffectiveRecipeResolver(k);
      var ov=new OverlaySet("RC-v2",ScopeLevel.Lot,"R2R");ov.Delta["Time"]=5;
      var(ok,eff,_,_)=r.Resolve(b,new[]{ov});Assert.True(ok);Assert.Equal(60,eff!["Time"]); }
    [Fact] public void 多层_高优先级叠加且结果唯一()
    { var(b,k)=Base();var r=new EffectiveRecipeResolver(k);
      var eq=new OverlaySet("RC-v3",ScopeLevel.Equipment,"base");eq.Delta["Power"]=10;
      var lot=new OverlaySet("RC-v3",ScopeLevel.Lot,"r2r");lot.Delta["Power"]=20;
      var(ok,eff,_,_)=r.Resolve(b,new[]{eq,lot}); // 排序后Lot后应用
      Assert.True(ok);Assert.Equal(1030,eff!["Power"]); }
}
```

## 三、合成与校验流程（手绘参考）
```
Recipe主档(版本化, 验证基线, RMS管理, 锁定GasKind/步骤/联锁)
   + OverlaySet们(只含Δ, 带作用域 腔/Lot/片/有效期, 来源/依据/版本, R2R产出)
   → 版本匹配过滤(主档升级则旧overlay失效重算)
   → 按优先级 片>Lot>腔/设备>基线 全序叠加(同层不重复写, 冲突拒)
   → 逐参数: locked拒 / knob范围[min,max] / 步长maxStep / all-or-nothing
   → Effective Recipe(唯一) + 审计trail(参数: from→to, 来源, Lot/腔/片)
   → RMS校验授权 → EAP→GEM(S2F41/S7) 在run前/片间安全点下发
   → S2F42受理(≠生效) → 装载 → S6F11/状态回告实际值比对一致=生效, 否则不加工/回滚
异常(FDC/SPC): 一键撤overlay回上一有效/基线, 可冻结该R2R控制器; EDA只读永不写
```

## 四、今日易错点
1. R2R 直接改 recipe 主档，同名配方漂移、无法追溯回滚。
2. overlay 复制整份 recipe（应只含增量 Δ）。
3. 补偿不带作用域/有效期，某腔/Lot 的补偿泄漏到其他生产。
4. 对 locked 参数静默忽略却声称整份生效（应整份拒绝）。
5. 多层 overlay 无全序优先级，合成结果不确定。
6. 只做单点范围不做相对上次的步长校验，允许设定跳变。
7. overlay 不绑 recipe 版本，主档升级后错套旧补偿。
8. 加工进行中下发 overlay、把 S2F42 受理当生效、无审计 trail。
9. 从 EDA 数据面试图写参数（必须 GEM 控制面）。
