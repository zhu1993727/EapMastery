# W31 · Day05 答案与参考实现

## 一、自测题标准答案
1. **上行数据/为何回读生效值**：上行三类——①过程特征：EDA 高频 trace 与 GEM Step/作业事件（供 VM 建模、FDC、R2R 特征）；②结果与对齐信息：每 run/片结束上报 inline 量测/结果、实际设定、腔/Lot/片/recipe 版本与时间戳，供 R2R 把量测对回到产生它的 run 和当时设定（Day04 归位）；③生效回读：overlay 装载后回读控制器里的**实际生效参数**。必须回读是因为"收到命令/受理"不等于"参数真的被装载且等于期望值"，可能被设备逻辑钳制、四舍五入、局部失败；只有回读实际值并与上位期望一致，R2R 才知道下一 run 真正用了什么设定、其模型与量测对齐才成立，否则 R2R 以为给了 u、设备实际用了 u'，闭环建立在错误前提上。
2. **下行机制/自带字段**：主配方由 RMS 经 S7（上传/下载/PP-Select 选择）或 S2F41 选配方命令选定（版本受控）；overlay 用 S2F41 远程命令携带 CP 参数名-值列表（或厂商约定参数消息），设备再做 baseline⊕overlay 合成。命令必带：唯一请求 id（幂等）、来源控制器/算法版本、目标设备/腔与作用域（Lot/片/run、有效期）、所基于的 recipe 版本、各 knob 的 Δ/目标值、期望上限/步长、生成时间与依据量测 run。缺版本/作用域/请求 id 的命令应拒绝。
3. **接收状态/加工中处理**：只在安全点、且控制状态允许时接收——Remote 模式、非 Local、非 Hold/Alarm 联锁、目标腔 Idle 或片间间隙、当前无正在执行的 run；同时通过 recipe 版本匹配、knob 范围/步长、locked 未被改等校验。加工进行中收到 overlay 应拒绝（回非 0，原因"not in safe state/processing"），因为 run 内必须保持设定稳定、中途改参数破坏一致性且状态机不允许；请上位在片间/下一 run 前重发。Local 模式/ Hold 中同样拒绝，避免与操作员/联锁冲突。
4. **握手状态机/受理非生效**：Idle→(下发)Sent→(语法与前置校验通过,回 S2F42 ACKC10=0)Accepted→(安全点合成并装载)Loaded→(回读实际值与期望一致,发 S6F11 生效事件)Effective；任一环节失败→Rejected/Failed 并带原因、回滚。ACKC10=0 只表示设备**收到并受理**了请求（语法对、当前可接收），此时参数尚未装载、run 仍不会用它；只有完成装载并回读一致、进入 Effective 才是真生效。上位必须以 Effective 事件为闭环成功判据，未到 Effective 不得开始下一 run，防止"以为调了其实没调"。
5. **幂等防叠加**：每条 overlay 命令带唯一请求 id，设备维护"已处理请求 id→结果"记录。重复到达同一 id 时不再执行 Δ 叠加，直接返回上一次处理结果（Accepted/Effective 与已生效值）；这样超时重发、网络重复投递不会把同一补偿加两次（否则 60+2 变 60+2+2）。幂等记录按作用域/时间清理，跨 recipe 版本或已过期请求不复用。本质和 GEM/作业命令的幂等重试一致。
6. **回读不一致处理**：装载后回读实际生效值若与合成期望不符（被钳制、精度舍入、写入失败、部分参数失败），判定 Failed：①整份 overlay 回滚到上一有效 effective 或基线（all-or-nothing，不允许部分参数生效的半状态）；②设备保持在已知安全设定、不开始下一 run；③经事件/返回码上报失败原因与实际读到的值；④上位据此决定重发/降步长/转人工，并记审计。绝不能"回读不一致却报生效"或带着半生效设定加工。
7. **Hold/异常期暂停下发**：R2R 调节的前提是工况稳定可控、输出变化可归因于设定。设备 Hold、FDC 报异常、报警联锁期间过程不稳定、可能有未完成/异常片，此时下发 overlay 会把异常工况的影响和控制调节混在一起，污染状态估计（残差不再只反映慢漂移），也可能与操作员干预/安全联锁冲突。应暂停自动下发与状态更新（或标记该时段数据不用于控制），待恢复、工况稳定并确认后再继续闭环；异常 run 的量测按 Day04 规则决定是否剔除，避免坏反馈带偏控制器。

## 二、参考实现（net8.0）：下发-生效握手状态机

```csharp
namespace EapLab.R2r.Handshake;
public enum HsState{ Idle,Sent,Accepted,Loaded,Effective,Rejected,Failed }
public sealed record OverlayCmd(string ReqId,string RecipeVer,string Chamber,
    Dictionary<string,double> Delta,bool Remote,bool Processing);

public sealed class OverlayHandshake
{
    public HsState State{get;private set;}=HsState.Idle;
    readonly HashSet<string> _seen=new();Dictionary<string,double> _effective=new();
    public Dictionary<string,double> Current{get;private set;}=new(){{"Time",60},{"Power",1000}};

    // 1 下发+受理(前置校验, 幂等)
    public (HsState s,string? err) Send(OverlayCmd cmd,Func<Dictionary<string,double>,(bool,string?)> validate)
    { if(_seen.Contains(cmd.ReqId))return(State,"duplicate-idempotent"); // 幂等不重复叠加
        _seen.Add(cmd.ReqId);State=HsState.Sent;
        if(!cmd.Remote||cmd.Processing)return Reject("not in safe state");
        var(vok,verr)=validate(cmd.Delta);if(!vok)return Reject(verr!);
        State=HsState.Accepted;return(State,null); }
    // 2 装载(合成)
    public void Load(OverlayCmd cmd){if(State!=HsState.Accepted)return;
        _effective=new Dictionary<string,double>(Current);foreach(var kv in cmd.Delta)_effective[kv.Key]+=kv.Value;
        State=HsState.Loaded; }
    // 3 回读确认(实际值==期望才Effective, 否则Failed回滚)
    public HsState Confirm(Dictionary<string,double> readback)
    { if(State!=HsState.Loaded)return State;
        if(readback.All(kv=>Math.Abs(kv.Value-_effective[kv.Key])<1e-6)){Current=_effective;State=HsState.Effective;}
        else{_effective=Current;State=HsState.Failed;} // 回滚
        return State; }
    (HsState,string?) Reject(string why){State=HsState.Rejected;return(State,why);}
}
```

### xUnit
```csharp
public class HandshakeTests
{
    static (Func<Dictionary<string,double>,(bool,string?)>) Validator()=>new(()=>(true,null));
    OverlayCmd Cmd(string id="r1",bool remote=true,bool proc=false)=>
        new(id,"RC-v3","C1",new(){["Time"]=2},remote,proc);
    [Fact] public void 完整握手到Effective()
    { var h=new OverlayHandshake();var(s,_)=h.Send(Cmd(),Validator().Item1);Assert.Equal(HsState.Accepted,s);
      h.Load(Cmd());Assert.Equal(HsState.Effective,h.Confirm(new(){["Time"]=62,["Power"]=1000}));
      Assert.Equal(62,h.Current["Time"]); }
    [Fact] public void 受理不等于生效()
    { var h=new OverlayHandshake();h.Send(Cmd(),Validator().Item1);
      Assert.Equal(HsState.Accepted,h.State);Assert.Equal(60,h.Current["Time"]); } // 还没装载
    [Fact] public void 加工中拒绝()
    { var h=new OverlayHandshake();var(s,e)=h.Send(Cmd(proc:true),Validator().Item1);
      Assert.Equal(HsState.Rejected,s);Assert.Equal("not in safe state",e); }
    [Fact] public void 幂等重发不叠加()
    { var h=new OverlayHandshake();h.Send(Cmd("x"),Validator().Item1);h.Load(Cmd("x"));h.Confirm(new(){["Time"]=62,["Power"]=1000});
      var(s2,_)=h.Send(Cmd("x"),Validator().Item1);Assert.Equal(HsState.Effective,s2);Assert.Equal(62,h.Current["Time"]); }
    [Fact] public void 回读不一致_Failed并回滚()
    { var h=new OverlayHandshake();h.Send(Cmd(),Validator().Item1);h.Load(Cmd());
      Assert.Equal(HsState.Failed,h.Confirm(new(){["Time"]=70,["Power"]=1000})); // 期望62读到70
      Assert.Equal(60,h.Current["Time"]); }
}
```

## 三、下发-生效时序（手绘参考）
```
R2R→RMS校验→EAP: S2F41 overlay命令(ReqId/recipeVer/腔/作用域/Δ/来源/有效期)
设备: 前置守门(Remote&非加工&安全点&版本匹配&knob范围步长&locked未改)
  Sent ─ACKC10=0→ Accepted(仅受理,未生效) ; 不满足→Rejected原因码
  安全点合成 baseline⊕overlay → Loaded
  回读实际生效值==期望? ─是→Effective + S6F11(生效值)回告(闭环成功判据, 才可开下一run)
                        └否→Failed, all-or-nothing回滚上一有效/基线, 不开工, 上报
超时未Effective: 按ReqId幂等重发(不重复叠加)/转人工 ; Hold/FDC异常期暂停下发
审计: ReqId/来源/版本/腔Lot片/参数from→to/各状态时间戳/结果, 关联MES谱系
通道: 上行EDA/GEM, 下行overlay只走GEM控制面; EDA只读
```

## 四、今日易错点
1. 把 S2F42 受理当生效（必须回读一致到 Effective）。
2. 加工中/Local/Hold 状态接收 overlay（应在安全点拒绝）。
3. 命令无 ReqId，超时重发把 Δ 叠加两次。
4. 回读不一致仍报生效、或部分参数生效形成半状态（应 all-or-nothing 回滚）。
5. overlay 不绑 recipe 版本/作用域，错套或泄漏到其他 Lot/腔。
6. 不回读实际值，R2R 用"以为的设定"建模，闭环前提错误。
7. Hold/异常期继续下发，污染状态估计。
8. 无审计 trail，无法逐 run 追溯实际设定与来源。
