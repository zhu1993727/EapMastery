## 二、背景知识（先读，40 分钟）

### 1. 上行接口（设备→R2R/VM/EDC）
- 过程特征：经 EDA 高频 trace（供 VM 建模/FDC）、经 GEM S6F11 的作业/Step 事件与关键值。
- 结果与量测关联：每 run/片结束上报实际设定（含生效 overlay 值）、加工结果/inline 量测、腔/Lot/片/recipe 版本、时间戳，供 R2R 对齐更新（Day04 归位）。
- 生效回读：overlay 装载后回读实际生效参数（不只是收到命令），供上位核对。

### 2. 下行接口（R2R→RMS→EAP→设备）
- 主配方选择：RMS 选定 recipe（S7 上传/下载/选择 PP-Select，或 S2F41 选配方命令），主档版本受控（W33）。
- overlay 参数块：以 S2F41 远程命令携带 CP（参数名-值列表，带 R2R 来源、作用域、版本、幂等号），或厂商约定的参数下发消息；设备合成 effective=baseline⊕overlay（Day03）。
- 命令内容必须自带：目标腔/作用域、基于的 recipe 版本、参数 Δ、控制器/批次 id、唯一请求 id（幂等）、有效期。

### 3. 接收时机与前置条件（状态机守门）
- 只在安全点接收：设备 Remote 模式、非 Hold/加工中（Idle 或片间 Step 间隙）、目标腔可用；加工进行中拒绝（保证 run 内设定稳定、状态合法）。
- recipe 版本匹配、参数在 knob 范围/步长内、locked 不被改（Day03 校验）；任一不过拒绝并回原因。

### 4. 生效确认握手（核心，复用 GEM"受理≠生效"）
1. Idle：上位下发，设备生成请求记录→Sent。
2. 收到并做语法/前置校验→S2F42 ACKC10=0 受理（Accepted）；非 0 直接拒绝（Rejected，带原因码）。
3. 设备在安全点装载参数（合成 effective、写控制器）→Loaded。
4. 回读实际生效值并与期望比对一致→Effective，经 S6F11/确认事件回告"已生效+生效值"；不一致→Failed，回滚到上一有效设定并告警。
5. 上位以 Effective 事件作为闭环成功判据；超时未 Effective 按幂等重发或转人工（Day02/04）。
- 关键：Accepted 只是收到，Effective 才是真生效，未生效不得开始下一 run。

### 5. 幂等、回滚、审计
- 幂等：同一请求 id 重复到达不重复叠加 Δ（返回上次结果），防止超时重发把补偿加两次。
- 回滚：装载/回读失败恢复上一有效 effective 或基线，保持设备处于已知安全设定。
- 审计：请求 id、来源控制器、recipe 版本、腔/Lot/片、参数 from→to、状态迁移时间戳、结果，关联 MES 谱系（W35），可逐 run 复盘。

### 6. 与 FDC/Hold 的联动
- 若 overlay 生效后、加工中 FDC 因异常建议 Hold，按 W30 链路处理；R2R 在设备 Hold/异常时停止下发新 overlay（工况不稳不调），恢复并确认后再继续闭环。
