# W31 · Day06 答案与参考实现

## 一、自测题标准答案
1. **为何不能统一 overlay/共享与独立**：多腔各有固定偏置（硬件/积膜/保养历史差异）且漂移速率不同，统一 overlay 假设各腔响应一致，结果是补了偏差大的腔、又把原本准的腔带偏（按下葫芦浮起瓢）。正确做法：**共享** recipe 主档基线（同一工艺标准、版本受控）与全局目标 T、控制算法；**独立**每腔的 EWMA 漂移状态、overlay 补偿（作用域到腔）、控制限/步长与量测历史。这样每腔只对自己的偏差负责，最终都到同一目标。
2. **C2C/C2O/结合**：C2O（Chamber-to-Optimal）目标是让每个腔各自把输出拉向全局最优/目标 T，允许各腔补偿量不同，保证"片无论过哪个腔结果都达标"；C2C（Chamber-to-Chamber）目标是腔间匹配，先消除各腔输出的相对差、让它们彼此对齐，再整体对目标。通常结合：用每腔独立 EWMA + 共同目标，既把腔间相对差压到最小（C2C 一致性），又让整体均值落在 T（C2O 达标）；对跨腔一致性极敏感的工艺，可先显式做腔匹配校正再统一对目标。
3. **归错腔后果/依赖数据**：R2R 更新要用"本腔量测−本腔当时设定"估本腔漂移；若把 B 腔加工片的量测归给 A 腔，A 腔会按错误残差调节、B 腔却没被纠正，两腔都越调越偏、腔间差反而扩大且难定位。正确流程依赖作业/谱系数据：E40 PJ/E94 CJ 与 E90 SlotMap 记录了每片在哪个腔、哪一步加工（W15/W16/W20-23），量测回来先按"片 id→加工腔"归属，取该腔当时生效的 u（含该腔 overlay）算残差，只更新该腔控制器；一片过多腔时按工艺贡献拆分或用多输入模型。
4. **腔间差拉不回的含义/处理**：R2R 只能在 knob 范围内做小幅补偿，若腔间固定差/漂移大到某腔补偿撞控制限仍到不了目标，说明这是**硬件层面问题**（硬件失配、积膜异常、传感器/执行器故障、保养超期），不是调参数能解决的。应：该腔停止自动 R2R、报警提示维护（清洁/校准/保养/检修），必要时停止该腔接片（经 EAP 调度/资源管理），其余腔继续；恢复后重置该腔状态重新建立基线。用 SPC 监控腔间差趋势，提前预警而非等撞限。
5. **保养/换件后处理**：保养或换件会改变该腔固有特性（偏置/增益/积膜状态），原 EWMA 估计的漂移状态和 overlay 是针对旧硬件状态的，继续用会错补偿。应：重置该腔控制器状态（EWMA 清零或按新基线重新初始化）、撤销旧 overlay 回到新基线，用保养后首批"工程片/监控片"重新估计偏置与增益、确认稳定后再恢复自动；该重置事件与 recipe/基线版本一起记录审计，保证补偿始终对应当前硬件状态。
6. **其他腔能否继续/隔离**：可以继续，靠**故障域隔离**：控制器、状态、overlay 都按腔独立，某腔 Hold/FDC 异常/量测缺失时只冻结该腔（保持其最后安全 overlay、不更新、不接新片或按调度处置），不向其他腔传播，其他腔照常闭环。这与 EDA 多客户端/双通道隔离、E40 多腔资源独立的思想一致：把异常限制在最小域，避免一个腔问题拖停整台设备/整条闭环；同时清晰上报哪腔被隔离、原因与影响片。
7. **共享主档+每腔 overlay 如何一致且可追溯**：一致——所有腔用同一版本 recipe 主档保证工艺标准统一，R2R 只在各自腔作用域内叠加小幅 overlay 把本腔拉到同一目标 T，于是"标准统一、输出一致"，无论片过哪个腔结果都达标；可追溯——主档版本全局统一记录，每腔 overlay 单独记录（腔 id、控制器、依据量测片/run、from→to、生效时间），结合 E90/E40/E94 的片-腔谱系，任何一片都能回溯"它在哪个腔、用了哪个主档版本+哪份腔 overlay、当时量测多少、为何这么调"，既一致又可逐片逐腔审计。

## 二、参考实现（net8.0）：多腔 R2R

```csharp
namespace EapLab.R2r.Multi;
using EapLab.R2r;
public sealed class ChamberCtrl
{
    public string Id{get;}readonly EwmaController _ewma;public bool Frozen{get;private set;}
    public ChamberCtrl(string id,double target,double b,double u0)
    {Id=id;_ewma=new EwmaController(target,b,0.4,u0,maxStep:10,dead:0.05,lo:0,hi:200);}
    public double? Update(double y,double usedU,bool reliable)
    { if(Frozen)return null;return _ewma.Update(y,usedU,reliable); }
    public void Freeze(){Frozen=true;}public void Reset(double u0){Frozen=false;}
    public double Output{get;private set;}public void SetOutput(double y){Output=y;}
}
public sealed class MultiChamberR2R
{
    public Dictionary<string,ChamberCtrl> Chambers{get;}=new();public double Target{get;}
    public MultiChamberR2R(double target,params string[] ids){Target=target;
        foreach(var id in ids)Chambers[id]=new ChamberCtrl(id,target,1.0,u0:target);}
    // 量测按腔归属更新, 返回各腔下一run设定; reliable=false模拟缺测/异常
    public Dictionary<string,double?> RunOnce(Dictionary<string,(double y,double usedU,bool ok)> meas)
    { var next=new Dictionary<string,double?>();
        foreach(var(id,c)in Chambers)
        { if(meas.TryGetValue(id,out var m)){var nu=c.Update(m.y,m.usedU,m.ok);next[id]=nu;c.SetOutput(m.y);}
          else next[id]=null; }
        return next; }
    public double ChamberSpread()=>Chambers.Values.Max(c=>c.Output)-Chambers.Values.Min(c=>c.Output);
    public void FreezeChamber(string id){Chambers[id].Freeze();}
}
```

### xUnit（综合案例）
```csharp
public class MultiChamberTests
{
    // 4腔初始偏置不同、漂移不同, 逐run收敛到目标、腔间差缩小
    [Fact] public void 多腔独立补偿_收敛且腔间差缩小()
    { var m=new MultiChamberR2R(100,"C1","C2","C3","C4");
        double[] bias={3,-2,1,0};var used=new(){["C1"]=100.0,["C2"]=100.0,["C3"]=100.0,["C4"]=100.0};
        double spread0=0;
        for(int r=0;r<25;r++){
          var meas=new Dictionary<string,(double,double,bool)>();
          for(int i=0;i<4;i++){var id="C"+(i+1);
            double y=used[id]+bias[i];bias[i]*=0.9; // 输出=设定+偏置, 偏置缓漂
            meas[id]=(y,used[id],true);}
          var nx=m.RunOnce(meas);
          if(r==0)spread0=m.ChamberSpread();
          foreach(var id in nx.Keys)if(nx[id] is double v)used[id]=v;
        }
        foreach(var c in m.Chambers.Values)Assert.True(Math.Abs(c.Output-100)<2);
        Assert.True(m.ChamberSpread()<spread0);
    }
    [Fact] public void 单腔冻结_不影响其他腔()
    { var m=new MultiChamberR2R(100,"C1","C2");m.FreezeChamber("C1");
      var nx=m.RunOnce(new(){["C1"]=(105,100,true),["C2"]=(104,100,true)});
      Assert.Null(nx["C1"]);Assert.NotNull(nx["C2"]); }
    [Fact] public void 某腔缺测保持_其余照常()
    { var m=new MultiChamberR2R(100,"C1","C2");
      var nx=m.RunOnce(new(){["C2"]=(104,100,true)}); // C1无数据
      Assert.Null(nx["C1"]);Assert.NotNull(nx["C2"]); }
}
```

## 三、多腔控制与归属（手绘参考）
```
             共享: recipe主档(同版本) / 目标T / 算法 / 控制限规则
        ┌──────────────┬──────────────┬──────────────┐
      C1腔            C2腔            C3腔            C4腔
 独立EWMA状态     独立EWMA状态     独立EWMA状态     独立EWMA状态
 独立overlay      独立overlay      独立overlay      独立overlay (作用域=腔)
     ▲               ▲               ▲               ▲
量测归属(片→腔): E90 SlotMap+E40/E94作业谱系 决定片在哪个腔, 取该腔当时u算残差
     │               │               │               │
 各腔输出→ C2O各自对T ; C2C腔间对齐 ; 监控腔间差(撞限=硬件问题→保养)
异常隔离: 某腔Hold/缺测/撞限→只冻结该腔(保持安全overlay/停接片), 其他腔继续
保养换件: 该腔状态重置+撤overlay回新基线+工程片重建 ; 全程按腔审计可逐片追溯
```

## 四、今日易错点
1. 多腔用一份统一 overlay，补一腔带偏其他腔。
2. 混淆 C2C（腔间对齐）与 C2O（各腔对目标）。
3. 量测不按片→腔归属，用错腔结果更新（越调越乱）。
4. 腔间差撞限还想靠 R2R 补（实为硬件问题，应保养）。
5. 保养/换件后不重置该腔状态，旧 overlay 错套新硬件。
6. 一个腔异常冻结全部腔（应故障域隔离）。
7. 主档不统一导致"标准不一致"，或每腔 overlay 不单独审计导致不可追溯。
8. 一片过多腔时错误地把结果只归给最后一个腔。
