# W31 · Day04 答案与参考实现

## 一、自测题标准答案
1. **三种量测特点**：inline/集成量测在设备内或线边，速度快、可逐片（接近全检）、时延小，但可测项目与精度有限；offline/独立量测机/实验室精度最高、项目全，但慢、成本高、通常抽检且时延达数小时/数批；VM 虚拟量测用过程特征模型即时预测，零额外物理量测、可全检每片、最快，但本质是预测、带误差与置信度，需实测校准。三者在速度、覆盖率、精度上权衡：inline 快而有限、offline 准而稀疏滞后、VM 全而需背书，R2R 通常融合使用。
2. **抽检无量化/不插值硬调**：无有效量测的 run 应**不更新控制器状态、沿用上一有效且安全的设定（hold-last-good）**，等下一条有效量测再更新。不能插值/猜测硬调，因为 R2R 的每次调节都应基于真实反馈，插值是虚构反馈，一旦插值偏差会把噪声当趋势、引入错误补偿并逐批累积，甚至振荡发散；没有观测就没有依据，正确做法是保持并标记"本 run 未更新/依据上一设定"，保证调节可追溯、不被假数据驱动。
3. **offline 晚两批的更新流程**：①量测带 run 序号/片/腔与当时下发设定 u 到达；②按 run 序号**归位**到产生它的那一 run（不是当前 run），取当时存档的 u 算残差 y-b·u；③按时间序把这条迟到更新并入控制器状态（EWMA 可用对应历史点重算/带序更新），再与之后已发生 run 的更新对齐；④若期间已发生工况/recipe 切换导致旧量测不再适用，则只记录不用于当前控制；⑤全程标注量测来源与到达延迟，审计可查。核心是"旧账对旧设定、按序归位"，绝不拿迟到结果对当前新设定。
4. **超界且与 VM 背离**：先判为**可疑量测**，不直接用于更新控制器（避免坏值带偏 EWMA）。处理：①物理合理性检查（超设备/工艺物理可能范围直接剔除）；②与高置信 VM、相邻片/腔结果交叉验证；③请求复测/确认量测设备状态；若复测一致则可能是真实突变（此时还要结合 FDC 是否有异常），确认坏则剔除并记数据质量事件，确认真实则按异常工况处理（可能需要停自动/人工）。在确认前控制器保持上一安全设定，不用单条可疑值大动作。
5. **融合优先级/权重/低置信**：实测（尤其高精度 inline/offline）可信度最高、优先作为控制依据，并用"实测−VM 预测"偏差去校正 VM 模型；无实测时，仅当 VM 置信度高才用其更新，且权重低于实测/采用更保守步长（因为是预测）；VM 低置信度时不单独作为控制依据，回退为保持设定、等实测；两者都无则保持。融合结果必须带来源（实测/VM）与置信度，审计能知道每 run 的控制依据；实测一到就以实测为准修正此前用 VM 做的更新。
6. **监控 Δu/单向增大含义**：R2R 控制器假设慢漂移可被小幅补偿拉回，正常情况下补偿量 Δu 应在一定范围内上下波动、长期均值稳定。若 Δu 持续单向增大（或残差带趋势、补偿频繁撞步长/控制限），说明控制器在"追一个它追不上的变化"——可能设备在持续劣化（积膜、耗材磨损、增益漂移）、过程模型失配（b 变了）、或传感器/量测偏置；这不是再调参数能解决的，应报警提示设备保养/模型重训/检修，而不是让 R2R 盲目把设定越推越远直到撞限废片。补偿量是设备健康的晴雨表（与 W25 RAM、W32 SPC 呼应）。
7. **连续无有效量测/原因**：达到预设阈值（如连续 N 个 run 无可靠实测且无高置信 VM）应**停止自动 R2R、保持最后安全设定并报警转人工**。因为控制器已失去反馈、处于开环运行，开环下设备漂移无人纠正，继续自动等于盲调，风险随批次累积；停自动可防止在无观测下产生错误补偿，由人工检查量测链路/VM/设备后再恢复，并对开环期间产品按风险评估处置。

## 二、参考实现（net8.0）：量测融合 + 守门

```csharp
namespace EapLab.R2r.Fusion;
public sealed record Measure(int Run,string Chamber,double UsedU,double? Real,double? Vm,double? VmConf,bool PhysicallyValid=true);
public enum MeasureSource{ None,Real,Vm }
public sealed record Fused(double? Y,MeasureSource Src,double Weight,string Note);

public sealed class MeasurementFusion
{
    readonly double _vmConfThr;public int ConsecutiveNoValid{get;private set;}readonly int _stopAfter;
    public MeasurementFusion(double vmConfThr=0.8,int stopAfter=3){_vmConfThr=vmConfThr;_stopAfter=stopAfter;}
    public bool AutoHalted{get;private set;}

    public Fused Fuse(Measure m)
    { if(!m.PhysicallyValid){return Suspect("physically impossible");}
        // 1 实测优先
        if(m.Real is double r){ConsecutiveNoValid=0;return new Fused(r,MeasureSource.Real,1.0,"real wins; calibrate VM");}
        // 2 高置信VM补盲(保守权重)
        if(m.Vm is double v&&m.VmConf is double c&&c>=_vmConfThr){ConsecutiveNoValid=0;return new Fused(v,MeasureSource.Vm,c*0.7,"VM fallback");}
        // 3 都没有/低置信: 不更新(hold-last-good)
        if(++ConsecutiveNoValid>=_stopAfter)AutoHalted=true;
        return new Fused(null,MeasureSource.None,0,AutoHalted?"halt auto, manual":"hold last good"); }
    // 实测与VM背离检测
    public bool Conflict(Measure m,double tol)=>m.Real is double r&&m.Vm is double v&&Math.Abs(r-v)>tol;
}
```

### xUnit
```csharp
public class FusionTests
{
    [Fact] public void 实测优先于VM()
    { var f=new MeasurementFusion();var r=f.Fuse(new Measure(1,"C1",60,Real:101.2,Vm:103,0.99));
      Assert.Equal(MeasureSource.Real,r.Src);Assert.Equal(1.0,r.Weight); }
    [Fact] public void 无实测_高置信VM补盲_权重保守()
    { var f=new MeasurementFusion(0.8);var r=f.Fuse(new Measure(1,"C1",60,null,Vm:101,VmConf:0.9));
      Assert.Equal(MeasureSource.Vm,r.Src);Assert.True(r.Weight<1.0); }
    [Fact] public void 低置信VM不控制_保持()
    { var f=new MeasurementFusion(0.8);var r=f.Fuse(new Measure(1,"C1",60,null,Vm:101,VmConf:0.4));
      Assert.Equal(MeasureSource.None,r.Src);Assert.Null(r.Y); }
    [Fact] public void 连续无有效量测达阈值停自动()
    { var f=new MeasurementFusion(0.8,stopAfter:3);
      for(int i=0;i<3;i++)f.Fuse(new Measure(i,"C1",60,null,null,null));
      Assert.True(f.AutoHalted); }
    [Fact] public void 物理不可能判可疑不用于控制()
    { var f=new MeasurementFusion();var r=f.Fuse(new Measure(1,"C1",60,Real:99999,null,null,false));
      Assert.Null(r.Y); }
    [Fact] public void 实测与VM超差判冲突()
    { var f=new MeasurementFusion();Assert.True(f.Conflict(new Measure(1,"C1",60,100,108,0.9),tol:3)); }
}
```

## 三、量测融合决策流（手绘参考）
```
量测到达(带run/腔/片 + 当时usedU + 时间戳)
  → 物理合理性? 否→可疑,剔除+数据质量事件, 保持设定
  → 与高置信VM/邻片一致? 严重背离→复测/交叉确认前不更新
  → 有实测? 是→以实测为准(权重1), 同时(实测-VM)校正VM模型
            否→VM置信≥阈值? 是→VM补盲(保守权重, 标来源) ; 否→不更新hold-last-good
  → 按run序号归位对齐当时u算残差(offline晚到按序重放, 工况已变则只记录)
  → 送EWMA/dEWMA更新→控制律→限幅→overlay
守门: 连续N次无有效量测→停自动转人工; 残差/Δu序列送SPC:
  Δu单向增大/撞限/非随机趋势→模型失配或设备劣化→保养/重训, 不盲目补偿
原则: 无观测不调节; 实测>高置信VM>保持; 每次控制依据可追溯来源
```

## 四、今日易错点
1. 抽检无量测时插值/猜测硬调（应 hold-last-good 不更新）。
2. offline 迟到量测对当前新设定算残差（应归位对当时 u、按序重放）。
3. 单条超界量测直接更新，把坏值当漂移（应交叉验证/剔除）。
4. 低置信 VM 当实测用于闭环控制。
5. 有实测不用、仍以 VM 为准（应实测优先并校正 VM）。
6. 融合结果不带来源/置信度，事后无法追溯控制依据。
7. 不监控 Δu/残差序列，控制器失配还在盲目补偿直到撞限。
8. 长期开环（无反馈）仍继续自动 R2R，应达阈值停自动转人工。
9. 量测不绑腔/片/当时 overlay 生效值，无法对齐与归因。
