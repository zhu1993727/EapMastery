# W31 · Day04（周四）R2R 的量测体系：实测/VM 融合、缺失异常处理与 SPC 守门

> 建议时长：95 分钟。R2R 的输入是量测，量测质量决定控制质量。今天梳理量测来源（inline/offline 实测、VM 虚拟量测）、全检/抽检与延迟对齐，重点掌握量测缺失、延迟、异常、VM 低置信度时控制器的正确策略，以及如何用 SPC 监控控制器本身（残差/补偿序列），为 W32 VM/SPC 铺路。

## 一、今日目标

## 二、背景知识（先读，40 分钟）

### 1. 量测来源与时效
- **inline/集成量测**：设备内或线边量测，快、可逐片，但精度/项目有限。
- **offline/standalone 量测**：独立量测机/实验室，精度高但慢、常抽检、延迟数小时/数批。
- **VM 虚拟量测**：用 EDA 过程特征 + 模型即时预测每片输出（W32 细讲），零额外物理量测、全覆盖，但带预测误差与置信度。
- R2R 希望量测又快又全又准，现实是三者权衡，因此需要融合。

### 2. 全检/抽检与控制粒度
- 全检（每片/每 run 都有值）控制最及时；抽检（每隔几片/批）导致部分 run 无反馈，控制器要在"无新量测"时保持设定而非乱调。
- VM 可把抽检"补成"全检（对未实测片给预测），但要标置信度。

### 3. 量测-控制对齐（再强调，配合 Day02）
- 每条量测必须带：目标对象（设备/腔/Lot/片/run）、产生时所用设定 u、时间戳；更新控制器时用对应当时 u 算残差。
- 乱序到达（offline 晚到）要按 run 序号归位，可重放/按序更新，不能用旧量测污染最新状态。

### 4. 量测异常与缺失策略（核心）
- **缺失（本 run 无量测）**：不更新 EWMA 状态、沿用上一安全设定（hold-last-good），不凭空调；等下一条有效量测。
- **延迟**：按 run 归位对齐后更新；若延迟过久、工况已切换，评估是否还适用，必要时丢弃或仅记录。
- **异常量测（超物理界/与 VM 或邻片严重背离）**：标记可疑，不直接用于更新（或降权），请求复测/用 VM 交叉验证，确认坏则剔除并计数据质量事件（呼应 FDC 质量门控）。
- **VM 低置信度**：不单独作为控制依据（或大幅降权），回退到等实测；高置信 VM 才可补盲。
- **连续缺失/异常**：达到阈值停止自动 R2R、转人工（Day02 安全兜底）。

### 5. 实测与 VM 融合（fusion）
- 有实测：以实测为准更新，同时用实测-预测偏差校正 VM 模型/作为状态高权重输入。
- 无实测有高置信 VM：用 VM 更新（权重低于实测，或保守步长）。
- 都无：保持。融合输出带"来源+置信度"，审计可区分本 run 控制依据是实测还是预测。

### 6. 用 SPC 监控控制器（W32 前瞻）
- R2R 也会"坏"：过程增益漂移、模型失配、传感器偏置会让补偿量 Δu 持续单向增大或残差出现趋势/越控制限。
- 对残差 e、估计状态 a、补偿 Δu 画控制图（EWMA 图/运行图），出现非随机趋势、连续同侧、超控制限即报警：不是工艺输出问题就是模型/设备问题，触发模型重训或设备保养，而不是让 R2R 盲目继续补偿（补偿量本身是设备健康的晴雨表，Δu 撞限=设备需要干预）。

### 7. 设备端 EAP 相关职责
- 保证量测关联的过程数据/上下文完整（哪片哪腔、当时 overlay 生效值），上报量测结果或 VM 输入特征时时间/对象对齐；记录每 run 控制依据来源。
