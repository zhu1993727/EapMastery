# W31 · Day01 答案与参考实现

## 一、自测题标准答案
1. **解决什么/为何批间**：R2R 补偿缓慢过程漂移——设备老化、腔体积膜/损耗、耗材衰减、腔间差异、来料与环境变化使相同设定的输出（膜厚/CD/overlay）逐渐偏离目标，R2R 每完成一个 run、拿到量测后自动微调下一个 run 的设定，把输出拉回目标、压缩批间方差。以批为周期是因为：①控制依据是量测结果，而量测（或可靠 VM）通常在 run 结束后才有；②这些漂移是慢变过程，不需要也不应该在 run 进行中实时抖动设定（run 内稳定才能保证一致性，实时干预是 FDC/设备底层回路的事）；③批间调整安全、可审计、步长可控，避免高频调节引发振荡。
2. **反馈/前馈/例子**：反馈是"看本 run 结果误差，调下一 run"，事后纠偏，例：CMP 本批抛后测厚度偏厚，下批略微增加抛光时间/压力；光刻本批 overlay 有 +X 系统性偏移，下批给反向补偿。前馈是"加工前先测到来料/上游扰动，提前调本 run 设定"，不等结果，例：光刻前测得前道图形/晶圆畸变（incoming overlay），本次曝光直接给对应场校正；CMP 前测到来料膜偏厚，本 run 预先加时。二者常结合：前馈抵消可预知的来料差异，反馈兜住剩余慢漂移。
3. **闭环环节/overlay 路径**：①设备按"recipe 基线+overlay"加工 run；②量测（metrology/inline 或 VM）得输出 y；③状态估计（EWMA 等估当前漂移）；④控制器按目标 T 与估计算下一 run 补偿 Δu（受步长/控制限约束）；⑤生成 overlay，经 **RMS 校验（不改主配方、版本授权）→EAP/Host→GEM 远程命令(S2F41/参数下发)** 到设备；⑥设备在 run 前/片间写入、校验范围、执行并以 S6F11 回告生效（受理≠生效），再加工下一 run 形成闭环。通道上：过程/结果数据上行走 EDA/GEM，补偿下行只走 GEM 控制面。
4. **R2R vs FDC**：时间尺度——FDC 在 run 加工进行中实时（秒/亚秒）监测，R2R 在 run 与 run 之间（批级）更新设定；目的——FDC 检测/分类突发异常、保安全（可建议 Hold/Stop），R2R 补偿慢漂移、让输出持续逼近目标、提升一致性；动作性质——FDC 是"发现不对并告警/建议干预"，一般不改设定，R2R 是"正常工况下持续微调设定"的优化控制；一个 run 中 FDC 盯安全、R2R 在 run 间优化，二者互补不替代。
5. **不改主档/与 RMS 分工**：recipe 主档是经过工艺验证、版本受控、对产品/工艺法定的基准，若 R2R 每批都直接改主档，会破坏可追溯与验证基线、不同 Lot/腔互相污染、无法审计"当时到底用了什么"。R2R 只产生**小幅、受控、带有效期/作用域（指定腔/Lot/片）的 overlay 补偿**，运行时叠加在主档上（实际设定=主档基线+overlay），主档保持不变。RMS 负责主档与参数的版本、审批、校验、下发与留痕；R2R 负责算补偿，补偿要经 RMS 校验授权、在步长/界限内才放行。
6. **VM 作用/没有会怎样**：R2R 更新依赖量测，而实体量测机台慢、常是抽检、有时滞后好几批，导致 R2R 更新稀疏、延迟，甚至过补偿/振荡。VM 用过程参数（EDA trace 特征）模型预测每片/每 run 的输出，给 R2R 提供快速、密集（可每片）、低成本的"虚拟量测"，让闭环更快更密、覆盖未抽检片，并在等量测期间先用 VM、实测回来再校正。没有 VM，R2R 只能靠稀疏滞后的实测，对快漂移响应慢、控制粒度粗、异常片发现晚；VM 置信度低时仍须回退到实测量测（W32 细讲）。
7. **EAP 职责**：①数据——经 EDA/GEM 提供 R2R 所需过程特征与结果、带齐 Lot/Job/Step/腔/片上下文与统一时钟（拿得到、对得齐）；②接收与校验——在 run 开始前/片间正确接收经 RMS/EAP 下发的 overlay，校验参数范围/作用域/版本，拒绝越界或无授权修改，且绝不改 recipe 主档；③生效确认——把 overlay 写入并以迁移/状态事件（S6F11）确认真正生效（受理≠生效），未生效不开始加工并回告；④可追溯——记录每 run 的主档版本、overlay 前后值、来源、Lot/腔/片，形成闭环谱系；⑤隔离——overlay 只经 GEM 控制面，EDA 只读。

## 二、参考实现（net8.0）：R2R 回路骨架

```csharp
namespace EapLab.R2r;
public sealed record Measurement(string RunId,double Y,double? FeedforwardDisturbance,bool FromVm);
public sealed record Overlay(string RunId,double DeltaU,string Source,bool Applied);

public interface IController{ double Compute(double target,double? estState,double? ff); }
// 最简比例反馈+前馈(Day02换EWMA): u = gain*(target-state)+ffGain*ff
public sealed class PWithFeedforward:IController
{ readonly double _k,_ff,_maxStep;
    public PWithFeedforward(double k,double ff,double maxStep){_k=k;_ff=ff;_maxStep=maxStep;}
    public double Compute(double t,double? s,double? ff)
    { double du=_k*(t-(s??t))+(ff is null?0:_ff*ff.Value);
        return Math.Clamp(du,-_maxStep,_maxStep); } } // 步长限幅, 防过补偿

public sealed class R2rLoop
{
    double _setpoint;readonly IController _c;public string RecipeBaseline{get;}
    public double LastState{get;private set;}public List<Overlay> History{get;}=new();
    public R2rLoop(double setpoint,string baseline,IController c){_setpoint=setpoint;RecipeBaseline=baseline;_c=c;}
    // 一个run结束: 量测→估计→算下一run overlay(不下发主档, 只产出补偿)
    public Overlay NextRun(string runId,Measurement m)
    { LastState=Estimate(m.Y);                                   // 状态估计(Day02 EWMA)
        double du=_c.Compute(_setpoint,LastState,m.FeedforwardDisturbance);
        return new Overlay(runId,du,m.FromVm?"VM":"Metrology",false); }
    // 设备侧: 校验范围并"应用"(教学), 实际=主档+overlay, 经GEM确认生效
    public (bool ok,double actual) Apply(Overlay o,double low,double high)
    { var actual=BaselineValue()+o.DeltaU;
        if(actual<low||actual>high)return(false,actual);          // 越界拒绝, 不改主档
        History.Add(o with{Applied=true});return(true,actual); }
    double BaselineValue()=>100; // 教学: recipe主档基线设定
}
```

### xUnit
```csharp
public class R2rLoopTests
{
    [Fact] public void 输出偏高_下一run给负补偿拉回目标()
    { var loop=new R2rLoop(100,"RC-v3",new PWithFeedforward(0.5,0,10));
      var o=loop.NextRun("R2",new Measurement("R1",104,null,false)); // 上run=104>目标100
      Assert.True(o.DeltaU<0); }
    [Fact] public void 前馈来料偏差_加工前提前补偿()
    { var loop=new R2rLoop(100,"RC-v3",new PWithFeedforward(0.5,1.0,10));
      var o=loop.NextRun("R1",new Measurement("R0",100,2.0,false));  // 状态正好但来料+2
      Assert.True(o.DeltaU>0); }
    [Fact] public void 步长限幅防过补偿()
    { var loop=new R2rLoop(100,"RC-v3",new PWithFeedforward(1.0,0,5));
      var o=loop.NextRun("R1",new Measurement("R0",130,null,false)); // 误差30
      Assert.Equal(-5,o.DeltaU); }
    [Fact] public void overlay越界被拒_主档不变()
    { var loop=new R2rLoop(100,"RC-v3",new PWithFeedforward(1,0,50));
      var o=loop.NextRun("R1",new Measurement("R0",160,null,false));
      var(ok,_)=loop.Apply(o,90,110);Assert.False(ok);Assert.Empty(loop.History); }
    [Fact] public void 闭环逐步收敛到目标()
    { var loop=new R2rLoop(100,"RC-v3",new PWithFeedforward(0.6,0,20));double y=108;
      for(int i=0;i<8;i++){var o=loop.NextRun("R"+i,new Measurement("R"+i,y,null,false));
        var(_,actual)=loop.Apply(o,0,200);y=actual-2;} // 简化过程: 补偿后输出回移
      Assert.True(Math.Abs(loop.LastState-100)<3); }
}
```

## 三、R2R 闭环（手绘参考，要求默画）
```
目标T(MES规格) ─┐
              ▼
设备加工run(recipe主档基线 + overlay) ──▶ 量测(Metrology/VM预测) ──▶ 输出y
              ▲                                        │
              │ overlay(Δu,受控小幅,作用域)             ▼
         RMS校验(不改主档)→EAP→GEM S2F41  ◀ 控制器(限幅) ◀ 状态估计(EWMA) ◀ 误差e=T-y
              │ 受理≠生效, S6F11确认
         设备run前/片间写入+范围校验+谱系(主档版本/前后值/Lot/腔/片)
前馈: 加工前测来料/上游扰动 ──提前补偿本run ; 反馈: 本run结果调下run
边界: FDC=run中实时保安全; R2R=run间慢漂移; RMS=主档版本; VM=快速量测; SPC=统计监控不直接控
铁律: 上行EDA/GEM, 下行overlay只走GEM控制面; 主配方永不被R2R直接改
```

## 四、今日易错点
1. 把 R2R 当实时控制（它是批间慢控制，run 内不抖设定）。
2. 分不清反馈/前馈（反馈看结果事后纠偏、前馈看来料提前补偿）。
3. 以为 R2R 直接改 recipe 主档（只叠加受控 overlay，主档不变）。
4. 混淆 R2R 与 FDC（一个优化一致性、一个实时保安全）。
5. 忽视 VM 作用，只用稀疏滞后实测导致响应慢/过补偿。
6. overlay 不经 RMS 校验/EAP→GEM，想从数据面直接下发。
7. 控制器无步长限幅，大误差一步过补偿引发振荡。
8. 只看 S2F42 受理就当 overlay 生效（要 S6F11/状态确认，未生效不得加工）。
9. 不记录每 run 主档版本与 overlay 谱系，事后无法追溯实际设定。
