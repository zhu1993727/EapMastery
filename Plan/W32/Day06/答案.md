# W32 · Day06 答案与参考实现

## 一、自测题标准答案
1. **五类监控对象**：①关键工艺/质量特性（膜厚、CD、overlay、刻蚀深度等 CTQ，按腔/产品分层）；②关键过程输入参数（稳定段温度/压力/功率的均值与波动）；③VM——预测值分布与 VM−实测残差（监控模型漂移、PI 覆盖率）；④R2R 控制器自身——补偿量 Δu 序列、估计状态 a、控制残差/误差（判控制器是否在硬扛或失配）；⑤设备度量与健康——E10/E116 状态时长、循环次数、耗材寿命等长期趋势（预测性维护）。统一由 SPC 判稳、异常转工程/保养/重训。
2. **FDC/SPC/R2R 分工**：时间尺度上 FDC 是 run 进行中的秒/亚秒级实时，R2R 是 run 与 run 之间的批级，SPC 是跨多 run/批的长期统计尺度。职责上 FDC 检测并分类**突发异常**、保设备与产品安全（可建议 Hold）；R2R 在过程**受控前提下**自动做小幅补偿、对中慢漂移；SPC **只监控判稳与能力**、不直接控制，发现非随机模式或能力下降就触发工程干预/停自动/重训/保养。一句话：FDC 管"这会儿有没有出事"，R2R 管"下一批往哪微调"，SPC 管"长期看稳不稳、行不行"。
3. **受控是 R2R 前提**：R2R 的 EWMA 模型假设输出偏差主要来自可预测的慢漂移（普通原因），这样"看结果微调下批"才成立。若过程失控、存在特殊原因（突发跳变、方差不稳、混腔），量测偏差不再是慢漂移而是异常事件，R2R 会把特殊原因误当漂移去补偿，越补越乱、掩盖真问题甚至撞限。因此先用 SPC 确认统计受控、FDC 无严重异常，R2R 才安全自动运行；一旦失控/严重 FDC 报警就暂停 R2R，排除特殊原因后再恢复。
4. **Δu 单调上升未撞限**：说明为了把输出拉回目标，控制器需要的补偿在持续增大，设备正朝一个方向持续劣化（电极磨损、积膜、耗材衰减、热漂移），R2R 在"硬扛"本应由维护解决的问题。虽暂未撞限，但趋势外推必然到限，应在撞限前预警：按 SPC 趋势/同侧规则报警→评估并安排预测性保养/清洁/更换→必要时提前冻结该腔自动、转人工，避免等撞限废片才被动停机；保养后按 W31 重置该腔状态。
5. **残差趋势的原因/处置**：R2R 控制残差（输出−目标）本应在零附近随机，若出现持续趋势/周期，可能：①过程增益 b 变化（设备老化使"设定对输出的影响系数"漂移，原控制器增益失配）；②量测/VM 出现偏置或漂移（传感器、量测机、VM 模型失准）；③存在未建模扰动（来料系统性变化、新的热/真空状态）；④recipe/工况切换后未重初始化。处置：先排查量测链与 FDC，确认数据可信；再重新整定控制器增益/EWMA 参数或重训 VM；若为设备问题转维护；期间对相应（腔）冻结自动 R2R、保持安全设定，确认恢复后重新基线化。
6. **分层/混层后果**：不同腔、产品、recipe、设备的固有均值和方差不同，SPC 控制限是针对"同一总体"估计的，必须按这些维度分层各建各的图（与 W31 每腔独立 R2R、Day05 交替规则一致）。混层会：①把多个不同均值的总体混在一起，人为增大 σ、控制限过宽，真异常被淹没（漏报）；②不同总体交替进入形成锯齿/双峰等假模式（误报），找不到根因；③能力指数被混合分布扭曲。分层后才能看清每个腔/产品真实的稳与不稳，异常也才定位得到来源。
7. **对 OEE 的影响**：SPC 失控/Cpk 不足会从三方面拉低 OEE：质量率 Q——失控产生超差品、报废返工，直接降低良品率；可用率 A——特殊原因异常导致非计划 Hold/停机抢修，增加宕机时间；性能 P——为规避风险降速、频繁调机/复测降低实际产出节奏。反之过程稳定受控、Cpk 高则质量损失少、异常停机少、节奏稳定，OEE 高；R2R+SPC 把突发失控转成受控的小幅调节与计划内预测性保养。链条上 E116 记录过程时间、E10 归类设备状态、SPC 判过程稳定性与能力、OEE 汇总成 A×P×Q 结果指标。

## 二、参考实现（net8.0）：R2R 控制器健康监控

```csharp
namespace EapLab.Spc;
using EapLab.Spc;
public enum Health{ Ok,Warning,Frozen }
public sealed class HealthEvent(string kind,string action);
public sealed class ControllerHealthMonitor
{
    readonly RulesEngine _duRules,_resRules;public Health State{get;private set;}=Health.Ok;
    public List<string> Actions{get;}=new();
    public ControllerHealthMonitor(double duCl,double duSigma,double resCl,double resSigma)
    {_duRules=new RulesEngine(duCl,duSigma);_resRules=new RulesEngine(resCl,resSigma);}

    // 每次R2R更新后喂入 补偿量Δu 与 残差; fdcCritical时立即冻结
    public Health Observe(IReadOnlyList<double> duSeq,IReadOnlyList<double> resSeq,bool fdcCritical=false)
    { if(fdcCritical){Freeze("FDC critical: pause R2R");return State;}
        var duV=_duRules.Evaluate(duSeq);var resV=_resRules.Evaluate(resSeq);
        bool duTrend=duV.Any(v=>v.Rule is 2 or 3);      // 单侧/单调: 设备劣化
        bool resTrend=resV.Any(v=>v.Rule is 2 or 3);    // 残差趋势: 模型/增益失配
        bool hitLimit=duV.Any(v=>v.Rule==1);            // 撞控制限
        if(hitLimit)Freeze("compensation exhausted: stop auto, maintenance");
        else if(duTrend)Warn("du drift: schedule predictive maintenance; reset after");
        else if(resTrend)Warn("residual trend: retune gain / retrain VM");
        return State; }
    void Warn(string a){if(State==Health.Ok){State=Health.Warning;Actions.Add(a);}}
    void Freeze(string a){State=Health.Frozen;Actions.Add(a);}
    public void RecoverAfterReset(){State=Health.Ok;Actions.Clear();}
}
```

## 三、FDC-SPC-R2R 协作升级流（手绘参考）
```
EDA/GEM数据 ─┬─ FDC(run中,秒级): 突发异常→分类→(critical)建议Hold ──┐
             ├─ R2R(run间,批级): 受控下EWMA补偿慢漂移→overlay→GEM  │
             └─ SPC(跨批,统计): 工艺/质量/VM残差/Δu/设备度量 判稳+能力
协作: SPC受控 & FDC无critical = R2R自动运行前提
  FDC critical → 立即冻结该(腔)R2R, 先排特殊原因
  SPC看Δu: 随机平稳=OK ; 单侧/单调=设备劣化→预警预测性保养 ; 撞限=补偿耗尽→停自动维修
  SPC看残差: 趋势/周期=增益失配/量测偏置/VM漂移→重整定/重训
  处置: 冻结(腔)→报警/工单→人工确认→保养/重训→重置基线→恢复
分层: 按腔/产品/recipe各建图(混层漏报+误报)
度量闭环: E116记过程→E10定状态→SPC判稳/Cpk→OEE=A×P×Q(失控拉低Q/A/P)
```

## 四、今日易错点
1. 混淆三者时间尺度与职责（想用 SPC 实时停设备、或让 R2R 处理突发故障）。
2. 过程失控还让 R2R 继续自动补偿特殊原因。
3. 只监控产品质量，不监控 R2R 的 Δu/残差（控制器带病运行到撞限）。
4. Δu 单调上升只当正常补偿，不做预测性保养预警。
5. 残差趋势一律归因工艺，忽略量测/VM 偏置与增益失配。
6. 控制图不按腔/产品分层，混层造成漏报/误报。
7. 认为 SPC 能直接控制设备（它只判稳，控制归 R2R/GEM）。
8. 割裂 SPC 与 OEE，看不到失控对 A/P/Q 的传导。
9. 保养/重训后不重置控制器基线就恢复自动。
