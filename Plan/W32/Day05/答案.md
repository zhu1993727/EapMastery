# W32 · Day05 答案与参考实现

## 一、自测题标准答案
1. **判异规则与异常（≥6）**：①一点超 ±3σ——突变/严重偏移或单点故障；②连续 9 点在中心线同侧（Nelson2/WE 连续 8 同侧）——均值发生偏移、未对中；③连续 6 点单调递增或递减——趋势（工具磨损、耗材衰减、缓慢漂移）；④连续 14 点交替上下——两个总体交替（两腔/两工位未正确分组、周期振荡）；⑤连续 3 点中 2 点落在同侧 2σ 外——中等程度均值偏移；⑥连续 5 点中 4 点在同侧 1σ 外——小幅持续偏移；⑦连续 15 点全在 ±1σ 内——变异异常小，多为分层/数据被处理/子组混合问题；⑧连续 8 点在 1σ 外（两侧）——双峰/混合总体。越界抓突变，排列规则抓"没越界但已非随机"的偏移、趋势与分层。
2. **15 点挤在中心为何异常**：受控过程本应有约 1/3 的点落在 1σ–3σ 之间，连续 15 点全在 ±1σ 内的概率极低，说明波动被"异常地压小"，常见原因不是工艺突然变好，而是：采样/子组把不同总体平均掉了（分层，如把多个腔混在一组取平均）、数据被人为筛选/四舍五入、控制限算错（σ 估大）、测量分辨率不足。它提示数据结构或测量有问题，会掩盖真实变异，必须查采样与测量系统。
3. **交替上下的现场问题**：高低规律交替最典型是**两个不同总体在交替进入样本却没分开**——如双腔/多工位设备两片轮流来自腔 A、腔 B（两腔固有偏置不同），或两批材料、两个夹具、昼夜/班次交替、正反工位。正确做法是按腔/工位分层分别建控制图（呼应 W31 每腔独立），或检查是否存在周期性机械/控制振荡；混在一张图会形成锯齿交替，误判为异常却找不到单一根因。
4. **公式/Cp 高 Cpk 低**：Cp=(USL−LSL)/(6σ)，只衡量公差带相对固有波动够不够宽（潜在能力，不管居中）；Cpu=(USL−μ)/(3σ)、Cpl=(μ−LSL)/(3σ)，Cpk=min(Cpu,Cpl)，同时反映离散程度与均值居中。Cp 高说明波动 σ 小、"精度潜力够"，但 Cpk 低说明**均值 μ 偏离公差中心**，导致靠近一侧规格限（一侧 Cpu 或 Cpl 很小）。办法是把均值对中（正是 R2R/调机目标），对中后 Cpk 会升到接近 Cp，而不必先减小波动。
5. **Cpk 以受控为前提**：Cp/Cpk 用受控状态下的组内 σ 描述"过程稳定时固有的、可重复的能力"。若过程存在特殊原因（失控、均值在跳、方差不稳），算出的 σ 混入了异常波动、分布不稳定不可预测，此时 Cpk 没有稳定含义、会被异常带偏（可能虚高或虚低），也无法指导改进。所以先靠控制图消除特殊原因、达到统计受控，再评估能力；失控状态下先纠异常，不算能力结论。
6. **Cp/Cpk vs Pp/Ppk**：Cp/Cpk 是短期/潜在能力，σ 用**组内变异**估计（如 Rbar/d2），剔除组间特殊原因，回答"过程稳定运行时能做到多好"；Pp/Ppk 是长期/整体性能，σ 用**全部数据的整体标准差**（含组间漂移、特殊原因），回答"这段时间实际表现如何"。通常 Ppk≤Cpk，差距大说明批间/长期漂移与特殊原因多（短期行、长期不稳）。R2R 压缩批间漂移正是在缩小 Cpk 与 Ppk 的差距。
7. **R2R 改善哪个/提升 Cp 靠什么**：R2R 主要改善 **Cpk（以及 Ppk）**——它通过逐批补偿把过程均值 μ 对中到目标、抑制批间慢漂移，从而抬高 min(Cpu,Cpl)、缩小长期与短期差距；但它基本不改变单 run 内的固有随机波动 σ，所以对 Cp（只由 6σ 与公差比决定）提升有限。要提升 Cp（减小固有变异）得靠系统层面：设备精度/维护、传感器与执行器、工艺窗口优化、减小来料波动、提升测量系统等。即"R2R 负责对中与稳批间，工程改进负责降本征波动"。

## 二、参考实现（net8.0）：判异规则引擎 + 过程能力

```csharp
namespace EapLab.Spc;
public sealed record Violation(int Rule,string Name,int At);
public sealed class RulesEngine
{
    readonly double _cl,_s;public RulesEngine(double cl,double sigma){_cl=cl;_s=sigma;}
    public List<Violation> Evaluate(IReadOnlyList<double> x)
    { var v=new List<Violation>();
        for(int i=0;i<x.Count;i++)
        { if(Math.Abs(x[i]-_cl)>3*_s)v.Add(new(1,"Beyond3Sigma",i));               // R1
            if(i>=8&&SameSide(x,i-8,i))v.Add(new(2,"NineSameSide",i));            // R2 连续9同侧
            if(i>=5&&Monotonic(x,i-5,i))v.Add(new(3,"SixTrend",i));               // R3 连续6点趋势
            if(i>=14&&AllWithin1S(x,i-14,i))v.Add(new(7,"FifteenWithin1S",i)); }  // R7 分层
        return v; }
    bool SameSide(IReadOnlyList<double>x,int a,int b){bool up=x[b]>_cl;for(int i=a;i<=b;i++)if((x[i]>_cl)!=up||x[i]==_cl)return false;return true;}
    bool Monotonic(IReadOnlyList<double>x,int a,int b){bool up=x[a+1]>x[a];for(int i=a+1;i<=b;i++)if(up!=x[i]>x[i-1]||x[i]==x[i-1])return false;return true;}
    bool AllWithin1S(IReadOnlyList<double>x,int a,int b){for(int i=a;i<=b;i++)if(Math.Abs(x[i]-_cl)>_s)return false;return true;}
}
public sealed record Capability(double Cp,double Cpu,double Cpl,double Cpk,double Pp,double Ppk);
public static class CapabilityCalc
{
    public static Capability Compute(double[] x,double lsl,double usl,double sigmaWithin)
    { double mu=x.Average();
        double cp=(usl-lsl)/(6*sigmaWithin);
        double cpu=(usl-mu)/(3*sigmaWithin),cpl=(mu-lsl)/(3*sigmaWithin);
        double cpk=Math.Min(cpu,cpl);
        double sdOverall=Math.Sqrt(x.Sum(v=>Math.Pow(v-mu,2))/(x.Length-1)); // 整体σ
        double pp=(usl-lsl)/(6*sdOverall),ppk=Math.Min((usl-mu),(mu-lsl))/(3*sdOverall);
        return new Capability(cp,cpu,cpl,cpk,pp,ppk); }
}
```

public class RulesCapabilityTests

## 四、今日易错点
1. 只看越 3σ，忽视排列规则（偏移/趋势未越界也异常）。
2. 规则全开导致虚警过多，不按工艺取舍。
3. 把"15 点挤中心"当好事（实为分层/数据问题）。
4. 双腔交替不分组，锯齿图找不到根因。
5. 混淆 Cp 与 Cpk，不知 Cp 高 Cpk 低是没居中。
6. 过程未受控就算 Cpk（σ 不稳定、结论无意义）。
7. 混淆 Cp/Cpk（组内短期）与 Pp/Ppk（整体长期）。
8. 以为 R2R 能提 Cp（它主要对中提 Cpk，降本征 σ 靠工程改进）。
9. 死记 1.33 却不知其与 σ 水平/长期 1.5σ 漂移的关系。
