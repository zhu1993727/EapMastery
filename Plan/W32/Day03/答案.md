# W32 · Day03 答案与参考实现

## 一、自测题标准答案
1. **七步管线**：①EDA 采高频 trace + GEM Step marker（带腔/Lot/片/recipe 上下文）；②片结束按 Step 分段、归一化对齐、提取统计特征向量；③VM 推理出点预测 ŷ、预测区间 PI、OOD 距离与置信度；④质量门控（数据 Good、非 OOD、置信达标、作用域匹配、时效内）；⑤量测融合——有实测用实测，否则用合格 VM（保守权重），都无则保持；⑥EWMA/dEWMA 更新状态、控制律算下一 run 设定并限幅/死区/控制限，生成带作用域版本的 overlay；⑦经 RMS 校验、EAP→GEM 在安全点下发、回读确认生效，进入下一 run。实测抽检回来再回灌校正 VM、更新 R2R。
2. **全检价值/风险/控制**：价值——抽检下未测片处于"黑户"，异常要等几批后才暴露，VM 逐片出值让异常片当片预警、R2R 反馈从每几批一次加密到每片一次，控制更及时、批内/批间方差更小，并形成逐片过程画像供良率分析。风险——VM 是预测、有误差，若当精确真值直接强控/判废会误伤好片、或被错误预测带偏 R2R。控制：必须带 PI 与置信度、设门控阈值、用抽检实测持续校准与偏差校正、低置信/OOD 回退等实测、判废与最终放行等关键决策保留实测或人工确认、记录每片控制依据来源可回溯。
3. **规格限 vs 控制限**：USL/LSL 规格限来自产品/工艺设计或客户要求，是"输出合格与否"的工程边界（与过程是否稳定无关，超出即不合格品）；SPC 控制限（UCL/LCL，Day04）由过程自身的统计分布（通常均值±3σ）算出，是"过程是否处于统计受控状态"的边界，用来发现非随机异常。一个过程可以统计受控（都在控制限内）却整体偏出规格限（能力不足 Cpk 低）；二者用途、来源不同，不能混用。
4. **区间跨 USL 的判定**：应判为"不确定/有风险"，不能因点预测在规格内就判安全。因为点预测只是期望值，PI 表达了合理波动范围，区间上界超过 USL 意味着真实值有可能超规格，存在出货风险。处置：复测/等待实测确认、必要时降级或保守处置，并结合置信度/区间宽度——区间很宽说明本次预测本身不可信（可能 OOD），更不能放行；只有整个 PI 都落在规格内才高把握判安全，点预测超规格且高置信则高风险预警。
5. **门控/不过怎么办**：门控含——①输入数据质量（关键 Step 特征齐全、trace 无未处理 Bad/Gap）；②模型可信（非 OOD、置信度≥阈值、PI 宽度在限内）；③作用域（recipe/腔/模型版本匹配，不跨工况）；④时效（在下次控制决策前产出，迟到不用于本次）。任一不过：VM 不进 R2R 闭环，控制器保持上一安全设定（hold-last-good），转等本 run/片实测，同时记数据/模型质量事件；连续多次不合格则按 W31 规则停自动转人工。绝不用低可信预测硬调。
6. **实测回灌动作**：①以实测为真值更新 R2R（对回该片/腔当时设定算残差，W31 Day04 归位）；②用实测−VM 偏差做 EWMA 在线校正后续 VM 预测（Day02）；③核对当时 VM 预测与实测的误差，更新模型残差监控（RMSE/覆盖率），判断模型是否漂移、是否需重训；④若实测与当时 VM 严重不符，回溯这期间用 VM 反馈做出的控制决策与受影响片，做风险评估/追溯；⑤把该(特征,实测)样本沉淀为重训数据。
7. **判废为何不只凭点预测**：VM 是带误差的预测而非真实测量，点预测没有表达不确定性，可能因模型误差、OOD、输入异常而错；判废/放行是高后果、不可逆的质量与成本决策，仅凭一个可能错的点值会误废好片（损失产能）或漏放坏片（质量逃逸）。正确做法是结合 PI/置信度：高把握（区间全在规格内/外）才自动分类，跨规格或低置信必须以物理实测或人工复核为准；VM 适合做逐片筛查、预警和 R2R 的快速（可回退）反馈，不替代关键质量裁决。

## 二、参考实现（net8.0）：端到端 VM→R2R 管线

```csharp
namespace EapLab.Vm;
using EapLab.R2r;
public enum Risk{ Safe,Uncertain,HighRisk }
public sealed record WaferInput(string Id,string Chamber,double[] Features,bool DataGood,string ModelScope,string ActualScope);
public sealed record PipeResult(bool UsedVm,Risk Risk,double? NextU,string Note);

public sealed class VmToR2rPipeline
{
    readonly LinearVm _vm;readonly EwmaController _r2r;
    readonly double _confThr, _maxPiHalf;public double LSL,USL;
    public VmToR2rPipeline(LinearVm vm,EwmaController r2r,double confThr,double maxPiHalf,double lsl,double usl)
    {_vm=vm;_r2r=r2r;_confThr=confThr;_maxPiHalf=maxPiHalf;LSL=lsl;USL=usl;}

    public PipeResult Process(WaferInput w,double usedU,double? real)
    { if(!w.DataGood)return new(false,Risk.Uncertain,null,"bad data, wait metrology");
        if(w.ModelScope!=w.ActualScope)return new(false,Risk.Uncertain,null,"scope mismatch, wait");
        var p=_vm.Predict(w.Features);
        double piHalf=p.Hi-p.Lo;
        bool gate=!p.OutOfDist&&p.Confidence>=_confThr&&piHalf<=_maxPiHalf;
        // 规格风险判定(用整个区间)
        Risk rk=p.Lo>=LSL&&p.Hi<=USL?Risk.Safe:(p.Lo>USL||p.Hi<LSL)?Risk.HighRisk:Risk.Uncertain;
        // 融合: 实测优先, 合格VM补盲, 否则保持
        double? y;bool usedVm;
        if(real is double rr){y=rr;usedVm=false;_vm.Correct(p.Yhat,rr);}
        else if(gate){y=p.Yhat;usedVm=true;}
        else return new(false,rk,null,"VM gate fail, hold-last-good");
        var nu=_r2r.Update(y.Value,usedU,reliable:true);
        return new(usedVm,rk,nu,usedVm?"VM feedback":"real feedback"); }
}
```

public class PipelineTests

## 三、端到端管线（手绘参考）
```
EDA trace + Step marker → 分段特征(WKN) → VM: ŷ/PI/OOD/置信
   → 门控(数据Good? 非OOD? 置信≥阈? PI不过宽? 作用域匹配? 时效?)
        否→保持hold-last-good等实测+质量事件(连续失败停自动)
        是↓
   规格判定(整个PI对USL/LSL): 全在内Safe / 跨界Uncertain复测 / 全在外HighRisk
   → 融合(实测优先且校正VM; 无实测用合格VM保守权重)
   → EWMA/dEWMA → 限幅/死区/控制限 → overlay(作用域/版本/ReqId)
   → RMS→EAP→GEM安全点下发→回读生效→下一run
实测回灌: 归位更新R2R + EWMA校正VM + 残差监控/重训 + 回溯VM期间决策与风险片
铁律: VM只预测不控制; 关键判废/放行以实测/人工为准; 预测非真值, 必带PI与置信
```

## 四、今日易错点
1. 把 VM 点预测当真值直接判废/强控（应带 PI、留实测裁决）。
2. 门控缺项（不查 OOD/作用域/数据质量/时效就进闭环）。
3. 混用规格限与 SPC 控制限。
4. 只看点预测在规格内就放行，忽略区间跨规格线。
5. 有实测却仍用 VM（应实测优先并校正 VM）。
6. 实测回来不归位、不校正 VM、不回溯 VM 期间决策。
7. VM 迟到仍用于本次控制；低可信预测不回退硬调。
8. 认为 VM 能直接下发设备（预测信息层，控制归 R2R/GEM）。
