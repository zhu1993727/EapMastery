## 二、背景知识（先读，25 分钟）

### 1. 自动下料链路（上料的镜像，但起点是任务结束）
```
A 加工收尾：所有访问该 Carrier 的 PJ/CJ 到终态,基板全部归位 Slot,机械手 Home,盒门关闭
B Host 判断可下料：E87 Loaded + 任务全结束 + 无 Hold → S15F9 Unload
C E87 守卫通过：Loaded→Unloaded,发 Unloaded 事件,停止一切盒内访问
D Host 调度 AMHS：通知天车来 LP1 取走 CarrierID=A
E E84 Pickup 硬握手：天车到达,设备先把盒送到交接位,ES 许可,小车抓取,COMPT
F 在位稳定 OFF → 桥接对接点2 → E87 OnPhysicalRemoved → Unloaded→NotInstalled,发 Removed
G Host 更新流向：盒在途/去下一工位或 Stocker,口空可接下一单
```

### 2. 下料与上料的关键差异
- 上料起点是"物理来盒"，下料起点是"逻辑任务结束"（逻辑先于物理，W11/W12 已强调）。
- 上料是物理→逻辑（Deposit 触发 Installed），下料是逻辑→物理（先 Unload 放行，才 Pickup）。
- 下料前必须确认盒内基板全部归位（E90 SlotMap 与加工记录一致），否则不能放盒走。

### 3. Unload 守卫（代码层）
- AllJobsFinished：关联 PJ/CJ 全部终态。
- AllSubstratesReturned：取出去的片都放回（对比加工前 SlotMap，片数/位置一致或符合预期产出）。
- RobotHome、DoorClosed、无未解除 Hold。
- 任一不满足，Unload 命令被状态机守卫拒绝（S15F10 非 0/异常事件），保持 Loaded。

### 4. 物理→逻辑异常联动
- **E84 Pickup 失败（T_compt/急停/VALID 丢）**：盒没被取走、在位仍 ON，桥接不产 Removed，E87 保持 Unloaded，报警重试/人工，不能误判口空。
- **Loaded 在位突丢（非正常移除）**：还没 Unload 在位就 OFF，桥接识别下降沿但 E87 当前 Loaded，E87 OnPhysicalRemoved 走高危分支：中止 PJ、高警报、账实核对。
- **Unloaded 在位突丢但非 E84 正常完成**：桥接查 E84 Outcome 不是 PickupCompleted，不产正常 Removed，产 PhysicalFault。

### 5. 逻辑→物理异常联动
- **上料校验失败（错料/读不到/无预约）**：盒物理在口上但逻辑不授权，Host 决策"退回"，反向调度 AMHS 对该口发起 E84 Pickup 把盒取走（盒来都来了，怎么让它走）。
- **Hold 期间**：E87 有 Hold，不允许 Unload，也就不调度 Pickup，盒留在口上等待解除。
- **Unloaded 后 AMHS 迟迟不来**：口被占用，报"等待取走过时"，Host 重新调度，避免口长期阻塞影响产能。

### 6. 双向联动的状态一致性原则
- 物理状态是最终事实，逻辑状态向物理对齐；但物理动作的发起要受逻辑授权门控。
- 任何一层卡住，另一层不得"假设成功"越过它：物理没取走，逻辑不能标移除；逻辑没放行，物理不能取（正常流程）。
- 所有跨层异常都要同时在两层留痕并通知 Host。
