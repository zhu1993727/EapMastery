# W13 · Day04 答案与参考实现

## 一、自测题标准答案
1. **下料步骤 / 逻辑先于物理**：A 加工收尾（关联 PJ/CJ 全终态、基板全归位、机械手 Home、门关）→B Host 判断可下料并发 Unload→C E87 守卫通过 Loaded→Unloaded、停访问→D Host 调度 AMHS 来取→E E84 Pickup 硬握手取盒（设备先送盒到交接位、ES 许可、小车抓取 COMPT）→F 在位稳定 OFF，桥接对接点2 触发 Removed，Unloaded→NotInstalled→G Host 更新流向、口空接单。下料是"逻辑先于物理"：上料由物理来盒触发（物理→逻辑），下料必须先在逻辑层确认加工真的结束、盒可以放行（Unload），才去发起物理取盒动作；没有逻辑放行，物理上不应把在制盒取走，这保证不会把还没做完、片没归位的盒提前搬走。
2. **Unload 四守卫 / 基板归位核对**：①AllJobsFinished——所有访问该 Carrier 的 ProcessJob/ControlJob 都到终态（完成/中止），没有在跑任务；②AllSubstratesReturned——加工中取出去的基板全部放回载具，对比加工前 E90 SlotMap 与当前槽位，片数一致、每片在预期目标槽（成品/返工按预期），没有片遗留在腔体/机械手/暂存位；③RobotHome + DoorClosed——机械手归位、盒门关闭，机构处于可安全被取走状态；④无未解除 Hold。基板归位靠 E90 位置跟踪：加工前记录源 SlotMap，加工中跟踪每片去向，Unload 前重新读当前 SlotMap 与"预期产出槽位图"逐槽比对，完全一致才放行。任一守卫不满足，状态机拒绝 Unload、保持 Loaded。
3. **Pickup 失败为何不能标 Removed / 各层状态**：Removed 的唯一合法触发是"E84 Pickup 正常完成 + 在位稳定 OFF"。Pickup 失败（T_compt 超时/急停/VALID 丢）时盒没被取走、在位传感器仍 ON，物理事实是盒还在口上；若 E87 仍标 Removed/NotInstalled，就变成"系统说口空、实际有盒"的账实不符，下一个盒上来会双盒碰撞、Host 也会错误调度。此时各层：E84 进 SafeHold/EStopHold 保持夹持；桥接层因 Outcome≠PickupCompleted 或在位未稳定 OFF 不产 Removed；E87 保持 Unloaded（已放行但未移除）；报警，重试 Pickup 或人工处理，直到物理真正取走才 Removed。
4. **Loaded 突丢 vs Unloaded 在位 OFF 的区别**：
   - **Loaded 在位突丢（非正常移除，高危）**：还没走 Unload、可能正加工、盒内可能有在途片，在位却 OFF。E87 OnPhysicalRemoved 检测到当前是 Loaded，走高危分支：立即中止关联 PJ、冻结取放、高级报警、清点在途基板做账实核对、强制回 NotInstalled 并标记非正常移除，锁口待清理。
   - **Unloaded 在位变 OFF（正常移除的预期）**：已 Unload、访问已结束、片已归位，此时若 E84 Outcome=PickupCompleted 且稳定 OFF，就是正常下料，走正常 Removed、回 NotInstalled、释放口；若 E84 没正常完成却 OFF，则桥接产 PhysicalFault 而非正常 Removed。
   区别核心：移除发生在 Unload 之前还是之后、盒内是否还可能有在途片——之前=高危事故，之后=正常流程。
5. **错料退回的联动链路**：上料校验失败时盒物理已在口上（E84 Deposit 成功、E87 停 Installed 不授权）。联动：①E87/桥接层把"准入异常（Mismatch/Unreadable/NoReservation）"事件报给 Host；②Host 决策"退回/转运"，不授权加工；③Host 向 AMHS 下发取盒任务（到该 LoadPort 取走这个实际 CarrierID，送去指定暂存/正确设备）；④AMHS 天车到达，对该口走一次 E84 Pickup 硬握手把盒取走；⑤在位稳定 OFF、E84 正常完成，桥接产 Removed，E87 从 Installed 直接回 NotInstalled（未授权取走低危撤销，W12 已定义）；⑥Host 更新流向、释放口。即逻辑拒绝→反向发起物理取走，由 Host 调度、E84 执行、桥接确认、E87 销账。
6. **Hold 时为何不 Unload 也不 Pickup**：Hold 表示该载具/批次被显式管控（质量/工程/设备原因），在未查明处理前必须"冻结现状"。不 Unload 是因为卸载意味着结束访问、准备让盒离开，而 Hold 往往正需要保留现场、继续调查或等待质量判定，不能放行；不调度 Pickup 是因为若把被 Hold 的盒物理搬走、混回物流，可能让有问题的批次流向下游，失去管控，甚至找不回。因此 Hold 期间盒物理留在口上、逻辑保持当前态、加工和搬运都冻结，只有 Hold 下发方解除后，才恢复 Unload→Pickup 流程。
7. **"物理是最终事实"与"物理动作受逻辑门控"如何统一**：两者作用方向不同、并不矛盾，合起来是一套闭环一致性原则。①**认知方向以物理为准**：当判断"盒到底在不在口上、处于什么客观状态"时，物理传感器/交接结果是最终事实，逻辑账目必须向物理对齐（对账、非正常移除检测），不能拿账目否定传感器，这保证系统"诚实"、能发现异常。②**动作方向受逻辑门控**：当要发起一个会改变物理世界的动作（加工取片、让天车把盒取走）时，必须先有逻辑授权（Loaded 才能取片、Unloaded 才正常 Pickup、无 Hold 才放行），物理不擅自行动，这保证错误的盒不被加工、在制盒不被误搬。一句话：**认识世界听物理的，改变世界听逻辑授权的**；两者冲突（如逻辑说该有盒、物理说没有）时冻结并报警交人工，而不是强行让一方迁就另一方。

## 二、参考实现（net8.0，关键片段）

### Unload 守卫聚合
```csharp
public sealed class UnloadGuard
{
    public bool AllJobsFinished { get; init; }
    public bool AllSubstratesReturned { get; init; }
    public bool RobotHome { get; init; }
    public bool DoorClosed { get; init; }
    public HoldState Hold { get; init; } = HoldState.None;
    public bool CanUnload() => AllJobsFinished && AllSubstratesReturned
        && RobotHome && DoorClosed && Hold==HoldState.None;
    public string BlockReason() => !CanUnload()
        ? string.Join(",", new[]
        {
            (!AllJobsFinished)?"任务未结束":"",
            (!AllSubstratesReturned)?"基板未归位":"",
            (!RobotHome)?"机械手未Home":"",
            (!DoorClosed)?"门未关":"",
            (Hold!=HoldState.None)?$"Hold={Hold}":""
        }.Where(s=>s!="")) : "OK";
}
```

### 下料编排器（逻辑先于物理）
```csharp
public sealed class AutoUnloadOrchestrator
{
    private readonly LoadPortManager _e87; private readonly IAmhs _amhs;
    public List<string> Timeline { get; } = new();
    public AutoUnloadOrchestrator(LoadPortManager e87,IAmhs amhs){_e87=e87;_amhs=amhs;}

    // Host: 判断可下料并 Unload, 然后调度 AMHS
    public bool BeginUnload(string lp, UnloadGuard guard)
    {
        if (!guard.CanUnload()) { Timeline.Add($"Unload被拒:{guard.BlockReason()}"); return false; }
        bool ok=_e87.Unload(lp);                 // E87 Loaded->Unloaded(状态机守卫)
        Timeline.Add(ok?"E87 Unloaded":"E87 Unload失败");
        if (ok) _amhs.RequestPickup(lp);         // 逻辑放行后才调度物理取盒
        return ok;
    }
    // E84 Pickup 正常完成 -> 桥接 Removed -> E87(由Day02桥接Drain统一调用)
    public void OnPickupDone(string lp)
    {
        _e87.OnPhysicalRemoved(lp);              // Unloaded->NotInstalled
        Timeline.Add($"Removed,口释放:{lp}");
    }
}
public interface IAmhs { void RequestPickup(string lp); void RequestDeposit(string lp,string id); }
```

### 跨层异常测试
```csharp
public class UnloadCrossLayerTests
{
    [Fact] public void 守卫不满足_不Unload不Pickup()
    {
        var (mgr,amhs)=BuildLoaded(); var orch=new AutoUnloadOrchestrator(mgr,amhs);
        var guard=new UnloadGuard{AllJobsFinished=false,AllSubstratesReturned=true,
                                  RobotHome=true,DoorClosed=true};
        Assert.False(orch.BeginUnload("LP1",guard));
        Assert.Equal(CarrierState.Loaded,mgr.Port("LP1").CarrierRef!.State);
        Assert.False(amhs.PickupRequested);       // 没放行不调度取盒
    }
    [Fact] public void Pickup失败_E87保持Unloaded不误判口空()
    {
        var (mgr,amhs)=BuildLoaded(); var orch=new AutoUnloadOrchestrator(mgr,amhs);
        orch.BeginUnload("LP1",OkGuard());
        Assert.Equal(CarrierState.Unloaded,mgr.Port("LP1").CarrierRef!.State);
        // E84 Pickup 失败: 桥接不产Removed(在位仍ON), 不调 OnPickupDone
        Assert.Equal(CarrierState.Unloaded,mgr.Port("LP1").CarrierRef!.State); // 保持
        Assert.Equal(PortState.Occupied,mgr.Port("LP1").State);
    }
    [Fact] public void Loaded在位突丢_非正常移除高危()
    {
        var (mgr,_)=BuildLoaded();                 // 当前 Loaded, 未 Unload
        mgr.OnPhysicalRemoved("LP1");              // 在位突丢
        Assert.Equal(PortState.Empty,mgr.Port("LP1").State);
        Assert.Contains(mgr.Port("LP1").Alarms,a=>a.Contains("非正常移除"));
    }
    [Fact] public void 错料_Host反向调度Pickup退回()
    {
        var rd=new StubReader(); rd.Set("LP1",new(true,"B"));
        var mgr=new LoadPortManager(rd,"LP1"); var amhs=new FakeAmhs();
        mgr.Reserve("LP1","A");
        var decision=mgr.OnPhysicalPlaced("LP1");  // Mismatch, 停 Installed
        Assert.Equal(VerifyDecision.Mismatch,decision);
        Assert.False(mgr.AuthorizeLoad("LP1"));
        amhs.RequestPickup("LP1");                 // Host 反向调度退回
        // E84 取走 -> Removed
        mgr.OnPhysicalRemoved("LP1");
        Assert.Equal(PortState.Empty,mgr.Port("LP1").State);
        Assert.True(amhs.PickupRequested);
    }
    // BuildLoaded/OkGuard/FakeAmhs 为测试辅助, 略
}
```

## 三、下料时间线（参考）
```
加工收尾(PJ终态/片归位/Home/门关) → Host Unload[守卫视CanUnload]
  → E87 Loaded→Unloaded(停访问) → Host调度AMHS取盒
  → E84 Pickup(送盒到位/ES/BUSY抓取/COMPT) → 在位稳定OFF
  → 桥接(Outcome=PickupCompleted)Removed → E87 Unloaded→NotInstalled → 口Empty
  → Host更新流向(在途/下工位/Stocker)
异常: 守卫不满足→拒Unload不Pickup; Pickup失败→保持Unloaded;
      Loaded突丢→非正常移除高危; 错料→反向Pickup退回; Hold→全冻结
```

## 四、今日易错点
1. 下料一完成加工就直接 Pickup（必须先 Unload 逻辑放行、守卫全过）。
2. 不核对基板归位就卸载（在途片/未归位片会随盒离开或丢失）。
3. E84 Pickup 失败还标 Removed（物理没取走，必须保持 Unloaded、口仍占用）。
4. 混淆 Loaded 突丢（高危非正常移除）和 Unloaded 后正常移除。
5. 错料只在逻辑 Hold，不知道要反向调度 E84 把盒物理取走。
6. Hold 期间还 Unload/Pickup（应冻结现状、盒留口上）。
7. 认为"物理为准"和"逻辑门控"矛盾（认知听物理、动作听授权，冲突冻结报警）。
8. Unloaded 后 AMHS 久不来不报警（口被占影响产能，需等待取走过时重调度）。
