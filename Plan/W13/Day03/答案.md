# W13 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何固定推进顺序 / 打乱后果**：数据是单向依赖的——E84 产生物理事实，桥接层读物理事实净化成业务事件，E87 读业务事件建载具账，Host 读 E87 事件做决策再回写授权。必须按"E84→桥接→E87→Host"同拍顺序推进，才能保证每一层读到的都是本拍最新的上游结果。打乱会出现同一拍内的时序倒置：例如 E87 先于桥接跑，就读不到本拍刚放好的 Placed，要多等一拍甚至漏事件；Host 先于 E87 跑就看不到刚产生的 Installed、当拍无法授权；严重时出现"逻辑先于物理"的假状态。固定顺序等价于在单线程里消除并发竞态，使每拍结果确定、可复现、可逐步断言，这也是把异步硬件世界收敛成确定仿真的关键。
2. **MockHost 决策逻辑 / 对应真实动作**：MockHost 维护一张预约表（lp→expectedId）。订阅 E87 事件流，收到 Installed(lp,actualId) 时：查该口预约，若 actualId==expectedId 则调 E87 AuthorizeLoad（等价 Host 发 S15F9 授权命令）；若不符/无预约/读不到则不授权、记录 Rejected/Hold 决策。它对应真实 FAB 里 EAP/MES 收到设备"载具安装"上报后，比对 MES 派工与预约、做防错料校验、再下发"允许装载/访问"命令的过程，即"物理事件驱动逻辑决策"的自动化闭环。
3. **为何必须 Installed→Loaded、能否省 Installed**：不能省。Installed 表示"物理就位、身份已读、待授权"，Loaded 表示"校验通过、Host 授权、可加工"，二者之间夹着不可省略的防错料校验和 Host 决策环节。省掉 Installed 直接 Loaded，等于抹掉"物理事实"和"逻辑授权"的分界，变成设备检测到盒就自动可加工，回到了"物理在位即可加工"的错误模型，错料/无预约/未授权都无法拦截。保留两个事件也让 Host 有明确的决策触发点（收到 Installed 才去校验授权），并让状态变化全程可观测、可审计。
4. **ID 不匹配在哪层哪步最终拦下 / 各层分工**：逐层看——E84 层只负责把盒安全放稳（它不知道 ID，不拦）；桥接层只判断"物理可信有无"，盒确实放稳了，正常产出 Placed（也不判 ID）；E87 层 OnPhysicalPlaced 读 RFID 得到实际 ID，ReservationVerifier 与该口预约期望比对，得出 Mismatch、VerifyState=Mismatch、Carrier 停在 Installed；MockHost 收到 Installed 比对预约不符，决定不授权（不调 AuthorizeLoad）。最终拦截点是 **E87 状态机 AuthorizeLoad 的守卫（Verify 必须 Verified）+ Host 不授权**双重保证：即使 Host 误发授权，状态机守卫也会因 Mismatch 拒绝迁移。体现分层防御：物理层管放稳、桥接管可信、E87 管校验、Host 管决策，各层不越界且纵深防御。
5. **逻辑时钟对集成测试的好处**：①确定可复现——相同输入和故障注入点，每次跑出完全相同的时间线，不依赖线程调度；②可单步——能精确断言"第几毫秒、哪一拍 E84 完成、哪一拍桥接去抖通过、哪一拍 Installed、哪一拍 Loaded"；③可快进——去抖 50ms、T_compt 30s 不用真等，一次 Tick 跨过；④无竞态——固定推进顺序替代多线程锁，避免偶发失败；⑤故障注入精确——可在指定拍制造抖动/急停/读失败，验证拦截。真实系统的并发性在集成验证阶段被逻辑时钟收敛，是协议/控制系统仿真的标准做法。
6. **时间线如何定位卡点**：时间线逐拍记录每个模块状态，卡顿时从后往前看第一个"没有按预期推进"的模块即可定位断层：例如 E84 已 Idle 但 Bridge 无 Placed→问题在去抖阈值/正常完成判定；Bridge 有 Placed 但 E87 无 Installed→问题在 OnPhysicalPlaced/RFID 读取；有 Installed 但 Host 没授权→问题在预约表/比对；Host 授权了但没到 Loaded→问题在 E87 状态机守卫（Hold/Verified/口状态）。时间线把跨层黑盒变成可逐拍检查的白盒，是集成调试最重要的手段。
7. **E84 正常但 RFID 读失败的最终状态**：E84 层正常回 Idle、在位稳定 ON（物理放盒成功）；桥接层正常产出 Placed；E87 层 OnPhysicalPlaced 调 ICarrierIdReader 返回失败，ReservationVerifier 输出 Unreadable、Carrier 建账但停在 Installed、VerifyState=Unreadable、产生准入异常告警；MockHost 收到带"读不到"的 Installed，不授权（Hold/请求重读或人工）；最终 E87=Installed（非 Loaded），口 Occupied，禁止取片加工，等待重新读取/换口/人工输入。即"物理成功、逻辑卡在身份识别"，这正是 Day05 学的准入类异常 B。

## 二、参考实现（net8.0，拼装 W11/W12/Day02）

### 统一编排器（固定推进顺序）
```csharp
namespace EapLab.E84E87;
using EapLab.E87;
using EapLab.E84;

public sealed class AutoLoadOrchestrator
{
    public HandshakeSimulator E84 { get; }
    public LoadPortManager E87 { get; }
    public PhysicalToLogicalBridge Bridge { get; }
    public MockHostController Host { get; }
    private readonly string[] _lps;
    private long _now;
    public List<string> Timeline { get; } = new();

    public AutoLoadOrchestrator(HandshakeSimulator e84, LoadPortManager e87,
        PhysicalToLogicalBridge bridge, MockHostController host, string[] lps)
    { E84=e84; E87=e87; Bridge=bridge; Host=host; _lps=lps; }

    public void Tick(long delta=10)
    {   // 固定顺序: ①E84 ②桥接 ③Drain到E87 ④Host处理E87事件并决策
        _now += delta;
        E84.Step(_now);                 // 1) E84 两 FSM 推进(接口按W11实现)
        Bridge.Tick(delta);             // 2) 去抖/边沿/正常判定
        var before = SnapshotE87Events();
        Bridge.DrainTo(E87);            // 3) Placed/Removed -> E87 建账
        var newEvents = DiffEvents(before);
        Host.Handle(newEvents, E87);    // 4) Host 见 Installed 决策授权
        Timeline.Add($"[t{_now}] {TraceLine()}");
    }
    public void RunUntilLoaded(string lp,int maxTicks=200)
    { for(int i=0;i<maxTicks;i++){ Tick(); if(E87.Port(lp).CarrierRef is {State:CarrierState.Loaded}) return; } }

    private List<string> SnapshotE87Events()=> new();
    private List<string> DiffEvents(List<string> before)=> new(); // 教学示意:实际收集E87新增事件
    private string TraceLine()=> string.Join(" | ", _lps.Select(lp=>
        $"{lp}:E87={E87.Port(lp).CarrierRef?.State.ToString()??"Empty"}"));
}
```

### 模拟 Host 决策器
```csharp
public sealed class MockHostController
{
    private readonly Dictionary<string,string> _reserve = new();
    public List<string> Decisions { get; } = new();
    public void Reserve(LoadPortManager mgr,string lp,string expectedId)
    { mgr.Reserve(lp,expectedId); _reserve[lp]=expectedId; Decisions.Add($"Reserve {lp}={expectedId}"); }

    public void Handle(List<string> newEvents, LoadPortManager mgr)
    {
        foreach (var lp in _reserve.Keys.ToList())
        {
            var c = mgr.Port(lp).CarrierRef;
            if (c==null || c.State!=CarrierState.Installed) continue;
            // 收到 Installed: 比对预约实际ID
            bool match = c.Verify==VerifyState.Verified; // E87校验器已比对
            if (match && _reserve.GetValueOrDefault(lp)==c.CarrierId)
            {
                bool ok=mgr.AuthorizeLoad(lp);
                Decisions.Add(ok?$"Authorized {lp}":$"授权被守卫拒绝 {lp}");
            }
            else
            {
                Decisions.Add($"Hold/Reject {lp} verify={c.Verify}"); // 不授权
            }
        }
    }
}
```

### 端到端测试
```csharp
public class AutoLoadPipelineTests
{
    // 辅助:构造 E84+桥+E87+Host 编排器(Stub RFID/IE84Provider 按前几天实现装配)
    private AutoLoadOrchestrator Build(StubReader rd, FakeE84 e84)
    {
        var lps=new[]{"LP1"};
        var e87=new LoadPortManager(rd,lps);
        var bridge=new PhysicalToLogicalBridge(e84,lps,30);
        var host=new MockHostController();
        // HandshakeSimulator 用 e84 提供, 装配略(按W11/Day02)
        return new AutoLoadOrchestrator(null!,e87,bridge,host,lps){ };
    }
    [Fact] public void 正常料_自动走到Loaded()
    {
        var rd=new StubReader(); rd.Set("LP1",new(true,"FOUP-A"));
        var e84=new FakeE84(); e84.SimulateDepositOk("LP1");
        var orch=Build(rd,e84); orch.Host.Reserve(orch.E87,"LP1","FOUP-A");
        orch.RunUntilLoaded("LP1");
        Assert.Equal(CarrierState.Loaded, orch.E87.Port("LP1").CarrierRef!.State);
        Assert.Contains(orch.Host.Decisions,d=>d.Contains("Authorized"));
    }
    [Fact] public void 错料_停Installed不授权()
    {
        var rd=new StubReader(); rd.Set("LP1",new(true,"FOUP-B")); // 实际B
        var e84=new FakeE84(); e84.SimulateDepositOk("LP1");
        var orch=Build(rd,e84); orch.Host.Reserve(orch.E87,"LP1","FOUP-A"); // 期望A
        for(int i=0;i<50;i++) orch.Tick();
        Assert.Equal(CarrierState.Installed, orch.E87.Port("LP1").CarrierRef!.State);
        Assert.Contains(orch.Host.Decisions,d=>d.Contains("Hold/Reject"));
    }
    [Fact] public void RFID读失败_停Installed()
    {
        var rd=new StubReader(); rd.Set("LP1",new(false,null));
        var e84=new FakeE84(); e84.SimulateDepositOk("LP1");
        var orch=Build(rd,e84); orch.Host.Reserve(orch.E87,"LP1","A");
        for(int i=0;i<50;i++) orch.Tick();
        Assert.Equal(CarrierState.Installed, orch.E87.Port("LP1").CarrierRef!.State);
    }
}
```
> 注：`HandshakeSimulator.Step/FakeE84` 等按 W11 Day06、W13 Day02 的接口对接，这里聚焦编排与决策骨架，实际把 E84 输出适配成 IE84Provider 即可。

## 三、正常上料时间线（对照 13 步，参考）
```
[t0]  Host.Reserve LP1=A (步骤1)
[t..] E84: Idle→WaitGrant→WaitBusy→Transfer→Complete→Idle (步骤3,天车Deposit)
[t..] Bridge: 原始ON→去抖中→稳定ON+上升沿+E84正常→Placed (步骤4,对接点1)
[t..] E87: OnPhysicalPlaced 读RFID=A,Verified, NotInstalled→Installed, 事件Installed(步骤5)
[t..] Host: 见Installed, A==A → AuthorizeLoad (步骤6)
[t..] E87: 守卫通过 Installed→Loaded, 事件Loaded (步骤7,可交E90/任务)
结果: E84=Idle/在位ON, E87=Loaded, Host=Authorized ✓
```

## 四、今日易错点
1. 同拍推进顺序颠倒导致漏事件/逻辑先于物理（固定 E84→桥→E87→Host）。
2. MockHost 不看 E87 事件主动轮询（应由 Installed 事件驱动决策）。
3. 省掉 Installed 直接 Loaded（抹掉校验授权环节，错料无法拦）。
4. 以为 ID 校验是 E84 的事（E84 不知 ID，校验在 E87+Host，分层纵深防御）。
5. Host 授权就认为一定 Loaded（还要过 E87 状态机守卫，双重保险）。
6. 用真实线程/随机时序导致集成测试偶发失败（用逻辑时钟确定复现）。
7. 不打印时间线，跨层卡顿时无从定位（逐拍 Trace 是白盒调试关键）。
8. RFID 失败仍让 Carrier 进 Loaded（应停 Installed、Unreadable、Hold）。
