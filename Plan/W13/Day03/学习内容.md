## 一、今日目标
1. 组装 AutoLoadPipeline：Host 预约 → E84 Deposit 仿真 → 桥接净化 → E87 Installed → Host 校验授权 → Loaded。
2. 实现模拟 Host 决策器 `MockHostController`：收到 Installed 自动比对预约并下 AuthorizeLoad。
3. 用统一逻辑时钟驱动 E84 两个 FSM、桥接层、E87 管理器，保证时序确定可复现。

## 二、集成架构（先读，25 分钟）

### 1. 模块装配关系
```
MockHostController (预约/校验/授权决策)
   │ Reserve(lp,id) / AuthorizeLoad(lp)  [等价 S15F9]
   ▼
LoadPortManager(E87) ◄──Placed/Removed── PhysicalToLogicalBridge(去抖/边沿/正常判定)
   ▲                                      ▲ 读 E84 结果+在位
   │ S16F1 等价事件回调                     │
   └────────────── IE84Provider ──── HandshakeSimulator(E84: LoadPortFsm+VehicleFsm)
                                          Deposit: 天车放盒
统一逻辑时钟 OrchestrationClock: 每拍依次 E84.Tick → Bridge.Tick → DrainTo(E87) → Host 处理事件
```

### 2. 统一时钟驱动顺序（关键，避免同拍竞态）
每一拍严格按信号/依赖方向推进：
1. E84 两个 FSM Tick（产生握手进展、改变物理在位）。
2. 桥接层 Tick（读 E84 结果和在位，去抖边沿，产出 Placed/Removed/Fault）。
3. Drain 到 E87 Manager（Placed→OnPhysicalPlaced：读 RFID、建 Carrier、到 Installed、产事件）。
4. MockHost 处理 E87 新事件：见 Installed→查预约→决策 AuthorizeLoad。
5. E87 执行授权→Loaded，产 Loaded 事件。
同拍内按此固定顺序，避免"E87 先于物理读"之类的时序倒置。

### 3. MockHostController 决策逻辑
- Reserve(lp,expectedId)：调 E87 Manager.Reserve，记录"我给哪个口预约了哪个 ID"。
- 订阅 E87 事件流：收到 Installed(lp,actualId)：
  - 查该口预约 expectedId；actualId==expectedId→AuthorizeLoad；
  - 不符/无预约/读不到→不授权，记录拦截决策（等价真实 Host 回 Hold）。
- 这模拟了真实 Host"物理事件驱动逻辑决策"的闭环，让集成链路无需人工即可自动走到 Loaded（正常料）或被拦（异常料）。

### 4. RFID 读取注入
- E87 的 ICarrierIdReader 用可配置 Stub：按口返回"固定 ID / 读失败"，用于跑正常和 ID 异常场景。
- 真实系统里 ID 在物理就位后由 LoadPort RFID 读出，这里用 Stub 模拟同一时机。

### 5. 全链路轨迹记录
- 每个模块暴露 Trace/Events，Orchestrator 每拍汇总成一条时间线记录：`[t] E84=.. / Bridge=.. / E87=.. / Host=..`，最终打印，对照 Day01 的 13 步总图验证节拍正确。

### 6. 上料链路完成判据
- 正常料：E84 回 Idle、在位稳定 ON、E87=Loaded、事件序列含 Installed→Loaded、Host 决策=Authorized。
- 异常料（错 ID/读不到/无预约）：E87 停在 Installed、Host 决策=Rejected/Hold、绝不到 Loaded。
