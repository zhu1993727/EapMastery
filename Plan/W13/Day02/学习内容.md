## 二、背景知识（先读，25 分钟）

### 1. 为什么需要专门的桥接层
E84 状态机（硬线握手）和 E87 状态机（载具逻辑）是两套独立模型，不能让 E87 直接读 E84 的原始信号——原始信号有抖动、有中间态、有异常中止。桥接层负责"物理信号→可信业务事件"的净化和翻译：
- 滤除抖动/毛刺（去抖）。
- 只在 E84 正常完成交接时产出事件（异常不产出）。
- 识别本次是 Deposit（盒来）还是 Pickup（盒走）。
- 幂等：同一物理事实只触发一次逻辑迁移。
- 这正是工业控制里"传感器原始量→工艺事件"的标准抽象层。

### 2. 桥接层输入输出
- 输入：①E84 交接状态机当前态（Idle/Wait.../SafeHold/EStopHold）与本次交接方向；②在位传感器原始电平 PresentRaw；③逻辑时钟。
- 输出（业务事件）：`PhysicalEvent.Placed(lpId)` 或 `PhysicalEvent.Removed(lpId)`，交给 LoadPortManager；异常时输出告警事件而非业务事件。

### 3. 在位信号去抖（Debounce）
- 传感器从 OFF→ON 有机械抖动/接触过程，必须连续稳定保持 DebounceMs 才认定"真的在位"。
- 用逻辑时钟步进：记录跳变时刻，每次 Tick 检查当前电平是否已持续超过阈值，未超过不产出事件；中途抖动回退则重置计时。
- Pickup 的 OFF 去抖同理（防止瞬时掉线误判移除）。

### 4. E84 正常完成判定
- 只有当 E84 状态机本次交接**正常回到 Idle**（而非 SafeHold/EStopHold/Rejected）且方向=Deposit、且在位稳定 ON，才产出 Placed。
- 若 E84 停在 SafeHold/EStopHold：即使传感器瞬时 ON 也不产出，改报"物理交接异常，未建账"。
- 这样把 W11 Day05 的异常处置和 W12 的建账门槛对接起来。

### 5. 方向识别与边沿触发
- 桥接层维护每个口的上一次稳定在位态 lastStablePresent，做**边沿检测**：OFF→ON 稳定=Placed 边沿；ON→OFF 稳定=Removed 边沿。只在边沿产出一次事件（幂等），避免电平持续期间重复触发。
- 方向也可结合 E84 本次交接方向交叉验证（Deposit 应对应 OFF→ON，矛盾则告警）。

### 6. 与 E87 的衔接
- 桥接层产出 Placed → LoadPortManager.OnPhysicalPlaced(lpId)（内部读 RFID、校验、建 Carrier、FSM 到 Installed）。
- 桥接层产出 Removed → LoadPortManager.OnPhysicalRemoved(lpId)（对接点2，Day04 细做，今天先留接口）。
- 桥接层不做 ID 校验/授权（那是 E87/Host 的事），只负责"可信的物理有无"这一单一职责。
