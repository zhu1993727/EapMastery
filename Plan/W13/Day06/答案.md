# W13 · Day06 答案与参考实现

## 一、自测题标准答案
1. **统一时钟下多口如何独立不串**：结构上每个 LoadPort 拥有各自独立的一整套对象——独立 E84 握手 FSM、独立桥接 DebounceEdgeTracker、独立 E87 CarrierFsm/LoadPort 对象，用 `Dictionary<lpId, PortRuntime>` 隔离，任何状态只通过显式 lpId 访问对应实例，不存在跨口共享的"当前盒"变量；统一时钟每拍遍历所有口、对每口独立执行"E84→桥→E87→Host"固定顺序，口与口之间无执行依赖，一口卡在异常只影响它自己的 Runtime，其他口照常推进。共享的只有无状态/按口隔离的 Host 决策器（内部预约表也按 lpId 存）。再用交错上料测试断言各口事件携带正确 ID，从结构和测试两层保证不串状态。
2. **错料退回跨层链路 / 为何不阻塞他口**：LP2 E84 Deposit 正常放盒→桥接产 Placed→E87 读到 X、与预约期望 B 比对 Mismatch、停 Installed→Host 决策不授权并请求 AMHS 对 LP2 发起 Pickup→E84 硬握手取走 X→桥接 Removed→E87 从 Installed 回 NotInstalled、LP2 回 Empty、Host 更新"X 已退回"。不阻塞其他口，是因为这套流程的所有状态和动作都封装在 LP2 自己的 PortRuntime 与调度队列里，统一时钟每拍是分别推进各口，LP2 等自己的 Pickup 时不会挂起全局时钟循环，LP1/LP3 的 FSM 每拍照常被 Tick，体现"每口独立状态机 + 并发推进、故障局部化"。
3. **RFID 失败人工放行的可追溯证据**：必须保留——①原始失败记录（何时、哪个口、RFID 重试几次失败、读写器状态/错误码）；②人工操作审计（操作人 ID、权限级别、时间、口位、人工输入/核对的 CarrierID、手动放行原因、对照 MES/实物标签的核对依据、审批信息）；③状态轨迹（Unreadable→人工确认→Verified/强制放行→Loaded 的完整事件链与 Host 决策）；④后续该载具的加工流向，保证一旦质量追溯能还原"这盒身份是经谁、依据什么确认的"。这些审计也是统计 RFID 故障率、识别硬件隐患、考核自动率的数据源。
4. **Pickup 重试前提 / 何时不能自动重试**：可自动重试的前提：盒的物理归属和位置确定（仍稳定在口上、在位 ON、E84 只是握手过程超时/小车临时问题）、机构无故障、无 ESTOP、重试次数未超限，且重试仍走完整 E84 握手。不能自动重试：①盒归属/位置不确定（可能半夹半悬、被移动）；②发生 ESTOP/安全回路动作（必须人工复位）；③LoadPort 或小车机械故障；④传感器矛盾（COMPT 与在位不一致）；⑤已达重试上限（防死循环，升级人工）。这与 W11 Day05"归属不确定禁止自动重试"一致，物理动作安全优先。
5. **断线手动上料为何 Spool 覆盖不了、要对账**：Spool 只缓存和重发"设备自己产生并知道的事件"。断线期间人工在 LP2 放盒，如果这个手动操作没有通过设备软件登记（或登记事件因断线上报不了、且恢复时被遗漏），设备本地/Host 镜像可能都没形成正确事件流，Spool 里根本没有"手动放了 D"这条事件可重发——Spool 无法凭空知道一个它没观测到的物理变化。重连后只有直接扫描物理现状（在位传感器+RFID）做全量对账，才会发现"物理有 D、账目没有"，从而补登。这正是增量机制（Spool）的盲区，必须用全量基线（Reconciler）兜底。
6. **对账基准 / 自动纠偏 vs 人工**：以物理事实 P（在位传感器+实际 RFID）为基准。可自动纠偏：**有无/数量类**客观可测差异——P有L无补建账、P无L有补销账（确认无在途片后）、L/H 状态偏差以贴近物理的设备态刷新 Host，这些传感器能确定判定。必须人工：**身份/安全类**——账 ID 与实物 ID 不一致（可能混料/调换，不能自动覆盖身份）、涉及在途基板去向不明、ESTOP/机械故障后的恢复、任何无法用传感器确定盒归属的情况。原则：客观数量听物理自动纠正，身份与安全存疑冻结交人。
7. **EAP 在自动物料系统的核心价值**：EAP 是物理世界与制造信息世界之间的枢纽和安全闸门——①把天车 E84 物理交接、传感器信号净化成可信的载具逻辑事件；②用 Carrier 状态机+预约校验在物料进入加工的第一关防错料、防未授权加工，保证 MES 计划与物理实物严格一致；③协调多口并行、自动/手动双模式、断线重连对账，保证无人值守下 7×24 账实一致、可追溯；④异常时安全拦截、局部隔离、正确联动物理退回/人工，既不停整线也不放过错误。一句话：让"对的料、在对的口、以对的状态、被对的工艺加工、全程可追溯"，这是先进 FAB 自动化与良率的地基。

## 二、参考实现（多口并行系统骨架，net8.0）

### 单口运行时 + 多口系统
```csharp
public sealed class PortRuntime
{
    public string Lp { get; }
    public E84Context E84 { get; }                 // 该口E84握手(按W11封装)
    public DebounceEdgeTracker Bridge { get; }
    public CarrierAggregate? Carrier { get; set; }
    public PortRuntime(string lp,int debounce){ Lp=lp; E84=new(); Bridge=new(){DebounceMs=debounce}; }
}
public sealed class E84Context { public HandshakeOutcome Outcome; public bool FsmIdle=true; public bool Present; }

public sealed class FabCellSimulator
{
    private readonly Dictionary<string,PortRuntime> _ports=new();
    public LoadPortManager E87 { get; }
    public MockHostController Host { get; }
    public List<string> Timeline { get; } = new();
    private long _now;
    public FabCellSimulator(LoadPortManager e87,MockHostController host,params string[] lps)
    { E87=e87; Host=host; foreach(var lp in lps)_ports[lp]=new PortRuntime(lp,30); }
    public PortRuntime Port(string lp)=>_ports[lp];

    public void Tick(long delta=10)
    {
        _now+=delta;
        foreach (var rt in _ports.Values)                 // 每口独立推进,互不阻塞
        {
            // 1) E84推进(此处由故障注入/仿真驱动rt.E84) 2)桥接去抖边沿
            var edge=rt.Bridge.DetectEdge(_now, rt.E84.Present, out _);
            if(edge is bool rising)
            {
                bool normal = rising ? rt.E84.Outcome==HandshakeOutcome.DepositCompleted && rt.E84.FsmIdle
                                     : rt.E84.Outcome==HandshakeOutcome.PickupCompleted && rt.E84.FsmIdle;
                if(normal){ if(rising) E87.OnPhysicalPlaced(rt.Lp); else E87.OnPhysicalRemoved(rt.Lp); }
                else Timeline.Add($"[t{_now}]{rt.Lp} 物理异常,不建/销账 outcome={rt.E84.Outcome}");
            }
        }
        Host.Handle(new(),E87);                            // 共享Host按口决策(内部按lpId)
        Timeline.Add($"[t{_now}] "+string.Join(",",_ports.Keys.Select(lp=>$"{lp}={E87.Port(lp).State}/{E87.Port(lp).CarrierRef?.State}")));
    }
    public void Run(int ticks){for(int i=0;i<ticks;i++)Tick();}
}
```

### 故障注入与综合测试
```csharp
public class FabCellDrillTests
{
    [Fact] public void 三口交错_正常错料读失败_互不阻塞()
    {
        var rd=new StubReader();
        rd.Set("LP1",new(true,"A")); rd.Set("LP2",new(true,"X")); rd.Set("LP3",new(false,null));
        var e87=new LoadPortManager(rd,"LP1","LP2","LP3");
        var host=new MockHostController();
        host.Reserve(e87,"LP1","A");host.Reserve(e87,"LP2","B");host.Reserve(e87,"LP3","C");
        var cell=new FabCellSimulator(e87,host,"LP1","LP2","LP3");
        // 注入三口 Deposit 物理就位(略:设置各 rt.E84.Outcome/Present)
        Deposit(cell,"LP1");Deposit(cell,"LP2");Deposit(cell,"LP3"); cell.Run(10);
        // LP1 正常 Loaded
        Assert.Equal(CarrierState.Loaded,e87.Port("LP1").CarrierRef!.State);
        // LP2 错料不授权,Host退回
        Assert.Equal(CarrierState.Installed,e87.Port("LP2").CarrierRef!.State);
        Assert.Contains(host.Decisions,d=>d.Contains("Hold/Reject")&&d.Contains("LP2"));
        // LP3 读失败,人工输入C后Loaded
        Assert.Equal(VerifyState.Unreadable,e87.Port("LP3").CarrierRef!.Verify);
        rd.Set("LP3",new(true,"C")); // 人工重读/输入
        Assert.True(e87.ManualVerify("LP3","C")); Assert.True(e87.AuthorizeLoad("LP3"));
        Assert.Equal(CarrierState.Loaded,e87.Port("LP3").CarrierRef!.State);
    }
    [Fact] public void E84急停_桥接不建账()
    {
        var e87=new LoadPortManager(new StubReader(),"LP1");
        var cell=new FabCellSimulator(e87,new MockHostController(),"LP1");
        var rt=cell.Port("LP1"); rt.E84.Outcome=HandshakeOutcome.EStop; rt.E84.FsmIdle=false; rt.E84.Present=true;
        cell.Run(5);
        Assert.Equal(PortState.Empty,e87.Port("LP1").State); // 没建账
    }
    [Fact] public void 抖动短于去抖_不触发()
    {
        var e87=new LoadPortManager(new StubReader(),"LP1");
        var cell=new FabCellSimulator(e87,new MockHostController(),"LP1");
        var rt=cell.Port("LP1"); rt.E84.Outcome=HandshakeOutcome.DepositCompleted;rt.E84.FsmIdle=true;
        rt.E84.Present=true; cell.Tick(10);cell.Tick(10);     // 20ms<30
        rt.E84.Present=false; cell.Tick(10);                 // 抖动回退
        Assert.Equal(PortState.Empty,e87.Port("LP1").State);
    }
    [Fact] public void 断线手动上料_重连对账补登()
    {
        // 断线期间手动在LP2放D,Host镜像无; 重连Reconciler发现P有L/H无→补登
        var phy=new MultiPhysicalView(); phy.SetPresent("LP2",true);phy.SetId("LP2","D");
        var e87=new LoadPortManager(new StubReader(),"LP1","LP2"); // 本地也还没账
        var rec=new Reconciler(e87,phy);
        var diffs=rec.Reconcile();
        Assert.Contains(diffs,d=>d.Contains("PhysicalHasLocalNone")&&d.Contains("LP2"));
        // 上层据物理补登(读D→Installed)并刷新Host镜像
        e87.OnManualPlaced("LP2","D",true);
        Assert.NotNull(e87.Port("LP2").CarrierRef);
    }
    static void Deposit(FabCellSimulator c,string lp){var r=c.Port(lp);r.E84.Outcome=HandshakeOutcome.DepositCompleted;r.E84.FsmIdle=true;r.E84.Present=true;}
}
```
> 说明：`E84Context/ManualVerify/OnManualPlaced/MultiPhysicalView` 等为按前几天接口补的适配方法，重点是多口隔离、故障注入点和断言思路；把 W11 真实双 FSM 替换 E84Context 即得到完整仿真。

## 三、系统架构 + 故障处置地图（手绘参考）
```
统一逻辑时钟每拍遍历各口(独立Runtime,故障局部化)
 LP1: E84FSM ─桥(去抖)─► E87 FSM ─► SharedHost(按lp预约/授权/调度AMHS)
 LP2: 同上(错料→不授权→反向Pickup退回)
 LP3: 同上(读失败→人工补登留痕→授权)
故障地图:
 E84急停/未完成 → 桥不建账,E87保持Empty
 传感器抖动<去抖 → 不触发
 ID不匹配       → Installed拦截+Host退回Pickup
 Loaded突丢     → 非正常移除:停PJ/高警/锁口/核在途片
 Pickup失败     → 保持Unloaded/口占用,归属确定可限次重试
 断线手动变化   → Spool盲区,重连Reconciler全量对账补登/销账/刷新
 ID账实不符     → 冻结人工,不自动改身份
收口: 全口Reconciler P/L/H一致 + 无未处理告警 = 通过
```

## 四、今日易错点
1. 多口用共享"当前盒"变量导致串状态（每口独立 Runtime、显式 lpId）。
2. 一口异常阻塞全局时钟推进（每口独立 Tick，故障局部化）。
3. 错料只 Hold 不做物理退回（要反向调度 E84 Pickup）。
4. 人工放行不留完整审计（失败记录+操作人+依据+状态链）。
5. Pickup 失败不分情况一律自动重试（归属不确定/急停/故障必须人工）。
6. 以为 Spool 能补断线期间的手动变化（观测不到，必须全量对账）。
7. 对账时自动覆盖身份 ID（身份不符冻结人工）。
8. 实验只看最终态不看时间线（要可回放、逐拍可追溯才算专家级验证）。
