# W13 · Day07 答案

## 一、W13 自测题（10 题）标准答案

### 1. 13 步全链路 / 通道 / 对接点
E84 硬线步：3 Deposit、12 Pickup；其余为 SECS 软件步。顺序：1 Host 预约→2 调度 AMHS→3 E84 Deposit→4 在位稳定 ON【对接点1】→5 读 ID+Installed 上报→6 Host 校验授权→7 Loaded→8 E90 SlotMap+建 PJ/CJ→9 加工→10 Unload→11 调度来取→12 E84 Pickup、在位 OFF【对接点2】→13 Removed+更新流向。对接点1=E84 正常完成+稳定 ON 触发 E87 安装；对接点2=E84 正常 Pickup+稳定 OFF 触发移除。

### 2. 四互为前提 / 违反后果
①先预约后到盒，否则计划外盒混料；②先 E84 Deposit 成功才 Installed，否则为没放稳的盒建虚账；③先 Loaded 授权才取片，否则错料被加工报废；④先 Unload（任务结束片归位）才 Pickup，否则在途片随盒丢失。跳序任一环节都会破坏安全或账实一致。

### 3. 桥接层必要性 / 四件事 / 单一职责
E84 原始电平有抖动、中间态、异常中止，E87 不能直接读。桥接层做四件事：去抖滤毛刺、只在 E84 正常完成时产出、识别 Deposit/Pickup 方向、边沿触发保证幂等。单一职责：只输出"可信的物理有无"业务事件（Placed/Removed/Fault），不做 ID 校验、授权、状态迁移（归 E87/Host）。

### 4. 去抖 vs 边沿 / 幂等
去抖解决"信号抖动毛刺被当真"，要求从最后跳变起连续稳定 ≥阈值才更新稳定态，中途反向跳变重置计时；边沿检测解决"持续电平重复触发"，只在稳定态 OFF→ON（上升）/ON→OFF（下降）的变化瞬间产出一次事件并更新上次值，持续电平不再产出，从而同一物理事实恰好触发一次（幂等）。

### 5. 上料编排固定顺序原因
数据单向依赖：E84 产物理事实→桥接净化→E87 建账→Host 据 E87 事件决策授权。固定"E84→桥→E87→Host"保证每层本拍读到最新上游结果；打乱会漏事件（E87 先于桥读不到本拍 Placed）、当拍无法授权（Host 先于 E87 看不到 Installed）或出现逻辑先于物理的假状态。固定顺序在单线程内消除竞态、确定可复现。

### 6. Unload 四守卫 / 基板归位核对
AllJobsFinished（PJ/CJ 全终态）、AllSubstratesReturned（片全归位）、RobotHome+DoorClosed（机构安全）、无 Hold。基板归位靠 E90：对比加工前源 SlotMap 与当前槽位，逐槽核对片数与每片目标槽，确认没有片遗留在腔体/机械手/暂存位，完全一致才放行。

### 7. 两类跨层异常各两个
物理→逻辑：①E84 Pickup 失败/急停→E87 保持 Unloaded 不误标移除；②Loaded 在位突丢→非正常移除，停 PJ、高警报、核在途片。逻辑→物理：①上料 ID 不匹配→Host 反向调度 E84 Pickup 退回错盒；②Hold 未解除→不 Unload 也不调度 Pickup，盒留口冻结。原则：物理没成功逻辑不记账，逻辑没放行物理不动作。

### 8. 手动模式变与不变 / 账实一致
手动只改变物理动作执行者（E84 旁路、人工放取），不改变逻辑记账要求：E87 照样建 Carrier、走状态机、读/校验 ID、报 Host。手动放盒经 HMI 选口、扫/输 ID、仍校验（强制放行需权限）、手动触发等价 OnPhysicalPlaced，上报标注手动并写审计（操作人/时间/口/ID/原因/依据），以此保证现场与 MES 账实一致、可追溯。

### 9. P/L/H 对账 / 基准 / 分类 / 时机
P=物理（传感器+RFID 事实）、L=设备 E87 账、H=Host 镜像账，以 P 为基准。可自动纠偏：有无/数量类（P有L无补登、P无L有销账、L/H 偏差以贴近物理的 L 刷新 H）；必须人工：身份 ID 不一致、在途片去向不明、急停/机械故障恢复。三时机：上线/重连后、手动切自动前、异常恢复后。

### 10. 多口不串 / 故障局部化
每口独立 PortRuntime（独立 E84 FSM、桥接去抖器、E87 CarrierFsm），用字典按 lpId 隔离，只经显式口位访问、无共享当前盒变量；统一时钟每拍遍历各口独立推进，一口卡异常只影响自己的 Runtime，不挂起全局循环，其他口照常 Tick；共享 Host 内部预约/决策也按口存储，加交错上料测试验证 ID 不串行。

## 三、E90 预热补充（为 W14 打底）
1. **粒度下钻**：E87 管"盒"，E90 管"盒里每一片 + 设备内每个位置"，是从载具级到基板级的深入。
2. **唯一位置不变式（最重要）**：一片基板任一时刻恰在一个确定位置，不能同时在两处、不能无故消失；移动=位置状态迁移，全程留轨迹。这是防丢片/重片的根本约束，W14 代码会用它做硬校验。
3. **位置空间**：外部=Carrier/Slot#；设备内=Robot/Aligner/Buffer/Chamber/LoadLock，统一抽象成 Location，基板在这些位置间迁移。
4. **SlotMap**：25 槽占用矩阵+每槽片 ID/状态，上料读源图、下料对结果图，正是 Unload 守卫 AllSubstratesReturned 的数据来源（本周已多次用到，W14 正式实现）。
5. **承上启下**：E87 Loaded 提供"盒可访问"前提，E90 提供"片在哪/源目槽"事实，E40 ProcessJob 据此声明"从源槽取→加工→放目标槽"，E94 跨载具交叉取片更依赖 E90 逐片校验。
6. **专家视角**：EAP 排查"丢片/错位/交叉取片"类问题，本质都是在查 E90 位置不变式在哪一步被破坏，W14/W15 会专门训练这类故障定位。

## 四、W13 全周易错点汇总
1. 把 E84 硬线步和 SECS 软件步混为一谈；对接点忽略"正常完成+稳定去抖"。
2. E87 直接读原始传感器（必须经桥接层去抖/边沿/正常判定/幂等）。
3. 去抖断续累加、电平重复触发（反向跳变重置、边沿只触发一次）。
4. 编排同拍顺序颠倒导致漏事件/逻辑先于物理。
5. 省 Installed 直接 Loaded；Unload 不查任务结束和基板归位。
6. E84 失败还建账/标移除；错料只 Hold 不反向物理退回。
7. Hold 时还 Unload/Pickup；手动操作不建账、不留审计。
8. 对账以账否物、自动覆盖身份 ID（身份存疑必须冻结人工）。
9. 以为 Spool 能补断线手动变化（需全量对账兜底）。
10. 多口共享变量串状态、一口异常阻塞全局。
