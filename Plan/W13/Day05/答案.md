# W13 · Day05 答案与参考实现

## 一、自测题标准答案
1. **手动改变/没改变什么 / 为何仍建账**：手动模式（Bypass）只改变**物理动作由谁执行**——E84 自动四相握手被旁路，FOUP 由操作员人工放/取，物理触发源从"天车硬握手"变成"人工操作"。它**不改变逻辑必须如实记账**这一要求：E87 的 Carrier 状态机照样要走（手动放盒一样要 NotInstalled→Installed→Loaded，手动取走一样要移除），ID 照样要读/校验，Host 照样要被通知。原因是 MES 账目、后续加工、物料追溯依赖的是"盒实际在不在、是什么、什么状态"，与它是被天车还是被人放上来无关；手动不建账就会出现现场有盒、系统空白的账实脱节，后续派工、取片、追溯全错。
2. **手动补登记流程 / 强制放行记录**：手动放盒：①E84 旁路、人工把盒放口上（物理在位 ON）；②操作员在 HMI/EAP 选口位、扫 RFID/输入 CarrierID；③系统仍做预约与 ID 校验，若一致走正常授权；若因 RFID 故障等需人工强制确认放行，必须有权限校验；④手动触发等价 OnPhysicalPlaced，E87 建 Carrier→Installed→（授权）Loaded；⑤上报 Host 并标注"手动操作"。强制人工放行要记录：操作人 ID、时间、LoadPortID、实物 CarrierID、手动原因（RFID 故障/无预约/应急）、核对依据（对照 MES/标签）、审批/权限级别。这些审计记录用于追溯责任、统计自动化率、发现反复手动背后的设备隐患。
3. **P/L/H 三方 / 基准**：P=物理事实（Physical），每个口在位传感器与 RFID 实际读到的有无和 ID，是地面真相；L=设备逻辑账（Local E87），LoadPortManager 内各口 Carrier 与状态；H=Host 镜像账，Host 侧维护的各口载具状态。以 **P 物理事实为基准**——传感器和实际 ID 是客观存在，逻辑账（L/H）是对它的记录，记录错了应向事实纠正，而不是反过来无视物理。每个口逐项比对"有无盒、CarrierID、状态"三者一致才算一致。
4. **四种差异与策略 / ID 不一致为何不自动改**：
   - **P有L无**（物理有盒、设备没账，漏建账/丢事件）：以 P 为准补建账，重读 ID、走 Installed，标记"对账补登"并上报。
   - **P无L有**（设备账上有盒、物理空，盒被异常取走/漏移除）：按非正常移除/补移除销账，核对是否有在途片、告警，再置空。
   - **ID 不一致**（账上 A、实际 B，串盒/读错）：冻结该口、高级报警、人工核查，**不自动改 ID**。
   - **L/H 状态偏差**（设备与 Host 镜像不一致，断线丢事件）：以更贴近物理的设备 L 为准刷新 Host 镜像，重发当前状态。
   ID 不一致不能自动改，是因为"账 A、实物 B"意味着出现了无法自动判定谁对的严重异常（可能上错盒、读错标签、盒被调换），自动用 B 覆盖 A 等于在未核实情况下篡改身份记录，可能把错料"洗"成合法、掩盖混料事故；身份是物料追溯的根，必须冻结交人工查清楚。数量有无是客观可测的可自动纠偏，身份存疑必须人工，这是安全边界。
5. **三类对账时机 / 手动切自动为何先对账**：①上线/HSMS 重连后（断线期间可能有手动/异常变化，Spool 也未必全覆盖）；②模式切换后（尤其手动切回自动）；③异常恢复后（急停/故障/非正常移除处理完、解锁口之前）。手动切自动前必须对账，是因为手动期间物理现场可能被人工改变（放/取/换盒），而自动逻辑这段时间没有全程跟踪，若直接恢复自动流程，自动状态机可能基于过时/错误的账目动作（以为口空其实有盒、以为是 A 实际是 B）。先全量对账把 L/H 对齐到当前物理 P，确认一致后才允许自动握手和加工，等于"交接班先盘点"。
6. **对账 vs Spool**：互补的两层可靠性。**Spool 是增量可靠**——断线期间把关键事件缓存、重连后按序重发、确认后删除，保证"发生过的事件不丢、顺序不乱"，覆盖正常事件流；**对账是基线校准（全量快照）**——重连/切模式/异常后直接读当前全部物理状态，与逻辑账逐口比对，发现并纠正任何偏差，包括 Spool 无法覆盖的情况（断线时人工手动操作、硬件级异常、缓存本身遗漏）。关系：先靠 Spool 重发增量事件，再用全量对账兜底验证最终态；两者都过才能确信账实一致。只靠 Spool 不知道断线期间现场是否被手动改动，只靠对账则平时开销大、失去实时事件流，故结合使用。
7. **P无L有原因 / 处理**：可能原因：①盒被非正常取走（手动拿走/天车误取）而逻辑没收到正常移除流程；②移除事件丢失（断线且 Spool 未覆盖）；③传感器之前误报在位、建了虚账；④盒掉落/被取走的机械异常。处理：先复核物理（重读传感器、必要时人工确认口确实空），再核对该 Carrier 是否有在途基板在设备内（若曾 Loaded，要按非正常移除清点在途片），确认后以 P 为准补做移除销账（置口 Empty、Carrier NotInstalled/归档），发差异告警和审计记录，排查为什么会账实背离（流程漏洞/传感器/断线），Host 同步纠正镜像。不能简单删账了事，要追溯在途片和根因。

## 二、参考实现（net8.0）

### 模式管理 + 手动补登记 + 审计
```csharp
public enum OperationMode { Auto, Manual }
public sealed record AuditEntry(string Time,string Operator,string Action,string Lp,string Detail);

public sealed class ModeManager
{
    public OperationMode Mode { get; private set; } = OperationMode.Auto;
    public List<AuditEntry> Audit { get; } = new();
    private readonly LoadPortManager _mgr;
    public ModeManager(LoadPortManager mgr){_mgr=mgr;}
    public bool CanSwitchToAuto(Reconciler r, out List<string> diffs)
    {   // 手动切自动前强制对账
        diffs = r.Reconcile();
        return diffs.Count==0;
    }
    public void SwitchToManual(string op){ Mode=OperationMode.Manual; Audit.Add(new(DateTime.Now.ToString("o"),op,"切手动","-","Bypass")); }
    public void SwitchToAuto(string op, Reconciler r)
    {
        if(!CanSwitchToAuto(r,out var d)) throw new InvalidOperationException($"账实不一致,不能切自动:{string.Join(";",d)}");
        Mode=OperationMode.Auto; Audit.Add(new(DateTime.Now.ToString("o"),op,"切自动","-","对账一致"));
    }
    // 手动放盒补登记(仍走E87状态机)
    public VerifyDecision ManualPlace(string op,string lp,string carrierId,bool forceOverride,string reason)
    {
        Audit.Add(new(DateTime.Now.ToString("o"),op,"手动放盒",lp,$"id={carrierId},force={forceOverride},reason={reason}"));
        // 手动等价物理就位: 直接用已知ID建账(物理在位由人工确认)
        return _mgr.OnManualPlaced(lp,carrierId,forceOverride);
    }
    public void ManualRemove(string op,string lp)
    { Audit.Add(new(DateTime.Now.ToString("o"),op,"手动取盒",lp,"")); _mgr.OnPhysicalRemoved(lp); }
}
```

### 三方对账器
```csharp
public enum DiffKind { PhysicalHasLocalNone, LocalHasPhysicalNone, IdMismatch, LocalHostMismatch }
public record Diff(DiffKind Kind,string Lp,string Detail);

public sealed class Reconciler
{
    public interface IPhysicalView { bool Present(string lp); string? ReadId(string lp); }       // P
    private readonly LoadPortManager _local;                                                       // L
    public Func<string,string?>? HostView { get; init; }                                           // H
    private readonly IPhysicalView _phy;
    public Reconciler(LoadPortManager local,IPhysicalView phy){_local=local;_phy=phy;}

    public List<string> Reconcile()
    {
        var report=new List<Diff>();
        foreach (var lp in _local.PortIds)
        {
            bool present=_phy.Present(lp); var actualId=_phy.ReadId(lp);
            var carrier=_local.Port(lp).CarrierRef;
            bool localHas = carrier is not null;
            // 1) P有L无: 补建账(教学:返回差异,由上层决定补登)
            if (present && !localHas) report.Add(new(DiffKind.PhysicalHasLocalNone,lp,"物理有盒逻辑无账→补登"));
            // 2) P无L有: 异常销账
            if (!present && localHas) report.Add(new(DiffKind.LocalHasPhysicalNone,lp,"逻辑有盒物理空→非正常移除/补销账"));
            // 3) ID不一致: 冻结,不自动改
            if (present && localHas && actualId is not null && actualId!=carrier!.CarrierId)
                report.Add(new(DiffKind.IdMismatch,lp,$"账={carrier.CarrierId} 实物={actualId}→冻结人工"));
            // 4) L/H 偏差
            if (HostView is not null && localHas)
            { var hostId=HostView(lp); if(hostId is not null && hostId!=carrier!.CarrierId)
                report.Add(new(DiffKind.LocalHostMismatch,lp,$"L={carrier.CarrierId} H={hostId}→以L刷新H")); }
        }
        return report.Select(d=>$"[{d.Kind}]{d.Lp}:{d.Detail}").ToList();
    }
}
```

public class ModeReconcileTests
{
    [Fact] public void 手动放盒_仍建账并留审计()
    {
        var (mgr,mode)=Build();
        mode.SwitchToManual("op1");
        mgr.Reserve("LP1","A");
        var d=mode.ManualPlace("op1","LP1","A",false,"RFID故障,人工核对");
        Assert.Equal(VerifyDecision.Verified,d);
        Assert.True(mgr.AuthorizeLoad("LP1"));
        Assert.Equal(CarrierState.Loaded,mgr.Port("LP1").CarrierRef!.State);
        Assert.Contains(mode.Audit,a=>a.Action=="手动放盒");
    }
    [Fact] public void 账实不一致_禁止切自动()
    {
        var (mgr,mode)=Build(); var rec=new Reconciler(mgr,new PhysicalView{Has=false}); // 物理空
        mgr.Reserve("LP1","A"); mgr.OnPhysicalPlaced("LP1");                              // 逻辑有账
        Assert.Throws<InvalidOperationException>(()=>mode.SwitchToAuto("op1",rec));
    }
    [Fact] public void ID不一致_报冻结差异不自动改()
    {

    }

## 三、P/L/H 对账流程（手绘参考）
```
 触发: 重连 / 手动切自动 / 异常恢复
   │
   ▼ 逐口遍历
 读物理P(在位+RFID) ──比对── 设备账L(E87) ──比对── Host镜像H
   ├ P有L无 → 补建账(读ID→Installed,标对账补登)
   ├ P无L有 → 核在途片→非正常移除/补销账+告警
   ├ ID不符 → 冻结+高警报+人工(不自动改身份)
   └ L/H偏差→ 以贴近物理的L刷新H,重发状态
   │
   ▼ 全部一致才允许恢复自动/解锁
 基准: 有无/数量听物理P; 身份存疑冻结人工; Spool增量 + 对账全量双保险
```

## 四、今日易错点
1. 以为手动模式不用建 E87 账（手动只换物理执行者，逻辑记账一步不能少）。
2. 手动强制放行不留审计（操作人/时间/原因/依据必须可追溯）。
3. 对账以 Host 账目否定物理事实（基准是物理 P）。
4. ID 不一致自动用实物覆盖账（身份存疑必须冻结人工，防"洗白"错料）。
5. 手动切自动不盘点直接恢复（必须先对账一致才恢复自动）。
6. 只靠 Spool 不做全量对账（手动/硬件异常 Spool 覆盖不到）。
7. P无L有直接删账（要核在途片、查根因、按非正常移除处理）。
8. 混淆"有无可自动纠偏"和"身份必须人工"的安全边界。
