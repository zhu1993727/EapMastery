# W13 · Day05（周五）自动/手动双模式 + 账实一致性对账（Reconciliation）

> 建议时长：85 分钟。真实 FAB 不是永远全自动：维护、异常、RFID 故障时要切手动；断线重连、模式切换、异常恢复后必须重新对齐"物理现场 vs 逻辑账目"。今天实现自动/手动双模式，并重点做专家级能力——账实一致性对账。

## 一、今日目标
1. 实现自动/手动（Bypass）双模式切换，明确两种模式下 E84/E87 各自行为。
2. 掌握手动放/取盒后 E87 补登记流程，保证账实一致、全程留痕。
3. 实现账实对账器 Reconciler：以物理传感器为基准，核对 E87 状态与 Host 镜像，输出差异与纠正动作。
4. 掌握三类对账时机：上线/重连后、模式切换后、异常恢复后。
5. xUnit 覆盖手动补登记、重连对账纠偏、差异检测与告警。

## 二、背景知识（先读，30 分钟）

### 1. 自动模式 vs 手动模式
| 维度 | 自动模式 Auto | 手动模式 Manual/Bypass |
|---|---|---|
| E84 硬线 | 自动四相握手 | BYPS 旁路，人工放/取 |
| 触发源 | 桥接层自动产 Placed/Removed | 操作员手动登记/人工触发 |
| ID 校验 | 强制预约校验 | 仍要核对，可有权限人工确认放行（留痕） |
| E87 状态机 | 正常自动迁移 | 同样要迁移（手动也要建账），只是触发来自人工登记 |
| Host 知情 | 实时事件 | 必须显著上报"手动操作"，同步账目 |
- 核心：**手动只改变"物理动作由谁做"，不改变"逻辑必须如实记账"**。手动放了盒，E87 一样要建 Carrier、走状态机、报 Host，否则账实脱节。

### 2. 手动操作补登记流程
- 手动放盒（E84 Bypass，人工把 FOUP 放口上）：操作员在 EAP/HMI 选择口位、扫描/输入 CarrierID→系统仍做预约/ID 校验（可按权限人工强制确认，记录操作人/原因）→E87 手动触发等价 OnPhysicalPlaced→Installed→（授权）→Loaded。
- 手动取盒：人工取走前仍应走 Unload 逻辑（或有权限强制，留痕），取走后手动登记移除→NotInstalled。
- 每次手动操作产生审计记录（谁、何时、哪个口、哪个 ID、为什么手动、依据），用于追溯和 KPI（自动率统计）。

### 3. 账实一致性模型（三方）
- **物理事实 P**：每个 LoadPort 在位传感器 + RFID 实际读到的 ID（地面真相）。
- **设备逻辑账 L**：E87 LoadPortManager 里各口 Carrier/状态。
- **Host 镜像账 H**：Host 侧维护的各口载具状态。
- 一致性要求：对每个口，P、L、H 三者的"有无盒 + CarrierID + 状态"一致。任两者不一致即差异，需要对账。

### 4. 对账器 Reconciler 设计
- 输入：物理快照 P（遍历口读传感器+RFID）、设备账 L、Host 镜像 H（可查询）。
- 逐口比对，输出差异类型：
  - P有L无（物理有盒、逻辑没账，漏建账/丢事件）；
  - P无L有（逻辑有账、物理空，盒被异常取走/漏移除）；
  - ID 不一致（账上 A、实际 B，串盒/读错）；
  - L有H无 / 状态不一致（设备与 Host 镜像偏差，断线丢事件）。
- 纠正策略（以物理 P 为基准）：
  - P有L无→补建账（读 ID、走 Installed，标记"对账补登"）；
  - P无L有→按非正常移除/补移除处理，销账并核对在途片，告警；
  - ID 不一致→冻结、高警报、人工核查，不自动改 ID；
  - L/H 状态偏差→以设备 L（贴近物理）刷新 Host 镜像，重发当前状态。
- 原则：**数量/有无以物理为准可自动纠偏；身份 ID 不一致不自动改，冻结人工**（防止用错误覆盖错误）。

### 5. 三类对账时机
1. **上线/HSMS 重连后**：Spool 重发之外，主动全量对账，防止断线期间手动/异常变化丢事件。
2. **模式切换后**：手动切回自动时，先对账确认现场与账目一致，才允许恢复自动流程。
3. **异常恢复后**：急停/故障/非正常移除处理完，对账确认最终态再解锁口。

### 6. 与 Spool 的关系（复用 W08）
- Spool 保证断线期间"事件不丢、按序重发"（增量可靠）；对账是"全量快照核对"（基线校准）。
- 两者互补：Spool 处理正常事件流，重连后对账兜底，发现 Spool 也没覆盖的现场变化（如手动操作、硬件异常）。
