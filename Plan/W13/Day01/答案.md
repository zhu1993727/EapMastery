# W13 · Day01 答案

## 一、自测题标准答案
1. **三系统职责边界**：
   - **AMHS（天车/OHT）**：物理搬运执行方。受 Host 调度（去哪个口、送/取哪个 CarrierID），通过 E84 并行硬线和设备 Load Port 完成放/取盒的安全握手；不懂工艺、不维护载具逻辑状态，只负责把盒物理搬到/搬离。
   - **设备端（Load Port 控制器 + EAP/SECS 接口，即你开发的部分）**：枢纽。向下用 E84 和天车做物理交接，向上用 SECS/GEM/OSS 和 Host 交互；负责检测在位、读 RFID、跑 E87 Carrier 状态机、上报物理与载具事件、执行 Host 的授权/卸载命令、对接 E90/E40/E94 加工。
   - **Host（FAB EAP/MES）**：逻辑决策中心。掌握工艺计划，下预约、做 ID 校验决策、授权装载、建 PJ/CJ 任务、调度 AMHS、更新载具流向与账目。
   - 设备端把"物理世界（盒到底在不在口上）"翻译成"逻辑世界（Host 可管理的载具状态）"，是 AMHS 与 Host 之间不可替代的枢纽。

2. **13 步及通道归属**：
   - 走 SECS（软件）：1 预约（S15F9）、5 安装上报（S16F1）、6 授权（S15F9）、7 Loaded 事件、8 SlotMap/建任务、10 Unload、13 Removed 上报、Host 决策与调度消息。
   - 走 E84（硬线）：3 Deposit 硬握手、12 Pickup 硬握手。
   - 顺序：1 Host 预约→2 调度 AMHS→3 E84 Deposit→4 在位稳定 ON【对接点1】→5 读 ID+Installed 上报→6 Host 校验授权→7 Loaded→8 E90 SlotMap+建 PJ/CJ→9 加工→10 Unload→11 调度来取→12 E84 Pickup、在位 OFF【对接点2】→13 Removed+更新流向。

3. **两对接点触发 / E84 异常为何不触发 E87**：对接点1（物理→逻辑）由"E84 Deposit 正常回到 Idle 且在位传感器稳定去抖 ON"唯一触发 E87 OnPhysicalPlaced；对接点2（物理完成）由"E84 Pickup 正常完成且在位稳定 OFF"触发 OnPhysicalRemoved。E84 处于 SafeHold/EStopHold/握手未完成时，盒可能半悬、没坐实、归属不确定，"物理就位"这个事实并未成立，若此时触发 E87 建账，就会为一个没放稳/没交接成功的盒创建载具状态、甚至误授权，后续天车把盒拿走或盒掉落，账目全错。因此逻辑建账只认"物理正常完成+传感器稳定"，E84 异常一律不触发，从源头保证账有实据。

4. **四个互为前提 / 违反后果**：
   - ①先预约后到盒：无预约上料=准入异常，自动线 Hold；违反则计划外盒可能被误加工（混料）。
   - ②先 E84 Deposit 成功才 Installed：物理是逻辑前提；违反则为没放稳的盒建账，导致虚账/掉盒后状态错乱。
   - ③先 Loaded 授权才取片加工：授权是加工前提；违反则未校验/错料盒被开门取片，用错工艺报废整批。
   - ④先 Unload（PJ 结束、片归位）才正常 Pickup：逻辑放行是物理取走前提；违反则盒内还有在途片就被取走，丢片撞片。
   闭环：预约→物理进→逻辑授权→加工→逻辑放行→物理出，任何一步跳序都会破坏安全或账实一致。

5. **设备端为何是枢纽**：AMHS 只会物理搬盒、不懂工艺和账目，Host 只做逻辑决策、不直接感知物理硬件；唯独设备端同时连着两边——下接 E84 硬线/传感器知道盒物理在不在，上接 SECS 能和 Host 交换载具状态与命令，负责把物理事件翻译成 Host 能用的逻辑对象和事件，再把 Host 的决策翻译成对物理流程的放行。没有设备端这层，Host 不知道盒是否真的到位、能不能加工，AMHS 也不知道该不该放/取，所以它是物料流和信息流汇合的枢纽，也是 EAP 工程师的核心职责所在。

6. **哪三方一致 / 恢复基准**：要保证 ①AMHS 以为的盒位置（搬运系统在途/在某口）、②设备 E87 的载具状态和传感器事实、③Host(MES) 的载具账目三者一致。恢复时以**设备端物理传感器 + 当前可查询的真实状态为基准**（盒到底在不在口上、读到什么 ID、状态机当前态），通过重连后全量状态查询（S15F5 读 Carrier/LoadPort 属性，或 S1F3/F4）做对账（reconciliation），用设备物理真实去校正 Host 账目和 AMHS 在途信息，而不是反过来以账目否定物理事实。物理事实是最终依据，逻辑账目向物理对齐，冲突时挂起并人工确认。

7. **闭环一句话**：Host 先预约，AMHS 经 E84 把盒物理放上，设备 E87 识别上报、Host 校验授权后加工，加工完逻辑放行，再经 E84 物理取走、Host 更新流向——"预约→物理进→逻辑授权→加工→逻辑放行→物理出、账实始终一致"的无人闭环。

## 四、10 分钟讲解提纲（参考）
1. 开场：全自动 FAB 里一个 FOUP 从天上来到被加工再离开，经过三个系统、两条通道。
2. 决策起点：MES 排产，Host 先给设备口预约预期 ID，并调度天车。
3. 物理进：天车到，E84 硬线四相握手安全放盒，在位稳定 ON（讲为什么必须硬线、故障安全）。
4. 对接点1：物理成功触发 E87 安装，读 RFID 上报 Installed（只到这，不自动可加工）。
5. 逻辑授权：Host 比对预约 ID，一致才 AuthorizeLoad，守卫视 Verified/无 Hold/口正常，进 Loaded。
6. 加工：E90 读槽位、建 PJ/CJ，只在 Loaded 取片。
7. 逻辑放行：加工完、片全归位，Host Unload 进 Unloaded。
8. 物理出：天车 E84 Pickup 取走，在位 OFF，对接点2 触发移除，Host 更新流向。
9. 强调四个时序不可乱的前提和两对接点，以及为什么物理事实是对账基准。
10. 收尾：这套闭环保证无人值守下物料流和信息流严格一致、防错料、可追溯。

## 五、今日易错点
1. 把 13 步全当成 SECS 消息（3/12 是 E84 硬线，其余才是软件）。
2. 以为 Host 直接指挥天车放盒动作（物理动作是 E84 双边硬握手，Host 只调度不控动作）。
3. 对接点忽略"稳定去抖"和"E84 正常完成"（异常/瞬态不能建账）。
4. 四个前提顺序记乱（尤其 Loaded 先于取片、Unload 先于 Pickup）。
5. 对账时以 Host 账目否定设备物理事实（应以物理传感器真实态为基准校正逻辑）。
6. 混淆 E87 状态迁移和 E84 握手状态机（它们并行、在对接点咬合，不是一个状态机）。
7. 忽略 AMHS 也有自己的"以为位置"，三方一致才是真一致。
