# W25 · Day03（周三）Performance 要素：理想节拍、实际节拍、降速与小停顿

> 建议时长：90 分钟。今天攻克 OEE 里最难自动识别的 Performance：如何从设备数据得到理想节拍、如何测实际节拍、如何区分"正常波动/降速/小停顿"，并把这些损失量化成 Performance 率。复用 W18/W23 的 beat、Makespan、WPH。

## 一、今日目标
1. 明确理想节拍（Ideal Cycle Time）的来源与固定口径，理解实际节拍的测量点。
2. 实现 CycleTracker：逐片/逐作业采集实际 cycle，算平均节拍、WPH、节拍分布。
3. 建立小停顿（Minor Stop）识别规则：时长阈值、自动恢复、与停机/正常间隔的边界。
4. 建立降速（Reduced Speed）识别：实际节拍相对理想的偏离、持续性判定。
5. 量化 Performance 率并拆分为"小停顿损失 + 降速损失"；xUnit 验证。

## 二、背景知识（先读，30 分钟）

### 1. 理想节拍（Ideal Cycle Time / nameplate）
- 设备在良好稳定状态下加工单位产出（一片/一批/一个作业）所需的最短标准时间，来自设备规格、工艺验证或历史最佳（口径固定，W24 Day07 已讨论两种取法）。
- 多腔/流水线用**节拍 beat**（W18）：稳态下相邻产出间隔，Makespan≈首片时间+(n−1)×beat；OEE Performance 用稳态节拍做理想值，不用把首片/换型算进理想节拍。
- 理想节拍必须按产品/配方/路线分别设定（不同 recipe cycle 不同），不能一个全厂值。

### 2. 实际节拍测量
- 测量点：从一片开始加工到该片完成（或稳态相邻两片完成时刻之差=实际 beat）。
- 数据来自 E40 PJ Step 起止、E94 作业事件、EPT Productive 段（同源同戳，W24）。
- 区分：加工 cycle（纯工艺）与产出间隔 beat（含上下片/传片），Performance 用哪个要固定（通常用产出间隔对总产出负责）。

### 3. 小停顿 Minor Stop 识别
- 定义：设备处于运行态、无产出、持续时间在 [下限, 停机阈值) 内且自动恢复（不需维修介入）的短暂中断（卡料、传感器等待、短暂等臂）。
- 规则要素：最小可辨时长（去抖）、停机阈值 MinorStopLimit（超过则记 Availability 停机而非小停顿）、是否自动恢复、次数与累计时长。
- 小停顿次数多、单次短，易被"设备在运行"掩盖，必须逐次记录起止与原因。

### 4. 降速 Reduced Speed 识别
- 实际节拍持续高于理想节拍（慢），但设备没停：用滑动窗口实际节拍/理想节拍比值，超过 SlowRatio 阈值并持续 N 个周期判为降速段。
- 区分偶发波动（正常分布抖动，不判损失或用统计控制限）与系统性降速（均值漂移）。
- 降速损失=（实际节拍−理想节拍）×该段产出，折算为损失时间。

### 5. Performance 率与损失分解
- Performance=(IdealCT×TotalCount)/RunTime；RunTime=净加工时间+小停顿时间+降速损失时间（从 Productive/运行时间里拆）。
- 可分解：1−Performance ≈ 小停顿损失占比 + 降速损失占比（Run Time 口径下），用于定位是"频繁停"还是"一直慢"。
- 与 W23 PerfMetrics 对接：beat/WPH/资源利用率，瓶颈资源降速会拖垮整机 Performance（TOC）。

### 6. 典型陷阱
- 用含换型/首片的平均时间当实际节拍（虚降 Performance）；小停顿阈值不固定导致 A/P 乱归类；不按配方分理想节拍；把正常统计波动误判降速；只看平均节拍漏掉长尾小停顿。
