# W25 · Day03 答案与参考实现

## 一、自测题标准答案
1. **理想节拍来源/按配方/稳态 beat**：理想节拍来自设备规格书、工艺验证（量产验证中良好稳定状态）或受控的历史最佳，取最短可持续标准时间并固定口径。必须按产品/配方/工艺路线分别设定，因为不同 recipe 的工艺步骤、层数、时间天然不同，用一个全厂统一值会让复杂工艺被误判降速、简单工艺被高估。用稳态 beat（相邻产出间隔）而非"含首片/换型的平均时间"：流水线/多腔设备首片有爬坡（要填满流水线）、换型有一次性准备，这些属 Availability/启动损失而非稳态性能；稳态 beat 才代表设备满速时的单位产出能力，Makespan≈首片+(n−1)×beat，OEE Performance 衡量的正是稳态运行效率。
2. **两测量口径 / Performance 用哪个**：纯加工 cycle 是单片在工艺模块内真正反应/处理的时间（Step 起止）；产出间隔 beat 是稳态相邻两片完成时刻之差，含上下片、传片、多腔并行重叠后的净产出节奏。Performance 对"总产出/运行时间"负责，应使用**产出间隔 beat**（与 TotalCount、RunTime 同一口径：单位时间出多少片）；纯加工 cycle 用于工艺/腔体诊断。两者不能混——用纯加工 cycle 当理想节拍会忽略传片/上下片开销，使 Performance 虚高。
3. **小停顿判定要素 / 与停机分界**：要素=①设备处于运行态（没切 Down、没在换型）；②无产出的时间间隔；③时长落在[最小可辨（去抖）, 停机阈值 MinorStopLimit)区间；④自动恢复、无需维修介入；⑤逐次记录起止/原因/次数用于统计。与 Availability 停机分界看时长阈值与是否需介入：短于下限视为正常间隔/抖动不计，区间内且自动恢复=小停顿（Performance 损失），达到/超过停机阈值或需要维修介入=停机（Availability 损失，切 UnscheduledDown）。阈值与规则必须厂内固定、一致执行，避免同一事件在 A/P 间乱归类。
4. **正常波动 vs 系统降速**：实际节拍本身服从统计分布、有自然抖动，单点偶尔变慢不能判降速。做法：用滑动窗口计算实际节拍/理想节拍比值（或节拍均值），当比值持续超过 SlowRatio 阈值并维持 N 个周期（均值漂移、而非单点离群）才判为降速段；更严谨用统计控制限（均值±控制带，接 SPC 思想）区分"在控波动"与"失控漂移"。偶发离群点按小停顿/异常点处理，系统性均值上移才是 Reduced Speed，避免把正常随机波动误记为性能损失。
5. **Performance 损失分解**：Run Time 可拆为净理想加工时间（IdealCT×Total）+小停顿累计时长+降速损失时间（Σ(实际节拍−理想节拍)×对应产出）。Performance=理想加工时间/RunTime；于是 1−Performance=(小停顿时长+降速损失时长)/RunTime，可分别算小停顿损失占比与降速损失占比。这样能回答性能损失主要来自"频繁短暂停"（次数多、治稳定性/物流）还是"一直跑得慢"（均值漂移、治工艺/设备老化），两者改善手段不同。
6. **平均节拍为何漏小停顿**：平均节拍把所有产出时间摊薄，大量每次仅几秒的小停顿被平摊到均值里，只让平均节拍轻微变大，看起来"只是略慢"，却掩盖了"停顿了几百次、累计损失可观、且指向特定机构反复卡滞"的事实。必须同时统计小停顿次数、单次时长分布、累计时长与长尾（P95/P99 节拍），才能发现"均值正常但长尾停顿频发"的问题；只看均值会把可通过消除频繁微停获得的性能提升漏掉。
7. **瓶颈腔降速传导（TOC）**：整机产出节拍由瓶颈资源决定（W18/W23）。若瓶颈腔实际 cycle 变慢，稳态 beat 被拉长，单位时间 TotalCount 下降，Performance=(IdealCT×Total)/RunTime 随之下降，而非瓶颈腔降速若未超过瓶颈则不影响整机产出（有缓冲/并行吸收）。因此分析 Performance 降速要下钻到资源级节拍与利用率：瓶颈腔节拍漂移、瓶颈处小停顿会直接拖垮整机 Performance；W23 的资源利用率/beat 分布与此处逐片节拍同源，可定位是哪个腔让整机变慢，优先治瓶颈（非瓶颈提速不改变整机 beat，W23 对比实验已证）。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Oee.Perf;
public sealed record WaferCycle(string Recipe,double Start,double Complete,string? Bottleneck=null)
{ public double Interval; /*相邻完成间隔, 外部填*/ }

public sealed class CycleTracker
{
    private readonly Dictionary<string,List<double>> _byRecipe=new(); // 产出间隔beat
    private double? _lastComplete;
    public void Add(WaferCycle w)
    { double beat=_lastComplete is null?w.Complete-w.Start:w.Complete-_lastComplete.Value;
        w=w with{Interval=beat}; _lastComplete=w.Complete;
        if(!_byRecipe.ContainsKey(w.Recipe))_byRecipe[w.Recipe]=new();
        _byRecipe[w.Recipe].Add(beat); }
    public double AvgBeat(string r)=>_byRecipe[r].Average();
    public double Wph(string r)=>3600.0/AvgBeat(r);
    public double Percentile(string r,double p){var x=_byRecipe[r].OrderBy(v=>v).ToList();
        return x[Math.Clamp((int)Math.Ceiling(p*x.Count)-1,0,x.Count-1)];}
}

public sealed record MinorStop(double Start,double End)
{ public double Dur=>End-Start; }
public sealed class MinorStopDetector
{
    readonly double _debounce,_limit; public MinorStopDetector(double debounceSec,double stopLimitSec)
    {_debounce=debounceSec;_limit=stopLimitSec;}
    // 返回: 0正常间隔 1小停顿 2应判停机(达阈值)
    public int Classify(double gapSec)=>gapSec<_debounce?0:gapSec<_limit?1:2;
    public List<MinorStop> Stops=new();
    public void Observe(double gapStart,double gapEnd)
    { if(Classify(gapEnd-gapStart)==1)Stops.Add(new(gapStart,gapEnd)); }
    public double MinorStopTime=>Stops.Sum(s=>s.Dur);
}

public sealed class SlowSpeedDetector
{
    readonly double _ideal,_slowRatio;readonly int _need;
    private readonly Queue<double> _win=new();
    public SlowSpeedDetector(double idealBeat,double slowRatio=1.1,int consecutive=3)
    {_ideal=idealBeat;_slowRatio=slowRatio;_need=consecutive;}
    public bool IsSlow(double beat) // 滑窗: 连续N周期比值超阈值判降速
    { _win.Enqueue(beat);if(_win.Count>_need)_win.Dequeue();
      return _win.Count==_need && _win.All(b=>b/_ideal>_slowRatio); }
    public static double SlowLoss(double actualBeat,double idealBeat,int count)=>
        Math.Max(0,actualBeat-idealBeat)*count;
}

public sealed class PerformanceBreakdown
{
    public static double Rate(double idealSec,int total,double runSec)=>runSec<=0?0:idealSec*total/runSec;
    public static (double minorShare,double slowShare) Split(double runSec,double minorSec,double slowSec)
    =>(minorSec/runSec,slowSec/runSec);
}
```

### xUnit
```csharp
public class PerfTests
{
    [Fact] public void 节拍均值与WPH()
    { var t=new CycleTracker();
      foreach(var c in new[]{100.0,200,300,400})t.Add(new("R_A",c-100,c)); // beat=100
      Assert.Equal(100,t.AvgBeat("R_A"),3);Assert.Equal(36,t.Wph("R_A"),3); }
    [Fact] public void 小停顿阈值三分界()
    { var d=new MinorStopDetector(2,30);
      Assert.Equal(0,d.Classify(1));Assert.Equal(1,d.Classify(15));Assert.Equal(2,d.Classify(60)); }
    [Fact] public void 降速需连续超阈值_单点不判()
    { var d=new SlowSpeedDetector(100,1.1,3);
      Assert.False(d.IsSlow(120));Assert.False(d.IsSlow(95));
      Assert.False(d.IsSlow(120)); // 窗口被95打断
      var d2=new SlowSpeedDetector(100,1.1,3);
      Assert.False(d2.IsSlow(120));Assert.False(d2.IsSlow(120));Assert.True(d2.IsSlow(120)); }
    [Fact] public void Performance拆分为小停顿加降速()
    { double run=1000,minor=100,slow=150;
      var(m,s)=PerformanceBreakdown.Split(run,minor,slow);
      Assert.Equal(0.1,m,3);Assert.Equal(0.15,s,3);
      Assert.Equal(0.75,PerformanceBreakdown.Rate(75,10,1000),3); }

    { var t=new CycleTracker();
      for(int i=0;i<19;i++)t.Add(new("R",i*100,i*100+100));
      t.Add(new("R",1900,2000)); // 第20片beat=100正常, 再补一个长尾
```

## 三、Performance 识别链（手绘参考）
```
逐片完成事件(E40/E94同源) → 相邻完成差=实际beat(稳态口径, 按recipe)
理想beat: 规格/验证/历史最佳, 按配方分别固定, 用稳态beat不含首片换型
运行态无产出间隔:
  <去抖下限=正常; [下限,停机阈值)且自动恢复=小停顿MinorStop(Performance);
  ≥阈值或需维修=停机(Availability)
节拍变慢: 滑窗 actual/ideal>SlowRatio 连续N周期(或控制限) = 降速段; 单点抖动不算
RunTime=理想加工(IdealCT*Total)+小停顿时长+降速损失(Σ(actual-ideal)*n)
Performance=IdealCT*Total/RunTime; 1-P=小停顿占比+降速占比
诊断: 均值+次数+P95/P99长尾; 瓶颈腔变慢→整机beat变长→整机Performance降(TOC)
```

## 四、今日易错点
1. 理想节拍全厂一个值、不按配方分（误判降速）。
2. 用含首片/换型的均值当实际或理想节拍（混淆启动损失与性能）。
3. 纯加工 cycle 与产出 beat 混，Performance 口径与 Total/RunTime 不一致。
4. 小停顿阈值不固定，同一事件在 Availability/Performance 间乱归类。
5. 单点节拍抖动就判降速（要滑窗连续/控制限，区分统计波动）。
6. 只看平均节拍，漏掉高频小停顿与 P95/P99 长尾。
7. 降速损失不折算成时间，无法和小停顿相加分解 Performance。
8. 忽视瓶颈传导：去优化非瓶颈腔节拍，整机 Performance 不变。
