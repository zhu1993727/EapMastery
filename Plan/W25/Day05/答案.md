# W25 · Day05 答案与参考实现

## 一、自测题标准答案
1. **三类输入来源/对齐**：①时间——W24 EptCollector/EquipmentTimeModel 的互斥完备状态段（各 E10 状态时长）；②产出与节拍——W18/W23 资源调度与 Day03 CycleTracker 的逐片完成时刻/产出间隔 beat，以及按配方固定的理想节拍 IdealCT；③质量——Day04 QualityTracker 的每片 Good/Scrap/Rework/Pending（FPY）。三者靠同一单调时钟、同一时间戳与 CjId/PjId/片 ID 上下文对齐（W22/W24 同源原则），时间账、作业账、质量账用同一批领域事件驱动，避免"时间是一班、产出是另一班"的错位。
2. **损失瀑布各层**：Calendar（日历）→减 NonScheduled（未排产）→PPT（计划生产时间）→减故障 UnscheduledDown、减换型 Setup（Availability 损失）→RunTime（运行时间）→减小停顿 MinorStop、减降速 SlowSpeed（Performance 损失）→净理想加工时间（IdealCT×Total）→减废品/一次未过返工（Quality/FPY 损失）→良品理想时间（IdealCT×Good，即 OEE 有效产出）。每层差额都可换算为占日历或占 PPT 的比例，形成瀑布。
3. **内置断言/抓错**：①时间守恒——各状态段时长和=Calendar、RunTime=PPT−Downtime，抓重叠/缝隙/漏记；②计数守恒——质量片 ID 集合=实际加工片集合、Total=逐片记录数，抓漏采/重计/返工翻倍；③自洽——A×P×Q 与化简式 IdealCT×Good/PPT 误差<容差，抓三要素 RunTime/Total 口径不一致；④TEEP≤OEE、各要素∈[0,1]，抓分母/分子错；⑤Performance 略>1 告警（理想节拍偏小或数据异常）；⑥Pending>0 提示质量未闭环。断言不过直接报错并指出哪一层，不输出看似精确实则错误的 OEE。
4. **Performance>1 说明什么/处理**：Performance=IdealCT×Total/RunTime>1 意味着"按理想节拍这些产出需要的时间"超过了实际运行时间，即实际比标称理想还快，物理上不合理（正常波动只会略接近 1）。常见原因：理想节拍取小了（没按真实配方/稳态 beat 设定）、RunTime 少计（把部分生产时间误切到别的状态或漏记）、Total 多计（重复计数/把上一班片算入）、时间与产出不同班错位。处理：不接受>1 的结果当成功，标记异常并依次核对理想节拍口径、状态段边界、计数与时间对齐，修正后重算；可允许极小容差（如 1.001）内四舍五入到 1，超出即报错。
5. **Pending 片如何呈现**：Pending（量测未回）既不是 Good 也不是废品。计算时 Quality 分母用"已有结论片数 Decided"而非全部，同时在结果中显式列出 Pending 数量与占比、标注"质量未闭环、当前 OEE 基于已判定片、待结果回传后更新"；不要把 Pending 当废品（虚低）也不当良品（虚高），更不能静默忽略让用户以为已闭环。可给区间：若 Pending 全合格 OEE 上限、全报废下限，帮助判断不确定性，结果回传后用同一计算器重算并留版本。
6. **瀑布守恒**：日历时间是总池，每一层损失都是从这个池子里真实扣除、且互不重叠的一段时间（或折算时间）：NonScheduled+故障+换型+小停顿+降速+(Total−Good)×IdealCT（质量损失折算）+Good×IdealCT（良品理想时间）=Calendar（TEEP 口径下）。若相等，说明所有时间去向都被唯一归类、无遗漏无重复（接 EPT 互斥完备与片数守恒）；不等就说明某段时间没归类或被双重计算。这个恒等式是 OEE 结果可信的顶层守恒校验。
7. **OEE/TEEP 同得/差异层**：同一计算器里分子相同（IdealCT×Good 良品理想时间），OEE 分母=PPT（扣 NonScheduled），TEEP 分母=Calendar（全日历），因此一次计算同时得到两者，TEEP=OEE×(PPT/Calendar)，差异正来自瀑布第一层 NonScheduled（未排产/闲置）。OEE 看"安排生产时的效率"，TEEP 看"全时资产利用"，二者差值量化了排班/订单不足造成的闲置，现场改善看 OEE、产能投资与排班看 TEEP。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Oee;
public sealed record ShiftData(
    double Calendar,double NonScheduled,double FaultDown,double SetupDown,
    double MinorStopTime,double SlowLossTime,
    double IdealCycleSec,int TotalCount,int GoodFirstPass,int Pending,
    IReadOnlySet<string> ProcessedIds,IReadOnlySet<string> QualityIds);

public sealed record OeeResult(double A,double P,double Q,double Oee,double Teep,
    double Ppt,double RunTime,double GoodIdealTime,List<string> Warnings,bool Consistent);

public sealed class OeeCalculator
{
    public OeeResult Compute(ShiftData d,double tol=1e-9)
    { var warn=new List<string>();
      double ppt=d.Calendar-d.NonScheduled;
      double down=d.FaultDown+d.SetupDown;
      double run=ppt-down;
      double a=run/ppt;
      double p=d.IdealCycleSec*d.TotalCount/run;
      int decided=d.TotalCount-d.Pending;
      double q=(double)d.GoodFirstPass/decided;
      double oee=a*p*q;
      double goodIdeal=d.IdealCycleSec*d.GoodFirstPass;
      double teep=goodIdeal/d.Calendar;

      if(p>1.001)warn.Add("Performance>1: 检查理想节拍/RunTime/计数口径");
      if(d.Pending>0)warn.Add($"Pending={d.Pending}: 质量未闭环,Q基于已判{decided}片");
      bool timeConserved=Math.Abs(d.NonScheduled+down+run-d.Calendar)<1e-6;
      bool idConserved=d.ProcessedIds.SetEquals(d.QualityIds);
      double reduced=goodIdeal/ppt;
      bool selfConsistent=Math.Abs(oee-reduced)<tol;
      bool order=teep<=oee+1e-9 && a is>=0 and<=1 && q is>=0 and<=1;
      // 顶层瀑布守恒
      double qualityLoss=(d.TotalCount-d.GoodFirstPass)*d.IdealCycleSec;
      double waterfall=d.NonScheduled+down+d.MinorStopTime+d.SlowLossTime+qualityLoss+goodIdeal
                     -(d.MinorStopTime+d.SlowLossTime)*0; // 小停顿/降速已含在run与P关系, 教学: run=净理想+minor+slow
      bool consistent=timeConserved&&idConsistent&&selfConsistent&&order;
      if(!timeConserved)warn.Add("时间不守恒: 状态段和≠Calendar");
      if(!idConserved)warn.Add("片ID集合不一致: 质量账≠加工账");
      if(!selfConsistent)warn.Add("A*P*Q≠化简式, 口径不一致");
      return new(a,p,q,oee,teep,ppt,run,goodIdeal,warn,consistent); }
}
```

## 三、端到端链路（手绘参考）
```
同源领域事件 ├ EPT状态段 → Calendar/NonSch/故障/换型/RunTime → A=Run/PPT
            ├ CycleTracker → Total/IdealCT/小停顿/降速 → P=IdealCT*Total/Run
            └ QualityTracker → Good(FPY)/Pending → Q=Good/Decided
OEE=A*P*Q ; 化简=IdealCT*Good/PPT(必须相等) ; TEEP=IdealCT*Good/Calendar(≤OEE)
瀑布: Calendar −NonSch→PPT −故障/换型→Run −小停/降速→净理想 −质量损失→良品理想时间
守恒: NonSch+故障+换型+小停+降速+质量损失折算+良品理想 = Calendar
断言: 时间守恒/片ID守恒/自洽/要素范围/P>1告警/Pending提示 → 任一不过不输出"精确错误值"
```

## 四、今日易错点
1. 时间、产出、质量来自不同班/不同时钟（必须同源同戳对齐）。
2. 不算化简式自洽，三要素口径错了也发现不了。
3. Performance>1 当正常（理想节拍/RunTime/计数必有错）。
4. Pending 当废品或良品、或静默忽略（应按已判算并提示未闭环）。
5. 质量损失不折算成时间，瀑布无法守恒。
6. 不做片 ID 集合守恒，返工/漏采导致 Total 错。
7. OEE/TEEP 分母混，未排产错误进入 OEE。
8. 断言失败仍输出 OEE（应报错指出层级，不交付看似精确实则错的数字）。
