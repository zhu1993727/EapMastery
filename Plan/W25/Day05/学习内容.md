# W25 · Day05（周五）端到端 OEE 计算器：时间账 × 节拍产出 × 良率

> 建议时长：95 分钟。今天把 W24 的 EPT 时间账、本周 RAM/Performance/Quality 三块组装成一个端到端 OEE 计算器：输入一个班次的状态段、逐片节拍与质量结果，输出三要素、OEE/TEEP、完整损失分解（时间→性能→质量），并用化简式做自洽校验。这是设备端 OEE 数据链路的集大成。

## 一、今日目标

## 二、背景知识（先读，25 分钟）

### 1. 数据从哪来（全链路同源）
- 时间：W24 EptCollector/EquipmentTimeModel 的状态段（Productive/Standby/各 Down/NonScheduled）。
- 产出/节拍：W18/W23、Day03 CycleTracker 的逐片完成时间与理想节拍（按配方）。
- 质量：Day04 QualityTracker 的 Good/Scrap/Rework/Pending（FPY）。
- 三者用同一单调时钟、同一 Cj/Pj 上下文对齐（W22/W24 同源），否则 OEE 对不上。

### 2. 计算步骤（严格顺序）
1. 由状态段求 CalendarTime、NonScheduled、PPT=Calendar−NonScheduled、Downtime（故障+换型分列）、RunTime=PPT−Downtime。
2. Availability=RunTime/PPT；再分故障损失率、换型损失率。
3. 由逐片节拍求 TotalCount、理想节拍 IdealCT、小停顿时长、降速损失时长；Performance=IdealCT×Total/RunTime。
4. 由质量结果求 Decided、Good(FPY)、Quality=Good/Decided（Pending 处理见 Day04）。
5. OEE=A×P×Q；TEEP=IdealCT×Good/Calendar；自洽：A×P×Q≈IdealCT×Good/PPT。
6. 损失分解：把"日历时间→良品理想时间"的全部缺口逐层归因，各损失之和+良品理想时间=日历时间（守恒）。

### 3. 损失瀑布（waterfall）
- Calendar → 减 NonScheduled → PPT → 减故障/换型 → RunTime → 减小停顿/降速 → 净理想加工时间 → 减废品/返工(FPY) → 良品理想时间。
- 每一层的比例都可算，形成损失瀑布，一眼看出最大缺口在哪一层（接帕累托）。

### 4. 口径一致性检查（计算器内置断言）
- 时间守恒：各状态段和=Calendar；RunTime=PPT−Downtime。
- 计数守恒：质量片 ID 集合=加工片集合（Day04）；Total 与逐片记录数一致。
- 自洽：三要素乘积 vs 化简式误差<容差；TEEP≤OEE；各要素∈[0,1]（Performance 略>1 要告警：理想节拍取小了或数据错）。
- Pending 未闭环时给出提示，不静默计入。

### 5. 与先进 FAB 实践对齐
- 长鑫/中芯/台积电等在设备侧统一时间模型与原因码层级（E10/E116/E58 思想），OEE 由 MES/EAP/YMS 数据汇聚；设备端工程师要保证"一次采对、时间对齐、原因可下钻"，这正是本计算器校验的内容。具体指标命名/阈值以厂内标准为准。
