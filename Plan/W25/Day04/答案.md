# W25 · Day04 答案与参考实现

## 一、自测题标准答案
1. **Total/Good 口径 / FPY vs 最终良率**：Total Count=统计期内完成加工、离开设备（或该工艺段）的总片数（含合格、报废、一次未过需返工的片）；Good Count=其中合格片数。FPY（First Pass Yield 一次通过率）=第一次通过该工艺、未经任何返工就合格的片数/总片数；最终良率=经过一轮或多轮返工修复后最终合格的片数/总片数。最终良率≥FPY，差值正是被返工"救回"的比例；FPY 一次成型，最终良率允许返修后计入。
2. **OEE 为何用 FPY**：OEE 衡量设备有效利用，返工件第一次没合格、需要重新占用设备时间（再跑一遍工艺、占腔、占臂、占 Run Time），这是真实产能损失。用 FPY 时，一次未过的片不计入 Good，Quality 下降，正好反映返工损耗；若用最终良率，返工件最终合格也算 Good，Quality 不扣分，等于让返工"白用"的设备时间在质量维度隐身（虽然 Performance 会被拉长时间间接影响，但质量损失被掩盖、无法独立暴露返工问题）。因此经典 OEE Quality 取 First Pass 口径，与"有效产出=一次做好"的精益目标一致。
3. **返工三方面处理**：①片数——返工是同一物理片重新加工，不新增片，全局 SubstrateId 集合守恒（W14/W23），Total Count 不因为同一片返工而翻倍，只在它第一次产出时计一次；②加工次数——该片 reworkCount+1、占用设备时间累加（可多次过工艺，受 MaxRework 限制），用于谱系与产能核算；③OEE——质量维度按一次通过：第一次未过即非 Good（拉低 FPY/Quality），返工后合格计入最终良率但不回补 FPY；时间维度返工多跑的时间计入 RunTime（使产出间隔变大、Performance 下降）。计数守恒、次数累加、质量按 FPY、时间自然体现，四者各司其职。
4. **启动损失 vs 过程废品 / 改善**：启动损失（六大损失⑥）发生在开机、换型、PM 后暖机/工艺未稳定的首批片，用"换型或开工后前 N 片"窗口专门标记；过程废品（⑤）是稳态运行中随机/系统性产生的缺陷。分开是因为改善手段不同：启动损失靠标准化暖机程序、首件确认、recipe/参数管理、缩短稳定时间、换型后快速达标（SMED+首件）；过程废品靠稳态工艺控制（FDC 监控、SPC 统计过程控制、R2R 调参、设备稳定性）。混在一起会把"换型后必废几片"当成随机工艺缺陷，找错改善方向，也无法评估暖机改进效果。
5. **返工时间会否双重扣**：不会，前提是口径分清。OEE 三要素各扣一类、不重叠：Quality 只按片的合格性扣分（一次未过→非 Good，分子少一片），不再把返工时间折算进 Quality；返工实际多占用的设备时间体现在 RunTime 增大（同样的良品花了更多运行时间），由 Performance（理想节拍×总产出/RunTime）承担；Availability 只在真正停机时扣。即"片是否一次合格"归 Quality、"多花了多少运行时间"归 Performance，同一返工在两个维度反映的是两种不同性质损失（质量未一次做好 + 产能被额外占用），并非对同一笔时间重复扣减；切忌再在 Quality 里按时间扣一遍。
6. **量测未回的片如何处理**：设为 Pending/Undetermined（结果待定）状态，不计入 Good 也不计入 Scrap，更不能先当废品——外部量测（YMS/检测设备）结果有延迟，误判废品会虚低良率且可能错误报废好片。落账时该片在质量维度挂起，Total 可先计入"已加工待判"，等量测结果回传再定 Good/Scrap/Rework；统计 Quality 时分母用"已有结论的片"或单列待判数量并注明，班末仍有待定则在报告标注未闭环，后续回补。保证质量结论只来自真实检测、EAP 不臆造结果。
7. **与 E90 守恒对齐**：质量计数以全局唯一片 ID 为主键，与 E90 SubstrateTracker 的位置/片数账、W23 MultiCarrierLedger 对齐：每片有且仅有一条质量结论（或待定），Σ(Good+Scrap+Rework+Pending)=经过该工艺段的不同片数=E90 对应位置变动守恒的片数，返工不新增 ID。用片 ID 集合做交叉断言：质量台账的片 ID 集合应等于作业实际加工的片 ID 集合（无遗漏、无重复、无凭空多出），任何对不上说明漏采、重计或位置账错误，从源头保证质量数据与物流数据一致。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Oee.Quality;
public enum QResult{Pending,Good,Scrap,Rework}
public sealed record QItem(string WaferId,QResult Result,bool InStartupWindow,int ReworkRound=0);

public sealed class QualityTracker
{
    private readonly Dictionary<string,QItem> _byWafer=new(); // 片ID唯一, 不重复计数
    public void Record(QItem it)=>_byWafer[it.WaferId]=it;     // 同片重判覆盖, 不新增
    public int Total=>_byWafer.Count;
    public int Decided=>_byWafer.Values.Count(x=>x.Result!=QResult.Pending);
    public int Good=>_byWafer.Values.Count(x=>x.Result==QResult.Good && x.ReworkRound==0);
    public int Scrap=>_byWafer.Values.Count(x=>x.Result==QResult.Scrap);
    public int Rework=>_byWafer.Values.Count(x=>x.Result==QResult.Rework);
    public int Pending=>_byWafer.Values.Count(x=>x.Result==QResult.Pending);
    public int StartupBad=>_byWafer.Values.Count(x=>x.InStartupWindow && x.Result!=QResult.Good);
    public int ProcessBad=>_byWafer.Values.Count(x=>!x.InStartupWindow && x.Result==QResult.Scrap);

    public double Fpy()=>Decided==0?0:(double)Good/Decided;          // 一次通过率(OEE用)
    public double FinalYield(int recoveredAfterRework)=>
        Decided==0?0:(double)(Good+recoveredAfterRework)/Decided;    // 返工救回后的最终良率
    public bool Conserved(ISet<string> processedIds)
    =>_byWafer.Keys.ToHashSet().SetEquals(processedIds);             // 与E90片ID集合一致
}
```

### xUnit
```csharp
public class QualityTests
{
    static QualityTracker Build()
    { var q=new QualityTracker();
      q.Record(new("W1",QResult.Good,true));
      q.Record(new("W2",QResult.Scrap,true));     // 启动损失
      for(int i=3;i<=10;i++)q.Record(new("W"+i,QResult.Good,false));
      q.Record(new("W11",QResult.Rework,false,0));// 一次未过需返工
      q.Record(new("W12",QResult.Scrap,false));   // 过程废品
      q.Record(new("W13",QResult.Pending,false)); // 量测未回
      return q; }
    [Fact] public void 片ID唯一_返工不翻倍()
    { var q=Build();q.Record(new("W11",QResult.Good,false,1)); // 返工后合格, 覆盖不新增
      Assert.Equal(13,q.Total);Assert.Equal(12,q.Decided);Assert.Equal(1,q.Pending); }
    [Fact] public void FPY低于最终良率()
    { var q=Build();double fpy=q.Fpy();
      Assert.True(q.FinalYield(1)>fpy); } // W11返工救回
    [Fact] public void 启动与过程废品分开()
    { var q=Build();Assert.Equal(1,q.StartupBad);Assert.Equal(1,q.ProcessBad); }
    [Fact] public void 待判不算废品也不算良品()
    { var q=Build();Assert.Equal(1,q.Pending);Assert.DoesNotContain(QResult.Pending,new[]{QResult.Good,QResult.Scrap}); }
    [Fact] public void 与E90加工片集合守恒()
    { var q=Build();
      var processed=Enumerable.Range(1,13).Select(i=>"W"+i).ToHashSet();
      Assert.True(q.Conserved(processed));
      processed.Add("W99");Assert.False(q.Conserved(processed)); }
    [Fact] public void OEE质量用FPY()
    { var q=Build(); // 10 good(first pass)/12 decided (W13 pending剔除)
      Assert.InRange(q.Fpy(),0,1); }
}
```

## 三、Quality 落账（手绘参考）
```
每片(全局唯一ID, 接E90/W23) → 检测/分档结果
  Pending(量测未回,挂起不判) | Good一次合格 | Scrap报废 | Rework可返工
  标记 InStartupWindow(换型/开工前N片) → 启动损失 vs 稳态过程废品
计数: Total=不同片数(返工不增片); FPY=一次Good/已判; 最终良率=(Good+返工救回)/已判
OEE-Quality 用 FPY: 一次未过即非Good, 返工救回不回补FPY
返工: 片数守恒 + reworkCount累加 + 额外RunTime归Performance(不在Q里再扣时间)
守恒断言: {质量台账片ID} == {E90实际加工片ID}, Good+Scrap+Rework+Pending=加工片数
启动损失→暖机/首件/recipe管理; 过程废品→FDC/SPC/R2R稳态控制
```

## 四、今日易错点
1. 用最终良率当 OEE Quality（掩盖返工占用的产能，应用 FPY）。
2. 返工片重复计入 Total（同片不增 ID，片数守恒）。
3. 返工时间在 Quality 与 Performance 双重折算（质量看片、时间看 RunTime，各司其职）。
4. 启动损失与过程废品混标，找错改善方向。
5. 量测未回直接判废（应 Pending 挂起，结果回传再定）。
6. 质量台账与 E90 片 ID 集合不做守恒交叉断言。
7. EAP 自行篡改/臆造质量结论（结论只来自真实检测，EAP 关联落账）。
8. 不关联 Cj/Pj/Step/缺陷代码，质量损失无法下钻到工艺段/批次。
