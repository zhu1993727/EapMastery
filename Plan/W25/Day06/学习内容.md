# W25 · Day06（周六）OEE 综合实验：一班端到端效率分析与改善对比

> 建议时长：110 分钟。今天把 RAM+OEE 全要素用于一个完整班次：复用 W24 的 8h 时间账，叠加逐片节拍、小停顿、降速、良率/返工，用 OeeCalculator 算出 A/P/Q、OEE/TEEP 与损失瀑布，再做"改善前 vs 改善后"对比实验，验证不同改善杠杆对 OEE 的提升，形成一份可向团队讲解的 OEE 分析报告。

## 一、今日目标
1. 组装一个完整 ShiftData（在 W24 班次时间账基础上补节拍/质量），端到端算 OEE。
2. 输出损失瀑布与帕累托，指出本班最大损失层与责任归属（设备/工艺/外部）。
3. 设计三组改善：治故障（提 A）、治降速小停顿（提 P）、治废品返工（提 Q），分别量化 OEE 提升。
4. 验证 TOC：只提升非瓶颈/只改善最小损失要素，OEE 提升有限；攻最大损失杠杆最大。
5. 产出 OEE 分析报告（数据、三要素、瀑布、帕累托、改善对比、建议）。

## 二、基线场景（8h=28800s，在 W24 基础上补数据）
- 时间账（W24）：Productive 22800、Standby 3000、Engineering 900、ScheduledDown(换型)1200、UnscheduledDown(故障)900、NonScheduled 0。
- 注意：OEE 的 PPT 口径下，RunTime=PPT−故障−换型=28800−900−1200=26700（Standby/Engineering 属运行内损失，由 Performance/管理口径体现，本实验按经典 OEE：Downtime 只取故障+换型，其余运行时间进入 RunTime）。
- 理想节拍 IdealCT=100s/片；实际总产出 Total=240 片（其中小停顿累计 300s、降速损失 500s 已体现在 RunTime 内）。
- 质量：一次合格 Good(FPY)=231，过程废品 5、返工一次未过 4（其中 3 片返工后合格）、启动不良 0（本例简化），Pending=0。
