# W25 · Day02 答案与参考实现

## 一、自测题标准答案
1. **三要素与化简式**：Availability=Run Time/Planned Production Time；Performance=(Ideal Cycle Time×Total Count)/Run Time；Quality=Good Count/Total Count。连乘：OEE=A×P×Q=(RunT/PPT)×(IdealCT×Total/RunT)×(Good/Total)，RunT 与 Total 约掉，化简为 **OEE=(Ideal Cycle Time×Good Count)/Planned Production Time**——即"全部良品按理想节拍所需时间"占计划生产时间比例。化简式是校验三要素计算自洽的金标准（乘出来必须等于化简式，否则口径不一致）。
2. **Planned Production Time / TEEP 分母**：PPT=日历总时间−Non-Scheduled（无订单、停产、法定休息等非设备责任、根本不安排生产的时间），再明确计划停机（换型/PM）在经典 OEE 里仍含在 PPT 内、由 Availability 扣减。OEE 分母是 PPT；TEEP 分母是全部日历时间（连未排产也包含），因此 TEEP=OEE×(PPT/日历时间)，把"没安排生产"也计入损失，衡量资产全时利用。两者差在是否把 Non-Scheduled 放进分母。
3. **六大损失归属 / 小停顿**：Availability——①故障停机（UnscheduledDown）、②换型调整（ScheduledDown 中的 Setup）；Performance——③空转小停顿、④降速运行；Quality——⑤过程废品缺陷、⑥开机/暖机/换型启动不良与返工。小停顿不是 Availability：它极短、自动恢复、设备并未真正进入"停机/不可用"状态（状态仍是运行中），若每次都计停机会把可用率切碎且不反映整体可用性；其影响是"在运行但有效产出速率下降"，正好由 Performance（实际产出/理想产出）累计体现。小停顿与停机按持续时长阈值、是否需人工介入固定划分。
4. **Performance 捕捉变慢 / 数据**：设备一直处于 Productive（Availability 不扣分），但每片实际 cycle time 大于理想节拍、或夹杂小停顿，单位时间产出变少。Performance=(Ideal Cycle Time×Total Count)/Run Time，用"这些总产出按理想节拍本应花的时间"除以"实际运行时间"，比值<1 即降速/小停顿损失。需要的数据：理想节拍 Ideal Cycle Time（工程标准/理论，口径固定）、总产出片数 Total Count、实际运行时间 Run Time——前两者来自 E40/E94 作业与计数，后者来自 EPT 时间账。
5. **OEE vs TEEP 关系**：TEEP≤OEE。OEE 分母只到 PPT（已扣未排产），TEEP 分母是更大的全部日历时间，分子（良品理想时间）相同，分母变大故 TEEP 更小。差值=未排产/非计划安排造成的资产闲置损失。OEE 回答"安排生产时干得好不好"，TEEP 回答"这份资产在全部时间里创造了多少有效产出"，产能投资/排班决策看 TEEP，现场改善看 OEE，不可混用。
6. **换型归属 / 不重不漏**：换型 Setup&Adjustment 属 Availability 损失（经典六大损失第②项），是计划内但不产出的停机，在 PPT 内由 Availability 扣减（Run Time=PPT−故障−换型）。不能忽略——否则可用率虚高、掩盖可通过 SMED 快速换型改善的损失；也不能重复计——不能既在 Availability 扣换型时间，又在 Performance 里把换型后的启动降速重复算（换型后的启动不良归 Quality 的 Startup 损失，但换型停机本身只在 Availability 计一次），每段时间/每片产出只能归一类损失。
7. **乘积与化简式对不上的口径问题**：逐项排查——①时间口径：Availability 用的 Run Time 与 Performance 分母 Run Time 是否同一口径（是否都扣了同样的停机、小停顿有没有被两边都扣）；②计数口径：Performance 的 Total Count 与 Quality 分母 Total Count 是否同一批（是否一个用投入、一个用产出，是否含返工片）；③理想节拍：是否前后一致、单位统一；④良品口径：Good Count 是否与 Total 同范围（Good=Total−废品−返工）；⑤时间单位：cycle time 与 PPT 是否同为秒/分。最常见是 Run Time 或 Total Count 在两要素里定义不一致，导致约分失败，必须用同一权威数据源（EPT 时间账 + 作业计数）。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Oee;
public sealed record OeeInput(
    double CalendarTime, double NonScheduled, double Downtime, // 秒, Downtime=故障+换型
    double IdealCycleSec, int TotalCount, int GoodCount);

public sealed class OeeModel
{
    public double PlannedProductionTime(OeeInput i)=>i.CalendarTime-i.NonScheduled;
    public double RunTime(OeeInput i)=>PlannedProductionTime(i)-i.Downtime;
    public double Availability(OeeInput i)=>RunTime(i)/PlannedProductionTime(i);
    public double Performance(OeeInput i)=>
        i.RunTime()<=0?0:(i.IdealCycleSec*i.TotalCount)/RunTime(i);
    public double Quality(OeeInput i)=>i.TotalCount==0?0:(double)i.GoodCount/i.TotalCount;
    public double Oee(OeeInput i)=>Availability(i)*Performance(i)*Quality(i);
    // 化简式: 良品理想时间 / PPT
    public double OeeReduced(OeeInput i)=>
        PlannedProductionTime(i)<=0?0:(i.IdealCycleSec*i.GoodCount)/PlannedProductionTime(i);
    // TEEP: 分母为全部日历时间
    public double Teep(OeeInput i)=>
        i.CalendarTime<=0?0:(i.IdealCycleSec*i.GoodCount)/i.CalendarTime;

    public bool SelfConsistent(OeeInput i,double tol=1e-9)=>Math.Abs(Oee(i)-OeeReduced(i))<tol;
}
```

### xUnit
```csharp
public class OeeModelTests
{
    // 一班: 日历28800, 未排产0, 停机2100(故障900+换型1200), 理想节拍100s/片, 总产228片, 良品220
    static readonly OeeInput In=new(28800,0,2100,100,228,220);
    [Fact] public void 三要素乘积等于化简式()
    { var m=new OeeModel();Assert.True(m.SelfConsistent(In)); }
    [Fact] public void 时间口径()
    { var m=new OeeModel();Assert.Equal(28800,m.PlannedProductionTime(In));Assert.Equal(26700,m.RunTime(In)); }
    [Fact] public void 三要素范围合理()
    { var m=new OeeModel();
      Assert.InRange(m.Availability(In),0,1);Assert.InRange(m.Performance(In),0,1.0001);
      Assert.InRange(m.Quality(In),0,1); }
    [Fact] public void TEEP不大于OEE()
    { var m=new OeeModel();Assert.True(m.Teep(In)<=m.Oee(In)); }
    [Fact] public void 有未排产时TEEP更低_OEE不变()
    { var m=new OeeModel();var a=In with{NonScheduled=3600,CalendarTime=28800};
      Assert.True(m.Teep(a)<m.Teep(In)); }
    [Fact] public void 换型计入可用率损失()

      Assert.True(m.Performance(slow)<m.Performance(In)); }
}
```

## 三、OEE 损失树（手绘参考）
```
日历时间
├ Non-Scheduled(未排产/停产) ─────── TEEP才计, OEE分母PPT已剔除
└ Planned Production Time(PPT)
   ├ Downtime → Availability损失: ①故障 ②换型Setup
   └ Run Time
      ├ 小停顿+降速 → Performance损失: ③Idling/MinorStop ④ReducedSpeed
      └ 净运行(理想节拍)
         ├ 废品/返工/启动不良 → Quality损失: ⑤ProcessDefect ⑥Startup/ReducedYield
         └ 良品理想时间 = OEE有效产出
A=RunT/PPT; P=IdealCT*Total/RunT; Q=Good/Total
OEE=A*P*Q=IdealCT*Good/PPT(化简金标准); TEEP=IdealCT*Good/日历 (≤OEE)
每段时间/每片只归一类损失, 三要素用同一权威时间账与作业计数
```

## 四、今日易错点
1. 用日历时间当 OEE 分母（那是 TEEP；OEE 用 PPT=日历−NonScheduled）。
2. 换型漏计（可用率虚高）或换型损失在 A、Q 重复计。
3. Performance 直接填 100%（忽略降速/小停顿，OEE 虚高）。
4. Quality 分母用投料而非总产出，或 Good/Total 不同批。
5. 小停顿当停机切 Availability（应归 Performance，阈值固定）。
6. 三要素 Run Time/Total Count 口径不一致，乘积对不上化简式。
7. 理想节拍前后不统一、时间/节拍单位混用。
8. OEE 与 TEEP 混用、不标注口径做横向比较。
