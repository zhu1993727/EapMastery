# W08 · Day01 答案与参考

## 一、自测题标准答案
1. **配置采集什么 / 什么时候采集 / 使能异常通知分别是哪步**：①**配置采集什么**=步骤 10-11（S2F33 定义报告，指定 RPTID 包含哪些 VID 变量）；②**配置什么时候采集**=步骤 12-15（S2F35 关联事件，指定 CEID 事件触发时上报哪些 RPTID 报告）；③**使能异常通知**=步骤 16（S5F3 使能报警，ALED=1，报警状态变化时才发 S5F1 上报）。三者配合：报告定义内容，事件定义时机，报警使能控制异常通知。
2. **Host 发 START 前必须完成的前置步骤（至少 5 步）**：①**TCP 连接 + HSMS Select**（W2，通信通道建立）；②**S1F13 建立通信**（W5，交换 MDLN/SOFTREV）；③**S1F17 请求在线**（W5，通信 ON-LINE）；④**控制 ONLINE**（W5，操作员切远程，否则 S2F41 被拒绝 ACKC10=4）；⑤**能力发现**（W6/W7，S1F3 查 SV、S1F5 查事件、S5F5 查报警，知道设备支持什么）；⑥**配置数据采集**（W6，S2F33 定义报告 + S2F35 关联事件，否则收不到命令执行结果的 S6F11）；⑦**使能报警**（W7，S5F3，否则收不到报警 S5F1）；⑧**下载配方**（W7，S7F3，否则 START 指定的配方不存在，命令失败）。这 8 步完成后，Host 才能发 START 并正确接收执行结果。
3. **命令执行过程中 Host 收到哪些 S6F11 / 对应什么 CEID**：①**命令开始**（CEID=3101，PENDING→EXECUTING 时触发，关联状态报告）；②**Lot 开始**（CEID=3001，工艺执行开始时触发，关联工艺数据报告）；③**Wafer 开始/结束**（CEID=3002/3003，每片 Wafer 开始/结束时触发，如果配置了关联）；④**Lot 结束**（CEID=3004，工艺执行完成时触发，关联工艺数据+状态报告）；⑤**命令完成**（CEID=3102，EXECUTING→COMPLETED 时触发，关联状态报告）。如果命令失败，还会收到**命令失败**（CEID=3103，关联状态报告，含失败原因）。每个 S6F11 都带 DATAID、CEID 和关联的报告列表，Host 回 S6F12 确认。
4. **工艺执行中触发温度过高报警，流程怎么变化 / Host 收到哪些消息**：工艺执行中触发温度过高报警（ALID=1001，严重）时：①设备设置报警（状态 CLEAR→SET）→ 发 **S5F1**（ALID=1001，报警设置）→ Host 回 **S5F2**；②严重报警中断命令 → 命令从 EXECUTING→**FAILED**（失败原因="温度过高中断"）→ 触发**命令失败事件**（CEID=3103）→ 发 **S6F11**（含状态报告和失败原因）→ Host 回 **S6F12**；③工艺执行停止（不再继续后续 Wafer）；④设备可能进入 Hold 状态或安全状态。Host 收到 S5F1 和 S6F11 命令失败事件后，应该通知操作员、暂停派工、触发维护流程。注意：命令失败是在 S2F42 ACKC10=0（命令已接受）之后发生的，所以 Host 不会收到 ACKC10 非 0，而是收到 S6F11 命令失败事件。
5. **哪些消息是 Host 主动发的 / 哪些是设备主动发的**：**Host 主动发的 primary**（W=1，设备回 reply）：S1F13、S1F15、S1F17、S1F3、S1F5、S1F7、S1F11、S2F33、S2F35、S5F3、S5F5、S7F3、S2F41、HSMS Select.req、Deselect.req。**设备主动发的 primary**（W=1，Host 回 reply）：S5F1（报警上报）、S6F11（事件上报）。**reply 消息**（W=0，不需要再回）：S1F14、S1F16、S1F18、S1F4、S1F6、S1F8、S1F12、S2F34、S2F36、S5F4、S5F6、S5F2（Host 回）、S6F12（Host 回）、S7F4、S2F42、Select.rsp、Deselect.rsp。关键区分：Host 主动发的是"请求/查询/命令"，设备主动发的是"通知/上报"（报警和事件）。
6. **断开前为什么先发 S1F15 再 Deselect / 直接 TCP 断开的问题**：①**S1F15 请求离线**是 GEM 层的优雅断开——通知设备"Host 要离线了"，设备可以做清理工作（停止事件上报、取消命令队列、记录日志），并回 S1F16 确认。通信状态从 ON-LINE→OFF-LINE，控制状态自动回 OFF-LINE。②**HSMS Deselect**是传输层的优雅断开——通知设备"Host 要取消 Select 状态"，设备回 Deselect.rsp，状态从 SELECTED→NOT SELECTED。③**TCP 断开**是最底层的连接关闭。顺序是 GEM 层→传输层→网络层，逐层优雅断开。**直接 TCP 断开的问题**：设备不知道 Host 是正常断开还是异常断开，可能会：①继续尝试发 S6F11/S5F1（发送失败，浪费资源）；②命令队列中的命令可能继续执行（没有收到离线通知）；③设备日志记录异常断开（而不是正常离线）；④Spool 可能被触发（设备认为通信中断，开始缓存事件/报警，W8 Day02 细讲）。专家实践：总是按 S1F15→Deselect→TCP 断开的顺序优雅断开，不要直接拔网线或关 TCP。

## 三、GEM 内核全栈能力速查表（8 层）
| 层 | 能力 | 关键组件 | 关键消息 |
|---|---|---|---|
| 1. 传输层 | TCP 连接、HSMS 连接、Select/Deselect、Linktest、T 超时 | HsmsConnection、HsmsStateMachine | Select.req/rsp、Linktest、Deselect |
| 2. 编码层 | SECS-II Item 模型、格式字节、List 递归、编码/解码 | SecsItem、SecsEncoder、SecsDecoder | 所有消息的 body |
| 3. 事务层 | primary/reply、SystemBytes 配对、多块消息、S9 错误 | TransactionManager、MultiBlockAssembler | S9F3/F5/F7/F11 |
| 4. GEM 状态层 | 通信状态(OFF/ON)、控制状态(OFF/ON)、建立通信、在线/离线 | GemStateMachine、S1Handler | S1F13/F14、S1F15/F18 |
| 5. 数据采集层 | 变量/事件/报告、定义报告、关联事件、S6F11 上报、S1 查询 | ReportStore、EventReportLinkStore、EventReportEngine、S1QueryHandler | S2F33/F34、S2F35/F36、S6F11/F12、S1F3/F11 |
| 6. 报警层 | 报警状态机(SET/CLEAR)、报警上报、使能/禁用、列表查询 | AlarmStore、S5F1Sender、S5F3Handler、S5F5Handler | S5F1/F2、S5F3/F4、S5F5/F6 |
| 7. 远程命令层 | 命令队列、异步执行、命令状态机、完成/失败事件通知 | RemoteCommandEngine、S2F41Handler、CommandEventBridge | S2F41/F42 |
| 8. 配方层 | 配方上传/下载/删除、配方校验、配方和 R2R 关系 | RecipeStore、S7F1Handler、S7F3Handler、S7F17Handler | S7F1/F2、S7F3/F4、S7F17/F18 |

## 四、端到端集成验证要点
- 所有 8 层组件协同工作，消息从 Host 发出到设备处理再到回复，每步的 hex 和状态变化可追溯。
- 完整流程 28 步，每步都有对应的消息和状态变化，无遗漏。
- 设备主动发的 S5F1/S6F11 能正确触发（报警使能、事件关联后），Host 能正确回 S5F2/S6F12。
- 命令执行过程中，命令状态 PENDING→EXECUTING→COMPLETED/FAILED 正确变化，状态变化触发对应的 S6F11。
- 断开连接按 S1F15→Deselect→TCP 顺序，设备正确清理状态。

## 五、今日易错点
1. 发 START 前不配置数据采集（收不到命令执行结果的 S6F11）。
2. 发 START 前不使能报警（收不到报警 S5F1）。
3. 发 START 前不下载配方（配方不存在，命令失败）。
4. 混淆命令接受（ACKC10=0）和命令完成（S6F11 事件）。
5. 直接 TCP 断开，不按 S1F15→Deselect 顺序优雅断开（设备可能异常处理）。
6. 完整流程中漏掉能力发现步骤（S1F3/S1F5/S5F5），盲目配置可能引用不存在的 VID/CEID/ALID。
7. S6F11 事件的 CEID 对应关系记错（命令开始=3101、命令完成=3102、命令失败=3103、LotStart=3001、LotEnd=3004）。
8. 以为所有事件都会发 S6F11（只有通过 S2F35 关联了报告的事件才发）。
