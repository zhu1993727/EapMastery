# W08 · Day02 答案与参考实现

## 一、自测题标准答案
1. **Spool 是什么 / 为什么需要 / 通信中断时怎么处理事件报警**：Spool（假脱机/缓存）是设备在通信中断时，把要发给 Host 的事件报告（S6F11）和报警（S5F1）缓存到本地存储，等通信恢复后再重发给 Host 的机制。需要 Spool 是因为 FAB 中设备可能因网络故障、Host 重启、维护等原因短暂断开，如果没有 Spool，中断期间的工艺数据（Wafer Start/End、Lot End）和报警就丢失了，Host 无法追溯生产历史和异常。通信中断时，设备切换到 Spool 模式：事件/报警不再直接发给 Host，而是写入 Spool 缓存（带时间戳和序列号），等通信恢复后按时间顺序重发。
2. **Spool 触发条件 / 通信恢复后怎么重发**：触发条件：①通信 OFF-LINE（S1F15 或设备主动离线）；②HSMS 断开（TCP 断开、Select 丢失）；③Host 不回确认（T3 超时，取决于设备实现）。恢复后重发流程：①设备检测到通信恢复（ON-LINE + Select 重新建立）；②查询 Spool 缓存是否有未发送记录；③有则按时间顺序（最早的先重发）逐条重发 S6F11/S5F1，每条带原始 body 和时间戳；④Host 回 S6F12/S5F2 确认后，设备从缓存中删除该记录；⑤全部重发完成后，Spool 清空，切换回正常上报模式。重发速率可能受限（避免 Host 过载），确认丢失可能导致重发（Host 需去重）。
3. **Spool 缓存在哪里 / 容量满了怎么办 / Host 怎么监控容量**：存储位置：①内存（RAM）——速度快但断电丢失，适合短期缓存；②非易失性存储（Flash/EEPROM/硬盘）——断电不丢，适合长期缓存，先进设备通常用这个。容量满时的策略（取决于设备实现）：①丢弃最旧的记录（FIFO，保留最新）；②拒绝新记录（停止缓存）；③覆盖最旧（环形缓冲区）。Host 监控容量：通过 S2F43（Spool 控制，查询操作）查询 Spool 状态（已用容量、剩余容量、记录数），在容量满之前恢复通信或清空 Spool。Host 建链后也应该查询设备的 Spool 最大容量（设备能力），评估通信中断的最大可容忍时间。
4. **S2F43/S2F44 作用 / Host 可以做哪些操作**：S2F43/S2F44 是 Host 控制 Spool 的接口。Host 可以做的操作（具体操作码以 E30 标准和设备实现为准）：①**查询 Spool 状态**——查询已用容量、剩余容量、记录数、是否启用；②**清空 Spool**——删除所有未发送的缓存记录（慎用，会丢失数据）；③**启用/禁用 Spool**——开启或关闭 Spool 功能（禁用后通信中断时事件/报警直接丢弃）；④**请求重发**——主动请求设备重发 Spool 中的记录（部分设备支持）。S2F44 是设备的确认，返回操作结果（ACKC=0 成功，非0失败）和查询操作时的 Spool 状态。
5. **Spool 重发和实时上报格式一样吗 / Host 怎么区分和去重**：格式**一样**——Spool 重发的 S6F11/S5F1 和实时上报的消息格式完全相同（标准的 SECS-II 消息），Host 不需要特殊解析。Spool 是透明的，Host 收到的消息格式统一。Host 区分和去重的方式：①**时间戳**——设备重发时可能在消息 body 中带原始时间戳（或通过 SV 查询），Host 根据时间戳判断是历史事件还是实时事件；②**序列号**——设备给每条消息分配唯一序列号，重发时序列号不变，Host 根据序列号去重；③**Spool 重发标志**——部分设备在重发时带特定标志（如扩展字段），Host 可以识别；④**DATAID**——S6F11 带 DATAID，如果 Host 知道配置变更时间，可以判断消息是哪个配置版本的。专家实践：Host 维护"已处理消息序列号"集合，收到重复序列号时跳过。
6. **通信中断时设备内部命令执行和工艺控制会停止吗 / Spool 影响内部状态吗**：**不会停止**。通信中断只影响"设备和 Host 之间的通信"，不影响设备内部的命令执行、工艺控制、报警检测、事件触发。设备在通信中断时仍然正常运行：命令队列中的命令继续执行、工艺继续加工、报警继续检测和设置、事件继续触发——只是这些事件和报警不发给 Host，而是写入 Spool 缓存。Spool 是"通信层的缓存机制"，不是"设备运行的暂停机制"。这是关键设计——设备的运行不依赖 Host 的连接，Host 只是监控和管理方，设备可以独立运行。等通信恢复后，Host 通过 Spool 重发补收中断期间的所有事件和报警，恢复对设备状态的认知。

## 二、参考实现（EapLab.Gem/Spool/）

### SpoolRecord.cs
```csharp
using EapLab.Secs2;

namespace EapLab.Gem.Spool;

public enum SpoolMessageType { EventReport, Alarm }

/// <summary>Spool 缓存记录。</summary>
public sealed class SpoolRecord
{
    public ulong SequenceNumber { get; }   // 唯一序列号（用于去重）
    public SpoolMessageType MessageType { get; }
    public byte Stream { get; }             // 消息 Stream（6=事件，5=报警）
    public byte Function { get; }           // 消息 Function（11=事件报告，1=报警）
    public SecsItem Body { get; }           // 完整消息 body
    public DateTime Timestamp { get; }      // 事件/报警发生时间

    public SpoolRecord(ulong seq, SpoolMessageType type, byte stream, byte function, SecsItem body)
    {
        SequenceNumber = seq;
        MessageType = type;
        Stream = stream;
        Function = function;
        Body = body;
        Timestamp = DateTime.Now;
    }
}
```

### SpoolStore.cs
```csharp
using System.Collections.Concurrent;
using EapLab.Transport.Logging;

namespace EapLab.Gem.Spool;

/// <summary>Spool 缓存存储：队列 + 容量管理。</summary>
public sealed class SpoolStore
{
    private readonly ConcurrentQueue<SpoolRecord> _queue = new();
    private readonly ILogSink _log;
    private readonly int _maxRecords; // 最大缓存记录数（设备定义，如 10000）
    private ulong _nextSeq = 1;

    public int Count => _queue.Count;
    public bool IsEmpty => _queue.IsEmpty;
    public int MaxRecords => _maxRecords;

    public SpoolStore(ILogSink log, int maxRecords = 10000)
    {
        _log = log;
        _maxRecords = maxRecords;
    }

    /// <summary>入队一条记录。容量满时丢弃最旧的记录（FIFO）。</summary>
    public void Enqueue(SpoolMessageType type, byte stream, byte function, SecsItem body)
    {
        // 容量满时丢弃最旧的
        while (_queue.Count >= _maxRecords)
        {
            if (_queue.TryDequeue(out var old))
                _log.Log(LogDir.WARN, $"Spool full, dropping oldest record: seq={old.SequenceNumber}");
            else break;
        }

        var record = new SpoolRecord(_nextSeq++, type, stream, function, body);
        _queue.Enqueue(record);
        _log.Log(LogDir.INFO, $"Spool enqueued: seq={record.SequenceNumber} type={type} count={_queue.Count}");
    }

    /// <summary>尝试出队一条记录（最早的）。</summary>
    public bool TryDequeue(out SpoolRecord? record) => _queue.TryDequeue(out record);

    /// <summary>查看最早的记录但不出队。</summary>
    public bool TryPeek(out SpoolRecord? record) => _queue.TryPeek(out record);

    /// <summary>清空所有记录。</summary>
    public void Clear()
    {
        while (_queue.TryDequeue(out _)) { }
        _log.Log(LogDir.INFO, "Spool cleared");
    }
}
```

### SpoolManager.cs
```csharp
using EapLab.Secs2;
using EapLab.Transport.Connection;
using EapLab.Transport.Logging;

namespace EapLab.Gem.Spool;

public enum SpoolMode { Normal, Spooling, Resending }

/// <summary>Spool 管理器：监听通信状态，控制 Spool 模式切换，重发缓存记录。</summary>
public sealed class SpoolManager
{
    private readonly SpoolStore _store;
    private readonly HsmsConnection _conn;
    private readonly ILogSink _log;
    private readonly object _sendLock = new();
    private bool _commOnline = false;

    public SpoolMode Mode { get; private set; } = SpoolMode.Normal;
    public int SpoolCount => _store.Count;

    public SpoolManager(SpoolStore store, HsmsConnection conn, ILogSink log)
    {
        _store = store;
        _conn = conn;
        _log = log;
    }

    /// <summary>通信状态变化通知（由 GemStateMachine 调用）。</summary>
    public void OnCommStateChanged(bool online)
    {
        _commOnline = online;
        if (!online)
        {
            // 通信中断 → 切换到 Spool 模式
            if (Mode == SpoolMode.Normal)
            {
                Mode = SpoolMode.Spooling;
                _log.Log(LogDir.WARN, "Comm offline, switched to Spooling mode");
            }
        }
        else
        {
            // 通信恢复 → 开始重发
            if (Mode == SpoolMode.Spooling || Mode == SpoolMode.Resending)
            {
                _log.Log(LogDir.INFO, "Comm online, starting Spool resend");
                _ = Task.Run(ResendAllAsync);
            }
        }
    }

    /// <summary>发送事件/报警（正常模式直接发，Spool 模式入队）。</summary>
    public void SendOrSpool(byte stream, byte function, SecsItem body)
    {
        var type = stream == 6 ? SpoolMessageType.EventReport : SpoolMessageType.Alarm;

        if (_commOnline && Mode == SpoolMode.Normal)
        {
            // 正常模式：直接发送
            _conn.SendPrimaryAsync(stream, function, body);
        }
        else
        {
            // Spool 模式：入队缓存
            _store.Enqueue(type, stream, function, body);
        }
    }

    /// <summary>重发所有缓存记录。</summary>
    private async Task ResendAllAsync()
    {
        lock (_sendLock)
        {
            if (Mode == SpoolMode.Resending) return; // 已经在重发
            Mode = SpoolMode.Resending;
        }

        try
        {
            int sentCount = 0;
            while (!_store.IsEmpty && _commOnline)
            {
                if (_store.TryPeek(out var record) && record != null)
                {
                    // 重发（带原始 body）
                    _conn.SendPrimaryAsync(record.Stream, record.Function, record.Body);
                    // 简化：发送后即出队（实际应等 Host 确认后再出队，W8 Day03 完善）
                    _store.TryDequeue(out _);
                    sentCount++;
                    await Task.Delay(100); // 控制重发速率，避免 Host 过载
                }
            }

            _log.Log(LogDir.INFO, $"Spool resend complete: {sentCount} records resent");
        }
        finally
        {
            lock (_sendLock)
            {
                if (_store.IsEmpty)
                {
                    Mode = SpoolMode.Normal;
                    _log.Log(LogDir.INFO, "Spool empty, switched back to Normal mode");
                }
                else
                {
                    Mode = SpoolMode.Spooling; // 还有缓存，回到 Spooling（通信可能又断了）
                }
            }
        }
    }

    /// <summary>Host 请求清空 Spool（S2F43 清空操作）。</summary>
    public void ClearSpool() => _store.Clear();

    /// <summary>Host 查询 Spool 状态（S2F43 查询操作）。</summary>
    public (int count, int max, SpoolMode mode) GetStatus()
        => (_store.Count, _store.MaxRecords, Mode);
}
```

### 单测（节选）
```csharp
public class SpoolTests
{
    [Fact]
    public void 通信中断_事件写入Spool()
    {
        var store = new SpoolStore(new ConsoleLogSink());
        var conn = new MockHsmsConnection();
        var manager = new SpoolManager(store, conn, new ConsoleLogSink());

        manager.OnCommStateChanged(false); // 通信中断
        manager.SendOrSpool(6, 11, SecsItem.L(SecsItem.U4(1), SecsItem.U2(3001)));

        Assert.Equal(SpoolMode.Spooling, manager.Mode);
        Assert.Equal(1, manager.SpoolCount);
    }

    [Fact]
    public void 通信恢复_重发Spool()
    {
        var store = new SpoolStore(new ConsoleLogSink());
        var conn = new MockHsmsConnection();
        var manager = new SpoolManager(store, conn, new ConsoleLogSink());

        manager.OnCommStateChanged(false);
        manager.SendOrSpool(6, 11, SecsItem.L(SecsItem.U4(1), SecsItem.U2(3001)));
        manager.SendOrSpool(5, 1, SecsItem.L(SecsItem.U4(1001), SecsItem.A("Temp High")));
        Assert.Equal(2, manager.SpoolCount);

        manager.OnCommStateChanged(true); // 通信恢复
        Thread.Sleep(500); // 等待重发完成

        Assert.Equal(0, manager.SpoolCount); // 全部重发
        Assert.Equal(SpoolMode.Normal, manager.Mode);
    }

    [Fact]
    public void Spool容量满_丢弃最旧()
    {
        var store = new SpoolStore(new ConsoleLogSink(), maxRecords: 3);
        for (int i = 0; i < 5; i++)
            store.Enqueue(SpoolMessageType.EventReport, 6, 11, SecsItem.U4((uint)i));

        Assert.Equal(3, store.Count); // 最多 3 条，丢弃最旧的 2 条
    }

    [Fact]
    public void 清空Spool()
    {
        var store = new SpoolStore(new ConsoleLogSink());
        store.Enqueue(SpoolMessageType.EventReport, 6, 11, SecsItem.U4(1));
        store.Enqueue(SpoolMessageType.Alarm, 5, 1, SecsItem.U4(1001));
        Assert.Equal(2, store.Count);

        store.Clear();
        Assert.Equal(0, store.Count);
    }

    [Fact]
    public void 正常模式_直接发送不缓存()
    {
        var store = new SpoolStore(new ConsoleLogSink());
        var conn = new MockHsmsConnection();
        var manager = new SpoolManager(store, conn, new ConsoleLogSink());
        // 默认 Normal 模式，通信在线

        manager.SendOrSpool(6, 11, SecsItem.U4(1));

        Assert.Equal(0, manager.SpoolCount); // 不缓存
        Assert.Single(conn.SentMessages);    // 直接发送
    }
}
```

## 四、今日易错点
1. 以为 Spool 会暂停设备内部运行（Spool 只缓存通信，设备内部命令执行和工艺控制不受影响）。
2. 以为 Spool 重发的消息格式和实时上报不同（格式完全一样，Spool 是透明的）。
3. 通信恢复后不重发 Spool 直接切回正常模式（应该先重发所有缓存，再切回正常）。
4. Spool 容量满时不处理（应该有策略：丢弃最旧/拒绝新记录/覆盖，不能无限增长）。
5. 重发时不控制速率（瞬间大量消息可能导致 Host 过载或网络拥塞，应限速）。
6. Host 不做去重（确认丢失可能导致设备重发同一条消息，Host 应根据序列号去重）。
7. 以为所有设备都支持 Spool（Spool 是可选能力，建链后应查询设备能力确认）。
8. 重发时不等 Host 确认就出队（应该等 S6F12/S5F2 确认后再从缓存删除，否则确认丢失会导致数据丢失，今天简化版直接出队，Day03 完善）。
