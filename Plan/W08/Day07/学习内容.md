## 四、W9 预热：E39 OSS 对象模型（30 分钟）

### 1. E39 是什么
- E39 = Object Services Specification（对象服务规范），SEMI 标准 E39。
- OSS 是 GEM300 的基础——从"消息级通信"升级到"对象级通信"。
- GEM（E30）是"消息级"：Host 发 S2F41 远程命令，设备回 S2F42，Host 不知道设备内部有什么对象。
- OSS（E39）是"对象级"：设备把内部实体（Job、ProcessJob、ControlJob、Carrier、Wafer 等）建模为"对象"，Host 可以通过 S14/S15/S16 消息族查询、创建、修改、删除这些对象。
- 简单说：GEM 是"遥控器"（发命令，设备执行），OSS 是"对象浏览器"（看到设备内部的对象，直接操作对象）。

### 2. OSS 的核心概念
- **Object（对象）**：设备内部的实体，如 ControlJob、ProcessJob、Carrier、Wafer、Recipe、Alarm 等。每个对象有唯一的 Object ID（OBJSPEC）。
- **Attribute（属性）**：对象的状态变量，如 ControlJob 的状态、ProcessJob 的配方、Carrier 的槽位映射。属性有 ATTRID（属性 ID）。
- **Method（方法）**：对象可以执行的操作，如 ControlJob 的 Start、Abort、Pause。方法有 METHODID。
- **Event（事件）**：对象状态变化时触发的通知，如 ControlJob 的 Started、Completed。事件有 CEID。
- **Type（类型）**：对象的类型定义，如 "ProcessJob"、"ControlJob"、"Carrier"。类型定义了该类型对象有哪些属性、方法、事件。
- **OBJSPEC（对象说明符）**：对象的唯一标识，格式为 "Type:ID"，如 "ProcessJob:PJ001"、"ControlJob:CJ001"。

### 3. OSS 的消息族（S14/S15/S16）
- **S14（对象类型查询）**：Host 查询设备支持哪些对象类型、每种类型有哪些属性/方法/事件。
  - S14F1/F2：查询对象类型列表
  - S14F3/F4：查询对象类型的属性列表
  - S14F5/F6：查询对象类型的方法列表
  - S14F7/F8：查询对象类型的事件列表
- **S15（对象实例操作）**：Host 对具体对象实例进行操作。
  - S15F1/F2：创建对象
  - S15F3/F4：删除对象
  - S15F5/F6：查询对象属性值
  - S15F7/F8：设置对象属性值
  - S15F9/F10：调用对象方法
  - S15F11/F12：查询对象存在性
- **S16（对象事件通知）**：设备向 Host 通知对象状态变化事件。
  - S16F1/F2：对象事件上报（类似 S6F11，但针对对象）
  - S16F3/F4：事件确认

### 4. OSS 与 GEM 的关系
- OSS 不是替代 GEM，而是**扩展** GEM。
- GEM 提供基础通信（连接/建链/状态/数据采集/报警/远程命令/配方）。
- OSS 在 GEM 之上提供对象级抽象（对象/属性/方法/事件）。
- GEM300 标准（E40/E87/E90/E94 等）都基于 OSS——它们定义了特定的对象类型（如 ProcessJob、Carrier、Substrate）和这些对象的属性/方法/事件。
- 学习路径：先掌握 GEM（W2-W8）→ 再掌握 OSS（W9-W10）→ 然后学习基于 OSS 的 GEM300 标准（E40/E87/E90/E94，W11-W23）。
