# W08 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为什么重发后不能立即删除 / 可靠重发怎么做**：重发后立即删除缓存有数据丢失风险——如果重发的消息在网络中丢失、或 Host 没收到、或 Host 收到了但确认消息丢失，缓存已经删了，这条事件/报警就永久丢失了，Host 永远收不到。可靠重发机制应该是：**重发后不删除，等 Host 回确认（S6F12/S5F2）后才从缓存删除**。实现：①重发时把记录从"待发送队列"移到"待确认队列"（或标记为"已发送待确认"）；②启动 T3 定时器（~45s）；③收到 Host 确认后，从"待确认队列"删除该记录，取消定时器；④T3 超时未收到确认，重发该记录（最多重发 N 次，如 3 次）；⑤超过最大重发次数，记录日志，保留或丢弃（取决于设备策略）。这和 TCP 的可靠传输原理一样——确认后才释放。
2. **SpoolManager 需要集成到哪几个地方 / 每个的作用**：需要集成到 3 个地方：①**事件/报警上报**（EventReportEngine.TriggerEvent 和 S5F1Sender）——发送 S6F11/S5F1 时调用 SpoolManager.SendOrSpool，正常模式直接发，Spool 模式入队缓存；②**通信状态变化**（GemStateMachine）——通信状态变化时调用 SpoolManager.OnCommStateChanged，OFF-LINE 触发 Spool 模式（开始缓存），ON-LINE 触发重发（把缓存的消息重发给 Host）；③**Host 确认处理**（HsmsConnection 收到 S6F12/S5F2 时）——调用 SpoolManager.OnAckReceived，从"待确认队列"删除对应记录（确认收到，缓存可以释放）。这 3 个集成点构成完整的 Spool 闭环：触发→缓存→重发→确认→释放。
3. **Host 回确认后 SpoolManager 应该做什么**：Host 回 S6F12（事件报告确认）或 S5F2（报警确认）后，SpoolManager 应该：①根据确认消息中的标识（DATAID 或 ALID，或消息序列号）找到"待确认队列"中对应的记录；②从"待确认队列"删除该记录（确认收到，缓存释放）；③取消该记录的 T3 重发定时器；④如果"待确认队列"和"待发送队列"都空了，且通信在线，切换回 Normal 模式（正常上报）。注意：确认消息可能带 DATAID（S6F12）或 ALID（S5F2），SpoolManager 需要根据这些标识匹配待确认记录；如果有多条相同标识的记录（如多个报警都是同一个 ALID），需要用序列号或时间戳精确匹配。
4. **S2F43/S2F44 作用 / Host 可以做哪些操作**：S2F43/S2F44 是 Host 控制 Spool 的接口。Host 可以做的操作（具体操作码以 E30 标准和设备实现为准）：①**查询 Spool 状态**——查询当前缓存记录数、已用容量、剩余容量、Spool 模式（Normal/Spooling/Resending）、是否启用；②**清空 Spool**——删除所有缓存记录（慎用，会丢失未发送的事件/报警）；③**启用 Spool**——开启 Spool 功能（通信中断时开始缓存）；④**禁用 Spool**——关闭 Spool 功能（通信中断时事件/报警直接丢弃，不缓存）；⑤**请求重发**——主动请求设备重发 Spool 中的记录（部分设备支持）。S2F44 是设备的确认，返回操作结果（ACKC=0 成功，非0失败）和查询操作时的 Spool 状态。
5. **Host 一直不回确认设备怎么做**：如果 Host 一直不回确认（S6F12/S5F2），设备应该：①T3 超时（默认 ~45s）后重发该记录；②每次重发都重新启动 T3 定时器；③最多重发 N 次（如 3 次，具体以设备实现为准）；④超过最大重发次数后，记录错误日志（"Spool 重发超时，Host 无响应"），然后根据设备策略处理——保留记录（等通信恢复后再试）或丢弃记录（释放空间）。同时，设备可能认为通信异常，触发 Spool 模式（把后续的事件/报警也入队缓存），并尝试重新建立通信（HSMS 重连）。这是可靠性设计——不能因为 Host 不响应就无限重发，也不能轻易丢弃数据。
6. **通信中断时设备正在执行的命令会受影响吗 / Spool 影响命令执行吗**：**不会受影响**。通信中断只影响"设备和 Host 之间的通信"，不影响设备内部的命令执行、工艺控制、报警检测、事件触发。设备在通信中断时仍然正常运行：命令队列中的命令继续执行、工艺继续加工、报警继续检测和设置、事件继续触发——只是这些事件和报警不发给 Host，而是写入 Spool 缓存。Spool 是"通信层的缓存机制"，不是"设备运行的暂停机制"。等通信恢复后，Host 通过 Spool 重发补收中断期间的所有事件和报警（包括命令开始/完成/失败事件），恢复对设备状态的认知。这是关键设计——设备的运行不依赖 Host 的连接，Host 只是监控和管理方，设备可以独立运行。

## 二、参考实现（EapLab.Gem/Spool/SpoolManager 完善版）

```csharp
using System.Collections.Concurrent;
using EapLab.Secs2;
using EapLab.Transport.Connection;
using EapLab.Transport.Logging;

namespace EapLab.Gem.Spool;

public enum SpoolMode { Normal, Spooling, Resending }

/// <summary>待确认记录：已发送，等待 Host 确认。</summary>
internal sealed class PendingAckRecord
{
    public SpoolRecord Record { get; }
    public int RetryCount { get; set; } = 0;
    public DateTime LastSentAt { get; set; }
    public CancellationTokenSource? TimerCts { get; set; }

    public PendingAckRecord(SpoolRecord record)
    {
        Record = record;
        LastSentAt = DateTime.Now;
    }
}

/// <summary>Spool 管理器（完善版）：可靠重发 + 确认后删除 + 超时重发。</summary>
public sealed class SpoolManager
{
    private readonly SpoolStore _store;
    private readonly HsmsConnection _conn;
    private readonly ILogSink _log;
    private readonly ConcurrentDictionary<ulong, PendingAckRecord> _pendingAck = new();
    private readonly object _sendLock = new();
    private bool _commOnline = false;
    private bool _enabled = true;
    private const int MaxRetry = 3;
    private const int AckTimeoutMs = 45000; // T3 ~45s

    public SpoolMode Mode { get; private set; } = SpoolMode.Normal;
    public int SpoolCount => _store.Count;
    public int PendingAckCount => _pendingAck.Count;
    public bool Enabled => _enabled;

    public SpoolManager(SpoolStore store, HsmsConnection conn, ILogSink log)
    {
        _store = store;
        _conn = conn;
        _log = log;
    }

    /// <summary>通信状态变化通知。</summary>
    public void OnCommStateChanged(bool online)
    {
        _commOnline = online;
        if (!online && _enabled)
        {
            if (Mode == SpoolMode.Normal)
            {
                Mode = SpoolMode.Spooling;
                _log.Log(LogDir.WARN, "Comm offline, switched to Spooling mode");
            }
        }
        else if (online)
        {
            if (Mode == SpoolMode.Spooling || !_store.IsEmpty)
            {
                _log.Log(LogDir.INFO, "Comm online, starting Spool resend");
                _ = Task.Run(ResendAllAsync);
            }
        }
    }

    /// <summary>发送事件/报警（正常模式直接发，Spool 模式入队）。</summary>
    public void SendOrSpool(byte stream, byte function, SecsItem body)
    {
        if (!_enabled) return; // Spool 禁用时，事件/报警直接丢弃（不缓存也不发送）

        var type = stream == 6 ? SpoolMessageType.EventReport : SpoolMessageType.Alarm;

        if (_commOnline && Mode == SpoolMode.Normal && _pendingAck.IsEmpty)
        {
            // 正常模式：直接发送，并加入待确认队列
            SendAndTrack(type, stream, function, body);
        }
        else
        {
            // Spool 模式：入队缓存
            _store.Enqueue(type, stream, function, body);
        }
    }

    /// <summary>发送并加入待确认队列。</summary>
    private void SendAndTrack(SpoolMessageType type, byte stream, byte function, SecsItem body)
    {
        var record = new SpoolRecord(0, type, stream, function, body); // 正常模式序列号不重要
        var pending = new PendingAckRecord(record);
        _pendingAck[record.SequenceNumber] = pending;

        _conn.SendPrimaryAsync(stream, function, body);

        // 启动超时定时器
        pending.TimerCts = new CancellationTokenSource();
        _ = Task.Delay(AckTimeoutMs, pending.TimerCts.Token).ContinueWith(t =>
        {
            if (!t.IsCanceled) OnAckTimeout(record.SequenceNumber);
        });
    }

    /// <summary>Host 确认收到（S6F12/S5F2）。</summary>
    public void OnAckReceived(byte stream, byte function, SecsItem body)
    {
        // 简化：根据 stream/function 匹配最早的待确认记录
        // 实际应根据 DATAID(S6F12) 或 ALID(S5F2) 精确匹配
        var key = _pendingAck.Keys.FirstOrDefault();
        if (key != 0 && _pendingAck.TryRemove(key, out var pending))
        {
            pending.TimerCts?.Cancel();
            _log.Log(LogDir.INFO, $"Ack received for seq={key}, removed from pending");
        }

        // 如果待确认队列和待发送队列都空了，切回 Normal
        if (_pendingAck.IsEmpty && _store.IsEmpty && _commOnline)
        {
            Mode = SpoolMode.Normal;
            _log.Log(LogDir.INFO, "All spool records acknowledged, switched to Normal mode");
        }
    }

    /// <summary>确认超时：重发或放弃。</summary>
    private void OnAckTimeout(ulong seq)
    {
        if (!_pendingAck.TryGetValue(seq, out var pending)) return;

        if (pending.RetryCount < MaxRetry)
        {
            pending.RetryCount++;
            pending.LastSentAt = DateTime.Now;
            _log.Log(LogDir.WARN, $"Ack timeout for seq={seq}, retry {pending.RetryCount}/{MaxRetry}");

            // 重发
            _conn.SendPrimaryAsync(pending.Record.Stream, pending.Record.Function, pending.Record.Body);

            // 重启定时器
            pending.TimerCts = new CancellationTokenSource();
            _ = Task.Delay(AckTimeoutMs, pending.TimerCts.Token).ContinueWith(t =>
            {
                if (!t.IsCanceled) OnAckTimeout(seq);
            });
        }
        else
        {
            // 超过最大重发次数，放弃
            _pendingAck.TryRemove(seq, out _);
            _log.Log(LogDir.ERR, $"Ack timeout for seq={seq}, max retry {MaxRetry} exceeded, giving up");
        }
    }

    /// <summary>重发所有缓存记录。</summary>
    private async Task ResendAllAsync()
    {
        lock (_sendLock)
        {
            if (Mode == SpoolMode.Resending) return;
            Mode = SpoolMode.Resending;
        }

        try
        {
            int sentCount = 0;
            while (!_store.IsEmpty && _commOnline)
            {
                if (_store.TryDequeue(out var record) && record != null)
                {
                    // 重发并加入待确认队列
                    var pending = new PendingAckRecord(record);
                    _pendingAck[record.SequenceNumber] = pending;
                    _conn.SendPrimaryAsync(record.Stream, record.Function, record.Body);
                    sentCount++;

                    // 启动超时定时器
                    pending.TimerCts = new CancellationTokenSource();
                    var seq = record.SequenceNumber;
                    _ = Task.Delay(AckTimeoutMs, pending.TimerCts.Token).ContinueWith(t =>
                    {
                        if (!t.IsCanceled) OnAckTimeout(seq);
                    });

                    await Task.Delay(100); // 限速
                }
            }

            _log.Log(LogDir.INFO, $"Spool resend complete: {sentCount} records resent");
        }
        finally
        {
            lock (_sendLock)
            {
                if (_store.IsEmpty && _pendingAck.IsEmpty)
                {
                    Mode = SpoolMode.Normal;
                    _log.Log(LogDir.INFO, "Spool empty, switched to Normal mode");
                }
                else
                {
                    Mode = SpoolMode.Spooling;
                }
            }
        }
    }

    // S2F43 控制操作
    public (int count, int max, SpoolMode mode, bool enabled) GetStatus()
        => (_store.Count, _store.MaxRecords, Mode, _enabled);

    public void ClearSpool()
    {
        _store.Clear();
        foreach (var key in _pendingAck.Keys)
        {
            if (_pendingAck.TryRemove(key, out var p)) p.TimerCts?.Cancel();
        }
        _log.Log(LogDir.INFO, "Spool cleared by host request");
    }

    public void SetEnabled(bool enabled)
    {
        _enabled = enabled;
        _log.Log(LogDir.INFO, $"Spool {(enabled ? "enabled" : "disabled")} by host request");
    }
}
```

### S2F43Handler.cs
```csharp
using EapLab.Secs2;
using EapLab.Transport.Logging;

namespace EapLab.Gem.Spool;

/// <summary>S2F43 Spool 控制处理器。</summary>
public sealed class S2F43Handler
{
    private readonly SpoolManager _spool;
    private readonly ILogSink _log;

    public S2F43Handler(SpoolManager spool, ILogSink log)
    {
        _spool = spool;
        _log = log;
    }

    /// <summary>处理 S2F43，返回 S2F44 body。</summary>
    public SecsItem Handle(SecsItem? body)
    {
        if (body is not SecsList root || root.Items.Count < 1)
            return Reply(1, null);

        if (root.Items[0] is not SecsU1 spctlItem || spctlItem.Values.Length != 1)
            return Reply(1, null);

        byte spctl = spctlItem.Values[0];
        _log.Log(LogDir.INFO, $"S2F43 Spool control: SPCTL={spctl}");

        SecsItem? statusData = null;
        byte ackc = 0;

        switch (spctl)
        {
            case 1: // 查询状态
                var (count, max, mode, enabled) = _spool.GetStatus();
                statusData = SecsItem.L(
                    SecsItem.U4((uint)count),   // 记录数
                    SecsItem.U4((uint)max),     // 最大容量
                    SecsItem.U1((byte)mode),    // 模式
                    SecsItem.U1(enabled ? (byte)1 : (byte)0) // 是否启用
                );
                break;
            case 2: // 清空
                _spool.ClearSpool();
                break;
            case 3: // 启用
                _spool.SetEnabled(true);
                break;
            case 4: // 禁用
                _spool.SetEnabled(false);
                break;
            default:
                ackc = 1; // 未知操作码
                break;
        }

        return Reply(ackc, statusData);
    }

    private static SecsItem Reply(byte ackc, SecsItem? statusData)
    {
        var items = new List<SecsItem> { SecsItem.U1(ackc) };
        if (statusData != null) items.Add(statusData);
        return SecsItem.L(items.ToArray());
    }
}
```

## 三、今日易错点
1. 重发后立即删除缓存（应等 Host 确认后再删除，否则数据丢失）。
2. Spool 不集成到通信状态变化（通信中断时不知道开始缓存，恢复时不知道重发）。
3. Spool 不集成到 Host 确认处理（确认后不知道删除待确认记录，导致超时重发）。
4. 重发时不限速（瞬间大量消息可能导致 Host 过载或网络拥塞）。
5. 超时重发没有最大次数限制（无限重发会导致资源泄漏）。
6. S2F43 操作码记错（1=查询、2=清空、3=启用、4=禁用，具体以标准和设备实现为准）。
7. 以为 Spool 禁用时事件还会缓存（禁用时事件直接丢弃，不缓存也不发送）。
8. 待确认队列匹配不精确（应根据 DATAID/ALID/序列号精确匹配，不能只按 stream/function 匹配）。
9. 通信恢复后不检查待确认队列就切回 Normal（应该等所有待确认记录都确认后再切回 Normal）。
