## 二、背景知识（先读，15 分钟）

### 1. 可靠重发机制（确认后删除）
- Day02 的简化版是"重发后即出队"，这有数据丢失风险——如果重发的消息丢了或 Host 没收到，缓存已经删了，数据就丢了。
- 可靠机制应该是：**重发后不删除，等 Host 回确认（S6F12/S5F2）后才从缓存删除**。
- 实现方式：
  1. 重发时，把记录从"待发送队列"移到"待确认队列"（或标记为"已发送待确认"）。
  2. 启动 T3 定时器（默认 ~45s）。
  3. 收到 Host 确认（S6F12/S5F2）后，从"待确认队列"删除该记录，取消定时器。
  4. T3 超时未收到确认，重发该记录（最多重发 N 次，如 3 次）。
  5. 超过最大重发次数，记录日志，保留或丢弃（取决于设备策略）。
- 今天实现简化版：重发后标记为"待确认"，收到确认后删除，超时重发（最多 3 次）。

### 2. Spool 集成点
SpoolManager 需要集成到 3 个地方：
1. **事件/报警上报**：EventReportEngine.TriggerEvent 和 S5F1Sender 发送 S6F11/S5F1 时，调用 SpoolManager.SendOrSpool——正常模式直接发，Spool 模式入队。
2. **通信状态变化**：GemStateMachine 通信状态变化时，调用 SpoolManager.OnCommStateChanged——OFF-LINE 触发 Spool，ON-LINE 触发重发。
3. **Host 确认处理**：HsmsConnection 收到 Host 回的 S6F12/S5F2 时，调用 SpoolManager.OnAckReceived——从"待确认队列"删除对应记录。

### 3. S2F43/S2F44 Spool 控制处理器
- S2F43 是 Host 发的 Spool 控制请求（W=1），S2F44 是设备回的确认（W=0）。
- 操作码（SPCTL，具体以 E30 标准和设备实现为准）：
  - 1 = 查询 Spool 状态（返回记录数、容量、模式）
  - 2 = 清空 Spool（删除所有缓存记录）
  - 3 = 启用 Spool
  - 4 = 禁用 Spool
- S2F44 body = L,2[U1 ACKC, <Spool 状态>]，查询操作时返回 Spool 状态。
- 今天实现简化版：支持查询（返回记录数和容量）、清空（删除所有记录），启用/禁用（开关 Spool 功能）。
