# W16 · Day05（周五）PJ 执行器：对接 E90 位置层与模块加工

> 建议时长：100 分钟。今天把 PJ 对象真正"跑起来"：写 `ProcessJobExecutor`，按 WaferOrder 对每片执行"E90 取片→沿 Route 逐模块加工（位置不变、状态推进）→E90 放目标槽"，同步推进 WaferProcess、驱动 Job 状态机、发 S16 事件。这是 E40 与 E90 的关键缝合层。

## 一、今日目标
1. 实现 `ProcessJobExecutor`：驱动一个 PJ 从 Start 到逐片执行到 Completed。
2. 每片执行：E90 Pick（源）→逐 Step 迁移到模块、Process、迁移下一步→E90 Place（目标）。
3. 执行中同步更新 WaferProcess（当前 Step/状态/位置）与 Job 聚合，发 5101/5102/5103/5104 事件。
4. 集成模块选择（同型多腔选可用）、配方进腔前二次校验、每步后不变式断言。
5. xUnit 覆盖单片/多片执行、步骤推进、异常中止、全片完成才 Job Completed。

## 二、执行器设计（先读，30 分钟）

### 1. 分层与依赖
```
ProcessJobExecutor
 ├ ProcessJobController/ProcessJob (Day04 对象与状态机)
 ├ SubstrateTracker (W14/W15: Pick/Transfer/Place/Process, 唯一改位置)
 ├ RouteValidator/ModuleRegistry (Day03: 选腔、配方版本)
 ├ PjMapValidator (Day02: 开工前源目/绑定校验)
 └ S16 事件发布 (Day04: 5101..5106)
原则: 执行器只做"编排与进度", 位置变更全部经 SubstrateTracker(E90), 加工在模块内状态推进
```

### 2. 主执行循环（按 WaferOrder）
```
Start PJ (状态机 Queued→Executing, 发5101)
开工前: PjMapValidator + RouteValidator 全绿, 否则拒绝Start(IllegalState/参数)
for waferId in WaferOrder:
   wp = 该片进度; wp.State=InProcess
   E90 Pick: 源(载具,槽) → Robot (AtPick读码核对)
   for step in Route.Topological:
       select module: 同型可用腔(未故障/空闲/能力支持), 发5102 StepEnter
       进腔前二次校验配方版本/偏移授权
       E90 Transfer 到 module; module.Process(recipe) [位置不变, wp.CurStepNo推进]
       发5102 StepDone; 离开该模块
   E90 Place: Robot → 目标(载具,槽) (AtPlace当下复核+读回)
   wp.State=Completed; 发5103; 每片后 E90 守恒断言
全部片Completed → Job Completed(状态机守卫), 发5104
```

### 3. 模块选择策略
- 同型多腔：在满足 ModuleType、能力、Available 的腔体中选当前空闲者；都忙则等待（逻辑时钟队列），故障腔跳过。
- 记录每步实际选中的腔体到 WaferProcess.StepTrace（良率追溯需要"哪片进过哪个腔"）。

### 4. 异常与中止
- 任一步校验失败/位置异常：立即把该 wp 置 Failed、Job 走 Abort（状态机）、发 5106、保留每片实际位置（Partial，W15），不继续后续片。
- Pause：在片与片之间或步骤安全点挂起（不在物理动作中途），Resume 从当前片当前步继续。
- 中止后按 W15 恢复策略（Resume/Rollback/人工），执行器提供当前现场快照。

### 5. 事件与位置一致性
- 每次 wp 推进与 E90 迁移后，断言 wp.Location == tracker.LocationOf(wafer)，进度与物理位置一致。
- S16 事件快照带 JobId/片/Step/模块/配方/状态，订阅过滤复用 W10。

### 6. 与 GEM/采集联动（印象）
- 加工过程的工艺参数采集走 E30 数据采集（VID/CEID，W06），FDC 订阅高频数据；PJ 事件是任务级，采集事件是参数级，二者时间戳关联。
