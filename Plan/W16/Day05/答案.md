# W16 · Day05 答案与参考实现

## 一、自测题标准答案
1. **职责边界 / 执行器为何不直接改位置**：ProcessJobExecutor 负责**编排与进度**——按 WaferOrder 决定做哪片、按 Route 决定先后步骤、选腔体、驱动 Job/片状态机、发 S16 任务事件，但它不直接修改片位置；SubstrateTracker（E90）是**唯一改变片位置**的层，Pick/Transfer/Place 都经它做 expectedFrom、容量、守恒、双向映射校验；模块（ProcessModule）负责**在片已到位后执行工艺加工**（位置不变、推进工艺状态、配方执行）。执行器不直接改位置，是因为位置安全（唯一/容量/守恒/交叉校验）全部内聚在 E90 位置层，若执行器绕过它直接改 SlotMap/位置，就绕开了所有防丢片/叠片/混片保证；分层后执行器专注任务流、位置层专注位置正确、模块专注工艺，单一职责、纵深防御。
2. **单片完整步骤序列**：①执行器取该片 WaferProcess，置 InProcess；②E90 Pick 从源(载具,槽)取到机械臂（AtPick 读码核对片 ID）；③按 Route 拓扑顺序取第一个 Step，选定可用同型腔体；④进腔前二次校验该 Step 配方存在/版本/偏移授权；⑤E90 Transfer 把片从臂迁到选定模块（位置=该腔）；⑥模块 Process（位置不变，wp.CurStepNo 推进、片状态 InProcess，发 5102 StepEnter/Done）；⑦E90 Transfer 离开该模块、迁到下一 Step 模块，重复③-⑥直到最后一步；⑧E90 Place 从臂放到目标(载具,槽)（AtPlace 当下复核目标空/未 Hold、放后读回 ID）；⑨wp 置 Completed、发 5103，E90 守恒断言；全部片走完后 Job 状态机在"全片完成"守卫下迁 Completed、发 5104。
3. **同型多腔选腔 / 为何记实际腔体**：一个逻辑 Step 绑定模块类型，对应多个同型腔体（如 ETCH 型有 C1/C2）。选腔策略：在类型匹配、能力支持该配方类、状态 Available、当前未被占用的腔体中选一个（可按空闲/负载均衡/腔体健康策略），都忙则在逻辑时钟队列等待、故障腔排除。必须记录每步**实际选中的腔体**到 WaferProcess.StepTrace，因为良率/工艺追溯要求精确知道"这片到底进的是 C1 还是 C2、何时、用什么配方"——同型腔也存在个体差异（腔体匹配、老化、污染），FDC/YMS/R2R 分析、问题腔隔离都依赖实际腔体记录，只记逻辑步骤不记物理腔无法定位腔体级问题。
4. **进腔前为何二次校验配方**：开工前校验发生在 PJ Start 前，到该片真正进某腔加工有时间窗，期间配方可能被 RMS 更新/换版、被人工改动、R2R 偏移授权变化或该腔实际下载版本与预期不符。进腔前（真正"改变晶圆"的最后一道关）基于当下状态再核一次 PPID 存在、版本与 Step 声明一致、偏移对当前 Lot 授权、该腔支持该配方，是 compare-and-set 式复核（同 W15 AtPlace 二次确认思想），防止用"开工时正确、加工时已变"的过期配方信息造成批量工艺错误，错配方事故代价极大，必须在加工瞬间前再确认。
5. **Pause 为何在安全点**：物理取放/加工是不可瞬间冻结的连续动作——机械臂运动中途、腔体工艺进行中直接暂停会留下不安全或不确定状态（片在半程、工艺中断在非安全节点、真空/温度过程被破坏），恢复时无法确定片的确切状态。安全点指片处于稳定可续的位置：两片之间（片在槽中）、或一个 Step 完整结束（片已离开腔体到稳定位、该步工艺已完成到可续边界）。在安全点挂起，片有确定位置、步骤边界清晰，Resume 才能从"当前片当前步"确定性续跑且不损坏工艺；这与 W11/W13"归属确定才可自动续、不确定则安全保持人工"一致。
6. **一片失败 Job 与其余片 / 保留现场**：失败片置 Failed，Job 经状态机迁 Aborted/Failed、发 5106，**立即停止调度后续片**（不继续，避免基于错误前提扩大影响，也防止设备在异常状态下连带出更多问题）；已经完成的片保持其已到位状态、正在加工的片停在安全点、未开始的片保持 Waiting。保留现场：每片当前实际位置（与 E90 对齐）、各自 Step/状态、失败片的期望 vs 实际与错误码、已发事件与轨迹、源/目标 SlotMap 快照、守恒快照，形成 Partial 现场（W15），供 Resume（排除故障后从失败片当前步续跑）、Rollback（已加工片安全退回）或人工处置，绝不在信息不全时重置或继续。
7. **进度与位置一致如何保证**：单一事实源 + 同步更新 + 断言。片位置以 E90 LocationSpace 为权威，执行器每次经 SubstrateTracker 做迁移后，立即把 WaferProcess.Location 同步为 tracker.LocationOf(wafer)（不自己另算位置），并断言二者一致、片状态与所处阶段匹配（如 InProcess 时位置应在某模块）；每个 Step、每片后做守恒/不变式断言。这样进度（工艺维度）与位置（物理维度）由执行器在同一驱动流程内同步推进、交叉印证，一旦出现不一致立即判异常，避免"进度说在 C2、位置却在臂上"的脱节。

## 二、参考实现（net8.0）

### 模块注册表与选腔
```csharp
namespace EapLab.E40;
public sealed class ModuleRegistry
{
    private readonly List<ProcessModule> _modules;
    public ModuleRegistry(IEnumerable<ProcessModule> m){_modules=m.ToList();}
    public ProcessModule? PickAvailable(string moduleType,string recipeKind)
        => _modules.Where(m=>m.ModuleType==moduleType && m.CanRun(recipeKind))
                   .OrderBy(m=>m.Name).FirstOrDefault();   // 确定性选择; 全忙/故障返回null
}
```

### PJ 执行器
```csharp
public sealed class ProcessJobExecutor
{
    private readonly SubstrateTracker _tracker; private readonly ModuleRegistry _modules;
    private readonly IReadOnlyDictionary<string,RecipeInfo> _recipes;
    public List<PjEvent> Events { get; }=new();
    public ProcessJobExecutor(SubstrateTracker t,ModuleRegistry m,IReadOnlyDictionary<string,RecipeInfo> r)
    {_tracker=t;_modules=m;_recipes=r;}
    private void Emit(string spec,int ceid,object snap)=>Events.Add(new PjEvent(spec,ceid,new Dictionary<string,object>{{"d",snap!}}));

    public void Run(ProcessJob job)
    {
        // Start
        if(!job.TryMethod(JobMethod.Start,out var e)) throw new InvalidOperationException($"Start被拒:{e}");
        Emit(job.Def.JobId,S16.PjCeid.Started,job.State);
        var order = job.Def.WaferOrder.Count>0 ? job.Def.WaferOrder : job.Wafers.Keys.ToList();

        foreach(var id in order)
        {
            var wp=job.Wafers[id]; wp.State=WaferState.InProcess;
            // Pick (经E90, 内含读码/容量/守恒)
            _tracker.Pick(id,wp.Src.Carrier,wp.Src.Slot,"Robot:R1");
            string? prevInternal=null;
            foreach(var step in job.Def.Route.Topological())
            {
                var mod=_modules.PickAvailable(step.ModuleType,step.RecipeKind)
                    ?? throw new InvalidOperationException($"Step{step.No} 无可用{step.ModuleType}腔,Job中止");
                // 进腔前二次校验配方
                if(!_recipes.TryGetValue(step.Ppid,out var ri)||!ri.Present||ri.Version!=step.Version)
                    throw new InvalidOperationException($"Step{step.No} 配方版本不符,中止");
                // 迁移到模块(首步从臂,后续从上一模块)
                var from = prevInternal ?? "Robot:R1";
                if(prevInternal is not null) _tracker.TransferInternal(id,prevInternal,mod.Name);
                else _tracker.TransferInternal(id,"Robot:R1",mod.Name);
                wp.CurStepNo=step.No; wp.Location=mod.Name; wp.StepTrace.Add($"{step.No}@{mod.Name}/{step.Ppid}");
                Emit(id,S16.PjCeid.StepEnter,$"S{step.No}@{mod.Name}");
                _tracker.Process(id,new InternalLocation(mod.Name).Key,step.Ppid,job.Def.JobId); // 位置不变,状态推进
                Emit(id,S16.PjCeid.StepEnter,$"S{step.No} done");
                wp.State=WaferState.StepDone; prevInternal=mod.Name;
                AssertProgressLocationConsistent(_tracker,wp);
            }
            // 最后模块回到臂再放目标
            if(prevInternal is not null) _tracker.TransferInternal(id,prevInternal,"Robot:R1");
            _tracker.Place(id,"Robot:R1",wp.Dst.Carrier,wp.Dst.Slot,WaferState.Completed); // AtPlace读回在E90
            wp.State=WaferState.Completed; wp.Location=new CarrierLocation(wp.Dst.Carrier,wp.Dst.Slot).Key;
            Emit(id,S16.PjCeid.WaferDone,wp.Dst);
            _tracker.Snapshot(); // 每片后守恒断言
        }
        job.CompleteIfAllDone();
        if(job.State==JobState.Completed) Emit(job.Def.JobId,S16.PjCeid.JobDone,"all");
        else throw new InvalidOperationException("片未全完成,Job不得Complete");
    }
    static void AssertProgressLocationConsistent(SubstrateTracker t,WaferProcess wp)
    { /* 断言 wp.Location == t.LocationOf(wp.WaferId).Key, 不一致即抛 */ }

    public void Abort(ProcessJob job,string reason)
    { job.TryMethod(JobMethod.Abort,out _); Emit(job.Def.JobId,S16.PjCeid.Aborted,reason); }
}
```
> 说明：`SubstrateTracker.Process/TransferInternal` 复用 W14；InternalLocation/CarrierLocation 为 W14 位置对象。模块加工用逻辑时钟，不引入真线程。

## 三、执行时序（手绘参考）
```
Host S15 Create PJ → S15 Start(F10仅受理) → 执行器:
 5101 Started
 for 片(WaferOrder):
   Pick(源→臂,E90读码) → for Step(拓扑): 选同型可用腔 → 进腔前配方复核
        Transfer(臂/上腔→本腔) → Process(位置不变/状态推进,5102) → 下一步
   Transfer回臂 → Place(臂→目标,E90读回,5103) → 守恒断言
 全片完成(守卫) → Completed(5104)
 异常: 片Failed→Job Abort(5106),停后续,留Partial现场(每片实际位置/Step/快照)
 Pause只在片间/步边界安全点; Resume从当前片当前步续
```

## 四、今日易错点
1. 执行器绕过 E90 直接改位置（唯一位置写入口必须是 SubstrateTracker）。
2. 不按 WaferOrder、跳片或重复片（按序遍历、与映射覆盖校验配合）。
3. 只记逻辑步骤不记实际腔体（无法做腔体级良率追溯/问题腔隔离）。
4. 只在开工前校验配方（进腔前必须二次复核，防中途换版）。
5. Pause 在运动/工艺中途（要在片间或步骤边界安全点，保证可续）。
6. 一片失败还继续后续片（立即停、保留 Partial 现场）。
7. 进度位置另算一份、不与 E90 对齐断言（以位置层为权威、同步+断言）。
8. 没全片完成就让 Job Completed（状态机 PermitIf 全片完成守卫）。
