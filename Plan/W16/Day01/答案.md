# W16 · Day01 答案

## 一、自测题标准答案
1. **E40 解决什么 / 为何不用一串 S2F41**：E40 定义标准化的"加工任务对象"——一次性声明加工哪些片、源/目标载具槽位、工艺步骤、配方与模块，并由设备自主调度执行、按标准对象事件回报 Job/片/步骤状态。直接用一串 S2F41 远程命令的问题：①任务无整体边界，Host 要逐步指挥取片/加工/放片，耦合设备内部动作、网络抖动即中断；②没有标准任务状态模型，进度、暂停/恢复/取消、异常处理全靠各厂自定义，跨厂商不一致；③一批片的源目映射、工艺路线、逐片状态无法作为一个对象统一跟踪和追溯；④Host 调度负担重、难以批量自动化。PJ 把"加工意图"作为整体下发，设备负责执行细节并标准回报，实现解耦、可调度、可跟踪、跨厂商一致，是先进 FAB 批处理自动化的基础。
2. **CJ/PJ 分工 / 最小调度单位**：ProcessJob（E40）是**最小可独立调度执行的加工单位**，绑定一组片和一条确定工艺路线（源目映射+有序工艺步骤+配方），描述"一个任务怎么加工这批片"；ControlJob（E94）是编排单位，包含/调度一个或多个 PJ，负责多个 PJ 的先后顺序、并行、跨载具协同与整体生命周期，描述"做哪几个任务、什么次序"。边界：PJ 内部不再嵌套别的 Job，只含片与工艺步骤；跨 PJ 的顺序、一批片先后经过不同工艺任务、多载具协同属于 CJ。记忆：CJ 编排任务，PJ 执行单任务。
3. **PJ 核心要素 / 与 CrossMap 关系**：PJ 含 ProcessJobId、Source/Destination 源目标槽位映射、有序 Process Step（每步模块/腔体+Recipe）、关联 Lot/优先级/状态、片集合及其逐片状态。Source/Destination 映射就是 W15 CrossMap 的**标准化形态**——CrossMap 表达的"每片源(盒,槽)→目标(盒,槽)"在 E40 中作为 PJ 的 Source Job/Destination Job 槽位映射被正式纳入作业对象，W15 做的源唯一/目标唯一/跨盒守恒/逐片校验全部直接服务于 PJ，只是 PJ 在此之上增加了工艺步骤、配方和任务状态机。
4. **Step/Recipe/Module 关系**：Module/Chamber 是执行加工的**物理单元**（某个工艺模块/腔体，如 C1 刻蚀腔）；Recipe 是在该模块上运行的**工艺程序/参数集**（配方，含工艺设定，版本受控）；Process Step 是 PJ 路线上的一个**加工步骤**，它把"在哪个 Module、用哪个 Recipe、对片做什么"绑定起来，是逻辑步骤。一个 PJ 由多个有序 Step 组成（如 Step1 在 Aligner 对准、Step2 在 C1 用 RCP_A 刻蚀、Step3 在 C2 用 RCP_B 处理），片随步骤在模块间迁移并加工。即 Module 是"在哪做"、Recipe 是"用什么参数做"、Step 是"第几步做、把前两者绑在一起"。
5. **Job 状态与片状态正交 / 并发例**：PJ 整体有任务级状态（如 Queued/Started/Executing/Paused/Completed/Aborted），每片有自己的位置和工艺进度（待加工/在某 Step 某腔加工中/该步完成/全部完成已放位）。二者独立：PJ=Executing 时内部各片可处于不同进度。例：一个 PJ 加工 3 片、经过 C1/C2 两腔并行，某时刻片1已完成放回目标槽、片2正在 C2 加工、片3还在源槽等待，PJ 整体仍是 Executing（未全部完成）；只有所有片完成所有步骤、归位，PJ 才 Completed。若用单一状态同时描述任务和所有片，会状态爆炸且无法表达这种部分完成的并发现实，故正交（同 W12 载具多状态机、W14 位置与工艺状态正交同一思想）。
6. **自底向上协作**：E87 管载具——载具到位、读 ID、Host 授权到 Loaded，提供"盒可访问"前提；E90 管片位置——在载具槽与设备内位置间建模、守唯一/容量/守恒、支持交叉搬运，提供"片在哪、安全取放"能力；E40 管加工任务——PJ 声明这批片的源目映射和工艺步骤，执行时驱动 E90 做位置迁移、驱动 Module 按 Recipe 加工，并跟踪 Job/片/步骤状态；E94 管编排——CJ 组织多个 PJ 的顺序并行与跨载具协同；E39 OSS 是对象载体——载具/片/PJ/CJ 都建模为 OSS 对象，S14 定义、S15 创建操作、S16 报事件；E30/E5/E37 是通信与 GEM 底座（连接、采集、报警、远程命令）。自底向上：E87 开门→E90 看片与搬片→E40 派单任务加工→E94 编排多任务，E39 承载、E30/E5 通信。
7. **PJ 开工前可行性校验**：①载具条件：所有 Source/Destination 载具在场且 E87 Loaded、未 Hold，源槽确有声明的片且 ID 对、目标槽为空（W15 Preflight）；②配方条件：每个 Step 引用的 Recipe 在设备上存在、版本/校验与声明一致（PP 验证，结合 RMS/R2R 偏移授权），不是未下载/版本不符配方；③模块条件：路线所需 Module/腔体可用、未故障未占用、能力匹配该工艺；④任务条件：PJ 定义自洽（源目映射唯一守恒、步骤顺序合法、片集合与映射一致）、JobId 不冲突、优先级/资源可满足；⑤设备状态：GEM 通信/控制状态允许远程加工（本地/远程、在线、无设备级 Hold/Alarm 阻断）。全部满足才 Start，任一不满足拒绝开工并回报原因，避免任务中途才发现前提缺失。

## 三、PJ 内部结构图（手绘参考）
```
ProcessJob { JobId, LotId, Priority, State(正交于片)
  SourceMap:      片 → (载具,源槽)          ┐ W15 CrossMap 标准化
  DestinationMap: 片 → (载具,目标槽)        ┘
  Steps[有序]: Step{ Module/Chamber, RecipeId+版本, (顺序/并行) }
  Wafers: 每片{ 当前位置(E90), 当前Step, 片状态, 轨迹 }
}
执行: 对每片按Steps: E90取片→Module按Recipe加工(位置不变状态推进)→下一Step→E90放目标
      全片完成且归位 → PJ Completed (经S16F1逐步回报)
```

## 四、费曼讲解稿（参考）
"假设一批 3 片要从 FOUP-A 取出、经过 C1、C2 两个腔体加工、放到 FOUP-B。一个 ProcessJob 就是下发给设备的一张完整工单：它先写清每片从 A 的哪个槽取、最后放到 B 的哪个槽——这就是我们上周做的 CrossMap，在标准里叫 Source/Destination 映射；然后写清工艺路线，分几步、每一步在哪个腔体、用哪个版本的配方；再带上批号和优先级。设备开工前先检查：两个盒都授权在位、源槽确实是这些片、目标槽空、配方都在且版本对、两个腔体可用，才开始。执行时设备自己调度：按路线用 E90 把片取到对应腔体，片在腔里时位置不变、工艺状态推进，加工完再取下一片，全程每片的位置和进度、整个 Job 的状态都通过标准对象事件回报。Job 状态和每片状态是两回事——Job 显示执行中时，可能一片已做完、一片在 C2、一片还没取。如果这批片还要再做下一工艺，那是再建一个 PJ，由更上层的 ControlJob 把多个 PJ 编排起来。"

## 五、今日易错点
1. 把 CJ 和 PJ 混为一谈（PJ 最小可独立执行，CJ 编排多 PJ；E40 vs E94）。
2. 以为 PJ 只是"配方执行"（它还含源目片槽映射、步骤路线、Job/片状态）。
3. 忽视 Source/Destination 就是 CrossMap 的标准化（W15 校验全部沿用）。
4. 混淆 Step（逻辑步骤）/Module（物理在哪）/Recipe（用什么参数）。
5. 用单一状态描述 Job 和所有片（必须正交，才能表达部分完成的并行）。
6. 以为 S2F41 逐条命令能替代 PJ（无任务边界、强耦合、难追溯、跨厂商不一致）。
7. 开工不校验配方版本/模块可用/载具 Loaded（前提缺失应在 Start 前拦）。
8. 忘了 PJ/CJ 都是 E39 OSS 对象（S14 定义、S15 操作、S16 事件，复用 W09/W10）。
