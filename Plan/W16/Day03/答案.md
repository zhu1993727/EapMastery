# W16 · Day03 答案与参考实现

## 一、自测题标准答案
1. **Step/Module/Recipe / 一 Step 对多腔**：Step 是逻辑工艺步骤（第几步做什么处理），Module/Chamber 是物理执行单元（在哪台/哪个腔做），Recipe 是该模块上运行的工艺程序与参数（用什么做）。一个逻辑 Step 绑定一个**模块类型/可选腔体集合**而非唯一腔体：当 C1、C2 是同型可互换腔体时，该 Step 可在任一空闲同型腔执行，调度时按可用性选腔，这就是"步骤内多实例并行"——同一 Step 对不同片可同时落在 C1、C2 上并行加工。逻辑步骤唯一、物理执行处可替换，既表达工艺意图又保留设备调度弹性（W18 多腔体深化）。
2. **串行/并行/回流表达 / 为何用依赖图**：串行=Step 间严格先后（Step1 完成才进 Step2），用有序列表+前向依赖即可；步骤内并行=同一 Step 的多片可在同型多腔同时执行（资源层并行，不改变步骤先后）；回流/重复=按条件回到前步或重复某类步骤，存在非线性跳转。纯线性列表只能表达固定顺序，表达不了"按条件分支""回到前面""多前驱汇聚"，复杂路径要用**步骤依赖图（DAG，带条件边；回流边需显式标注且保证可终止）**：节点是 Step、边是"完成且满足条件才可进入"，从而表达分支、汇聚、有限次循环，同时能用图算法检测非法环、校验每步可达。
3. **R2R 改不改主配方 / Recipe 校验内容**：R2R **不改主配方档**，只在基础 Recipe（RMS/S7 统一下发管理）之上施加经授权的**参数偏移 overlay**，实际执行=基础配方+本批偏移，主档保持稳定、偏移单独记录审计。PJ 里 Recipe 校验要核：①设备上存在该 PPID（S7 配方已下载）；②配方版本/校验值与 PJ 声明一致（不是旧版/被改动版本）；③若用 R2R 偏移，偏移有授权、针对当前批次/工况、与基础配方兼容；④该模块能力支持此配方类型；⑤（需要时）配方与产品/Lot/工艺路线匹配。全部一致才允许在该 Step 用其加工。
4. **错配方为何重大 / 在哪拦**：配方直接决定工艺参数（温度、气体、功率、时间等），用错或用旧配方会让整批片工艺条件错误，往往批量报废/返工，且可能损伤腔体，属于重大质量事故；更棘手的是设备"正常跑完"不报错，只能靠事前校验和事后良率发现。拦截应分层、越早越好：①PJ 开工前可行性校验（Day01）统一核对所有 Step 的配方存在与版本，整任务不合法就不 Start；②每步进入该模块加工前再核一次该 Step 配方与偏移（防止执行期间配方被换/RMS 更新），双层校验，绝不带着版本疑问加工。
5. **Route 可行性校验项 / 路径连通**：①模块——每步目标模块类型存在、当前可用（未故障/未被不可共享占用）、能力支持该配方类；②配方——PPID 存在、版本一致、R2R 偏移授权兼容；③顺序/依赖——StepNo 唯一、依赖引用的步骤都存在、依赖图无非法环（回流边显式且可终止）；④**路径连通**——相邻（有依赖关系）的两个步骤所在模块之间存在设备可达的搬运路径（机械臂/LoadLock/Buffer 能把片从上一步模块送到下一步模块），例如大气侧模块与真空侧模块之间必须经 LoadLock，若两步骤间没有可达物理路径，逻辑路线再对也无法执行；⑤资源——路线所需并行度不超过设备同型腔/臂数量。
6. **Route 与 WaferMap 为何解耦**：WaferMap 回答"每片是谁、从哪个源槽来、到哪个目标槽去"（物料/位置维度），Route 回答"片要经过哪些工艺步骤、在哪类模块用什么配方"（工艺维度）。二者正交解耦：同一工艺路线可作用于不同源目布局的多批片（Route 复用），同一批片换工艺时只改 Route 不改源目映射，交叉布局变化也不影响工艺定义；PJ 执行时把两者组合（对 WaferMap 中每片按 Route 推进，用 E90 在源槽、各模块、目标槽间迁移）。耦合在一起会导致换布局就要重写工艺、换工艺就要重排源目，无法复用且易出错。
7. **片在腔内位置/状态/事件**：片经 E90 Transfer 进入腔体后，位置保持在该 Chamber 不变（片物理上就在腔里），工艺状态按 Processing→（加工）→Processed 推进（W14 Process：位置不改、只改工艺状态）；进入 Step 时发"片 X 进入 Step n / 模块 C1 / 配方 RCP_A/版本"事件，加工完成发"片 X 完成 Step n、结果量测（若有）"事件，经 S16F1（OSS 对象事件）/S6F11 回报，供 FDC 监控过程、YMS/R2R 关联"哪片在哪个腔用什么配方得到什么结果"，然后片才迁移到下一 Step 模块。

namespace EapLab.E40;
public enum ModuleState { Available, Fault, Busy }
public sealed class ProcessModule
{
    public string Name { get; } public string ModuleType { get; }
    public ModuleState State { get; set; }=ModuleState.Available;
    public HashSet<string> SupportedRecipeKinds { get; }      // 能力: 支持的配方类
    public int Capacity { get; init; }=1;
    public ProcessModule(string name,string type,IEnumerable<string> kinds){Name=name;ModuleType=type;SupportedRecipeKinds=new(kinds);}
    public bool CanRun(string recipeKind)=>State==ModuleState.Available && SupportedRecipeKinds.Contains(recipeKind);
}
public sealed record RecipeInfo(string Ppid,string Version,string Kind,bool Present,string? AuthorizedOverlayForLot);

### Step 与 Route（依赖图）
```csharp
public sealed class ProcessStep
{
    public int No { get; } public string ModuleType { get; } public string Ppid { get; }
    public string Version { get; } public string RecipeKind { get; }
    public List<int> DependsOn { get; }=new();  // 前驱步骤(空=起始); 支持分支/汇聚
    public bool IsLoopBack { get; init; }       // 回流边需显式标注
    public ProcessStep(int no,string moduleType,string ppid,string ver,string kind,params int[] deps)
    {No=no;ModuleType=moduleType;Ppid=ppid;Version=ver;RecipeKind=kind;DependsOn.AddRange(deps);}
}
public sealed class ProcessRoute
{
    public Dictionary<int,ProcessStep> Steps { get; }=new();
    public ProcessRoute Add(ProcessStep s){Steps[s.No]=s;return this;}
    public IEnumerable<ProcessStep> Topological() // 确定性顺序(教学:按依赖+序号)
    { var done=new HashSet<int>(); var remain=new List<ProcessStep>(Steps.Values);
      while(remain.Count>0){ var nxt=remain.Where(s=>s.DependsOn.All(done.Contains)).OrderBy(s=>s.No).ToList();
        if(nxt.Count==0) throw new InvalidOperationException("依赖环或缺失(回流须可终止)");
        foreach(var s in nxt){done.Add(s.No);yield return s;} remain.RemoveAll(s=>done.Contains(s.No)); } }
}
```

### Route 可行性校验
```csharp
public enum RouteIssueCode { ModuleMissing,ModuleUnsupported,ModuleFault,RecipeMissing,VersionMismatch,
    OverlayNotAuthorized,DepMissing,IllegalLoop,NotReachable,StepNoDuplicate }
public sealed record RouteIssue(RouteIssueCode Code,string Detail);

public sealed class RouteValidator
{
    private readonly Dictionary<string,ProcessModule> _modules; private readonly Dictionary<string,RecipeInfo> _recipes;
    private readonly Func<string,string,bool> _reachable;                 // (fromType,toType)->物理可达
    public RouteValidator(IEnumerable<ProcessModule> modules,IEnumerable<RecipeInfo> recipes,Func<string,string,bool> reachable)
    {_modules=modules.ToDictionary(m=>m.Name);_recipes=recipes.ToDictionary(r=>r.Ppid);_reachable=reachable;}

    public List<RouteIssue> Validate(ProcessRoute route,string lotId)
    {
        var issues=new List<RouteIssue>();
        if(route.Steps.Values.Select(s=>s.No).Distinct().Count()!=route.Steps.Count)
            issues.Add(new(RouteIssueCode.StepNoDuplicate,"步骤号重复"));
        foreach(var s in route.Steps.Values)
        {
            // 依赖存在 / 回流标注
            foreach(var d in s.DependsOn)
            { if(!route.Steps.ContainsKey(d)) issues.Add(new(RouteIssueCode.DepMissing,$"Step{s.No}依赖不存在的{d}"));
              else if(d>=s.No && !s.IsLoopBack) issues.Add(new(RouteIssueCode.IllegalLoop,$"Step{s.No}回指{d}未标注回流")); }
            // 存在支持该类型且可跑该配方的模块
            var candidates=_modules.Values.Where(m=>m.ModuleType==s.ModuleType).ToList();
            if(candidates.Count==0){issues.Add(new(RouteIssueCode.ModuleMissing,$"Step{s.No}无{s.ModuleType}模块"));continue;}
            if(!candidates.Any(m=>m.SupportedRecipeKinds.Contains(s.RecipeKind)))
                issues.Add(new(RouteIssueCode.ModuleUnsupported,$"Step{s.No}模块不支持{s.RecipeKind}"));
            if(candidates.All(m=>m.State==ModuleState.Fault)) issues.Add(new(RouteIssueCode.ModuleFault,$"Step{s.No}模块全故障"));
            // 配方
            if(!_recipes.TryGetValue(s.Ppid,out var r)) issues.Add(new(RouteIssueCode.RecipeMissing,s.Ppid));
            else
            { if(!r.Present) issues.Add(new(RouteIssueCode.RecipeMissing,$"{s.Ppid}未下载"));
              if(r.Version!=s.Version) issues.Add(new(RouteIssueCode.VersionMismatch,$"{s.Ppid} 声明{s.Version} 实际{r.Version}"));
              if(r.AuthorizedOverlayForLot is null || r.AuthorizedOverlayForLot!=lotId)
                  {/* 无偏移时正常; 若需要R2R偏移则必须授权, 由调用方标记后判 OverlayNotAuthorized */} }
        }
        // 路径连通: 依赖的前后步模块类型之间可达
        foreach(var s in route.Steps.Values)
            foreach(var d in s.DependsOn.Where(route.Steps.ContainsKey))
            { var from=route.Steps[d].ModuleType;
              if(!_reachable(from,s.ModuleType)) issues.Add(new(RouteIssueCode.NotReachable,$"{from}->{s.ModuleType} 不可达")); }
        return issues;
    }
}
```

public class RouteTests
{
    static (List<ProcessModule>,List<RecipeInfo>) Assets()
    { var mods=new List<ProcessModule>{ new("C1","ETCH",new[]{"ETCH_K"}),new("C2","ETCH",new[]{"ETCH_K"}),new("AL","ALIGN",new[]{"ALIGN_K"}) };

    [Fact] public void 合法路线_对准后刻蚀_通过()

                                  .Add(new(2,"ETCH","RCP_A","v3","ETCH_K",1));

## 三、今日易错点
1. 把逻辑 Step 和物理腔体一一绑死（同型多腔可替换、步骤内并行）。
2. 只用线性列表表达分支/回流（要用依赖图、检测非法环、回流显式可终止）。
3. 以为 R2R 改主配方档（只加授权 overlay 偏移，主档稳定、偏移审计）。
4. 只在开工前校验一次配方（执行进该步前再核版本，防中途被换）。
5. 忽略路径连通（逻辑相邻步骤之间必须有物理可达搬运路径，如经 LoadLock）。
6. Route 和 WaferMap 耦合（工艺维度与物料位置维度正交解耦、各自复用）。
7. 片在腔加工误建位置迁移（位置不变、工艺状态推进，发进/出 Step 事件）。
8. 不校验模块能力（某腔不支持该配方类却安排加工）。
