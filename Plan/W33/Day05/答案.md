# W33 · Day05 答案与参考实现

## 一、自测题标准答案
1. **下载 vs 选择/为何分开**：下载（S7）是把配方体从 RMS 存到设备本地存储器，属于仓储/传输动作，设备可同时存许多 PPID；选择（PP-Select）是从本地已存配方中指定"接下来加工实际使用哪一个"，属于生产动作。分开的好处：配方可一次下载、多次/按需选用，切换产品只选不重传、效率高；下载阶段专注传输完整性，选择阶段专注"用对版本"，职责清晰、门控独立，也便于多配方管理与一致性控制。
2. **消息/参数**：用 GEM 远程命令 S2F41，RCMD 为 PP-SELECT（厂商也可能命名 SELECT_PPG 等），CP 参数携带 PPID（配方标识）、版本号，多腔/多层时带目标腔号/工艺层，可带工单/Lot 关联与请求 id（幂等）；设备以 S2F42 回 ACKC10（0=受理）。注意受理只是收到请求，真正选中要靠状态变量回读确认。
3. **五条前置门控/缺项风险**：①Remote 模式（非 Local/Offline，否则上位无权控制）；②设备/目标腔处于 Idle 或片间安全点、未在加工（加工中换配方破坏 run 一致性甚至引发危险）；③目标 PPID/版本已下载且一致性校验通过（本地==golden，否则可能跑被私改/损坏/旧版配方）；④与 MES 当前工单/Lot/工艺路线要求的 PPID/版本一致（防跑错产品配方造成批量报废）；⑤无 Hold/严重 Alarm/安全联锁。任一不满足都应拒绝并回原因；缺一致性会跑错参数、缺工单匹配会跑错产品、加工中选择会造成 run 内参数混乱。
4. **为何回读**：S2F42 ACKC10=0 只表示设备受理了选择命令，真正切换可能因内部状态、同名歧义、写入失败而未完成。必须回读设备"当前选中 PPID/版本"状态变量（多腔逐腔回读），与请求值逐一比对一致才判 Selected/生效；不一致判失败、保持原配方并告警。这与 overlay 生效、GEM 命令"受理≠生效"完全一致，防止"上位以为选了 A、设备实际还是 B"。
5. **加工中请求/原因**：应拒绝（回非 0，原因如 processing/bad state），请上位在片间安全点或本 run 结束后重发。因为一个 run 内配方必须保持稳定一致，中途换步骤/参数会导致该片工艺不完整、结果不可预测，也可能违反设备状态机（加工态不允许装载/切换）、带来安全风险；这与 overlay 只在 run 前/片间下发、FDC 异常期暂停调节是同一原则——run 内稳定优先。
6. **选择与作业启动顺序**：先选配方并回读确认 Selected（配方层就绪）→再做 E40 PJ/E94 CJ 的资源分配与作业创建、片盒/Slot 校验（E87/E90，作业与物理层就绪）→最后收到启动命令才开始加工。配方未确认 Selected 不得 Start，形成"配方对→作业合法→物理片在位"的门控链（呼应 W22 十阶段门控：物理事实→逻辑授权→任务编排）。多腔时各腔配方分别选定确认后，作业才可跨腔调度。
7. **缺配方/版本不一致闭环**：不允许直接选择或报错了事，应自动闭环：①选择门控发现本地缺失或一致性不过→触发 S7 下载（Day02，先 Inquire 后 Send）；②下载后做 golden 一致性校验（Day03，PPID/版本/长度/hash）；③校验通过后再执行 PP-Select 并回读确认；④若下载/校验/选择反复失败则升级告警、禁止该设备/腔开工。即"缺则下、下则校、校则选、选则认"，每步以实际状态为准、幂等可重试，全过程审计。

## 二、参考实现（net8.0）：配方选择器

```csharp
namespace EapLab.Rms.Select;
public enum SelState{ Idle,Requested,Accepted,Selected,Rejected }
public sealed record SelectReq(string ReqId,string Ppid,string Ver,string Chamber,string WorkOrderVer);
public sealed class RecipeSelector
{
    readonly HashSet<string> _done=new();
    // 门控输入: remote/processing/本地一致/工单版本匹配/无hold; 当前设备选中值
    public (SelState s,string? err)
        Select(SelectReq r,bool remote,bool processing,bool localMatch,bool noHold,
               Func<string,string?> readbackPpid,Func<string,string?> readbackVer,Action<string,string> setCurrent)
    { if(_done.Contains(r.ReqId))return(SelState.Selected,"idempotent"); // 幂等
        _done.Add(r.ReqId);
        if(!remote)return Rej("not remote");
        if(processing)return Rej("processing");
        if(!localMatch)return Rej("local recipe not compliant, redownload first");
        if(r.Ver!=r.WorkOrderVer)return Rej("version mismatch with workorder");
        if(!noHold)return Rej("hold/alarm interlock");
        setCurrent(r.Ppid,r.Ver);                                        // 设备内部切换
        // 回读确认(受理≠生效)
        if(readbackPpid(r.Chamber)!=r.Ppid||readbackVer(r.Chamber)!=r.Ver)return Rej("readback mismatch");
        return(SelState.Selected,null); }
    (SelState,string?)Rej(string e)=>(SelState.Rejected,e);
}
```

public class SelectorTests

## 三、PP-Select 门控时序（手绘参考）
```
MES工单(要求PPID/版本) → EAP发 S2F41 PP-SELECT(PPID,版本,腔,ReqId)
 门控(缺一拒): Remote? 非加工/安全点? 本地已下载且hash==golden? 版本==工单? 无Hold/Alarm?
   否→拒绝原因(缺/不一致→自动S7重下+校验再选)
   是→设备内部切换 → S2F42 ACKC10=0(仅受理)
 → 回读当前PPID/版本==请求? ─是→Selected+S6F11(配方就绪) ; 否→失败保持原配方告警
 → 配方Selected 才允许 E40/E94作业就绪→Start加工(配方→作业→物理片 门控链)
多腔: 逐腔选择逐腔回读; 加工中拒选(run内稳定); 重复ReqId幂等不重复切
闭环: 缺则下→下则校→校则选→选则认, 每步以设备实际状态为准
```

## 四、今日易错点
1. 把下载当选择（S7 存储≠PP-Select 指定使用）。
2. S2F42=0 就当选中（要回读当前 PPID/版本一致）。
3. 漏门控：Local/加工中/本地不一致/版本不符工单/Hold 仍选择。
4. 不校验与 MES 工单版本一致，跑错产品配方。
5. 加工中允许换配方，破坏 run 一致性。
6. 配方未确认 Selected 就启动 PJ/CJ。
7. 多腔只选一个腔或不逐腔回读。
8. 本地缺失只报错不自动"下-校-选"闭环；重复选择无幂等。
