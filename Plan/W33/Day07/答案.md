# W33 · Day07 答案

## 一、综合自测卷（7 题）参考答案
1. **新配方到生产全过程**：Draft 编辑→Validating 工程片验证→PendingApproval 工艺/质量会签（申请人≠批准人）→Released 成为 RMS golden（body+强 hash）→经 S7 分发：S7F1 Inquire（查空间/状态）→S7F2=0 就绪→S7F3 下发（PPID/PPHEAD/PPBODY=B）→S7F4=0 写入→回读做一致性校验（PPID/版本/长度/hash）通过进入 Distributed→生产时 MES 工单指定 PPID/版本→PP-Select 五门控（Remote/安全点/本地一致/版本合工单/无 Hold）→S2F41 选择、S2F42 受理→回读当前 PPID/版本一致 Selected→配方就绪后 E40/E94 作业与物理片门控通过才 Start。全程状态机、消息、校验、审计留痕。
2. **下载握手/三级判据**：先 S7F1 询问、S7F2 ACKC7=0 表设备就绪可接收（此时未传 body）；再 S7F3 下发、S7F4=0 表设备写入并校验成功；最后 S7F5/F6 回读 body 算 hash 与 golden 一致才表内容真正正确。区别：S7F2=0=准备好（一个字节没传），S7F4=0=传完写入（但之后可能被改/损坏），回读一致=此刻内容与主库完全相同（进入 Distributed 的最终判据）。三者逐级递进，任一不过不进入下一步。
3. **一致性要素/手段/同名 hash 变**：要素=PPID、版本、长度、checksum/强哈希、（仲裁）逐字节，外加适用设备/格式元数据。手段检错能力递增：长度→累加和/checksum→CRC（突发位错）→SHA-256（抗碰撞、防刻意篡改）。PPID 没变 hash 变=疑似面板私改（也可能损坏），处置：立即联锁禁选→回读取证、比对差异→从 RMS 重下正确版并复检→上报告警与质量调查、追溯设备/时间/人，重下仍异常判存储硬件问题转维修。
4. **ECN/决策/overlay 长期化**：ECN=提出（旧→新值与依据）→影响分析（产品/设备/在制 Lot/上下游/R2R/VM）→会签（权责分离）→验证→Released 新版本（旧版冻结 Superseded）→分发替换→投产 SPC/FDC 监控→异常受控回滚。决策依据：永久性/结构性/超 knob 范围/跨产品通用→ECN 改主档；knob 内/小幅/特定腔 Lot 片/短期可撤→R2R overlay。若某腔 overlay 长期单侧增大或撞限（SPC 监控到），说明基线系统性偏移，应把验证有效的补偿提升为 ECN 主档修改、做保养、R2R 归零重建、VM 按需重训。
5. **五门控/选前再校验/加工不换**：Remote 模式、设备/腔在安全点未加工、本地已下载且 hash==golden、版本与 MES 工单一致、无 Hold/严重 Alarm。选前再校验是因为下载后到生产之间仍可能被改/损坏/掉电，PP-Select 紧挨生产，是"即将执行这份"的最后闸门。加工中不能换是因为 run 内配方必须稳定一致，中途换步骤/参数使该片结果不可预测且违反设备状态机、有安全风险，故加工中请求一律拒绝、请片间重发。
6. **灰度/五类例外/Tampered**：试点 1–2 台→SPC/VM/FDC 观察窗达标→分批扩大→全量并更新 baseline；任一批异常冻结后续、已升级受控回滚上一 baseline，记录批次原子边界。五类：Missing 缺失（下载）、Outdated 旧版（升级）、Corrupt 损坏（重下，仍坏维修）、Tampered 同名 hash 变（未授权私改）、UnauthorizedException 未批准专属版本（整改或补授权）。Tampered 最优先因为它是绕过变更体系的未授权改动、可能正用未知参数批量生产、涉合规与人为违规，必须立即联锁取证调查，其余多为可自动修复的同步问题。
7. **主档升级联动**：R2R overlay——绑定旧版本，主档一变立即失效、不得叠加，针对新版本重新初始化（工程片建初始状态）；VM 模型——作用域绑定版本，核对是否适用，不匹配用新数据重训；在制 Lot——明确生效时点（跑完当前 Lot 再切或立即切并隔离评估），避免同一 Lot 跨版本无记录；MES 工单——工艺路线引用的目标版本随 ECN 更新，新工单指向新版本；机群——按灰度分发切换并盘点一致，异常受控回滚。所有联动以新版本号绑定并审计。

## 二、费曼三问参考
- **下载/选择/生效分开**：下载像把菜谱抄进厨房的菜谱柜（存了很多份），选择像从柜子里抽出今晚要做的那一份放在灶台，生效像厨师确认"我手里确实就是这份、一页没少没被改"。三步分开且每步都确认，才不会出现"柜子里有≠今晚做这份≠手里这份对"；任何一步想当然（发过了=存了、受理了=选中了）都会在生产时跑错配方。
- **主档=盖章法定文件，overlay=可撕便签**：recipe 主档是经过评审盖章、对所有机台所有 Lot 生效的法定文件，改它必须走正式变更（ECN）并留旧档；R2R overlay 是针对某腔某 Lot 临时贴的便签，写完即撕、绝不誊抄到法定文件上；工程师在面板偷偷改设备本地配方，等于私下篡改盖章文件还不上报，是质量事故。便签贴久了且越写越厚，说明法定文件本身该修订了，这时才走正式流程改主档。
- **单机到机群放大**：一台机对不难，难在一百台机同时对；异步升级时漏一台、慢一台、被私改一台，就会出现"同工艺不同机台结果不同"的机台差。灰度像先在一两条产线试跑新配方、盯紧指标没问题再一批批推开，一旦异常立刻停推并把试点退回旧版，把风险锁在最小范围；定期盘点像点名，逐台核对"该跑 v4、实际是不是 v4、有没有被偷改"，并形成可审计台账。

## 三、EapLab.Rms 资产盘点
- 根：Recipe/RecipeStep、RcState/RcTrigger、RecipeLifecycle（生命周期状态机、生产可用判定）。
- .S7：PProgram（Body/Crc/Length）、AckC7、S7Phase、S7DownloadSession（Inquire→Send→Downloaded、中断回读核实）。
- .Compliance：CompareResult、RecipeComparer（PPID/版本/长度/hash/逐字节）、Disposition、AuditEntry、ComplianceAuditor（联锁-重下-升级闭环）。
- .Ecn：EcnRequest/EcnState/EcnTrigger、EcnWorkflow（权责分离/受控回滚）、ChangeDecision（主档 vs overlay 决策树）。
- .Select：SelState、SelectReq、RecipeSelector（五门控+回读+幂等）。
- .Fleet：EqState、EqRecipe、FleetRecipeManager（baseline/分类/分发/灰度回滚）。
- 依赖方向：RMS 是配方事实源；S7 负责传输、Compliance 负责校验、Select 负责门控、Fleet 负责机群；R2R overlay 运行时叠加、绝不写回主档；build+test 全绿，tag `w33-rms`。

## 四、W33 全周易错点总清单
1. 只有 PPID 无版本、版本可覆盖、旧版不冻结。
2. 允许 Draft/Obsolete/未分发配方生产，非法生命周期跳转不拦。
3. 把 PPBODY 当 A 文本（实为 B，Host 透明传输）。
4. 跳过 S7F1 直接 F3；把 S7F2=0 当下载完成（要 F4=0+回读一致）。
5. ACKC7 不分可恢复/不可恢复，盲目重发；大配方不做整包校验。
6. 只比长度/弱校验，防不住私改；同名 hash 变只重下不调查。
7. 不一致不先联锁、重下失败不升级、漏选前最后校验。
8. ECN 申请人自批、跳验证；结构性/超范围改动图快走 overlay。
9. overlay 长期化不提升 ECN；主档升级不重置 R2R/VM。
10. 私下热改/私下回滚无记录。
11. 下载当选择；S2F42=0 当选中；漏五门控、加工中换配方、未选中就 Start。
12. 多腔不逐腔选择回读；重复选择无幂等。
13. 单机一致当机群一致；无 baseline/目标矩阵；Tampered 当同步问题。
14. 全量无灰度无观察窗、异常不能回滚、无机群审计台账。
15. 主档切换不明确在制 Lot 生效时点、不更新 MES 工单引用版本。
