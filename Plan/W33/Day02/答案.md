# W33 · Day02 答案与参考实现

## 一、自测题标准答案
1. **消息对与方向**（教学口径，精确字段以 SEMI E5/设备手册为准）：下载 Host→设备——S7F1 Process Program Load Inquire（询问可否装载，带 PPID/长度）/S7F2 设备回 ACKC7；S7F3 Process Program Send（正式下发 PPID+PPHEAD+PPBODY）/S7F4 回 ACKC7 结果。上传 Host←设备——S7F5 Process Program Request（请求上传指定 PPID）/S7F6 返回 PPID+PPHEAD+PPBODY。删除——S7F17 删除请求/S7F18 确认。目录——S7F19 请求设备当前配方目录/S7F20 返回 PPID 清单。记忆：F1/F2 先问、F3/F4 下发、F5/F6 取回、F17/F18 删、F19/F20 盘点。
2. **S7F3 结构/PPBODY 为何 B**：S7F3 为 `L,3 [PPID(A 字符串标识), PPHEAD(L/A 头部属性如长度/格式/时间), PPBODY(B 二进制字节串，配方体)]`。PPBODY 是 B，因为配方体是设备厂商私有的二进制编码（控制器直接执行的机器格式），不是标准可读文本；Host/RMS 通常**不解析其内部参数**，只做透明存储/传输与完整性校验（长度、checksum），解析与执行是设备控制器的事。这与 S6 报告里可读的过程数据不同，别把 PPBODY 当 A 文本处理。
3. **为何先 Inquire/跳过的问题**：S7F1 先询问，让设备在接收大文件前检查存储空间是否够、当前状态是否允许写入（是否在加工/本地写保护）、PPID 是否冲突；设备回 ACKC7=0 表示就绪，Host 才发 S7F3。跳过直接发 S7F3，可能传到一半才发现空间不足/状态不允许/同名冲突，浪费链路、留下半截损坏副本，甚至影响正在进行的作业；先问后发把失败前置、保证设备就绪，是大文件可靠传输的标准握手。
4. **成功判据/S7F2=0**：完整成功判据是 S7F1→S7F2=0（允许装载）**且** S7F3→S7F4=0（设备写入并校验通过），最好再回读 body/checksum 与 golden 比对一致（Day03）。S7F2=0 只代表设备"同意接收、准备好了"，此时一个字节配方体都还没下发，绝不代表下载完成；只有 S7F4=0（并通过一致性校验）才是真正下载成功、可进入 Distributed。
5. **ACKC7 原因码与处理**（教学值）：0 接受继续；1 不允许/权限不足（查模式/权限/写保护，不可硬发）；2 PPID 不存在（上传/删除目标缺失，上报核对）；3 PPID 已存在（重复下载，确认是否覆盖或走版本更新）；4 长度不符/空间不足（清理空间、删废弃副本后重试，可恢复）；5 PPBODY 校验错（checksum/格式不符，重传，多次失败上报，可能链路/编码问题）；6 非法 PPID/参数（命名不合规，拒绝并修正）。原则：空间/临时状态类可退避重试且有上限；校验错/非法/权限类不可盲目重发，上报告警并记录，靠目录/回读核实状态。
6. **大配方分段/完整性**：当 PPBODY 超过单条 SECS 消息上限，按厂商扩展/分块协议切成多块按序发送，每块带序号，设备按序缓存拼接，全部到齐后做**整包**长度与 checksum 校验（不是只校验单块），完整一致才确认成功，任一块缺失/错序/校验失败则整份判失败、丢弃半成品并重传；同时结合 HSMS 超时控制。本质与分包传输一致：分块只是传输手段，成功判据仍是"整包还原且校验一致"。
7. **中断后核实真实状态**：不凭"我发过 S7F3"假设成功（可能只写了一半或设备回的 S7F4 丢失）。应：①用 S7F19/F20 查设备目录确认该 PPID 是否存在；②用 S7F5/F6 回读 PPBODY，计算 checksum/长度与 RMS golden 比对；③三者（目录存在+body 一致+checksum 相同）都满足才判 Distributed，否则按缺失/损坏重新下载。即"以设备实际状态和回读为准"，与 GEM 受理≠生效、命令幂等的思想一致，避免半成品配方被选中生产。

## 二、参考实现（net8.0）：S7 下载会话状态机

```csharp
namespace EapLab.Rms.S7;
public enum S7Phase{ Idle,Inquired,AckToLoad,Sent,Downloaded,Failed }
public enum AckC7{ Ok=0,NotAllowed=1,NoSuchPpid=2,PpidExists=3,NoSpace=4,BodyBad=5,IllegalPpid=6 }
public sealed record PProgram(string Ppid,string Version,byte[] Body)
{ public int Length=>Body.Length;public string Crc=>Body.Length.ToString("X")+":"+Body.Sum(b=>b).ToString("X"); }

public sealed class S7DownloadSession
{
    public S7Phase Phase{get;private set;}=S7Phase.Idle;public int Attempts{get;private set;}
    // S7F1 询问, 设备依据空间/状态/同名回 ACKC7
    public AckC7 SendInquire(PProgram pp,bool enoughSpace,bool writable,bool exists)
    { if(Phase!=S7Phase.Idle)throw new InvalidOperationException("bad phase");
        Attempts++;AckC7 ack=!writable?AckC7.NotAllowed:!enoughSpace?AckC7.NoSpace:exists?AckC7.PpidExists:AckC7.Ok;
        Phase=ack==AckC7.Ok?S7Phase.Inquired:S7Phase.Failed;return ack; }
    // S7F3 下发, 设备写入并校验长度/checksum 后回 S7F4
    public AckC7 SendBody(PProgram pp,Func<byte[],bool> deviceWriteAndCheck)
    { if(Phase!=S7Phase.Inquired)throw new InvalidOperationException("must inquire first");
        Phase=S7Phase.Sent;bool ok=deviceWriteAndCheck(pp.Body);
        if(ok){Phase=S7Phase.Downloaded;return AckC7.Ok;}
        Phase=S7Phase.Failed;return AckC7.BodyBad; }
    public void Reset(){Phase=S7Phase.Idle;}
    // 中断恢复: 目录存在 + 回读CRC一致 才算已下载
    public bool VerifyAfterInterrupt(PProgram golden,bool inDirectory,string readbackCrc)
    =>inDirectory&&readbackCrc==golden.Crc;
}
```

## 三、S7 下载时序（手绘参考）
```
Host(EAP/RMS)                 设备
 │ S7F1 Inquire(PPID,len) ───▶│ 查空间/状态/同名
 │◀─ S7F2 ACKC7=0(就绪) ──────│  非0: 清理/等空闲/核对, 不发F3
 │ S7F3 Send(PPID,HEAD,BODY)─▶│ 写本地+校验长度/checksum (PPBODY=B,Host不解析内部)
 │◀─ S7F4 ACKC7=0(写入成功) ──│
 成功=F2=0 且 F4=0, 再S7F5/F6回读CRC与golden一致 → Distributed → 可PP-Select
中断恢复: S7F19/F20目录在否 + S7F5/F6回读CRC一致, 缺一即重下(不信"发过了")
大配方: 分块按序→整包拼接→整包checksum, 任一失败丢弃半成品重传
ACKC7: 0ok 1不允许 2无此PPID 3已存在 4空间 5body校验错 6非法 (可恢复退避有上限, 不可恢复上报)
```

## 四、今日易错点
1. 把 PPBODY 当可读 A 文本（实为 B 二进制，Host 透明传输）。
2. 跳过 S7F1 直接 S7F3，失败留半截副本。
3. 把 S7F2=0 当下载完成（只是就绪，要 S7F4=0+回读一致）。
4. 记混消息方向（F3 下发、F6 回传）。
5. ACKC7 原因码不分可恢复/不可恢复，盲目重发。
6. 大配方只校验分块不校验整包 checksum。
7. 中断后凭发送记录假设成功，不用目录+回读核实。
8. 允许非 Released 配方下载、下载不一致就 PP-Select。
