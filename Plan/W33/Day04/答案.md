# W33 · Day04 答案与参考实现

## 一、自测题标准答案
1. **版本规则/不可覆盖**：(PPID, version) 唯一确定一份配方内容与 hash；版本号单调、只增不改，每次 ECN 派生新版本，旧版本内容**冻结保留**、永不被覆盖或复用。原因：质量追溯要求任意历史 Lot 都能还原"当时跑的确切参数"，若旧版被覆盖，历史问题无法复现、回滚无据、审计断链；同时避免同名同版内容不一致。可用 major.minor 区分变更等级（结构/重大工艺改 major 需完整重验，小修订升 minor 做对应验证），规则企业自定但必须明确可审计。
2. **ECN 步骤**：①提出变更请求（申请人、目标 PPID、参数旧值→新值、原因与数据依据）；②变更影响分析（产品/设备/腔/在制 Lot/上下游/R2R 与 VM 影响、风险等级）；③会签审批（工艺/设备/质量，必要时客户，申请人≠批准人，权责分离）；④验证（工程片/小批量，确认有效无副作用并归档数据）；⑤批准发布为新 golden（走生命周期状态机 Released）；⑥分发替换（S7 下载+一致性校验、切换默认 PP-Select 版本、旧版 Superseded）；⑦投产生效与 SPC/FDC 监控，异常时受控回滚上一 Released 版。全程电子签名、时间戳、记录可审计。
3. **影响分析覆盖**：横向——同配方用于哪些产品/工艺层/机台/腔，全量切换还是分产品版本；纵向——对前道来料要求与后道工艺窗口的影响；控制系统——主档变了，R2R 基线/overlay、VM 模型是否需重置或重训（W31/W32）；在制品——生效时点与在制 Lot 的关系（跑完再切/立即切并隔离评估）；文档与资源——SOP、控制计划、检验标准、培训是否同步；风险等级——据此确定验证深度与审批级别。
4. **两类例子**：应走 ECN 改主档——①把刻蚀步骤气体从 A 改为 B 或增删一个工艺步骤（结构性、永久性）；②经验证要把某工艺温度基线长期提高 15℃且超出 R2R 可调 knob 范围、适用于所有腔所有 Lot（跨产品新基线）；③修改硬联锁/端点条件。应用 R2R overlay——①某腔因积膜慢漂移，本 Lot 抛光时间在 knob 范围内 +2s，下批随量测自动回调；②针对当前 Lot 的 overlay 套刻做小幅焦距/剂量补偿，Lot 结束即失效；③抵消腔间小幅固定差的临时补偿（作用域到腔、可撤销）。判据：永久/结构/超范围/跨产品→ECN；临时/小幅/knob 内/特定作用域/自动可撤→overlay。
5. **overlay 长期化的含义/做法**：正常 overlay 应在零附近小幅波动、随漂移补偿而消长；若某腔 overlay 长期偏置且持续增大（SPC 监控 Δu 单侧趋势/撞限，W32 Day06），说明不是可自动抵消的随机慢漂移，而是**基线本身已经系统性偏移**（设备老化、积膜到需保养、原 recipe 基线不再合适），靠 R2R 硬扛会到补偿极限。做法：把这段时间被数据验证有效的补偿量固化，**发起 ECN 修改主档基线**（新版本），同时对该腔做保养/校正，并把 R2R 状态与 overlay 归零、基于新基线重建，VM 按需重训。这是 R2R/SPC 数据反哺工艺与设备改进的标准闭环。
6. **主档切换为何重置 R2R/VM**：R2R 的 EWMA 状态、过程增益假设、overlay 都是相对"旧主档基线"估计的，VM 模型学的是"旧基线下过程特征→输出"的关系；主档版本一变，基线参数、工艺窗口、特征-输出关系都可能改变，旧状态/模型不再适用，继续用会错补偿、错预测（相当于在新过程上套旧模型外推）。因此主档切换时：旧 overlay 立即失效（W31 Day03 已绑定版本），R2R 针对新版本重新初始化（可用工程片建立初始状态），VM 确认模型作用域、不匹配则用新数据重训，全部与新版本号绑定留痕。
7. **回滚也要受控**：回滚本质也是一次"生产所用配方版本的变更"，若工程师私下改回，等于绕开审批做了一次无记录热改：无法知道谁在何时为何切回、可能回滚到未经确认的版本、多机台不一致，且破坏审计链，和面板私改同样危险。受控回滚要：基于预先保留的上一 Released golden，按授权发起、记录原因（新版本 SPC/FDC 异常证据）、经 S7 分发并一致性校验、明确生效范围、全程留痕，事后还要补变更评审。这样回滚可追溯、可复现、全机台一致，符合质量体系。

## 二、参考实现（net8.0）：ECN 受控变更流程

```csharp
namespace EapLab.Rms.Ecn;
public enum EcnState{ Draft,ImpactAnalyzed,PendingSignOff,Approved,Validated,Released,Rejected,RolledBack }
public enum EcnTrigger{ Analyze,SignOff,Approve,Validate,Release,Reject,Rollback }
public sealed class EcnRequest
{ public string Ppid,FromVer,ToVer,Reason,Requester;public HashSet<string> SignOffs{get;}=new();
    public bool PermanentOrStructural,WithinKnob,ScopeSpecific;public EcnState State{get;internal set;}=EcnState.Draft;
    public EcnRequest(string ppid,string from,string to,string who,string why){Ppid=ppid;FromVer=from;ToVer=to;Requester=who;Reason=why;} }
public static class ChangeDecision
{ // 主档ECN vs R2R overlay 决策树
    public static string Route(bool permanentOrStructural,bool withinKnob,bool scopeSpecific,double delta,double knobRange)
    { if(permanentOrStructural||!withinKnob||Math.Abs(delta)>knobRange)return "ECN-MASTER";
        return scopeSpecific?"R2R-OVERLAY":"ECN-MASTER"; } // 非特定作用域的通用调整也走主档
}
public sealed class EcnWorkflow
{
    static readonly Dictionary<(EcnState,EcnTrigger),EcnState> M=new()
    { [(EcnState.Draft,EcnTrigger.Analyze)]=EcnState.ImpactAnalyzed,
      [(EcnState.ImpactAnalyzed,EcnTrigger.SignOff)]=EcnState.PendingSignOff,
      [(EcnState.PendingSignOff,EcnTrigger.Approve)]=EcnState.Approved,
      [(EcnState.Approved,EcnTrigger.Validate)]=EcnState.Validated,
      [(EcnState.Validated,EcnTrigger.Release)]=EcnState.Released,
      [(EcnState.PendingSignOff,EcnTrigger.Reject)]=EcnState.Rejected };
    public void Fire(EcnRequest r,EcnTrigger t,string? actor=null)
    { if(t==EcnTrigger.Approve&&actor==r.Requester)throw new InvalidOperationException("separation of duty");
        if(!M.TryGetValue((r.State,t),out var ns))throw new InvalidOperationException($"{r.State}+{t} illegal");
        r.State=ns; }
    public void Rollback(EcnRequest r){if(r.State!=EcnState.Released)throw new InvalidOperationException("only released can rollback");
        r.State=EcnState.RolledBack;} // 受控回滚, 留痕
}
```

### xUnit
```csharp
public class EcnTests
{
    [Fact] public void 正常ECN到发布()
    { var w=new EcnWorkflow();var r=new EcnRequest("R","3","4","eng","improve");
      w.Fire(r,EcnTrigger.Analyze);w.Fire(r,EcnTrigger.SignOff);w.Fire(r,EcnTrigger.Approve,"mgr");
      w.Fire(r,EcnTrigger.Validate);w.Fire(r,EcnTrigger.Release);Assert.Equal(EcnState.Released,r.State); }
    [Fact] public void 申请人不能自批_权责分离()
    { var w=new EcnWorkflow();var r=new EcnRequest("R","3","4","eng","x");
      w.Fire(r,EcnTrigger.Analyze);w.Fire(r,EcnTrigger.SignOff);
      Assert.Throws<InvalidOperationException>(()=>w.Fire(r,EcnTrigger.Approve,"eng")); }
    [Fact] public void 结构性改动走ECN()
    { Assert.Equal("ECN-MASTER",ChangeDecision.Route(true,true,true,1,10)); }
    [Fact] public void knob内特定腔Lot小幅补偿走overlay()
    { Assert.Equal("R2R-OVERLAY",ChangeDecision.Route(false,true,true,2,10)); }
    [Fact] public void 超knob范围即使临时也走ECN()
    { Assert.Equal("ECN-MASTER",ChangeDecision.Route(false,false,true,20,10)); }
    [Fact] public void 通用非特定作用域调整走主档()
    { Assert.Equal("ECN-MASTER",ChangeDecision.Route(false,true,false,2,10)); }
    [Fact] public void 只有已发布版本可受控回滚()
    { var w=new EcnWorkflow();var r=new EcnRequest("R","3","4","e","x"){State=EcnState.Approved};
      Assert.Throws<InvalidOperationException>(()=>w.Rollback(r)); }
}
```

## 三、ECN 流程与决策树（手绘参考）
```
变更需求(数据依据: SPC/FDC/R2R撞限/客户)
 ├─ 永久/结构/超knob/跨产品通用 ─→ ECN改主档(新版本, 旧版冻结)
 │     Draft→影响分析→会签(申请人≠批准人)→验证→Approved→Released
 │     →S7分发+一致性校验→切换默认版本, 旧版Superseded→SPC/FDC监控→异常受控回滚(留痕)
 │     →主档变: R2R状态/overlay归零重建, VM作用域核对/重训
 └─ knob内/小幅/特定腔Lot片/短期可撤 ─→ R2R overlay(运行时叠加, 不改主档)
        若overlay长期单侧增大/撞限 → 基线该改 → 提升为ECN, 保养+归零重建
在制Lot: 明确生效时点(跑完再切/立即切隔离评估); 版本只增不改,(PPID,ver)唯一
铁律: 禁止面板热改(Day03篡改检测抓); 回滚也是受控变更; 全程电子签名可审计
```

## 四、今日易错点
1. 版本可覆盖、旧版不冻结，历史无法追溯/回滚。
2. ECN 跳过影响分析或验证直接发布；申请人自批（无权责分离）。
3. 结构性/超范围改动图快用 overlay（必须 ECN）。
4. 通用跨产品调整也用临时 overlay（应固化进主档）。
5. overlay 长期单侧增大仍硬扛，不提升为 ECN/不保养。
6. 主档切换后不重置 R2R、不核对/重训 VM，新基线套旧状态。
7. 私下回滚/热改、无记录、机台不一致。
8. 不明确在制 Lot 的变更生效时点，造成同 Lot 跨版本混乱。
