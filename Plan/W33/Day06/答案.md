# W33 · Day06 答案与参考实现

## 一、自测题标准答案
1. **单机≠机群/机台差来源**：单机只保证"这一台本地副本与 golden 一致"，而机群有几十上百台同型设备，ECN 发布新版本时要逐台分发切换，人工/异步过程中会出现漏升、延迟升、升级失败未处理、某台被本地私改、个别机台残留旧版等情况，于是同一 PPID 在不同机台实际跑不同版本，形成 tool-to-tool variation（机台差）：相同产品过不同机台结果系统性不同，是良率与一致性杀手。机群级治理要在任意时刻掌握每台"应跑哪版、实跑哪版、是否一致"，并可控统一。
2. **三个概念**：fleet baseline 是某 PPID 当前经批准、应在全适用机群生效的权威版本（来自最新 Released golden/ECN）；目标矩阵=每台适用设备**应当**所处的版本（一般等于 baseline，少数经批准的机台专属受控例外表不同）；设备实际状态=每台**实际**选中的版本、本地 hash 与 golden 是否一致、最后核对时间。目标与实际逐台比对，差异即例外项。
3. **单台分发步骤/设备忙**：①确认目标版本 golden 已 Released；②S7F1 Inquire 设备就绪与空间；③S7F3 下载、S7F4 确认；④一致性校验（PPID/版本/长度/hash，Day03）；⑤在安全点（Idle/片间、Remote、无 Hold）做 PP-Select 并回读确认（Day05）；⑥更新该机实际状态与台账。设备忙（在加工）时不强制打断当前 run，把分发/切换排入队列，等其到片间/空闲安全点再执行，与生产调度协同，保证 run 内配方稳定；失败自动重试有上限，超限升级为人工/维修。
4. **五类例外/Tampered 优先**：Missing（本地无此 PPID，需下载）、Outdated（本地是旧版本，需升级）、Tampered（同名同版但 hash 不符，疑似面板私改/未授权变更）、Corrupt（长度/字节损坏，重下，仍坏查硬件）、UnauthorizedException（存在未经批准的机台专属版本，需整改或补批准）。Tampered 优先级最高，因为它不是传输/同步问题，而是**绕过变更体系的未授权改动**，可能正在用未知参数生产、有合规与批量质量风险且可能涉及人为违规，必须立即联锁禁止生产、取证回读、启动质量调查与追责，其余四类多为可自动修复的同步问题。
5. **灰度推进/冻结回滚**：新版本先在 1–2 台试点机台（canary）发布并用 SPC/VM/FDC 观察一个窗口，确认输出、稳定性、Cpk 无异常（放行判据）后，再按批次（如按线别/比例）逐步扩大，每批都有放行判据与观察窗，最后全量并更新 fleet baseline。过程中任一批出现 SPC 判异、FDC 异常或质量信号：立即**冻结**后续批次发布，已升级机台按受控流程**回滚**到上一 baseline golden（分发旧版+校验+切回+留痕），把影响限制在小范围；明确记录"已升到哪一批"的原子边界与在制 Lot 处置，避免无记录的半机群状态。
6. **审计报告回答的问题**：每台设备每个 PPID 的应然版本（baseline/目标矩阵）、实然版本与 hash、是否一致、最后核对时间；当前 ECN 版本由谁、何时、依据什么批准；何时分发/切换到哪台、谁/哪个系统执行、结果；有哪些例外（五类）、处置状态、Tampered 调查结论；是否存在未批准机台专属版本及授权凭据；灰度批次与回滚记录。即完整证明"全机群跑的都是批准版本、所有差异都受控可追溯"。
7. **受控例外 vs Tampered**：本质区别在"是否经过变更体系批准且可追溯"。受控机台专属例外是因客户特殊要求/特定工艺验证，经 ECN/偏差流程显式批准、记录在目标矩阵里、有有效期与责任人、其 body 也在 RMS 主库登记并有 hash，属于**已知、授权、可审计的差异**；Tampered 是设备本地内容与主库不符却没有任何批准记录，是**未知、未授权、绕过体系**的改动。前者是管理内的合法状态，后者是违规/事故；判断依据就是"目标矩阵里有没有这条经批准的记录、body hash 能否对到主库登记值"。

## 二、参考实现（net8.0）：机群配方治理

```csharp
namespace EapLab.Rms.Fleet;
public enum EqState{ Compliant,Missing,Outdated,Tampered,Corrupt,AuthorizedException }
public sealed class EqRecipe
{ public string Eq{get;}public string? LocalVer{get;set;}public bool HashMatch{get;set;}public bool Exists{get;set;}=true;
    public bool ApprovedException{get;set;}public EqRecipe(string eq){Eq=eq;} }
public sealed class FleetRecipeManager
{
    readonly Dictionary<string,EqRecipe> _eq=new();public string Baseline{get;private set;}
    public FleetRecipeManager(string baseline,IEnumerable<string> eqs){Baseline=baseline;foreach(var e in eqs)_eq[e]=new EqRecipe(e){LocalVer=baseline,HashMatch=true};}
    public void SetBaseline(string v){Baseline=v;} // ECN发布
    public EqState Classify(EqRecipe r)
    { if(r.ApprovedException)return EqState.AuthorizedException;
        if(!r.Exists)return EqState.Missing;
        if(r.LocalVer!=Baseline)return EqState.Outdated;
        if(!r.HashMatch)return EqState.Tampered;
        return EqState.Compliant; }
    public Dictionary<string,EqState> Sweep()=>_eq.ToDictionary(k=>k.Key,k=>Classify(k.Value));
    // 对一台分发: 忙则排队(教学用busy模拟), 成功则版本对齐且hash一致
    public bool Deploy(string eq,string ver,bool busy)
    { if(busy)return false; // 等安全点
        var r=_eq[eq];r.LocalVer=ver;r.HashMatch=true;r.Exists=true;return true; }
    // 灰度: 只对给定批次推进, 任一回滚信号则冻结并回滚该批
    public (bool advanced,List<string> rolled) StageRollout(IEnumerable<string> batch,string ver,Func<string,bool> canaryOk)
    { var rolled=new List<string>();
        foreach(var eq in batch){if(!canaryOk(eq)){foreach(var x in batch)Deploy(x,Baseline,true is false?false:false); // 冻结: 已升的回滚
                rolled.Add(eq);}
            else Deploy(eq,ver,false); }
        return(rolled.Count==0,rolled); }
}
```

## 三、机群治理流（手绘参考）
```
ECN发布新golden → 设fleet baseline → 目标矩阵(每台应然版本, 受控例外显式登记)
 灰度: 试点1-2台 → SPC/VM/FDC观察窗达标 → 分批扩大 → 全量 ; 异常冻结+受控回滚上一baseline
每台分发(忙则排队到安全点): Inquire→S7下载→hash校验→PP-Select回读→更新台账
周期/事件盘点Sweep: S7F19目录+S7F5回读hash → 五类例外
  Missing缺 / Outdated旧 → 自动分发 ; Corrupt损坏→重下(仍坏维修)
  Tampered同名hash变(未授权私改)→立即联锁+取证+质量调查追责(最高优先)
  AuthorizedException须有ECN/偏差批准记录, 否则整改
审计台账: 应然/实然版本,hash,一致性,ECN审批,分发时间/操作者,例外与回滚→全机群可追溯
```

## 四、今日易错点
1. 只保证单机一致就以为机群一致（漏升/旧版/私改造成机台差）。
2. 不区分应然（目标矩阵）与实然（设备实际）版本。
3. 设备忙时强制打断在制 run 分发切换（应排队到安全点）。
4. 把 Tampered 当普通同步问题自动覆盖（应联锁取证调查）。
5. 未经批准的机台版本被误当合法例外（要看授权记录与主库 hash）。
6. 新版本一次性全量推、无灰度无观察窗、异常不能快速回滚。
7. 灰度无原子批次边界，机群处于无记录的半新半旧状态。
8. 无机群台账/审计，回答不了"每台在跑哪版、谁批的、何时换的"。
