# W33 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何下载后还要校验**：S7F4=0 只证明下载那一刻设备写入并回了确认，之后本地副本仍可能变化或本来就有隐患：工程师从设备面板手动编辑、被旧作业覆盖、存储掉电/老化损坏、通信位错、或实际下错版本。质量体系要求"每次生产前都能证明设备上正在用的配方与已批准 golden 完全一致"，因此要在下载后、选择前、巡检时反复做一致性校验，把"曾经下对"升级为"此刻仍然对"。
2. **校验手段差别**：长度校验最快，能发现截断/多余字节，但同长度错误检不出；累加和/checksum（求和/异或）实现简单、能检出多数随机传输错，但检错能力有限且可能被刻意构造碰撞，不能防有意篡改；CRC 循环冗余校验对突发位错检出能力强，适合传输/存储检错；SHA-256 等加密哈希抗碰撞能力极强，任意一字节改变哈希都显著不同，既能检错也能防刻意篡改、满足合规审计。工程上配方一致性优先用强哈希（或厂商 CRC+哈希双保险），教学用长度+累加和演示原理。
3. **一致要素**：①身份一致——PPID 相同；②版本一致——版本号相同（同名不同版即不一致）；③长度一致——PPBODY 字节数相同；④内容一致——checksum/强哈希相同，高风险或仲裁场景用 S7F5/F6 回读 body 逐字节比对；⑤元数据一致——适用设备/腔、参数范围、格式版本匹配。全部满足才判一致，结论是确定的"一致/不一致"，不存在"差不多能用"。
4. **PPID 没变 hash 变了**：最可能是有人从设备面板/本地私自改动了配方内容却没改名字版本（也可能本地存储损坏，但概率与性质不同）。这是最危险的**违规变更/疑似篡改**：名义上跑批准配方、实际跑私改参数，会造成难以追溯的批量质量风险。处置：立即联锁禁止该配方被选择生产→回读 body 取证并比对差异→从 RMS 重下正确 golden 并复检→上报告警与质量/工程流程，追溯是哪台设备、何时、可能是谁改动，记录审计；重下后仍异常则判设备存储问题转维修。
5. **不一致闭环处置**：①检出不一致立即把该配方/设备置为不可选（EAP/设备联锁，先防止误生产）；②自动从 RMS 用 S7 重新下载正确版本（Day02 先 Inquire 后 Send），下载后重新做一致性校验；③若重下后仍不一致，判设备存储/通信硬件异常，禁止该设备/腔接相关产品、上报告警、开维修/偏差单；④全程审计留痕（期望与实际 hash、差异字节、设备、时间、处置结果、是否疑似人为）；⑤恢复一致并复核通过后才解除联锁、允许生产。与 E87/E94 前置门控一致：条件不满足不放片。
6. **校验时机/选前最后一关**：时机包括——下载后立即校验（作为进入 Distributed 的条件）；PP-Select 选择执行前强制校验；换 Lot/换班与定期巡检（S7F19/F20 盘点目录+关键配方 hash 轮询）；事件触发（设备重启/掉电恢复、本地配方编辑告警 S6F11）。PP-Select 前是最后一道关，因为它紧挨着真正生产：即使此前都一致，下载后到生产之间仍可能被改/损坏，选前再校验一次能确保"即将执行的这一份"就是 golden，把住不放任何不一致配方上线的最后闸门。
7. **overlay 写回主档的问题**：R2R overlay 是运行时叠加的临时补偿，设计上不进 recipe 主档 body（W31 Day03）。若错误地把 overlay 写回设备本地 recipe，主档 body 就被改变：①破坏 golden 与本地一致性，选前 hash 校验会报"配方被篡改"并联锁停机；②临时补偿被固化，作用域结束/换 Lot/换腔后仍残留，污染后续生产且难追溯；③不同腔把各自补偿写回同名配方，导致机台间配方发散、单一可信源失效。所以 overlay 必须只在运行内存叠加、绝不落主档，这样主档 body 恒定、一致性校验才成立。

## 二、参考实现（net8.0）：一致性比较与审计

```csharp
namespace EapLab.Rms.Compliance;
using EapLab.Rms.S7;
public sealed record CompareResult(bool Match,string Reason,string ExpectedCrc,string ActualCrc);
public static class RecipeComparer
{
    public static CompareResult Compare(PProgram golden,PProgram? local,bool localExists)
    { if(!localExists||local is null)return new(false,"missing","-","-");
        if(local.Ppid!=golden.Ppid)return new(false,"ppid mismatch",golden.Ppid,local.Ppid);
        if(local.Version!=golden.Version)return new(false,"version mismatch",golden.Version,local.Version);
        if(local.Body.Length!=golden.Body.Length)return new(false,"length mismatch",golden.Crc,local.Crc);
        string gc=golden.Crc,lc=local.Crc;
        if(gc!=lc)return new(false,"body hash mismatch",gc,lc);
        if(!local.Body.SequenceEqual(golden.Body))return new(false,"byte mismatch",gc,lc);
        return new(true,"match",gc,lc); }
}
public enum Disposition{ Blocked,Redownloaded,Escalated,Cleared }
public sealed record AuditEntry(string Eq,string Ppid,string Ver,string Reason,Disposition D,DateTime At);
public sealed class ComplianceAuditor
{
    public List<AuditEntry> Log{get;}=new();
    // 返回处置: 不一致先联锁, 尝试重下; 重下仍失败升级
    public Disposition Handle(string eq,PProgram golden,PProgram? local,bool exists,Func<bool> redownload)
    { var r=RecipeComparer.Compare(golden,local,exists);
        if(r.Match)return Disposition.Cleared;
        Log.Add(new AuditEntry(eq,golden.Ppid,golden.Version,r.Reason,Disposition.Blocked,DateTime.UtcNow));
        bool ok=redownload();
        if(!ok){Log.Add(new AuditEntry(eq,golden.Ppid,golden.Version,"redownload failed",Disposition.Escalated,DateTime.UtcNow));return Disposition.Escalated;}
        Log.Add(new AuditEntry(eq,golden.Ppid,golden.Version,"redownloaded",Disposition.Redownloaded,DateTime.UtcNow));
        return Disposition.Redownloaded; }
}
```

public class ComplianceTests

## 三、一致性处置闭环（手绘参考）
```
RMS golden(PPID+版本+body+强hash, 唯一可信源)
  │ S7F19/F20盘点 + S7F5/F6回读设备本地副本
  ▼
比对: PPID → 版本 → 长度 → checksum/SHA → (仲裁)逐字节 ; 全同才match
  不一致类型: 缺失 / 版本错配 / 长度或hash不符(损坏) / 同名hash变(疑似面板私改, 重点审计)
  ▼ 不一致
①联锁禁止选择生产(不放片, 同E87/E94门控) ②自动S7重下并复检
③仍不一致→禁该设备/腔+告警+维修/偏差单 ④全程审计(期望/实际hash,差异,设备,时间,人)
时机: 下载后 / PP-Select前(最后闸门) / 换班换Lot定期巡检 / 重启掉电/本地编辑事件
铁律: overlay运行时叠加绝不写回主档body, 否则golden被污染、触发篡改联锁、补偿残留发散
```

## 四、今日易错点
1. 认为 S7F4=0 就永久一致（下载后仍可能被改/损坏）。
2. 只比长度或弱 checksum，无法防刻意私改（应用强哈希）。
3. 只比 PPID 不比版本，同名旧版蒙混过关。
4. hash 不符直接重下不取证、不审计，漏掉人为篡改追溯。
5. 不一致却不先联锁，存在误生产窗口。
6. 重下失败不升级，反复盲目重试。
7. 漏掉 PP-Select 前最后一道校验。
8. 把 R2R overlay 写回本地 recipe，污染 golden 并触发误告警/补偿残留。
