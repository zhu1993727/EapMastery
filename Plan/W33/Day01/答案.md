# W33 · Day01 答案与参考实现

## 一、自测题标准答案
1. **核心价值/防的事故**：RMS 是配方的单一可信源与全生命周期管控平台，保证"任何设备、任何时间生产所执行的配方，都是经过验证审批的正确版本且与主库一致"。防止：工程师在设备面板私自改动本地配方导致的隐性漂移；跑错 PPID/旧版本/未批准配方；多台同型设备配方不一致造成机台差、批量良率事故；变更无审批无记录、出问题无法追溯"当时跑的是哪版参数"；以及配方丢失/混乱。手段是集中主库+版本化+审批发布+分发校验+变更受控+全程审计。
2. **构成/为何要版本**：recipe 含标识（PPID、版本、适用设备/腔/产品/工艺层）、若干 Step，每步一组工艺参数（温度、压力、功率、各气路流量、时间、端点条件等，带类型/单位/允许范围），以及配方体 body 与校验和。仅有 PPID 不够，因为同一配方会因工艺改进/ECN 不断演进，PPID 相同而内容不同；必须叠加版本号（及 checksum）才能唯一确定"这一版内容"，实现可追溯、可回滚、可校验设备副本与主库一致，否则无法区分新旧、无法定位质量问题对应哪版参数。
3. **生命周期与合法迁移**：Draft（编辑）→Validating（工程片验证）→PendingApproval（提交会签）→Released（批准发布成为 golden）→Distributed（经 S7 分发到设备并校验一致）→Active（被 PP-Select 选中执行）；变更时由 Released 派生出新版本回 Draft/走 ECN，旧版变 Superseded；任何版本可→Obsolete 废止。合法迁移如 Draft→Validating→PendingApproval→Released→Distributed→Active、Active→Distributed（换选）、Released→Superseded（被新版替代）、任意非废止→Obsolete。非法跳转须拒绝：Draft 直接 Active（未验证审批）、Obsolete→Active（废止配方不能复活生产）、未 Distributed 就 Active（设备上没有一致副本）等。
4. **golden/本地副本/生产前**：golden recipe 是 RMS 主库中经批准的权威版本（含完整 body 与 checksum）；设备本地副本是经 S7 下载、存在设备控制器里的缓存。二者是"主本与副本"关系。生产前必须校验设备本地副本的 checksum/body 与 golden 完全一致（Day03），一致才允许选择执行；不一致说明本地被改动或下载不完整，应禁止使用、重新下载并复检，从源头杜绝"名义选了某 PPID、实际参数被私改"。
5. **系统分工**：MES 按工单/产品/工艺路线决定"该用哪个 PPID/版本"并下达生产要求（管工艺路线与调度，不存配方内容）；RMS 存配方内容与版本、负责验证审批发布、提供合法副本与一致性校验（管配方本身）；EAP 承上启下，按 MES 要求从 RMS 取对应版本、经 SECS S7/远程命令下载并选择到设备、回读本地副本与执行状态（管传输与对接）；设备负责存储本地副本、按所选配方执行并回报实际所选 PPID/版本与状态。即 MES 定"用哪个"、RMS 保"内容对"、EAP 管"送到并核对"、设备"执行"。
6. **overlay 与主档关系**：RMS 主档变更是对被验证法定基线的永久性修改，必须走 ECN 评审、产生新版本并重新验证发布；R2R 的 overlay 不是主档变更——它是针对特定腔/Lot/片/run、带有效期的小幅临时补偿，运行时叠加在 Released 主档之上（effective=baseline⊕overlay），主档内容与版本不变、overlay 可撤销（W31 Day03）。关系：RMS 提供并校验不变的基线，R2R 在其之上做受控微调，overlay 必须声明基于哪个主档版本，主档一升级旧 overlay 即失效重算。这样既自动优化又不污染法定配方。
7. **Draft/Obsolete 不可生产**：Draft 处于编辑/未验证未审批状态，参数可能随时在变、未被证明能产出合格产品，直接生产等于拿产品做未授权实验；Obsolete 是已废止版本（被新版取代或因问题停用），其工艺已不被认可，再用会造成已知风险且不受支持。质量体系要求只有 Released（且已一致分发）的配方才能进入生产，状态机在编译/逻辑层面封死非法状态用于生产，是防错（poka-yoke）与合规审计的基础。

## 二、参考实现（net8.0）：Recipe 实体 + 生命周期状态机

```csharp
namespace EapLab.Rms;
public enum RcState{ Draft,Validating,PendingApproval,Released,Distributed,Active,Superseded,Obsolete }
public enum RcTrigger{ SubmitValidate,ValidateOk,SubmitApproval,Approve,Distribute,Select,Deselect,ReviseByEcn,Supersede,Retire,Reject }
public sealed record RecipeStep(string Name,Dictionary<string,double> Params);
public sealed class Recipe
{ public string Ppid{get;}public string Version{get;}public List<RecipeStep> Steps{get;}=new();
    public string Checksum{get;set;}="";public RcState State{get;internal set;}=RcState.Draft;
    public Recipe(string ppid,string ver){Ppid=ppid;Version=ver;} }

public sealed class RecipeLifecycle
{
    static readonly Dictionary<(RcState,RcTrigger),RcState> Map=new()
    { [(RcState.Draft,RcTrigger.SubmitValidate)]=RcState.Validating,
      [(RcState.Validating,RcTrigger.SubmitApproval)]=RcState.PendingApproval,
      [(RcState.Validating,RcTrigger.Reject)]=RcState.Draft,
      [(RcState.PendingApproval,RcTrigger.Approve)]=RcState.Released,
      [(RcState.PendingApproval,RcTrigger.Reject)]=RcState.Draft,
      [(RcState.Released,RcTrigger.Distribute)]=RcState.Distributed,
      [(RcState.Distributed,RcTrigger.Select)]=RcState.Active,
      [(RcState.Active,RcTrigger.Deselect)]=RcState.Distributed,
      [(RcState.Released,RcTrigger.ReviseByEcn)]=RcState.Draft,   // 派生新版
      [(RcState.Released,RcTrigger.Supersede)]=RcState.Superseded,
      [(RcState.Active,RcTrigger.Supersede)]=RcState.Superseded,
    };
    static RcState[] Any=new[]{RcState.Draft,RcState.Validating,RcState.PendingApproval,RcState.Released,RcState.Distributed,RcState.Active,RcState.Superseded};
    public bool CanFire(RcState s,RcTrigger t)=>Map.ContainsKey((s,t))||(t==RcTrigger.Retire&&Array.IndexOf(Any,s)>=0);
    public void Fire(Recipe r,RcTrigger t)
    { if(!CanFire(r.State,t))throw new InvalidOperationException($"{r.State}+{t} illegal");
        r.State=t==RcTrigger.Retire?RcState.Obsolete:Map[(r.State,t)]; }
    public bool IsProductionUsable(RcState s)=>s is RcState.Distributed or RcState.Active; // 已发布且一致分发
}
```

### xUnit
```csharp
public class LifecycleTests
{
    [Fact] public void 正常发布到激活()
    { var lc=new RecipeLifecycle();var r=new Recipe("ETCH_A","3");
      foreach(var t in new[]{RcTrigger.SubmitValidate,RcTrigger.ValidateOk,RcTrigger.SubmitApproval,RcTrigger.Approve,RcTrigger.Distribute,RcTrigger.Select})
      { if(t==RcTrigger.ValidateOk)continue; lc.Fire(r,t); }
      Assert.Equal(RcState.Active,r.State);Assert.True(lc.IsProductionUsable(r.State)); }
    [Fact] public void Draft不能直接激活()
    { var lc=new RecipeLifecycle();var r=new Recipe("R","1");
      Assert.Throws<InvalidOperationException>(()=>lc.Fire(r,RcTrigger.Select)); }
    [Fact] public void Obsolete不能复活生产()
    { var lc=new RecipeLifecycle();var r=new Recipe("R","1"){State=RcState.Obsolete};
      Assert.False(lc.CanFire(r.State,RcTrigger.Select)); }
    [Fact] public void 未分发不能选择()
    { var lc=new RecipeLifecycle();var r=new Recipe("R","1"){State=RcState.Released};
      Assert.False(lc.CanFire(r.State,RcTrigger.Select)); }
    [Fact] public void ECN修订走新版本_旧版被替代()
    { var lc=new RecipeLifecycle();var old=new Recipe("R","1"){State=RcState.Released};
      lc.Fire(old,RcTrigger.Supersede);Assert.Equal(RcState.Superseded,old.State);
      Assert.False(lc.IsProductionUsable(old.State)); }
    [Fact] public void 审批驳回回草稿()
    { var lc=new RecipeLifecycle();var r=new Recipe("R","1"){State=RcState.PendingApproval};
      lc.Fire(r,RcTrigger.Reject);Assert.Equal(RcState.Draft,r.State); }
}
```

## 三、生命周期与系统交互（手绘参考）
```
Draft→Validating(工程片)→PendingApproval(工艺/质量会签)→Released(golden主库)
      →Distributed(S7下载+checksum一致)→Active(PP-Select执行) ; 可Deselect回Distributed
变更: Released --ECN--> 新版本Draft重走流程; 旧版→Superseded ; 任意→Obsolete(留档)
非法一律拒绝: Draft→Active / Obsolete→Active / 未Distributed→Active
系统: MES定用哪个PPID版本 → RMS保内容对(主库/审批/版本) → EAP经S7送并核对 → 设备执行回读
golden(RMS主库,body+checksum) ←─生产前必须一致─ 设备本地副本(被私改即禁用以重下)
R2R: 不改主档, 在Released基线上叠overlay(作用域/有效期), 主档升级则overlay失效重算
```

## 四、今日易错点
1. 把 RMS 当单纯文件仓库（核心是版本/审批/一致性受控）。
2. 只有 PPID 没有版本，无法区分内容演进。
3. 允许 Draft/Obsolete/未分发配方直接生产。
4. 不校验设备本地副本与 golden 一致就跑。
5. 混淆 MES（定用哪个）与 RMS（保内容对）职责。
6. 把 R2R overlay 当主档变更（应叠加不改主档、走作用域而非 ECN）。
7. ECN 直接覆盖旧版（应派生新版本、旧版 Superseded 留档可追溯）。
8. 生命周期非法跳转不拦截，状态机形同虚设。
