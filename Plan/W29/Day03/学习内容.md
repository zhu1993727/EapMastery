## 二、背景知识（先读，40 分钟）

### 1. .proto 定义（教学）
```
message Sample { double at=1; double v=2; Quality q=3; }   // enum Quality{GOOD=0;BAD=1;...}
message Packet { string plan_id=1; uint64 seq=2; double from=3; double to=4;
                 uint64 gap=5; bool continuous=6; repeated Sample rows=7; repeated Sample events=8; }
service Eda { rpc Subscribe(PlanReq) returns (stream Packet); }   // 服务端流
```
- 每个字段后 `=数字` 是**字段编号（tag）**，一旦发布不可复用/改义；新增字段用新编号，旧客户端忽略未知字段——这就是 protobuf 向后/向前兼容机制（对应模型版本只增不删）。

### 2. protobuf 为何紧凑快速
- 无标签文本：XML 每个值带开闭标签和字段名，protobuf 只带小整数 tag + 原始二进制值。
- varint：小整数用 1 字节、按值变长；double 固定 8 字节；字符串/嵌套 message 为 length-delimited。
- 字段标签 = `(field_number << 3) | wire_type`；wire_type：0=varint，1=64bit，2=length-delimited，5=32bit。
- 强类型 + 代码生成，序列化/反序列化是字段读写而非文本解析，CPU 远低于 XML DOM。

### 3. gRPC 与 server streaming
- gRPC 四模式：一元(unary)、服务端流、客户端流、双向流。EDA 订阅=**服务端流**：客户端一次 Subscribe 请求，设备在同一 HTTP/2 流上持续 `await streamWriter.WriteAsync(packet)`，直到客户端取消或会话结束。
- HTTP/2 多路复用：一条 TCP 连接承载多个流，多订阅共享连接、头部压缩（HPACK），比每包建 HTTP 回调更省。
- 取消：客户端取消传 Context token，设备端捕获后停该订阅、释放（等价 Day01 Cancel，且 HTTP/2 流级隔离）。

### 4. Freeze III 与 E164
- E164 集中定义跨标准公共 protobuf 元素（公共 message/enum/Well-Known Names），各标准复用，保证互操作（W27 Day06）。你的 .proto 应 import 公共定义而非重复造。

### 5. 同设备 II/III 并存
- 内容协商：FreezeII 客户端走 Day02 XML 回调，FreezeIII 客户端走今天 gRPC 流；内核产出同一 Packet，编码器不同（W28 架构的直接收益）。

### 6. 工程落地
- 真实项目用 Grpc.AspNetCore + .proto 代码生成（或 protobuf-net）；今天为看清原理手写一个最小二进制编码器模拟 wire format，重点在理解"tag+varint+定长"和体积对比，不替代正式 protobuf 库。
