# W29 · Day03 答案与参考实现

## 一、自测题标准答案
1. **字段编号/兼容**：protobuf 二进制里字段靠编号(tag)识别而非字段名，编号一旦随版本发布就永久绑定该字段语义。不能改义（编号 3 从 double 改成别的类型，旧数据按旧类型解析就错）、不能复用（删掉的编号若给新字段，旧客户端发来的旧数据会把新字段误解析）。兼容做法是只增不删不改：新增字段用全新编号，旧客户端遇到不认识的编号当未知字段跳过（前向兼容），新客户端读不含新字段的旧数据时取默认值（后向兼容）。这与 EDA 模型"只增不删、改语义升版本"完全一致。
2. **标签公式/wire_type**：标签 = `(field_number << 3) | wire_type`，varint 编码。wire_type 标识值的编码形态：0=varint（int32/int64/enum/bool 变长整数）、1=64-bit（fixed64/double，固定 8 字节）、2=length-delimited（string/bytes/嵌套 message/repeated，先长度后内容）、5=32-bit（fixed32/float，固定 4 字节）。例如字段 1 是 double(wire_type1)，标签=(1<<3)|1=0x09；字段 2 是 string(wire_type2)，标签=(2<<3)|2=0x12。
3. **小和快的三原因**：①无字段名标签开销——XML 每个值重复带 `<fieldName>…</fieldName>` 文本，protobuf 只带 1 字节左右的数字 tag；②数值用二进制+varint——小整数 1 字节、double 原始 8 字节，不像 XML 把 350.5 编成文本字符；③强类型 schema 代码生成，序列化是按字段编号的二进制读写、反序列化按 tag 直接定位，无需 XML 的词法/语法解析、DOM 构建与字符串转数字，CPU 与内存分配都低得多；外加 HTTP/2 头部压缩与连接复用降低传输开销。
4. **gRPC 模式/持续返回/取消**：EDA 订阅对应**服务端流（server streaming）**：客户端发一次 Subscribe 请求（声明变量/触发/频率），设备在同一条 HTTP/2 流上多次 WriteAsync 持续返回 Packet（周期包/事件包），无需客户端轮询或反复建连。取消方式：客户端取消订阅时其 CancellationToken 触发，设备端在写循环里捕获到取消即停止该流、退订对应采集计划并释放缓冲；会话关闭也会结束其下所有流，等价于 Day01 的 Cancel/级联，且 HTTP/2 各流相互独立。
5. **HTTP/2 多路复用省在哪**：FreezeII 每包向回调端点发一次独立 HTTP/1 请求，反复 TCP/TLS 握手或至少重复请求行与头部、并发多请求还可能占多条连接；HTTP/2 在一条 TCP 连接上多路复用多个流（多个订阅/数据包），二进制分帧、头部用 HPACK 压缩只在首次/变更时传、请求与响应交错不阻塞，因此连接数、头部字节、握手与上下文切换都更少，高频多订阅下延迟和吞吐更优。
6. **II/III 并存**：靠 W28 的内核-编码分层与会话内容协商。设备内核对所有客户端产出同一个中性 Packet；会话建立时客户端声明支持的 Freeze 版本，ReportService 为 II 客户端绑定 SoapXmlEncoder+HTTP 回调（Day02），为 III 客户端绑定 ProtoEncoder+gRPC 流（今天），两条传输链独立、互不影响，从而同一设备同时服务存量 II 与新 III 客户端，平滑迁移。
7. **E164 在 III 的作用**：Freeze III 用 protobuf 重写编码后，跨标准需要共享的公共 message、enum、数据类型与 Well-Known Names 由 E164 集中定义，各标准（E120/E125/E132/E134 等）import 复用而非各自重复定义，保证字段编号、类型、语义在全标准范围内一致、互操作不冲突；它同时承载标准语义命名（WKN），让 protobuf 数据也具备跨厂商统一语义。

### 教学：最小 protobuf wire-format 编码器（看清 tag/varint/定长）
```csharp
namespace EapLab.Eda.Proto;
public sealed class ProtoWriter
{
    readonly MemoryStream _ms=new();
    // tag=(field<<3)|wire, varint
    public ProtoWriter Tag(int field,int wire){Varint(((ulong)field<<3)|(ulong)wire);return this;}
    public ProtoWriter Varint(ulong v){while(v>=0x80){_ms.WriteByte((byte)(v|0x80));v>>=7;}_ms.WriteByte((byte)v);return this;}
    public ProtoWriter Double(int field,double v){Tag(field,1);var b=BitConverter.GetBytes(v);if(!BitConverter.IsLittleEndian)Array.Reverse(b);_ms.Write(b,0,8);return this;}
    public ProtoWriter Bool(int field,bool v){Tag(field,0);Varint(v?1UL:0);return this;}
    public ProtoWriter Uint64(int field,ulong v){Tag(field,0);Varint(v);return this;}
    public ProtoWriter String(int field,string s){var b=System.Text.Encoding.UTF8.GetBytes(s);Tag(field,2);Varint((ulong)b.Length);_ms.Write(b,0,b.Length);return this;}
    public ProtoWriter Msg(int field,Action<ProtoWriter> inner){var sub=new ProtoWriter();inner(sub);var b=sub.Bytes();Tag(field,2);Varint((ulong)b.Length);_ms.Write(b,0,b.Length);return this;}
    public byte[] Bytes()=>_ms.ToArray();
}

public static class ProtoPacketEncoder
{
    static void Sample(ProtoWriter w,Pt p,int atF,int vF,int qF)
    {w.Double(atF,p.At).Double(vF,p.V).Uint64(qF,(ulong)p.Q);} // q当enum(varint)
    public static byte[] Encode(Packet p)
    { var w=new ProtoWriter().String(1,p.PlanId).Uint64(2,p.Seq).Uint64(5,p.Gap).Bool(6,p.Continuous);
        foreach(var r in p.Rows)w.Msg(7,s=>Sample(s,r,1,2,3));
        foreach(var e in p.Events)w.Msg(8,s=>Sample(s,e,1,2,3));
        return w.Bytes(); }
}
```

## 三、gRPC 订阅流（手绘参考）
```
FDC ─Subscribe(PlanReq)─▶ 设备 gRPC(HTTP/2)
        ◀══ stream Packet1,Packet2,... (一条HTTP/2流持续写) ══
取消: 客户端CancellationToken取消 / 会话关闭 → 停写、退订计划、释放缓冲(流级隔离)
多订阅: HTTP/2一条TCP多路复用多stream + HPACK头压缩(对比II每包独立HTTP/1回调)
编码: tag=(field<<3)|wire; varint小整数1B; double 8B; string/msg=长度+内容; 无字段名
兼容: 字段编号只增不删不改义, 旧客户端跳过未知tag, 新客户端读旧包取默认值
并存: 内核同一Packet, II→SoapXmlEncoder回调, III→ProtoEncoder流(E164公共proto)
```

## 四、今日易错点
1. 复用/改义已发布字段编号，破坏前后兼容。
2. 把 protobuf 当文本可读（二进制，靠 .proto/schema 解析）。
3. 记混 wire_type（double=1、string/嵌套=2、varint=0、float=5）。
4. 用 unary 一元调用做订阅（应 server streaming 持续推）。
5. 客户端取消后设备端不退出写循环、不退订（流泄漏）。
6. 以为 gRPC 每包建连（HTTP/2 多路复用一条连接多流）。
7. 重复定义公共 message/enum 而非 import E164。
8. 只比可读性不比体积，忽视 XML 在高频下的真实带宽/CPU 成本（要实测字节数）。
