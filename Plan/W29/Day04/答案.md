# W29 · Day04 答案与参考实现

## 一、自测题标准答案
1. **有界+DropOldest 而非 await 等待**：实时 trace 的价值在"最新且不拖垮设备"。若通道满时生产者 await 等待最慢的消费者，采样/扇出线程就会被它反压阻塞，导致所有订阅者和采样节拍一起变慢（一个慢客户端拖垮全局）。有界 Channel + DropOldest 让写入永不长时间阻塞：满了丢该订阅者最旧周期包、保最新波形并计数标 Gap，生产者立刻继续服务他人。等待模式只适合"绝不丢且消费者跟得上"的可靠事务（那是 GEM/事件通道的场景），实时周期流必须有界丢旧、隔离慢者。
2. **慢者不影响他人的实现**：扇出时为每个订阅者持有独立有界 Channel，生产者把同一 Packet 用 TryWrite 快速写入每个通道（写不进就按该通道策略丢它自己的旧包，绝不 await），各订阅者跑独立的 `await reader.ReadAllAsync(ct)` 消费/发送循环。于是慢消费者只让它自己的通道堆积/丢点，生产者写其他通道与采样主循环都不等待它，消费速度相互独立，实现故障与背压隔离。
3. **周期丢旧/事件不丢分开**：用两类通道——周期通道 CreateBounded(cap, DropOldest)，满了覆盖最旧并 Dropped++/标 Gap；事件/异常通道单独建，容量更大且 FullMode 用 Wait（或独立可靠队列），扇出时事件包只进事件通道、不参与周期覆盖，发送时事件优先出队。也可在订阅者内部分两个队列（cyc 可丢、evt 不丢），发送循环先排空 evt 再取 cyc，保证关键事件永不被周期点挤掉（W28 Day04 优先级在 async 下的落地）。
4. **backlog 增长含义/动作**：某订阅通道在飞量（写入-发送之差）单调增长，说明它消费/发送速率持续低于生产速率（网络慢或客户端处理慢），只靠丢旧会一直丢、数据无价值。保护动作：①先降该订阅频率（协商降采样率/增大 flush 批量）；②仍不收敛则主动断开该订阅/会话并级联清理，保设备与其他客户端；③全程指标告警。原则是局部降级、必要时切除最慢者，绝不让单点拖垮全局。
5. **重连从哪开始/不补历史**：重连是新会话/新订阅，从建立成功的当前时刻开始续传实时数据，断连期间不补。因为实时通道有界、断连期数据并未完整缓存，补历史会让实时连接背负重传、破坏实时性，且历史时序的完整存储本就是 EDC/历史数据库的职责（W34）：要历史走带时间范围的查询接口，实时流只负责"此刻往前"。这样实时面简单有界、历史面可靠完整，职责清晰。
6. **async 取消后不发**：为每个订阅建独立 CancellationTokenSource，消费循环 `await channel.Reader.ReadAllAsync(cts.Token)`；取消订阅或关会话时 cts.Cancel() 并 channel.Writer.TryComplete()，循环因 OperationCanceledException 退出，进入 finally 退订采集计划、释放通道；同时在扇出侧把该订阅从分发表移除（三处切断：不采样入队、不扇出、循环退出）。这样取消后不会再有新包进入、也不会有残留循环把旧包发出，保证"之后一字节不发"，且不影响其他订阅 token。
7. **压测指标/期望**：指标=吞吐（包/秒、采样点/秒、MB/s）、端到端延迟（采样时刻到发送的 P50/P95/P99）、丢点率、CPU%、GC 次数与托管内存、各通道 backlog。正常负载（N 客户端×目标频率×点数，在预算内）期望：P99 延迟稳定不发散、丢点率 0、CPU/内存平稳无持续增长、GC 少。人为制造一个慢消费者时期望：仅它自己出现丢点/Gap 与 backlog，其他订阅者零丢点、延迟不变，采样节拍稳定；超水位时新订阅被拒（429/503）或最慢者被降频/切除。用这些断言证明隔离与有界成立。

## 二、参考实现（net8.0）：有界扇出 Hub

```csharp
using System.Threading.Channels;
namespace EapLab.Eda.Hub;
public sealed class Subscription:IDisposable
{
    public string Id{get;}public Channel<Packet> Cyc{get;}public Channel<Packet> Evt{get;}
    public CancellationTokenSource Cts{get;}=new();public long Dropped{get;private set;}
    public Subscription(string id,int cap)
    { Id=id;
      Cyc=Channel.CreateBounded<Packet>(new BoundedChannelOptions(cap){FullMode=BoundedChannelFullMode.DropOldest,
        SingleReader=true,SingleWriter=true});
      Evt=Channel.CreateBounded<Packet>(new BoundedChannelOptions(cap){FullMode=BoundedChannelFullMode.Wait}); }
    public bool TryPush(Packet p,bool isEvent)
    { var ch=isEvent?Evt:Cyc;
        if(!ch.Writer.TryWrite(p)){if(!isEvent)Dropped++;return false;}return true; }
    public void Dispose(){Cts.Cancel();Cyc.Writer.TryComplete();Evt.Writer.TryComplete();Cts.Dispose();}
}

public sealed class SubscriptionHub
{
    readonly Dictionary<string,Subscription> _subs=new();public long TotalInFlight{get;private set;}
    readonly long _watermark;
    public SubscriptionHub(long watermark=1_000_000){_watermark=watermark;}
    public string? Add(string id,int cap)
    { lock(_subs){if(TotalInFlight>=_watermark)return"over watermark";_subs[id]=new Subscription(id,cap);TotalInFlight+=cap;return null;} }
    // fan-out: 周期包丢旧不阻塞; 事件包优先
    public void FanOut(Packet p,bool isEvent)
    { List<Subscription> snap;lock(_subs)snap=_subs.Values.ToList();
        foreach(var s in snap)s.TryPush(p,isEvent); }
    public long DroppedOf(string id)=>_subs[id].Dropped;
    public void Remove(string id){lock(_subs)if(_subs.Remove(id,out var s)){TotalInFlight-=s.Cyc.Reader.Count+s.Evt.Reader.Count;s.Dispose();}}
    public int Count{get{lock(_subs)return _subs.Count;}}
}
```

### xUnit（含并发与隔离）
```csharp
public class HubTests
{ static Packet Pk(long s)=>new(){Seq=s,PlanId="p",Rows=new[]{new Pt(0.01*s,1,Quality.Good)}};
    [Fact] public void 扇出到所有订阅()
    { var h=new SubscriptionHub();h.Add("a",10);h.Add("b",10);h.FanOut(Pk(1),false);
      Assert.True(h.Sub("a").Cyc.Reader.TryRead(out _));Assert.True(h.Sub("b").Cyc.Reader.TryRead(out _)); }
    [Fact] public void 慢者丢旧_他人不丢()
    { var h=new SubscriptionHub();h.Add("slow",2);h.Add("fast",100);
      for(int i=0;i<10;i++)h.FanOut(Pk(i),false); // slow不消费, 容量2
      Assert.Equal(8,h.DroppedOf("slow"));Assert.Equal(10,h.Sub("fast").Cyc.Reader.Count); }
    [Fact] public void 事件不被周期挤丢()
    { var h=new SubscriptionHub();h.Add("a",2);
      for(int i=0;i<5;i++)h.FanOut(Pk(i),false);h.FanOut(new Packet{Seq=99,Events=new(){new Pt(0,1,Quality.Good)}},true);
      Assert.True(h.Sub("a").Evt.Reader.TryRead(out var ev));Assert.Equal(99,ev.Seq); }
    [Fact] public void 超水位拒绝新订阅()
    { var h=new SubscriptionHub(watermark:5);h.Add("a",5);Assert.Equal("over watermark",h.Add("b",5)); }
    [Fact] public void 取消移除后不再收到()
    { var h=new SubscriptionHub();h.Add("a",10);h.Remove("a");h.FanOut(Pk(1),false);Assert.Equal(0,h.Count); }
    [Fact] public async Task 并发扇出线程安全()
    { var h=new SubscriptionHub();h.Add("a",100000);
      await Task.WhenAll(Enumerable.Range(0,4).Select(t=>Task.Run(()=>{for(int i=0;i<1000;i++)h.FanOut(Pk(i),false);})));
      Assert.Equal(4000,h.Sub("a").Cyc.Reader.Count); }
}
```
> 说明：为让测试可读，用 `Sub(id)` 取订阅（实现里加一个 lock 内的只读访问器）。真实工程消费侧为 `await sub.Cyc.Reader.ReadAllAsync(sub.Cts.Token)` 异步发送。

## 三、fan-out 背压（手绘参考）
```
采样生产者 ─Packet─▶ SubscriptionHub.FanOut
        ├─▶ subA.Cyc(有界DropOldest) ─独立async消费循环─▶ A客户端(慢:只丢自己,标Gap)
        ├─▶ subB.Cyc ... ─▶ B客户端(不受A影响)
        └─▶ 各sub.Evt(有界Wait/大容量,优先不丢)
关键: TryWrite不await慢者; 周期丢旧计数, 事件优先; backlog涨→降频→切除
断连: 停循环/清通道/达阈值级联; 重连=新订阅从当前续传, 不补历史(历史走EDC查询)
取消: 独立CTS Cancel+Complete+移出分发表(采样/扇出/循环三处切断), 之后零字节
水位: Σ通道容量上限, 超→429/503或降最慢者; 压测看吞吐/P50P95P99/丢点/CPU/GC/内存
```

## 四、今日易错点
1. 通道满时 await 慢消费者，反压拖垮采样与其他订阅。
2. 所有订阅共用一个队列，慢者阻塞全局（必须每订阅独立通道）。
3. 事件和周期同通道，事件被周期覆盖丢失。
4. 丢点不计数、不标 Gap，客户端不知数据不完整。
5. backlog 持续涨只丢不处理，不做降频/切除。
6. 重连试图在实时通道补全部历史（应走 EDC 查询）。
7. 取消只停消费循环、不移出分发表/不退订，仍有残留发送。
8. 不设全局水位，客户端数×容量把内存吃满；不压测 P99 与丢点率。
