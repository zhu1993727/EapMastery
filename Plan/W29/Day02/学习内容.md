# W29 · Day02（周二）Freeze II 回报：SOAP/XML 编码与客户端回调 + 抓包

> 建议时长：95 分钟。今天落地 Freeze II 的真实数据回报：把 Packet 序列化为符合 E138 公共组件风格的 XML，设备作为 HTTP 客户端主动 POST 到各客户端登记的回调端点，并用 Wireshark 抓 loopback HTTP 报文，亲眼看到"设备推数据"的过程与 XML 形态。

## 一、今日目标
1. 掌握 Freeze II 双向 Web Services 形态：客户端暴露回调端点，设备 POST XML 数据包。
2. 用 XmlWriter/XDocument 把中性 Packet 序列化为结构化 XML（时间窗、变量、采样行、质量、事件）。
3. 实现 CallbackTransport（ITransport 的 HTTP 版）：HttpClient 异步 POST、每客户端独立、超时与失败计数。
4. 用 Wireshark+Npcap 抓 127.0.0.1 HTTP，对照请求行/Header/Body 的 XML。
5. xUnit 验证 XML 结构正确、字段齐全、失败隔离。

## 二、背景知识（先读，35 分钟）

### 1. SOAP/XML 回报结构（教学模型，精确标签以 SEMI E138/原文为准）
- 一个数据包 XML 大致含：信封/消息头（会话、计划、包序号、起止时间）、变量列表、周期采样行（每行时间戳+各变量值+质量）、事件/异常快照段、Gap/连续性。
- 关键不是背标签名，而是理解"层级结构 + 自描述（每点带路径/单位/质量）+ 人可读"。
- 教学用简化 XML 表达语义；真实项目按现场 Freeze II 版本 Schema（E138 公共组件）生成。

### 2. 设备反向当客户端
- 客户端建会话时登记自己的回调 URL（Day01 /callback）；设备上报时角色反转——设备 EDA Server 作为 HTTP Client，向 FDC/YMS 的回调 URL POST。
- 每个目标一个独立 HttpClient/发送任务（IHttpClientFactory 管理，避免 socket 耗尽），失败只影响该目标。

### 3. XML 序列化要点
- 数值用不变文化（InvariantCulture，小数点用 "."）；时间用 ISO8601（UTC，带 Z）；质量枚举写成标准字符串；特殊字符转义。
- 用 XmlWriter 流式写大报文，避免字符串拼接占内存；高频时 XML 冗长是主要开销（为 Day03 protobuf 对比埋伏笔）。
- 单位/WKN 随字段携带（W28 Day02），客户端不依赖外部点表即可解析。

### 4. HTTP 细节
- POST，Content-Type: application/soap+xml 或 text/xml（按版本），Content-Length；客户端回 200/202 表示接收，非 2xx/超时即失败、计 FailStreak。
- 超时要短于 flush 周期，避免一个慢目标拖住发送循环；异步、不阻塞采样。

### 5. Wireshark 抓包步骤（复用 W02 环境）
1. 选 Npcap Loopback Adapter；过滤 `http`（或 tcp.port==回调端口）。
2. 启动设备服务与一个本地回调接收端（可用最小 API 起一个 /receive）。
3. 建会话、登记回调、订阅、等 1s flush，抓到 POST：看请求行、Host、Content-Type、Body 里的 XML 采样行。
4. Follow HTTP Stream 看完整往返；对比 XML 字节数（为 Day03 量体积）。

### 6. 与 GEM HSMS 抓包对照
- HSMS 是二进制帧（W02 抓过 4B 长度+10B 头+SECS-II body）；这里是文本 HTTP/XML，肉眼可读——直观对比两通道编码差异。
