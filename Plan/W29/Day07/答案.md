# W29 · Day07 答案

## 一、综合自测卷（7 题）参考答案
1. **宿主/后台/启停/错误码**：四端点=GET /metadata、POST/DELETE /sessions、POST /plans + pause/resume + DELETE、POST /callback；内核经 DI 单例注入，端点只做适配；SamplingService/ReportPumpService 用 PeriodicTimer+CT 后台 tick/flush。启动=建模型数据源→起后台循环→开监听；停止=停监听→停采样→停发送→级联撤会话→释放。错误码：401 认证、403 越权、404 无会话、422 超频超点、429/503 超配额、204 成功无内容。EDA 端口与 HSMS 分离可独立启停。
2. **II/III/兼容/小快**：FreezeII=设备向客户端 SOAP 回调 POST XML（XmlWriter 流式、ISO8601/InvariantCulture、IHttpClientFactory）；FreezeIII=.proto + gRPC server streaming 沿 HTTP/2 流持续推。字段编号只增不删不改义、旧端跳过未知 tag、新端读旧包取默认值即兼容。protobuf 小快因为无字段名只带 tag、数值二进制/varint、强类型代码生成免文本解析，加 HTTP/2 复用与 HPACK；实测同 Packet 体积通常不到 XML 一半。
3. **扇出隔离/断连取消**：每订阅独立有界 Channel，生产者 TryWrite 扇出、绝不 await 慢者；周期通道 DropOldest 丢旧计 Gap、事件独立通道优先不丢；backlog 持续涨先降频再切除。断连停循环清通道、达阈值级联撤会话；重连=新订阅从当前续传、不补历史（历史归 EDC 查询）；取消用独立 CTS+Complete+移出分发表，切断采样/扇出/消费三处，之后零字节。全局水位限总在飞量，压测看吞吐/P50P95P99/丢点/CPU/GC。
4. **同源/只读/控制优先**：GEM 与 EDA 共享唯一 FSM+数据源（一本账两视图），经同源事件出口拿同快照同戳；EDA 只注入 IReadOnlyDataBus（无 Publish/Command/Fire），编译期封死写路径，改参数一律走控制面（R2R 经 RMS/EAP→GEM 命令）。线程/端口/连接独立，EDA 有界背压不回灌 GEM，资源紧张时限/切数据面保控制面，GEM 事务不依赖 EDA 发送成功，EDA 可单独关停而生产不中断。
5. **marker 对齐/误差/后果**：GEM 状态迁移事件带同一单调时钟时间戳，作为 marker 注入 EDA 时间窗，在连续波形上标出 Step/Job/Hold 边界；事件时刻与最近采样点差应≤一个采样周期（100Hz 即≤10ms）。缺失或时钟不同源则无法按 Step/Recipe 分段，FDC 阈值分段失效、VM 特征切片错位、出现"切换前就异常"的假象，导致误判与错误归因。
6. **故障注入表现/断言**：数据面故障（FDC 慢/断）——仅 FDC 通道 DropOldest/Gap 或被判死级联撤订阅，GEM 作业链照常到 Completed、YMS 零丢点、GEM 命令延迟在阈值内；控制面故障（加工中 Alarm/Hold）——Hold 由设备 FSM 经控制面执行（S5F1 仅通知），EDA 不断、只读采到 Hold 现场供归因且无任何写动作。隔离断言五条：控制不受数据影响、故障只局限自身、控制动作不中断数据、EDA 无写接口、同源对齐≤一周期。
7. **升级 III 动什么**：不动——CEM 模型、自描述、授权会话、采集运行时、环形缓冲、打包 Packet、生命周期级联、GEM 通道与全部 xUnit；新增——.proto/E164 公共定义、ProtoPacketEncoder、gRPC server streaming 端点与 HTTP/2 承载，会话内容协商时为 III 客户端选 protobuf 路径，II 客户端继续走 XML 回调，同设备并存平滑迁移。这正是 W28"稳定内核 + 可插拔编码传输"的兑现。

## 二、费曼三问参考
- **为何 EDA 只读不控**：EDA 同时被 FDC/YMS/R2R 等多方连接、定位是高频数据采集，若任何一方能经它写参数/Hold，就绕过了 GEM 控制状态机、命令授权和安全联锁，多方都能改设备、控制不确定也不安全；所以写操作收敛到唯一控制面（GEM/RMS），EDA 用只读接口在编译期就无法写。
- **慢消费者为何不能反压采样**：采样要按固定节拍保真地记录所有客户端共享的波形，若写某客户端时 await 等它消费，它一慢，采样节拍和其他客户端全被拖住；正确做法是每客户端有界通道、写不进就丢它自己的旧点标 Gap，采样与他人继续前进，把故障锁在该客户端内。
- **II 怎么平滑走到 III**：业务内核产出与编码无关的中性 Packet，II 用 XML 回调、III 用 protobuf/gRPC 流，只是两个可插拔编码器与传输；会话建立时协商版本、按客户端选择，于是老客户端继续 XML、新客户端上 protobuf，无需停机重写、无需二选一，逐步迁移。

## 四、W29 全周易错点总清单
1. 端点写业务、内核每请求 new（应单例、逻辑在内核）。
2. 后台循环无 CT、停服停不下或写已释放资源；启停顺序错。
3. 内部异常直接 500，不做错误码映射；EDA 与 HSMS 端口不分离。
4. XML 用 DOM/字符串拼接、每点重复路径单位、new HttpClient 致 socket 耗尽。
5. 数值本地文化、时间不带时区；数据点不带单位/质量。
6. 复用/改义 protobuf 字段编号；用 unary 做订阅；以为 gRPC 每包建连。
7. 通道满 await 慢者反压全局；周期/事件同通道导致事件被覆盖。
8. 重连在实时通道补历史；取消不移出分发表/不退订。
9. 不设全局水位、不压测 P99/丢点。
10. 两通道各存状态、EDA 拿可写接口、GEM 等 EDA 发送结果。
11. R2R/APC 经 EDA 写参数（绕过状态机联锁）。
12. 事件 marker 缺失或时钟不同源，trace 无法按 Step 分段。
13. 资源紧张优先保数据吞吐（应控制可靠优先）。
14. 只单测各自正常，不做"一方故障另一方正常"的交叉隔离断言。
