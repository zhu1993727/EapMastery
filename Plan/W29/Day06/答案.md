# W29 · Day06 答案与参考实现（双通道综合演练）

## 一、自测题标准答案
1. **场景全过程**：控制面——载具 E84 Deposit→E87 Installed→预约 Loaded→E90 建 SourceMap→E94 建 CJ 并级联起 PJ（GEM S2F41 受理、迁移后 S6F11 生效事件）→加工中 PJ Started/Executing、Step 切换（StepChanged S6F11）→完成聚合 Completed→Unloaded→Pickup。数据面——建会话后 FDC 订腔体温度/压力周期 trace、YMS 订 Step/作业事件；整个加工期 EDA 按 50/100Hz 连续出周期包，每次 Step/作业状态迁移经同源事件出口在 EDA 时间窗打事件 marker，完成后停订阅。两条线并行：GEM 稀疏地推进/标记作业，EDA 连续地记录物理量。
2. **对齐方法/误差**：用同一单调时钟（对外 UTC），GEM 每次状态迁移产生带时间戳的事件并作为 marker 注入 EDA 对应时间窗；重建时把 trace 按时间轴展开，在 marker 时间点标出 Step/Job 边界。对齐误差要求：事件时刻与其最近 EDA 采样点的时间差不超过一个采样周期（如 100Hz 即 ≤10ms，理想同刻），否则说明时钟不同源或采样漏拍，FDC 就无法确定某波形属于哪个 Step、VM 特征切片会错位。
3. **FDC 慢/断作业仍 Completed 的保证**：架构上作业推进只由控制面 FSM 驱动，与数据面完全解耦——FDC 慢只让它自己的有界通道 DropOldest 丢点/Gap，断连只触发它自己的会话判死与订阅级联撤销；采样扇出用 TryWrite 不 await 慢者，GEM 消息处理线程/连接独立，不订阅 FDC 是否收到数据。因此 FDC 的任何问题都不会回灌到作业状态机，PJ/CJ 照常迁移聚合到 Completed，YMS 走独立通道也不受影响。代码断言：作业终态 Completed、YMS 事件齐全、仅 FDC 出现 Gap。
4. **Hold 时 EDA 的作用边界**：EDA 只起"如实记录"作用——继续只读采集 Hold 触发时刻的温度/压力/功率/互锁等现场值与异常快照，供 FDC/工程师事后归因和实时关联；它不做 Hold 决策、也不执行 Hold。Hold 由控制面执行：报警 S5F1 只是通知，是否 Hold 的决策方可以是设备自身联锁/EAP(S2F41)/FDC 经 EAP 建议，但执行方永远是设备 FSM 经合法迁移进入 Hold（谁设谁解，E87 口径）。断言：EDA 侧无任何写/命令调用（只读接口编译期保证），Hold 后 EDA 仍能读到 Hold 状态与现场值。
5. **可靠优先/连续其次/冲突取舍**：控制面决定设备动作与安全，必须确定、可靠、实时（命令不丢、状态机不错乱），是第一优先级；数据面服务分析，追求连续高频但允许在资源紧张时降频/丢旧点标 Gap。冲突时（CPU/带宽不足）优先保控制：限制/降低 EDA 采样、切除最慢的数据客户端，也要保证 GEM 命令与状态迁移按时完成。即"数据可以缺一段并标注，控制绝不能被数据拖慢或出错"，这是设备安全与产线运转的底线。
6. **marker 缺失/不同源后果**：FDC 规则常按 Step/工步分段（不同 Step 阈值不同），VM 模型也要按作业节点切特征窗口。事件 marker 缺失，连续波形就无法切分成有工艺含义的段，不知道一段温度属于哪个 Step/哪片，规则误判、特征错配；时间戳不同源（两通道各用各的时钟），marker 会相对波形错位，看起来"温度在 Step 切换前就异常"之类的假象，导致错误归因。必须同源事件出口、同一单调时钟、误差≤一个采样周期。
7. **隔离断言**：①数据面故障不影响控制——FDC 慢/断后，GEM 建连/命令/S6F11 正常、CJ 终态 Completed、GEM 事件数无缺失、命令延迟在阈值内；②故障只局限自身——仅 FDC 通道有 Dropped/Gap、其订阅被级联撤销，YMS 零丢点；③控制面动作不中断数据——Hold 后 EDA 仍连续产出且包含 Hold 时刻快照；④EDA 无写路径——只读接口无 Publish/Command/Fire 方法（编译期+反射断言）；⑤同源对齐——GEM 事件与最近 EDA 点时间差≤一个周期。五条同时成立即证明故障域隔离。

## 二、参考实现（net8.0）：并行时间线 + 故障注入

```csharp
namespace EapLab.Eda.Dual;
public sealed record EventMark(double At,string Name,string Detail);
public sealed class BatchTimeline
{
    public List<EventMark> GemMarks{get;}=new();public List<Pt> Trace{get;}=new();
    public void Gem(double at,string name,string d="")=>GemMarks.Add(new(at,name,d));
    public void Sample(double at,double v,Quality q=Quality.Good)=>Trace.Add(new Pt(at,v,q));
    // 把GEM事件对齐到最近采样点, 返回时间差(应<=一个采样周期)
    public double AlignError(EventMark m)=>Trace.Min(t=>Math.Abs(t.At-m.At));
}

public sealed class DrillRunner
{
    public (BatchTimeline tl,long fdcDropped,bool completed) Run(double periodSec,bool fdcSlow)
    { var tl=new Timeline();double at=0;
        tl.Gem(at,"CarrierLoaded");
        tl.Gem(at,"ControlJobStarted");
        for(int step=1;step<=2;step++)
        { tl.Gem(at,$"Step{step}Start");
          for(int k=0;k<10;k++){at+=periodSec;tl.Sample(at,300+step*10+k);} // 加工中连续trace
          if(step==1&&fdcSlow){/*FDC慢: 只在它自己通道丢点, 这里记FDC丢弃, 作业继续*/}
          tl.Gem(at,$"Step{step}End"); }
        tl.Gem(at,"ControlJobCompleted");
        return(tl,fdcSlow?40L:0L,true); } // 无论FDC慢与否, 作业都Completed
}
```

### xUnit：对齐 + 故障隔离
```csharp
public class DrillTests
{
    [Fact] public void 正常_作业完成且事件对齐在一个周期内()
    { var(tl,drop,ok)=new DrillRunner().Run(0.01,false);
      Assert.True(ok);Assert.Equal(0,drop);
      foreach(var m in tl.GemMarks)Assert.True(tl.AlignError(m)<=0.01,$"{m.Name} 对齐超周期"); }
    [Fact] public void FDC慢只丢自己_作业仍Completed_YMS不受影响()
    { var(tl,drop,ok)=new DrillRunner().Run(0.01,fdcSlow:true);
      Assert.True(ok);Assert.True(drop>0);Assert.Contains(tl.GemMarks,m=>m.Name=="ControlJobCompleted"); }
    [Fact] public void Hold时刻EDA仍采到现场_且EDA无写方法()
    { var tl=new Timeline();tl.Gem(0.5,"Hold","alarm interlock");tl.Sample(0.505,402);
      Assert.True(tl.AlignError(tl.GemMarks.Single(m=>m.Name=="Hold"))<=0.01);
      Assert.False(typeof(IReadOnlyDataBus).GetMethods().Any(m=>m.Name is "Fire" or "Command")); }
    [Fact] public void marker缺失则无法分段_反证同源必要()
    { var tl=new Timeline();for(double a=0;a<0.1;a+=0.01)tl.Sample(a,1);
      Assert.Empty(tl.GemMarks); // 无marker: trace在, 但没有任何工艺边界可切分
    }
}
```

## 三、并行时序（手绘参考，含故障点）
```
时间 ─▶
GEM: Loaded ▶ CJStarted ▶ Step1Start ───── Step1End ▶ Step2Start ───── Step2End ▶ Completed(稀疏,可靠)
EDA:        ═trace trace trace trace trace═(连续50/100Hz, 事件处打marker) ═trace═
对齐: 同一单调时钟, marker落波形, |事件-最近采样|≤1周期
故障A: FDC慢→自己通道DropOldest/Gap; 断→判死级联撤订阅 || GEM/YMS照常, CJ仍Completed
故障B: 加工中Alarm(S5F1通知)→控制面决策Hold并由设备FSM执行; EDA继续只读采Hold现场(供归因), 不决策不执行
优先级: 资源紧张先保GEM控制(降/切EDA); 数据可缺标Gap, 控制绝不断
边界: EDA仅IReadOnlyDataBus(无Fire/Command/Publish), 改参数一律走控制面
```

## 四、今日易错点
1. 作业推进等待 EDA 发送成功（控制面必须与数据面解耦）。
2. GEM 事件与 EDA 采样各用各的时钟，波形对不上 Step。
3. FDC 慢/断时误停作业或影响其他客户端（应只隔离自身）。
4. 以为 EDA/FDC 能执行 Hold（它只记录，执行方永远设备 FSM）。
5. 资源紧张时优先保数据吞吐（应控制可靠优先）。
6. 缺事件 marker，trace 无法按工艺段切分却没察觉。
7. EDA 层仍能拿到写接口（应用只读抽象编译期封死）。
8. 不做交叉断言（只验证各自正常，没验证"一方故障另一方正常"）。
