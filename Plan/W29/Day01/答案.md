# W29 · Day01 答案与参考实现

## 一、自测题标准答案
1. **为何端点不写业务/分层**：端点职责是传输适配（解析 HTTP 请求、模型绑定、调用内核、把结果/错误映射成 HTTP 响应），采样调度、授权、三触发、背压、级联是长期稳定且要被 xUnit 覆盖的业务内核（W28 已实现并与传输无关）。若写进 Controller，业务就和 HTTP 框架耦合、无法脱离网络单测、换 gRPC/Freeze III 要重写、还会在请求线程里做高频重活拖垮服务。分层=ASP.NET Core 宿主（端点+后台服务+DI）只调 EdaServer 内核，内核不认识 HTTP。
2. **四类端点/状态码**：①`GET /metadata` 取自描述，200（未认证 401、越权裁剪）；②`POST /sessions` 认证授权建会话 201 返回 sessionId，凭证错 401、达会话上限 503；`DELETE /sessions/{id}` 关闭级联 204，不存在 404；③`POST /sessions/{id}/plans` 建计划 201，越权 403、超频/超点 422、超配额 429；`POST .../plans/{pid}/pause|resume` 200、`DELETE .../plans/{pid}` 204；④`POST /sessions/{id}/callback` 登记 FreezeII 回调地址 200。统一错误体 `{code,message}`。
3. **请求线程 vs 后台线程**：请求线程（线程池）处理建会话/建计划/暂停恢复等低频控制操作，只对内核注册表做增删改，快速返回；采样后台线程（SamplingService）按基础节拍高频执行 Tick 读值入环形缓冲，上报后台线程定时 Flush、编码、发送。二者通过内核里线程安全的计划注册表（不可变快照）与有界缓冲协作：请求改注册表、后台读快照采样，不在请求里等待或执行采样，互不阻塞。
4. **定节拍/响应停止**：在 `ExecuteAsync(CancellationToken ct)` 内用 `PeriodicTimer(period)` 或 `Task.Delay(period,ct)` 循环，每到一个节拍 `await timer.WaitForNextTickAsync(ct)` 后调一次内核 Tick/Flush；把 ct 传入所有异步操作，停止时 ct 取消会跳出循环、走 finally 释放。不能用无 ct 的 while+Sleep（无法及时停、停止时仍写资源），也不要在后台服务里用阻塞式 Thread.Sleep 占线程。
5. **启停顺序/乱序后果**：启动顺序=先建设备模型/数据源/内核（恢复状态）→启动采样与上报后台循环→最后开始监听端口接客，避免请求到达时内核未就绪（空引用/订阅失败）。停止顺序=先停止接收新请求/连接→通知 ct 停采样 tick→停上报 flush 并尽量排空→对所有会话级联撤销计划、退订、清队列、关连接→释放缓冲资源。乱序（先释放资源后停采样）会 ObjectDisposed/向已释放缓冲写入；先关监听但不级联会留僵尸会话；采样没停就销毁数据源会读到撕裂状态。
6. **错误→状态码**：未认证/凭证错→401 Unauthorized；已认证但访问可见域外路径（越权）→403 Forbidden；会话 id 不存在→404 NotFound；超频/超点数/参数语义非法（量纲、触发与变量类型不符）→422 Unprocessable Entity；达到最大会话/总采样配额/发送水位→429 Too Many Requests 或 503 Service Unavailable（带 Retry-After）；正常无内容（关闭/删除成功）→204。内核返回错误字符串，端点集中映射，避免把内部异常直接抛成 500。
7. **端口分离原因**：GEM/HSMS 是控制面（TCP 长连接、一对一、控制事务，要求确定与实时），EDA 是数据面（HTTP/gRPC、多客户端、高频只读）。端口/进程/线程资源分离后，EDA 高并发或某客户端异常不会占用/拖垮 HSMS 监听，可独立启停 EDA 而不中断设备控制，也便于独立做 TLS、限流、防火墙策略与扩容；这是 Day01"通道隔离、EDA 不控"在部署层的落实。

## 二、参考实现（net8.0）

### Program.cs（最小 API + DI + 后台服务）
```csharp
var builder=WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<EdaServer>();                 // 内核单例(模型/数据源/运行时)
builder.Services.AddHostedService<SamplingService>();       // 集中采样+flush后台服务
builder.Services.AddHostedService<ReportPumpService>();     // 上报发送循环
var app=builder.Build();

// 1 自描述(按会话裁剪, 教学: 直接返回模型元数据)
app.MapGet("/metadata",(EdaServer s,string? session)=>Results.Ok(s.Describe(session)));

// 2 会话
app.MapPost("/sessions",(EdaServer s,ConnectReq r)=>{
    var err=s.Connect(r.SessionId,r.Cred,r.Role,r.Freeze,GrantFor);
    return err is null?Results.Created($"/sessions/{r.SessionId}",new{r.SessionId}):MapErr(err);});
app.MapDelete("/sessions/{id}",(EdaServer s,string id)=>{ s.CloseSession(id);return Results.NoContent();});

// 3 采集计划CRUD
app.MapPost("/sessions/{id}/plans",(EdaServer s,string id,PlanReq p)=>{
    var err=s.Subscribe(id,p.PlanId,p.Trigger,p.Tags,p.Hz);
    return err is null?Results.Created("",null):MapErr(err);});
app.MapPost("/sessions/{id}/plans/{pid}/{act}",(EdaServer s,string id,string pid,string act)=>{
    if(act=="pause")s.Runtime.Pause(pid);else if(act=="resume")s.Runtime.Resume(pid);return Results.Ok();});
app.MapDelete("/sessions/{id}/plans/{pid}",(EdaServer s,string pid)=>{s.Runtime.Cancel(pid);return Results.NoContent();});

// 4 FreezeII 回调登记
app.MapPost("/sessions/{id}/callback",(string id,CallbackReq c,EdaServer s)=>{s.Reports.SetCallback(id,c.Url);return Results.Ok();});
app.Run();

{"auth fail"=>"结果".Length==0?Results.Problem():Results.Json(new{code=e},statusCode:401),
 "out of scope"=>Results.Json(new{code=e},statusCode:403),

 "hz over grant" or "tag over grant"=>Results.Json(new{code=e},statusCode:422),
 "session limit"=>Results.Json(new{code=e},statusCode:429),_=>Results.Json(new{code=e},statusCode:400)};
static Grant GrantFor(string role)=>new(){VisiblePrefix=new(){"/Equipment"},MaxHz=100,MaxTags=50000};
```

### 后台服务
```csharp
public sealed class SamplingService:BackgroundService
{
    readonly EdaServer _s;readonly PeriodicTimer _t=new(TimeSpan.FromMilliseconds(10)); // 基础节拍10ms=100Hz
    public SamplingService(EdaServer s){_s=s;}double _at;
    protected override async Task ExecuteAsync(CancellationToken ct)
    { while(await _t.WaitForNextTickAsync(ct)){ _at+=0.01;_s.Tick(_at);} }
}
public sealed class ReportPumpService:BackgroundService
{
    readonly EdaServer _s;public ReportPumpService(EdaServer s){_s=s;}
    protected override async Task ExecuteAsync(CancellationToken ct)
    { using var t=new PeriodicTimer(TimeSpan.FromMilliseconds(1000)); // 1s flush
        while(await t.WaitForNextTickAsync(ct)) foreach(var id in _s.ActiveSessions)
        { var pk=_s.FlushNext(id);if(pk!=null)_s.Push(id,pk);} }
}
```

## 三、线程协作（手绘参考）
```
HTTP线程池(低频控制): POST /sessions /plans → 只改内核注册表(线程安全/快照), 快速响应
后台SamplingService: PeriodicTimer基础tick → EdaServer.Tick → 采样入环形缓冲
后台ReportPumpService: 定时Flush → Packet → 编码 → 每会话发送队列 → 网络
启动: 建模型/数据源 → 起后台循环 → 开监听 ; 停止: 停监听→停采样→停发送→级联撤会话→释放
错误映射: 401认证/403越权/404无会话/422超频超点/429配额/204成功无内容
端口: EDA(如5100,HTTP/gRPC) 与 GEM HSMS(5000) 分离, 独立启停, 数据面不拖垮控制面
原则: 端点只适配传输, 业务全在可单测的EdaServer内核
```

## 四、今日易错点
1. 把采样/授权逻辑写进 Controller，与 HTTP 耦合并占用请求线程。
2. 内核被当成每次请求 new（应单例，否则模型/数据源/会话全丢）。
3. while+Thread.Sleep 无 CancellationToken，停服停不下来、停时写已释放资源。
4. 先开监听后建内核，请求早到导致空引用。
5. 停止不级联撤会话，留僵尸计划/连接。
6. 内部异常直接 500，不做内核错误到 HTTP 状态码的映射。
7. 请求线程里阻塞等采样结果，高频时线程池耗尽。
8. EDA 与 HSMS 共用端口/线程，数据面异常波及控制面。
