# W29 · Day01（周一）用 ASP.NET Core 承载真实 Interface-A 服务（最小 API + 后台服务）

> 建议时长：100 分钟。本周把 W28 的内存 EDA 内核接到真实网络。第一课用 ASP.NET Core 最小 Web API 搭出 EDA 服务骨架：依赖注入注册内核、设计四类 HTTP 端点、用 BackgroundService 跑集中采样与上报、优雅启停。今天重点是"宿主怎么承载内核"，业务逻辑仍复用 W28。

## 一、今日目标
1. 建立 ASP.NET Core 最小 API 工程结构，把 EdaServer 内核通过 DI 注册为单例。
2. 设计 EDA 四类端点：自描述 GET、会话建立/关闭、采集计划 CRUD、（FreezeII）回报回调地址登记。
3. 用 BackgroundService 承载集中采样 tick 与上报 flush 循环，理解请求线程与后台线程协作。
4. 实现优雅启停（CancellationToken、停止采样、级联清理会话）。
5. 用 WebApplicationFactory 对端点做集成测试；xUnit 验证。

## 二、背景知识（先读，35 分钟）

### 1. 宿主与内核分层（延续 W28）
- 内核（建模/授权/采样/运行时/上报）与传输无关、可单测；ASP.NET Core 只是"宿主+传输适配"：HTTP 请求进来→调内核方法→把结果序列化返回。绝不把采样/状态机逻辑写进端点 Controller。
- DI 容器把 EdaServer（单例，持有设备模型与数据源）、采样后台服务、编码器注册进去；端点通过构造注入拿到内核。

### 2. 四类端点设计（REST 风格教学映射）
- `GET /metadata`（或 /selfdescription）：返回 EqSD（按会话授权裁剪）。
- `POST /sessions`：认证授权建会话，返回 sessionId；`DELETE /sessions/{id}`：关闭并级联撤销。
- `POST /sessions/{id}/plans`：建采集计划（变量/触发/频率/上报条件/回调地址）；`POST .../plans/{pid}/pause|resume`、`DELETE .../plans/{pid}`。
- `POST /callback`（FreezeII）：登记客户端数据接收端点（设备往这里 POST XML）；FreezeIII 则用 gRPC 流（Day03）。
- 所有写操作先过内核授权闸门，端点只做模型绑定、状态码映射（越权→403、超频→422/400、会话不存在→404、超配额→429/503）。

### 3. 后台服务 BackgroundService
- `SamplingService : BackgroundService`，在 `ExecuteAsync(ct)` 里按基础节拍周期循环：到点调 `server.Tick(monoNow)`；另一个循环/定时器按 flush 间隔调 `Flush` 并交给 ReportService 发送。
- 请求线程（建会话/订阅）只改内核注册表；后台线程做高频采样与发送，二者通过内核内的线程安全集合/快照协作（W28 Day04 已处理并发）。
- 关键：后台循环用 `Task.Delay(period, ct)` 或 PeriodicTimer 定节拍，捕获 ct 以响应停止；绝不在请求里阻塞等待采样。

### 4. 优雅启停与资源释放
- 启动：先建设备模型/数据源、恢复必要状态，再开放端口监听（就绪后才接客）。
- 停止：收到 IHostApplicationLifetime.ApplicationStopping/ct 取消→停采样 tick→停发送→对所有会话做级联撤销→释放缓冲/连接。避免停止过程中还在写已释放资源（ObjectDisposed）。

### 5. 状态码与错误契约、日志
- 统一错误返回体（code/message），与内核错误字符串映射；结构化日志记录连接/订阅/拒绝/断连/级联，便于现场排查（谁、何时、订了什么、为何拒）。

### 6. 工程与端口
- EDA 端口与 GEM(HSMS 5000 演示)分离（如 5100），可独立启停；HTTPS/TLS 配置（现场安全，先 HTTP 跑通再上 TLS）。
- 目标框架 net8.0；Grpc/protobuf Day03 再加，今天先最小 API。
