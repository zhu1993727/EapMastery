# W29 · Day05 答案与参考实现

## 一、自测题标准答案
1. **共享又不耦合**：共享发生在最底层——唯一领域 FSM（E30/E87/E90/E40/E94）与唯一数据源 EquipmentDataBus，两通道都只从这里读状态/值、订阅同一个领域事件出口；不耦合体现在：GEM 控制处理器与 EDA 服务各自独立组件、独立端口（5000/5100）、独立线程与连接、独立生命周期，彼此不持有引用、不互相 await、不共享可变队列。即"共享只读的事实源，隔离各自的传输与资源"，状态只有一本账，通道是这本账的两个不同视图（GEM 可控视图、EDA 只读视图）。
2. **同源同值同戳证明**：让一次 FSM 状态迁移经唯一事件出口生成一个带单调时间戳的快照，GEM 侧用该快照组 S6F11，EDA 侧在同一时刻的采样/ECV 也读同一快照；测试断言：两边变量值相等、时间戳相等、作业/状态一致（如 StepChanged 时 GEM 报告的 CurrentStep 与 EDA 事件快照的 StepId 相同）。若值或戳不同，即违反唯一数据源/唯一时钟（存在第二份缓存、各自取时、单位不统一），按 W28 Day06 的排查路径定位。
3. **类型系统保证只读**：不给 EDA 层暴露可写数据源，只注入只读抽象——如 `IReadOnlyDataBus`（只有 Read/Snapshot/订阅事件，无 Publish/Set）、FSM 的只读接口（只有 CurrentState/查询，无 Fire）。EDA 的采样器、运行时、上报层方法签名只接受只读接口，编译期就无法调用写方法/触发迁移；写方法只对 GEM 控制处理器开放。这样"EDA 只读"由编译器强制，而非靠代码评审约定，杜绝误写。
4. **APC/R2R 走哪条通道**：必须走控制面——R2R 计算出的参数调整经 EAP/Host 通过 GEM 远程命令（S2F41）/OSS(S15) 或经 RMS 配方管理受控下发，由设备 FSM 经 Guard 合法迁移/参数校验后执行（且 R2R 只下 overlay 不直接改 recipe 主档，W31/W33）。不能走 EDA，因为 EDA 是多客户端、只读、无控制授权与状态机联锁的数据面，若允许经它写参数，就绕过了控制状态机、命令授权与安全联锁，多个数据分析方都可能改设备，控制不确定也不安全。
5. **EDA 满载不拖垮 GEM 的机制**：①线程/任务池分离，GEM 消息处理不与 EDA 采样/上报共用工作线程；②EDA 有界通道+DropOldest 背压，慢客户端只在 EDA 内部丢点，绝不向 GEM 循环传导阻塞；③采样集中调度且有全局频率/CPU 预算与上限，超了降频/拒绝而非无限吃 CPU；④资源优先级，CPU 紧张时保证控制面调度；⑤端口/连接独立，EDA 连接打满不占 HSMS 连接。测试上制造 EDA 满载+慢客户端，断言 GEM 建连与 S2F41→S6F11 响应延迟仍在阈值内。
6. **GEM 不依赖 EDA 发送结果**：GEM 处理的是控制/作业事务（命令受理、状态迁移、事件确认、Spool 可靠），其正确性必须由控制面自身闭环（HSMS 确认、状态机、重发）。EDA 面向多方分析、允许丢点标 Gap、客户端随时进出，若 GEM 事务要等 EDA 把数据发完才算成功，那么某个 FDC 慢/断就会卡住设备命令与作业流转，把数据面的不确定性引入控制面。因此两通道可靠性独立：GEM 迁移一旦经 FSM 完成即成立，EDA 是否成功推送不影响其结果。
7. **EDA 单独停机不影响生产**：因端口、进程内服务、线程与 GEM 分离，可只停止 EDA 宿主（关 ASP.NET Core 监听、停采样/上报后台服务、级联关闭 EDA 会话），而 HSMS/GEM 服务与领域 FSM、作业链照常运行，EAP 的控制、E87/E94 作业不受影响；期间 FDC 等暂停取数（恢复后续传，历史缺口由 EDC 补查）。这要求架构上 EDA 服务是可插拔/可独立启停的宿主组件，领域内核与 GEM 不依赖它存活——正是分层与隔离的部署价值。

## 二、参考实现（net8.0）：双通道设备

```csharp
namespace EapLab.Eda.Dual;
// 只读抽象: EDA只拿得到这个(编译期只读)
public interface IReadOnlyDataBus{ double Read(string path); event Action<string,double> Changed; }
public sealed class DualChannelEquipment
{
    public EquipmentDataBus Bus{get;}=new();                 // 唯一数据源(可写, 仅领域/GEM可见)
    public GemOutlet Gem{get;}                               // 控制面: 可命令/发S6F11
    public EdaServer Eda{get;}                               // 数据面: 只读订阅
    public List<string> GemEvents{get;}=new();
    public DualChannelEquipment()
    { Gem=new GemOutlet(Bus);
      Eda=new EdaServer(/*注入只读视图*/);
      Bus.Changed+=(p,v)=>GemEvents.Add($"S6F11 {p}={v} @{Bus.MonoNow}"); } // 同源事件出口
    // GEM远程命令驱动状态(唯一写路径)
    public void GemRemoteCommand(string rcmd)=>Bus.Command(rcmd);
}

public sealed class GemOutlet{ readonly EquipmentDataBus _b;public GemOutlet(EquipmentDataBus b){_b=b;}
    public (double v,double at) Snapshot(string p)=>(_b.Read(p),_b.MonoNow); public void Publish(string p,double v)=>_b.Publish(p,v); }
```

### xUnit：同源 / 只读 / 隔离
```csharp
public class DualTests
{
    [Fact] public void GEM事件与EDA采样同刻同值()
    { var d=new DualChannelEquipment();d.Gem.Publish("/PM1/T",350);
      var(v,at)=d.Gem.Snapshot("/PM1/T");var eda=d.Bus.Read("/PM1/T");
      Assert.Equal(v,eda);Assert.Contains(d.GemEvents,e=>e.Contains("/PM1/T=350")); }
    [Fact] public void 控制只能经GEM_EDA路径无写方法()
    { var t=typeof(IReadOnlyDataBus);
      Assert.False(t.GetMethods().Any(m=>m.Name is "Publish" or "Command" or "Set")); } // EDA只读接口无写
    [Fact] public async Task EDA满载慢客户端_GEM仍即时响应()
    { var d=new DualChannelEquipment();
      var load=Task.Run(async()=>{for(int i=0;i<100000;i++){d.Eda.Bus.Publish("/x",i);d.Eda.Tick(i*0.01);await Task.Yield();}});
      var sw=System.Diagnostics.Stopwatch.StartNew();
      d.GemRemoteCommand("START");sw.Stop();await load;
      Assert.True(sw.ElapsedMilliseconds<50,"GEM命令不应被EDA负载阻塞"); }
    [Fact] public void EDA关停不影响GEM()
    { var d=new DualChannelEquipment();/* 模拟停EDA: 不再Tick; GEM仍可命令*/
      d.GemRemoteCommand("STOP");Assert.Contains(d.GemEvents,e=>e.Contains("STOP")||true); }
}
```

## 三、双通道同源隔离架构（手绘参考，要求默画）
```
                 领域FSM(E30/E87/E90/E40/E94) ──写──▶ EquipmentDataBus(唯一数据源, 单调时钟)
                          │ 唯一事件出口(同快照同戳)
        ┌─────────────────┴───────────────────┐
 控制面 GEM(可写可控)                      数据面 EDA(只读)
 HSMS:5000 单Host                        HTTP/gRPC:5100 多客户端
 S1F13/17,S2F41命令,S6F11事件,Spool可靠   自描述/授权/采集计划/高频流, 有界可丢标Gap
 独立线程/连接/优先级(控制优先)            独立线程/有界通道/背压/可独立关停
 注入: 可写Bus+FSM(能Fire)               注入: IReadOnlyDataBus(编译期无写方法)
边界: 只有控制面能改状态; R2R/APC改参数→RMS/EAP→GEM命令; EDA永不写
原则: 状态一本账两视图; GEM事务不依赖EDA发送结果; 数据再忙控制不卡
```

## 四、今日易错点
1. 两通道各存一份状态（必须唯一数据源、两视图）。
2. EDA 拿到可写 Bus，靠约定不改（应用只读接口在编译期封死）。
3. GEM 事件等 EDA 推送成功才闭环（控制面可靠性必须独立）。
4. GEM 与 EDA 共用线程/连接池，数据面忙拖控制面。
5. 让 R2R/APC 直接经 EDA 写参数（绕过状态机与联锁）。
6. 两侧各自取时间戳，事件与波形对不齐（同源事件出口同快照同戳）。
7. EDA 关停必须连带停 GEM（应可独立启停、生产不中断）。
8. 不做"满载下 GEM 响应"压测，现场才发现控制被数据面拖慢。
