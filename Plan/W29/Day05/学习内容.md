# W29 · Day05（周五）GEM + EDA 同源双通道实战：控制面与数据面并行不悖

> 建议时长：100 分钟。今天把两条通道放进同一台设备：HSMS/GEM 负责一对一控制（S1F13/F14、S2F41 命令、S6F11 事件），HTTP/gRPC EDA 负责多客户端高频只读采集。验证三件事：同源同值、端口/线程隔离、EDA 高负载不影响 GEM 控制实时性，且 EDA 永远不能控制设备。

## 一、今日目标
1. 组装 DualChannelEquipment：共享唯一数据源/领域 FSM，GEM 出口与 EDA 服务并列、端口与后台资源隔离。
2. 验证同源同值：GEM S6F11 事件快照与同一时刻 EDA 采样值一致、时间戳同源。
3. 验证控制单向性：GEM S2F41 可驱动状态迁移；EDA 侧任何订阅/数据路径都不能改状态。
4. 压测隔离：EDA 满载高频 + 一个慢客户端时，GEM 建连/命令响应仍及时（控制面不被拖垮）。
5. xUnit 双通道场景测试。

## 二、背景知识（先读，35 分钟）

### 1. 双通道在同一进程的架构
- 底层：领域 FSM（E30/E87/E90/E40/E94）+ EquipmentDataBus 唯一数据源（W27 Day01）。
- 控制面：HSMS Server(5000) + GEM 处理器（S1F13/14、S1F17/18、S2F41 命令、S6F11 事件、S5F1 报警），单 Host、可写可控。
- 数据面：ASP.NET Core EDA(5100) + 采样/上报后台服务，多客户端、只读。
- 两通道只通过"读同一数据源、订阅同一领域事件出口"耦合，互不持有对方、互不阻塞；线程/端口/连接池独立。

### 2. 同源事件出口（复用 W22）
- 领域 FSM 状态迁移时，经唯一事件出口同时：①供 GEM 组 S6F11/S16F1；②供 EDA 采 ECV 快照。两侧拿到同一快照、同一单调时间戳，保证可对齐（W24 同快照同戳）。
- GEM 事件是稀疏事务（确认可靠），EDA 周期是连续流（有界可丢标 Gap），可靠性语义不同但数据源相同。

### 3. 控制单向性（硬边界）
- 只有控制面能改状态：S2F41 RCMD→合法迁移、S15 OSS 设属性/调方法、远程 Hold/Resume 等，全部经 FSM Guard。
- EDA 命名空间只持有只读接口（IReadOnlyBus/快照读取、事件订阅），编译期就拿不到写方法——用类型系统强制"EDA 只读"，而不是靠约定。
- APC(R2R)要调参数也走控制面（经 RMS/EAP→GEM 命令），绝不经 EDA 写（W31/W33 再展开）。

### 4. 资源隔离与优先级
- 线程：GEM 连接/消息处理用独立线程/任务与 EDA 采样、上报分开；CPU 紧张时控制面优先级高于数据面（可限制 EDA 后台线程数/CPU 配额）。
- 背压边界：EDA 慢客户端只影响 EDA 通道（Day04），绝不向 GEM 消息循环传导；GEM 事务不依赖 EDA 是否发送成功。
- 独立启停：EDA 服务可单独关停维护/升级，GEM 控制与生产不中断（Day01 端口分离）。

### 5. 对照现场
- 先进 FAB 里设备同时对接：EAP(Host) 走 SECS/GEM 控制与作业，FDC/YMS/R2R 走 Interface-A 高频取数；设备端工程师必须保证"数据再忙，控制不卡；数据只读，控制唯一"。这正是今天要内化成代码与测试的能力。
