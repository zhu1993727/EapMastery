## 二、背景知识（先读，30 分钟）

### 1. 槽位编号与物理约定
- 12 寸 FOUP 标准 25 槽，编号 1..25（**1-based**，SECS 上报通常也用 1..25，代码内部数组 0-based 要做 +1/-1 转换，这是常见 off-by-one 坑）。
- 槽位方向（Slot1 在顶还是底）依设备/载具约定，跨设备交叉取片时必须统一编号映射，不能想当然。
- 每槽三态：Empty（空）、Occupied（有且仅有一片，可带 SubstrateID）、Abnormal（异常：叠片/错位/未可靠就位）。

### 2. SlotMap 内存模型
- 用长度 25 的数组 `SlotState[]` + 可选 `Dictionary<slot,substrateId>`。
- 提供：SetOccupied/SetEmpty/MarkAbnormal、IsOccupied、Count（占用数）、OccupiedSlots（有序槽号列表）、按槽取片 ID。
- 不变式：容量 25；一个槽 Occupied 最多绑一个 ID；Abnormal 单独标记不参与正常取放。

### 3. SECS 表达（结合 W03 编码）
实际实现常见三种，按 Host 约定/标准选择，都要能看懂：
- **紧凑位图（B 类型）**：用若干字节的 bit 表示占用，1 bit/槽，25 槽需 4 字节（32 bit，高位/低位对齐约定要明确）。最省带宽。
- **布尔数组（List of Boolean）**：L,25[BOOLEAN...]，每槽一个 true/false，直观、略占带宽。
- **结构化 List**：L[n[L,2[U1 slotNo, A substrateId]]] 或 L[n 槽信息]，能带每片 ID/状态，信息最全（交叉取片、逐片追溯用）。
- 教学以"位图 + 结构化 ID 列表"组合：位图表占用、ID 列表表身份。

### 4. 位图手工编解码（重点练）
- 25 槽 → 4 字节：第 k 槽（1-based）对应第 (k-1) 个 bit；bitIndex/8=字节下标，bitIndex%8=位偏移，大端/位序约定固定。
- 例：槽 1、3、25 有片 → bit0、bit2、bit24 置 1，其余 0；写出 4 字节十六进制。
- 解码反向：遍历 25 bit 还原每槽 bool；忽略第 25 槽之后的保留 bit（26..32）。

### 5. 源图 vs 结果图
- **SourceSlotMap（源槽位图）**：载具上料、E87 Loaded 后读取/Host 下发，描述"加工前每槽有什么片"。
- **ResultSlotMap（结果槽位图）**：加工/取放全部结束后，由基板跟踪器根据每片最终位置生成，描述"下料前每槽是什么片"。
- **对比 Diff**：同槽加工（源槽进、结果同槽出，占用集合应一致，ID 一致）vs 交叉取片（源盒片进、目标盒出，源图减少、目标图增加，总数守恒）。Diff 输出：新增槽、消失槽、ID 变化槽、数量差，供 Unload 守卫和异常检测用。

### 6. 与 E90 位置模型的关系
- SlotMap 是"载具位置"这一类 Location 的快照；设备内位置（臂/腔）的占用不在 SlotMap，而在基板跟踪器的全局位置表。全局守恒 = 所有载具 SlotMap 占用数 + 设备内位置占用数 = 上料总数（Day03/05 用）。
