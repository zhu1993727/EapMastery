# W14 · Day04 答案与参考实现

## 一、自测题标准答案
1. **Pick/Place 前后置条件**：
   - **Pick（槽→臂）**：前置=片确实在指定载具指定槽（expectedFrom 校验）、目标机械臂为空（容量 1 未满）、该载具处于 Loaded 可访问、没有 Hold；后置=片 CurrentLocation 变为机械臂、源槽 SlotMap 变空、臂 Occupants 含该片、片状态可置 InTransfer。
   - **Place（臂→槽）**：前置=片在指定臂上、目标槽为空（容量 1，防叠片）、目标载具允许访问且是任务声明的目标槽；后置=片在目标槽、臂变空、目标槽 SlotMap 占用并绑 ID、片状态按情况置 Processed/OnCarrier。两者都建立在原子 Move 上，前置不满足直接拒绝零副作用，后置由 Move 事务保证双向映射与 SlotMap 一致、不变式成立。
2. **Process 为何只改状态不改位置 / 原则**：加工时片物理上停在工艺腔体内（Chamber），位置没有发生移动，变化的是工艺进度（未加工→加工中→已加工）。Process 不调用 Move、只把片状态 Processing→Processed 并记录 recipe/腔/起止时间，体现"**位置（在哪）与工艺状态（加工到哪步）正交分离**"的建模原则（Day03 已述）。若把"加工"误建成一次位置迁移，就会虚构片的移动、污染轨迹、破坏位置语义。位置只在真正物理搬运时变，工艺在原地改状态，轨迹因此能如实区分"移动"和"加工"。
3. **位置事件字段 / 投影**：字段包括 SubstrateId（片）、Action（Pick/Place/Transfer/Process）、From、To（Process 时 From=To=腔）、SubstrateState（迁移后状态）、Timestamp、关联 LoadPort/Carrier/Slot、关联 ProcessJobId/ControlJobId（接 E40/E94）、结果/异常码。投影：OSS 走 S16F1 对象事件（Substrate 对象，CEID 如 4401 Moved、4402 Processed，快照带上述属性，复用 W10 对象事件与订阅）；传统 GEM 走 S6F11（CEID=基板移动/加工事件，报告 RPT 含片ID/源/目标/位置等 VID，需先 S2F33/35 定义）。同一内部位置事件经两个适配器投影，和 W10 单一领域事件双出口一致。
4. **轨迹四类问题 / 为何必须留**：①完整路径——这片依次经过哪些位置；②某时刻在哪——按时间回放定位历史位置；③某腔加工过哪些片——按腔/工艺反查片清单（良率与缺陷追溯）；④停留时长——片在设备内/各段耗时（产能与瓶颈分析）。先进 FAB 必须留轨迹，因为晶圆价值高、工艺步骤多，一旦出现良率异常、设备污染、混片争议，必须能精确回答"这片何时到哪、进过哪个腔、用什么配方、和哪些批同腔"，才能定位根因、圈定受影响片范围、满足质量追溯与客户审计；没有轨迹就只能整批隔离，代价巨大。
5. **Transfer 失败处置**：立即中止整条路径编排（后续动作不再执行），利用 Move 事务保证失败动作零副作用、片保持在失败前的确定位置（不出现半迁移）；置相关任务/搬运为异常挂起、冻结该臂/路径后续调度，产出失败位置事件与告警（带片 ID、意图 From→To、失败码、当前实际位置）；依据三不变式做一次全量 Reassert 确认全局仍自洽；由恢复策略决定人工或安全重试（片归属确定、可回到确定状态才允许限次重试，归属不明则人工，原则同 W11/W13）。绝不"跳过失败步继续"，否则后续动作基于错误位置必然连锁出错。
6. **在途事件多如何减流**：复用 W10 订阅模型做设备端过滤——Host 按粒度订阅：只订阅关键节点事件（片进腔/加工完成/片放回/异常），忽略高频纯在途 Transfer（臂↔对准器↔锁之间的中间移动）；或按 Substrate/Carrier/ProcessJob 实例订阅关心的片，CEID 白名单只放行 Moved 关键拍、Processed、异常事件。设备端在事件出口用 SubscriptionTable 过滤（空订阅全发、一旦订阅按白名单），只把 Host 真正需要的事件上线，在途细节留在本地轨迹可按需查询，从而显著降低 SECS 流量同时不丢关键追溯节点。
7. **片停在臂上没放回的后果**：守恒层面总数仍守恒（片在 InternalLocation 臂上，TotalInside 仍计入，不丢片），但它不在任何载具槽里；Unload 守卫 AllSubstratesReturned 会失败——结果 SlotMap 比预期少这片、源/目标槽都找不到它，卸载被拒绝并报警，提示有片滞留设备内（臂上），防止盒被取走而片留在机台。这正是"守恒保证片没丢 + Unload 守卫保证片归位"两层配合：守恒告诉你片还在（在臂上），守卫阻止在片未归位时放行载具，直到把片放回正确槽才允许下料。

## 二、参考实现（net8.0，接 Day03 LocationSpace）

### 位置事件与轨迹
```csharp
public enum SubAction { Pick, Place, Transfer, Process }
public sealed record LocationEvent(string SubstrateId,SubAction Action,LocationId? From,LocationId? To,
    SubstrateState State,long Ts,string? PjId=null,string? Err=null);

public sealed class Trajectory
{
    public string SubstrateId { get; }
    public List<LocationEvent> Points { get; }=new();
    public Trajectory(string id){SubstrateId=id;}
    public LocationId? WhereAt(long ts) => Points.LastOrDefault(p=>p.Ts<=ts)?.To ?? Points.FirstOrDefault()?.From;
    public IEnumerable<LocationEvent> InChamber(string chamber)=>
        Points.Where(p=>p.Action==SubAction.Process && (p.To?.Key??"").Contains(chamber));
}
```

### 搬运服务（高级动作 + 事件 + 轨迹）
```csharp
public sealed class SubstrateTransferService
{
    private readonly LocationSpace _space;
    public Dictionary<string,Trajectory> Trajectories { get; }=new();
    public List<LocationEvent> Events { get; }=new();
    public event Action<LocationEvent>? LocationEvent;
    private long _clock;
    public SubstrateTransferService(LocationSpace space){_space=space;}

    private Trajectory Tj(string id)=>Trajectories.TryGetValue(id,out var t)?t:Trajectories[id]=new(id);
    private void Emit(LocationEvent e){ Events.Add(e); Tj(e.SubstrateId).Points.Add(e); LocationEvent?.Invoke(e); }
    public void Tick(long d)=>_clock+=d;

    public void Pick(string id,CarrierLocation from,InternalLocation arm,string? pj=null)
    {
        if(!arm.Key.Contains("Robot")) throw new InvalidOperationException("Pick目标必须是机械臂");
        _space.Move(id,from,arm,SubstrateState.InTransfer);
        Emit(new(id,SubAction.Pick,from,arm,SubstrateState.InTransfer,_clock,pj));
    }
    public void Place(string id,InternalLocation arm,CarrierLocation to,SubstrateState final,string? pj=null)
    {
        if(!arm.Key.Contains("Robot")) throw new InvalidOperationException("Place源必须是机械臂");
        _space.Move(id,arm,to,final);
        Emit(new(id,SubAction.Place,arm,to,final,_clock,pj));
    }
    public void Transfer(string id,InternalLocation from,InternalLocation to,string? pj=null)
    {
        _space.Move(id,from,to,SubstrateState.InTransfer);
        Emit(new(id,SubAction.Transfer,from,to,SubstrateState.InTransfer,_clock,pj));
    }
    public void Process(string id,InternalLocation chamber,string recipe,string? pj=null)
    {
        if(_space.LocationOf(id).Key!=chamber.Key) throw new InvalidOperationException("片不在该腔无法加工");
        _space.SubstrateState(id,SubstrateState.Processing); Emit(new(id,SubAction.Process,chamber,chamber,SubstrateState.Processing,_clock,pj));
        Tick(1); // 工艺耗时(逻辑)
        _space.SubstrateState(id,SubstrateState.Processed); Emit(new(id,SubAction.Process,chamber,chamber,SubstrateState.Processed,_clock,pj));
    }
}
```

### 单片完整路径编排
```csharp
public sealed class SingleWaferRoute
{
    private readonly SubstrateTransferService _svc;
    public SingleWaferRoute(SubstrateTransferService svc){_svc=svc;}
    public void Run(string id,string carrier,int slot,string pj)
    {
        var S=new CarrierLocation(carrier,slot);
        var R1=new InternalLocation("Robot:R1"); var AL=new InternalLocation("Aligner");
        var LL=new InternalLocation("LoadLock:LL1"); var VR=new InternalLocation("Robot:VR");
        var C1=new InternalLocation("Chamber:C1");
        _svc.Pick(id,S,R1,pj);
        _svc.Transfer(id,R1,AL,pj); _svc.Transfer(id,AL,R1,pj);
        _svc.Transfer(id,R1,LL,pj); _svc.Transfer(id,LL,VR,pj); _svc.Transfer(id,VR,C1,pj);
        _svc.Process(id,C1,"RCP_A",pj);
        _svc.Transfer(id,C1,VR,pj); _svc.Transfer(id,VR,LL,pj); _svc.Transfer(id,LL,R1,pj);
        _svc.Place(id,R1,S,SubstrateState.Processed,pj);   // 同槽放回
    }
}
```

## 三、事件投影示意（OSS/GEM 双适配器）
```
内部 LocationEvent ──► OssEventAdapter: S16F1(Substrate:W5, CEID 4401 Moved, 快照[From,To,State])
                  ──► GemEventAdapter: S6F11(CEID 基板移动, RPT[VID片ID/源/目标])
   Process(4402/加工CEID) 同理; 关键CEID经W10订阅表过滤, 在途细节仅存本地Trajectory
   断线: 关键事件进 W08 Spool, 重连按序重发, Host确认后删除
```

## 四、今日易错点
1. 把 Process 当成位置迁移（加工在原地，只改工艺状态）。
2. Pick/Place 不校验臂空/目标槽空（双重放置、叠片）。
3. 高级动作绕过原子 Move 直接改映射（丢失不变式保护和事务回滚）。
4. 事件只发线上不留本地轨迹（断线/过滤后无法追溯，要本地 Trajectory+线上投影双份）。
5. 路径某步失败还继续编排（立即中止、零副作用、挂起、按归属决定重试/人工）。
6. 在途高频事件全量上报（用订阅白名单只发关键节点，本地留全量轨迹）。
7. 片停臂上以为"没丢就没事"（守恒没丢但 Unload 守卫会拦，必须归位才能下料）。
8. 事件不带 PJ/CJ 关联（后续无法把片轨迹归到具体加工任务）。
