## 二、背景知识（先读，30 分钟）

### 1. 四类基板异常
- **丢片 Missing（片不见了）**：任务声明/源图有这片，但结果图和设备内所有位置都找不到。违反守恒（总数少）。原因：取放失误、掉片、传感器漏检、迁移记录丢失。
- **重片/叠片 Double（一个槽/位置有两片）**：容量 1 的位置出现两片，违反容量不变式。原因：目标槽已有片还放入、双臂协调错误、空取（以为取走实际没取）后又放。
- **错位 Misplaced（片在错误的槽/位置）**：片存在、数量对，但不在任务声明的目标槽（W5 应回槽5却到了槽7），或源/目标交叉映射错。
- **ID 不符 WrongId（片身份错）**：槽位对但片 ID 与预期不一致（交叉混片、读码错、两片对调），数量守恒但身份错。
- 区别要点：丢片/重片破坏数量与容量；错位/ID 不符数量守恒但位置或身份错，更隐蔽，必须靠逐片 ID 校验才能发现。

### 2. 四方一致性核对
```
①SourceMap(上料源图,片从哪来)
②JobPlan(任务声明:每片 源槽→目标槽/路径, E40)
③LivePositions(实时位置空间:每片当前在哪)
④ResultMap(下料结果图:最终每槽是谁)
核对关系:
 - 数量: Source 片数 == Live 总数(守恒) == Result 片数(无移出时)
 - 去向: 每片按 JobPlan 的目标,Result 中该目标槽==该片ID
 - 身份: Result 每槽 ID == JobPlan 预期放入该片的 ID
 - 残留: 设备内位置(臂/腔/暂存)在结束时必须全空
```

### 3. 检测时机（多层防线）
- **动作前（Pre-check）**：Pick 前源槽确实有该片；Place 前目标槽空。把异常挡在动作前。
- **动作中（In-variant）**：每次 Move 后三不变式断言（Day03），即时抓重片/丢片。
- **动作后（Post-check）**：单片路径结束，片在声明目标位置、ID 一致。
- **下料前（Final Check）**：全载具/全任务四方核对，设备内无残留，结果图符合计划，才允许 Unload（对接 W13 Unload 守卫）。

### 4. 检测规则实现要点
- Missing：集合差集——应在的片集合 -（结果图片 ∪ 设备内片）= 丢失集合。
- Double：扫描所有容量 1 位置 Occupants>1（Move 已拦，Final 再扫兜底）。
- Misplaced：对每片比较 Live/Result 位置与 JobPlan.TargetSlot。
- WrongId：逐槽比较 Result.IdAt(slot) 与 JobPlan.ExpectedId(slot)。
- LeftInside：结束后设备内 InternalLocation 占用非空=残留。

### 5. 处置策略
- 任何一类异常：立即挂起相关任务、禁止 Unload、发高级告警（带异常类型/片ID/期望/实际/位置快照）、锁相关载具。
- 丢片/重片多为硬件/传感器问题，通常必须人工现场确认（片是否物理掉落/叠放），不自动"改账"。
- 错位/ID 不符要防止错误片流入下游，Hold 载具，人工核对后决定重放/隔离。
- 原则同前：数量/物理异常安全停机，身份异常冻结人工，绝不用"修改记录"假装一致。

### 6. 与传感器的关系
- 软件检测基于映射和计划，最终事实靠硬件传感器（槽位有无、臂持片、映射器 Mapper 扫描 SlotMap、读码器）。
- Final Check 应结合 Mapper 实际扫描结果与软件结果图交叉验证，而不是只信软件账本。
