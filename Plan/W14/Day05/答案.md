# W14 · Day05 答案与参考实现

## 一、自测题标准答案
1. **丢片/重片破坏什么 / 错位ID不符为何隐蔽**：丢片 Missing 破坏**守恒不变式**（进入总数对不上，某片在所有位置都找不到，总数变少）；重片/叠片 Double 破坏**位置容量不变式**（容量 1 的槽/臂/腔出现两片）。错位 Misplaced 和 ID 不符 WrongId **数量和容量都守恒**（片一片不少、每处都只有一片），只是放错槽或片身份对调，仅看占用位图和总数完全正常，因此更隐蔽——必须逐片比对 SubstrateID 与任务声明的目标槽才能发现。这也是为什么先进 FAB 强调逐片读码而不只靠槽位推断：只数片数会漏掉"片对、位置/身份错"。
2. **四方 / 两两核对**：①SourceMap 上料源图（片从哪来、有哪些片）；②JobPlan 任务声明（每片源槽→目标槽/路径、预期 ID）；③LivePositions 实时位置空间（每片当前在哪）；④ResultMap 下料结果图（最终每槽是谁）。两两核对：数量上 Source 片数=Live 总数=Result 片数（守恒，无正常移出时）；去向上每片按 JobPlan 目标，Result 该目标槽放的正是该片；身份上 Result 每槽 ID==JobPlan 对该槽的预期 ID；残留上结束时 Live 中设备内位置全空。四方一致才证明"对的片、走了对的路径、到了对的槽、没有遗漏"。
3. **四检测时机 / 多层防线**：①动作前 Pre-check（Pick 前源槽确有该片、Place 前目标槽空）把错误挡在物理动作前；②动作中 In-variant（每次 Move 后断言三不变式）即时抓重片/丢片/双重放置；③动作后 Post-check（单片路径结束确认片在声明目标、ID 一致）抓单片级错位；④下料前 Final Check（全任务/全载具四方核对、设备内无残留）做总验收。多层防线因为单层都可能漏：动作前挡不住执行中的偏差，不变式只保证"自洽"不保证"符合任务目标"（数量对但错位它发现不了），必须在不同粒度层层兜底，越早发现损失越小、越容易定位。
4. **Final Check 放行条件**：①数量守恒（Source/计划片数=Result 片数，无 Missing）；②无容量违例（无 Double/叠片）；③逐片位置正确（每片在 JobPlan 声明目标槽，无 Misplaced）；④逐片 ID 正确（每槽 ID 与预期一致，无 WrongId）；⑤设备内无残留（所有 InternalLocation 臂/对准器/锁/腔/暂存全空，无 LeftInside）；⑥（结合硬件）Mapper 扫描结果与软件结果图一致。全部满足才允许 Unload（对接 W13 Unload 守卫 AllSubstratesReturned），任一不过即阻止下料、Hold、报警。
5. **LeftInside 检测 / 与丢片关系**：结束时遍历所有设备内 InternalLocation（Robot/Aligner/LoadLock/Buffer/Chamber），Occupants 非空即残留 LeftInside（片没回载具、滞留在机台内）。它和丢片关系：LeftInside 是"守恒成立但没归位"——片还在设备内、总数没少，能在设备内找到，属于未归位；Missing 是"哪里都找不到"、守恒被破坏。检测到 LeftInside 时 Unload 同样被拦（防止盒取走、片留机台），但定位更明确（知道片在哪个内部位置，可调度取回）；若只看载具结果图少片却不扫设备内部，就会把 LeftInside 误判成 Missing，所以 Final Check 必须同时核对载具和设备内位置。
6. **错位/ID 不符为何不自动改账**：软件账本记录的是"发生了什么"，错位/ID 不符说明物理现实与计划冲突，但软件无法自动判断谁对——可能是片真放错了（物理事故），也可能是读码错误/计划本身有误，自动改账等于用一方说法覆盖另一方、把异常"抹平"，会让错片/混片以"账目一致"的假象流入下游，失去发现和追溯事故的机会（甚至掩盖设备硬件故障）。正确做法是冻结、Hold、保留现场与全部记录、报警交人工核查物理片身份后决定重放/隔离/返工。数量异常安全停机、身份异常冻结人工，绝不"改记录假装一致"。
7. **为何与 Mapper 硬件扫描交叉验证**：软件结果图是根据内部迁移记录推算出来的，若传感器漏检、空取/误取、软件记录与物理动作脱节，软件账本可能"自洽但失真"（以为放了实际没放、以为槽空实际有片）。Mapper（载具槽位映射传感器/扫描）独立检测物理 FOUP 每槽真实有无甚至读片 ID，是不依赖软件记录的客观事实源。Final Check 用 Mapper 实际扫描与软件结果图交叉验证，一致才可信；不一致说明软件跟踪或硬件动作出了问题，立即报警。这和 W13"物理事实是最终基准、逻辑账向物理对齐"一脉相承，防止"自证正确"。

## 二、参考实现（net8.0）

### 任务计划
```csharp
namespace EapLab.E90;
// 每片: 片ID -> 源槽/目标槽(交叉取片时源载具与目标载具可不同)
public sealed record WaferPlan(string SubstrateId,string SrcCarrier,int SrcSlot,string DstCarrier,int DstSlot);
public sealed class JobPlan
{
    public List<WaferPlan> Wafers { get; }=new();
    public WaferPlan? PlanOf(string id)=>Wafers.FirstOrDefault(w=>w.SubstrateId==id);
    public string? ExpectedIdAt(string carrier,int slot)=>
        Wafers.FirstOrDefault(w=>w.DstCarrier==carrier&&w.DstSlot==slot)?.SubstrateId;
}
public enum ConsistencyIssue { Missing, Double, Misplaced, WrongId, LeftInside }
public sealed record Issue(ConsistencyIssue Kind,string Detail);
```

### 一致性校验器
```csharp
public sealed class ConsistencyChecker
{
    private readonly LocationSpace _space;
    public ConsistencyChecker(LocationSpace space){_space=space;}

    public List<Issue> FinalCheck(JobPlan plan, IDictionary<string,SlotMap> resultMaps,
        SlotMap? mapperScan=null, string? mapperCarrier=null)
    {
        var issues=new List<Issue>();
        // 1) 设备内残留 LeftInside + 收集实时位置
        var inside=new List<string>();
        foreach(var loc in _space.InternalLocations())
            foreach(var id in loc.Occupants.ToList()) inside.Add(id);
        foreach(var id in inside) issues.Add(new(ConsistencyIssue.LeftInside,$"{id} 残留设备内"));

        foreach(var w in plan.Wafers)
        {
            // 2) 片是否存在(丢片)
            LocationId loc;
            try{ loc=_space.LocationOf(w.SubstrateId); }
            catch(SubstrateTrackingException){ issues.Add(new(ConsistencyIssue.Missing,$"{w.SubstrateId} 找不到")); continue; }

            // 3) 是否在计划目标槽(错位)
            var expected=new CarrierLocation(w.DstCarrier,w.DstSlot);
            if(loc.Key!=expected.Key)
                issues.Add(new(ConsistencyIssue.Misplaced,$"{w.SubstrateId} 应在{expected.Key}实际{loc.Key}"));
        }
        // 4) 逐槽身份(ID不符) + 重片
        foreach(var (carrier,map) in resultMaps)
        {
            for(int s=1;s<=SlotMap.SlotCount;s++)
            {
                if(map.StateAt(s)==SlotState.Abnormal) issues.Add(new(ConsistencyIssue.Double,$"{carrier}:S{s} 异常/叠片"));
                if(map.StateAt(s)==SlotState.Occupied)
                {
                    var actual=map.IdAt(s); var expect=plan.ExpectedIdAt(carrier,s);
                    // 非计划槽但有片也归错位; 计划槽但ID不符=WrongId
                    if(expect is null) issues.Add(new(ConsistencyIssue.Misplaced,$"{carrier}:S{s} 有计划外片 {actual}"));
                    else if(expect!=actual) issues.Add(new(ConsistencyIssue.WrongId,$"{carrier}:S{s} 期望{expect}实际{actual}"));
                }
            }
        }
        // 5) 数量守恒(丢片兜底)
        int planned=plan.Wafers.Count;
        int inMaps=resultMaps.Values.Sum(m=>m.OccupiedCount)+inside.Count;
        if(inMaps!=planned) issues.Add(new(ConsistencyIssue.Missing,$"数量不符 计划{planned} 现存{inMaps}"));

        // 6) Mapper 硬件扫描交叉验证
        if(mapperScan is not null && mapperCarrier is not null && resultMaps.TryGetValue(mapperCarrier,out var soft))
            for(int s=1;s<=SlotMap.SlotCount;s++)
                if((mapperScan.StateAt(s)==SlotState.Occupied)!=(soft.StateAt(s)==SlotState.Occupied))
                    issues.Add(new(ConsistencyIssue.Misplaced,$"S{s} 软件与Mapper扫描不一致"));
        return issues;
    }
    public bool CanUnload(List<Issue> issues)=>issues.Count==0;
}
```
> `LocationSpace.InternalLocations()` 返回所有 InternalLocation（实现时在 LocationSpace 增加按类型枚举内部位置的方法即可）。

### xUnit（异常注入）
```csharp
public class ConsistencyTests
{
    [Fact] public void 正常同槽_FinalCheck无问题()
    {
        var (space,plan,maps)=BuildOneWaferSameSlot();
        var issues=new ConsistencyChecker(space).FinalCheck(plan,maps);
        Assert.Empty(issues);
    }
    [Fact] public void 片残留臂上_LeftInside且不能Unload()
    {
        var (space,plan,maps)=BuildOneWaferSameSlot();
        // 片没放回槽, 仍在R1: 结果图槽5为空
        maps["A"].SetEmpty(5);
        var issues=new ConsistencyChecker(space).FinalCheck(plan,maps);
        Assert.Contains(issues,i=>i.Kind==ConsistencyIssue.LeftInside);
        Assert.False(new ConsistencyChecker(space).CanUnload(issues));
    }
    [Fact] public void 放错槽_Misplaced()
    {
        var (space,plan,maps)=BuildPlaned(w=>w.DstSlot=7); // 应回5实际7
        var issues=new ConsistencyChecker(space).FinalCheck(plan,maps);
        Assert.Contains(issues,i=>i.Kind==ConsistencyIssue.Misplaced);
    }
    [Fact] public void ID不符_WrongId_数量守恒也能抓()
    {
        var (space,plan,maps)=BuildOneWaferSameSlot();
        maps["A"].SetOccupied(5,"WX"); // 槽对但片ID错
        var issues=new ConsistencyChecker(space).FinalCheck(plan,maps);
        Assert.Contains(issues,i=>i.Kind==ConsistencyIssue.WrongId);
    }

}
```

## 三、异常检测地图（手绘参考）
```
动作前 Pre: 源槽有片? 目标槽空? ──否──► 拒绝动作
动作中 Move: 唯一/容量/守恒 ──破坏──► 回滚+告警
动作后 Post: 单片在目标?ID对? ──否──► 单片异常挂起
下料前 Final(四方):
  SourceMap ↔ 数量守恒 ↔ ResultMap
  JobPlan   ↔ 逐片目标/ID ↔ LivePositions
  设备内位置全空(无LeftInside) + Mapper硬件扫描一致
  └─ Missing/Double/Misplaced/WrongId/LeftInside ─► Hold+禁止Unload+报警(不自动改账)
```

## 四、今日易错点
1. 只数片数认为一致（错位/ID 不符数量守恒，必须逐片 ID 核对）。
2. 混淆 LeftInside（片在设备内、守恒）和 Missing（哪都没有、破坏守恒）。
3. 只在 Final Check 检测（要动作前/中/后/下料前多层防线）。
4. 检测到错位自动改软件账（必须冻结人工，防"抹平"异常）。
5. 只信软件结果图，不和 Mapper 硬件扫描交叉验证（账本可能自洽失真）。
6. Place 前不查目标槽空（叠片应在动作前就拦）。
7. Final Check 不扫设备内位置（在途/残留片被误判丢失或随盒取走）。
8. 异常不带期望/实际/位置快照（无法快速定位和复盘）。
