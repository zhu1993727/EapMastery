# W14 · Day07 答案

## 一、排障推演参考（现象→查哪→根因→处置）
1. **下料报少一片**：先查守恒——对比计划片数、结果 SlotMap 占用数、设备内位置占用。若设备内某 InternalLocation 非空→LeftInside（片没归位，在臂/腔/暂存），调度取回再 Unload；若设备内也没有、总数确实少→Missing，查该片 Trajectory 最后位置与对应动作事件、传感器/Mapper 记录，定位掉片/漏检点，安全停机人工确认，不补假账。关键先分清"残留"还是"真丢"。
2. **某槽 Mapper 扫到两片**：容量违例 Double/叠片。查该槽 Place 历史：是否目标槽已有片还放入（Place 前置失效）、是否空取后重放、双臂是否同时对同一槽操作。立即 Hold 载具、禁止取放，人工处理物理叠片（防碎片），复查该槽相关动作序列与传感器，软件标记 Abnormal 不参与自动流程。
3. **数量对但两片 ID 对调**：WrongId/Misplaced，数量守恒所以位图和总数正常，靠逐片 ID 与 JobPlan 目标槽比对才发现。查两片 Trajectory 的 Place 目标、交叉映射是否写反、读码是否串号。Hold 该批防止错片流下游，人工核对物理片刻码，按真实身份决定返工/隔离，复盘交叉调度或读码绑定环节。
4. **片卡在机械臂、无法 Unload**：LeftInside，Final Check 扫到 Robot 位置非空、AllSubstratesReturned 不满足而拒绝 Unload（这是正确保护）。查卡在哪一步、为何没 Place（目标槽异常？路径中断？），确认臂持片安全后，走恢复流程把片放到安全槽/原槽，位置空间补登这次恢复迁移并留痕，再 Final Check 通过才 Unload；归属不明则人工。

## 二、综合自测卷（8 题）标准答案
1. **三不变式 + 在途建模**：唯一位置=一片任一时刻恰在一个位置；位置容量=任一位置承载数不超容量（槽/臂/腔多为 1）；总数守恒=各载具槽内片数+设备内片数=进入总数（进加出减）。在途建模把机械臂/传递路径本身建成容量 1 的 InternalLocation：取片=源槽→臂、放片=臂→目标槽，于是传递期间片"在臂上"有明确唯一归属，既不违反唯一位置（不会哪都不在），也始终计入设备内总数支撑守恒；若在途不建模，片在取放之间无位置，唯一位置和守恒同时被破坏，正是丢片盲区。
2. **位图（MSB-first，bit=槽-1，字节 bit/8、位 0x80>>(bit%8)）**：
   - 槽1→bit0→byte0 bit7=1；槽16→bit15→byte1 bit0=1（0x80）；槽25→bit24→byte2 bit0=1（0x80）。
   - byte0=0x80，byte1=0x80，byte2=0x80，byte3=0x00 → `80 80 80 00`。
3. **expectedFrom/加锁/快照/改后断言各防什么**：expectedFrom 防基于过期位置的误操作（乐观并发，片已被别的流程移走则拒绝）；加锁防并发下"检查容量+放入"之间被插入导致双重放置（原子性）；快照保证一旦后续断言失败能整体回滚到改动前、零副作用；改后断言在改动对外生效前验证三不变式，把任何破坏唯一/容量/守恒的改动拦下并回滚。四者分别解决"过期前提、并发竞争、失败恢复、最终自洽"，合起来保证位置模型在任何并发/异常下永远一致。
4. **谁改位置谁改状态**：Pick/Place/Transfer 改**位置**（调用 Move，片在槽/臂/内部位置间迁移，片状态可附带置 InTransfer）；Process **不改位置**只改**工艺状态**（Processing→Processed，片始终在腔）。因为位置描述物理在哪、工艺状态描述加工到哪步，二者正交；真正物理搬运才迁移位置，原地加工只推进状态，这样轨迹能如实区分移动与加工，不虚构位移。
5. **四方对比发现异常**：SourceMap↔LivePositions/ResultMap 比数量（少了→Missing）；JobPlan↔LivePositions 比每片目标位置（片不在声明目标槽→Misplaced）；JobPlan↔ResultMap 逐槽比预期 ID 与实际 ID（槽对 ID 错→WrongId）；LivePositions 扫设备内位置（结束仍非空→LeftInside）；容量扫描/硬件 Mapper 发现 Double。图见 Day05 异常检测地图。
6. **Installed 拒绝 Pick / 总原则**：Installed 只代表物理在位，尚未完成读 ID、校验和 Host 授权（Loaded），此时片不属于"可加工"状态，Tracker 门控拒绝 Pick。体现总原则——**认识世界听物理（Installed 是物理事实），改变世界听逻辑授权（Loaded 才可取片），授权未到不动物理**（与 W12/W13 一脉相承），防止对错料/未授权盒操作。
7. **四者分工**：本地 Trajectory=全量留痕（含在途），不依赖连接，供回放/追溯/某时刻定位；线上订阅事件=按 Host 白名单只发关键节点（进腔/完成/放回/异常）省带宽；Spool=断线时缓存关键上线事件、重连按序补发确认后删，保证 Host 不丢关键轨迹；Mapper 硬件扫描=独立于软件账本的物理客观事实，Final Check 与软件结果图交叉验证，防账本"自洽失真"。前三者管"记录与上报的完整可靠"，Mapper 管"软件是否符合物理现实"。
8. **交叉取片为何双盒守恒+逐片映射**：片从源盒移到目标盒，源 SlotMap 减一片、目标增一片，必须把两个载具作为一个全局系统同时守恒（源减=目标增、全局总数不变），只看单盒会把正常移出误判丢失、或漏掉目标盒多片；逐片映射（CrossMap 记录每片源(盒,槽)→目标(盒,槽)）才能确认"对的片到了对的目标槽"，防止混片、放错槽、源目对调。交叉涉及两批 lot，错误代价翻倍，所以校验粒度必须到单片、守恒范围必须跨两盒。

## 三、W15 预热思考题参考
1. **源盒/目标盒 Final Check 各看什么**：源盒看"应移出的片是否都已正确移出、本盒剩余片是否在各自正确槽、没有该走没走或多走的片、设备内无属于源盒的残留"；目标盒看"应接收的片是否都到了声明目标槽且 ID 一致、没有计划外片/叠片"；两者合起来做全局守恒（源减少集合按 ID==目标增加集合）。
2. **单片臂交换两槽为何要 Buffer**：一个机械臂容量 1、一次只能持一片。要交换 S1、S3：先取 S1 到臂，但 S3 要去 S1 而 S1 位置被"逻辑占用的片"腾空需要先把臂上的 W1 放到临时位置；没有第二个持片位置就无法腾挪。借助 Buffer（暂存位）：W1:S1→Buffer，W3:S3→S1，W1:Buffer→S3，完成交换。本质是容量约束下需要额外暂存位置打破循环等待（类似两变量交换需要第三个临时变量）。
3. **交叉途中目标盒 Hold、片在臂上**：立即冻结该交叉流程，臂上的片有明确归属（在臂、守恒没破），不能强行放进已 Hold 的目标盒（逻辑未授权不动作），也不能丢着不管；安全策略是把片退放到源盒原槽或指定安全 Buffer（记录一次恢复迁移与原因、保留轨迹），保持唯一位置和守恒，挂起任务等目标盒解除 Hold 后再调度；若无法安全退回（机构受限）则安全保持+人工，绝不在目标 Hold 状态下强制放置。

## 四、三张闭卷图要点（自检清单）
- 位置空间图：是否画出载具槽位与全部设备内位置、每处容量、在途归属、双向映射。
- 路径图：每步 From→To 是否正确、Process 是否原地不改位置、片状态标注、最终回槽/到目标。
- 四方核对图：四个来源、两两比对关系、五类异常各自的发现路径、Mapper 交叉验证、Final Check→Unload 门控。

## 五、W14 全周易错点总清单
1. E87 盒级与 E90 片级粒度混淆；Installed 就取片（必须 Loaded）。
2. 25 槽≠25 片；槽号 1-based off-by-one；位图 4 字节、MSB-first、保留 bit 清零。
3. 双向映射只改一边；Move 不用事务/不 expectedFrom/不加锁/不快照/不改后断言。
4. 在途不建模（片在取放间无归属）；Process 误当位置迁移。
5. 只数片数（漏错位/ID 不符，要逐片 ID）；混淆 LeftInside 与 Missing。
6. 检测只靠 Final 一层（要动作前/中/后/下料前多层）。
7. 异常自动改账抹平（数量异常停机、身份异常冻结人工）。
8. 只信软件账本，不和 Mapper 交叉验证。
9. 交叉取片只看单盒守恒（要跨两盒全局守恒+逐片映射）。
10. 载具移除不查设备内残留；本地轨迹/线上订阅/Spool 职责不清。
