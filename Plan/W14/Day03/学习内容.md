# W14 · Day03（周三）位置空间建模：Location、Substrate 与三不变式校验（代码）

> 建议时长：90 分钟。今天用代码实现 Day01 的位置模型：统一 Location（载具槽位+设备内位置）、Substrate、双向位置映射、位置容量，并把"唯一位置/容量/守恒"三不变式做成每次迁移都强制校验的事务。这是基板跟踪器的内核。

## 一、今日目标
1. 实现 `Location`/`LocationId`（区分载具槽位与设备内位置，带容量）。
2. 实现 `Substrate`（片 ID、当前位置、状态）与位置空间 `LocationSpace`（双向映射）。
3. 实现原子迁移 `Move(sub, from, to)`：事务内校验+改双向映射+不变式检查，失败整体回滚。
4. 把三不变式编码成可复用校验器，违反即抛专用异常并产出告警。
5. xUnit 覆盖正常迁移、双重放置、片不在源、容量溢出、守恒破坏。

## 二、设计（先读，25 分钟）

### 1. Location 建模
```
LocationId: 统一标识一个位置
  CarrierLocation(carrierId, slot)  // 载具内槽位,容量1
  InternalLocation(name)            // Robot:R1/Aligner/Chamber:C1...,容量按类型
Location: { Id, Capacity, Occupants(基板ID集合) }
  IsFull / CanAccept
```
- 槽位位置与 SlotMap 打通：CarrierLocation 的占用就是该载具 SlotMap 的占用。
- 设备内位置（臂/对准器/腔/锁/暂存）容量：臂、对准器、单晶圆腔通常 1；Buffer 可多。

### 2. Substrate 建模
- SubstrateId、SubstrateState（OnCarrier/InTransfer/Processing/Processed/Done）、CurrentLocationId、移动历史。
- 片状态与位置正交：位置说"在哪"，片状态说"加工到哪一步"。

### 3. 双向映射（LocationSpace）
- `_substrateLocation: subId -> LocationId`（片在哪）
- `_locationOccupants: locId -> Set<subId>`（位置有谁）
- 查询：LocationOf(sub)、Occupants(loc)、CountInCarrier/CountInternal/TotalInside。
- 两个映射必须始终一致，只允许通过 Move 修改（封装写入口）。

### 4. 原子迁移 Move（核心）
```
Move(subId, expectedFrom, to):
 加锁/事务:
  1 校验片存在、当前位置==expectedFrom(防基于过期位置操作)
  2 校验目标存在、目标未满(容量)、目标不是同一位置
  3 快照(便于回滚)
  4 从源 Occupants 移除; 若源是载具槽→同步SlotMap置空
  5 片.CurrentLocation=to; to.Occupants 加入; 载具槽→SlotMap置占用
  6 提交后跑三不变式断言(唯一/容量/守恒),失败回滚快照并抛异常
  7 记录移动历史 + 发位置变更事件
```
- "expectedFrom" 是乐观并发保护：调用方必须知道片从哪取，若实际位置已变（被别的流程动过），拒绝，防止误操作。

### 5. 三不变式校验器
- UniqueLocation：遍历片，每片 CurrentLocation 非空且唯一归属；位置 Occupants 与片映射互为镜像一致。
- Capacity：每个位置 Occupants.Count ≤ Capacity。
- Conservation：TotalInside（载具内+设备内）== 登记进入总数（减去已正常移出），可用快照基线核对。
- 每次 Move 提交后增量校验（也可全量 Reassert 用于对账）。

### 6. 异常模型
- `SubstrateTrackingException` 带错误码：NotAtExpectedLocation、LocationFull、SubstrateMissing、DoublePlace、ConservationBroken。
- 上层捕获后转告警（S5F1/OSS 事件）并安全挂起相关取放，等价真实 EAP 的防错逻辑。
