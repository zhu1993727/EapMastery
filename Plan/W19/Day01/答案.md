# W19 · Day01 答案与参考实现

## 一、自测题标准答案
1. **八阶段及门**：①物理上料门——E84 Deposit 握手正常+稳定去抖在位→E87 Installed，预约核对通过才 Loaded；②位置注册门——E90 为 Loaded 载具注册 SlotMap、建立总数基线，载具/槽位图有效；③PJ 建立门——WaferMap+Route 通过静态六校验（源唯一/目标唯一/槽范围/片集合/路线可达/配方）才受理创建；④开工双校验门——载具绑定口与 ID 一致、配方版本、资源可用、无 Hold，通过才 Start；⑤并发执行门——资源区间互斥、每拍三不变式，违例即停；⑥跨载具搬运门——AtPick 读码对源、AtPlace CAS+读回对目标、跨盒全局守恒；⑦严格完成门——全片 Completed+AtDestination+设备内空+终验+无异常+数据全；⑧下料门 UnloadGuard——任务全完、片全归位、臂回原点、门关闭、无 Hold 才放行 Unload。每道门 fail-closed，不过不进下一步。
2. **依赖单向/解耦原因**：依赖单向（Cell→各标准模块→Domain，下层不反向依赖上层）避免循环依赖、让每个标准模块可独立编译、独立单测、可复用；模块通过接口和事件解耦，使得 E90 不需要知道 E40 的存在、E40 不直接操纵 E87，替换/升级某一层（如换调度器、换 Host 接口）不波及其他层，集成时由 Cell 总装层按流程编排、订阅事件推进。若双向硬连，会形成牵一发动全身的耦合网，无法独立测试，也违背"标准模块各司其职"的设计。
3. **三个单一事实源 / 不私改**：片物理位置只问 E90（SubstrateTracker 是唯一改位置入口）、任务/片工艺状态只问 E40 PJ 状态机、载具逻辑状态只问 E87（Installed/Loaded 等）。不能私改他域状态，因为同一事实若多处可写会出现不一致（E40 以为片在腔、E90 记录在臂），且并发下无法定位权威状态；所有跨域变更必须请求对应域的公开方法（如 E40 要搬片必须调 E90.Move），由该域校验并产生事件，其他域订阅事件更新自己的视图，保证全局只有一个权威来源。
4. **Loaded 与 E90 注册先后 / 为何只有 Loaded 可取片**：先物理在位 Installed，经预约核对、授权后才 Loaded，Loaded 之后 E90 才为其注册 SlotMap 与基线（逻辑注册依赖载具已被授权参与生产）；顺序是物理事实→逻辑授权→位置建模。只有 Loaded 表示"载具身份核对无误、被 Host 授权、绑定到正确口、允许自动生产"，Installed 只是物理插到位（可能错料/未授权/待核对），若允许对非 Loaded 载具自动取片，就可能对错料/未授权/未建账的盒操作，造成混片、错料，所以自动取片门控在 Loaded。
5. **静态六校验 vs 开工双校验**：静态六校验在**建 PJ 时（计划阶段）**，对象是任务定义本身——源目映射自洽（源/目标唯一、槽范围、片集合守恒）、工艺路线拓扑可达、配方字段完整，不依赖当前设备实时状态，错了直接拒绝创建；开工双校验在 **Start 时（执行前夕）**，对象是计划与当前现实是否匹配——载具是否真在绑定口且 ID 对、配方版本是否与当前一致、所需资源是否可用、有无 Hold/Alarm。前者保证"定义自洽"，后者保证"此刻可执行"，静态通过不代表开工时现场没变，所以两道都要。
6. **UnloadGuard 条件 / 缺一会怎样**：条件=该载具相关的所有 Job 已完成、属于它的片全部归位（设备内/臂/锁/Buffer 无相关片）、机械臂回原点、载具门/舱门关闭、无未解除 Hold。缺任一就放行会：任务没完就下料导致片还在设备内被连盒取走（丢片/滞留）、臂未归位或门未关时物理交接碰撞、有 Hold 时绕过管控。因此 UnloadGuard fail-closed，任一不满足拒绝 Unload，这是下料前最后一道物理安全门（W13）。
7. **可观测输出 / 用途**：①事件时间线（载具/位置/资源/Job/S16 全事件带逻辑时间戳）——回放、排障、审计、映射真实 S16F1；②最终布局（每片实际槽位 vs 目标）——核对归位与跨载具结果；③守恒核对（Σ载具+设备内=基线，逐拍记录）——证明无丢叠片；④Makespan/节拍/资源利用率——产能分析（W18）；⑤完成结论（AllCompleted/Partial/异常及原因）——供 Host/MES 决策。它们分别服务正确性证明、质量追溯、产能优化和故障复盘。

## 二、参考实现（net8.0）

### Cell 总装
```csharp
namespace EapLab.Cell;
public sealed class VirtualClusterTool
{
    public CarrierManager Carriers { get; }                 // W13 E87
    public SubstrateTracker Tracker { get; }                // W14 E90
    public GlobalScheduler Scheduler { get; }               // W18
    public ChamberSelector Selector { get; }
    public ConcurrentRuntime Runtime { get; }              // W18 执行器
    public List<string> AuditLog { get; }=new();
    public VirtualClusterTool(/* 注入各模块 */){ /* 组装, 订阅彼此事件 */ }

    public RunReport RunNormal(string srcPort,string dstPort,ProcessJobDefinition def)
    {
        // 1 物理上料->Loaded (E84/E87)
        var src=Carriers.OnPhysicalPlaced(srcPort); Carriers.VerifyReservation(srcPort);
        var loaded=Carriers.ToLoaded(srcPort); Assert(loaded);
        var dst=Carriers.OnPhysicalPlaced(dstPort); Carriers.ToLoaded(dstPort);
        Audit("E87 源/目标载具 Loaded");

        // 2 E90 注册 + 基线
        Tracker.OnCarrierLoaded(srcPort); Tracker.OnCarrierLoaded(dstPort);
        int baseline=Tracker.TotalCount; Audit($"E90 注册, 基线{baseline}");

        // 3 建PJ静态校验 -> 4 开工双校验 -> Start
        var issues=PjMapValidator.Validate(def); Assert(!issues.Any());
        var job=ProcessJobController.Create(def);
        Assert(job.StartGuard(Tracker,Carriers));           // 载具绑定/配方/资源/Hold
        job.Start(); Audit("E40 PJ Start -> Executing");

        // 5+6 多腔并发执行 + 跨载具搬运(内部逐拍守恒)
        Runtime.Execute(job); Audit("多腔并发执行完成");

        // 7 严格完成
        var(ok,reasons)=new CompletionGuard(Tracker).Evaluate(job,dataComplete:true,noBlockingIssue:true);
        Assert(ok,string.Join(';',reasons)); Audit("严格完成门通过 -> Completed");

        // 8 下料门
        Assert(new UnloadGuard(Tracker,Carriers).CanUnload(dstPort));
        Carriers.Unload(dstPort); Audit("UnloadGuard 放行 -> E87 Unload");
        return RunReport.Build(job,Tracker,AuditLog);
    }
    static void Assert(bool c,string? m=null){ if(!c)throw new InvalidOperationException("端到端门控失败:"+m); }
    void Audit(string s){AuditLog.Add(s);}
}
public sealed class RunReport
{ public int Baseline,FinalInside; public bool Conserved,AllAtDestination,Completed; public int Makespan; public List<string> Timeline=new();
  public static RunReport Build(ProcessJob j,SubstrateTracker t,List<string> log)=>new()
  { FinalInside=t.TotalInside, Conserved=t.AssertInvariantsSafe(), AllAtDestination=j.AllAtDestination(t),
    Completed=j.State==JState.Completed, Timeline=log }; }
```

### happy path xUnit
```csharp
public class EndToEndNormalTests
{
    [Fact] public void 六片源A到目标B_全程门控_严格完成_守恒()
    { var cell=VirtualClusterToolFactory.Build3Chamber();
      var def=PjLab.CrossCarrierJob(jobId:"PJ1",src:"A",dst:"B",wafers:Enumerable.Range(1,6).Select(i=>$"W{i}"));
      var rep=cell.RunNormal(srcPort:"LP1",dstPort:"LP2",def);
      Assert.True(rep.Completed);
      Assert.True(rep.AllAtDestination);
      Assert.Equal(0,rep.FinalInside);          // 设备内全空
      Assert.True(rep.Conserved);               // 守恒
      Assert.Contains(cell.AuditLog,x=>x.Contains("UnloadGuard"));
    }
    [Fact] public void 非Loaded载具_开工门拒绝()
    { var cell=VirtualClusterToolFactory.Build3Chamber();
      var def=PjLab.CrossCarrierJob("PJ","A","B",new[]{"W1"});
      cell.Carriers.OnPhysicalPlaced("LP1");    // 只Installed不Loaded
      Assert.Throws<InvalidOperationException>(()=>cell.RunNormal("LP1","LP2",def)); }
}
```

## 三、端到端阶段门（手绘参考）
```
E84 Deposit去抖在位 → E87 Installed→预约核对→Loaded
 → E90注册SlotMap+基线
 → E40 静态六校验→Create → 开工双校验→Start(Executing)
 → W18多腔并发(选腔/流水线/双臂/双锁, 每拍守恒, S16进度)
 → W15跨载具(AtPick读码/AtPlace读回/全局守恒)
 → W17严格完成五条件 → Completed
 → UnloadGuard(任务完/片归位/臂原点/门关/无Hold) → E87 Unload → E84 Pickup
单一事实源: 位置问E90 / 任务问E40-FSM / 载具问E87; 跨域只调公开方法+订阅事件
```

## 四、今日易错点
1. 集成时在 E40 里直接改片位置（必须调 E90，跨域只走公开方法+事件）。
2. 模块双向依赖、硬连（依赖单向、接口/事件解耦，便于独立测试替换）。
3. 跳过 E87 授权直接对 Installed 载具取片（必须 Loaded）。
4. 把静态校验当开工校验（定义自洽≠此刻现场可执行，两道都要）。
5. UnloadGuard 条件不全就放行（片未归位/臂未原点/有 Hold 都不能下料）。
6. 只断言 Job.Completed 不查物理归位与守恒（严格完成要位置+终验+数据一起）。
7. 门控不 fail-closed（门不过必须阻断，不能"先继续再说"）。
8. 不留统一事件时间线（无法回放/排障/审计/映射 S16）。
