# W19 · Day05 答案与参考实现

## 一、自测题标准答案
1. **S14/S15/S16 序列**：①Host 用 S14F1/F3 取 ProcessJob 对象类与属性定义（S14F2/F4 返回定义，空集合回 L,0）；②Host S15F1/F3 发 Create 带初始属性（源目映射、路线、LotId 等），设备校验后回 ACKC（0 成功，缺必填回 6、类型不符回 7、已存在回 3），PJ 实例处于 Queued；③Host S15F9/F10 调 Start 方法，设备回 ACKC=0 表受理，状态机迁移后发 S16F1（Started，带 OBJSPEC/CEID/属性快照）；④执行中每次 Step 进入、片完成、暂停、完成/中止都由状态迁移触发 S16F1，Host S16F2 确认；⑤Host 可 S15F5/F6 查属性、F7/F8 原子改可写属性；⑥终态后对象保留可查或按策略删（S15F3/F4）。
2. **F10 不代表生效 / Pause 例**：S15F10 的 ACKC=0 只表示"方法名存在、参数合法、当前允许受理该请求"，是同步受理应答；方法真正完成往往依赖异步物理过程。以 Pause 为例：ACKC=0 时任务只是进入 Pausing，当前片可能正在不可中断的腔体工艺中，必须等它走到安全点，状态机才迁到 Paused 并发 S16F1（Paused）。Host 若把 F10=0 当成"已暂停"就会误判（以为能安全开罩/下料，实际还在加工）。正确做法是等 Paused 的 S16F1 作为生效事实。
3. **S2F41/F42/S6F11 作用**：S2F41 是 Host 下发远程命令（RCMD+CP 参数），如 START_PJ/PAUSE_PJ；S2F42 是设备对该命令的同步应答（ACKC10，0=已接受、非 0=拒绝原因），只表受理；命令真正执行完成后，设备发 S6F11 事件报告（携带对应 CEID 与报告数据）作为完成事实。即 F41 是请求、F42 是"收到且接受"、S6F11 才是"做完了"，同样是受理与生效分离，Host 以 S6F11 为准。
4. **S16F1 与 S6F11 关系 / 一致性**：S16F1 是 E39 OSS 的对象事件（面向对象模型，告诉 Host 哪个对象实例发生了哪个 CEID 及属性快照）；S6F11 是 GEM 事件报告（面向采集，按 CEID→RPTID→VID 组织的报告数据）。同一业务点（如片完成）两者都会发。一致性保证：**只在状态机迁移成功后触发，且两者都从同一个权威状态对象现取数据**（同一份 Job/片状态、同一时间戳/事件序号），而不是各自维护一份副本；这样 OSS 对象视图与采集报告数值必然一致，也便于下游关联。
5. **ACKC 3/5/8/10 场景**：3 已存在——用相同 JobId 再 Create 一个 ProcessJob；5 只读——S15F7 试图改 State/进度等只读属性（状态只能由状态机迁移改变）；8 状态非法——对已 Completed/Aborted 终态 PJ 调 Start，或对 Queued（未启动）调 Resume；10 参数错——调 Start 方法时 CP/参数缺失、JobId 找不到对应实例、枚举值非法。（另：6 缺必填=Create 时没给源目映射；7 类型不匹配=进度本应数值却给字符串。）
6. **迁移成功后才发事件**：命令到达时状态未必能改变（Guard 可能拒绝、可能要等安全点），若收到命令就发"已开始/已暂停"事件，而状态实际没迁移成功，就会对外谎报状态，Host 据此决策出错。先让状态机原子迁移成功（Guard 通过、进入新状态），再发事件，保证"事件所述即状态实际"，事件不会领先或背离状态；迁移失败则不发该事件、回拒绝，零副作用。这也是单一状态写入口的要求。
7. **片级数据随 WaferDone 上报 / 下游**：WaferDone 时携带该片经过的实际腔体、配方版本、加工起止时间、关键工艺参数与量测结果、片最终位置等。下游：FDC 据此做故障检测与分类（关联腔/参数异常）、YMS 做良率管理（把结果与设备/腔/配方/时间关联做良率归因）、R2R 据此计算下一片/下一批的参数偏移、MES 据此更新每片工序状态与流向（分档/返工）。这些数据必须在片完成时点及时、完整、带身份上报，否则 APC 闭环和良率追溯失去依据。

## 二、参考实现（net8.0）

### S15 方法受理 → 状态机 → S16 事件
```csharp
namespace EapLab.Cell.Host;
public enum Ackc { Ok=0, NoClass=1, NoInstance=2, AlreadyExists=3, NoAttr=4, ReadOnly=5,
                   MissingRequired=6, TypeMismatch=7, IllegalState=8, NoMethod=9, BadParam=10, Internal=99 }
public sealed class PjHostService
{
    private readonly Dictionary<string,ProcessJob> _jobs=new();
    private readonly JobStateMachines _fsms=new();
    public event Action<string,PjEvent>? OnS16;       // OBJSPEC, 事件
    public Ackc Create(string jobId,ProcessJobDefinition def)
    { if(_jobs.ContainsKey(jobId))return Ackc.AlreadyExists;
      var issues=PjMapValidator.Validate(def); if(issues.Any(i=>i.Code==PjIssueCode.MissingRequired))return Ackc.MissingRequired;
      if(issues.Any())return Ackc.TypeMismatch;
      _jobs[jobId]=ProcessJobController.Create(def); _fsms.Bind(jobId,new JobStateMachine()); return Ackc.Ok; }

    public Ackc InvokeMethod(string jobId,JobCommand cmd)   // S15F9/F10: 仅受理
    { if(!_jobs.TryGetValue(jobId,out var job))return Ackc.NoInstance;
      var fsm=_fsms.Of(jobId);
      if(cmd is JobCommand.Start && !fsm.CanStart)return Ackc.IllegalState;
      if(!fsm.Try(cmd))return Ackc.IllegalState;            // Guard拒绝=状态非法, 零副作用
      return Ackc.Ok; }                                     // 受理; 生效以S16为准
    internal void RaiseAfterTransition(string jobId,PjEvent ev){ OnS16?.Invoke(jobId,ev); }
}
```

### S2F41 远程命令桥
```csharp
public sealed record RemoteCommand(string Rcmd,Dictionary<string,string> Cp);
public sealed class RemoteCommandBridge
{
    private readonly PjHostService _svc; public RemoteCommandBridge(PjHostService s){_svc=s;}
    public int Accept(RemoteCommand rc)   // S2F42 ACKC10: 0受理
    { var map=new Dictionary<string,JobCommand>(StringComparer.OrdinalIgnoreCase)
      { ["START_PJ"]=JobCommand.Start,["PAUSE_PJ"]=JobCommand.Pause,
        ["RESUME_PJ"]=JobCommand.Resume,["CANCEL_PJ"]=JobCommand.Cancel,["ABORT_PJ"]=JobCommand.Abort };
      if(!map.TryGetValue(rc.Rcmd,out var cmd))return 9;     // 未知命令
      if(!rc.Cp.TryGetValue("JobId",out var id)||string.IsNullOrEmpty(id))return 10;
      return (int)_svc.InvokeMethod(id,cmd);                 // 受理; 完成靠S6F11
    }
}
```

### 采集联动：迁移点同源发 S16 与 S6F11
```csharp
public enum PjCeid { Started=5101,StepEnter=5102,WaferDone=5103,JobDone=5104,Paused=5105,Aborted=5106 }
public sealed class CollectionLink
{
    public List<(PjCeid ceid,Dictionary<string,object> vid)> S6Reports { get; }=new();
    public Dictionary<string,object> Snapshot(ProcessJob j)=>new()
    { ["JobId"]=j.Id,["State"]=j.State.ToString(),["CurWafer"]=j.CurWafer??"",
      ["CurStep"]=j.CurStepNo,["Progress"]=j.Progress,["Completed"]=j.CompletedCount };
    public void OnTransition(string id,ProcessJob job,PjCeid ceid,Action<string,PjEvent> s16)
    { var snap=Snapshot(job);                              // 同源现取
      s16(id,new PjEvent((int)ceid,snap));                 // S16F1
      S6Reports.Add((ceid,snap)); }                        // S6F11(同一份数据)
}
```

## 三、Host 交互闭环（手绘参考）
```
S14取定义 → S15F1 Create(ACKC: 3已存在/6缺参/7类型错) → Queued
S2F41 START_PJ → S2F42 ACKC=0(仅受理) → 状态机Start成功
   → 同源发 S16F1(Started) + S6F11(5101, VID快照)
每步/片: 迁移成功 → S16F1 + S6F11(5102/5103, 带腔/配方/量测)
PAUSE: F41→F42受理→Pausing→安全点→S16/S6F11(5105 Paused生效)
RESUME→... ; 全片完成→5104 JobDone; Abort→5106
铁律: 先状态迁移成功后发事件; S16与S6F11同一权威状态现取; 序号单调+Spool
Host: 应答=受理, S16/S6F11=生效事实
```

## 四、今日易错点
1. 把 S15F10/S2F42=0 当完成（只是受理，生效看 S16/S6F11）。
2. 收到命令就发事件（必须状态迁移成功后发，失败零副作用不发）。
3. S16 与 S6F11 各存一份数据导致不一致（同一权威状态同源现取）。
4. ACKC 用错（终态操作=8 状态非法、改只读=5、重复创建=3、缺参=10/6）。
5. 允许直接改 State 属性（状态只读，只能状态机迁移）。
6. 远程命令不校验 RCMD/CP（未知命令、缺 JobId 要明确拒绝码）。
7. 片级数据不在 WaferDone 带齐（FDC/YMS/R2R/MES 失去追溯与闭环依据）。
8. 事件不编号/不接 Spool（断线丢事件、重连无法去重补齐）。
9. 空集合不回 L,0（S14 查询空结果的规范应答）。
