# W19 · Day03 答案与参考实现

## 一、自测题标准答案
1. **统一六步 / 安全优先**：①第一时间停止危险动作（停运动/停工艺输出、保压/泄能，保证人和设备安全）；②把片移到安全确定位置或在当前稳定位安全保持；③让状态机迁移到确定状态（Pausing/Paused/Failed/Aborted，不允许停在模糊中间态）；④冻结现场快照（每片实际位置/Step/资源/事件/守恒）；⑤守恒核对（唯一/容量/总数）；⑥按恢复路径处理（Resume/Rollback/改派/人工）。安全永远先于继续生产，因为片报废、设备损坏、人员受伤不可逆，而停产的损失可恢复；任何自动恢复逻辑都建立在"先进入安全态"之上，绝不能为了不停机而在危险/不确定状态下继续动作。
2. **腔故障三时机**：等待（片还在源/锁/臂、未进腔）——纯计划变更，排除故障腔、选健康同型腔改派，片无损；在腔（片正在腔内加工时故障）——工艺中断、状态未知，走故障处置：判断该步完成/需返工/报废，安全撤出到稳定位或保持，发 Alarm/Fault、记中断点，不能直接换腔续；加工后待归位（片已加工完、尚未离开腔/刚出腔）——工艺有效则优先安全取出归位并标记完成，若取出机构受同一故障影响则安全保持，已完成成果尽量保留。差别核心是"片是否已被故障物理影响"。
3. **局部 vs 全局边界 / 健康片继续条件**：局部故障只涉及某个可隔离资源（单腔、单臂的一侧、某载具），且隔离后其他资源仍能在不违反安全与不变式的前提下运行，则只隔离故障资源、其他健康片继续（如 C2 故障，C1/C3 继续，等待 C2 的片改派）；全局异常影响共用安全基础（真空系统、安全门、整机电源/控制、唯一真空臂故障导致无法搬运）时，全线到安全点。健康片继续的条件：其路径不依赖故障资源、资源调度能重排且仍守互斥/守恒、无共同安全风险。
4. **故障+Pause 顺序/终态**：先响应安全——对故障片做故障处置（撤到安全位/保持、标记受影响不可自动续），同时让所有其他在执行并发单元走到各自安全点（工艺到边界、运动到位）；当全部单元（含故障片）都处于安全确定状态后，整体进入 Paused，并在 ResumeToken/快照中标注存在故障片与故障资源。Resume 时故障片不会被自动续跑（需先处理故障/返工决策），其余健康片在资源恢复或改派后可续。即"故障处置"和"暂停到安全点"都完成后才 Paused，不能带着运动中/反应中的片暂停。
5. **Abort 时目标载具被卸 / 为何不能自动退**：在途片的计划目标槽随载具消失，若它来自源载具且源仍在、路径安全，可退回源；若源也不在、或片在真空侧无法回到已卸载目标，就没有合法的确定位置可自动放置，此时必须把片安全保持在设备内稳定位（锁/Buffer/腔）、锁定设备、冻结快照转人工。不能"自动退"是因为自动动作需要确定、合法、物理可达且守守恒的目标槽，目标/源缺失时任何猜测性放置都可能丢片、叠片或把片送到错误盒，属于身份/归属存疑，按 fail-safe 只能安全保持等待人工确认现场。
6. **双臂各持片掉电恢复**：①不假设逻辑进度，重启读传感器：两臂各持没持片、持的是谁（读码）、各腔/锁有无片；②重建 E90 位置空间，把两臂持片建模为两个内部位置（各容量 1），做全局守恒核对（片总数对、无一片两位置）；③结合持久化进度判断 Swap 进行到哪一步（旧片是否已取出、新片是否已放入、目标腔是否空）；④若腔空且身份明确，从"换位放入新片/送走旧片"的安全边界续做或逐片安全归位；⑤若读不清身份或腔是否空存疑，安全保持转人工，绝不盲目往腔内放片（防叠片）。恢复幂等，多次重启结论一致。
7. **无未定义分支 / 兜底**：真实生产中异常会以任意时机、任意组合出现，若存在没设计到的（异常×时机×并发状态）组合，程序会落到未知状态、可能做出危险动作或卡死且片去向不明，这是最危险的。所以异常矩阵要枚举所有组合并为每格指定确定处置；对穷尽不了或无法保证安全自动处理的情况，统一兜底为 **fail-safe 安全保持**：停止自动动作、片在当前稳定位保持、锁设备/载具、报警转人工，并保留完整快照。宁可保守停机由人处理，也不让系统在未定义状态下"猜着继续"。

## 三、参考实现（net8.0，异常处置骨架）
```csharp
namespace EapLab.Cell;
public enum FaultScope { Local, Global }
public sealed class ExceptionHandler
{
    private readonly SubstrateTracker _t; public ExceptionHandler(SubstrateTracker t){_t=t;}

    // 局部资源故障: 返回受影响片; 等待片改派由调度器处理, 健康片继续
    public List<string> OnResourceFault(string resource,FaultScope scope,ProcessJob job,
        Dictionary<string,string> waferResource)
    {
        var affected=waferResource.Where(kv=>kv.Value==resource).Select(kv=>kv.Key).ToList();
        foreach(var w in affected)
        { var loc=_t.LocationOf(w).Key;
          if(loc.Contains(resource) && IsProcessing(loc))   // 在故障资源内加工: 故障处置, 不改派
              job.MarkWaferFaulted(w,"工艺中断,需返工/报废决策");
          // 尚未进入者不在此列, 由调度器改派
        }
        if(scope==FaultScope.Global) job.RequestSafeStopAll(); // 全局: 全线到安全点
        _t.AssertInvariants();
        return affected;
    }

    // 叠加: 故障 + Pause —— 全部单元(含故障片)安全后才Paused
    public bool TryPausedAfterFault(ProcessJob job,ConcurrentPauseBarrier barrier)
    { if(!barrier.AllSafe) return false;
      if(job.HasFaultedWafer) job.MarkResumeBlocked("存在故障片,Resume不自动续该片");
      job.ToPaused(); return true; }

    // 归属缺失: 无合法目标 -> fail-safe安全保持, 不猜
    public void SafeHold(string wafer,string why)
    { if(!_t.IsAtStableInternalPosition(wafer)) throw new InvalidOperationException("片不在稳定位,先安全到位");
      _t.HoldWafer(wafer); throw new ManualInterventionRequired(wafer,why); }
}
public sealed class ManualInterventionRequired:Exception
{ public string Wafer; public ManualInterventionRequired(string w,string why):base($"{w}需人工:{why}"){Wafer=w;} }
```

## 四、异常矩阵推进流程（手绘参考）
```
异常发生 → 判范围(局部隔离/全局安全停) × 时机(动作前/在途/在腔/待归位/终验)
  → 停危险动作 → 片到安全位或保持 → 状态机到确定态 → 冻结快照 → 守恒核对
  → 恢复: 等待片改派 / 在腔片故障处置 / 无合法归处→fail-safe安全保持转人工
叠加(故障+Pause / Abort+丢载具 / 双臂持片掉电):
  不允许未定义分支; 所有单元安全+守恒成立才迁移; 身份/归属存疑一律人工
```

## 五、今日易错点
1. 为不停机在危险/不确定状态下继续动作（安全先于生产，先到安全态）。
2. 异常后 Job 停在模糊中间态（必须迁移到确定状态并冻结快照）。
3. 把在腔故障片直接改派别的腔（工艺中断状态未知，走故障处置）。
4. 局部故障误停全线、或全局故障只隔离单资源（按依赖与安全边界判范围）。
5. 叠加异常只处理一个、漏掉另一个（故障处置+到安全点都完成才 Paused）。
6. 目标/源缺失时猜测性放片（无合法归处必须安全保持人工）。
7. 双臂持片掉电按逻辑进度盲目续（物理读码重建、腔空才放）。
8. 异常路径不做守恒断言（异常最易丢叠片，更要每步查不变式）。
9. 矩阵存在"未定义组合"（穷尽+fail-safe 兜底，不留未知分支）。
