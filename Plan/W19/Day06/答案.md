# W19 · Day06 答案与参考实现

## 一、自测题标准答案
1. **为何多 PJ 混合**：设备有多个 LoadPort、不同批次载具同时在位，若一个 PJ 全做完才做下一个，当该 PJ 因等载具、等某腔、片不足而出现空隙时，其他腔/臂就闲置，整体产能低。多 PJ 混合让设备在资源允许时并行推进不同批次的片，用一个 PJ 的片去填补另一个 PJ 的等待空隙，保持瓶颈资源持续忙碌，从而提升设备利用率与产出。本质是用多任务负载填满流水线、消除非瓶颈空闲。
2. **全局日历 vs 单 PJ / 仲裁链**：单 PJ 调度只在一个任务的动作间排资源，看不到其他 PJ，两个 PJ 会各自认为某腔空闲而冲突；全局资源日历是设备级唯一的，所有 PJ 的动作都向它申请区间，统一裁决。仲裁优先级链：①可行性（资源容量/互斥、拓扑可达、前驱依赖满足，硬约束）→②任务/动作优先级（急单/Lot 优先级）→③公平（同级 FIFO+老化防饥饿）→④确定性 tie-break（固定 ID 序，结果可复现）。死锁规避仍用全局资源全序+all-or-nothing，只是范围扩到所有 PJ。
3. **独立/依赖调度 / 最早开始**：独立 PJ 用不同载具、无片流转，只共享资源，动作之间无先后约束，可在资源空闲时自由并行；依赖 PJ 中后继 PJ-B 的输入是前驱 PJ-A 的输出（如先 A 蚀刻、后 B 清洗），用依赖图 DAG 约束，B 的相关动作必须等 A 对应片完成并到达指定位置才能开始。进入最早开始时间计算时，一个动作的 ready=max(资源日历给出的最早空闲时间, 所有前驱动作完成时间的最大值)，即同时满足"资源可用"和"前驱就绪"两个条件后才能开始。
4. **上下料重叠 / 条件**：LoadPort 的 E84 物理交接、E87 上料/下料使用的是端口/AMHS 通道，与机内腔/真空臂加工资源不相交，因此一个载具在机内加工时，可在空闲口并行完成另一载具的交接上料、或对已满足 UnloadGuard 的成品载具下料（换盒不停车）。条件：①使用不同 LoadPort、资源不冲突；②下料载具必须先满足 UnloadGuard（相关 PJ 全完成、片全归位、臂原点、门关、无 Hold），不能因下料取走机内还有片的载具；③上料走完整 E84→E87 Loaded→E90 注册门；④端口交接与机内动作的共用资源（如 EFEM 大气臂若同时用于取片和上料）要进全局日历排时间，不真冲突。
5. **指标定义 / 瓶颈利用率**：Makespan=混合负载从首个动作开始到最后动作结束的总时长；稳态节拍=稳定状态下相邻产出片的时间间隔（瓶颈决定）；资源利用率=资源实际忙时间/总可用时间；WIP=设备内同时在制（已取离源、尚未归位）的片数。瓶颈决定整线节拍，若瓶颈利用率不到 100%（有空闲），说明它在等上游供片或被调度浪费，这段空闲直接等于产出损失、本可用来出片，所以优化目标就是让瓶颈接近 100% 忙；非瓶颈利用率低是正常的（它们本来就比瓶颈快、要等瓶颈），不必追求其 100%。
6. **如何证明全局调度更优**：在相同片数、相同工艺/搬运时间参数下，分别跑"单 PJ 串行（做完一个再下一个）"和"多 PJ 全局调度"，对比 Makespan（全局应更短）、瓶颈利用率（全局应更接近 100%、空闲空隙更少）、稳态节拍与单位时间产出（WPH，全局更高）；再做控制变量：开/关双锁乒乓、亲和/均衡选腔，量化每项策略对 Makespan/利用率的改善。用同一逻辑时钟、同一随机剧本（确定性）对比，结论可复现，从而定量证明全局调度通过填平瓶颈空闲提升了产能。
7. **与 E94 关系**：今天的"全局多 PJ 资源调度 + PJ 间依赖 DAG + 多载具协同 + 优先级公平"正是 E94 ControlJob 的内核——CJ 的职责就是编排多个 ProcessJob（跨载具、规定顺序与依赖、统一调度）。区别是今天用教学代码实现机制，W20 起用 SEMI E94 标准对象/状态机/控制作业模型把它正式化（ControlJob 包含多个 ProcessJob、CJ 状态机级联 PJ 状态机、跨载具流程），即今天是"原理实现"，E94 是"标准形态"，学 E94 时会把今天的全局调度器映射成标准 ControlJob 编排。

## 二、参考实现（net8.0）

### 设备级全局调度（多 PJ）
```csharp
namespace EapLab.E40.Sched;
public sealed class GlobalMultiJobScheduler
{
    private readonly Dictionary<string,ResourceCalendar> _cal;     // 设备级唯一资源日历
    private long _tie;
    public GlobalMultiJobScheduler(IEnumerable<Resource> rs){_cal=rs.ToDictionary(r=>r.Id,r=>new ResourceCalendar(r.Id,r.Capacity));}

    public int Schedule(MJobOp op)   // 跨所有PJ统一仲裁
    {
        int start=Math.Max(op.ReadyAt,op.PredDoneAt);
        foreach(var r in op.Needs.OrderBy(x=>x,StringComparer.Ordinal)) // 全局固定顺序防死锁
            start=_cal[r].EarliestStart(start,op.Duration);
        foreach(var r in op.Needs) _cal[r].Book(start,start+op.Duration);
        op.Start=start; op.End=start+op.Duration; op.Order=_tie++;
        return start;
    }
}
public sealed class MJobOp
{ public string JobId=""; public string Wafer=""; public List<string> Needs=new(); public int Duration,ReadyAt,PredDoneAt,Priority,Arrival;
  public int? Start,End; public long Order; }
```

### PJ 依赖 DAG
```csharp
public sealed class JobDag
{
    private readonly Dictionary<string,List<string>> _succ=new();   // A->B
    public JobDag Depends(string before,string after){ if(!_succ.ContainsKey(before))_succ[before]=new(); _succ[before].Add(after); return this; }
    public List<string> Topo()   // 拓扑排序, 有环报错
    { var indeg=new Dictionary<string,int>();
      foreach(var kv in _succ) indeg.TryAdd(kv.Key,0);
      foreach(var kv in _succ) foreach(var b in kv.Value) indeg[b]=indeg.GetValueOrDefault(b)+1;
      var q=new Queue<string>(indeg.Where(x=>x.Value==0).Select(x=>x.Key).OrderBy(x=>x));
      var res=new List<string>();
      while(q.Count>0){ var a=q.Dequeue(); res.Add(a);
        foreach(var b in _succ.GetValueOrDefault(a,new())) if(--indeg[b]==0)q.Enqueue(b); }
      if(res.Count!=indeg.Count)throw new InvalidOperationException("依赖有环");
      return res; }
}
```

### 指标统计
```csharp
public sealed class PerfMetrics
{
    public int Makespan(IEnumerable<MJobOp> ops)=>ops.Max(o=>o.End??0);
    public double Utilization(string resource,IEnumerable<MJobOp> ops,int horizon)
    { int busy=ops.Where(o=>o.Needs.Contains(resource)).Sum(o=>(o.End!-o.Start!));
      return horizon==0?0:Math.Round(100.0*busy/horizon,1); }
    public int Beat(string resource,IEnumerable<MJobOp> ops)
    { var ends=ops.Where(o=>o.Needs.Contains(resource)).Select(o=>o.End!.Value).OrderBy(x=>x).ToList();
      return ends.Count<2?0:ends.Zip(ends.Skip(1),(a,b)=>b-a).Max(); }
    public double Wph(int wafers,int makespanSec)=>Math.Round(3600.0*wafers/makespanSec,1);
}
```

## 三、多 PJ 全局视图（手绘参考）
```
LP1: Lot-A ─ PJ1 ┐
                ├─ 全局资源日历(设备唯一): C1/C2/C3,VR,LL1/LL2,EFEM 统一仲裁
LP2: Lot-B ─ PJ2 ┘   可行性→优先级→同级FIFO+老化→确定性tie-break
PJ依赖DAG: A(蚀刻)输出 → B(清洗)输入; ready=max(资源空闲,前驱完成)
端口重叠: 机内加工(真空侧) ‖ 空闲口E84/E87上下料(大气侧), 共用EFEM进日历
指标: Makespan / 节拍(瓶颈) / 利用率(瓶颈≈100%) / WIP / WPH
→ 即 E94 ControlJob 编排内核(W20标准化)
```

## 四、今日易错点
1. 每个 PJ 各用一个资源日历（跨 PJ 会冲突，必须设备级唯一全局日历）。
2. 只按优先级不做公平老化（低优先级 PJ 被饿死）。
3. 忽略 PJ 间依赖，后继在前驱输出前就取片（ready 要 max 资源与前驱）。
4. 依赖图成环不检测（拓扑排序发现环要报错）。
5. 上下料与机内动作的共用资源（EFEM）不排期（声称并行实则冲突）。
6. 未满足 UnloadGuard 就下料取走机内有片的载具。
7. 追求所有资源利用率 100%（只瓶颈需要，非瓶颈空闲正常）。
8. 不用同参数/确定性剧本对比就下"优化有效"结论（控制变量、可复现）。
9. 把多 PJ 全局调度当成新东西另起炉灶（它就是 E94 CJ 编排内核，保持同一资源/状态/守恒框架）。
