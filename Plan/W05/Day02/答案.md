# W05 · Day02 答案与参考实现

## 一、自测题标准答案
1. **Select 成功后是否就 ON-LINE**：**不是**。HSMS Select 成功只进入 SELECTED（传输层选通），还需要：①S1F13/F14 建立通信（交换身份）；②S1F17/F18 请求在线（设备接受后才进入 GEM ON-LINE）。三步完成后 Host 才能发控制命令。
2. **S1F13 vs S1F17**：S1F13（Establish Communications）是**建立通信身份**，Host 和设备交换 MDLN/SOFTREV，body 是 `L,2[A MDLN, A SOFTREV]`；S1F17（Request On-line）是**请求设备进入在线状态**，body 为空，设备回 S1F18 带 ACKC1 确认码。S1F13 不改变 GEM 通信状态，S1F17 成功后才从 OFF-LINE→ON-LINE。
3. **ACKC1=0/=1 含义 / Host 收到 =1 怎么做**：ACKC1=0=**接受**在线/离线请求，状态切换；ACKC1=1=**拒绝**（设备不允许进入该状态，可能设备正在运行、有报警、或配置为不允许 Host 控制）。Host 收到 =1 后：记日志告警，不切换状态，根据业务决定重试、通知操作员、或检查设备状态后再请求。
4. **设备主动 OFF-LINE 会发 S1F15 吗 / Host 怎么知道**：**不会发 S1F15**（S1F15 是 Host→设备的请求）。设备主动 OFF-LINE（如急停、故障）时，直接切换内部状态，通常通过**S6F11 事件上报**（如果定义了"状态变化"事件 CEID）通知 Host；Host 也可以通过**查询状态变量(SV)**主动发现。后续 Host 发控制命令会被设备拒绝（ACKC 非 0）。
5. **S1F1 vs S1F13**：S1F1（Are You There）是**轻量级探测**，body 为空，设备回 S1F2 带身份，不改变任何状态，可随时发；S1F13（Establish Communications）是**正式建立通信**，Host 带自己的身份，设备回身份，双方确认通信关系，通常在 Select 后、S1F17 前发，是建链流程的正式步骤。S1F1 可以重复发，S1F13 通常在建链时发一次。
6. **哪步失败导致"能 ping 通但发命令没反应"**：最可能是 **S1F17 被拒绝（ACKC1=1）或没发 S1F17**——设备停在 OFF-LINE，能 ping 通、能 Select、能收消息，但拒绝执行远程命令。也可能是 S1F13 没成功（身份不匹配），或设备控制状态停在 EQUIPMENT OFF-LINE。排查顺序：ping→TCP→Select→S1F13→S1F17(ACKC)→控制状态。

## 二、参考实现（EapLab.Gem/Messages/）

### S1 消息处理（设备端）
```csharp
using EapLab.Secs2.Items;
using EapLab.Secs2.Transaction;

namespace EapLab.Gem.Messages;

public sealed class S1Handler
{
    private readonly GemStateMachine _gem;
    private readonly string _mdln = "EAP-SIM-01";
    private readonly string _softrev = "1.0.0";

    public S1Handler(GemStateMachine gem) => _gem = gem;

    /// <summary>设备端收到 S1 primary 后调用，返回 reply body。</summary>
    public SecsItem? HandlePrimary(byte f, SecsItem? body) => f switch
    {
        1  => HandleAreYouThere(),          // S1F1
        13 => HandleEstablishComm(body),    // S1F13
        15 => HandleRequestOffline(),        // S1F15
        17 => HandleRequestOnline(),         // S1F17
        _  => null                            // 不支持，上层回 S9F5
    };

    private SecsItem HandleAreYouThere()
        => Secs.L(Secs.A(_mdln), Secs.A(_softrev));

    private SecsItem HandleEstablishComm(SecsItem? body)
    {
        // body 是 Host 的 MDLN/SOFTREV，记录下来用于日志/审计
        if (body is SecsList list && list.Count >= 2)
        {
            // 可提取 Host 身份：list.Items[0] as SecsAscii
        }
        _gem.OnCommEstablished();   // 标记通信已建立（不改变 ONLINE 状态）
        return Secs.L(Secs.A(_mdln), Secs.A(_softrev));
    }

    private SecsItem HandleRequestOffline()
    {
        bool ok = _gem.RequestOffline();
        byte ackc = ok ? (byte)0 : (byte)1;
        return Secs.L(Secs.U1(ackc), Secs.A(ok ? "OK" : "Rejected"));
    }

    private SecsItem HandleRequestOnline()
    {
        bool ok = _gem.RequestOnline();
        byte ackc = ok ? (byte)0 : (byte)1;
        return Secs.L(Secs.U1(ackc), Secs.A(ok ? "OK" : "Rejected"));
    }
}
```

### Host 端建链流程
```csharp
public async Task<bool> EstablishFullLinkAsync(HsmsConnection conn)
{
    // 前提：HSMS 已 SELECTED（W2 完成）

    // 1. S1F13 建立通信
    var s1f13Body = Secs.L(Secs.A("HOST-MDLN"), Secs.A("2.0.0"));
    var s1f14 = await conn.SendAndWaitReply(1, 13, s1f13Body, TimeSpan.FromSeconds(10));
    if (s1f14 == null) { _log.Err("S1F13 失败"); return false; }
    _log.Evt("S1F13 成功，设备身份已交换");

    // 2. S1F17 请求在线
    var s1f18 = await conn.SendAndWaitReply(1, 17, null, TimeSpan.FromSeconds(10));
    if (s1f18 == null) { _log.Err("S1F17 超时"); return false; }
    // 解析 ACKC1：L,2[U1 ACKC1, A ERRMSG]
    byte ackc = ExtractAckc(s1f18);
    if (ackc != 0) { _log.Err($"S1F17 被拒绝，ACKC1={ackc}"); return false; }

    _log.Evt("GEM ON-LINE，建链完成");
    return true;
}
```

### GemStateMachine 关键方法（Day05 完整实现，这里先给接口）
```csharp
public sealed class GemStateMachine
{
    public GemCommState CommState { get; private set; } = GemCommState.Offline;
    public bool CommEstablished { get; private set; }

    public void OnCommEstablished() => CommEstablished = true;

    public bool RequestOnline()
    {
        if (CommState == GemCommState.Online) return true;  // 已经在线
        // 实际设备可能有条件：无急停、无严重报警、配置允许
        CommState = GemCommState.Online;
        return true;
    }

    public bool RequestOffline()
    {
        if (CommState == GemCommState.Offline) return true;
        CommState = GemCommState.Offline;
        return true;
    }

    public void EquipmentInitiatedOffline()  // 设备主动 OFF-LINE（急停等）
    {
        if (CommState == GemCommState.Online)
        {
            CommState = GemCommState.Offline;
            // 触发状态变化事件，通过 S6F11 上报 Host
        }
    }
}
```

## 三、完整建链流程预期日志
```
Host:  TCP Connect → OK
Host:  HSMS Select.req → Select.rsp(Status=0) → SELECTED
Host:  TX S1F13 W=1 sys=00000001 body=L,2[A"HOST",A"2.0"]
Equip: RX S1F13 → 记录 Host 身份 → TX S1F14 sys=00000001 body=L,2[A"EAP-SIM",A"1.0"]
Host:  RX S1F14 → 匹配 → 通信建立
Host:  TX S1F17 W=1 sys=00000002 body=空
Equip: RX S1F17 → 检查条件 → 接受 → GEM OFFLINE→ONLINE
Equip: TX S1F18 sys=00000002 body=L,2[U1=0, A"OK"]
Host:  RX S1F18 → ACKC1=0 → GEM ON-LINE
Host:  ═══ 建链完成，可发 S2F41/S2F33 等业务消息 ═══
```

## 四、ACKC1 速查卡
| ACKC1 | 含义 | 动作 |
|---|---|---|
| 0 | 接受（Accept） | 状态切换，继续业务 |
| 1 | 拒绝（Rejected） | 不切换状态，Host 记日志/重试/通知操作员 |
| 2 | 不支持（Not supported） | 设备不支持此命令，Host 不应重试 |
| 其他 | 设备特定原因 | 查设备手册 |

## 五、今日易错点
1. 以为 S1F13 成功就进入 ON-LINE（S1F13 只交换身份，ON-LINE 需要 S1F17）。
2. S1F17 body 带数据（应为空 body）。
3. 设备主动 OFF-LINE 时以为会发 S1F15（S1F15 是 Host→设备，设备主动 OFF-LINE 通过事件上报）。
4. ACKC1 非 0 也当成功（0 才是接受）。
5. 建链流程跳过 S1F13 直接发 S1F17（虽然部分设备允许，但标准流程应先 S1F13）。
6. S1F1 和 S1F13 混淆（一个是探测，一个是正式建链）。
