# W05 · Day06 答案与综合实验参考

## 一、自测题标准答案
1. **哪步失败导致"能 ping 通但发命令被拒绝"**：最可能是 **S1F17 被拒绝（ACKC1=1）或没发 S1F17**——设备停在通信 OFF-LINE，能 ping 通、能 Select、能收消息，但拒绝执行远程命令（回 ACKC10=4）。也可能是控制状态停在 EQUIPMENT OFF-LINE（设备在本地模式），此时通信 ON-LINE 但控制 OFF-LINE，S2F41 也被拒绝。排查顺序：ping→TCP→Select→S1F13→S1F17(ACKC)→控制状态。
2. **S1F18 ACKC1=0/=1 含义 / Host 收到 =1 怎么做**：ACKC1=0=**接受**在线请求，设备进入通信 ON-LINE；ACKC1=1=**拒绝**（设备不允许进入在线状态，可能有急停/严重报警/本地锁定/正在运行）。Host 收到 =1 后：记日志告警，通知操作员检查设备状态（急停、报警、本地/远程开关），等设备条件满足后再重试 S1F17；不应盲目死循环重发。
3. **ACKC10=0 是否表示执行成功 / Host 怎么知道结果**：**不是**。ACKC10=0 只表示"命令已被设备接受并排队"，是命令接受的确认，不是命令执行完成的确认。Host 通过 **S6F11 事件上报**知道命令执行结果——设备执行完命令后触发"命令完成"或"命令失败"事件（CEID），通过 S6F11 上报，Host 回 S6F12 确认。Host 也可以通过查询状态变量(SV)主动查询，但事件上报是标准方式。
4. **急停时通信/控制状态怎么变 / 正在执行的命令怎么处理**：急停时，控制状态**立即回 EQUIPMENT OFF-LINE**（设备进入安全状态）；通信状态**通常保持 ON-LINE**（急停不影响通信通道，Host 仍能收事件/报警、查询状态），除非设备配置为急停时也断通信。正在执行的命令被**中断**，设备发 S6F11 事件（命令失败，原因=急停/中断）通知 Host；Host 收到事件后记日志，命令标记为失败，后续 S2F41 会被拒绝（ACKC10=4）。
5. **控制状态切 ONLINE 时 Host 怎么知道 / 轮询还是事件**：标准方式是**事件上报**——设备控制状态变化时触发"控制状态变化"事件（CEID），通过 S6F11 上报给 Host，Host 回 S6F12 确认。Host 也可以通过查询状态变量(SV)轮询，但事件上报更及时、更省资源。前提是 Host 已通过 S2F33/S2F35 定义并关联了"控制状态变化"事件。如果没定义，Host 只能轮询或不知道。
6. **哪个场景最容易在现场出问题 / 为什么**：**场景3（控制 OFF-LINE→切远程→接受）**最容易出问题。因为现场设备经常在本地/远程模式之间切换，操作员可能忘了切远程，Host 发命令被拒绝后排查困难；而且控制状态变化事件可能没定义或没关联，Host 不知道设备何时切到远程，只能盲目重试或轮询。这也是现场"命令发不出去"的最常见原因之一——通信正常但设备在本地模式。

## 二、4 个场景的预期结果与日志

### 场景1：正常建链 + 远程命令
```
Host:  TCP Connect → OK
Host:  HSMS Select → SELECTED
Host:  TX S1F13 W=1 body=L,2[A"HOST",A"2.0"]
Equip: RX S1F13 → 记录 Host 身份 → CommEstablished=true
Equip: TX S1F14 body=L,2[A"EAP-SIM",A"1.0"]
Host:  RX S1F14 → 通信建立
Host:  TX S1F17 W=1 body=空
Equip: RX S1F17 → 检查条件 → 接受 → CommState OFFLINE→ONLINE
Equip: TX S1F18 body=L,2[U1=0,A"OK"]
Host:  RX S1F18 ACKC1=0 → 通信 ON-LINE
Equip: 操作员切远程 → ControlState OFFLINE→ONLINE → 触发事件
Equip: TX S6F11 body=L,3[U4=1,U2=3001,L,1[L,2[U2=1,L,1[A"ONLINE"]]]]
Host:  RX S6F11 → 控制 ONLINE → TX S6F12 body=U4=1
Host:  TX S2F41 body=L,2[A"START",L,3[L,2[A"LOTID",A"LOT001"],L,2[A"RECIPE",A"RCP_A"],L,2[A"QUANTITY",U2=25]]]
Equip: RX S2F41 → 校验状态/命令/参数 → 接受 → 排队执行
Equip: TX S2F42 body=L,2[U1=0,A"Command accepted"]
Host:  RX S2F42 ACKC10=0 → 命令已接受
Equip: 异步执行 START → 完成 → 触发事件
Equip: TX S6F11 body=L,3[U4=1,U2=3002,L,1[L,2[U2=2,L,1[A"START OK"]]]]
Host:  RX S6F11 → 命令完成 → TX S6F12 body=U4=1
✓ 场景1通过
```

### 场景2：OFF-LINE 发 S2F41
```
Host:  SELECTED 但通信 OFF-LINE（没发 S1F17）
Host:  TX S2F41 START
Equip: RX S2F41 → IsMessageAllowed → RejectedOffline
Equip: TX S2F42 body=L,2[U1=4,A"Equipment OFF-LINE"]

Equip: 状态保持 OFF-LINE，命令未排队
✓ 场景2通过
```

### 场景3：控制 OFF-LINE → 切远程 → 接受
```
Host:  通信 ON-LINE，控制 OFF-LINE
Host:  TX S2F41 START
Equip: RX S2F41 → IsMessageAllowed → RejectedControlOffline
Equip: TX S2F42 body=L,2[U1=4,A"Control OFF-LINE"]
Host:  RX S2F42 ACKC10=4 → 被拒绝
Equip: 操作员按"远程"按钮 → ControlState OFFLINE→ONLINE
Equip: TX S6F11 事件(控制状态变化: ONLINE)
Host:  RX S6F11 → 控制 ONLINE
Host:  TX S2F41 START（重试）
Equip: RX S2F41 → IsMessageAllowed → Allowed → 校验 → 接受
Equip: TX S2F42 body=L,2[U1=0,A"Command accepted"]
Host:  RX S2F42 ACKC10=0 → 命令已接受
✓ 场景3通过
```

### 场景4：急停联动
```
Host:  通信 ON-LINE，控制 ONLINE
Host:  TX S2F41 START
Equip: RX S2F41 → 接受 → 排队 → 开始执行
Equip: TX S2F42 ACKC10=0
Host:  命令执行中...
Equip: 操作员按急停 → EmergencyStop()
Equip: ControlState ONLINE→OFFLINE → 中断正在执行的命令
Equip: TX S6F11 事件(命令失败: 急停中断)
Host:  RX S6F11 → 命令失败，记日志
Host:  TX S2F41 START（再发一条）
Equip: RX S2F41 → IsMessageAllowed → RejectedControlOffline
Equip: TX S2F42 ACKC10=4 → 被拒绝
✓ 场景4通过
```

## 四、今日验收（DoD）
- Host 端建链流程可自动完成（Select→S1F13→S1F17→等待控制 ONLINE）。
- 设备端 GEM 状态机可自动响应 S1F13/S1F15/S1F17/S2F41。
- 4 个场景全部跑通，每个场景有抓包截图、日志、状态变化记录。
- 远程命令执行完成后有 S6F11 事件通知，Host 能正确解析。
- 急停后控制状态回 OFF-LINE，后续命令被拒绝。

## 五、易错点
1. 以为 S1F17 成功就等于控制 ONLINE（通信 ONLINE 不等于控制 ONLINE）。
2. 以为 ACKC10=0 表示命令执行成功（只表示已接受，执行结果靠事件）。
3. 急停时通信状态也断（通常只断控制状态，通信保持）。
4. 控制状态变化没定义事件，Host 不知道设备何时切远程（应定义并关联"控制状态变化"事件）。
5. OFF-LINE 时发 S2F41 期望被执行（会被拒绝，ACKC10=4）。
6. 命令执行失败时以为 S2F42 会返回错误（S2F42 只返回接受/拒绝，执行失败靠 S6F11 事件）。
7. 建链流程跳过 S1F13 直接发 S1F17（虽然部分设备允许，但标准流程应先 S1F13 交换身份）。
