## 二、背景知识（先读，20 分钟）

### 1. 协议栈定位（一句话各归位）
- **E37 HSMS**：管连接、选通、心跳、超时（传输层）。
- **E5 SECS-II**：管消息编码、事务配对（表示层/事务层）。
- **E30 GEM**：管**设备行为模型**——设备有哪些状态、事件、报警、变量、报告、远程命令、配方，以及 Host 如何通过 SECS-II 消息监控和控制设备（行为层/业务层）。
- 关系：GEM 用 SECS-II 消息表达业务语义，SECS-II 借 HSMS 传输。GEM 不定义新的编码或传输，只定义"哪些 SxFy 做什么、设备在什么状态下允许什么"。

### 2. GEM 通信状态机（必背）
GEM 定义设备的**通信状态（Communications State）**：
```
          ┌──────────────┐
          │  OFF-LINE    │ ← 设备上电默认状态
          └──────┬───────┘
                 │ S1F17 Request On-line（Host 请求）
                 │ 或设备自动 ONLINE（可配置）
                 ▼
          ┌──────────────┐
          │   ON-LINE    │ ← Host 可完全监控控制设备
          └──────┬───────┘
                 │ S1F15 Request Off-line（Host 请求）
                 │ 或设备主动 OFF-LINE（如急停、故障）
                 ▼
          回到 OFF-LINE
```
- **OFF-LINE**：设备不接受 Host 的控制命令，只接受有限的通信相关消息（S1F1/F2、S1F13/F14、S1F17/F18 等）。
- **ON-LINE**：设备接受 Host 的全部 GEM 消息（远程命令、报告定义、事件关联、配方管理等）。
- 状态转换必须有明确的触发事件，不能静默切换。

### 3. GEM 控制状态（Control State）
GEM 还定义设备的**控制状态（Control State）**，表示 Host 对设备的控制权限：
- **EQUIPMENT OFF-LINE**：设备本地控制，Host 不能发远程命令（S2F41）。
- **EQUIPMENT ON-LINE**：Host 可以发远程命令控制设备。
- 控制状态和通信状态是**两个独立的状态机**，但通常关联：通信 ON-LINE 后，控制状态才能切到 EQUIPMENT ON-LINE。
- 现场常说的"设备在线"通常指通信 ON-LINE + 控制 EQUIPMENT ON-LINE。

### 4. HSMS SELECTED vs GEM 状态（关键区别）
| 维度 | HSMS SELECTED | GEM ON-LINE |
|---|---|---|
| 层级 | 传输层 | 业务层 |
| 含义 | TCP 连接 + HSMS 选通成功 | 设备接受 Host 业务监控控制 |
| 前提 | 无 | 必须先 SELECTED |
| 能做什么 | 能收发任何 SECS-II 消息 | 能执行业务命令（远程命令、报告定义等）|
| 谁发起 | Active 发 Select | Host 发 S1F17 或设备自动 |
- 设备可以 SELECTED 但 OFF-LINE：此时能传消息，但设备拒绝控制命令。
- 设备不可能 ON-LINE 但未 SELECTED：没有传输通道就无法业务交互。

### 5. GEM 设备模型总览（先眼熟，后续周深入）
GEM 把设备抽象为：
- **状态机（State Machine）**：设备/单元/子单元的处理状态（W12+ GEM300 细讲）。
- **事件（Events/CEID）**：设备发生的事情，触发报告上报（W6）。
- **报警（Alarms/ALID）**：设备异常状态，S5F1 上报（W7）。
- **变量（Variables/VID）**：设备数据，分状态变量(SV)、设备变量(DV)（W6）。
- **报告（Reports/RPTID）**：事件触发时上报的变量集合（W6）。
- **远程命令（Remote Commands/RCMD）**：Host 控制设备的命令（W7）。
- **配方（Process Programs/PPID）**：设备运行的工艺配方（W7）。
