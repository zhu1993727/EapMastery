# W05 · Day01 答案与参考

## 一、自测题标准答案
1. **GEM vs SECS-II 边界 / GEM 是否定义新编码**：SECS-II(E5) 定义消息的**编码格式和事务机制**（数据项树、SxFy 框架、primary/reply）；GEM(E30) 定义**设备行为模型和业务语义**（设备有哪些状态/事件/报警/变量，哪些 SxFy 做什么，设备在什么状态允许什么消息）。GEM **不定义新的编码格式**，它复用 SECS-II 的编码和事务，只规定"用哪些消息、按什么流程、在什么状态下"。
2. **上电默认状态 / 如何进入 ON-LINE**：设备上电后默认在 **OFF-LINE**。Host 通过发 **S1F17（Request On-line）**请求设备进入 ON-LINE，设备回 S1F18（On-line Acknowledge），ACKC=0 表示接受，状态切换到 ON-LINE。部分设备支持配置为"上电自动 ON-LINE"，但标准默认是 OFF-LINE。
3. **SELECTED 但 OFF-LINE 时能否收 S2F41**：能收到消息（HSMS 通道是通的），但设备**拒绝执行**远程命令。设备会回 S2F42 带 ACKC10 非 0（如"设备在 OFF-LINE 状态，命令被拒绝"），或直接不处理。OFF-LINE 状态下设备只接受通信相关消息（S1F1/F2、S1F13/F14、S1F17/F18 等），不接受控制类消息。
4. **通信状态 vs 控制状态**：不是同一个状态机。**通信状态（OFF-LINE/ON-LINE）**表示设备是否接受 Host 的业务监控和消息交互；**控制状态（EQUIPMENT OFF-LINE/ON-LINE）**表示 Host 是否有权限发远程命令控制设备。两者独立但通常关联：通信 ON-LINE 是控制 EQUIPMENT ON-LINE 的前提；通信 OFF-LINE 时控制状态必然是 EQUIPMENT OFF-LINE。现场常说的"在线"通常指两者都 ON。
5. **设备主动 OFF-LINE 时 Host 怎么知道 / HSMS 会断吗**：设备主动 OFF-LINE（如急停、故障）时，**HSMS 连接不会断**（仍然 SELECTED），设备会通过 **S6F11 事件上报**（如果定义了"状态变化"事件）或 Host 通过查询状态变量(SV)发现。Host 后续发控制命令会被设备拒绝（ACKC 非 0）。只有设备主动 Separate 或网络故障时 HSMS 才会断。
6. **GEM 7 大组件 / 哪个是"事件触发时上报的变量集合"**：7 大组件是①状态机、②事件(CEID)、③报警(ALID)、④变量(VID，含 SV/DV)、⑤报告(RPTID)、⑥远程命令(RCMD)、⑦配方(PPID)。**报告(Reports/RPTID)**是"事件触发时上报的变量集合"——S2F33 定义报告包含哪些变量，S2F35 把报告关联到事件，事件发生时设备按报告定义采集变量值并通过 S6F11 上报。

## 三、HSMS SELECTED 与 GEM 状态层级关系
```
应用层（GEM 业务）
  ▲
  │ GEM ON-LINE：接受业务命令（S2F41、S2F33、S2F35...）
  │ GEM OFF-LINE：只接受通信相关消息，拒绝控制命令
  │
  │ 前提：必须先 SELECTED
  ▼
传输层（HSMS）
  ▲
  │ SELECTED：TCP 连接 + HSMS 选通，能收发任何 SECS-II 消息
  │ NOT SELECTED：只能 Select，不能传数据消息
  │
  ▼
物理层（TCP/IP）
```
关键：SELECTED 是"通道通了"，ON-LINE 是"业务开放了"；通道通了不代表业务开放，业务开放必须通道先通。

## 四、参考实现（EapLab.Gem/State/）

### GemCommState.cs
```csharp
namespace EapLab.Gem.State;
public enum GemCommState
{
    Offline,   // 设备上电默认，不接受控制命令
    Online     // 接受 Host 全部 GEM 消息
}
```

### GemControlState.cs
```csharp
namespace EapLab.Gem.State;
public enum GemControlState
{
    EquipmentOffline,  // 本地控制，Host 不能发远程命令
    EquipmentOnline    // Host 可以发远程命令
}
```

## 五、今日易错点
1. 以为 SELECTED 就等于 ON-LINE（传输层和业务层是两回事）。
2. 以为 OFF-LINE 时 HSMS 会断（连接保持，只是拒绝业务命令）。
3. 混淆通信状态和控制状态（两个独立状态机，通常关联但不等价）。
4. 以为 GEM 定义新的编码格式（GEM 复用 SECS-II，只定义业务语义）。
5. 设备主动 OFF-LINE 时以为 Host 一定会收到通知（设备可能只通过事件上报，Host 也可能要主动查询）。
6. 以为 OFF-LINE 下设备不能发任何消息（设备仍可主动上报报警/事件，只是不接受 Host 控制）。
