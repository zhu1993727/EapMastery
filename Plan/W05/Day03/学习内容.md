## 二、背景知识（先读，25 分钟）

### 1. GEM 控制状态（Control State）
GEM 定义设备的**控制状态**，表示 Host 对设备的控制权限：
```
┌──────────────────────┐
│ EQUIPMENT OFF-LINE   │ ← 设备本地控制，Host 不能发远程命令
│ (本地/手动模式)        │
└──────────┬───────────┘
           │ Host 请求控制（通过 S2F41 或专用消息）
           │ 或设备配置为允许 Host 控制
           ▼
┌──────────────────────┐
│ EQUIPMENT ON-LINE    │ ← Host 可以发远程命令控制设备
│ (Host/远程模式)       │
└──────────┬───────────┘
           │ 设备本地操作（如按本地按钮）
           │ 或急停/故障
           ▼
      回到 EQUIPMENT OFF-LINE
```
- **EQUIPMENT OFF-LINE**：设备由本地操作员控制，Host 发 S2F41 远程命令会被拒绝（ACKC10 非 0）。
- **EQUIPMENT ON-LINE**：Host 可以发远程命令控制设备（START/STOP/PAUSE 等）。
- 控制状态和通信状态是**两个独立状态机**，但通常关联：通信 ON-LINE 是控制 EQUIPMENT ON-LINE 的前提；通信 OFF-LINE 时控制状态必然是 EQUIPMENT OFF-LINE。
- 现场常说的"设备在远程模式"就是指控制状态 EQUIPMENT ON-LINE。

### 2. 控制状态与通信状态的组合
| 通信状态 | 控制状态 | 含义 | Host 能做什么 |
|---|---|---|---|
| OFF-LINE | EQUIPMENT OFF-LINE | 未建链或已离线 | 只能发通信相关消息 |
| ON-LINE | EQUIPMENT OFF-LINE | 已建链但设备本地控制 | 可监控（收事件/报警），不能发远程命令 |
| ON-LINE | EQUIPMENT ON-LINE | 完全在线，Host 控制 | 可监控 + 可发远程命令 |
- 最常见的现场状态是 ON-LINE + EQUIPMENT ON-LINE。

### 3. S2F41（Host Command Send）远程命令
- **方向**：Host→设备（S2F41 primary），设备→Host（S2F42 reply）。
- **W 位**：S2F41 W=1（要求回复），S2F42 W=0。
- **body 结构**：
  - S2F41：`L,2[A RCMD, L,n[L,2[A CPNAME, <CPVALUE>]]]`
    - RCMD：远程命令名（如 "START"、"STOP"、"PAUSE"、"RESUME"）。
    - CPNAME：命令参数名（如 "LOTID"、"RECIPE"、"QUANTITY"）。
    - CPVALUE：参数值（任意 SECS-II 类型，A/U1/U2/F4 等）。
  - S2F42：`L,2[U1 ACKC10, A ERRMSG?]`
    - ACKC10：命令确认码（0=命令被接受，非0=各种拒绝原因）。
    - ERRMSG：可选错误信息文本。

### 4. 远程命令的完整流程（必背）
```
Host(上位机)                              Equipment(设备)
  │                                          │  前提：通信 ON-LINE + 控制 EQUIPMENT ON-LINE
  │── S2F41 Host Command Send(RCMD, 参数) ─►│
  │                                          │  校验：状态、命令名、参数名、参数值
  │                                          │  ├─ 校验失败 → 回 S2F42 ACKC10 非0
  │                                          │  └─ 校验通过 → 接受命令，排队执行
  │◄─ S2F42 ACKC10=0(命令已接受) ──────────│
  │                                          │
  │          设备异步执行命令（可能几秒到几分钟）│
  │                                          │
  │◄─ S6F11 事件上报(命令完成/失败) ────────│  命令执行完成后，通过事件通知 Host
  │── S6F12 ACK ───────────────────────────►│
```
- **关键**：S2F42 ACKC10=0 只表示"命令已被接受并排队"，**不表示命令已执行完成**。
- 命令执行是**异步**的，设备通过 S6F11 事件上报命令完成/失败（如果定义了相关事件）。
- Host 不能靠 S2F42 判断命令是否成功执行，必须监听事件。

### 5. ACKC10（远程命令确认码）
| ACKC10 | 含义 |
|---|---|
| 0 | 命令被接受（Command accepted），已排队执行 |
| 1 | 命令不被接受（Command not accepted），通用拒绝 |
| 2 | 参数名/参数值错误（Invalid command parameter） |
| 3 | 设备忙（Equipment busy），无法接受新命令 |
| 4 | 设备在 EQUIPMENT OFF-LINE 状态，拒绝远程命令 |
| 5+ | 设备特定原因 |
> 具体值以 E30 原文及设备实现为准，核心是"0=接受，非0=拒绝"。
