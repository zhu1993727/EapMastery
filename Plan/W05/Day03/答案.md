# W05 · Day03 答案与参考实现

## 一、自测题标准答案
1. **通信状态 vs 控制状态 / EQUIPMENT ON-LINE 含义**：不是同一个状态机。通信状态（OFF-LINE/ON-LINE）表示设备是否接受 Host 的业务消息交互；控制状态（EQUIPMENT OFF-LINE/ON-LINE）表示 Host 是否有权限发远程命令控制设备。EQUIPMENT ON-LINE 表示设备处于"远程/Host 控制模式"，Host 可以发 S2F41 远程命令（START/STOP 等），设备会接受并执行。
2. **ACKC10=0 是否表示命令执行成功**：**不是**。ACKC10=0 只表示"命令已被设备接受并排队执行"，是**命令接受**的确认，不是**命令执行完成**的确认。命令执行是异步的，可能需要几秒到几分钟，S2F42 在命令接受后立即返回，不等执行完成。
3. **Host 怎么知道命令执行完成 / 靠 S2F42 吗**：**不靠 S2F42**。Host 通过**S6F11 事件上报**知道命令执行完成——设备执行完命令后，触发"命令完成"事件（CEID），通过 S6F11 上报给 Host，Host 回 S6F12 确认。Host 也可以通过查询状态变量(SV)主动查询设备状态，但事件上报是标准方式。
4. **EQUIPMENT OFF-LINE 时发 S2F41 会怎样**：设备会**拒绝**远程命令，回 S2F42 带 ACKC10 非 0（通常是 4="设备在 OFF-LINE 状态"或 1="命令不被接受"）。设备不会执行命令，也不会排队。Host 收到拒绝后应记日志，通知操作员将设备切到远程模式，或等待设备进入 EQUIPMENT ON-LINE。
5. **CPVALUE 任意类型 / U2 例子**：CPVALUE 可以是任意 SECS-II 类型，因为不同命令的参数值类型不同——LOTID 是字符串(A)，数量是整数(U2/U4)，温度是浮点(F4/F8)，开关是布尔(BOOLEAN)。例子：START 命令的 QUANTITY（生产数量）参数用 U2，值为 25，编码为 `A8 01 00 19`。
6. **通信 ON-LINE 但控制 EQUIPMENT OFF-LINE 时能做/不能做**：能做——收设备主动上报的事件(S6F11)和报警(S5F1)、查询状态变量(SV)、定义报告(S2F33)和关联事件(S2F35)（部分设备允许）、管理配方(S7)（部分设备允许）；不能做——发 S2F41 远程命令控制设备（会被拒绝）。此时 Host 是"监控模式"，不是"控制模式"。

## 二、参考实现（EapLab.Gem/Messages/）

### S2F41 远程命令处理（设备端）
```csharp
using EapLab.Secs2.Items;
using EapLab.Gem.State;

namespace EapLab.Gem.Messages;

public sealed class RemoteCommandHandler
{
    private readonly GemStateMachine _gem;
    private readonly Dictionary<string, Func<Dictionary<string, SecsItem>, byte>> _validators;

    public RemoteCommandHandler(GemStateMachine gem)
    {
        _gem = gem;
        _validators = new()
        {
            ["START"] = ValidateStart,
            ["STOP"] = ValidateStop,
            ["PAUSE"] = ValidatePause
        };
    }

    public SecsItem HandleS2F41(SecsItem? body)
    {
        // 1. 校验控制状态
        if (_gem.ControlState != GemControlState.EquipmentOnline)
            return Reply(4, "Equipment is OFF-LINE");

        // 2. 解析 body：L,2[A RCMD, L,n[L,2[A CPNAME, CPVALUE]]]
        if (body is not SecsList root || root.Count < 2)
            return Reply(2, "Invalid body structure");

        string rcmd = ExtractAscii(root.Items[0]);
        var parameters = ParseParameters(root.Items[1] as SecsList);

        // 3. 校验命令名
        if (!_validators.ContainsKey(rcmd))
            return Reply(1, $"Unknown command: {rcmd}");

        // 4. 校验参数
        byte ackc = _validators[rcmd](parameters);
        if (ackc != 0) return Reply(ackc, "Parameter validation failed");

        // 5. 接受命令，排队异步执行
        _gem.EnqueueCommand(rcmd, parameters);   // 内部排队，异步执行
        return Reply(0, "Command accepted");      // 立即返回，不等执行完成
    }

    private SecsItem Reply(byte ackc, string errmsg)
        => Secs.L(Secs.U1(ackc), Secs.A(errmsg));

    private string ExtractAscii(SecsItem item)
        => item is SecsAscii a ? a.Value() : "";

    private Dictionary<string, SecsItem> ParseParameters(SecsList? paramList)
    {
        var dict = new Dictionary<string, SecsItem>();
        if (paramList == null) return dict;
        foreach (var p in paramList.Items)
        {
            if (p is SecsList pair && pair.Count >= 2)
                dict[ExtractAscii(pair.Items[0])] = pair.Items[1];
        }
        return dict;
    }

    // 命令校验器示例
    private byte ValidateStart(Dictionary<string, SecsItem> p)
    {
        if (!p.ContainsKey("LOTID")) return 2;       // 缺 LOTID
        if (!p.ContainsKey("RECIPE")) return 2;      // 缺 RECIPE
        if (p.ContainsKey("QUANTITY") && p["QUANTITY"] is SecsNumber q && q.Values().First() <= 0)
            return 2;                                   // 数量非法
        return 0;
    }
    private byte ValidateStop(Dictionary<string, SecsItem> p) => 0;
    private byte ValidatePause(Dictionary<string, SecsItem> p) => 0;
}
```

### 命令异步执行与完成事件（设备端）
```csharp
// 在 GemStateMachine 中
public void EnqueueCommand(string rcmd, Dictionary<string, SecsItem> parameters)
{
    _ = Task.Run(async () =>
    {
        try
        {
            await ExecuteCommandAsync(rcmd, parameters);   // 实际执行（可能几秒）
            // 执行成功，触发"命令完成"事件
            _eventService.TriggerEvent(CEID_CommandComplete,
                new Dictionary<string, object> { ["RCMD"] = rcmd, ["RESULT"] = "OK" });
        }
        catch (Exception ex)
        {
            // 执行失败，触发"命令失败"事件
            _eventService.TriggerEvent(CEID_CommandFailed,
                new Dictionary<string, object> { ["RCMD"] = rcmd, ["ERROR"] = ex.Message });
        }
    });
}
```

### Host 端发送远程命令
```csharp
public async Task<bool> SendRemoteCommandAsync(HsmsConnection conn, string rcmd,
    Dictionary<string, object> parameters)
{
    // 构造 body：L,2[A RCMD, L,n[L,2[A CPNAME, CPVALUE]]]
    var paramList = parameters.Select(kv =>
        Secs.L(Secs.A(kv.Key), ToSecsItem(kv.Value))).ToArray();
    var body = Secs.L(Secs.A(rcmd), Secs.L(paramList));

    var reply = await conn.SendAndWaitReply(2, 41, body, TimeSpan.FromSeconds(10));
    if (reply == null) { _log.Err("S2F41 超时"); return false; }

    byte ackc = ExtractAckc(reply);   // L,2[U1 ACKC10, A ERRMSG]
    if (ackc != 0)
    {
        _log.Err($"S2F41 被拒绝，ACKC10={ackc}");
        return false;
    }

    _log.Evt($"S2F41 命令 {rcmd} 已接受，等待执行完成事件");
    // 注意：此时命令只是被接受，执行完成要等 S6F11 事件
    return true;
}
```

## 三、远程命令完整时序（标准画法）
```
Host                                  Equipment
  │                                    │  前提：通信 ON-LINE + 控制 EQUIPMENT ON-LINE
  │── S2F41 (RCMD=START, 参数) ──────►│
  │                                    │  校验状态/命令名/参数
  │◄─ S2F42 ACKC10=0 ────────────────│  ← 命令已接受（不是已完成！）
  │                                    │
  │         异步执行（几秒~几分钟）      │
  │                                    │
  │◄─ S6F11 (CEID=命令完成, 结果) ────│  ← 命令执行完成通知
  │── S6F12 ACK ─────────────────────►│
  │                                    │
  │  若执行失败：                        │
  │◄─ S6F11 (CEID=命令失败, 错误信息) ─│
```

## 四、ACKC10 速查卡
| ACKC10 | 含义 | Host 动作 |
|---|---|---|
| 0 | 命令已接受，排队执行 | 等待 S6F11 完成事件 |
| 1 | 命令不被接受（通用） | 记日志，检查命令名/设备状态 |
| 2 | 参数名/参数值错误 | 修正参数后重发 |
| 3 | 设备忙 | 等待后重试 |
| 4 | 设备 OFF-LINE | 通知操作员切远程模式 |
| 5+ | 设备特定原因 | 查设备手册 |

## 五、今日易错点
1. 以为 ACKC10=0 表示命令执行成功（只表示已接受，执行完成靠事件）。
2. 以为 S2F42 会等命令执行完才返回（S2F42 立即返回，执行是异步的）。
3. 混淆通信状态和控制状态（EQUIPMENT ON-LINE 是控制状态，不是通信状态）。
4. EQUIPMENT OFF-LINE 时发远程命令期望被执行（会被拒绝，ACKC10 非 0）。
5. CPVALUE 固定为字符串类型（可以是任意类型，按命令定义）。
6. 命令执行失败时以为 S2F42 会返回错误（S2F42 只返回接受/拒绝，执行失败靠 S6F11 事件）。
7. 不监听命令完成事件，以为发完命令就完事了（必须监听事件才能知道执行结果）。
