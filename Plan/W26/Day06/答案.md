# W26 · Day06 综合答辩范文与追问标准答案

## 一、标准答辩话术（按六部分，可直接作为个人模板）

### 1）分层与边界
这台设备的设备端 SECS/GEM Interface 是"被管方"，通过 HSMS 与 FAB 端 EAP(Host) 一对一通信；FAB EAP 再与 MES（派工/批次）、FDC（故障检测分类）、RMS（配方）、YMS（良率）等 CIM 子系统交互，AMHS 经 E84 硬线和 LoadPort 交接，CIM 是这些系统的统称、不是某一家产品。设备端内部我按标准分层、依赖单向：Domain 放泛型状态机/时钟/事件总线；E5 做 SECS2/HSMS；E30 GEM；E39 OSS；E84 独立硬线；E87 管盒、E90 管片、E40 管加工作业、E94 管跨盒批次编排；Ept/Ram/Oee 只订阅事件做度量；Cell 层 FabLineOrchestrator 编排全链路。每层一个单一事实源：控制态问 E30、载具问 E87、片位置唯一问 E90、作业问 E40/E94 FSM，跨层只读、不反向写。

### 2）主流程时序（门控：物理→授权→编排）
十阶段：HSMS 选通后 S1F13/14 交换 MDLN/SOFTREV、S1F17 申请在线进 Remote；①E84 四相握手 Deposit、COMPT 后在位 ON；②E87 Installed（物理事实）；③与预约 ID 核对通过才 Loaded（逻辑授权，唯一 Loaded 才能自动取片）；④E90 扫 SourceMap 建位置基线；⑤Host 经 OSS S15F1 建 E94 ControlJob（过六不变量静态校验），S15F10 调启动只是"接受"；⑥级联起首批 E40 PJ；⑦多腔并发、跨 PJ 交接；⑧全部完成且片到输出才聚合 Completed；⑨UnloadGuard 五条件满足转 Unloaded，最后 E84 Pickup。全程关键消息：远程命令 S2F41/42、对象 S15、异步事件 S6F11 与 S16F1 同源生成、报警 S5F1（先 S5F3 使能）、配方 S7。所有 ACKC0/S15F10 都只是受理，真正生效以状态机合法迁移后的 S6F11/S16F1 为准——受理≠生效。

### 3）状态机设计
Carrier、PJ、CJ 都复用 Domain 的泛型 StateMachine：显式合法边、Guard 裁决、Fire 原子、非法零副作用、外部命令只是触发不直接赋状态。PJ 是 Queued→Started→Executing⇄Pausing⇄Paused、终态 Completed/Cancelled/Aborted/Failed；Cancel 仅 NothingTouched，Abort 执行中并对片分类。CJ 状态由各 PJ 自下而上聚合，优先级 失败中止>Pausing>全Paused>Executing>全Completed(且片到输出)>全Queued，且只有聚合后 CJ 层状态真变化才发一次事件，避免子层抖动刷屏。外部 JobCommand 与内部 JobEvent 分开，都要过合法边+Guard。

### 4）片流与守恒
物理位置只有 E90 SubstrateTracker 一个 Move 入口（expectedFrom+锁+快照+改后断言+失败回滚），CJ 只编排绝不改位置。并行 Fork 展开每片路径、Join 用 JoinBarrier 等所有前驱片到齐才放行，缺一条健康支路则健康支继续、缺路安全等待不丢片；条件流转（量测合格才进下一 PJ）由结果门控决定后继，不合格走 Rework——Rework 是同片新实例+reworkCount+上限，不新增片 ID。全程以全局 SubstrateId 集合守恒：并集=全体、子集互斥、Σ载具+设备内部=基线，合拆批需显式授权并记谱系。

### 5）异常与恢复
腔故障：沿依赖图出边找下游消费者、入边找上游供片，按三策略——能隔离就 Degraded 让健康支路继续，关键路径级联停（下游 Stop、上游 Hold 停供），可恢复则 PropagateHold 带超时升级；菱形汇合缺路按 JoinBarrier 安全等。HSMS 断线：本地进入安全态、已授权动作继续、需授权的新动作挂起，上报类 S6F11/S5F1/S16F1 进 Spool 按序缓存；重连按 HSMS→E87 三对账→E90 以物理重建(P→L)→E40/E94 重建(L→H)→Spool 补发，命令类不盲目重发而是对账后幂等。E84 异常 VALID 去抖/ESTOP fail-safe、归属不确定不自动重试转人工。量测延迟的片挂 Pending、不判废不阻塞后续可放行片。

### 6）资源与度量
四类资源（腔/LoadLock/臂/端口）按资源 ID 全序申请、all-or-nothing、资源分配图找环防死锁；双臂 Swap 先取后放，LoadLock 两门永不同开、双锁乒乓；瓶颈资源决定 beat（TOC）。全程领域事件同源进 E116：切互斥完备状态段（等料是 Standby 不是故障、提示报警不切段），RAM 从故障段算 MTBF/MTTR/MDT，OEE 用时间账定 A、逐片节拍定 P、FPY 定 Q，OEE=A·P·Q=IdealCT·Good/PPT，班末出损失瀑布。FDC 要 10Hz 高频参数走 Interface-A（EDA，多客户端订阅），不走低频一对一的 GEM S6F11。

## 二、八连追问标准答案
1. **ACKC0 后断线、双方认知不一致**：ACKC0 只是"收到并接受请求"，不代表已生效。设备侧是否真启动以 PJ/CJ-FSM 是否完成合法迁移为准，迁移成功后产生 S6F11/S16F1（Started 事件）。断线期间该事件进 Spool；重连先做状态对账（以设备 FSM 实际状态与 E90 实际位置为权威重建 L→H），再补发 Started 事件，Host 以迁移后事件而非 ACKC 判定生效；启动命令本身幂等（带 CJ/PJ 标识，重复收到不重复起作业）。结论：永远以"状态机迁移+事件"为生效凭据，ACK 只是传输层受理。
2. **双口同时上下料共用双臂防死锁/撞片**：端口各自独立、但臂/锁是共享资源，统一进 GlobalResourceCalendar，按资源 ID 全序申请、区间互斥、all-or-nothing（要么一次拿齐要么不拿），资源分配图检测环；动作上双臂 Swap 固定五步先取后放，臂的运动区间互斥校验，InOut 先卸后上串行化，E90 每次移动经唯一入口做容量/唯一位置断言。这样不会出现两流程互占对方需要的臂/位形成循环等待，也不会双占同一位置。
3. **Join 一支路故障、另一支已完成**：已完成片停在安全位/Buffer 保持、状态冻结记快照（不丢、不重复投）；故障支路按策略隔离或级联，JoinBarrier 不做"半汇合"——要么等故障支路恢复补齐、要么走显式授权的降级路径（如 Partial 需 Host 授权并带明细），缺哪片、在哪、什么状态全部可查；恢复时以 E90 实际位置重核交接位、幂等交接，已完成片不重做，故障片续跑，最终集合守恒。绝不允许在缺片情况下把 Join 当完成。
4. **Rework 怎么记/片数变吗**：E90——还是同一 SubstrateId、位置按实际移动、片数不增；E40——为返工生成该路线的新 PJ 实例、reworkCount+1、受 MaxRework 限制、加工时间累加；E94——编排上是回流（新实例+轮次上限、DAG 无环），记谱系 genealogy；质量账——第一次未过不算一次 Good（拉低 FPY），返工后合格计入最终良率但不回补 FPY，额外占用时间落在 RunTime 影响 Performance。全局片 ID 集合守恒，片数绝不增加，只增加加工次数。
5. **量测延迟能否先放/OEE 质量**：可以先把片放到指定安全位置（如待判 Buffer/输出但标记 Pending），不阻塞其他无关片流动，但不得当良品流入下道关键工艺或当废品处理；质量台账挂 Pending，OEE 的 Q 分母用"已判定片"，同时标注 Pending 数量与未闭环，必要时给"全合格/全报废"区间，结果回传后用同一计算器重算。核心：物理可平顺流动、结论不臆造、指标标注不确定性。
6. **OEE 三要素取数/对不上怎么查**：A 取 Ept 时间账（RunTime/PPT），P 取 E40/E94 逐片完成记录与按配方的理想节拍，Q 取质量台账 FPY，三者同一单调时钟、同一 Cj/Pj/片 ID 对齐。对不上先跑计算器内置断言：时间守恒（段和=日历）、片 ID 集合守恒（质量账=加工账）、自洽（A·P·Q 是否=IdealCT·Good/PPT）；A·P 先不等是 RunTime 口径问题，乘 Q 后不等是 Total/Good 口径问题，逐层锁定；P>1 告警查理想节拍/RunTime/计数。
7. **FDC 10Hz 为何走 Interface-A 不走 GEM**：GEM(SECS/GEM) 是设备↔单一 Host 的中低频事务通信，适合命令、事件、状态、稀疏采集，高频 10Hz 参数用 S6F11 会造成消息风暴、挤占控制事务且只有一个接收方；EDA/Interface-A 面向多客户端（FDC/YMS 等）高频订阅式数据采集，按 E120/E125 自描述模型订阅参数、客户端各自取数，与控制通道隔离互不影响。所以高频参数走 Interface-A，控制与事务走 GEM，两条通道分工。
8. **为何不能自解 LotHold/谁解/流程**：LotHold 是 MES/Host 基于批次质量、工艺、工程判断设置的逻辑管控，设备端没有做出这个判断的上下文与权限，自解会绕过质量与工艺管控、可能导致问题批次继续流动。设备职责是如实保持受限（不自动加工该 Lot）、上报状态与原因；解除必须由原设置方（Host/MES 工艺/质量工程师）核实处理后，经远程命令/对象操作显式解除，设备收到合法解除指令并校验后才恢复，全程留痕。CarrierHold/EquipmentHold 同理，谁设谁解、设备不擅自放行。

## 四、答辩万能骨架（记住这六句，任何 EAP 场景都能展开）
1. 先划边界：谁是单一事实源、依赖单向、设备端只被管。
2. 再讲门控：物理事实→逻辑授权→任务编排，顺序不反。
3. 状态只走合法边+Guard，命令是请求、生效看迁移后事件。
4. 片位置只有一个入口，全局 ID 集合守恒，汇合不半闭、返工不增片。
5. 异常先安全、冻快照、按依赖定影响域，恢复以物理实际重建、幂等不重。
6. 一切过程同源进时间账，最终用 RAM/OEE 量化，高频数据走 EDA、控制走 GEM。

## 五、今日易错点（答辩中暴露即回炉）
1. 把 FAB EAP/MES/FDC/CIM 混为一谈（CIM 是统称）。
2. 门控顺序颠倒、Installed 就当能生产。
3. 把 ACK/受理讲成生效。
4. 状态被外部直接赋值、不经 FSM 合法边。
5. CJ/编排直接改片位置、Join 半汇合、Rework 增片。
6. 断线盲目重发命令、不做 P→L→H 对账。
7. 量测未回就判废/判良。
8. 高频数据塞 GEM、不区分 Interface-A。
9. 设备自解 Hold。
10. OEE 三要素不同源、不算化简式自洽。
