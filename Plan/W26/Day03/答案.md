# W26 · Day03 参考图（图 1–8）与费曼讲解提纲

> 用法：先闭卷默画，再对照本文件改红。参考图是"要素齐全"的最低标准，布局可不同，但状态/信号/消息/不变量不能缺。

## 图1 HSMS 控制状态机
```
        TCP connect ok                 Select.rsp(ok)
NOT_CONNECTED ───────────▶ NOT_SELECTED ───────────▶ SELECTED ◀──▶ 数据消息收发
     ▲  TCP断/Separate/T5/T6   │ Select失败/Reject      │ Linktest.req↔rsp(T7保活)
     └─────────────────────────┴◀── Separate.req/链路断 ┘
SType: 1/2 Select req/rsp, 3/4 Linktest req/rsp, 5 Separate.req, 7 Reject
超时: T3等数据回复~45s T5建连 T6控制事务 T7选中保活 T8帧间
```
费曼：TCP 像电话拨通了，Select 是"对上暗号、确认是你、建立这一条专用会话"，之后才能谈业务（数据消息）；Linktest 是通话中定期"喂喂还在吗"，半天不应就挂断重连。

## 图2 SECS2 编码结构
```
格式字节 = [高6位=类型码][低2位=长度字节数-1] ; 其后长度N(大端) ; 再N字节内容
类型码: L8 B9 Bool10 A16 J17 I系列24.. F8=32 F4=33 U系列40.. ; 多字节大端
例: U2=0x00A9 → 0xB1(U2,长度占2→低2位=1) 0x02 0x00 0xA9
    A"ON"   → 0x41(A,长度1) 0x03 'O''N'
    L,2[...]→ L头长度2, 内部递归两个元素
```
费曼：每段数据都自带"我是什么类型、我有多长"，收方按长度切、遇到 L 就递归往里读；高低位拼一个字节是为了用一个字节同时表达类型和长度占几字节，省空间又自描述。

## 图3 GEM 控制状态机
```
两维: 在线维 OFF-LINE ◀─S1F17请求/S1F18应答─▶ ON-LINE
      控制维(在线时): LOCAL(本机操作) ◀─切换─▶ REMOTE(Host远程可令)
上电默认 OFF-LINE; S1F13 Establish Comm/S1F14回MDLN+SOFTREV
OFF-LINE时Host不能远程控制生产; 报警/采集能力按状态受限
```
费曼：设备开机先"离线"，要主动申请在线、双方核对型号版本；在线还分"听现场面板的(Local)"还是"听上位机的(Remote)"，这是两个独立开关，别混成一个状态。

## 图4 采集三层 VID→RPT→CEID
```
VID(温度/压力/片数...) ──S2F33 Define Report──▶ RPT(一组VID)
RPT ──S2F35 Link Event Report──▶ CEID(事件)
运行: 事件发生 → 取关联RPT当前值快照 → S6F11(DATAID,CEID,RPT[VID:值]) → Host
S2F37使能; 快照在状态/事件成立后取(权威新值)
```
费曼：不把每个变量无脑狂发，而是先把变量打包成报告、再规定"哪个事件发生时带哪份报告"，事件一到就拍一张当时的快照发上去，既省流量又对得齐。

## 图5 OSS 对象模型与 S14/S15/S16
```
对象模型: Class类 → Instance实例 → Attribute属性 / Method方法 / 集合
S14(F1-8) 取元数据目录, reply=L,2[ACKC,List], 空集合回L,0
S15: F1/2建 F3/4删 F5/6查(严格按序) F7/8设(两阶段原子) F9/10调方法 F11/12存在
ACKC:0ok 1类型不存在 2实例不存在 3已存在 4属性不存在 5只读 6缺必填
     7类型不符 8非法状态 9无此方法 10参数错 99内部错
S16F1=L,3[OBJSPEC,CEID,L,n属性快照]/F2确认; S15F10接受≠完成,完成靠S16F1
```
费曼：把设备抽象成一堆有属性、有方法的对象，像操作数据库一样增删改查调；"设属性"要先整体校验再一次生效，不会改一半；"调方法"的收到只代表答应做，做完另发事件。

## 图6 E84 四相握手时序
```
硬线并行I/O(非TCP): 设备→小车 CS/ES/HO0/HO1 ; 小车→设备 SS/VR/TR_REQ/BUSY/COMPT ; 共用 VALID/ESTOP/BYPS
四相: 请求→应答/到位→传送(VALID门控,信号稳定才认)→完成COMPT, 信号按相位回退
HO0/HO1每次交接翻转=防连续两次交接丢拍/重拍; VALID去抖; ESTOP/BYPS fail-safe
Deposit: COMPT后在位ON→Installed(物理先); Pickup: 账面先Unloaded,COMPT后在位OFF
归属不确定→禁自动重试,转人工
```
费曼：LoadPort 和天车 OHT 之间是一束真实电平线，不靠网络，双方像打旗语一唱一和分四步；HO 位每次翻面防止两次连续交接数错，VALID 要求信号稳住了才算数，毛刺不理，保证不撞盒、不重复取放。

## 图7 E87 Carrier 状态机
```
NotInstalled ─在位(物理)→ Installed ─预约/ID校验通过(逻辑授权)→ Loaded
   ▲取走/Pickup                    Unloaded ◀─加工完、片回输出盒─┘
Installed=物理事实; Loaded=逻辑授权, 唯一Loaded才允许自动取片
预约Reservation: 安装时核对实际CarrierID/批次, 不符不Loaded
Hold: CarrierHold/LotHold/EquipmentHold 只能由设置方(Host/MES)解, 设备不自解
```
费曼：盒子放上来(Installed)只是"物理上在"，系统核对过预约、确认是对的料才"授权生产"(Loaded)，两步分开就能从根上防上错料；任何 Hold 设备自己没权解除，必须上层放行。

## 图8 E90 SlotMap 与位置移动
```
Slot三态 Empty/Occupied/Abnormal; 25槽1-based, 4字节MSB-first, 槽k→bit k-1
槽1/16/25=80 80 80 00 ; 槽1/3/25=A0 00 80 00 (bit25..31保留0)
唯一入口 Move(expectedFrom,加全局锁,移动前快照,改后断言容量/唯一/守恒,失败回滚)
Pick/Place/Transfer改位置; Process只改工艺状态不改位置
三不变式: 唯一位置 / 位置容量(臂腔=1) / 总数守恒
五类异常: Missing空 Double双占 Misplaced错位 WrongId身份不符 LeftInside遗留
```
费曼：全设备片在哪只有一本账、只有一个"移动"函数能改，每次移动都先验来源、上锁、留快照、移完再查总数对不对，错了就回滚——这样并发取放也不会出现一片在两处或片凭空消失。

## 三、讲解通用评分（费曼是否达标的四条）
1. 一句话定位准确（不与相邻标准混，如 E84 是硬线、E87 管盒、E90 管片）。
2. 机制讲清"为什么这样设计"（如唯一入口、两阶段、物理先于授权），不只是背名词。
3. 有一个设备现场例子（上错料、撞盒、断线、双占）。
4. 能讲一个异常分支（失败回滚、fail-safe、Hold 谁解、归属不确定不重试）。
四条都满足=A；缺 1 条=B；讲不清或有原则错=C，回炉对应周并重画重讲。
