# W26 · Day04 参考图（图 9–15）与费曼讲解提纲

## 图9 交叉取片与全局守恒
```
三类模式: 顺序单取 / 双臂交叉Swap / 多腔多盒交叉
CrossMap四约束: 来源合法 / 目标有空位且角色对 / 路径不撞(臂锁) / 全局片集合守恒
恒等式: Σ各载具片数 + 设备内部片数 = 基线常量 ; 合拆批: 并集=全体,子集互斥,不新增ID
Buffer临时位: 打破"甲要乙的位、乙要甲的位"占用循环(防死锁)
六道校验关: 清单一致/读码身份/目标可用/臂锁/容量/全局守恒
```
费曼：交叉取片是最容易混批丢片的地方，因为片在多个盒子和腔体间换来换去；兜底原则就一条——无论怎么换，全设备片的集合和总数永远不变，每次取放过六道校验，用缓冲位解开"互相等对方位置"的死结。

## 图10 E40 PJ 三正交与状态机
```
WaferMap(源/目的/顺序,执行时绑LoadPort核口) | ProcessRoute(Step/Module/Recipe,串/并行/DAG) | 状态进度
Queued/Received→Started→Executing ⇄ Pausing⇄Paused ; 终态 Completed/Cancelled/Aborted/Failed
外部JobCommand(Host) + 内部JobEvent(片完成/故障) → 合法边+Guard, 不直接赋值
Cancel=仅NothingTouched; Abort=执行中强停并对片分类
Completed守卫: 全Step完成+片全到Destination+无遗留+守恒; 安全点=机构安全/片安全位/无临界动作/可一致快照
```
费曼：一个 PJ 分三件互不耦合的事——加工哪些片、按什么路线走、现在跑到哪；状态迁移必须走合法边和守卫，外部命令只是"请求"，没动工才能取消、动工后只能中止并把每片安排好，完成的硬标准是片真的到了输出盒且账对得上。

## 图11 多腔资源/死锁/Swap/LoadLock
```
四类资源: 腔Chamber / LoadLock / 臂Arm / 端口辅助
防死锁: 资源ID全序申请 + all-or-nothing + 资源分配图找环(破坏循环等待)
双臂Swap五步: 臂1取已加工→臂2取待加工→换位→放入(先取后放), 减少空跑
LoadLock: 对大气门/对真空门永不同开, 压力到位才开门; 双锁乒乓(一个加工一个装片)
Makespan≈首片+(n-1)*beat; beat由瓶颈资源定(TOC)
```
费曼：多腔就像多个工位共用机械臂和闸门，死锁都是"你占我要的、我占你要的"形成环，规定所有人按同一固定顺序申请资源就形不成环；双臂交换一次动作完成一进一出，双锁乒乓让真空不中断，瓶颈工位决定整机出片节奏。

## 图12 E94 CJ 三层与状态聚合
```
ControlJob(批次层,跨载具编排,1对多PJ) → ProcessJob(加工层,一路线一组片) → Wafer/Step(片层,E90管位置)
CJ只编排不改位置(唯一入口E90)
控制依赖(谁先启动) ⊥ 片流依赖(谁的片给谁); 片流: 顺序/Fork并行/Join汇合/回流(新实例+轮次上限)
六不变量: ≥1PJ顺序唯一/路径DAG无环/不重复分配输出槽唯一/片集合守恒/载具角色合法/后继来源合法
聚合优先级: 失败中止>Pausing>全Paused>Executing>全Completed(片到输出)>全Queued
仅CJ聚合后状态真变化才发1次事件(子层抖动不重复冒泡)
```
费曼：CJ 是跨多个盒子编排一批活的"总工单"，它只管派活、绝不直接挪片（挪片永远问 E90）；下层多个 PJ 各自跑，CJ 状态按"最严重/最靠后"的原则自下而上汇总，且只有汇总结果真的变了才对外说一声，避免刷屏和抖动。

## 图13 级联/故障传播/恢复
```
命令级联按子态分类: Completed不动/Executing执行/Pausing-Paused幂等/Queued挂SuspendPending
故障三策略: 局部隔离继续(Degraded) / 关键路径级联停(下游Stop上游Hold) / 可恢复PropagateHold(超时升级)
依赖闭包: 出边→下游消费者, 入边→上游供片, 无连通=无关; 菱形汇合缺路健康支继续,JoinBarrier安全等不丢片
两层栅栏: PJ内臂锁安全点 + 跨PJ全Paused
Abort续跑三原则: 已发生不回退 / 未完片以E90实际位置为准 / 从首个未完成PJ裁剪重编译(Aborted不可Resume,新建续跑CJ,记谱系)
Resume: ResumeToken各PJ恢复点+交接位(Pending/HandedOver/Received)+全局ID, 按E90实际重核, 交接幂等
```
费曼：一个地方坏了，要顺着"谁给它供片、它给谁供片"判断影响圈，能隔离就让其他支路继续，不能就上下游一起安全停；恢复时不相信记忆只信 E90 里片的真实位置，已经做过的不重来、没做的重新编排，做到不重一片、不漏一片。

## 图14 全链路十阶段主干
```
0通信上线(HSMS/S1F13-14/S1F17) →1 E84 Deposit硬线 →2 E87 Installed →3预约Loaded
→4 E90 SourceMap基线 →5 E94 Create CJ →6级联起首批E40 PJ →7多腔并发+跨PJ交接
→8严格完成聚合 →9 UnloadGuard→Unloaded→E84 Pickup
门控次序: 物理事实(E84/E90)→逻辑授权(E87 Loaded)→任务编排(E40/E94)
五层唯一权威: E30控制态/CarrierMgr/SubstrateTracker(唯一改位)/JobFSM/CjFSM; 跨层只读
消息: 请求应答对 vs 异步上报; 受理ACKC0≠生效(看迁移后事件); S16F1与S6F11同源
重连对账: HSMS→E87三对账→E90重建(P→L)→E40/E94(L→H)→Spool补发
```
费曼：整条线像过三道闸——先确认物理上真的到了、再确认系统授权、最后才派工，顺序绝不能反；每一层状态只有一个权威来源，别人只读不改；上位机回"收到"只是受理，真正生效要看状态迁移后的事件，断线恢复按从物理到逻辑的顺序一层层重建。

## 图15 E10/E116/OEE 时间树与损失瀑布
```
总时间=NonScheduled + Scheduled
Scheduled=Uptime(Productive/Standby/Engineering)+Downtime(SchDown/UnschDown) 两轴:计划/增值
E116状态段: 互斥(一刻一段)+完备(无缝叠,段和=总时长)+切换原子; 单调时钟计时UTC打点
采集两段式: 事件改信号→Classifier纯函数算态(与顺序无关); 提示报警/加工传片不切段
瀑布: 日历-NonSch→PPT-故障/换型→Run-小停/降速→净理想-质量损失→良品理想时间
A=Run/PPT P=IdealCT*Total/Run Q=Good/Total(FPY); OEE=A*P*Q=IdealCT*Good/PPT; TEEP=.../日历(≤OEE)
RAM: MTBF=运行/故障数 MTTR=修复/故障数 MDT含等待; 六损失 A故障换型/P小停降速/Q废品启动
```
费曼：把设备一天的时间切成互不重叠、首尾相接的小段并归类，等料是待机不是故障、提示报警不切段；这些时间一路扣到"良品理想时间"就是 OEE，三要素相乘；光修好故障不多出片 OEE 不会涨，必须把省下的时间变成合格产出。

## 二、15 图贯通串讲脚本（12–15 分钟主线，照此脱稿讲）
1. **建链**：HSMS 三态选通（图1），SECS2 自描述编码承载报文（图2），GEM 上线进 Remote（图3），配好采集三层（图4）与 OSS 对象模型（图5）。
2. **上料**：天车经 E84 硬线四相握手 Deposit（图6）→E87 物理 Installed、预约授权 Loaded（图7）。
3. **建账**：E90 扫 SourceMap、唯一位置账（图8），交叉取片守全局守恒（图9）。
4. **加工**：E94 建 CJ 编排（图12）→起 E40 PJ（图10）→多腔资源调度/防死锁/Swap（图11）。
5. **异常恢复**：故障按依赖闭包级联、两层栅栏安全停、按 E90 实际续跑（图13）。
6. **下料**：完成聚合、UnloadGuard、E84 Pickup（图14 收口）。
7. **度量**：全程时间段进 E116/E10，算 RAM 与 OEE 损失瀑布（图15），反哺改善。
