# W26 · Day01 笔试（上）标准答案与批改要点

> 批改：A=能默写且无原则错；B=方向对但有遗漏/小错；C=不会或原则错。C 当天回炉对应周。

## A. HSMS/E37
1. **控制状态/SType**：NOT CONNECTED（TCP 未连）→TCP 连上后 NOT SELECTED→发 Select.req 收到 Select.rsp 成功→SELECTED（可传数据消息）；断链/Select 失败回退。SType：1 Select.req、2 Select.rsp、3 Linktest.req、4 Linktest.rsp、5 Separate.req、6 未用/保留、7 Reject.req、8 未用、9 Separate（注：标准 SType 1..9，数据消息 SType=0；记忆以 1 Select.req/2 rsp、3/4 Linktest、5 Separate.req、7 Reject.req、9 Separate 为核心，精确表回查 W02）。
2. **超时**：T3 数据消息回复超时（约 45s，发了 Primary 等 Secondary）；T5 ConnectSeparate 建立连接超时（约 10s）；T6 控制事务超时（约 5s，Select/Linktest 等控制交换）；T7 选中后连接空闲保活超时（约 10s，到点发 Linktest）；T8 网络字节间隔超时（保活/帧间，约 5s 量级，精确值回查 W02）。
3. **帧结构**：前 4 字节大端长度（=其后 message header+body 字节数）+10 字节消息头（含 SessionID/SystemBytes、SType/W-bit 等）+body。Select.req 由主动建立 HSMS 会话的一方发起（通常 Host 主动连设备、或按配置，谁 Active 谁发 Select）。
4. **Ping 通但 Select 不成排查**：先确认 TCP 层（端口/IP/防火墙，Ping 通只代表网络层可达不代表端口开）；再看 HSMS 端口与 SessionID/DeviceID 是否匹配、对端是否已被别的连接占用（单会话）、Select.req 是否到达、有无 Select.rsp/Reject（SType7 及 reject reason）、T6 是否超时、双方 HSMS 模式（Active/Passive）与版本是否一致；抓包看帧长度/头是否合法。顺序：TCP 连通→端口监听→Select 收发→Reject/超时原因。

## B. E5/SECS2
5. **格式字节**：高 6 位=格式类型码，低 2 位=长度所占字节数−1（0..3，即长度用 1..4 字节）。类型码：L=8（0x08 段）、B=9、Boolean=10、A=16（ASCII）、J=17（JIS）、I8/I4/I2/I1=24/26/28/30 系列、F8=32、F4=33、U8/U4/U2/U1=40/42/44/46 系列（记忆：U1=0x24/U2=0xA9 段、U4=0xB1 段，精确编码见第 6 题与 W03）。
6. **字节序/编码**：多字节整数与长度字段均**大端（big-endian）**。U2 值 0x00A9：类型 U2 高 6 位=44（二进制 101100），长度 2 字节→低 2 位=1（长度字节数−1=1），格式字节=(44<<2)|1=177=0xB1，后跟长度字节 0x02，再跟大端数据 0x00 0xA9。F4：类型码 33，单长度字节时格式字节=(33<<2)|0=132=0x84。
7. **L,2[A"ON",U1 1] 编码思路**：先外层 List：类型 L(8)，2 个元素→格式字节(8<<2)|长度字节数指示，长度=2；元素①A"ON"：类型 A(16)，长度 3，内容 'O''N'（ASCII 字节）；元素②U1 值 1：类型 U1(46)，长度 1，数据 0x01。整体= L头 + A头+"ON" + U1头+01。长度字节数按元素实际长度是否超 255 决定 1/2/3 字节（本例都 1 字节长度）。
8. **解析未知报文**：按偏移读格式字节→拆出类型码(高6位)与长度字节数(低2位+1)→读长度 N→按类型取 N 字节内容；若是 L，则对其 N 个元素递归执行同样步骤，用"剩余待解析元素计数+偏移"控制直到整棵树消费完；全程大端还原数值，校验声明长度与实际剩余字节一致（不一致报格式错）。本质是递归下降的 TLV/Length-Value 解析。

## C. E30/GEM
9. **上电/建立通信**：上电默认 OFF-LINE（设备未与 Host 建立在线控制）。S1F17=Request On-Line（设备请求进入在线），Host 回 S1F18；S1F13=Establish Communications Request（交换建立通信），S1F14 回复携带 MDLN（设备型号）、SOFTREV（软件版本），用于双方识别与版本核对。
10. **远程命令**：S2F41 body=L,2[A RCMD（远程命令名）, L,n[L,2[A CPNAME,CPVALUE]]]（命令名 + n 组参数名值对）；S2F42 回 ACKC10，=0 表示**已接受（accepted）**该命令请求，但不代表已执行完成——真正执行完成要看后续状态迁移与 S6F11 事件（受理≠生效）。非 0 为拒绝（命令不存在/参数错等）。
11. **采集三层**：S2F33 Define Report（定义 RPT：把若干 VID 组成报告）、S2F35 Link Event Report（把 CEID 与 RPTID 关联）、运行时 S6F11 Event Report 上报（DATAID+CEID+各报告快照）；另 S2F37 配使能/禁用。顺序：先有 VID，再 S2F33 组 RPT，再 S2F35 关联 CEID，事件发生才 S6F11。
12. **报警/Spool**：S5F1 报警发送需先用 S5F3（Enable/Disable Alarm）使能该 ALID；S5F1 带 ALID、ALCD（含报警状态位：置位/清除）、ALTEX。Spool 缓存**上报类**消息 S6F11/S5F1/S16F1（设备主动发的事件/报警/执行确认），按序缓存、链路恢复后按序重发，收到对端确认后删除；T3 超时重发有上限（≤3 次），队列满按 FIFO 淘汰；命令类不盲目重发，走重连对账幂等。
13. **配方 S7**：S7F1 Process Job Load（上传/下发 PP，含 PPID+PPBODY）、S7F3 目录/选定 PP 下载请求方向、S7F17 Delete PP（删配方）；PPBODY 是 B（二进制）类型，配方正文按字节流传输，不解释为文本。

## D. E39/OSS
14. **六对象/元数据**：六对象=Physical/Logical Equipment、Module/Sensor/Actuator 等对象类与实例、属性、行为方法、集合、异常等（对象类 Class、实例 Instance、属性 Attribute、方法 Method、对象标识、数据规范，精确六概念回查 W09）。S14F1..F8 为 GetAttr 类元数据查询（按类/实例取属性目录），reply=L,2[U1 ACKC, List]；当查询集合为空时返回 L,0（空 List），而不是报错。
15. **S15 ACKC**：0 成功/接受；1 对象类型不存在；2 实例不存在；3 实例已存在；4 属性不存在；5 属性只读；6 缺少必填属性；7 属性值类型/数据不合法；8 当前状态不允许该操作（非法状态）；9 方法不存在；10 方法参数错；99 其他内部错误。S15F1/F2 建实例、F3/F4 删、F5/F6 查属性（严格按序）、F7/F8 设属性（两阶段原子）、F9/F10 调方法、F11/F12 存在性检查。
16. **S16/两阶段**：S16F1=L,3[A OBJSPEC（对象标识）, U4 CEID（事件）, L,n（属性名值快照）]，F2 为确认。S15F9/F10 调方法返回接受只代表请求被受理，方法异步执行完成由 S16F1 事件数据汇报（受理≠完成，同远程命令）。S15F7/F8 设属性是两阶段提交：先请求、校验全部属性可原子设置，再整体生效，任一属性非法则整体不生效（原子性，不会改一半）。

## E. E84/E87
17. **E84**：Local Parallel Transfer Interface，LoadPort 与 AMHS/OHT 之间的**并行硬线数字 I/O**，独立于 TCP/SECS（不走 HSMS）。三组信号：设备→小车（CS、ES、HO0/HO1 等）、小车→设备（SS、VR、TR_REQ、BUSY、COMPT、CONT 等）、双方共用（VALID、ESTOP、BYPS）。四相握手按信号相位推进；HO 位（HO0/HO1）每次交接翻转用于防丢拍/区分连续交接；VALID 做门控与去抖（信号稳定有效才认），整体 fail-safe（异常进入安全态）。
18. **Deposit/Pickup 先后**：Deposit（上料）——小车放好、COMPT 后载具在位信号 ON，再据此转 Installed（物理事实先于账面）；Pickup（下料）——账面先完成 Unloaded 授权，物理取走、COMPT 后在位信号 OFF（账面授权先于物理离开）。归属不确定（在位/握手信号矛盾、中途异常）时禁止自动重试，防止重复取放/撞盒，转人工确认。
19. **E87 状态/区别**：NotInstalled→Installed→（预约匹配）Loaded→加工完 Unloaded→取走回 NotInstalled。Installed=**物理事实**（载具已放到端口、探测在位）；Loaded=**逻辑授权**（预约/ID 校验通过、系统认可可用）。只有唯一 Loaded 的载具才允许设备自动从中取片；仅 Installed 未 Loaded 不能自动生产（防错料）。
20. **Hold/预约**：CarrierHold（载具级）、LotHold（批次级）、EquipmentHold（设备级），设备端**不能自行解除**，必须由设置方（Host/MES）按流程解除；设备如实保持受限并上报。预约（Reservation）通过事先下发的预期载具 ID/槽位/批次，在 Installed 时核对实际 ID 与预约，不匹配则不 Loaded、Hold/报警，从而防止上错料/错批次。

## 四、高频原则性错误（这些错=必须回炉）
1. SECS2 大小端写反、格式字节高低位拆错。
2. 把 S2F42 ACKC0/S15F10 接受当成执行完成。
3. S6F11 与 S2F33/35 定义顺序搞反或混淆。
4. Spool 缓存命令类、或重发不按序/确认前删除。
5. E84 当成走 TCP/SECS；Deposit/Pickup 账面与物理先后颠倒。
6. Installed 与 Loaded 混、以为 Installed 就能自动取片。
7. 以为设备能自解三类 Hold。
