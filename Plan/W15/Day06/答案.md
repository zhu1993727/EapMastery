# W15 · Day06 答案与参考实现

## 一、自测题标准答案
1. **混合交叉源盒 A 最终 SlotMap 如何定**：逐槽由 CrossMap 决定——对 A 的每个初始槽，看对应 Entry 类型：同槽 Entry（A:Sk→A:Sk）加工后片仍在 Sk，该槽保持占用且 ID 不变；跨盒 Entry（A:Sk→B:*）片转出后 Sk 应变空；没有 Entry 的槽保持初始状态不变。最终 A 的 SlotMap = 初始布局应用全部 Entry 后的结果：本例 S1=W1（同槽留）、S2 空（W2 转出）、S3=W3（同槽留）、S4 空（W4 转出）。终验时逐槽核对"该留的片在、该走的槽空"，并与目标盒 B 增加的片合起来守恒（总数 4）。
2. **分档动态生成 CrossMap 补哪些校验**：目标在加工后按量测结果才确定，动态分配目标槽时仍要满足全部计划/实时约束：①目标唯一——动态分配时不能给两片分同一目标槽（维护已分配目标集合）；②目标槽实时为空（查目标盒当前 SlotMap，不能分到已占槽）；③目标盒 Loaded 未 Hold（合格盒/返工盒都要在场可用）；④槽范围 1..25；⑤全局守恒（每个源片恰好被分配一个目标，不重不漏）；⑥结果等级与目标盒映射规则本身受控（哪类结果去哪个盒由工艺/Host 规则定，不可设备随意决定），并记录"该片为何被分到该盒"的判定依据用于追溯。动态只改变"目标怎么选"，不降低任何交叉校验标准。
3. **合批为何不能逐盒守恒 / 正确口径**：逐盒守恒（每盒源片数=目标片数）只适用于单源单目标的普通交叉；合批是 A、C 两个源盒汇入一个目标盒 G，A 减少 2、C 减少 2、G 增加 4，对任一单盒"源=目标"都不成立。正确口径是**全局片集合守恒**：所有源取出的 SubstrateId 集合 == 所有目标放入的集合（{W1,W2,U1,U2} 全局去重一致、总数 4 不变），即守恒范围覆盖全部参与载具、按片身份而非按盒计数。同时合/拆批改变批次构成，必须有显式批令授权（MergeSplitAuthorized）和来源批/目标批记录，否则 ValidatePlan 拒绝。
4. **F2 靠哪层 / 没有二次确认会怎样**：靠 **AtPlace 放置关的当下二次确认**兜住（Day04/05）。Preflight 在执行前看 B:S1 是空的，但执行时间窗内并行操作把它占用，AtPlace 在真正 Place 瞬间重新检查目标槽状态，发现已占即中止该 Entry、转暂存/挂起，绝不放入。若没有 AtPlace 二次确认、沿用预检旧结论直接 Place，就会把片放进一个已被占用的容量 1 槽位，造成叠片/碰撞，或覆盖/争抢该槽片身份，正是交叉混片和物理事故的典型来源；预检不能替代临放置前的 CAS 式复核。
5. **F3 退回源 vs Buffer 条件**：片已取出在臂/设备内、目标盒 Hold 时——**退回源原槽**适用于源载具仍在场且 Loaded、源原槽仍为空（没被别的片占用）、机构能安全返回，这是最干净的处置（片回到确定的原位置，CrossMap 状态回退，目标恢复后可重新执行）；**放 Buffer 暂存**适用于源已不可用（源盒也被取走/Hold）、源槽被占、或机构无法回源，但有空闲且受保护的 Buffer 位，此时把片放入 Buffer 保持唯一位置与守恒、挂起任务并记录，待条件恢复再续跑。两者都要求片有确定归属、守恒不破；若两者都不具备（无安全槽/位、物理状态不确定）则安全保持+人工，禁止强放目标或让片滞留臂上。
6. **F4 双臂争腔如何确定性串行**：不靠运行时偶然，而靠**逻辑时钟 + 全局资源表 + 固定申请顺序**确定性裁决。每个动作声明所需资源（含共享腔体 C1），调度器在每拍按确定顺序尝试原子占用：R1 的动作先申请到 {R1,C1}，资源表把 C1 标记忙；同拍 R2 的动作申请 {R2,C1} 时发现 C1 忙，本拍不执行、按公平队列下一拍再试，于是两动作必然串行、绝不并行进入 C1。因为调度是单线程逻辑时钟、资源"检查-占用"原子、申请顺序固定，结果每次运行都一致可复现，不存在真线程竞态下"有时碰撞有时正常"的不确定性。
7. **E90 全链路保证总结**：从 E87 载具 Loaded（授权可访问）开始，E90 注册每片并建立位置空间；交叉全程保证：每片有唯一确定位置（在途也归属臂/腔/Buffer）、每个位置不超容量（无叠片）、跨所有相关载具与设备内部全局守恒（无丢片）；CrossMap 逐片声明源→目标并经静态校验、实时预检、取片读码、放置前二次确认与放后读回、跨盒终验六道关，保证"对的片从对的源、走到对的目标槽、身份不混"；任何异常安全挂起或暂存/退回、可续跑可回退、轨迹审计完整；最终所有片归位、设备内清空、终验通过，才向 W13 UnloadGuard 提供片归位判据允许下料。一句话：E87 授权进出，E90 保证交叉过程中每一片"位置唯一、数量守恒、身份正确、全程可溯、归位才放"。

## 二、参考实现（net8.0，三场景）

### 场景二：量测分档动态生成 CrossMap
```csharp
public interface IMetrologySource { string GradeOf(string wafer); } // Pass / Fail
public static class SortingPlanner
{
    public static CrossMap Build(IEnumerable<string> wafers, (string carrier,SlotMap map) good,
        (string carrier,SlotMap map) rework, IMetrologySource metro, int[] srcSlots)
    {
        var map=new CrossMap(); int g=1,r=1; var usedG=new HashSet<int>(); var usedR=new HashSet<int>();
        int i=0;
        foreach(var w in wafers)
        {
            int src=srcSlots[i++];
            if(metro.GradeOf(w)=="Pass")
            { while(good.map.StateAt(g)==SlotState.Occupied||!usedG.Add(g)) g++; // 找空槽+目标唯一
              map.Add(new CrossEntry(w,new SlotRef("A",src),new SlotRef(good.carrier,g++),"RCP")); }
            else
            { while(rework.map.StateAt(r)==SlotState.Occupied||!usedR.Add(r)) r++;
              map.Add(new CrossEntry(w,new SlotRef("A",src),new SlotRef(rework.carrier,r++),"RWORK")); }
        }
        return map;
    }
}
```

## 四、今日易错点
1. 混合交叉不逐槽判定留/转（源盒最终布局要按 Entry 类型逐槽推导）。
2. 分档动态选目标时放松目标唯一/空槽/Loaded 校验（动态不降低标准）。
3. 合批用逐盒守恒（要全局片集合守恒+显式批令授权）。
4. 以为预检通过放置就安全（F2 证明必须 AtPlace 当下二次确认）。
5. 在途目标 Hold 强放或让片滞留臂上（退回/暂存，保持归属与守恒）。
6. 双臂并行靠运气不碰撞（逻辑时钟+资源表+固定顺序确定性串行）。
7. Rollback 只改状态不回搬物理片（必须经位置层逐片取回，守恒复原）。
8. 分档/合批不记录判定依据和批令（结果分档原因、批次构成必须可追溯）。
