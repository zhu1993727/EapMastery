# W15 · Day05 答案与参考实现

## 一、自测题标准答案
1. **分层 / 为何位置变更只能经位置层**：分层=计划层 CrossMap+ValidatePlan（方案自洽）→预检层 CrossPreflight（当下可行）→调度层 CrossScheduler（资源/Buffer/双臂，产出安全动作序列）→执行层 SubstrateTracker/LocationSpace（唯一真正改变片位置、守三不变式）→终验层 CrossFinalChecker（跨盒逐片验收）→恢复层 CrossRecovery。位置变更只能经 SubstrateTracker/LocationSpace，因为只有它在原子 Move 内做 expectedFrom 校验、容量检查、双向映射更新、不变式断言与回滚；若编排器或调度器绕过它直接改 SlotMap/位置，就会绕开所有安全保证，可能叠片、丢片、账实不一致。上层只负责"决定做什么动作、什么顺序"，底层位置层负责"安全地改变位置"，单一写入口是纵深防御的核心。
2. **Execute 六步 / 基线与快照时机**：①ValidatePlan 静态校验；②Preflight 实时预检；③**锁定基线总数与初始 SlotMap 快照**；④Scheduler 逐条产出动作并执行（AtPick 取片读码→Running，设备内 Transfer/Process 每步守恒，AtPlace 当下复核目标后放置读回→Done，目标被占先暂存占据者）；⑤全部 Done 后 CrossFinalChecker 跨盒终验；⑥输出 CrossResult。基线总数和初始快照在第③步（校验通过、开始改动之前）锁定，因为守恒校验需要一个"开始时到底多少片、各在哪"的权威参照，Rollback 也需要初始布局作为复原目标；一旦开始取放，SlotMap 就会变化，必须在任何改动前冻结初始值，否则基线随过程漂移、守恒和回退都失去正确基准。
3. **如何与 Scheduler 协作处理目标被占**：编排器准备放置某 Entry 前，Scheduler 判断其目标槽当前是否被另一片占据（该占据片也在本次 CrossMap 中待移动）。若被占，不直接放置，而是由 Scheduler 产出"先把占据片移到 Buffer"的前置动作（经位置层安全执行、占据片状态记为在途暂存），腾出目标槽后再执行当前 Entry 的 Place，最后再把 Buffer 里的占据片搬到它自己的目标。整个过程资源按固定顺序申请、双臂互斥、位置层逐步校验不变式，编排器按 Scheduler 给的序列驱动，形成"暂存占据者→当前片到位→暂存片归位"的无死锁顺序。
4. **某条失败为何进 Partial**：继续执行会基于错误前提连锁出错（例如目标 Hold 还往下搬会让更多片悬在途中、混片扩散）；全部清空/重置又不符合物理现实（已 Done 的片已在目标盒、Running 的片在设备内，软件清空不回搬物理片只会账实脱节）。进入 Partial 是唯一正确：立即停止后续调度，**完整保留每条 Entry 状态和每片实际位置、已发生的轨迹与快照**，使系统处于"已完成的确定、未完成的可知、在途的有归属"的受控中间态，再据此选择 Resume 续跑、Rollback 回退或人工，既不扩大错误也不丢失现场。
5. **CrossResult 为何带每片实际位置**：恢复决策必须以物理/实时位置为准而非计划状态。Resume 要知道 Running 片当前在哪个内部位置才能继续搬；Rollback 要知道 Done 片确实在目标槽才能取回；异常报警要告诉操作员每片真实在哪以便现场处置；终验和守恒也要实际位置核对。只带成功/失败标志不足以安全恢复，必须带每片 CurrentLocation（及 Entry 状态、期望目标、偏差），把"计划、现实、差异"一次交代清楚，这也是"认识世界听物理"在结果层面的体现。
6. **与 E40 ProcessJob 关系**：本周编排器是 E40 ProcessJob 的"位置安全搬运内核/前身"。CrossEntry（片、源、目标、Recipe）对应 PJ 中 Source/Destination 的片槽映射与加工配方；编排器的取-加工-放循环对应 PJ 执行时对每片的搬运与加工；Entry 状态机对应 PJ 内每片/每步的执行状态。W16 起 E40 会在此之上加入正式的 ProcessJob 对象、Job 状态机、加工步骤与配方参数、多腔体流程，E94 ControlJob 再编排多个 PJ。本周先保证"片从对的源到对的目标、全程位置安全守恒"，E40 再补"任务/工艺语义和状态机"。
7. **Unload 判据 / 接 W13**：交叉完成后能否 Unload 由 CrossFinalChecker 的结果提供（对接 W13 UnloadGuard 的 AllSubstratesReturned/片归位条件）：所有 Entry Done、源盒该转的都转出且留片正确、目标盒该到的都到且逐片 ID 对、全局守恒、设备内与 Buffer 全空，才认为片全部归位、允许相关载具 Unload；任一载具还有未归位片或终验不通过，UnloadGuard 拒绝下料。这样 W13 的下料总守卫从 E90 交叉层获得精确的逐片归位判据，和 W14 同槽场景形成统一出口。

### 编排器
```csharp
public sealed class CrossTransferOrchestrator
{
    private readonly SubstrateTracker _tracker;
    private readonly CrossScheduler _scheduler;
    private readonly CrossFinalChecker _final;
    private readonly CrossRecovery _recovery;
    private readonly IReadOnlyDictionary<string,SlotMap> _maps;
    private readonly Dictionary<string,SlotMap> _initialSnapshots=new();
    private readonly Func<string,bool> _loaded,_hold;
    private int _baseline;
    public CrossTransferOrchestrator(SubstrateTracker tracker,IReadOnlyDictionary<string,SlotMap> maps,
        Func<string,bool> loaded,Func<string,bool> hold)
    { _tracker=tracker; _maps=new Dictionary<string,SlotMap>(maps); foreach(var(k,v)in maps)_initialSnapshots[k]=Clone(v);
      _scheduler=new CrossScheduler(); _final=new CrossFinalChecker(); _recovery=new CrossRecovery(tracker);
      _loaded=loaded;_hold=hold; }
    static SlotMap Clone(SlotMap s){var c=new SlotMap();foreach(var sl in s.OccupiedSlots)c.SetOccupied(sl,s.IdAt(sl));return c;}

    public CrossResult Execute(CrossMap map)
    {
        var res=new CrossResult();
        var carriers=new HashSet<string>(_maps.Keys);
        // 1 静态校验
        var planIssues=map.ValidatePlan(carriers);
        if(planIssues.Any()){res.Issues=planIssues;return Fail(res);}
        // 2 预检
        var pre=new CrossPreflight(_tracker,_maps,_loaded,_hold).Check(map);
        if(pre.Any()){res.Issues=pre;return Fail(res);}
        // 3 锁基线
        _baseline=_maps.Values.Sum(m=>m.OccupiedCount);
        // 4 调度执行
        _scheduler.Schedule(map,
            targetOccupied:e=>!e.IsSameSlot && _maps[e.Dst.Carrier].StateAt(e.Dst.Slot)==SlotState.Occupied,
            move:(id,from,to)=>MoveOne(id,from,to,map,res),
            "Buffer:B1",new[]{"Robot:R1","Robot:R2"});
        Snapshot(res);
        // 5 终验
        var issues=_final.Verify(map,_maps,_initialSnapshots,InternalCount());
        res.Issues.AddRange(issues.Select(i=>new CrossIssue(CrossIssueCode.Conservation,i.Detail)));
        foreach(var e in map.Entries)(e.Status==EntryStatus.Done?res.Done:res.Failed).Add(e.Id);
        foreach(var e in map.Entries) res.Positions.Add(new(e.Id,e.Status.ToString(),_tracker.LocationOf(e.Id).Key,$"{e.Dst.Carrier}:S{e.Dst.Slot}"));
        res.Success = res.Issues.Count==0 && res.Failed.Count==0;
        return res;
    }

    private void MoveOne(string id,string from,string to,CrossMap map,CrossResult res)
    {
        // 解析 (carrier,slot) / 内部位置, 教学简化: from/to 形如 "A:S1" 或 "Internal:Robot:R1"
        var e=map.Entries.FirstOrDefault(x=>x.Id==id);
        // AtPick + 路径 + AtPlace 均经 SubstrateTracker(位置层), 此处给出同/跨盒主干
        if(e is null) return;
        // AtPick: 读码核对(源槽Id==e.Id)在Preflight/AtPick保证; 取片
        _tracker.Pick(e.Id,e.Src.Carrier,e.Src.Slot,"Robot:R1"); e.Status=EntryStatus.Running;
        // 设备内(可Process,略) → AtPlace 当下复核
        if(_hold(e.Dst.Carrier)) throw new InvalidOperationException($"{id} 目标Hold→Partial,退回/暂存");
        _tracker.Place(e.Id,"Robot:R1",e.Dst.Carrier,e.Dst.Slot); // 内部已做容量/不变式
        if(_maps[e.Dst.Carrier].IdAt(e.Dst.Slot)!=e.Id) throw new InvalidOperationException($"{id} 读回不符");
        e.Status=EntryStatus.Done;
    }
    private int InternalCount()=>0; // 教学:终验时设备内应已清空,实际从LocationSpace统计
    private void Snapshot(CrossResult res)=>
        res.BalanceSnapshots.Add(GlobalBalance.Snapshot(_maps,InternalCount(),_baseline));
    private static CrossResult Fail(CrossResult r){r.Success=false;return r;}

    public CrossResult Resume(CrossMap map,IDictionary<string,string> runningAt)
    { _recovery.Resume(map,runningAt); return Execute(map); }
    public void Rollback(CrossMap map)=>_recovery.Rollback(map);
}
```
> 说明：MoveOne 用 SubstrateTracker 的 Pick/Place 走位置层（W14），Scheduler 负责顺序与暂存；真实实现中 from/to 解析、Process 路径、双臂选择按设备结构细化，架构与安全边界不变。

public class OrchestratorTests
{
    [Fact] public void 两片跨盒_端到端成功_终验守恒()
    {
        var t=BuildTrackerLoaded(out var A,out var B);
        var maps=new Dictionary<string,SlotMap>{{"A",A},{"B",B}};
        var orch=new CrossTransferOrchestrator(t,maps,c=>true,c=>false);
        var map=new CrossMap().Add(new("W1",new("A",1),new("B",1),"R"))
                              .Add(new("W3",new("A",3),new("B",2),"R"));
        var r=orch.Execute(map);
        Assert.True(r.Success); Assert.Equal("W1",B.IdAt(1)); Assert.Equal("W3",B.IdAt(2));
        Assert.Equal(SlotState.Empty,A.StateAt(1));
    }
    [Fact] public void 目标盒Hold_进入Partial_可Rollback复原()
    {
        var t=BuildTrackerLoaded(out var A,out var B);
        var maps=new Dictionary<string,SlotMap>{{"A",A},{"B",B}};
        bool holdB=false;
        var orch=new CrossTransferOrchestrator(t,maps,c=>true,c=>c=="B"&&holdB);
        var map=new CrossMap().Add(new("W1",new("A",1),new("B",1),"R"));
        holdB=true;
        var r=orch.Execute(map);
        Assert.False(r.Success); Assert.True(r.IsPartial||r.Failed.Count>0);
        orch.Rollback(map);
        Assert.Equal("W1",A.IdAt(1)); t.Snapshot();
    }
}

## 三、编排全链路（手绘参考）
```
CrossMap ─ValidatePlan─► Preflight ─锁基线/初始快照─► Scheduler(资源/Buffer/双臂)
   逐Entry: AtPick(Pick+读码,Running) → 设备内Transfer/Process(每步守恒)
            → AtPlace(当下复核目标空/未Hold → Place → 读回ID,Done)
            目标被占: 占据者先Buffer → 当前片到位 → 暂存片归位
   全部Done → CrossFinalChecker(源逐片/目标逐片/全局守恒/Buffer空)
   失败 → Partial(保留状态+每片实际位置) → Resume/Rollback/人工
   通过 → 输出CrossResult → W13 UnloadGuard获得片归位判据
```

## 四、今日易错点
1. 编排器/调度器绕过位置层直接改 SlotMap（丢失全部不变式保护，唯一写入口必须是 LocationSpace）。
2. 基线和初始快照在开始改动后才记录（守恒/回退基准漂移）。
3. 目标被占直接硬放或跳过（要 Scheduler 暂存占据者、无死锁排序）。
4. 失败后继续执行或整体重置（应进 Partial 保留现场与实际位置）。
5. CrossResult 只报成败不报每片实际位置（无法安全 Resume/Rollback/人工）。
6. AtPlace 用预检旧结论，不当下复核（时间窗内目标可能被占/Hold）。
7. Rollback 不逐片经位置层、不守恒（复原动作同样要安全校验）。
8. 交叉终验通过才 Unload 的链路没接到 W13 守卫（片未归位不得下料）。
