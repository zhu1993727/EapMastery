## 二、编排器结构（先读，25 分钟）

### 1. 依赖与分层
```
CrossTransferOrchestrator
 ├ CrossMap(计划) ─ ValidatePlan(静态)
 ├ CrossPreflight(实时预检, 依赖 SubstrateTracker 的 SlotMap/载具状态)
 ├ CrossScheduler(资源/Buffer/双臂, 产出安全动作序列)
 ├ SubstrateTracker(W14: Pick/Place/Transfer/Process + 位置空间/不变式)
 ├ CrossFinalChecker(跨盒终验)
 ├ CrossRecovery(Resume/Rollback)
 └ 事件/审计/守恒快照输出
分层原则: 计划校验→时机预检→调度规划→位置层执行(唯一改变位置)→终验; 每层只负责自己的事
```

### 2. 主流程 Execute
```
1 ValidatePlan: 有静态问题→拒绝, 返回问题列表
2 Preflight: 实时条件不满足→不下发(或按策略等待), 返回问题
3 锁定基线总数, 记录初始SlotMap快照(供Rollback/FinalCheck)
4 Scheduler 逐条产出动作; 对每条Entry:
   AtPick: Pick + 读码核对(模拟IdAt源), Running
   设备内路径(可选Process): Transfer/Process, 每步守恒快照
   AtPlace: 当下复核目标空/未Hold → Place → 读回ID核对 → Done
   目标被占: Scheduler 先把占据者移Buffer
5 全部Done后 CrossFinalChecker 跨盒终验
6 输出结果(成功/异常条目/守恒快照/事件轨迹)
任一安全校验失败: 中止后续、保留状态、进入Partial, 等待Resume/Rollback/人工
```

### 3. 执行策略与可注入
- `ICrossExecutor`：抽象实际取放（教学用 SubstrateTracker，真实对接运动控制），便于注入故障（Day06 演练）。
- 载具 Hold/Loaded 状态以委托注入，和 W13 模式一致。
- 时钟/事件用逻辑顺序，确定性可复现。

### 4. 结果对象
```
CrossResult: Success, DoneEntries, FailedEntries, BalanceSnapshots, Events, Issues
失败时含每片当前实际位置, 供恢复决策
```

### 5. 与 W14/W13 的衔接点
- 载具必须 E87 Loaded（SubstrateTracker 门控，W14/W12）。
- 交叉完成、FinalCheck 通过，才允许相关载具 Unload（W13 UnloadGuard 的片归位判据）。
- 位置迁移全部经 W14 LocationSpace，保证三不变式，编排器不直接改位置。

### 6. 为 E40 做的预留
- CrossEntry 已含 Recipe/路径，后续扩展为 ProcessJob 的 Source/Destination 映射与加工步骤；
- 编排器执行循环后续由 E40 PJ 状态机驱动（W16-W18），本周先实现"位置安全的交叉搬运"。
