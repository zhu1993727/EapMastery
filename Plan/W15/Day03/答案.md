# W15 · Day03 答案与参考实现

## 一、自测题标准答案
1. **单臂交换为何要 Buffer / 三步**：单臂容量 1，一次只能持一片。要把 S1 的 W1 和 S3 的 W3 互换：臂取走 W1 后，W3 要放进 S1，但此时臂被 W1 占着、无法同时再取 W3；而要腾出手必须先放下 W1，可 W1 的目标 S3 又被 W3 占着——形成"W1 等 S3 空、W3 等 S1 空、臂只能持一片"的循环。Buffer 提供第三个临时位置打破循环：①W1：S1→臂→Buffer（腾出 S1）；②W3：S3→臂→S1（W3 到位、腾出 S3）；③W1：Buffer→臂→S3（W1 到位）。等价两变量交换需要第三个临时变量。
2. **Buffer 是否法外之地 / 约束**：不是，Buffer 是受同样不变式约束的正规位置。片在 Buffer：①有明确唯一位置（具体 Buffer 位），计入唯一位置不变式；②受 Buffer 容量约束，不能超位（每个 Buffer 位容量 1）；③计入全局守恒（InternalCount 含 Buffer 占用，在途/暂存片不丢）；④记录轨迹（何时进/出 Buffer、原因）；⑤下料 Final Check 时 Buffer 必须清空（LeftInside 检测同样覆盖 Buffer），片不能长期遗忘在暂存位。Buffer 只是"临时停放"，不是脱离账本。
3. **位置占用环 / 检测打破**：位置占用环指若干待移动片形成循环等待——片 A 的目标槽被片 B 占着、B 的目标被 C 占、C 的目标又被 A 占，谁都无法直接到位（都要等对方先腾）。检测：把"占据者→等待者"建成有向依赖图，出现环（可 DFS 找回路/并查集）即死锁。打破：把环中任一片先移到 Buffer，释放它占据的槽，环就断开，其余片可依次到位，最后把 Buffer 的片放到已腾出的目标。本质是用额外容量（Buffer）打破循环等待这一死锁必要条件。
4. **双臂 swap 提效原理 / 互锁**：双臂 R1/R2 各容量 1，可在一次往返中让一只臂从某位置取片的同时另一只臂向该位置（或相邻工位）放片，一次动作完成"放+取"，省去单臂"空手去、取片回、再空手去放"的空行程，显著减少搬运时间（常见于腔体交换：一臂放未加工片进腔同时另一臂取走已加工片）。互锁条件：两臂绝不能同时访问同一物理位置（同槽/同腔/同 Buffer 位/同一 LoadLock），不能进入彼此的物理干涉区（共享轴、重叠行程），冲突资源必须串行；还要符合腔体/锁的工艺约束（如不能同时开同一闸门）。
5. **不用真线程模拟并行且互斥**：用**逻辑时钟 + 资源占用表**做确定性调度（同 W11 模拟器，避免线程竞态、可复现）。每个动作声明它需要的资源集合 lockResources（如 {R1,Slot5} 或 {R2,C1}）和占用区间；调度器按拍推进，启动动作前检查其所需资源当前是否全部空闲，空闲则原子占用、动作结束释放，被占则该动作等待（这一拍不执行）。这样不冲突的动作可在同一拍并行推进，争用同一资源的动作自动串行，互斥由"资源表检查-占用"的原子性保证，结果确定、易测、易复现，又如实反映了物理互锁。
6. **统一资源申请顺序防死锁**：并发死锁的必要条件之一是"循环等待"——多个流程以不同顺序持有并申请资源（甲先占槽再申请臂、乙先占臂再申请槽）形成等待环。规定所有动作**按全局固定顺序申请资源**（例如按 LocationId/资源名排序后依次加锁，逆序释放），则资源等待关系不可能成环（没人会"持有排序靠后的资源再去等排序靠前的资源"），从而破坏循环等待条件、预防资源级死锁。注意它解决"资源等待环"，而槽位占用环仍需 Buffer 打破，二者是两类不同的环。
7. **为何调度序列要被 LocationSpace 逐步验证**：调度器只做"动作规划"，它输出的序列是否真的安全（每步源有片、目标空、容量不超、片身份对、最终守恒）必须由位置事实层 LocationSpace 在逐步执行时用三不变式校验，形成"规划-执行-校验"闭环。这样调度算法的任何 bug（错误并行、漏暂存、环没打破）都会在执行对应动作时被 Move 的前置校验和不变式断言即时拦截并回滚，而不是产生错误的物理动作；同时保证无论调度怎么优化，落到底层永远满足唯一位置/容量/守恒。调度器负责高效，LocationSpace 负责正确，职责分离、纵深防御。

## 二、参考实现（net8.0，逻辑时钟调度）

### 资源与动作
```csharp
namespace EapLab.E90.Sched;
public sealed record MoveAction(string Wafer,string From,string To,string Arm,string[] Resources);

public sealed class ResourceTable   // 逻辑时钟资源互斥
{
    private readonly HashSet<string> _busy=new();
    public bool CanAcquire(IEnumerable<string> res)=>res.All(r=>!_busy.Contains(r));
    public bool TryAcquire(IEnumerable<string> res)
    { var list=res.ToArray(); lock(this){ if(!CanAcquire(list))return false; foreach(var r in list)_busy.Add(r); return true; } }
    public void Release(IEnumerable<string> res){ foreach(var r in res)_busy.Remove(r); }
}
```

### 单臂交换（Buffer 打破环）
```csharp
public static class SingleArmSwap
{   // 交换 same carrier 的 sA/sB 两片, buffer 为暂存槽位(设备内)
    public static List<MoveAction> Swap(string carrier,int sA,int sB,string arm,string buffer)
    {
        var a=$"Carrier:{carrier}:S{sA}", b=$"Carrier:{carrier}:S{sB}";
        return new()
        {
            new("Wafer@"+sA,a,buffer,arm,new[]{arm,a,buffer}),
            new("Wafer@"+sB,b,a,arm,new[]{arm,b,a}),
            new("Wafer@"+sA,buffer,b,arm,new[]{arm,buffer,b}),
        };
    }
}
```

### 最小调度器（目标被占→Buffer 暂存；双臂资源互斥）
```csharp
public sealed class CrossScheduler
{
    private readonly ResourceTable _res=new();
    private readonly List<string> _busyTargets=new(); // 被暂存片腾出逻辑(简化)
    public List<string> Executed { get; }=new();
    private int _clock;
    // 逐条执行交叉; 若目标被占, 先把占据者移到buffer
    public void Schedule(Cross.CrossMap map, Func<Cross.CrossEntry,bool> targetOccupied,
        Action<string,string,string> move, string buffer, string[] arms)
    {
        var pending=new Queue<Cross.CrossEntry>(map.Entries);
        var armIdx=0;
        while(pending.Count>0)
        {
            var e=pending.Dequeue();
            var arm=arms[armIdx++%arms.Length];
            var src=$"{e.Src.Carrier}:S{e.Src.Slot}", dst=$"{e.Dst.Carrier}:S{e.Dst.Slot}";
            var need=new[]{arm,src,dst}.OrderBy(x=>x).ToArray();   // 统一顺序申请,防资源环
            if(!_res.TryAcquire(need)){ pending.Enqueue(e); continue; } // 资源忙,重新排队(公平)
            try
            {
                if(targetOccupied(e))   // 目标被另一片占: 占据者先去Buffer
                { var blocker=$"blocker-of:{dst}";
                  if(!_res.TryAcquire(new[]{arm,buffer}.OrderBy(x=>x).ToArray())){ pending.Enqueue(e); continue; }
                  move(blocker,dst,buffer); Executed.Add($"{_clock}: {blocker} {dst}->{buffer} (暂存)");
                  _res.Release(new[]{arm,buffer});
                }
                move(e.Id,src,dst); Executed.Add($"{_clock}: {e.Id} {src}->{dst} via {arm}");
                e.Status=Cross.EntryStatus.Done;
            }
            finally{ _res.Release(need); _clock++; }
        }
    }
}
```

### xUnit
```csharp
public class SchedulerTests
{
    [Fact] public void 单臂两槽交换_序列含Buffer且三步()
    { var seq=SingleArmSwap.Swap("A",1,3,"R1","Buffer:B1");
      Assert.Equal(3,seq.Count); Assert.Contains(seq,a=>a.To=="Buffer:B1");
      Assert.Equal("Carrier:A:S1",seq[2].To); }

    [Fact] public void 双臂同资源_第二个动作等待不并行()
    { var t=new ResourceTable();
      Assert.True(t.TryAcquire(new[]{"R1","C1"}));
      Assert.False(t.TryAcquire(new[]{"R2","C1"})); // 同腔C1互斥,必须串行
      t.Release(new[]{"R1","C1"});
      Assert.True(t.TryAcquire(new[]{"R2","C1"})); }

    [Fact] public void 双臂不冲突资源_可同时占用()
    { var t=new ResourceTable();
      Assert.True(t.TryAcquire(new[]{"R1","C1"}));
      Assert.True(t.TryAcquire(new[]{"R2","C2"})); } // 不同腔,可并行

    [Fact] public void 统一顺序申请_不会自相死锁()
    { // 两动作资源集合相同但都按排序申请, ResourceTable 原子判定, 一个获一个等, 无环
      var t=new ResourceTable();
      var r1=new[]{"A","B"}.OrderBy(x=>x).ToArray();
      var r2=new[]{"B","A"}.OrderBy(x=>x).ToArray();
      Assert.True(t.TryAcquire(r1)); Assert.False(t.TryAcquire(r2)); }
}
```

## 三、调度决策流程（手绘参考）
```
取下一条Entry ──资源(臂/源/目标)按固定顺序申请
   ├ 资源忙 → 重新入公平队列(不阻塞,防饥饿)
   ├ 目标被占 → 占据者先移Buffer(打破占用环)→再搬当前片→后续处理Buffer片
   └ 资源齐 → Pick源→(设备内路径)→Place目标, LocationSpace逐步校验三不变式
双臂: 动作声明资源; 不冲突同拍并行, 争用同位置/干涉区串行; 全部完成后Buffer必须清空
```

## 四、今日易错点
1. 以为单臂能直接交换两槽（容量 1 必须 Buffer 暂存，三步）。
2. 把 Buffer 当账外位置（同样守唯一/容量/守恒、Final Check 要清空）。
3. 不检测位置占用环导致死锁（DFS 找环、Buffer 打破）。
4. 双臂只看臂不同就并行（同槽/同腔/同锁/干涉区也要互斥）。
5. 用真线程模拟并行导致竞态难复现（逻辑时钟+资源表确定性调度）。
6. 资源申请顺序不一致形成等待环（固定全局顺序加锁）。
7. 调度器自认为正确却不经 LocationSpace 执行校验（规划与事实校验分离、纵深防御）。
8. 暂存片忘记后续归位（Buffer 片要有明确后续动作，下料前清空）。
