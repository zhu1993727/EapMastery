# W15 · Day04（周四）交叉场景逐片校验与异常处置

> 建议时长：85 分钟。交叉取片把两个载具耦合，异常面比同槽更大。今天系统梳理交叉全流程的逐片校验点、交叉特有异常（在途中止、目标盒异常、跨盒混片等）与安全处置策略，并实现交叉版 Final Check。

## 一、今日目标
1. 建立交叉全流程校验链：计划校验→预检→取片校验→在途监控→放置校验→跨盒终验。
2. 掌握交叉特有异常：源盒异常取走、目标盒 Hold/取走/满载、在途片悬置、跨盒 ID 混片、部分完成。
3. 实现交叉 Final Check：源/目标双盒按 CrossMap 逐片验收 + 全局守恒 + Buffer 清空。
4. 掌握部分完成（Partial Complete）的状态保留与恢复/续跑/回退策略。
5. xUnit 覆盖交叉五类异常与部分完成恢复。

## 二、背景知识（先读，30 分钟）

### 1. 交叉全流程校验链（六道关）
1. **计划校验 ValidatePlan**：CrossMap 自洽（Day02）。
2. **预检 Preflight**：源有该片、目标空、双盒 Loaded 未 Hold（Day02）。
3. **取片校验 AtPick**：实际取到的片 ID==Entry.Id（读码复核），源槽正确变空，Entry→Running。
4. **在途监控 InTransit**：片在设备内位置明确、守恒；目标盒状态持续可用；双臂/Buffer 无冲突。
5. **放置校验 AtPlace**：放置前再次确认目标槽仍空（可能被其他流程占用）、目标未 Hold，放后读回确认该槽 ID==Entry.Id，Entry→Done。
6. **跨盒终验 FinalCheck**：所有 Entry Done；源盒"该走的都走、留的都对"，目标盒"该到的都到且 ID 对"；全局守恒、设备内/Buffer 全空。

### 2. 交叉特有异常
- **源盒在取片后异常（卸载/掉线/Hold）**：片已离开源盒，源盒状态变化不影响在途片，但要决定片还能否回/去目标，记录"源已不在场"。
- **目标盒 Hold/满载/被取走（在途时）**：片已取出却无法放入声明目标。处置：安全退回到源原槽（源还在）或放 Buffer 暂存挂起，绝不能强放或丢在臂上；目标恢复后续跑。
- **在途片悬置**：设备故障/急停时片停在臂/腔/Buffer，位置确定但任务未完成，需要恢复流程（W11/W13 归属原则：位置确定可安全保持/续跑，归属不明人工）。
- **跨盒 ID 混片**：放后读回 ID≠Entry.Id，或目标槽出现非计划片，立即冻结两盒、报警，防污染扩散。
- **部分完成 Partial**：CrossMap 中部分 Entry Done、部分 Pending/Running 时中断。必须保留每条 Entry 精确状态和片实际位置，支持续跑（从未完成继续）或安全回退（把已搬片退回源），不能整体重置。

### 3. 放置前"二次确认"的必要性
- 预检通过到真正放置之间有时间窗，目标槽可能被另一条并行 Entry、手动操作或异常占用，目标盒可能被 Hold。AtPlace 必须基于**当下**状态再判一次（compare-and-set 思想），不能用预检时的旧结论。

### 4. 交叉 Final Check（逐片）
```
对每条 Entry:
  Done 要求: 源槽现状符合(该走则空/同槽则是该片), 目标槽 Occupied 且 Id==Entry.Id
源盒核对: 现存片 == (初始片 - 应转出片) 集合, 逐槽ID对
目标盒核对: 现存片 == 应转入片集合, 逐槽ID对
全局: 源剩余 + 目标现存 = 初始总数; 设备内/Buffer=0; 无 Running/Failed 悬挂
合/拆批: 按批令核对批次构成
```

### 5. 部分完成恢复策略
- **续跑 Resume**（首选，条件允许）：加载 CrossMap 与实时位置，对 Running 片先确认其实际位置，继续完成到目标；Pending 片照常执行；全程不变式。
- **回退 Rollback**（目标不可用且需撤销）：把 Done 的片按反向映射从目标取回放回源，恢复初始布局（同样逐片校验、守恒）。
- **安全保持+人工**（有片归属/物理不确定）：冻结、报警、记录现场，人工确认后选择续跑/回退。
- 三种策略都以"片实际位置"为准，禁止凭 CrossMap 状态想当然。

### 6. 审计与追溯
- 交叉涉及两 lot，每条 Entry 的取/放/读码/异常/恢复都进审计与轨迹，支持事后还原"哪片何时从哪到哪、谁中断、如何恢复"。
