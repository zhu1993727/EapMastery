# W15 · Day04 答案与参考实现

## 一、自测题标准答案
1. **六道关 / AtPick、AtPlace 确认什么**：①ValidatePlan 计划自洽；②Preflight 执行前源有片/目标空/双盒可用；③AtPick 取片关：实际从源槽取到的片读码 ID==Entry.Id、确从声明源槽取、取后源槽正确变空，Entry 才置 Running；④InTransit 在途关：片在设备内位置明确、全局守恒、目标盒持续可用、资源无冲突；⑤AtPlace 放置关：放置当下再确认目标槽仍空且目标盒未 Hold，放后读回该槽 ID==Entry.Id，才置 Done；⑥FinalCheck 跨盒终验。AtPick 确认"取对了片、从对的槽取走"（防空取/错取），AtPlace 确认"放到当下仍可用的对的目标槽、放进去的就是这片"（防预检后变化导致的错放/叠片/混片）。
2. **放置前二次确认 / 思想**：Preflight 在执行前检查通过，但从预检到真正放置存在时间窗，期间并行 Entry、手动操作、异常都可能改变目标槽（被占）或让目标盒被 Hold/取走，预检结论会过期。AtPlace 必须基于**当下实时状态**再判一次目标空、未 Hold 才放，这是 compare-and-set（CAS，比较并设置）/乐观并发思想：不假设旧观察仍有效，在真正改变世界的瞬间重新验证前提，前提变化就中止该条并走异常处置，避免用过期信息把片放到已占/已禁的槽。
3. **在途目标盒 Hold 处置 / 不能怎么做**：片已从源取出、在臂/设备内（位置确定、守恒未破），目标已不可放。正确：优先安全**退回源原槽**（源盒仍在场且原槽空，记录一次恢复迁移与原因），源不可用则放入指定 **Buffer 暂存并挂起任务**，保持片唯一位置与守恒、轨迹留痕，等目标盒解除 Hold 后续跑完成。不能：①强行放入已 Hold 的目标盒（逻辑禁止还改变物理）；②让片长期停在臂上不管（占用臂、阻塞调度且不安全）；③直接改 CrossMap 换个没授权的目标槽（未经授权改变流向=潜在混片）；④丢弃或在账目上"假定已到目标"（造假、丢片）。
4. **Final Check 如何核对源/目标盒**：逐 Entry 验收——Done 条目其源槽现状正确（跨盒则源槽应空、同槽则仍是该片）、目标槽 Occupied 且 ID==Entry.Id。源盒整体：现存片集合应恰等于"初始片集合减去应转出片集合"，逐槽 ID 对，既没多转也没少转；目标盒整体：现存片集合恰等于"应转入片集合"，逐槽 ID 对。再做全局：源剩余数+目标现存数=初始总数（全局守恒），设备内位置与 Buffer 全空（无 LeftInside），没有 Running/Failed 悬挂条目；合/拆批还要按批令核对批次构成。任一不符按 Missing/Double/Misplaced/WrongId/LeftInside 分类并冻结。
5. **部分完成 / 为何不能整体重置 / Resume 与 Rollback**：部分完成指交叉中断时 CrossMap 里一部分 Entry 已 Done、一部分 Running（片在设备内）、一部分 Pending。不能整体重置，因为物理上 Done 的片已经在目标盒、Running 的片在设备内，重置软件状态不会把物理片搬回去，反而造成账实脱节、丢片/混片。必须保留每条 Entry 精确状态和每片实际位置。**Resume 续跑**（首选，目标恢复可用时）：以实时位置为准，Running 片先定位再继续搬到目标，Pending 片正常执行，最终达成 CrossMap。**Rollback 回退**（目标确定不可用、需撤销本次交叉时）：对已 Done 片按反向映射从目标取回放回源、Running 片退回，逐片校验守恒，恢复初始布局。若片归属或物理状态不确定，则安全保持+人工，不自动续/退。
6. **放后读回 ID 不符 / 处置**：说明放入声明目标槽的片不是 Entry 声明的片——可能放错片（交叉混片）、读码错误、目标槽被并行操作放入别的片、或片在搬运中被对调。处置：立即将该 Entry 置 Failed、冻结源和目标两个载具（防止错误片继续流向下游扩大污染）、保留现场与全部轨迹/读码记录、发高级告警（声明 ID、实际读回 ID、槽位、相关 Entry），人工核对物理片刻码后决定纠正/隔离/返工，禁止软件直接改写 ID 或移动来"对齐"CrossMap（那会掩盖混片事故）。
7. **审计细到每 Entry 取放读码的原因**：交叉一次耦合两个载具、两批 lot，错误追溯范围大。只有为每条 Entry 记录"何时从哪个源槽取、取到的片读码是什么、经哪些设备内位置、何时放入哪个目标槽、放后读回是什么、有无异常与恢复动作、操作/任务主体"，才能在出现混片/良率问题时逐片还原真实流向、判断错在哪一步、精确圈定受影响的片和批次范围、满足质量追溯与客户审计；粗粒度记录（只记"交叉完成"）在出问题时无法区分是计划错、读码错、并行冲突还是放错槽，无法定责和止损。

### 交叉终验
```csharp
namespace EapLab.E90.Cross;
public sealed class CrossFinalChecker
{
    public List<Issue> Verify(CrossMap map,
        IReadOnlyDictionary<string,SlotMap> now,                 // 当前各载具SlotMap
        IReadOnlyDictionary<string,SlotMap> initial,              // 初始各载具SlotMap
        int internalCount)
    {
        var issues=new List<Issue>();
        foreach(var e in map.Entries)
        {
            if(e.Status!=EntryStatus.Done){ issues.Add(new(ConsistencyIssue.LeftInside,$"{e.Id} 未Done({e.Status})")); continue; }
            var dst=now[e.Dst.Carrier];
            if(dst.StateAt(e.Dst.Slot)!=SlotState.Occupied)
                issues.Add(new(ConsistencyIssue.Missing,$"{e.Id} 目标槽{e.Dst}空"));
            else if(dst.IdAt(e.Dst.Slot)!=e.Id)
                issues.Add(new(ConsistencyIssue.WrongId,$"{e.Id} 目标槽实际{dst.IdAt(e.Dst.Slot)}"));
            if(!e.IsSameSlot && now[e.Src.Carrier].StateAt(e.Src.Slot)==SlotState.Occupied)
                issues.Add(new(ConsistencyIssue.Misplaced,$"{e.Id} 源槽{e.Src}未清空"));
        }
        int nowTotal=now.Values.Sum(m=>m.OccupiedCount)+internalCount;
        int initTotal=initial.Values.Sum(m=>m.OccupiedCount);
        if(nowTotal!=initTotal) issues.Add(new(ConsistencyIssue.Missing,$"跨盒守恒破坏 now={nowTotal} init={initTotal}"));
        if(internalCount>0) issues.Add(new(ConsistencyIssue.LeftInside,$"设备内/Buffer残留 {internalCount}"));
        return issues;
    }
}
```

### 部分完成恢复
```csharp
public sealed class CrossRecovery
{
    private readonly SubstrateTracker _t;
    public CrossRecovery(SubstrateTracker t){_t=t;}

    // 续跑: 以实时位置为准把未完成条目做到目标(简化:Running片需调用方告知其当前内部位置)
    public void Resume(CrossMap map, IDictionary<string,string> runningAtInternal)
    {
        foreach(var e in map.Entries)
        {
            if(e.Status==EntryStatus.Done) continue;
            if(e.Status==EntryStatus.Running && runningAtInternal.TryGetValue(e.Id,out var internalLoc))
            {   // 从其实际所在内部位置继续搬到目标
                _t.TransferInternal(e.Id,internalLoc,"Robot:R1");
                _t.Place(e.Id,"Robot:R1",e.Dst.Carrier,e.Dst.Slot);
                e.Status=EntryStatus.Done;
            }
            else if(e.Status==EntryStatus.Pending)
            {   // 正常从头执行(路径简化)
                _t.Pick(e.Id,e.Src.Carrier,e.Src.Slot,"Robot:R1");
                _t.Place(e.Id,"Robot:R1",e.Dst.Carrier,e.Dst.Slot);
                e.Status=EntryStatus.Done;
            }
        }
    }
    // 回退: 已Done片从目标取回放回源, 恢复初始布局
    public void Rollback(CrossMap map)
    {
        foreach(var e in map.Entries.Where(x=>x.Status==EntryStatus.Done))
        {
            _t.Pick(e.Id,e.Dst.Carrier,e.Dst.Slot,"Robot:R1");
            _t.Place(e.Id,"Robot:R1",e.Src.Carrier,e.Src.Slot,SubstrateState.OnCarrier);
            e.Status=EntryStatus.Pending;
        }
    }
}
```

```csharp
public void SafePlace(CrossEntry e, IReadOnlyDictionary<string,SlotMap> now, Func<string,bool> hold)
{
    // AtPlace: 当下再确认, 而非用Preflight旧结论
    if(hold(e.Dst.Carrier)) throw new InvalidOperationException($"{e.Id} 目标盒Hold, 退回/暂存");
    var dst=now[e.Dst.Carrier];
    if(!e.IsSameSlot && dst.StateAt(e.Dst.Slot)==SlotState.Occupied)
        throw new InvalidOperationException($"{e.Id} 目标槽刚被占用:{dst.IdAt(e.Dst.Slot)}");
    // 执行Place, 然后读回校验
    // ...Place...
    if(dst.IdAt(e.Dst.Slot)!=e.Id) throw new InvalidOperationException($"{e.Id} 放后读回不符,冻结两盒");
    e.Status=EntryStatus.Done;
}
```

## 三、交叉异常处置地图（手绘参考）
```
计划关 ValidatePlan ─错─► 拒绝下发(改计划)
预检关 Preflight   ─错─► 不下发/等待条件
取片关 AtPick 读码不符 ─► 冻结源, 不继续
在途  目标Hold/取走/满载 ─► 退回源原槽 或 Buffer暂存挂起(不强放/不丢臂/不擅改目标)
放置关 AtPlace 当下复核目标空+未Hold; 放后读回ID ─不符─► Failed+冻结两盒
终验  FinalCheck 源逐片/目标逐片/全局守恒/Buffer空
中断  Partial: 保留每Entry状态+实际位置 ─► Resume(首选)/Rollback/人工
```

## 四、今日易错点
1. 只有预检、放置前不二次确认（时间窗内目标可能被占/Hold，要 CAS 式复核）。
2. 在途目标不可用时强放、丢臂上、或擅自改目标槽（应退回/暂存挂起）。
3. 部分完成整体重置软件状态（物理片不会回退，必然账实脱节）。
4. Resume 凭 CrossMap 想当然，不先定位 Running 片实际位置。
5. 终验只看目标盒不核对源盒"该走是否都走"。
6. 放后不读回 ID（交叉混片数量守恒，只有读回逐片 ID 能抓）。
7. 全局守恒漏算设备内/Buffer（LeftInside）。
8. 交叉异常只记结果不记每条 Entry 取放读码轨迹（无法跨两 lot 追溯）。
