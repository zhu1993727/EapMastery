# W15 · Day02 答案与参考实现

## 一、自测题标准答案
1. **ValidatePlan vs Preflight / 为何两阶段**：ValidatePlan 是**计划阶段静态校验**，只看 CrossMap 自身是否自洽（源唯一、目标唯一、片集合守恒、槽范围、载具已登记），不依赖实时设备状态，在任务下发前就能做，错误属于"方案本身不成立"。Preflight 是**执行前实时可行性预检**，结合当下 SlotMap 和载具状态判断每条映射现在能不能做（源槽确实有这片、目标槽为空、载具 Loaded 未 Hold、臂可用），错误属于"方案对但此刻条件不具备"。分两阶段因为：静态冲突应在生成/下发计划时尽早拒绝（不占用设备、不等到现场），而实时条件随时变化（槽被占、盒被 Hold），只能在临执行前确认；两阶段分离让"方案正确性"和"时机可行性"各管一层，也是多层防线思想。
2. **目标冲突为何带载具 / 例**：槽位的唯一标识是（载具，槽号）二元组，不是槽号 alone。不同载具各有独立的 1..25 槽，A 盒 S1 和 B 盒 S1 是两个物理位置、可各放一片，不冲突；只有**同一载具**的同一槽被两条 Entry 同时作为目标才冲突（容量 1 叠片）。若只按槽号判定，会把 W1→A:S1 与 W3→B:S1 误判冲突而拒绝合法跨盒交叉。源冲突同理：A:S1 与 B:S1 是不同源。代码用 `(carrier,slot)` 值元组做键。
3. **合/拆批为何普通守恒不适用 / 处理**：普通交叉假设"同一批片只换位置"，源片集合==目标片集合、数量不变。合批是多个源载具的片汇入较少目标载具（源片集合跨多盒、目标合并），拆批反之从一盒分到多盒，某些重布场景目标片集合的"载具归属"会重排，单纯"每条映射源集合=目标集合"的逐条守恒表达不了多对多的批结构。处理：给 CrossMap 显式标记 MergeSplit 类型与批令（Lot/Batch 授权、来源批与目标批清单），守恒改为**全局片集合守恒**（所有源取出的片==所有目标放入的片，按 SubstrateId 全局去重比对，而非逐盒相等），并要求合/拆批必须有显式授权与批记录，防止未经许可改变批次构成。
4. **在途片计入哪 / 为何不能漏**：已从源槽取出、尚未放入目标槽的片，物理上在设备内位置（机械臂/对准器/腔/暂存），跨盒守恒里计入 **InternalCount（设备内位置占用数）**。全局恒等式：Σ各载具 SlotMap 占用 + InternalCount == 基线总数。不能漏，因为取片后源 SlotMap 已减、目标还没增，若不把在途片计入 InternalCount，中间态总数会凭空少一片，被误判丢片，也无法证明片还安全地在臂/腔上。正是在途计入设备内，才保证交叉从第一步到最后一步任意时刻守恒都成立。
5. **源槽 ID 不符说明什么**：CrossEntry 声明从（A,S5）取 W5，Preflight 却读到 A:S5 的片是另一个 ID，可能：①错料/混料——该槽实际是别的片（上料、前序交叉或人工放错）；②读码/RFID 错误或绑定串号；③CrossMap 计划本身基于过期信息（槽位已被前一步重排，计划没更新）；④前序交叉没按计划放，导致连锁错位。无论哪种，都说明"计划与现实不一致"，必须拒绝取片、Hold、核对，绝不能"槽里有片就取"，否则会把错误的片按 W5 的路线加工/投放，造成交叉污染。
6. **Entry 状态机 / 边界事件**：Pending（待执行，已通过静态校验、未开始）→Running（在途，已执行 Pick 从源槽取出、片进入设备内）→Done（完成，已成功 Place 到声明目标槽且目标槽 ID 核对一致）；任一环节失败→Failed（异常，带失败码与当前实际位置，挂起交恢复）。Running→Done 的边界事件是"片成功放入**声明的**目标槽、目标 SlotMap 占用且片 ID 与 Entry 一致、不变式校验通过"，仅完成 Place 动作但放错槽/ID 不符不能进 Done，应进 Failed（Misplaced/WrongId）。
7. **为何返回问题列表而非遇错即抛**：计划/预检常同时存在多处问题（多条映射目标冲突、若干槽范围非法、几个载具未 Loaded），返回完整问题列表能一次性把所有冲突报给上层/操作员，便于批量修正计划，而不是修一个再跑、再暴露下一个，反复占用下发流程；这属于"校验/诊断"语义（收集所有违规），不同于"执行"语义（执行必须遇错即停、事务回滚保证安全）。所以 ValidatePlan/Preflight 返回 Issue 列表，真正的迁移动作（Move/Pick/Place）才用异常做硬中断，两类语义分开。

### 模型

```csharp
namespace EapLab.E90.Cross;
public enum EntryStatus { Pending, Running, Done, Failed }
public sealed record SlotRef(string Carrier,int Slot);
public sealed class CrossEntry
{
    public string Id { get; } public SlotRef Src { get; } public SlotRef Dst { get; }
    public string Recipe { get; } public EntryStatus Status { get; set; }=EntryStatus.Pending;
    public CrossEntry(string id,SlotRef src,SlotRef dst,string recipe){Id=id;Src=src;Dst=dst;Recipe=recipe;}
    public bool IsSameSlot => Src==Dst;
}
public enum CrossIssueCode { DuplicateSource,DuplicateTarget,SlotRange,UnknownCarrier,Conservation,
    SourceEmpty,SourceIdMismatch,TargetOccupied,CarrierNotLoaded,CarrierHold,MergeSplitNeedsAuth }
public sealed record CrossIssue(CrossIssueCode Code,string Detail);
```

### CrossMap + 静态校验
```csharp
public sealed class CrossMap
{
    public List<CrossEntry> Entries { get; }=new();
    public bool IsMergeSplit { get; init; }
    public bool MergeSplitAuthorized { get; init; }
    public CrossMap Add(CrossEntry e){Entries.Add(e);return this;}

    public List<CrossIssue> ValidatePlan(ISet<string> knownCarriers)
    {
        var issues=new List<CrossIssue>();
        var srcSeen=new Dictionary<SlotRef,string>(); var dstSeen=new Dictionary<SlotRef,string>();
        var srcIds=new HashSet<string>(); var dstIds=new HashSet<string>();
        foreach(var e in Entries)
        {
            if(e.Src.Slot is <1 or >25 || e.Dst.Slot is <1 or >25)
                issues.Add(new(CrossIssueCode.SlotRange,$"{e.Id} 槽号越界"));
            if(!knownCarriers.Contains(e.Src.Carrier)||!knownCarriers.Contains(e.Dst.Carrier))
                issues.Add(new(CrossIssueCode.UnknownCarrier,$"{e.Id} 载具未登记"));
            if(srcSeen.TryGetValue(e.Src,out var other)) issues.Add(new(CrossIssueCode.DuplicateSource,$"源冲突 {e.Src}: {other}/{e.Id}"));
            else srcSeen[e.Src]=e.Id;
            if(dstSeen.TryGetValue(e.Dst,out var o2)) issues.Add(new(CrossIssueCode.DuplicateTarget,$"目标冲突 {e.Dst}: {o2}/{e.Id}"));
            else dstSeen[e.Dst]=e.Id;
            srcIds.Add(e.Id); // 简化:片ID即Entry.Id
            dstIds.Add(e.Id);
        }
        if(IsMergeSplit)
        { if(!MergeSplitAuthorized) issues.Add(new(CrossIssueCode.MergeSplitNeedsAuth,"合/拆批缺少显式批令授权")); }
        else if(!srcIds.SetEquals(dstIds))
            issues.Add(new(CrossIssueCode.Conservation,"普通交叉源片集合与目标片集合不一致"));
        return issues;
    }
}
```

### 执行前预检（对接 W14 SubstrateTracker 的 SlotMap/载具状态）
```csharp
public sealed class CrossPreflight
{
    private readonly SubstrateTracker _tracker;
    private readonly IReadOnlyDictionary<string,SlotMap> _maps;
    private readonly Func<string,bool> _loaded; private readonly Func<string,bool> _hold;
    public CrossPreflight(SubstrateTracker t,IReadOnlyDictionary<string,SlotMap> maps,
        Func<string,bool> loaded,Func<string,bool> hold){_tracker=t;_maps=maps;_loaded=loaded;_hold=hold;}

    public List<CrossIssue> Check(CrossMap map)
    {
        var issues=new List<CrossIssue>();
        foreach(var e in map.Entries)
        {
            if(!_loaded(e.Src.Carrier)||!_loaded(e.Dst.Carrier))
                {issues.Add(new(CrossIssueCode.CarrierNotLoaded,$"{e.Id} 载具未Loaded"));continue;}
            if(_hold(e.Src.Carrier)||_hold(e.Dst.Carrier))
                {issues.Add(new(CrossIssueCode.CarrierHold,$"{e.Id} 载具Hold"));continue;}
            var sm=_maps[e.Src.Carrier];
            if(sm.StateAt(e.Src.Slot)!=SlotState.Occupied)
                issues.Add(new(CrossIssueCode.SourceEmpty,$"{e.Id} 源槽{e.Src}空"));
            else if(sm.IdAt(e.Src.Slot)!=e.Id)
                issues.Add(new(CrossIssueCode.SourceIdMismatch,$"{e.Id} 源槽实际{sm.IdAt(e.Src.Slot)}"));
            if(!e.IsSameSlot)
            {
                var dm=_maps[e.Dst.Carrier];
                if(dm.StateAt(e.Dst.Slot)==SlotState.Occupied)
                    issues.Add(new(CrossIssueCode.TargetOccupied,$"{e.Id} 目标槽{e.Dst}已占用:{dm.IdAt(e.Dst.Slot)}"));
            }
        }
        return issues;
    }
}
```

### 跨盒全局守恒快照
```csharp
public sealed class GlobalBalance
{
    public static string Snapshot(IReadOnlyDictionary<string,SlotMap> maps,int internalCount,int baseline)
    {
        var per=maps.Select(kv=>$"{kv.Key}={kv.Value.OccupiedCount}");
        int carrierSum=maps.Values.Sum(m=>m.OccupiedCount);
        int total=carrierSum+internalCount;
        return $"载具[{string.Join(",",per)}] 设备内={internalCount} 合计={total} 基线={baseline} {(total==baseline?"守恒OK":"守恒破坏!")}";
    }
}
```

## 三、今日易错点
1. 静态校验和实时预检混为一谈（方案正确性 vs 时机可行性，分两阶段）。
2. 目标/源冲突只按槽号不按（载具,槽），误判跨盒同槽号。
3. 合/拆批套用普通逐盒守恒（要全局片集合守恒+显式批令授权）。
4. 在途片不计入设备内，中间态误报丢片。
5. 源槽"有片就取"，不核对片 ID（错料/混料必须拦）。
6. 校验遇错即抛，无法一次报全计划问题（校验收集、执行才硬中断）。
7. Entry 放错槽也标 Done（必须放到声明目标且 ID 一致才 Done，否则 Failed）。
8. 守恒基线不随交叉开始锁定、不区分载具占用与设备内占用。
