## 三、本周知识地图（先默写再对照）
```
交叉取片 Cross Transfer
├ 模式: 同槽/同盒换槽/跨盒(交叉是一般形式, 源(盒,槽)→目标(盒,槽))

├ 调度: 臂/Buffer容量约束; 占用环用Buffer打破; 双臂逻辑时钟+资源表+固定顺序
├ 六道关: 计划→预检→AtPick读码→在途→AtPlace二次确认+读回→跨盒终验
├ 守恒: Σ载具占用+设备内(含Buffer)=基线; 在途计入设备内; 合拆批全局集合守恒+批令
├ 异常: 源ID不符/预检后被占/在途目标Hold/跨盒混片/Partial; Resume/Rollback/人工
└ 编排器: 计划→预检→锁基线→调度执行(唯一经位置层)→终验→结果(带每片实际位置)
```

## 四、W16 预热：E40 ProcessJob 模型与结构（25 分钟）
### 1. 从 CrossMap 到 ProcessJob
- CrossMap 解决"片从哪到哪"的位置问题；真实加工还要描述"用什么配方、走哪些工艺步骤、在哪些腔、按什么顺序、什么状态算完成"——这就是 E40 ProcessJob（PJ）。
- E40 = SEMI E40 **Process Job（PJ）标准**，GEM300 的加工任务核心，定义作业如何声明、执行、状态跟踪。

### 2. PJ 的关键组成（先建立印象）
- **ProcessJob 本体**：JobID、关联的载具/槽位映射、加工步骤序列（Process Job 内对每片/每批的处理顺序）、配方、优先级、状态。
- **Source Job / Destination Job（源/目标作业映射）**：显式声明每片从哪个载具哪个槽来、加工后到哪个载具哪个槽——正是 CrossMap 的标准化形态。
- **Processing Step/Recipe**：在哪个模块/腔、用什么 Recipe、顺序与并行关系。
- PJ 执行时驱动设备：取片（E90 位置迁移）→加工（状态/工艺）→放片（E90），全程状态机跟踪。

### 3. PJ 与已学标准的关系全景
```
E87 管盒(可访问) → E90 管片位置(唯一/守恒/交叉) →
E40 ProcessJob 管"一次加工任务"(源目映射+工艺步骤+状态机) →
E94 ControlJob 管"多个PJ的编排"(跨载具/顺序/协同)
E39 OSS 承载这些对象(S14定义/S15操作/S16事件), E5/E37是通信底座
```
