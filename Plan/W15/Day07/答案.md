# W15 · Day07 答案

## 一、排障推演参考
1. **交叉到一半目标盒少片、源盒也对不上**：不要分别看两个盒，立即切到**跨盒全局视角**。先按 CrossMap 列出每条 Entry 状态（Done/Running/Pending），再用位置空间统计 Σ源/目标载具占用 + 设备内（臂/腔/Buffer）占用并与基线比对：若总数守恒、差的片在设备内→LeftInside/在途（没放完，定位到具体内部位置取回/续放即可）；若设备内也没有、总数少→真 Missing，沿该片 Trajectory 查最后一次成功迁移与之后动作、读码和传感器，定位掉片/漏检点，安全停机人工，不补假账；若总数对但槽/ID 不符→Misplaced/WrongId，逐片读码核对。根因多为中途异常导致 Partial 未正确恢复、或只按单盒盘点。处置核心是"全局守恒 + Entry 状态 + 每片实际位置"三件套。
2. **双臂偶发同腔碰撞、时有时无**：这是典型并发时序竞态特征——说明资源互斥没做成确定性的。查双臂调度是否用了真线程/异步且共享腔体资源只做了"检查时空闲"而非"检查-占用原子"，导致两臂在同一时间窗都通过检查进入 C1。根因是缺少全局资源表 + 原子占用 + 固定申请顺序（可能还有物理干涉区未纳入资源集合）。修复：改为逻辑时钟确定性调度，动作声明全部占用资源（腔、锁、共享轴、干涉区），资源表原子"检查并占用"、冲突动作确定地串行、固定顺序申请防等待环，并加"两臂资源集合交集必须为空才允许同拍"的单测反复跑（确定性下要么总过要么总不过，不会偶发）。

## 二、综合自测卷（8 题）标准答案
1. **三类模式关系 / 交叉一般形式**：同槽（源=目标位置）、同盒换槽（载具同槽不同）、跨盒（载具槽都可不同）。交叉把源(盒,槽)和目标(盒,槽)都当自由变量，同槽/同盒是其退化特例，故为一般形式，可用统一模型与引擎处理全部，不必为每种写一套。
2. **四条静态约束 / 目标冲突带载具**：源唯一（同源槽不被两条 Entry 取）、目标唯一（同目标槽不被两条放）、片集合守恒（普通交叉源片=目标片）、槽范围 1..25 且载具登记。目标冲突必须带载具，因为槽位身份是（载具,槽号），A:S1 与 B:S1 是两个物理位置可各放一片，只按槽号会误判合法跨盒交叉为冲突。
3. **单臂交换 S2/S5 序列 / Buffer 作用**：①W@S2→臂→Buffer:B1（腾 S2）；②W@S5→臂→S2（该片到位、腾 S5）；③Buffer:B1→臂→S5（第一片到位）。Buffer 提供第三个容量位置，打破"两片各自目标被对方占着、单臂只能持一片"的循环依赖（类似交换两变量需临时变量），且 Buffer 片全程守唯一/容量/守恒、终验须清空。
4. **六道关 / AtPlace 思想**：ValidatePlan（方案自洽）、Preflight（执行前源有片ID对/目标空/盒可用）、AtPick（取片当下读码确认取对片取对槽）、InTransit（在途位置明确守恒、目标持续可用）、AtPlace（放置当下再确认目标空、未 Hold，放后读回 ID）、FinalCheck（跨盒逐片终验）。AtPlace 二次确认是 compare-and-set/乐观并发思想：预检到放置有时间窗，前提可能已变，必须在真正改变世界的瞬间基于当下状态重验，防止用过期结论叠片/错放。
5. **跨盒守恒 / 在途与 Buffer / 合批**：恒等式 Σ所有相关载具 SlotMap 占用 + 设备内位置占用 == 基线总数。已取未放的在途片计入设备内（臂/腔），Buffer 暂存片也计入设备内，二者都不能漏，否则中间态误报丢片。合批（多源→单目标）不满足逐盒相等，改用全局 SubstrateId 集合守恒（所有源取出集合==所有目标放入集合、总数不变），并需显式批令授权与批次记录。
6. **Partial 不重置 / 三选择**：软件重置不会把已到目标盒、已在设备内的物理片搬回，会造成账实脱节，故必须保留每条 Entry 状态和每片实际位置。Resume 续跑：目标恢复可用、片位置确定，以实际位置为准从未完成处继续到目标（首选）；Rollback 回退：目标确定不可用需撤销，经位置层把已搬片逐片取回源、恢复初始布局；人工：片归属或物理状态不确定（急停/机械故障/身份存疑），安全保持、冻结、现场确认后再决定。
7. **编排器六层 / 唯一位置层写**：计划层（CrossMap+静态校验）、预检层（实时可行性）、调度层（资源/Buffer/双臂安全序列）、执行层（SubstrateTracker/LocationSpace，唯一改位置、守三不变式）、终验层（跨盒逐片验收）、恢复层（Resume/Rollback）。只有位置层能改位置，因为原子 Move 内聚了 expectedFrom、容量校验、双向映射、不变式断言与回滚；上层绕过它直接改 SlotMap 就绕开了全部安全保证。上层决策"做什么/什么顺序"，位置层保证"安全地改"。
8. **E87→E90→E40→E94 分层 / PJ 增量**：E87 管盒（载具在位/授权/可访问）；E90 管片位置（唯一/容量/守恒/交叉取放轨迹）；E40 ProcessJob 管一次加工任务（源目映射 + 工艺步骤 + 配方 + Job 状态机）；E94 ControlJob 管多个 PJ 的编排（跨载具、顺序与协同）；它们都通过 E39 OSS 建模、经 E5/E37 通信。PJ 相对 CrossMap 的增量是**工艺任务语义**：CrossMap 只回答"片从哪到哪"，PJ 还要回答"用什么配方、经哪些模块/腔、什么步骤顺序与并行、每片/整任务什么状态、何时开始/完成/异常、如何与设备能力绑定"，即从"位置安全搬运"升级为"可跟踪的完整加工作业"。

## 三、四张闭卷图自检要点
- 交叉流向：源减/目标增/在途位置/全局守恒等式/两 lot 耦合风险是否标出。
- 交换序列：三步顺序、Buffer 临时位、双臂资源交集为空才可并行。
- 六道链：每关输入、校验内容、拦截的具体异常、AtPick/AtPlace 读码点。
- Partial 决策：以实际位置为根，Resume/Rollback/人工三条分支条件与守恒要求。

## 四、W16 预热思考题参考
1. **PJ 相对 CrossMap 增量**：工艺任务语义——配方、加工步骤/路径、模块与腔体、顺序并行、任务与片的状态机、开始/完成/异常生命周期、与设备能力和 Host 命令的绑定；CrossMap 只是 PJ 内 Source/Destination 位置映射这一部分。
2. **为何显式 Source/Destination**：显式建模让"每片从哪来、应到哪去"在任务下发时就确定且可校验（源唯一、目标唯一、可预检、可终验、可追溯），防止设备"取到哪算哪"的不确定行为导致混片、错槽、无法审计；也让 Host 能在加工前做防错、加工中跟踪、加工后逐片核对，是交叉安全和批次追溯的基础。
3. **PJ 状态与每片状态正交**：PJ 是整体任务状态（如 Queued/Started/Executing/Completed/Aborted），每片有自己的位置+加工状态（待加工/在某腔加工中/已加工/已放位）。一个 PJ 加工多片、跨两腔时，PJ 处于 Executing 而各片分别处于不同步骤/位置，PJ 是否完成取决于所有片都完成；二者正交，类似 W12 载具多状态机——整体任务状态不替代单片状态，否则无法表达"部分片完成、一片在 C1、一片在 C2"的并发现实。

## 五、W15 全周易错点总清单
1. 同槽/同盒/跨盒当三套逻辑（交叉统一源→目标）。
2. CrossMap 不做计划阶段冲突检查；目标冲突不按（载具,槽）判定。
3. 合/拆批误用逐盒守恒（要全局集合守恒+批令授权）。
4. 在途/Buffer 片不计入设备内，中间态误报丢片；Buffer 终验不清空。
5. 静态校验与实时预检不分；校验遇错即抛无法一次报全。
6. 单臂交换不用 Buffer 造成死等；占用环不检测。
7. 双臂用真线程、检查与占用不原子导致偶发碰撞（要逻辑时钟+资源表+固定顺序）。
8. 只有预检、AtPlace 不当下二次确认（时间窗内目标被占/Hold）。
9. 取/放不读码核对 ID（交叉混片数量守恒、唯逐片 ID 可抓）。
10. Partial 整体重置；Resume 凭计划不看实际位置；Rollback 不经位置层。
11. 编排器/调度器绕过位置层直接改 SlotMap。
12. 只按单盒盘点交叉结果（必须跨盒全局守恒+Entry 状态+每片实际位置）。
