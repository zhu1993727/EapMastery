# W28 · Day07 答案

## 一、五组辨析（闭卷口述参考）
1. **物理树 vs 逻辑对象**：物理树随稳定硬件拓扑（腔/子系统/部件），路径长期不变；逻辑对象承载动态作业/载具/片/汇总（值变结构不变），由权威 FSM 同源更新、EDA 只读。
2. **自描述 vs WKN**：自描述(E125)让客户端发现"有什么、类型单位"（结构互通）；WKN(E164)把私有量映射到跨厂商标准语义（语义互通），二者结合才通用。
3. **采样 vs 上报**：采样按 Hz 内部读值打戳入缓冲（保真、高频），上报按定时/凑点/事件批量打包发送（省连接），解耦后慢网络不反压采样。
4. **周期覆盖 vs 事件不丢**：周期 trace 实时优先、慢消费可覆盖最旧并标 Gap；事件/异常快照离散关键、不可替代，用独立不丢队列、发送时优先保。
5. **实时不补 vs Spool 不丢**：EDA 实时流有界、丢点标 Gap、重连不补历史（历史归 EDC）；GEM Spool 缓存控制/事件事务、按序确认不丢（业务正确性）。

## 二、综合自测卷（7 题）参考答案
1. **建模/粒度契约/GEM300**：五步 Module→Subsystem→Component→Logical→挂成员；粒度判据是"是否需独立订阅/定位"，内部中间量不暴露；命名一经发布即契约，只增不删、改语义升模型版本。E87 载具、E90 片、E40 PJ/Step、E94 CJ、E30 控制态映射为逻辑对象上的 SVDV/Event/Exception，全部由对应权威 FSM/Manager 更新，EDA 只读投影不自算，Lint 校验路径唯一/无孤儿/类型单位枚举/同型一致/可溯源。
2. **WKN/量纲/覆盖率**：识别通用量→按 E164 定义（量纲+类型+方向）选 WKN→私有路径 1:1 绑定→量纲/枚举一致校验；内部 SI 基准+单位换算，流量映压力等量纲错配直接拒；覆盖率=已映/应映通用量，专有量标 vendor-specific 不硬凑；映射随模型版本/ECN 管理；同一量可有 GEM VID/私有路径/WKN 三名、同源同值。
3. **集中调度/环形/低GC/预算**：一个基础 tick 循环、计划按周期换算每 N tick 采、一次 tick 多计划共享读值同戳，线程数与订阅数无关；单调时钟定节拍、UTC 对外；RingBuffer 固定容量 O(1)、覆盖最旧、内存有界；低 GC 靠 struct 点、ArrayPool 复用、热路径零 LINQ/字符串/闭包、集合预分配；性能预算 Σ点数×Hz 估 CPU/带宽，配每客户端上限与全局总预算，超限降频/拒绝，资源与 GEM 隔离。
4. **运行时/Packet/背压级联**：计划先过授权闸门再注册，周期挂采样调度、事件订阅 FSM 同源出口，分通道、同源同时钟；Packet 含序号/时间窗/变量/周期行/事件快照/质量汇总/Gap/连续性；flush 定时/凑点/事件即报；背压时丢最旧周期保事件、丢弃计数并标质量；会话关闭按 sessionId 级联摘调度、退订事件、清缓冲队列、释放配额；遍历取不可变快照防并发。
5. **II/III 上报/协商/隔离判死**：Freeze II 设备调客户端 SOAP 回调发 XML，Freeze III 走 gRPC 服务端流推 protobuf，语义相同；ITransport 抽象 + 会话内容协商，同设备 II/III 并存；每会话独立发送队列与发送循环，单点慢断只影响自己；实时不补历史；连续失败达阈值判会话死亡，触发采集层级联撤销。
6. **点的全路径/同源证明**：硬件值→EquipmentDataBus→采样调度读快照打戳→RingBuffer→flush 成 Packet→按会话编码→独立队列→ITransport→客户端。同源证明=同刻让 GemOutlet 与 EDA 读同一 Bus 变量断言等值等戳；不一致多为存在第二份数据源、时钟不同源、单位未统一、读快照缺锁。
7. **换 HTTP 动哪/为何分层**：只替换 ITransport 实现与 onboard 真实连接/协商，建模、自描述、授权、采样、缓冲、打包、编码选择、生命周期级联全部不动、xUnit 继续有效。分层是为了内核稳定可测、传输可换（内存→HTTP、XML→protobuf），与 EapLab"域与通信分离"一致，升级 Freeze III 或换框架不重写业务。

## 三、费曼三问参考
- **为何集中调度**：订阅数会随客户端增长，若每计划一个定时器，线程和上下文切换随之膨胀、节拍互抖；集中成一个基础节拍、按周期分级，一次 tick 服务所有到期计划、同刻只读一次值，线程恒定、同戳、可预测，订阅再多也不加线程。
- **周期可覆盖事件不可丢**：周期波形缺一小段可标 Gap 后继续，FDC 能容忍且实时性最重要；但"Step 切换/报警"这类事件是离散的工艺坐标与故障证据，丢一个就对不上波形、查不到根因，无法用后续点补回，所以必须独立队列、优先保、不覆盖。
- **内核与传输为何分离**：采集/建模/授权/打包是长期稳定的业务内核，HTTP/SOAP/gRPC/protobuf 是会演进替换的外层；分离后内核可用内存测试快速验证，换 Freeze 版本或真实网络只写适配层，业务不重写、测试不失效，这是能从 Freeze II 平滑走到 III 的根本。

## 五、W28 全周易错点总清单
1. 物理树按工艺组织导致路径随产品变；粒度过粗/过细；内部量全暴露。
2. 数值无单位、状态无枚举、同型模块结构不一致。
3. 命名发布后随意改删、不升版本。
4. EDA 自算作业/片状态而非读权威 FSM。
5. WKN 只看名字映、量纲错配、一 WKN 映多义量、专有量硬凑。
6. 多单位混算、不做 SI 基准与换算。
7. 每计划一线程/定时器；墙上时钟定节拍；无界集合承载高频流。
8. 热路径 class 分配/字符串/LINQ 造成 GC 抖动。
9. 事件进覆盖缓冲、发送堵塞回压采样线程。
10. Packet 无序号/Gap/质量，丢点静默。
11. 计划不过授权、会话亡不级联撤、遍历中改集合。
12. II/III 不做协商、强制单一编码。
13. 实时流重连补历史、混淆 Spool 可靠语义。
14. 业务与 HTTP 框架耦合、EDA 缓存值导致与 GEM 不同源。
