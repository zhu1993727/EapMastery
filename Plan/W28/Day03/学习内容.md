# W28 · Day03（周三）高频采样引擎：统一调度、单调时间戳与环形缓冲

> 建议时长：100 分钟。EDA 的性能命脉在采样引擎。今天解决"多客户端、多计划、上百点、几十~上千 Hz"下如何低延迟、低 GC、有界内存、不抖动地采样：统一采样调度（而非每计划一线程）、单调时钟时间戳、环形缓冲、线程安全与背压。这是区别"会用 EDA"和"能做 EDA 设备端"的关键一课。

## 一、今日目标
1. 理解为什么不能每个采集计划开一个定时器/线程，掌握统一采样调度（按频率分级、一次 tick 服务多计划）。
2. 掌握单调时钟时间戳（与 W24 时间账一致）、采样节拍与抖动控制。
3. 实现有界环形缓冲 RingBuffer：覆盖最旧、容量有界、无动态扩张、O(1) 读写。
4. 掌握高频低 GC 技术：struct 值类型、复用缓冲/ArrayPool、避免装箱与闭包分配、批量写入。
5. 用 C# 实现 RingBuffer + SampleScheduler（多频率分级、线程安全、统计丢点）；xUnit 验证。

## 二、背景知识（先读，40 分钟）

### 1. 统一采样调度（架构核心）
- 错误做法：每个客户端每个计划开一个 Timer/线程，100Hz×多客户端会产生大量定时器、上下文切换与锁竞争，CPU 飙升、节拍互相抖动。
- 正确做法：**一个集中采样调度器**，按"基础节拍"运行（如 10ms tick），把计划按其采样周期归类（10Hz=每 10 tick、50Hz=每 2 tick、100Hz=每 tick），一次 tick 内统一从数据源读值并分发给到期计划。读一次、多计划共享（同一时刻多客户端订同一变量只读一次）。
- 好处：线程数恒定、锁集中、同源同戳、可预测；新增计划只是注册，不新增线程。

### 2. 单调时钟与时间戳
- 用单调时钟（Stopwatch/高分辨率计时）定节拍与时间间隔，避免墙上时钟回拨/NTP 校时导致时间倒流或间隔为负（与 W24 EPT 同一原则）；对外可同时给 UTC 墙上时间用于跨系统对齐，内部节拍与间隔用单调时间。
- 同一 tick 内同一变量的多个订阅者共享同一时间戳（同源同戳），保证 FDC 波形与 GEM 事件、E116 时间账可对齐。

### 3. 环形缓冲 RingBuffer（有界、低 GC）
- 固定容量数组 + 写/读指针，写满后按策略覆盖最旧（实时流）或标记溢出；O(1) 入队/出队、无扩容、无 GC 压力、内存严格有界。
- 与 Day04 会话发送队列配合：采样进环形缓冲，上报时批量取一段 flush。
- 区分实时覆盖（trace 允许覆盖旧点并记 Gap）与事件/异常快照（不可覆盖、单独队列）。

### 4. 高频低 GC 要点（C#/.NET）
- 采样点用 readonly struct（At/Value/Quality），避免 class 堆分配与装箱。
- 复用数组/缓冲（ArrayPool<T>.Shared.Rent/Return）、批量写入，不在每点 new 集合、不在热路径拼字符串/装箱 ToString、避免 LINQ/闭包在 tick 内分配。
- 读值走只读快照（数据源提供线程安全快照读取），不在采样线程持锁做重活；序列化/发送放到上报线程，生产消费解耦。
- 关注 GC 暂停（Gen0/Gen1 回收会造成采样抖动），用对象/数组复用把分配降到接近零。

### 5. 采样精度与抖动、线程模型
- 基础节拍精度：用高精度定时器/专用循环，避免 Thread.Sleep 精度不足导致抖动；记录每点计划时间与实际时间，抖动可观测。
- 线程模型：采样线程（高频、只做读值+拷贝进缓冲，极短临界区）；上报线程（批量取、序列化、发送，慢操作在此）；数据源更新线程。三者通过有界缓冲解耦，慢发送不阻塞采样（呼应 Day04 背压、Day05 上报）。

### 6. 性能预算（专家意识）
- 估算：N 点 × F Hz = 每秒采样操作数；评估 CPU、内存带宽、网络；设全局采样总预算与每客户端上限（Day04 配额），超限拒绝/降频，保证最坏情况下设备与 GEM 不受影响。
