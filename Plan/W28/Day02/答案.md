# W28 · Day02 答案与参考实现

## 一、自测题标准答案
1. **映射四步/为何不能只看名字**：①识别通用量（跨设备通用的物理量/状态）；②按 E164 定义选标准 WKN（标准名+量纲+类型+方向）；③把私有 CEM 路径与 WKN 一对一绑定、映射随自描述下发；④校验量纲/类型/方向/枚举语义一致才允许。不能只看名字像，因为不同厂商命名随意，同名可能物理含义不同（"Power"可能是 RF 正向功率也可能是电源功耗、"Temp"可能是腔体也可能是冷却水），必须核对物理量纲与语义，错映会让跨设备 FDC 规则把不同物理量当同一量、产生误判，危害大于不映。
2. **为何 SI 基准/工程单位**：内部以 SI 统一存储（K/Pa/W/s、比例 0–1）可消除多单位混用、保证计算（FDC 阈值、SPC 控制限、跨设备聚合）在同一量纲基准上正确，且 WKN 标准语义通常以 SI 定义。工程单位（mTorr、℃、slm）用于现场显示与习惯上报，做法是存储 SI、在元数据里声明单位、必要时在展示层按单位换算器转回工程单位；无论怎么显示，参与规则计算与跨设备比较的是 SI 值，且单位字段始终随数据携带。
3. **换算/量纲检查**：压力 1 Torr=133.322 Pa、1 mTorr=0.133322 Pa（如 10mTorr≈1.333Pa）；温度 K=℃+273.15、℉=℃×9/5+32；流量 1 slm=1000 sccm。量纲检查抓"把不同物理量纲映到同一 WKN"的错：如把 MFC 流量(sccm，量纲=物质流率)映到腔体压力 WKN(Pa，量纲=压强)、把功率(W)映到能量、把温度映成温差；即使数值类型都是 double，量纲标签不符就拒绝映射，从源头杜绝跨量纲误采。
4. **覆盖率/专有量/硬凑危害**：覆盖率=已正确映射的通用量数 / 应映射通用量数，应接近全覆盖，缺口意味着跨设备规则在该量上取不到标准值。厂商/工艺专有量无对应 WKN 时保留私有路径、标 vendor-specific 并写说明，客户端知道它非标准、仅本机型用。硬凑 WKN（把语义不完全一致的量塞进标准名）会让标准规则在该机型上取到"看似标准实则不同义"的值，造成静默误判且难排查，比保留为未映射私有名更危险。
5. **一个 WKN 映两个语义量/防法**：会造成标准名指向歧义——客户端按 WKN 取值时不知道实际是哪个量，跨设备规则在该机型上语义漂移、结果不可信。防法：注册表约束本设备内一个 WKN 对一个私有路径（1:1）、一个私有路径至多一个 WKN；校验器检测重复映射并报错；同时做量纲/枚举一致性校验，语义不符不予绑定；确需多个同类传感器（多点温度）用带索引的标准子路径而不是复用同一 WKN。
6. **版本/变更管理/评审时机**：映射表是客户端规则依赖的对外契约，软件升级、点表变更、机型衍生会增改变量，若不版本化，旧客户端会按旧映射错取。故映射表随 EqSD 模型版本管理，变更走 ECN 并保留兼容（只增不删、废弃过渡）。评审时机：新机型建模完成后、每次点表/软件版本变更后；由设备方与 FDC/YMS 使用者会签，确认通用量覆盖、量纲语义、单位、枚举对齐，冻结后纳入发布。
7. **三个名字关系**：同一底层量可有三种引用名——GEM VID（面向单 Host 采集/报告，常厂商化）、私有 CEM 路径（设备 EDA 模型里的层级路径，用于深度诊断）、标准 WKN（E164 跨厂商标准语义，用于通用 FDC/SPC 规则）。三者指向同一权威数据源、值一致；EDA 自描述同时携带私有名与 WKN（Day03 元数据），客户端标准分析用 WKN、需要厂商特有细节时用私有名，GEM 通道用 VID；命名解耦但同源。

## 二、参考实现（net8.0）：单位换算 + WKN 注册表 + 校验

```csharp
namespace EapLab.Eda.Wkn;
public enum Dimension{ Temperature,Pressure,Power,FlowRate,Time,Dimensionless }
public static class UnitConvert
{
    static double ToSi(double v,string u)=>u switch
    { "C"=>v+273.15,"K"=>v,"F"=>(v-32)*5/9+273.15,
      "Pa"=>v,"mTorr"=>v*0.133322,"Torr"=>v*133.322,
      "sccm"=>v/1000.0,"slm"=>v,"W"=>v,"s"=>v,""=>v,_=>double.NaN };
    public static double Si(double v,string u){var x=ToSi(v,u);if(double.IsNaN(x))throw new ArgumentException("unknown unit "+u);return x;}
}
public sealed record WknDef(string Name,Dimension Dim,string SiUnit);
public sealed class WknRegistry
{
    readonly Dictionary<string,WknDef> _wkn=new();      // 标准定义
    readonly Dictionary<string,string> _priv2Wkn=new(); // 私有路径->WKN
    public WknRegistry Define(WknDef d){_wkn[d.Name]=d;return this;}
    public string? Bind(string priv,string wkn,Dimension privDim)
    { if(!_wkn.TryGetValue(wkn,out var def))return"unknown wkn";
      if(def.Dim!=privDim)return"dimension mismatch";             // 量纲一致
      if(_priv2Wkn.ContainsKey(priv))return"priv already bound";
      if(_priv2Wkn.ContainsValue(wkn))return"wkn already bound";  // 1:1
      _priv2Wkn[priv]=wkn;return null; }
    public string? Of(string priv)=>_priv2Wkn.GetValueOrDefault(priv);
    public double Coverage(IEnumerable<string> genericPriv)=>
        genericPriv.Count(_priv2Wkn.ContainsKey)/(double)genericPriv.Count();
    public List<string> Unmapped(IEnumerable<string> generic)=>generic.Where(p=>!_priv2Wkn.ContainsKey(p)).ToList();
}
```

public class WknTests

    { var r=Reg();r.Bind("/PM1/Temp","WKN.Chamber.Temperature",Dimension.Temperature);

    { Assert.Equal(623.15,UnitConvert.Si(350,"C"),2);

## 三、映射治理流程（手绘参考）
```
成员清单 ─识别通用量─▶ 候选 ─选E164 WKN(名+量纲+类型+方向)─▶ 量纲/枚举一致? ─否→不映,标vendor-specific
                                          │是
                                   私有路径↔WKN 1:1 绑定(注册表)
                                          │
                       SI基准存储(Pa/K/W/slmm) + 单位换算器 + 单位随数据
校验: 量纲不符/重复映射/缺失/枚举不一致/未知单位 全部报错
覆盖率=已映通用量/应映; 缺口可见; 专有量保留私有名不硬凑
版本: 映射表随EqSD版本, 变更走ECN只增不删; 设备方+FDC/YMS会签冻结
一名三指: GEM VID / 私有CEM路径 / 标准WKN → 同一数据源, 值一致
```

## 四、今日易错点
1. 只看名字像就映 WKN，不核对量纲语义（错映比不映更危险）。
2. 多单位混存混算（应 SI 基准、单位随数据、展示层换算）。
3. 流量映压力、温度映温差等量纲错配不拦截。
4. 一个 WKN 映多个私有量造成标准名歧义。
5. 专有量硬凑标准 WKN，规则静默误判。
6. 不统计覆盖率，缺口到上线才发现。
7. 映射表不版本化，升级后旧客户端错取。
8. 枚举状态编号各厂自定、不与 WKN 标准枚举对齐。
