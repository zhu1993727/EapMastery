# W28 · Day04 答案与参考实现

## 一、自测题标准答案
1. **职责链**：已授权会话提交计划（变量/触发/频率/上报条件）→运行时过授权闸门（可见域/频率上限/点数上限，拒越权超频）→注册（周期计划挂统一采样调度器，事件/异常计划订阅同源 FSM 事件出口）→运行（周期点进环形缓冲，事件/异常即时 ECV/EXV 快照进独立不覆盖队列）→上报线程按定时/凑点/事件 Drain 成 Packet→交编码发送层（Day05）→会话关闭级联撤销全部计划并释放。
2. **周期与事件融合/不阻塞**：二者驱动源不同——周期由采样节拍驱动、事件由 FSM 状态迁移驱动。运行时让它们读同一数据源、用同一单调时钟，但进不同缓冲（周期环形可覆盖、事件独立不可丢）、走不同上报策略；事件经同源事件出口回调注入，只做极快的快照入队即返回，不进入高频采样循环，采样线程也不等待事件，因此互不阻塞。事件还在对应时间窗 Packet 里打 marker，供 FDC 对齐波形与工艺节点。
3. **Packet 字段/Gap 来源**：含计划 ID、单调递增包序号、时间窗起止（单调时间+UTC）、变量路径集合、周期点行（时间戳/值/质量）、本窗事件/异常快照列表、质量汇总（Good/Bad 计数、Gap 丢点数、是否连续）。Gap 来自环形缓冲覆盖最旧（慢消费者丢点，Overwritten 计数）或发送队列丢弃；Bad/Uncertain 来自数据源本身（传感器故障/可疑）。flush 时把丢点区间与计数写进 Packet、受影响点标 Gap，客户端据此知道这段不完整。
4. **flush 三条件/事件立即报**：定时到（FlushEverySec）、凑够点数（FlushEveryN）、事件即报。周期 trace 关注波形、批量定时报即可；而 Step 切换/报警等事件是工艺节点与故障现场，FDC 需要即时响应（如异常要尽快触发规则判定/Hold 建议），若等定时打包会延迟关键判定，因此允许配置"事件发生立即 flush 该计划"，在实时性与网络效率间按数据性质取舍。
5. **发送堵塞丢弃优先级/原因**：事件/异常包优先级高于周期包。发送队列有界且网络堵时，优先丢弃最旧的周期 trace 包（连续波形缺一段可标 Gap、FDC 可容忍少量缺失），务必保住事件/异常快照（离散且不可替代，丢了就无法定位工艺节点/故障根因）。本质与 Day03"周期可覆盖、事件不可丢"一致，沿整条管线保持该优先级，并对所有丢弃计数上报。
6. **会话关闭清理/不做后果**：要做——从统一采样调度器摘除该会话全部计划（不再为其 tick 采样）、从 FSM 事件出口退订事件/异常回调、Drain/释放各环形与事件队列、删除 sessionId→plans 映射、释放配额计数。不做会产生僵尸计划：设备持续为已断线客户端采样、事件回调仍触发、缓冲占内存、配额被死会话占用导致新客户端订不上，累积拖垮 EDA 服务（W27 Day04 原则在运行时的落地）。
7. **遍历中移除的并发安全**：采样线程高频遍历计划列表，另一线程（会话关闭/取消）会移除计划，直接 foreach 改集合会抛 InvalidOperationException 或漏采。做法：计划注册表用并发安全结构（ConcurrentDictionary + 不可变快照列表），或所有增删与遍历在同一把锁/单线程上下文串行化（调度循环开始时取一份计划不可变快照遍历，变更作用于下一周期）；事件退订与摘除原子完成。避免在持锁遍历中做网络/序列化等重活，锁内只做集合变更与指针操作。

## 二、参考实现（net8.0）：采集运行时

```csharp
namespace EapLab.Eda.Runtime;
public enum PlanState{ Active,Paused,Cancelled }
public sealed class RuntimePlan{
    public string Id{get;}public string Session{get;}public Trigger Trigger{get;}
    public PlanState State{get;set;}=PlanState.Active;
    public RingBuffer Cyc{get;}public Queue<Pt> Ev{get;}=new();public long Seq;
    public RuntimePlan(string id,string sess,Trigger t,int cap){Id=id;Session=sess;Trigger=t;Cyc=new RingBuffer(cap);} }

public sealed class Packet{public long Seq{get;init;}public string PlanId{get;init;}="";
    public Pt[] Rows{get;init;}=Array.Empty<Pt>();public List<Pt> Events{get;init;}=new();
    public long Gap{get;init;}public bool Continuous{get;init;} }

public sealed class CollectionRuntime
{
    readonly EdaSessionManager _sm;readonly EquipmentDataBus _bus;
    readonly Dictionary<string,RuntimePlan> _plans=new(); // planId->plan
    readonly Dictionary<string,List<string>> _bySess=new();long _seq;
    public CollectionRuntime(EdaSessionManager sm,EquipmentDataBus bus){_sm=sm;_bus=bus;}

    // 注册: 过会话与授权闸门(复用SessionManager.Subscribe校验)
    public string? Create(string sess,string planId,Trigger t,string[] tags,double hz)
    { var sid=_sm.GetSession(sess)??null; if(sid is null)return"no session";
        var err=_sm.Subscribe(sess,tags,hz); if(err!=null)return err;
        _plans[planId]=new RuntimePlan(planId,sess,t,cap:2000);
        if(!_bySess.ContainsKey(sess))_bySess[sess]=new();_bySess[sess].Add(planId);return null; }

    public void Pause(string id){if(_plans.TryGetValue(id,out var p))p.State=PlanState.Paused;}
    public void Resume(string id){if(_plans.TryGetValue(id,out var p))p.State=PlanState.Active;}

    // 周期tick: 只采Active周期计划
    public void CycleTick(double at,string tag,double v,Quality q)
    { foreach(var p in _plans.Values)
        if(p.State==PlanState.Active&&p.Trigger==Trigger.Periodic)p.Cyc.Write(new Pt(at,v,q)); }

    // 事件/异常注入: 独立不可丢队列
    public void OnEvent(string planId,double at,double v,Quality q=Quality.Good)
    { if(_plans.TryGetValue(planId,out var p)&&p.State==PlanState.Active&&p.Trigger!=Trigger.Periodic)
            p.Ev.Enqueue(new Pt(at,v,q)); }

    // flush: 周期+事件合并成包, 带序号/Gap/连续性
    public Packet? Flush(string id)
    { if(!_plans.TryGetValue(id,out var p)||p.State==PlanState.Cancelled)return null;
        var rows=p.Cyc.Drain();var ev=p.Ev.ToList();p.Ev.Clear();
        if(rows.Length==0&&ev.Count==0)return null;
        var gap=p.Cyc.Overwritten; // Drain后读取累计覆盖(教学: 简化)
        return new Packet{Seq=++_seq,PlanId=id,Rows=rows,Events=ev,Gap=gap,Continuous=gap==0}; }

    // 会话关闭级联撤销
    public int TeardownSession(string sess)
    { if(!_bySess.TryGetValue(sess,out var ids))return 0;
        foreach(var id in ids)_plans.Remove(id);_bySess.Remove(sess);return ids.Count; }
    public int PlanCount=>_plans.Count;
}
```

## 三、运行时职责链（手绘参考）
```
会话提交计划 ─授权闸门(可见域/Hz/点数)─▶ 注册: 周期→采样调度器 ; 事件/异常→FSM同源事件出口
运行: 采样线程周期tick→环形缓冲(可覆盖,Overwritten→Gap)
      FSM事件→即时ECV/EXV快照→独立队列(不可丢, 优先级高)
上报线程 flush(定时/凑点/事件即报)→Packet{序号,时间窗,行,事件,质量汇总,Gap,连续性}→编码发送
背压: 发送堵→丢最旧周期包保事件包, 全部丢弃计数+质量码, 不静默
生命周期: 计划绑会话, Active/Paused/Cancelled; 会话亡→摘调度+退订+释放(无僵尸计划)
并发: 遍历取不可变快照, 增删原子, 锁内只动集合不做重活; 序号/时间戳单调可查漏包
```

## 四、今日易错点
1. 计划注册不走授权闸门，越权/超频计划进入调度。
2. 事件进周期循环或进覆盖缓冲，导致阻塞或关键节点丢失。
3. Packet 无序号/时间窗/Gap，客户端无法判漏包与不连续。
4. 慢消费者丢点不计数、不标质量（必须 Gap 可观测）。
5. 发送堵塞时事件包和周期包同等丢弃（应保事件）。
6. 会话关闭不级联撤计划，僵尸计划持续耗资源。
7. foreach 遍历中另一线程移除计划导致枚举异常。
8. 暂停/恢复语义错（暂停仍采样或恢复后状态错乱）。
