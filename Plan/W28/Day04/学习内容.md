# W28 · Day04（周四）采集计划运行时：多客户端多计划调度与三触发融合

> 建议时长：100 分钟。把 W27 的 DCM 概念与 Day03 的采样引擎组装成真正的运行时：计划注册（绑会话、过授权）、周期/事件/异常三触发融合调度、批量打包、背压与质量码、会话结束级联撤销。今天产出 EDA 采集面的核心调度内核。

## 一、今日目标
1. 组装采集运行时：会话授权校验→计划注册→统一调度→缓冲→批量上报的完整闭环。
2. 三触发融合：周期 tick 走采样引擎，事件/异常由领域 FSM 同源注入即时快照，互不阻塞。
3. 批量打包：定时/凑点 flush，数据包带时间窗、变量集、质量码、Gap 统计。
4. 背压闭环：缓冲水位→覆盖/Gap 标记→质量码上报；会话结束级联撤销计划。
5. 用 C# 实现 CollectionRuntime（整合 Session 授权、SampleScheduler、RingBuffer、Packet）；xUnit 验证。

## 二、背景知识（先读，35 分钟）

### 1. 运行时职责链
1. 客户端在已授权会话内提交采集计划（变量/触发/频率/上报条件）。
2. 运行时先过**授权闸门**（可见域、频率上限、点数上限，W27 Day04），不通过拒绝。
3. 通过则注册：周期计划挂到统一采样调度器（Day03），事件/异常计划订阅领域事件出口（复用 W22 同源事件出口）。
4. 运行：周期点进环形缓冲；事件/异常发生时即时取 ECV/EXV 快照进独立队列。
5. 上报线程按定时/凑点把缓冲 Drain 成 Packet 交给编码/发送层（Day05）。
6. 会话关闭：撤销其全部计划（从调度器摘除、事件退订、缓冲释放）。

### 2. 三触发融合的关键
- 周期与事件来自不同"驱动源"：周期由采样节拍驱动，事件由 FSM 状态迁移驱动。运行时要让两者共享同一数据源与同一时钟，但进不同缓冲、用不同上报策略（周期可覆盖、事件不可丢）。
- 事件发生时，除 ECV 快照外，可在数据包里标注"该时间窗内发生了哪些事件"，让 FDC 把波形与工艺节点对齐（Step 开始处打 marker）。

### 3. 批量打包 Packet（运行时视角）
- Packet：计划 ID、时间窗起止（单调时间+UTC）、变量路径集合、周期点行（struct 批量）、本窗事件/异常快照列表、质量汇总（Good/Bad 计数、Gap 丢点数、是否连续）。
- flush 条件：定时到 或 点数到 或 事件即报（可配置事件触发立即 flush 该计划）。

### 4. 背压与质量码闭环
- 环形缓冲覆盖最旧时累加 Overwritten，flush 时把丢点数写入 Packet.Gap 并把受影响区间点质量标 Gap；Bad/Uncertain 来自数据源（传感器故障）。
- 发送层若也堵（网络慢），上报线程队列有界，满则按计划优先级（事件>周期）丢弃周期旧包、保事件包，并计数。
- 所有丢弃都可观测（计数/日志/质量码），绝不静默。

### 5. 会话与计划生命周期联动
- 计划强绑会话（W27 Day04）。运行时维护 sessionId→plans 映射；会话 Reap/Close 时一次性摘除该会话全部计划，调度器不再为其采样、事件退订、内存释放，杜绝僵尸计划。
- 计划自身可 Active/Paused/Resumed/Cancelled（暂停保留注册但不采样）。

### 6. 确定性与线程安全
- 采样线程只写缓冲、上报线程只 Drain、事件线程写事件队列，各自临界区极短；计划注册表的增删用并发安全结构或在统一锁内变更，避免"遍历调度时计划被移除"的枚举异常。
- 时间戳、序号单调，Packet 序号连续，客户端可据此检测漏包。
