# W28 · Day05 答案与参考实现

## 一、自测题标准答案
1. **II/III 回报连接形态**：Freeze II 是双向 SOAP Web Services——客户端自己也暴露一个数据接收回调端点，设备在有数据时主动调用客户端的回报方法、把 XML 数据包 POST 过去（请求/响应式回调，报文为 SOAP/XML）；Freeze III 更接近 gRPC 服务端流——客户端建立订阅后，设备在一条持久流上持续推送 protobuf 二进制数据包（连接复用、单向流、低延迟低开销）。两者 Packet 语义完全相同，差别只在编码（XML vs protobuf）与传输交互（回调 vs 流）。
2. **传输抽象/同时服务**：把"发给谁、发什么"与"怎么编码、怎么传"分离——上层运行时只产出与编码无关的中性 Packet，定义 ITransport.Send(session, bytes)，XmlPacketEncoder/ProtoEncoder 可插拔。会话建立时做内容协商（客户端声明支持 Freeze II 还是 III），ReportService 为每个会话绑定对应编码器与传输，因此同一台设备可同时向只支持 II 的老客户端发 XML、向支持 III 的新客户端发 protobuf，互不影响，平滑过渡、向后兼容。
3. **断连不影响他人的原因**：每会话独立发送队列与独立发送任务（异步），采样线程只负责把 Packet 投入对应会话队列即返回，不直接做网络发送；某客户端慢/断只阻塞它自己的发送循环、堆积它自己的有界队列（超限按策略丢周期保事件+Gap），设备采样主循环和其他会话的发送循环各自独立线程/异步链路，因此单点故障被隔离在该会话内，不回灌采样、不波及其余客户端。
4. **补不补历史/归谁**：实时 EDA 流一般**不补**断连期间历史——它是"此刻的连续波形"，重连后继续推新数据，因为补历史会让实时通道背负重传、破坏实时性，且断连期数据本就没在实时通道完整缓存（有界队列）。历史时序的长期存储与回查由 EDC/历史数据库（厂内设备数据汇聚平台，W34）负责，需要历史走查询接口而非实时流。要区分：GEM 事务可靠不丢（Spool），EDA 实时流有界、丢点标 Gap、历史另由数据平台保障。
5. **连续失败/级联联动**：每次发送失败计数并记录最后错误、可做有限重试；连续失败/超时达到阈值即判定该会话死亡，上报给会话管理器，触发 W27 Day04/本周 Day04 的级联撤销——摘除该会话全部采集计划、从调度器退订、清发送队列、释放配额，避免向死连接无限写、僵尸计划空耗。即"发送层判死→会话层清理→采集层停采"一条链联动。
6. **Cancel 保证/常见 bug**：必须保证取消后该计划立即停止出包、不再向任何队列投递、释放其缓冲与编码上下文，且不影响同会话其他计划。常见 bug：取消只停了采样但发送队列残留旧包仍被发出（取消后还收到数据）；事件回调未退订仍在生成快照；遍历中移除导致并发异常或漏处理；取消一个计划误清整会话。正确做法是状态置 Cancelled 原子地同时切断"采样入队、事件注入、flush 出包"三处并退订释放。
7. **先内存抽象后真实 HTTP 的好处**：先在内存把采集运行时与上报的业务逻辑（路由、编码选择、队列隔离、生命周期、背压、级联）做对并用 xUnit 快速验证，不被网络框架细节干扰；W29 只需把 ITransport 的内存实现替换为 ASP.NET Core HTTP(S)/gRPC 实现，上层逻辑零改动。这正是"内核稳定、传输可换"的分层价值——可测试、可演进（Freeze II→III）、可替换（内存→真实网络），避免业务逻辑和框架耦合后难以单测与升级。

## 二、参考实现（net8.0）：上报服务 + 模拟客户端

```csharp
namespace EapLab.Eda.Report;
public enum Freeze{ II_XML, III_PB }
public interface ITransport{ void Send(string session,ReadOnlyMemory<byte> payload);bool Alive{get;}int FailStreak{get;} }

// 内存模拟传输: 可制造断连/失败
public sealed class InMemoryTransport : ITransport
{
    public Dictionary<string,List<byte[]>> Inbox{get;}=new();
    public bool Disconnected{get;set;}public int FailStreak{get;private set;}public bool Alive=>!Disconnected;
    public void Send(string s,ReadOnlyMemory<byte> p)
    { if(Disconnected){FailStreak++;throw new InvalidOperationException("conn down");}
        FailStreak=0;if(!Inbox.ContainsKey(s))Inbox[s]=new();Inbox[s].Add(p.ToArray()); }
}

public sealed class ClientEndpoint // 模拟客户端: 声明支持的Freeze版本
{ public string Session{get;}public Freeze Freeze{get;}public ClientEndpoint(string s,Freeze f){Session=s;Freeze=f;} }

public sealed class ReportService
{
    readonly InMemoryTransport _t;readonly Dictionary<string,Freeze> _enc=new();
    readonly Dictionary<string,Queue<byte[]>> _q=new();public int DeadSessions{get;private set;}
    readonly int _failLimit;
    public ReportService(InMemoryTransport t,int failLimit=3){_t=t;_failLimit=failLimit;}
    public void Onboard(ClientEndpoint c){_enc[c.Session]=c.Freeze;_q[c.Session]=new();}

    public void Publish(string session,Packet pkt,Func<Packet,string> toXml,Func<Packet,byte[]> toPb)
    { if(!_q.ContainsKey(session))return; // 未 onboard/已取消不发
        var bytes=_enc[session]==Freeze.II_XML?System.Text.Encoding.UTF8.GetBytes(toXml(pkt)):toPb(pkt);
        _q[session].Enqueue(bytes); }
    // 每会话独立发送循环(教学: 同步驱动一次)
    public string? Pump(string session)
    { if(!_q.TryGetValue(session,out var q))return"no session";
        while(q.Count>0){var b=q.Dequeue();
            try{_t.Send(session,b);}
            catch{ if(_t.FailStreak>=_failLimit){DeadSessions++;return"dead->teardown";} return"retry later";} }
        return null; }
    public void Cancel(string session){_q.Remove(session);_enc.Remove(session);} // 取消后绝不再发
    public int Queued(string s)=>_q.TryGetValue(s,out var q)?q.Count:0;
}
```

## 三、上报链路（手绘参考）
```
CollectionRuntime.Packet(中性, 有序号/质量/Gap)
        │ 按会话路由
        ▼
ReportService: 会话协商编码(II=XML回调 / III=PB流) → 每会话独立有界发送队列
        │ 独立异步发送循环(故障隔离)
        ▼
ITransport ──II: 调客户端回调WebService(SOAP/XML) ; III: gRPC流推protobuf
断连: 只堵自己队列(丢周期保事件+Gap), 有限重试, 连续失败判死→会话级联撤销; 实时不补历史(历史归EDC)
生命周期: Onboard建队列; Pause停取; Resume续; Cancel切断采样/事件/出包三处并释放, 之后绝不发
W29: ITransport内存实现换成ASP.NET Core HTTP/HTTP2, 上层逻辑零改
```

## 四、今日易错点
1. 采样线程直接做网络发送，一客户端慢拖垮全部（必须每会话独立异步队列）。
2. 不做内容协商，所有客户端强制一种编码（应按会话选、II/III 并存）。
3. 断连后实时流试图补全部历史（实时不补，历史归 EDC/历史库）。
4. 发送失败无限重试、不判死、不级联撤销（僵尸会话空耗）。
5. Cancel 只停采样，残留队列仍发出/事件未退订。
6. 取消一个计划误清整会话其他计划。
7. 业务逻辑和 HTTP 框架耦合，无法单测、难升级 Freeze III。
8. 混淆 GEM Spool 的可靠不丢与 EDA 实时流的有界+Gap。
