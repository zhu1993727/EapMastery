# W28 · Day01 答案与参考实现

## 一、自测题标准答案
1. **建模五步**：①定模块 Module（按机械/功能独立性，输入硬件结构图/BOM，输出 ProcessModule[i]/TransferModule/LoadLock[i]/LoadPort[i]/Utility）；②定子系统 Subsystem（模块内按功能域 Vacuum/Temperature/RF/Gas/Motion/Process）；③定部件 Component（最小可采/可控有意义单元：加热区、MFC、阀、轴、传感器）；④挂逻辑对象 Logical（Job/Step、Carrier、Wafer、Equipment 汇总）；⑤挂成员（SVDV/ECV/EXV/Event/Exception，补类型/单位/量程/枚举/WKN）。每步输出更细一层的对象树与成员清单，最终产出可生成 EqSD 的完整模型。
2. **物理树按稳定拓扑的原因**：客户端（FDC/YMS）的订阅、规则、看板要长期稳定、跨批次复用。硬件拓扑（哪个腔、哪个 MFC）物理上稳定少变；工艺/配方/批次频繁变化，若按工艺组织树，换产品/改配方对象路径就变，订阅全部失效、模型不稳定。正确做法是物理树固定，工艺动态内容（当前 recipe、step、片）作为逻辑对象上的变量值变化，结构不动而值在变，兼顾稳定与表达。
3. **粒度/不暴露的量**：判据是"客户端是否需要独立订阅或定位到它"——需要独立监测/归因/下钻才单独成节点或成员。不该暴露：纯内部控制中间量（PID 内部累加、状态机临时变量）、未经标定/无意义的原始寄存器值、重复冗余量（可由其他量推导且无人直接订阅）、涉及安全/配方机密且未授权的量。过粗会丢诊断信息（一个大对象几百个无结构点），过细增建模/维护/安全面与性能负担；目标是"诊断够用、结构清晰、同型可枚举"。
4. **命名是契约/演进规则**：客户端按路径/名字订阅并在规则、看板、历史库里长期引用，一旦发布，改名/删点/改语义就会让既有订阅与分析失效，因此命名是对外契约。演进规则：只增不轻易改删；确需废弃先标 Deprecated 保留过渡期；新增成员向后兼容；改语义/单位/类型必须升模型版本（EqSD revision）并在自描述体现；索引顺序稳定。严禁"悄悄改含义"。
5. **GEM300 映射**：①E87——`/Equipment/LoadPort[1]/Carrier`（逻辑对象）下 SVDV：CarrierId、ManagementState(枚举 NotInstalled/Installed/Loaded/Unloaded)、ReservationState，Event：CarrierInstalled/Loaded/Unloaded，Exception：CarrierHold/LotHold；②E40——`/Equipment/ProcessModule[i]/Job` 下 SVDV：ProcessJobId、CurrentStepId、JobState(枚举)、StepProgress，Event：StepChanged（ECV: StepId/Recipe/WaferId）、JobCompleted；③E94——`/Equipment/ControlJob`（逻辑）下 SVDV：ControlJobId、AggregateState、ProcessJobList，Event：ControlJobStateChanged（ECV: from/to/CjId）。
6. **谁更新/EDA 能否自算**：这些逻辑成员必须由对应权威 FSM/Manager 同源更新——载具变量由 E87 CarrierManager、片变量由 E90 SubstrateTracker、PJ 由 JobStateMachine、CJ 由 CjStateMachine、控制态由 E30 控制状态机更新；EDA 层只做只读投影/采样，**不能自己推算或改写状态**（否则又成两本账、可能与控制面不一致）。EDA 读到的永远是权威域的当前值，这是 Day01 同源原则在建模层的落实。
7. **校验项/抓什么错**：①路径全局唯一（抓重复路径/订阅歧义）；②树连通、除根无孤儿（抓挂错/漏挂节点）；③物理/逻辑类型必标（抓类型缺失导致客户端无法区分硬件与抽象）；④数值型 SVDV 必带类型与单位/量纲（抓无法解析/单位混用）；⑤状态量带枚举字典、布尔语义明确（抓状态码不可读）；⑥命名符合规范、多实例索引一致（抓命名混乱）；⑦同型模块结构一致（抓同型设备结构不一致使客户端无法泛化）；⑧逻辑成员可溯源到来源 FSM（抓 EDA 自造状态/无权威来源）。

## 二、参考实现（net8.0）：建模校验器

```csharp
namespace EapLab.Eda.Lint;
public sealed class LintIssue{public string Path{get;init;}="";public string Msg{get;init;}="";
    public override string ToString()=>$"[{Path}] {Msg}";}

public sealed class CemModelLint
{
    static readonly HashSet<string> Numeric=new(){"double","int","float","long"};
    public List<LintIssue> Check(CemObject root)
    { var iss=new List<LintIssue>();var all=root.Flatten().ToList();
        // 1 路径唯一
        foreach(var g in all.GroupBy(o=>o.Path).Where(g=>g.Count()>1))
            iss.Add(new(){Path=g.Key,Msg="duplicate path"});
        // 2 连通无孤儿 + 3 类型必标(Kind有效)
        foreach(var o in all)
        { if(o!=root&&o.Parent is null)iss.Add(new(){Path=o.Path,Msg="orphan node"});
          if(!Enum.IsDefined(typeof(CemKind),o.Kind))iss.Add(new(){Path=o.Path,Msg="missing kind"}); }
        // 4/7 成员: 数值型必须有单位; 命名规范; 状态量要枚举(教学:名字含State须有枚举-此处校验非空描述)
        foreach(var(p,m) in all.SelectMany(o=>o.Members.Select(m=>(o.Path,m))))
        { var path=$"{p}/{m.Name}";
          if(Numeric.Contains(m.DataType.ToLower())&&string.IsNullOrWhiteSpace(m.Unit))
              iss.Add(new(){Path=path,Msg="numeric member missing unit"});
          if(!IsValidName(m.Name))iss.Add(new(){Path=path,Msg="bad naming"});
          if(m.Name.Contains("State")&&string.IsNullOrWhiteSpace(m.DataType))
              iss.Add(new(){Path=path,Msg="state needs enum/type"}); }
        // 7 同型模块结构一致: ProcessModule[i] 子对象名集合应相同
        var pms=all.Where(o=>o.Name.StartsWith("ProcessModule[")).ToList();
        if(pms.Count>1)
        { var sig=pms.Select(p=>string.Join(",",p.Children.Select(c=>c.Name).OrderBy(x=>x))).Distinct().Count();
          if(sig>1)iss.Add(new(){Path="/Equipment",Msg="homogeneous modules differ in structure"}); }
        return iss; }
    static bool IsValidName(string n)=>!string.IsNullOrEmpty(n)&&char.IsLetter(n[0])&&!n.Contains(' ');
}
```

### xUnit
```csharp
public class LintTests
{
    [Fact] public void 规范模型零问题()
    { var t=TypicalToolTree.Build();Assert.Empty(new CemModelLint().Check(t)); }
    [Fact] public void 数值缺单位被抓()
    { var t=new CemObject("Equipment",CemKind.Equipment)
            .Add(new CemObject("ProcessModule[1]",CemKind.Module)
              .Add(new CemObject("RF",CemKind.Subsystem).With(new Member("Power",MemberKind.SVDV,"double",""))));
      Assert.Contains(new CemModelLint().Check(t),i=>i.Msg=="numeric member missing unit"); }
    [Fact] public void 孤儿节点被抓()
    { var root=new CemObject("Equipment",CemKind.Equipment);var orphan=new CemObject("X",CemKind.Module);
      Assert.Contains(new CemModelLint().Check(root).Concat(new CemModelLint().Check(orphan)),i=>i.Msg=="orphan node"); }
    [Fact] public void 同型模块结构不一致被抓()
    { var eq=new CemObject("Equipment",CemKind.Equipment);
      var a=new CemObject("ProcessModule[1]",CemKind.Module);a.Add(new CemObject("RF",CemKind.Subsystem));
      var b=new CemObject("ProcessModule[2]",CemKind.Module);b.Add(new CemObject("Vacuum",CemKind.Subsystem));
      eq.Add(a).Add(b);
      Assert.Contains(new CemModelLint().Check(eq),i=>i.Msg.Contains("homogeneous")); }
    [Fact] public void 非法命名被抓()
    { var eq=new CemObject("Equipment",CemKind.Equipment)
        .Add(new CemObject("M",CemKind.Module).With(new Member("bad name",MemberKind.SVDV,"string")));
      Assert.Contains(new CemModelLint().Check(eq),i=>i.Msg=="bad naming"); }
}
```

## 三、建模流程（手绘参考）
```
输入: 硬件BOM/点表 + 领域FSM(E87/E90/E40/E94/E30) + E164 WKN + FDC需求
五步: Module(同型[i]) → Subsystem(功能域) → Component(可采最小单元)
      → Logical(Job/Carrier/Wafer/Overall) → 成员(SVDV/ECV/EXV/Event/Exception+类型单位WKN)
原则: 物理树随硬件稳定(工艺动态做成变量值); 粒度=需独立订阅才暴露; 同型结构一致
命名契约: 稳定/语义化/带单位枚举; 只增不删, 改语义升版本
同源: 逻辑成员由权威FSM更新, EDA只读投影不自算
Lint: 路径唯一/无孤儿/类型必标/数值带单位/状态带枚举/命名合规/同型一致/可溯源
```

## 四、今日易错点
1. 按工艺/配方组织物理树，换产品路径就变（物理树要随硬件稳定）。
2. 粒度失控：内部中间量全暴露或大对象无结构。
3. 数值点不带单位量纲、状态点不带枚举。
4. 同型模块结构不一致，客户端无法泛化。
5. 命名随意、发布后改名删点破坏订阅契约。
6. EDA 层自己推算作业/片状态（必须由权威 FSM 同源更新、只读投影）。
7. 只建物理量，漏了 E87/E90/E40/E94 逻辑对象，FDC 拿不到作业上下文。
8. 不做建模校验，问题到客户端联调才暴露。
