# W30 · Day06 答案与参考实现

## 一、自测题标准答案
1. **此消彼长/取舍**：判定阈值决定灵敏度——阈值越严（越靠近正常中心）越容易触发，真故障更难逃（漏报少）但正常波动也更易被报（误报多）；阈值越松反之。二者在同一规则上此消彼长（ROC 曲线刻画）。取舍看代价不对称：安全/硬件/良率相关故障漏报代价极高（损伤设备、废片、安全事故），宁可容忍少量误报也要从严（OR/低阈值+快速确认）；纯产能/提示类误报会造成不必要 Hold、损失产出并让操作员逐渐无视告警，应用 AND 互证、持续确认、模型复核降低误报。最终按"漏报代价 vs 误报代价"分级设定，并通过持续复盘调优。
2. **降误报手段（≥5）**：①去抖/持续时间（连续 N 点/T 时长才确认，滤瞬时噪声）；②迟滞回差（触发与恢复不同阈值，防边界抖动）；③按 Step/Recipe/产品分段加载基线，过渡段（升温/抽真空）放宽或屏蔽；④多条件 AND 互证（如流量低且压力漂移才报）与时序指纹；⑤坏点/质量门控（Bad/Gap 不判工艺）；⑥抑制维护/非加工/换气等已知工况；⑦报警冷却时间与激活期不重复；⑧用偏差（相对设定值）而非绝对硬限，捕捉缓慢漂移并区分设定差异；⑨多变量/模型复核单变量告警；⑩按腔/保养周期动态基线。
3. **生命周期/去重/时长**：Raised（首次触发，唯一一次）→Active（持续越限，不再重复推送，可被人工 Acknowledge）→持续超阈值则升级（warning→major→critical）→恢复越过回差发 Cleared 闭合。去重维度=同规则+同对象（腔/通道/MFC）+同上下文（Job/Lot）只保留一条活跃故障，相关联规则聚合为一个故障，避免一次异常刷多条。持续时长=Cleared.At − Raised.At（未闭合则为当前时间−Raised.At），用于升级与 MTTR/停机分析（呼应 W25 RAM）。
4. **三者关系/执行方/谁设谁解**：S5F1 Alarm 是设备自身已判定故障的离散**通知**（ALID/类别，S5F3 使能），说明"设备知道并报告"；FDC fault 是上层基于过程数据**检测推断**的异常与建议（设备未必自知、可能更早），说明"分析方发现并建议"；Hold（E30 控制状态/E87 Carrier/Lot/Equipment Hold）是**控制状态与执行结果**。前两者都是信号/建议，都不是执行方；是否 Hold 由策略层（设备联锁/EAP/经 EAP 的 FDC 建议）**决策**，而**执行方永远是设备 FSM**。谁设谁解：设备自身设的 Hold 只能设备条件满足后解、Host 经命令设的 Hold 由 Host 解，一方不能擅自解另一方设的 Hold，保证责任与安全边界清晰。
5. **报 critical 是否等于已 Hold/闭环**：不等于。FDC 报 critical 只代表"分析方判定严重并建议 Hold"，设备此时可能仍在 Running。正确闭环：FDC 出 critical fault+建议→EAP/策略层按授权与联锁裁决→经 GEM S2F41 下发 Hold（带 fault id/原因）→设备 S2F42 受理（ACKC10=0 仅受理）→设备 FSM 合法迁移到 Hold→以迁移后 S6F11 Hold 状态事件为生效判据并回告 FDC/EAP→谁设谁解、恢复时 Cleared/Resume。未收到生效 S6F11 前不得假设已 Hold；FDC 本身不经 EDA 直接停设备。
6. **MFC 漂移/为何硬限抓不到/组合**：MFC 老化/堵塞/校准漂移使实际流量缓慢偏离设定，早期偏差小、绝对值仍在工艺硬限内，单变量上下限不会触发，等越硬限时已漂移很久、可能废片。正确规则：用"实际−设定"的**偏差**（结合死区）超阈值且**持续 N 秒**（去抖），并与该路气体导致的**腔压同向漂移**做 AND 互证（降误报、区分正常设定切换），在不同 Step 用不同设定基线；指纹{GasFlow Low/Drift, Pressure Drift}分类为 F_MFC_DRIFT(major)，建议复校/保养，偏差扩大或持续超时升级，必要时经 EAP→GEM Hold。设备 S5F1 往往到更严重才报，FDC 实现提前预警。
7. **RF 失配 critical/回控**：RF 匹配网络/调谐异常时反射功率骤升、正向功率下降、腔压/等离子波动，不仅导致本步工艺失效（刻蚀/沉积能量不对、废片），高反射还可能**损伤射频源/匹配器硬件**，后果重且发展快，故定 critical。检测用反射功率 HH 且正向功率低（AND）+时序（反射先升后波动）互证，指纹{RFFwd Low, RFRefl High, Pressure Wave}→F_RF_MISMATCH，立即产出 Hold/终止本步建议；回控链路= FDC critical→EAP 策略裁决（自动 Hold 授权/联锁满足）→GEM S2F41 Stop/Hold→设备 FSM 执行并停 RF/工艺→S6F11 回告生效，同时关联设备自身 RF 联锁 S5F1 报警互相印证，事后按持续时长与证据排查匹配网络。

## 二、参考实现（net8.0）：告警生命周期管理器

```csharp
namespace EapLab.Fdc.Life;
public sealed class ActiveAlarm{
    public string Key{get;}public DateTime Raised{get;}public Severity Sev{get;set;}
    public DateTime? Cleared{get;private set;}public bool Ack{get;private set;}
    public ActiveAlarm(string key,DateTime t,Severity s){Key=key;Raised=t;Sev=s;}
    public void Acknowledge()=>Ack=true;
    public TimeSpan Duration(DateTime now)=> (Cleared??now)-Raised;
    public bool Escalate(TimeSpan after,DateTime now,Severity to){if(!Cleared.HasValue&&Duration(now)>after&&Sev<to){Sev=to;return true;}return false;}
    public void Close(DateTime t)=>Cleared=t; }

public sealed class AlarmLifecycle
{
    readonly Dictionary<string,ActiveAlarm> _a=new();
    public event Action<ActiveAlarm>? OnRaised;
    // key=规则+对象+上下文; 边沿Raised去重, 持续可升级, 恢复Cleared
    public ActiveAlarm? Raise(string rule,string obj,string lot,Severity sev,DateTime now)
    { var k=$"{rule}|{obj}|{lot}";if(_a.ContainsKey(k))return null; // 激活期不重复
        var al=new ActiveAlarm(k,now,sev);_a[k]=al;OnRaised?.Invoke(al);return al; }
    public ActiveAlarm? Clear(string rule,string obj,string lot,DateTime now)
    { var k=$"{rule}|{obj}|{lot}";if(!_a.Remove(k,out var al))return null;al.Close(now);return al; }
    public int ActiveCount=>_a.Count;
    public List<ActiveAlarm> EscalateOver(TimeSpan after,DateTime now,Severity to)
    { var r=new List<ActiveAlarm>();foreach(var a in _a.Values)if(a.Escalate(after,now,to))r.Add(a);return r; }
}
```

### xUnit（含两案例）
```csharp
public class LifecycleTests

    [Fact] public void Raised去重_恢复闭合算时长()
    { var m=new AlarmLifecycle();var t=DateTime.UtcNow;
      Assert.NotNull(m.Raise("FlowDev","MFC1","L1",Severity.Major,t));
      Assert.Null(m.Raise("FlowDev","MFC1","L1",Severity.Major,t.AddSeconds(1))); // 不重复
```

## 三、信号→决策→Hold 关系（手绘参考）
```
信号层(都不是执行方):
  S5F1 Alarm=设备自判离散通知(ALID,S5F3使能) ; FDC fault=上层trace/多变量检测推断(可更早,带证据/分级)
决策层: 策略(EAP/制造授权+联锁+设备状态) 决定是否Hold; FDC只建议不直写(EDA只读)
执行层: 设备FSM经GEM S2F41受理→迁移Hold→S6F11生效(受理≠生效); 谁设谁解, Resume闭合
告警生命周期: Raised(唯一)→Active(去重:规则+对象+Lot, 不刷)→超时升级→Cleared(越回差)
  持续时长=Clear-Raise; 抑制期冻结不误清; 误报漏报复盘→阈值/互证/指纹迭代走ECN
案例A MFC漂移: 偏差(实际-设定)+持续+压力同向AND(硬限早期抓不到)→major→复校/升级
案例B RF失配: 反射HH&正向低&压力波AND+时序→critical(伤硬件废片)→立即经EAP→GEM Hold
```

## 四、今日易错点
1. 认为阈值越严越好（误报泛滥导致告警被无视，要按代价分级）。
2. 持续故障每点重复告警、不做去重与聚合，形成告警风暴。
3. 不做升级，warning 挂很久不到 critical。
4. 把 S5F1/FDC 告警当成 Hold（它们是信号，Hold 是控制执行结果）。
5. 以为 FDC critical 设备就停了（要经策略→GEM→S6F11 生效确认）。
6. 一方擅自解另一方设的 Hold（谁设谁解）。
7. MFC 缓慢漂移只靠绝对硬限（要用偏差+持续+互证）。
8. 误报/漏报不记录不复盘，规则一次配完不迭代（应走 ECN 持续调优）。
