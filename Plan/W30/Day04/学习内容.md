## 二、背景知识（先读，35 分钟）

### 1. 接口契约（ICD）包含什么
- **订阅点表**：每个采集量的 CEM 路径、E164 WKN、数据类型、工程单位/SI、量程、是否周期/事件、数据质量要求、用途（哪条规则用）。
- **采集参数**：采样率（Hz）、上报 flush 周期、打包方式、Freeze 版本、是否需要事件即报。
- **上下文事件**：哪些 Event/Exception 必须发、各自携带哪些 ECV/EXV（StepId/RecipeId/LotId/JobId/腔号/片 id/状态 from-to）。
- **时间与质量**：统一时钟/时间戳格式、质量码、Gap 处理、丢点可观测。
- **会话与 SLA**：重连行为、会话上限、FDC 侧消费能力、数据延迟 SLA（采样到 FDC 收到的 P99）。

### 2. 必需上下文事件（设备端必须吐全）
- 作业：ControlJob/ProcessJob 创建/开始/完成/取消/失败（E94/E40）；Step 切换（StepId、Recipe、腔、片）。
- 物料：Carrier Installed/Loaded、LotId 绑定、Wafer 进出腔（E87/E90）。
- 控制：On/Off-Line、Local/Remote、Hold/Resume/Pause（E30），谁设的 Hold。
- 报警：设备 S5F1 Alarm 置位/清除也要在 EDA 侧作为 Exception 事件可见（双通道对齐）。
- 没有这些 marker，FDC 无法分段、无法关联 Lot/片，规则和良率归因都失效（Day03 已述）。

### 3. 检测延迟预算反推（设备端 SLA）
- 链路延迟 = 采样周期 T_s + 规则持续窗口 T_d + flush 周期 T_f + 网络/计算 T_c。要求总延迟 ≤ 允许响应时间 T_req（且采样密度对异常时间尺度 5–10 倍）。
- 由此反推：T_s、T_f 的上限写进契约并可测；FDC 收到数据的端到端 P99 延迟作为联调验收项。
- 设备端不能为省资源把 flush 设太长，否则 FDC 检出滞后、Hold 来不及。

### 4. 告警回控链路（决策≠执行的契约化）
1. FDC 检出并分级，产出 fault + 建议动作（warning 记录 / critical 建议 Hold/Stop）。
2. EAP/Host 侧策略层裁决（结合设备状态、Lot、是否允许自动 Hold、联锁条件），决定是否下发。
3. 经 GEM：S2F41 远程命令（Hold/Stop，带 CP：原因/fault id/来源），设备 FSM 校验 Guard 后执行。
4. 受理≠生效：S2F42 ACKC10=0 只代表受理，真正生效以迁移后 S6F11（控制状态/Hold 事件）为准；FDC/EAP 以此确认。
5. 超时/拒绝回告：设备无法执行（状态不允许）回非 0 与原因，策略层处理（重试/升级人工/报警）。
- 设备端契约：只接受经 GEM 的合法命令、严格走状态机、谁设谁解、回告完整；EDA 侧永远不接受写。

### 5. 职责边界（RACI 简版）
- 设备端 EAP：点表可得性/质量/频率/时钟/事件 marker/命令受控执行与回告（Responsible）。
- FDC：规则/模型、检测分类、建议（Responsible）；EAP/制造：回控策略与授权（Accountable）；工艺：阈值/规则参数（Approved，ECN 受控）。

### 6. 联调与验收
- 用同一 Lot 跑片，比对：FDC 收到的点频率/缺点、事件 marker 与 GEM S6F11 时间线一致、注入一个越限看端到端检测到回控的时延与正确性。这就是 Day06 演练的前置规格。
