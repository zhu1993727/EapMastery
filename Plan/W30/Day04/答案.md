# W30 · Day04 答案与参考实现

## 一、自测题标准答案
1. **契约组成**：①订阅点表——每点 CEM 路径、E164 WKN、数据类型、单位/SI、量程、周期还是事件、质量要求、被哪条规则使用；②采集参数——采样率、flush 上报周期、打包方式、Freeze 版本、事件是否即报；③上下文事件清单——必发 Event/Exception 及其 ECV/EXV；④时间与质量——统一时钟与时间戳格式、质量码、Gap/丢点可观测；⑤会话与 SLA——重连行为、会话上限、FDC 消费能力、采样到 FDC 收到的端到端延迟 P99 与可用性。契约要版本化、双方会签、随 ECN 变更。
2. **必需上下文事件/ECV**：作业类——ControlJob/ProcessJob 创建/开始/完成/取消/失败（E94/E40），Step 切换（StepId、RecipeId、腔号、WaferId、序号）；物料类——Carrier Installed/Loaded、LotId 绑定、Wafer 进出腔（E87/E90，含 Slot/位置）；控制类——On/Off-Line、Local/Remote、Hold/Resume/Pause（E30，含 from-to、Hold 原因与设置方）；报警类——S5F1 Alarm 置位/清除同时作为 EDA Exception 事件（ALID/类别/严重度）。关键 ECV 是 LotId/JobId/StepId/RecipeId/Module/WaferId/状态迁移，缺了 FDC 就无法把波形分段、关联到具体片与 Lot、做良率归因。
3. **延迟公式/flush 限制**：端到端检测延迟 ≈ 采样周期 T_s + 规则持续窗口 T_d + flush 上报周期 T_f + 网络与 FDC 计算 T_c，要求总延迟 ≤ 允许响应时间 T_req，且采样密度对异常时间尺度达 5–10 倍。flush 是"攒一批再发"，设太长，异常发生后要等近一个 flush 周期数据才离开设备，T_f 直接叠加进检测延迟，可能导致 FDC 检出时已错过 Hold 窗口；所以 T_f 必须由 T_req 倒推上限（实时 FDC 常亚秒~秒级），不能为省 HTTP 调用无限调大，并把端到端 P99 延迟写进 SLA 验收。
4. **回控链路/决策执行**：①FDC 检出异常、分类分级，产出 fault 与建议动作（记录/建议 Hold/Stop，含 fault id、证据、来源）；②EAP/Host 策略层结合设备控制状态、Lot、自动 Hold 授权与联锁条件裁决是否动作（决策方）；③经 GEM 用 S2F41 下发 Hold/Stop 远程命令（带原因/fault id CP）；④设备 FSM 校验 Guard、合法迁移执行 Hold（执行方永远是设备）；⑤迁移后经 S6F11（Hold 状态事件）/相关报警回告，FDC/EAP 据此确认闭环。FDC 不直写设备（EDA 只读），决策与执行分离、谁设谁解。
5. **ACKC10≠已 Hold/以何为准**：S2F41→S2F42 ACKC10=0 只表示设备**受理**了远程命令（语法/当前可接收），不代表状态已迁移；真正生效要等设备 FSM 完成迁移后发出的 S6F11 控制状态/Hold 事件（并能读到 Hold 状态变量）。可能受理后因 Guard/资源/安全条件不满足而未迁移或迁移失败。因此 FDC/EAP 必须以迁移后 S6F11（或对应状态变量）作为 Hold 生效判据，并设超时：受理后一定时间未收到生效事件则判命令未落实、走异常处理。这就是你在 GEM 阶段反复练的"受理≠生效"。
6. **拒绝/超时处理**：设备当前状态不允许（如 Local 模式、非 Running、Guard 不满足）时 S2F42 回非 0 ACKC 并带原因，或受理后迁移失败回错误事件；网络层超时未收到 ACK/生效事件，策略层按幂等原则重试（同一命令带幂等标识，设备不重复执行）或升级：标记该设备/ Lot、转人工处置、必要时触发更高级别联锁/停线建议，并完整记录 fault→建议→命令→结果时间线供追溯。绝不在未确认生效时假设已 Hold 而继续放片。
7. **RACI**：设备端 EAP=Responsible（负责点表可得性、数据质量/频率/统一时钟、上下文事件 marker、命令经 GEM 受控执行与结果回告）；FDC 系统/团队=Responsible（规则与模型、检测分类、产生建议）；制造/EAP 策略=Accountable（自动回控授权与策略、对是否 Hold 最终负责）；工艺工程师=Approved/Accountable（阈值、规则参数、Recipe 相关基线，变更走 ECN 审批）；MES/EDC=Support/Informed（提供 Lot/工单上下文、落数据与追溯）。设备端不决定阈值也不做 FDC 算法，但必须保证"拿得到、对得齐、控得回"。

## 二、参考实现（net8.0）：契约校验器

```csharp
namespace EapLab.Fdc.Contract;
public sealed class PointSpec{public string Path{get;init;}="";public string? Wkn{get;init;}public string Unit{get;init;}="";
    public bool Periodic{get;init;}public double Hz{get;init;}}
public sealed class SubscriptionContract
{
    public List<PointSpec> Points{get;init;}=new();public HashSet<string> RequiredEvents{get;init;}=new();
    public double SampleHz{get;init;}public double FlushSec{get;init;}public double ReqRespSec{get;init;}
}
public sealed class ContractIssue{public string Msg{get;init;}="";public override string ToString()=>Msg;}

public sealed class ContractValidator
{
    static readonly HashSet<string> MustEvents=new(){"JobStart","JobComplete","StepChanged","CarrierLoaded","HoldChanged","AlarmChanged"};
    public List<ContractIssue> Validate(SubscriptionContract c)
    { var iss=new List<ContractIssue>();
        foreach(var p in c.Points)
        { if(string.IsNullOrEmpty(p.Wkn))iss.Add(new(){Msg=$"{p.Path} 缺WKN"});
          if(string.IsNullOrEmpty(p.Unit)&&p.Periodic)iss.Add(new(){Msg=$"{p.Path} 周期量缺单位"}); }
        var miss=MustEvents.Except(c.RequiredEvents);
        foreach(var e in miss)iss.Add(new(){Msg=$"缺必需上下文事件 {e}"});
        // 延迟预算: Ts+Td(估0)+Tf+Tc(估0.2) <= T_req
        double latency=1.0/c.SampleHz+c.FlushSec+0.2;
        if(latency>c.ReqRespSec)iss.Add(new(){Msg=$"延迟预算{latency:F2}s > 要求{c.ReqRespSec}s, 需提高采样/缩短flush"});
        return iss; }
}
```

### xUnit
```csharp
public class ContractTests
{
    static SubscriptionContract Good()=>new()
    { SampleHz=50,FlushSec=0.5,ReqRespSec=2,
      Points=new(){new(){Path="/PM1/T",Wkn="WKN.Chamber.Temperature",Unit="C",Periodic=true,Hz=50}},
      RequiredEvents=new(){"JobStart","JobComplete","StepChanged","CarrierLoaded","HoldChanged","AlarmChanged"} };
    [Fact] public void 完备契约零问题()=>Assert.Empty(new ContractValidator().Validate(Good()));
    [Fact] public void 缺WKN与单位被抓()
    { var c=Good();c.Points[0].Wkn=null;c.Points[0].Unit="";
      var iss=new ContractValidator().Validate(c);Assert.Contains(iss,i=>i.Msg.Contains("WKN"));Assert.Contains(iss,i=>i.Msg.Contains("单位")); }
    [Fact] public void 缺必需事件被抓()
    { var c=Good();c.RequiredEvents.Remove("StepChanged");
      Assert.Contains(new ContractValidator().Validate(c),i=>i.Msg.Contains("StepChanged")); }
    [Fact] public void flush过长违反延迟预算()
    { var c=Good();var bad=c with{FlushSec=5}; // 0.02+5+0.2 > 2
      Assert.Contains(new ContractValidator().Validate(bad),i=>i.Msg.Contains("延迟预算")); }
}
```

## 三、FDC↔设备时序（手绘参考）
```
FDC ─POST会话/订阅(点表:路径/WKN/单位/Hz, 事件marker, Freeze)─▶ 设备EDA(过授权)
设备 ◀══周期trace(质量码/Gap, 统一单调时钟+UTC)══ ; 作业/控制/报警事件即报(带Lot/Job/Step/Recipe/片ECV)
FDC分段(Step/Recipe)→规则检测分类→分级fault+建议
   critical: FDC→EAP策略裁决(状态/授权/联锁)→GEM S2F41 Hold(CP:faultid/原因)
设备: S2F42 ACKC10=0(仅受理) → FSM迁移 → S6F11 Hold事件(生效判据) → FDC/EAP确认闭环
超时/拒绝: 非0原因/未收到S6F11→幂等重试或升级人工, 不假设已Hold
铁律: EDA只读不写; 回控只走GEM; 受理≠生效; 谁设Hold谁解
延迟SLA: 1/Hz + 持续窗 + flush + 网络计算 ≤ T_req; 端到端P99可测可验收
```

## 四、今日易错点
1. 点表缺 WKN/单位/质量，FDC 无法跨设备解析与判可信。
2. 只给连续 trace、不给 Step/Job/Lot/Hold/Alarm 事件 marker。
3. flush 为省带宽设太长，检测延迟超响应窗口。
4. 把 S2F42 受理当 Hold 生效（应以迁移后 S6F11 为准）。
5. FDC 经 EDA 直写设备或绕过策略层直接 Hold。
6. 命令无幂等标识，超时重试导致重复执行。
7. 不设生效超时与拒绝回告，未 Hold 却继续放片。
8. 契约不版本化、阈值/点表变更不走 ECN，双方口径漂移。
