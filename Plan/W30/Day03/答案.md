# W30 · Day03 答案与参考实现

## 一、自测题标准答案
1. **六种原语/判定式/针对故障**：
   - 限界 H/HH、L/LL：x>H(HH) 或 x<L(LL) 触发，针对越工艺窗口，HH/LL 更严对应更重处置。
   - 变化率 rate：|x(t)-x(t-Δ)|/Δ > R，针对骤升骤降/突变，绝对值可能仍在界内。
   - 卡死 stuck：滑动窗内 max-min < ε 且该工序本应有波动，持续 T，针对传感器断线/值冻结/通信冻结。
   - 毛刺 spike：偏离阈值但宽度 < 最小持续即回正，需结合宽度区分噪声与真实短异常。
   - 死区 deadband：|x-x_ref|<δ 视为不变，针对阈值附近噪声抖动。
   - 持续/去抖 duration：条件连续满足 N 点/T 时长才报，针对单点噪声误报。
   - 迟滞 hysteresis：触发用高阈值、解除用低阈值（回差带），针对阈值附近反复报警-恢复。
2. **去抖/回差/持续时间区别**：去抖（debounce）要求条件连续成立一小段才确认，滤除瞬时尖峰噪声，关注"是不是一瞬间"；持续时间是去抖的量化形式（连续 N 点/T），强调异常稳定存在；迟滞回差解决的是报警后的"解除"抖动——触发与恢复用不同阈值（如 >100 报警、降到 <95 才恢复），防止值在 100 附近来回跳导致反复告警。三者可叠加：进入需持续越限（去抖/持续），退出需越过回差（迟滞）。
3. **stuck 为何用窗口极差**：真实值很少严格"等于某值不变"，正常量也有微小波动，而传感器冻结/断线往往表现为输出恒定或变化极小。用滑动窗口 max-min<ε（允许小于噪声死区 ε 的微变）比"等于上一值不变"更鲁棒：既识别冻结，又不因正常量化微抖漏判，也避免浮点严格相等问题；同时要求该工序本应有变化、并持续一定时长，防止在天然平稳段误报。
4. **Step 切换两件事/清窗口原因**：①加载新段对应的 RuleSet（阈值/规则类型随 Step/Recipe/产品切换，升温段宽、稳态段严）；②清空所有有状态规则的历史窗口与报警状态（rate 的上一点、stuck 的窗口、去抖计数、已激活状态）。必须清窗口，因为上一段（如升温）的斜率/数值若带进新段（稳态），会用旧段数据算出错误的变化率/极差，在切换瞬间产生跨段误报；状态重置保证每段规则只在本段数据上独立判定。
5. **AND/OR/时序取舍**：AND（多条件同时成立才报）通过要求"多个相互印证的症状"降低误报，适合单一条件易被正常工况触发、但组合出现才是真故障的场景（如 RF 前向功率低且反射高才报失配），代价是某条件缺失时可能漏报；OR（任一成立即报）优先保安全，用于任何一个征兆出现就不能放过的危险场景，代价是误报增多。时序组合（A 升高后 N 秒内 B 下降）匹配故障因果指纹，进一步提精度。原则：安全关键、漏报代价高用 OR/宽条件；误报代价高（会误 Hold 损失产能）用 AND/时序加确认。
6. **质量影响/跨缺口重置**：规则只应对 Good 点做限界/趋势判定；Bad/Uncertain 点是采集/传感器不可信，不能当真值触发工艺故障（否则把坏点误判成工艺异常），应跳过或单独计数据质量告警；Gap 段表示丢点、数据不连续。跨缺口必须重置 rate/stuck/去抖窗口，因为缺口两侧时间不连续，用上一有效点和缺口后第一点算变化率会得到被时间差放大的假突变、用跨缺口拼出的窗口算极差/持续时间也失真。重置后从新连续段重新积累窗口，并可标记该段统计不完整。
7. **为何规则为主模型为辅**：规则（限界/趋势/组合）完全可解释——触发时能直接给出哪个量、什么时间、值/阈值/持续/所在 Step，工程师能快速确认、放行、追责，验证与审计容易、部署轻、确定性强、不依赖大量训练数据，符合 FAB 对稳定与合规的要求；多变量统计/ML 模型能抓复杂耦合与隐蔽异常，但可解释性弱、需训练维护、存在漂移与误报风险。因此先进 FAB 用规则覆盖绝大多数明确故障做主力与安全兜底，用 PCA/ML 做补充去发现规则难描述的复杂异常，二者分层、模型结果常仍回落到可解释规则/指纹确认。

## 二、参考实现（net8.0）：有状态规则原语求值器

```csharp
namespace EapLab.Fdc.Rules;
// 流式逐点求值, 带状态; 只对Good点判定
public abstract class Rule{
    public string Tag{get;}protected bool _active;protected Rule(string tag){Tag=tag;}
    public abstract bool Eval(Pt p); // 返回本次是否处于报警态
    public void Reset(){_active=false;OnReset();}protected virtual void OnReset(){}
}
// 限界 + 去抖(连续N点) + 迟滞回差(解除阈值)
public sealed class LimitRule:Rule
{ readonly double _hi,_clear,_dead;readonly int _need;int _cnt;
    public LimitRule(string tag,double hi,double clearBelow,int need):base(tag){_hi=hi;_clear=clearBelow;_need=need;}
    public override bool Eval(Pt p)
    { if(p.Q!=Quality.Good)return _active;
        if(!_active){if(p.V>_hi&&++_cnt>=_need)_active=true;}
        else if(p.V<_clear){_active=false;_cnt=0;}
        return _active; }
    protected override void OnReset(){_cnt=0;} }
// 卡死: 窗口极差<eps 持续need点(本应有波动)
public sealed class StuckRule:Rule
{ readonly double _eps;readonly int _win,_need;readonly Queue<double> _q=new();int _stuck;
    public StuckRule(string tag,double eps,int win,int need):base(tag){_eps=eps;_win=win;_need=need;}
    public override bool Eval(Pt p)
    { if(p.Q!=Quality.Good)return _active;_q.Enqueue(p.V);if(_q.Count>_win)_q.Dequeue();
        bool stuck=_q.Count==_win&&_q.Max()-_q.Min()<_eps;
        _stuck=stuck?_stuck+1:0;return _active=_stuck>=_need; }
    protected override void OnReset(){_q.Clear();_stuck=0;} }
// 变化率(跨Gap由调用方Reset)
public sealed class RateRule:Rule
{ double? _prev;readonly double _maxDelta;public RateRule(string t,double maxDelta):base(t){_maxDelta=maxDelta;}
    public override bool Eval(Pt p)
    { if(p.Q!=Quality.Good)return _active;bool hit=_prev is not null&&Math.Abs(p.V-_prev.Value)>_maxDelta;_prev=p.V;return _active=hit; }
    protected override void OnReset(){_prev=null;} }
```

## 四、分段规则集（手绘参考）
```
事件marker(StepChanged/JobStart) ─▶ 规则引擎: ①加载该Step/Recipe的RuleSet ②所有规则Reset清窗口
升温段: 限界宽, 启用Rate(允许大斜率上限), 不启用稳态Stuck
稳态段: 严格限界+小死区+去抖+回差, Stuck启用, Rate阈值收紧
规则流: Good点→对应规则(限界/rate/stuck/spike)→去抖持续→迟滞状态→触发症状→分类(Day02)
       Bad/Gap: 不判工艺, 单独数据质量告警, 跨Gap重置窗口
抑制: 维护/非Scheduled/换气道屏蔽相关规则; 报警激活后需越回差+持续才恢复, 不刷屏
组合: AND降误报(互相印证), OR保安全, 时序(A后N秒B)匹配因果指纹; 参数随Recipe版本受控(ECN)
```

## 五、今日易错点
1. 只有限界，缺变化率/卡死，绝对值正常的突变/冻结漏检。
2. 阈值附近无回差、无去抖，噪声导致反复告警刷屏。
3. stuck 用严格相等判不变（应用窗口极差+死区+持续）。
4. Step 切换不换规则、不清窗口，跨段斜率/极差造成误报。
5. 对 Bad/Gap 点照常委派工艺故障（坏点当真值）。
6. 跨缺口不重置，算出被时间差放大的假变化率。
7. 安全关键场景全用 AND 导致漏报，误报敏感场景全用 OR 导致误 Hold。
8. 规则参数不随 Recipe/产品版本受控，现场改阈值无审计（应走 ECN）。
