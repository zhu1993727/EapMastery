# W30 · Day05（周五）实现轻量 FDC 规则引擎：消费 EDA Packet，分段检测与告警边沿

> 建议时长：100 分钟。今天把 Day02–04 的原理落成代码：一个能消费 W29 EDA Packet（周期行 + 事件 marker）的流式 FDC 引擎——按 Step/Recipe 切换规则集、逐点跑规则原语、质量门控、抑制，输出"激活/恢复"边沿告警（不刷屏）并送分类器分级。这是设备端理解 FDC 内部如何工作的关键实现。

## 一、今日目标
1. 组装 FdcEngine：输入 EDA Packet（周期点 + 事件 marker + 上下文），输出故障告警流。
2. 实现分段：StepChanged/JobStart 时切换 RuleSet 并 Reset 全部规则状态。
3. 实现告警边沿管理：只在"正常→报警"发 Raised、"报警→正常"发 Cleared，激活期不重复刷。
4. 接入抑制（指定状态屏蔽规则）、质量门控（Bad/Gap 不判工艺）、分类器分级与 Hold 建议。
5. xUnit 覆盖：分段切换、去抖回差、边沿不重复、抑制、坏点不判、critical 出 Hold 建议。

## 二、背景知识（先读，25 分钟）

### 1. 引擎输入输出
- 输入：W29 的 Packet（Rows 周期点、Events 作业/控制事件 marker，带统一时间戳与质量）、当前上下文（Job/Step/Recipe/Lot）。
- 输出：FaultAlarm 流——Raised（规则首次触发，含规则/值/阈值/Step/时间）、Cleared（越过回差恢复）；送 Day02 分类器得到 FaultId/严重度/建议。

### 2. 处理流水线
1. 先处理 Events：若 StepChanged/JobStart→更新上下文、加载对应 RuleSet、Reset 规则。
2. 再逐行处理 Rows：按 Tag 找该段规则，质量门控（非 Good 跳过工艺判定），规则流式求值。
3. 边沿管理：比较规则上一态与当前态，仅在跳变时产出告警；激活期保持不重复。
4. 抑制：当前处于被抑制状态（维护/指定 Step）则跳过对应规则，也不产生恢复误报。
5. Raised 送分类器→分级；critical 产出 Hold 建议对象（仅建议，回控走 Day04 链路）。

### 3. 状态正确性要点
- 规则是有状态的（Day03），分段必须 Reset；引擎本身的告警激活态也要在分段/作业结束时清理，避免跨 Job 悬挂。
- 事件先于同一时间窗的周期点处理（先确定"现在在哪个 Step"，再用该段规则判该窗数据）。
- 多 Tag 点按到达顺序/时间排序后判，变化率依赖相邻点顺序。

### 4. 与设备端的关系（你的视角）
- 这个引擎在 FDC 侧（厂务/上位），但你要懂它怎么消费你的 Packet：这决定了设备端 EDA 必须保证点序、marker 先到、质量码、时间对齐（Day04 契约）。理解消费方，才能把数据出口做对。

### 5. 工程扩展（了解即可）
- 真实 FDC 规则成百上千、多腔并行，引擎要按 Module/腔分实例、规则编译/索引、热加载规则版本（ECN）；多变量/PCA 是另一类"规则"，挂同一流水线。今天做单腔教学版，结构要能扩展。
