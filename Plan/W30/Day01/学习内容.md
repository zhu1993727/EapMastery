## 二、背景知识（先读，40 分钟）

### 1. APC 是什么、不是什么
- APC（Advanced Process Control，先进过程控制）：用设备/工艺数据自动监控、诊断、调整工艺，减少波动、提升良率与一致性的一组系统/方法的总称。它是**一类能力的统称**，不是单个软件。
- 它不等于"设备自动控制"（设备自身的实时控制回路在控制器/PLC 层），APC 在其上层做监控、诊断与批间优化。

### 2. APC 全族（英文全称必须会）
- **FDC** Fault Detection and Classification（故障检测与分类）：实时监测过程数据，检测异常并归类故障类型（本周重点）。
- **R2R** Run-to-Run（逐批/逐 run 控制）：每批加工后根据量测结果调整下一批工艺设定（overlay/配方参数微调），W31。
- **VM** Virtual Metrology（虚拟量测）：用过程参数+模型预测每片/每批的量测值（免实际量测或补量测时延），W32。
- **SPC** Statistical Process Control（统计过程控制）：控制图、Cpk 等长期统计监控过程稳定性，W32。
- 关联系统：
  - **RMS** Recipe Management System（配方管理系统）：配方/参数版本管理与下发，W33。
  - **ADC** Automatic Data Collection（自动数据采集，方法/计划层）；**EDC** 厂内设备数据汇聚子系统（数据平台层，W34）。
  - **ECN** Engineering Change Notice（工程变更通知）：参数/配方/规则变更的受控流程。
  - **YMS** Yield Management System（良率管理）、MES（制造执行，W35）。

### 3. 三个时间尺度（建立框架，后面逐周深入）
- 实时（秒/亚秒，加工中）：FDC 盯 trace，异常即时告警/建议 Hold；设备自身控制回路更快（毫秒）。
- 逐批（批与批之间）：R2R 在一批结束、拿到量测后算下一批参数微调；VM 在加工结束即给预测量测。
- 长期（小时/天/周）：SPC 控制图看趋势漂移、Cpk；YMS 关联良率。
- 数据从快到慢逐层汇聚：EDA 高频→FDC 实时→VM/R2R 批级→SPC/YMS 长期。

### 4. CIM 数据流与控制流（核心图）
- 上行（数据）：设备经 EDA(Interface-A 高频) 与 GEM 事件(S6F11) → EAP/数据总线 → FDC（实时）、EDC/历史库（落盘）、VM/R2R（批级）、SPC/YMS（统计）。
- 下行（控制）：APC 的调整/建议**不直接写设备**，而是经 EAP/Host 通过 GEM 远程命令/OSS 或经 RMS 校验后下发，由设备 FSM 执行（决策方≠执行方，W29 已立边界）。
- MES 管工单/派工/谱系（W35），为 APC 提供 Lot/Recipe/工艺路线上下文。

### 5. 设备端 EAP 开发者的定位（你的岗位坐标）
- 你负责：设备两套接口稳定（GEM 控制 + EDA 数据）、同源数据正确、事件/上下文齐全（Step/Recipe/Lot marker）、受控执行下行命令并回告结果。
- 你不负责但要懂：FDC 规则、R2R 算法、VM 模型本身；你要能和这些系统对齐接口契约（订阅哪些点、什么频率、事件怎么对齐、告警怎么回控）。
- 关键交付：让 APC"拿得到、对得齐、控得回"。

### 6. 先进 FAB 的部署现实（长鑫/中芯/台积电类）
- 设备端 EDA 多客户端直连或经厂内数据采集网关汇聚；FDC 常是 EDA 的第一大消费者；R2R/VM 高度依赖与 RMS、量测、MES 的主数据一致；各子系统可能不同厂商，靠标准接口与统一命名(WKN)/上下文对齐集成——这正是你前几周打基础的价值。
