# W30 · Day01 答案与参考实现

## 一、自测题标准答案
1. **全族全称与职责**：
   - FDC Fault Detection and Classification 故障检测与分类：实时盯过程数据，发现异常并判定故障类型/严重度。
   - R2R Run-to-Run 逐批控制：每批后按量测结果调整下一批工艺设定（参数微调/overlay，不改 recipe 主档）。
   - VM Virtual Metrology 虚拟量测：用过程参数与模型预测每片/批量测值，补量测时延、实现全检。
   - SPC Statistical Process Control 统计过程控制：控制图/Cpk 等长期统计监控稳定性与漂移。
   - RMS Recipe Management System 配方管理：配方与参数版本受控管理、校验、下发。
   - ADC Automatic Data Collection 自动数据采集：采集方法/计划层（采什么、怎么采）。
   - EDC 厂内设备数据汇聚子系统：设备数据汇聚/治理/历史存储的数据平台层。
   - ECN Engineering Change Notice 工程变更通知：参数/配方/规则变更的受控审批与生效流程。
2. **APC 与设备实时控制回路区别**：设备自身控制回路（PLC/控制器，毫秒级）是直接驱动执行器的底层闭环（如温控 PID、压力闭环、伺服），实时性极高、在设备内部、保障物理过程按设定运行；APC 在其上层（秒级~批级~长期），基于过程数据做异常监控、诊断、批间参数优化与统计，它不直接驱动执行器，而是给设定值/建议，再经控制面下发。一个是"把当前设定执行好"，一个是"判断该不该调整设定、如何优化"。
3. **时间尺度**：FDC 在加工进行中实时（秒/亚秒）监测 trace 并即时告警；R2R 在一批（run）结束、拿到量测后、下一批开始前调整设定，是批间尺度；SPC 在更长时间（小时/天）用控制图看过程是否统计稳定、能力是否足够；VM 横跨加工结束到批级——加工一结束就用过程数据预测该片刻/批的量测值，为 R2R 快速提供输入（免等量测机台）。数据由快到慢：EDA 高频→FDC 实时→VM/R2R 批级→SPC/YMS 长期。
4. **上行/下行流与通道**：上行数据——设备经 EDA/Interface-A 高频周期/事件数据，和 GEM 的 S6F11/S16F1 作业事件，送到 EAP/数据总线，再分给 FDC（实时）、EDC 落历史、VM/R2R（批级）、SPC/YMS（统计）；高频连续量走 EDA，稀疏作业/状态事件走 GEM。下行控制——FDC 的 Hold 建议、R2R 的参数调整不直连设备，而是到 EAP/Host，经 GEM S2F41 远程命令/OSS S15 或经 RMS 版本校验后，通过 HSMS 下发给设备，由设备 FSM 合法迁移执行并回告。
5. **为何不能直写/正确链路**：设备执行动作必须经过其控制状态机、命令授权与安全联锁（W29 只读边界），FDC 只是一个数据分析方、经 EDA 只有只读通道，若允许它直写停机/Hold，就绕过了 GEM 控制面与联锁，多方都能改设备、不确定也不安全。正确链路：FDC 检出异常→按严重度产出告警/建议（必要时经规则与授权策略）→EAP/Host 决策（可结合设备/EAP/MES 状态）→经 GEM 远程命令下发 Hold/Stop→设备 FSM 执行、谁设谁解、经 S6F11/S5F1 回告。即 FDC 是"检测/建议方"，EAP/设备是"决策/执行方"，决策方≠执行方。
6. **EAP 三项交付/对应能力**：①拿得到——两套接口稳定、EDA 高频点与 GEM 事件齐全、授权订阅不丢关键量（对应 W27–W29 的建模/采集/双通道）；②对得齐——提供 Step/Recipe/Lot/Job 等事件 marker 与统一单调时钟、WKN 标准命名、单位质量码，让 FDC 能按工艺段切分 trace、VM/R2R 能关联上下文（对应同源事件出口、E125/E164）；③控得回——下行命令经 GEM 受控执行、受理≠生效、迁移后 S6F11 确认、Hold 谁设谁解（对应 GEM 控制状态机与 W29 控制面）。
7. **不同厂商如何集成**：靠标准接口 + 统一语义 + 主数据一致——设备侧用 SEMI 标准（SECS/GEM、EDA/Interface-A、GEM300）保证任何厂商设备都以标准方式出数/受控；用 E164 WKN 统一跨厂商变量语义、统一单位量纲；用统一的事件/上下文模型（Lot/Carrier/Job/Step/Recipe）与统一时钟对齐；配方/参数主数据由 RMS、工单由 MES 统一下发与对齐，系统间用契约化接口（订阅点表、频率、事件、回控命令）集成。标准让"不同厂商"在接口层可替换、可组合。

## 二、参考实现（net8.0）：CIM 交互矩阵

```csharp
namespace EapLab.Cim;
public enum Direction{ UpData,DownControl,Both }
public enum Channel{ Gem, Eda, Both, Internal }
public enum Timescale{ Realtime, PerRun, LongTerm, Static }
public sealed record CimLink(string From,string To,string What,Direction Dir,Channel Ch,Timescale Ts);

public sealed class CimTopology
{
    public List<CimLink> Links{get;}=new();
    public CimTopology Add(CimLink l){Links.Add(l);return this;}
    // 设备上行: 高频走EDA, 作业事件走GEM
    public IEnumerable<CimLink> Upstream=>Links.Where(l=>l.Dir!=Direction.DownControl);
    // 下行控制必须且只能经GEM(控制面), 不允许EDA下行写
    public IEnumerable<CimLink> Downstream=>Links.Where(l=>l.Dir!=Direction.UpData);
    public bool Valid => Downstream.All(l=>l.Ch is Channel.Gem or Channel.Internal); // 不变式: 控制不走EDA
    public IEnumerable<string> ConsumersOf(string what)=>Links.Where(l=>l.What.Contains(what)).Select(l=>l.To);
}

public static class FabCim
{
    public static CimTopology Build()=>new CimTopology()
      .Add(new("Equipment","FDC","高频trace/事件",Direction.UpData,Channel.Eda,Timescale.Realtime))
      .Add(new("Equipment","EAP","作业/报警事件",Direction.UpData,Channel.Gem,Timescale.Realtime))
      .Add(new("Equipment","EDC","全量数据落盘",Direction.UpData,Channel.Both,Timescale.LongTerm))
      .Add(new("FDC","EAP","Hold/Stop建议",Direction.DownControl,Channel.Internal,Timescale.Realtime))
      .Add(new("EAP","Equipment","远程命令Hold/参数",Direction.DownControl,Channel.Gem,Timescale.Realtime))
      .Add(new("Equipment","VM","过程特征",Direction.UpData,Channel.Eda,Timescale.PerRun))
      .Add(new("VM","R2R","预测量测",Direction.Both,Channel.Internal,Timescale.PerRun))
      .Add(new("R2R","RMS","下批参数overlay",Direction.DownControl,Channel.Internal,Timescale.PerRun))
      .Add(new("RMS","EAP","校验后配方/参数",Direction.DownControl,Channel.Internal,Timescale.PerRun))
      .Add(new("EDC","SPC","历史数据",Direction.UpData,Channel.Internal,Timescale.LongTerm))
      .Add(new("MES","EAP","工单/派工/Recipe上下文",Direction.DownControl,Channel.Gem,Timescale.Static));
}
```

### xUnit
```csharp
public class TopologyTests
{
    [Fact] public void 下行控制绝不走EDA()
    { Assert.True(FabCim.Build().Valid); }
    [Fact] public void 高频实时数据走EDA到FDC()
    { var t=FabCim.Build();Assert.Contains(t.Upstream,l=>l.To=="FDC"&&l.Ch==Channel.Eda&&l.Ts==Timescale.Realtime); }
    [Fact] public void R2R调整经RMS再到EAP_不直连设备()
    { var t=FabCim.Build();Assert.Contains(t.Downstream,l=>l.From=="R2R"&&l.To=="RMS");
      Assert.DoesNotContain(t.Links,l=>l.From=="R2R"&&l.To=="Equipment"); }
    [Fact] public void 控制回控最终经GEM到设备()
    { Assert.Contains(FabCim.Build().Downstream,l=>l.To=="Equipment"&&l.Ch==Channel.Gem); }
    [Fact] public void 非法EDA下行被不变式拦截()
    { var bad=FabCim.Build();bad.Add(new("FDC","Equipment","直写停机",Direction.DownControl,Channel.Eda,Timescale.Realtime));
      Assert.False(bad.Valid); }
}
```

## 三、CIM 全景交互（手绘参考，要求默画）
```
        MES(工单/派工/谱系/Recipe上下文)
          │ GEM/接口下发上下文
          ▼
设备 ◀═GEM/HSMS(控制: S2F41/S15, 稀疏事件S6F11)══▶ EAP/Host ──▶ RMS(配方版本)
  │  ▲                                            ▲   │            ▲
  │  └────────下行控制(决策≠执行, 只走GEM)────────┘   │ FDC建议/R2R overlay
  └═EDA/Interface-A(高频只读多客户端)═┬──────────────┘
        ▲              ▲             ▲
       FDC(实时)      VM(批级预测)   EDC(汇聚落盘)──SPC/YMS(长期统计)
        └ 异常告警/分类; R2R(批间, VM给预测→R2R算overlay→RMS校验→EAP→GEM)
时间尺度: FDC实时(秒) < R2R/VM逐批 < SPC长期; 数据由快到慢逐层汇聚
铁律: 上行高频走EDA/事件走GEM; 下行控制只走GEM(经EAP/RMS), EDA永不写
EAP职责: 拿得到(接口全) / 对得齐(marker+时钟+WKN) / 控得回(GEM受控执行回告)
```

## 四、今日易错点
1. 把 APC 当单一软件（它是 FDC/R2R/VM/SPC 一类能力统称）。
2. 混淆 APC 与设备毫秒级底层控制回路。
3. 英文全称记不牢（尤其 FDC/VM/ECN/EDC）。
4. 时间尺度错位（用 SPC 做实时检测、用 FDC 做批间优化）。
5. 让 FDC/R2R 直写设备（必须经 EAP/RMS→GEM，决策≠执行）。
6. 高频作业事件也全塞 GEM 或高频量全塞 GEM（连续量走 EDA、稀疏控制事件走 GEM）。
7. 忽视 Step/Recipe/Lot 上下文，导致 APC 无法分段/关联。
8. 以为单厂商整套才叫 CIM（CIM 是多子系统统称，可多厂商靠标准集成）。
