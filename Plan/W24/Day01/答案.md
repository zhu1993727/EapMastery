# W24 · Day01 答案与参考实现

## 一、自测题标准答案
1. **E116 解决什么 / 没有会怎样**：E116 用标准口径在设备端记录真实运行时间被花在哪些状态（加工、待机、故障、换型、维护、等待物料等），并带原因与作业上下文、标准化上报。没有它，设备/EAP/MES/厂务各用自定义口径统计利用率与停机，数字对不齐、无法比较机台、无法准确归因效率损失（到底是设备坏了、没料、还是在换型），产能规划、OEE、可靠性改进都失去可信原始数据。它是"设备时间账"的统一来源。
2. **四者分工**：E10 定义设备状态分类（这是什么状态，状态层次模型）；E116 定义性能状态如何随时间被跟踪、记录、上报（过程怎么记、带什么上下文）；E58 定义可靠性/可用性指标（MTBF、MTTR、可用率等）的口径与算法（用记录的数据算指标）；OEE 是上层工厂效率指标（可用率×性能率×良率），消费这些数据。一句话：E10 定状态、E116 记过程、E58/OEE 算指标。
3. **互斥完备 / 违反后果**：互斥=任意时刻恰好一个活动状态段，不能同时处于两个状态；完备=统计区间内时间无缝隙也无重叠，所有段时长之和恰等于总时长（时间守恒）。违反互斥（重叠）会让同一时间被重复计入两个状态（如既算生产又算故障），各状态占比之和超过 100%、利用率虚高或重复计损；违反完备（缝隙）会有时间不属于任何状态而丢失，各状态之和小于总时长、"时间去哪了"说不清。两者共同保证时间账闭合、指标可信。
4. **Segment 字段 / 原因码上下文**：至少含状态、开始时间、结束时间（时长=end-start）、原因码（进入该状态/停机的具体原因分类）、触发来源（作业事件/硬件/操作员/Host）、关联上下文（CjId/PjId/资源/载具）、是否计划内。原因码区分损失性质（等料是外部物流问题、故障是设备可靠性问题、换型/维护是计划或管理问题），决定改进责任方；关联作业让性能时间能和具体批次/工艺对齐，支持按产品/配方分析效率；没有上下文的"停机 X 分钟"无法指导改进。
5. **切换原子 / 时间相等**：进入新状态时必须先把当前活动段在 t 时刻闭合（end=t），同时在同一 t 开启新段（start=t），旧段结束时刻=新段开始时刻。这样相邻段首尾相接、既无缝隙也无重叠，时间轴连续闭合；若先结束后延迟开始会漏记一段（缝隙），若新段已开始旧段未结会重叠。切换必须是一个原子操作（同一时刻、成对、加锁），保证并发事件下仍只有一个活动段。
6. **单调时钟 vs 墙钟**：计时长要用单调递增时钟（monotonic，只增不回拨），因为系统墙钟（本地时间）会被 NTP 校时、手动改时、闰秒等向前/向后调整，若用它算时长，回拨会得到负时长或重复计时、前跳会虚增时长，状态段时长失真。正确做法：用单调时钟计算"持续了多少秒"（时长），用 UTC 墙钟只给每个事件点打"绝对时间戳"（便于跨系统对齐），两者分工；跨设备对齐再靠 NTP/PTP 时间同步。
7. **与 PJ/CJ 事件对齐 / 避免两本账**：性能状态段切换由设备真实的 PJ/CJ/硬件事件驱动，并复用 W22 的同源原则——同一事件（如 PJ 迁移 Executing）在同一时刻、经统一出口既推进作业状态机，又切换 EPT 状态段（进入 Productive），共用同一时间戳与权威状态快照。不允许性能账自己另搞一套轮询/缓存去推断状态。这样"作业在加工"的区间与"设备处于生产状态"的区间严格一致、成对闭合，不会出现作业说在跑、性能账记空闲的两本时间账。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Ept;
// 教学状态枚举(E10完整层次Day02展开, 此处用最小集搭机制)
public enum EqState{ Unknown, Productive, Standby, Engineering, ScheduledDown, UnscheduledDown }
public sealed record Segment(EqState State,double Start,double End,string Reason,
    string Source,string? CjId,string? PjId,bool Planned)
{ public double Dur=>End-Start; }

public sealed class EquipmentTimeModel
{
    private readonly List<Segment> _closed=new();
    private EqState _cur=EqState.Unknown; private double _curStart;
    private string _reason="",_source=""; private string? _cj,_pj; private bool _planned;
    public IReadOnlyList<Segment> Closed=>_closed;
    public EqState Current=>_cur;

    // t为单调时钟秒; 首次Enter即统计起点
    public void Enter(EqState s,double t,string reason,string source,string? cj=null,string? pj=null,bool planned=false)
    { lock(this)
      { if(_cur!=EqState.Unknown)
        { if(s==_cur)return;                      // 幂等: 已在该态不重开
          _closed.Add(new Segment(_cur,_curStart,t,_reason,_source,_cj,_pj,_planned)); }
        _cur=s;_curStart=t;_reason=reason;_source=source;_cj=cj;_pj=pj;_planned=planned; } }

    // 统计终点闭合
    public void Close(double t){lock(this){ if(_cur==EqState.Unknown)return;
        _closed.Add(new Segment(_cur,_curStart,t,_reason,_source,_cj,_pj,_planned));_cur=EqState.Unknown; }}

    public double TotalDur=>_closed.Sum(s=>s.Dur);
    public double DurOf(EqState s)=>_closed.Where(x=>x.State==s).Sum(x=>x.Dur);
    public bool TimeConserved(double horizon)=>Math.Abs(TotalDur-horizon)<1e-9;
    // 完备性: 相邻段首尾相接, 无缝无叠
    public bool Contiguous()
    { for(int i=1;i<_closed.Count;i++) if(Math.Abs(_closed[i].Start-_closed[i-1].End)>1e-9)return false;
      return !_closed.Any(s=>s.Dur<0); }
    public bool NoOverlap=>Contiguous();
}
```

### xUnit
```csharp
public class TimeModelTests
{
    [Fact] public void 切换首尾相接_时间守恒()
    { var m=new EquipmentTimeModel();
      m.Enter(EqState.Productive,0,"PJ_START","JOB",cj:"CJ1",pj:"A");
      m.Enter(EqState.UnscheduledDown,100,"CH_FAULT","HW");
      m.Enter(EqState.Productive,160,"RESUME","JOB");
      m.Close(300);
      Assert.True(m.Contiguous()); Assert.True(m.TimeConserved(300));
      Assert.Equal(240,m.DurOf(EqState.Productive)); Assert.Equal(60,m.DurOf(EqState.UnscheduledDown)); }
    [Fact] public void 同态重复Enter幂等_不开新段()
    { var m=new EquipmentTimeModel(); m.Enter(EqState.Standby,0,"IDLE","SYS");
      m.Enter(EqState.Standby,10,"IDLE","SYS"); m.Close(20);
      Assert.Single(m.Closed); Assert.Equal(20,m.Closed[0].Dur); }
    [Fact] public void 无缝隙_完备性检查()
    { var m=new EquipmentTimeModel();
      m.Enter(EqState.Productive,0,"s","x"); m.Enter(EqState.Standby,50,"s","x"); m.Close(120);
      Assert.True(m.Contiguous()); Assert.Equal(120,m.TotalDur); }
```

## 三、EPT 时间模型（手绘参考）
```
时间轴 ───────────────────────────────────────►
[Productive 0-100][UnscheduledDown 100-160][Productive 160-300]
 旧段end(t)==新段start(t): 无缝隙/无重叠; 任意时刻恰一段(互斥); 段和=总时长(完备)
Segment: state/start/end/reason/source/CjId/PjId/planned
时钟: 单调时钟算时长, UTC打绝对点, NTP/PTP对齐
驱动: PJ/CJ/硬件事件 → 统一出口同时推进作业FSM与EPT段(同源同戳)
分工: E10定状态 / E116记过程 / E58·OEE算指标
```

## 四、今日易错点
1. 混淆 E10（定状态）/E116（记过程）/E58/OEE（算指标）。
2. 状态段允许重叠（同时间双计）或有缝隙（漏记），时间不守恒。
3. 切换不是原子、旧段结束与新段开始时刻不一致。
4. 同态重复进入开新段（应幂等）。
5. 段不带原因码/作业上下文，停机无法归因、无法按批分析。
6. 用可回拨墙钟算时长（应用单调时钟，UTC 只打时间点）。
7. EPT 自己轮询推断状态、与作业 FSM 两本账（要同源事件驱动）。
8. 把"没料等待"当设备故障（状态/原因码必须区分外部与设备，影响可用率口径）。
