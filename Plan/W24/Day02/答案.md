# W24 · Day02 答案与参考实现

## 一、自测题标准答案
1. **E10 顶层分类树**：设备总时间先分 Non-Scheduled Time（未排产）与 Scheduled Time（已排产）。Scheduled Time 分 Uptime（能生产）与 Downtime（不能生产）。Uptime 分 Productive（在增值加工）与 Non-Productive（设备好但没增值加工：Standby 待机、Engineering 工程）。Downtime 分 Unscheduled Down（突发非计划：故障/异常/待修）与 Scheduled Down（事先计划：PM 保养、Setup 换型、配方切换、计划维护）。即：总时间→是否排产→能否生产→是否增值加工，逐层二分。
2. **Productive/Standby/Engineering 区别举例**：Productive=设备正在对片做增值工艺（刻蚀/沉积中，含加工必需的在线传片等辅助动作），如反应腔正在处理一批片；Standby=设备健康可用、但没有片/没有任务而空等，如等 AMHS 送料、等 Host 下 CJ、无载具的空闲；Engineering=设备可用但处于工程目的而非批量生产，如工程师做工艺验证跑片、调机、设备 qualification。三者设备都"没坏"，区别是 Productive 在增值量产、Engineering 在做工程活动、Standby 是什么都没做地等。
3. **计划 vs 非计划停机**：本质区别在"是否事先安排/预期"。Scheduled Down 是计划内、提前排程的不能生产时间，管理上可预期、不计入突发故障，如定期 PM 保养、换型 Setup、配方/载具切换、计划内校准；Unscheduled Down 是计划外突发、设备本应能生产却因故障/异常不能，如真空腔突发报警、机械手故障、等待维修备件，它直接打击可用率、是可靠性改进对象。两者时长在 OEE/可用率中归属不同，混用会掩盖真实故障水平。
4. **Non-Scheduled 为何不算可用率损失**：可用率衡量"在**计划应当生产的时间**里设备有多可用"。Non-Scheduled 是根本没排产（无订单、节假日、未排班、厂务停供导致整厂不安排），设备在这段时间本来就不被要求生产，因此不放进可用率的统计分母（Scheduled Time），自然不算设备自身的可用率损失——它是排产/经营层面的时间，不是设备可靠性问题。若把它当停机，会让设备为"没被安排干活"背锅，低估可用率且归因错误（W25 讲 OEE 口径时会再明确分母边界）。
5. **控制状态 vs 活动状态关系**：二者正交、回答不同问题。E30/GEM 控制状态描述设备是否被 Host 连接受控（On-Line/Off-Line）、由谁控制（Local/Remote）；E10 活动状态描述时间花在哪类活动（生产/待机/工程/停机）。它们组合描述现场：On-Line Remote+正在加工=Productive；On-Line+等料=Standby；Off-Line+工程师做 PM=Scheduled Down；On-Line+突发故障=Unscheduled Down；Local 下工程师跑片=Engineering。不能把 Off-Line 直接等于停机（离线可能在做计划保养，也可能只是通信断了但设备健康），也不能把 On-Line 直接等于生产（在线照样可能 Standby 等料）。
6. **在线无报警等料归类**：Standby（属于 Scheduled→Uptime→Non-Productive）。因为设备已排产、健康可生产（在线、无报警），只是没有料/任务而未进行增值加工，这是"等待外部输入"的待机，不是设备不能生产的故障，所以不是 Unscheduled Down。它反映的是物流/调度/上料环节的损失（可用 W23 的 WIP/等待指标定位），而不是设备可靠性损失。
7. **冲突时唯一归类优先级**：按"不能生产优先、增值与否其次"的顺序：①先判 Non-Scheduled（根本没排产→Non-Scheduled）；②已排产下，判是否不能生产——计划内不能生产→Scheduled Down，突发不能生产→Unscheduled Down（停机优先于一切"看起来在忙"的信号）；③能生产时，正在加工→Productive；④能生产、工程模式/工程跑片→Engineering；⑤能生产但没加工也非工程→Standby。即 Down > Productive > Engineering > Standby（在已排产且能生产的前提下细分），保证多信号同时存在时结果唯一、确定、可复现。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Ept;
public enum E10State{ NonScheduled, Productive, Standby, Engineering, ScheduledDown, UnscheduledDown }
public sealed class EquipmentSignals
{ public bool Scheduled;            // 是否排产
  public bool CanProduce;           // 物理上能否生产(无故障)
  public bool Processing;           // 是否正在加工
  public bool EngineeringMode;      // 工程模式/跑片
  public bool PlannedStop;          // 计划停机(PM/换型)
  public bool FaultStop; }          // 突发故障停机

public sealed class E10StateClassifier
{
    public E10State Classify(EquipmentSignals s)
    { if(!s.Scheduled)return E10State.NonScheduled;            // 未排产优先排除
      if(s.FaultStop || !s.CanProduce && !s.PlannedStop)
        return E10State.UnscheduledDown;                       // 突发不能生产
      if(s.PlannedStop)return E10State.ScheduledDown;          // 计划停机
      if(s.Processing)return E10State.Productive;              // 增值加工
      if(s.EngineeringMode)return E10State.Engineering;        // 工程活动
      return E10State.Standby; }                               // 可用但空等
}
```

```csharp
public class E10ClassifierTests
{ readonly E10StateClassifier _c=new();
    EquipmentSignals S(Action<EquipmentSignals>? init=null)
    { var s=new EquipmentSignals{Scheduled=true,CanProduce=true};init?.Invoke(s);return s; }
    [Fact] public void 加工中_Productive()=>Assert.Equal(E10State.Productive,_c.Classify.S(x=>x.Processing=true));
    [Fact] public void 在线无报警等料_Standby()=>Assert.Equal(E10State.Standby,_c.Classify.S());
    [Fact] public void 工程跑片_Engineering()=>Assert.Equal(E10State.Engineering,_c.Classify.S(x=>x.EngineeringMode=true));
    [Fact] public void 突发故障_UnscheduledDown()
    =>Assert.Equal(E10State.UnscheduledDown,_c.Classify.S(x=>{x.CanProduce=false;x.FaultStop=true;}));
    [Fact] public void PM保养_ScheduledDown()
    =>Assert.Equal(E10State.ScheduledDown,_c.Classify.S(x=>{x.CanProduce=false;x.PlannedStop=true;}));

    =>Assert.Equal(E10State.NonScheduled,_c.Classify(new EquipmentSignals{Scheduled=false}));
```

## 三、E10 分类树（手绘参考）
```
设备总时间
├ Non-Scheduled 未排产(无订单/节假日, 不进可用率分母)
└ Scheduled 已排产
   ├ Uptime 能生产
   │  ├ Productive 增值加工(含必要在线辅助)
   │  └ Non-Productive
   │     ├ Standby 待机(等料/等指令/无载具, 设备健康)
   │     └ Engineering 工程(跑片/调试/验证)
   └ Downtime 不能生产
      ├ Unscheduled Down 突发(故障/异常/待修) → 打可用率
      └ Scheduled Down 计划(PM/Setup换型/校准)
两轴: 计划轴(Scheduled与否, Down计划与否) + 增值轴(Productive vs 非)
正交: 控制状态(On/Off-Line, Local/Remote) ≠ 活动状态(E10)
优先级: NonScheduled → UnSchDown → SchDown → Productive → Engineering → Standby
```

## 四、今日易错点
1. 把等料 Standby 当故障停机（设备健康，是外部等待，非 Unscheduled Down）。
2. 把 PM/换型当非计划停机（属 Scheduled Down，可预期）。
3. 把 On-Line 等同生产、Off-Line 等同停机（控制状态与活动状态正交）。
4. Non-Scheduled 计入可用率损失（没排产不进分母，不是设备问题）。
5. 工程跑片误算 Productive 量产（属 Engineering）。
6. 多信号冲突无优先级、结果随机（按 Down>Productive>Engineering>Standby 唯一判定）。
7. 提示类报警（不影响生产）就切到 Down（只有真不能生产才停机）。
8. 忽略"加工必需的在线传片/对正"通常计入 Productive。
