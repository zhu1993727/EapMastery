# W24 · Day04 答案与参考实现

## 一、自测题标准答案
1. **状态迁移如何到 Host**：先定义 VID（如当前状态、from/to、原因码、段开始时间、累计各态时长），用 S2F33 把相关 VID 组成一个或多个 RPT，用 S2F35 把"状态迁移 CEID(7101)"关联到这些 RPT；运行时 EptCollector 一旦切段，就按关联关系取当前 VID 值组成报告快照，通过 S6F11 上报（DATAID + CEID + RPT[VID:值]）。Host 收到 7101 即知道设备从哪个 E10 状态迁到哪个状态、原因、时间点与累计时间账。
2. **VID/CEID 举例**：VID——当前 E10 状态码、状态名称、前一状态、进入时间戳、本段已持续、原因码、触发来源、关联 CjId/PjId、本班 Productive/Standby/UnscheduledDown/ScheduledDown 累计时长、累计加工片数。CEID——7101 E10 状态迁移、7102 班次开始、7103 班次结束（带汇总）、7104 非计划停机开始、7105 停机清除、7106 PM/Setup 计划停机开始结束、7107 工程模式进出。
3. **事件驱动 vs 周期快照**：状态段是稀疏的、只在状态真正变化时切换，事件驱动（变化即报）最准确、最省流量，也保证每段边界都有明确事件；高频周期上报会产生大量重复的"还是同一状态"消息且可能漏掉两次采样间的短暂切换。周期快照作为兜底：按较慢周期（如每分钟）报当前状态+累计时长，用于 Host 漏收事件后对账、看板刷新、检测通信静默（长时间无任何消息），它不替代边界事件，二者互补。
4. **S6F11/S16F1 同源**：状态段切换是一个事实，统一出口在切段成功的同一时刻从同一权威来源（EptCollector 的当前信号与 EquipmentTimeModel 的累计值）拍一份快照，用这份快照同时组装 GEM 的 S6F11（CEID+RPT/VID）和对象化通道的 S16F1（OBJSPEC+CEID+属性）。两通道引用同一份快照对象、同一时间戳，不各自重新查询/计算，保证"当前状态、累计时长、原因"完全一致（接 W22 同源原则）。
5. **快照何时取 / 为何**：必须在状态机/时间模型**切段成功之后**的同一时刻取——先让旧段闭合、新段状态确定（from/to、边界时间戳、更新后的累计），再对这个确定的新状态拍快照。若在切段前取，会报出旧状态或不一致的边界时间；若两通道在不同时刻各自取，中间若又有事件就会不一致。"先迁移、后对权威新状态拍快照、再统一发出"保证报文内容与设备真实状态严格对应。
6. **断线多次切换如何不丢不乱**：每次状态迁移的 S6F11/S16F1 都是已发生事实，断线期间进 Spool 队列按发生顺序缓存（带单调序号），重连后先补一个"当前状态+各态累计"快照做权威对账，再按序补发缓存事件，Host 按序号去重、按顺序应用、ACK 后设备删除；即使断线内经历 Productive→Down→Productive 多次切换，Host 也能按序重建完整状态段、并用对账快照校验累计时长，既不丢段也不乱序、不重复。
7. **班次汇总内容**：班次总时长与起止时间；各 E10 状态累计时长与占比（Productive/Standby/Engineering/ScheduledDown/UnscheduledDown/NonScheduled）；时间守恒校验（各段和=班次时长）；加工片数/完成 CJ 数；非计划停机次数、每次原因码与时长（MTTR 原料）、计划停机（PM/换型）次数时长；最长/平均待机段；关联的故障/维护记录；必要时初步可用率/利用率（Day05/W25 细化）。汇总即这一班的完整时间账，供 E58/OEE 与改善分析。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Ept.Report;
// VID 定义(教学)
public enum EptVid{ CurState,PrevState,ReasonCode,Source,CjId,PjId,SegStart,SegDur,
    AccProductive,AccStandby,AccEng,AccSchDown,AccUnschDown,WaferCount,UtcStamp }
public enum EptCeid{ StateChange=7101,ShiftStart=7102,ShiftEnd=7103,
    UnschDownBegin=7104,DownClear=7105,SchDown=7106,Engineering=7107,Heartbeat=7199 }

public sealed record EptSnapshot(E10State Cur,E10State Prev,string Reason,double At,
    IReadOnlyDictionary<EptVid,object> Vars);

public sealed class EptReporting
{
    public List<SecsMessage> Outbox{get;}=new(); private readonly Queue<SecsMessage> _spool=new();
    public bool LinkUp{get;set;}=true;
    // 切段成功后调用: 同一快照同时出 S6F11 与 S16F1
    public void OnStateChanged(EptSnapshot snap)
    { var gem=new SecsMessage("S6F11",snap); var oss=new SecsMessage("S16F1",snap);
      foreach(var m in new[]{gem,oss}){ if(LinkUp)Outbox.Add(m); else _spool.Enqueue(m); } }
    public void ShiftSummary(double total,IReadOnlyDictionary<E10State,double> by){/*组装7103*/}

    public List<SecsMessage> Reconnect(EptSnapshot curSnapshot)
    { LinkUp=true; var flush=_spool.ToList();_spool.Clear();
      flush.Insert(0,new SecsMessage("SNAPSHOT",curSnapshot)); // 先权威对账再按序补
      return flush; }
}
```

## 三、EPT 上报结构（手绘参考）
```
S2F33 定义: EptVid(状态/原因/段起止/各态累计/片数/UTC) → StateRpt
S2F35 关联: 7101状态迁移/7102班开始/7103班汇总/7104-7105停机/7106PM/7107工程 → RPT
运行: 切段成功 → 对权威新状态拍一份EptSnapshot
      → 统一出口同快照出 S6F11(GEM) + S16F1(OSS), 同时间戳
兜底: 慢周期 7199 当前态+累计(对账/静默检测), 不替代边界事件
可靠: 断线事件入Spool(带序号) → 重连先发当前快照对账 → 按序补发, Host去重, ACK删
班汇总7103: 各态时长占比/守恒/停机次数时长原因/片数 → E58/OEE原料
```

## 四、今日易错点
1. 不建 VID/RPT/CEID 关联就发裸数据（Host 无法解析，走 S2F33/35 标准定义）。
2. S6F11 与 S16F1 各自现算、快照不同步（必须同一份快照同时间戳）。
3. 在切段前取快照（报旧态/边界错，要迁移成功后取权威新态）。
4. 只用高频周期上报（漏短切换、流量浪费；边界事件为主、周期兜底）。
5. 断线性能事件直接丢弃（应 Spool，重连先对账再按序补）。
6. 重连不发当前快照对账（多段切换后累计无法校验）。
7. 班次不发汇总或汇总不做时间守恒校验。
8. CEID/VID 教学编号当固定标准（现场按 S2F33 实际定义，编号可规划，机制不变）。
