# W24 · Day03（周三）EPT 状态段采集器：把作业/硬件事件翻译成时间账

> 建议时长：90 分钟。今天把 Day01 的时间模型与 Day02 的 E10 状态分类接起来，实现一个自动采集器：订阅 E40/E94 作业事件、E87 载具事件、硬件/报警/维护信号，实时切换 E10 状态段，形成完整、闭合、可归因的设备时间账。

## 一、今日目标
1. 实现 EptCollector：订阅各类现场事件，经 E10StateClassifier 判定后驱动 EquipmentTimeModel 切段。
2. 建立"现场事件→信号变化→E10 状态"的映射表（作业/载具/故障/维护/排产）。
3. 保证同源：作业 FSM 事件与性能段切换共用事件、同时间戳（接 W22）。
4. 处理状态段的嵌套/瞬时事件（短暂报警不切段、加工中传片不切段）。
5. xUnit 覆盖一个完整上料-加工-等料-故障-恢复-下料周期的时间账正确性。

## 二、背景知识（先读，30 分钟）

### 1. 采集器的输入事件
- 作业事件（E40/E94）：PJ/CJ Started/Executing→生产；全部完成且无后续→待机；Paused→按原因（等 Host=Standby、故障=UnscheduledDown）。
- 载具事件（E87）：无任何 Loaded 载具且无作业→Standby（等料）；载具 Loaded 但作业未到→仍 Standby（等指令）。
- 硬件/报警：导致不能生产的故障→UnscheduledDown（带故障原因码）；恢复→回到应处状态。
- 维护/换型：PM/Setup 开始→ScheduledDown，结束→回 Standby/Productive。
- 排产信号：班次开始/结束→进入/退出 Scheduled（Non-Scheduled 段）。
- 工程模式：操作员/Host 切 Engineering→Engineering 段。

### 2. 事件→信号→状态的两段式
- 采集器不直接从事件跳到状态，而是先维护一份当前 EquipmentSignals（是否排产/能否生产/是否加工/工程/计划停/故障停），事件只改相关信号位；再由 Classifier 从完整信号集算出唯一 E10 状态。
- 好处：多事件叠加时（故障时恰好无料）状态由完整信号决定、与事件先后无关（同 W23 叠加异常思路），避免事件顺序耦合。

### 3. 同源与时间戳
- 采集器订阅的就是驱动作业 FSM 的同一批事件（统一事件总线），在同一处理时刻更新信号并切段，时间戳一致，杜绝两本账。
- 时长用单调时钟；事件带 UTC 时间点。

### 4. 瞬时/嵌套事件处理（难点）
- 短暂提示报警（不影响 CanProduce）：不改信号、不切段，只记录事件。
- 加工中的传片/对正：Processing 仍为真，保持 Productive（必要在线动作计入生产）。
- 故障中断加工：CanProduce=false+FaultStop→立刻切 UnscheduledDown（旧 Productive 段闭合），恢复后回到 Productive（若仍有在加工）或 Standby。
- 计划停机与故障同时：按 Day02 优先级，先确认是否真不能生产与计划属性，唯一归类。

### 5. 时间账的实时输出
- 任意时刻可查：当前状态、已累计各类时长、当前段已持续多久、状态切换历史。
- 为 Day04 上报、Day05 利用率/损失统计提供数据源。

### 6. 与 W23 仿真的对应
- W23 PerfMetrics 由仿真事件直接统计；真实设备的等价物就是 EptCollector——它产出的就是真实版 Makespan/生产/等待/故障时间，Day05 用它算真实利用率与损失。
