# W24 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何两段式**：若事件直接切状态，状态就依赖事件到达顺序——"故障开始"和"无料"两个事件先后不同会切出不同结果，叠加/恢复时极易出错，也难处理瞬时事件。两段式让事件只负责更新对应的信号位（CanProduce/Processing/PlannedStop 等），状态永远由 Classifier 对**当前完整信号集**做一次纯函数计算。这样多事件叠加的结果只取决于信号现状、与先后无关（和 W23 叠加异常正交合成同理），逻辑单一、可复现、好测试，也天然处理"恢复后该回到什么状态"（按现存信号重算，而不是记一堆返回路径）。
2. **六类事件/信号位**：①排产班开始/结束→Scheduled；②PJ/CJ Started/Executing→Processing=true，全部完成→Processing=false；③E87 载具 Loaded/Unloaded（影响"是否等料"，无载具且无作业→待机，通过信号综合体现）；④硬件故障/致命报警→CanProduce=false、FaultStop=true，故障消除→复位；⑤PM/Setup 换型开始/结束→PlannedStop=true/false、CanProduce 相应切换；⑥工程模式进入/退出→EngineeringMode=true/false。另可加 Paused 原因（等 Host vs 故障）映射到对应信号。
3. **故障到恢复的段序列**：加工中故障——当前 Productive 段在故障时刻闭合，立即开启 UnscheduledDown 段（带故障原因码，持续到修复），修复后信号重算：若该作业仍在、可继续加工则回到 Productive（新段），若无料/无作业则回 Standby。即 Productive(t0–t1) → UnscheduledDown(t1–t2) → Productive(t2–…)，三段首尾相接、时长守恒，故障段被精确量化且可归因。
4. **短报警/传片为何不切段**：提示类短报警不改变 CanProduce（设备仍能正常生产），不构成状态变化，只作为事件记录，若切段会凭空制造一段停机、虚降可用率；加工中的传片/对正是完成工艺的必要在线动作，Processing 仍为真、属于 Productive 的一部分，若切成 Standby 会把正常生产时间错误记成待机、低估生产时间。切段的唯一依据是 Classifier 算出的 E10 状态真的发生变化，瞬时/不改变信号的事件不满足这一条件。
5. **故障叠加无料**：按完整信号与优先级算——故障使 CanProduce=false、FaultStop=true，这是"不能生产"的更严状态，优先于"无料待机"，所以归 UnscheduledDown（设备本应可生产却坏了，等待修复期间即使本来也没料，仍记故障停机，因为故障是更根本的能力缺失）；等故障修复后，若无料无作业信号重算结果才是 Standby。即多条件并存取"最严/最根本"状态，避免把故障时间伪装成待机而漏掉可靠性问题。
6. **如何不两本账**：采集器与作业 FSM 挂在同一事件总线、订阅同一批领域事件（PJ/CJ Started、完成、Paused、故障、载具事件等），在同一事件处理时刻既推进作业状态机、又更新 EPT 信号并切段，共用同一单调时钟读数与时间戳（W22 同源原则）。EPT 不自己轮询、不另建状态推断，只消费权威领域事件。于是"作业 Executing 区间"与"Productive 段"严格同起同落，时间账与作业账天然对齐。
7. **查询口径**：当前段已持续=单调时钟 now − 当前段 start（EquipmentTimeModel 记录_curStart）；本班各类累计=对已闭合段按 E10 状态求和 DurOf(state)，再加上当前活动段的已持续时间（实时口径）。可提供 Snapshot(now) 返回当前状态、当前段时长、各状态累计、总时长、各占比，供上报与看板；闭合（班次结束 Close）后得到最终 immutable 时间账。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Ept;
public enum DomainEventKind{ ShiftStart,ShiftEnd,JobStart,JobFinish,CarrierLoaded,CarrierUnloaded,
                            FaultBegin,FaultClear,PmBegin,PmEnd,EngageEngineering,ExitEngineering,InfoAlarm }
public sealed record DomainEvent(DomainEventKind Kind,double At,string Reason="",string? Cj=null,string? Pj=null);

public sealed class EptCollector
{
    private readonly EquipmentSignals _s=new(){Scheduled=false,CanProduce=true};
    private readonly E10StateClassifier _clf=new(); private readonly EquipmentTimeModel _tm=new();
    private E10State _last=E10State.NonScheduled; private double _now;
    public IReadOnlyList<Segment> Segments=>_tm.Closed; public E10State Current=>_last;

    public void Handle(DomainEvent e)
    { _now=e.At;
      switch(e.Kind)
      { case DomainEventKind.ShiftStart:_s.Scheduled=true;break;
        case DomainEventKind.ShiftEnd:_s.Scheduled=false;_s.Processing=false;break;
        case DomainEventKind.JobStart:_s.Processing=true;break;
        case DomainEventKind.JobFinish:_s.Processing=false;break;
        case DomainEventKind.FaultBegin:_s.CanProduce=false;_s.FaultStop=true;break;
        case DomainEventKind.FaultClear:_s.CanProduce=true;_s.FaultStop=false;break;
        case DomainEventKind.PmBegin:_s.PlannedStop=true;_s.CanProduce=false;_s.Processing=false;break;
        case DomainEventKind.PmEnd:_s.PlannedStop=false;_s.CanProduce=true;break;
        case DomainEventKind.EngageEngineering:_s.EngineeringMode=true;_s.Processing=false;break;
        case DomainEventKind.ExitEngineering:_s.EngineeringMode=false;break;
        case DomainEventKind.InfoAlarm: /*不改信号, 不切段*/ break;
        // CarrierLoaded/Unloaded 不直接定状态(是否等料由Processing/有无作业综合, 教学略)
      }
      Reclassify(e); }

    void Reclassify(DomainEvent e)
    { var st=_clf.Classify(_s);
      if(st!=_last){_tm.Enter(st,_now,e.Reason,e.Kind.ToString(),e.Cj,e.Pj,e.Planned());_last=st;} }
    public void EndShift(double at){_now=at;_tm.Close(at);}
    public double Dur(E10State s)=>_tm.DurOf(s)+(Current==s?_now-_curStart:0);
    private double _curStart; // 简化: 由TimeModel内部持有, 教学从略
}
internal static class EvExt{ public static bool Planned(this DomainEvent e)=>e.Kind is DomainEventKind.PmBegin; }
```

### xUnit：完整周期
```csharp
public class EptCollectorTests
{
    [Fact] public void 上料加工故障恢复下料_时间账正确()
    { var c=new EptCollector(); double t=0;
      c.Handle(new(DomainEventKind.ShiftStart,t));                 // 0 排产开始→Standby
      c.Handle(new(DomainEventKind.CarrierLoaded,10));
      c.Handle(new(DomainEventKind.JobStart,20));                   // 20 Productive
      c.Handle(new(DomainEventKind.InfoAlarm,50));                  // 提示报警不切段
      c.Handle(new(DomainEventKind.FaultBegin,100,"CH_FAULT"));     // 100 UnscheduledDown
      c.Handle(new(DomainEventKind.FaultClear,160));                // 160 回Productive(作业仍在)
      c.Handle(new(DomainEventKind.JobFinish,260));                 // 260 Standby
      c.Handle(new(DomainEventKind.ShiftEnd,300)); c.EndShift(300);
      var states=c.Segments.Select(s=>s.State).ToList();
      Assert.Equal(E10State.Standby,states[0]);
      Assert.Contains(E10State.Productive,states);
      Assert.Contains(E10State.UnscheduledDown,states);
      // Productive: 20-100(80) + 160-260(100)=180; Down=60; Standby=20+40=60
      Assert.Equal(60,c.Segments.First(s=>s.State==E10State.UnscheduledDown).Dur);
      Assert.True(c.Segments.Zip(c.Segments.Skip(1),(a,b)=>Math.Abs(a.End-b.Start)<1e-9).All(x=>x)); }
    [Fact] public void 加工中传片保持Productive()
    { var c=new EptCollector();
      c.Handle(new(DomainEventKind.ShiftStart,0));c.Handle(new(DomainEventKind.JobStart,5));
      // 传片不产生DomainEvent切段(Processing一直true), 仅内部动作
      c.Handle(new(DomainEventKind.JobFinish,100));c.EndShift(100);
      Assert.Equal(95,c.Segments.Last(s=>s.State==E10State.Productive).Dur); }
    [Fact] public void 故障叠加无料_记UnscheduledDown()
    { var c=new EptCollector();c.Handle(new(DomainEventKind.ShiftStart,0)); // Standby
      c.Handle(new(DomainEventKind.FaultBegin,30,"X"));
      Assert.Equal(E10State.UnscheduledDown,c.Current); }
    [Fact] public void PM是ScheduledDown()
    { var c=new EptCollector();c.Handle(new(DomainEventKind.ShiftStart,0));
      c.Handle(new(DomainEventKind.JobStart,10));
      c.Handle(new(DomainEventKind.PmBegin,60));Assert.Equal(E10State.ScheduledDown,c.Current);
      c.Handle(new(DomainEventKind.PmEnd,120));c.Handle(new(DomainEventKind.JobFinish,130));
      Assert.Equal(E10State.Standby,c.Current); }
}
```

## 三、采集器数据流（手绘参考）
```
领域事件(作业E40/E94/载具E87/硬件报警/维护/排产)
   │ 同一事件总线, 同时推进作业FSM(同源同戳, 单调时钟)
   ▼ 只改信号位
EquipmentSignals{Scheduled,CanProduce,Processing,Engineering,PlannedStop,FaultStop}
   │ Classifier纯函数(与事件顺序无关, 多条件取最严)
   ▼ 状态真的变了才Enter切段(旧段end==新段start)
EquipmentTimeModel: 互斥完备状态段 + 原因码 + Cj/Pj上下文
查询: 当前段时长=now-curStart; 各类累计=已闭合DurOf+当前段; Snapshot占比
不切段: 提示类报警/加工中传片(信号不变); 故障即时切Down, 恢复按现存信号回态
```

## 四、今日易错点
1. 事件直接切状态（顺序耦合，应事件改信号、分类器算状态）。
2. 自建轮询推断状态、与作业 FSM 两本账（订阅同一事件总线、同源同戳）。
3. 提示类短报警也切停机段（虚降可用率）。
4. 加工中传片/对正切成 Standby（必要在线动作属 Productive）。
5. 故障恢复后写死回 Productive（应按现存信号重算，可能回 Standby）。
6. 故障叠加无料记成 Standby（故障更根本，记 UnscheduledDown）。
7. 切段时旧段不闭合/时间戳不一致（缝隙或重叠，时间不守恒）。
8. 段不带原因码/作业上下文，后续无法按故障类型/批次归因。
