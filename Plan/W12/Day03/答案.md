# W12 · Day03 答案

## 一、自测题标准答案
1. **LoadPort 状态 vs Carrier 状态 / 对应关系**：LoadPort 状态描述"工位本身"能不能用、有没有被占用（DISABLED 禁用维护 / ENABLED 可用，可用下分 EMPTY 空、OCCUPIED 占用、FAULT 故障）；Carrier 状态描述"盒子"的生命周期（NOT_INSTALLED/INSTALLED/LOADED/UNLOADED）。二者是 1:1 关联但不同对象：一个 LoadPort 同一时刻最多一个 Carrier。对应关系：LP_EMPTY ↔ Carrier NOT_INSTALLED（口空无盒）；LP_OCCUPIED ↔ Carrier 处于 INSTALLED/LOADED/UNLOADED 之一（口被占，盒在走自己的生命周期）。口禁用/故障是工位维度，会冻结其上盒状态的推进，但不等于盒状态本身。编程时要把"口对象"和"当前载具对象"分开建模，不能用一个字段混表达。

2. **预约完整生命周期**：①**下预约**：Host 派工前向设备下发（LoadPortID+预期 CarrierID，可带 LotID/操作类型/预计到达），口由 UNRESERVED→RESERVED 并记录期望 ID；②**预约保持**：口空但被保留，等待对应 FOUP，期间不为其他 Carrier 授权、不被别的盒占用；③**上料匹配**：物理上料读到实际 ID，与期望 ID 校验；④**预约兑现**：匹配成功并授权 LOADED 后，该预约被消耗兑现；旁支：⑤**取消**：盒到之前 Host 可取消，口回 UNRESERVED 可重新调度；⑥**超时未到**：预约后长期无对应盒，设备上报预约超时，Host 决定续等/取消/改派，避免口被空占；⑦**下料预约**：取走也可预约预期取走的 ID，防取错盒。

3. **校验三分支及处理**：
   - **匹配 ID_OK**：口已预约且实际 CarrierID==期望 ID（类型/Lot 等联动也一致）→校验通过，具备授权前提，Host 授权后进 LOADED 可加工。
   - **不匹配 MISMATCH**：口已预约但实际 ID≠期望 ID（上错盒/送错口）→防错料拦截：不授权、停留 INSTALLED、置 Hold、声光/上报报警，禁止开门取片，等待取走或改派，绝不加工。
   - **无预约/读不到 NO_RESERVATION / ID_UNREADABLE**：口根本没预约（计划外来盒），或 RFID 多次重试仍读不到 ID（标签损坏/读写器故障）→全自动线默认 Hold、不自动加工，上报由 Host/人工裁决；手动/维护模式经有权限人员核对 MES 后可人工确认放行，但必须记录操作人、时间、原因，留痕可追溯。

4. **为何必须在 LOADED 前拦截 / 先加工再发现的后果**：LOADED 是唯一允许开门取片、ProcessJob 加工的状态，拦截在授权之前等于在"物理上还没碰盒内晶圆"时就挡住错误。若先加工再发现 ID 不符：设备已经按错误配方/错误工艺对错误批次的晶圆做了处理，造成①整批晶圆报废或工艺污染，②错误的片可能被放回错误 FOUP、污染后续整条工艺路线，③设备腔体可能需要清洗/验证才能恢复，④全自动无人线没有人工及时发现，错误会向下游扩散。半导体单批价值极高且污染不可逆，必须把错误挡在"任何加工动作发生之前"，这就是防错（poka-yoke）在载具准入上的体现——宁可停线等确认，也不能赌它是对的。

5. **预期/现实/对齐点**：**预期来自 MES/Host 的派工与预约**（这个口该来哪个 CarrierID、属于哪个 Lot、走什么工艺、用什么配方，是计划侧）；**现实来自设备物理读取**（E84 在位传感器确认盒到了、LoadPort RFID 实际读到的 CarrierID、类型，是物理侧）；**对齐点在设备端 E87 的上料校验**（INSTALLED 之后、Host 授权 LOADED 之前），把实际读到的物理 ID 与该口预约的期望 ID 强制比对，一致才放行、不一致就 Hold。这是 MES 计划在设备末端的"最后一道物理执行校验"，保证信息流和物料流严格一致。

6. **多口并行最需防止的错误**：最需要防止**载具与口位张冠李戴（ID 与 LoadPortID 绑定错误/串口）**——即把 LP2 读到的 CarrierID 当成 LP1 的上报，或预约/授权发错口。多口各自独立状态机、同时处于不同阶段，一旦上报时 CarrierID 和 LoadPortID 对应错，Host 就会给错盒授权、用错工艺，等于防错料机制被自己破坏。实现上必须：每个 LoadPort 独立持有自己的传感器读取、预约记录、Carrier 对象和状态机，上报事件强制携带正确的 LoadPortID，严禁用共享变量/数组下标错位串口感知；测试要专门构造"两口同时上料、交错读到不同 ID"的用例验证不串。其次防口被重复预约、未预约口被占用等。

7. **读不到 ID 时自动线 vs 手动 / 手动放行为何留痕**：全自动线无人值守，读不到 ID 意味着无法确认盒子身份、无法和 MES 计划对齐，按"身份不明不加工"原则自动 Hold、不授权、上报，等待人工或重新读取/换口，绝不让身份不明的盒流入加工。手动/维护模式下，允许有权限的操作员对照 MES 和实物标签人工确认身份后手动放行（处理 RFID 故障等例外，避免无谓停线）。手动放行必须留痕（操作人、时间、口位、实物 ID、核对依据、原因）是因为：这一步绕过了自动防错校验，属于"人为承担正确性责任"的例外操作，半导体要求全程可追溯，一旦这批货后续出问题，必须能查到是谁、依据什么放行的；同时留痕也用于统计 RFID 故障率、发现标签/读写器隐患，防止手动放行被滥用成常态而使防错体系形同虚设。

## 二、LoadPort 状态机 + 预约生命周期（手绘参考）
```
LoadPort:
 DISABLED ◄─维护/禁用─► ENABLED
 ENABLED: EMPTY ──在位ON──► OCCUPIED ──在位OFF──► EMPTY
            ▲                  │ 其上 Carrier: INSTALLED→LOADED→UNLOADED
            └──────────────────┘
 任意 ──故障──► FAULT(冻结推进/拒绝交接/报警) ──复位──► EMPTY/DISABLED
预约(挂在口上):
 (EMPTY,UNRESERVED) ─Host预约(预期ID)─► RESERVED(等待对应盒)
   RESERVED ─上料匹配成功+授权─► 预约兑现(消耗)
   RESERVED ─Host取消(盒未到)─► UNRESERVED
   RESERVED ─长期无盒─► 预约超时上报(续等/取消/改派)
```

## 三、防错料判定真值表（参考答案）
| 口预约 | 实际读取 | 读取成功 | 结论 | 动作 |
|---|---|---|---|---|
| 有，预期A | A | 成功 | 匹配 ID_OK | 可授权→LOADED |
| 有，预期A | B | 成功 | 不匹配 MISMATCH | Hold/报警/禁开门 |
| 有，预期A | 读不到 | 失败 | ID_UNREADABLE | Hold/重试/人工 |
| 无 | A | 成功 | 无预约 NO_RESV | 自动线Hold；手动可确认放行(留痕) |
| 无 | 读不到 | 失败 | 无预约+读不到 | Hold，人工核对 |
| 有预期A，类型也校验 | A但类型错 | 成功 | 类型不符 | 视同不匹配，拦截 |

## 四、三个现场案例推演（参考答案）
### 案例1 送错盒（LP1 预约 FOUP-A，天车送来 FOUP-B）
E84 放稳→在位 ON→INSTALLED→RFID 读到 B→比对预约期望 A，不匹配→校验失败：不授权、停留 INSTALLED、置 Hold、上报"载具 ID 不匹配，期望 A 实际 B"、报警提示操作员/AMHS→禁止开门取片→Host 通知 AMHS 把 B 取走、重新调度 A 到 LP1。全程不加工。
### 案例2 RFID 读不出
放稳→INSTALLED→RFID 连续重试（如 3 次）仍失败→ID_UNREADABLE：不授权、Hold、上报读写失败并提示（标签损坏/读写器故障/盒放置偏移）→自动线等待：可提示重新放置/换口重读，仍失败则人工；手动模式有权限人员核对实物标签与 MES 后手动输入 ID 放行并留痕；读写器故障则报修。
### 案例3 盒送到没预约的邻口（LP2 无预约，盒被放到 LP2）
LP2 在位 ON→INSTALLED→读到 ID 但该口 UNRESERVED 无预约→NO_RESERVATION：自动线不授权、Hold、上报"计划外载具/未预约口上料"，同时不会错误地拿 LP1 的预约去匹配（预约绑定口位，不跨口借用）→Host 核对：是调度送错口则让 AMHS 转运到正确口 LP1，或补建预约（经规则允许）后再校验授权。关键：预约和口绑定，不能"A 的预约拿去放行 B 口上的盒"。

## 五、今日易错点
1. 用一个字段混表达 LoadPort 状态和 Carrier 状态（工位 vs 盒，分开建模、1:1 关联）。
2. 以为预约是上料后补登记（先进 FAB 先预约后上料、上料即校验）。
3. 只比 ID 不比对类型/Lot/口位（防错料应多维联动）。
4. 预约跨口借用（A 口预约不能放行 B 口的盒，预约绑定 LoadPortID）。
5. 多口并发时 CarrierID 与 LoadPortID 绑定错位/串口感知（严重，需独立状态机+专测）。
6. ID 读不到就默认放行（自动线必须 Hold，手动放行要权限+留痕）。
7. 忽略预约超时和取消（口会被长期空占，影响调度）。
8. 不匹配还先开门看看（拦截必须发生在任何盒内访问之前）。
