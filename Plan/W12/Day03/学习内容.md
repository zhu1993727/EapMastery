## 二、背景知识（先读，30 分钟）

### 1. LoadPort 工位状态机
LoadPort 是物理工位，独立于其上的 Carrier，教学状态：
```
LP_DISABLED(禁用/维护) ◄─启用/维护结束─► LP_ENABLED(启用可用)
LP_ENABLED:
   LP_EMPTY(口空,可被预约/可Deposit)
      │ 上料(在位ON) → LP_OCCUPIED(口被占用,其上Carrier走自己的状态机)
      │ 下料(在位OFF)→ LP_EMPTY
   口故障 → LP_FAULT(故障,拒绝交接/推进,报警)
```
- 口状态回答"这个工位能不能用、有没有盒"；盒状态回答"盒处于生命周期哪一步"。
- LP_EMPTY 时 Carrier 为 NOT_INSTALLED；LP_OCCUPIED 时 Carrier 在 INSTALLED/LOADED/UNLOADED 之一。
- 口禁用/故障时：不接受新预约、不响应 E84 自动交接、其上载具状态推进被冻结。

### 2. 预约（Reservation）全流程
- **下预约**：Host 在派工前向设备下发：LoadPortID + 预期 CarrierID（可能还带 LotID、预计到达、操作类型 上料/下料）。设备把该口置 RESERVED 并记录期望 ID。
- **预约保持**：口空但已预约，等待对应 FOUP 到来；期间该口一般不为其他 Carrier 授权（防止占口）。
- **上料匹配**：物理上料、读到实际 ID，与该口预约期望 ID 比对（核心，见第 3 节）。
- **预约兑现**：匹配并授权 LOADED 后，该预约被"消耗/兑现"。
- **取消预约**：Host 可在盒未到前取消（RESERVED→UNRESERVED），口回到可调度。
- **预约超时**：预约后长时间没有对应盒到达，设备可上报超时，由 Host 决定续等/取消/改派，避免口被长期空占。
- **下料预约**：取走也可能有预约（预期取走哪个 ID），防止取错盒。

### 3. CarrierID 读取与校验三分支
- 读取：FOUP 坐实后，LoadPort 的 RFID 读写器读标签（也支持条码扫描/操作员手动输入兜底）。读取时机=INSTALLED 后、授权前。读取结果：成功得到 ID / 读失败（标签损坏、读写器故障、多次重试仍失败）。
- 校验三分支：
  1. **匹配（ID_OK）**：口已预约 且 实际ID==期望ID → 校验通过，可授权 LOADED。
  2. **不匹配（MISMATCH）**：口已预约 但 实际ID≠期望ID → 防错料拦截，不授权、Hold、报警上报（上错盒/上错口）。
  3. **无预约/读不到（NO_RESERVATION / ID_UNREADABLE）**：口未预约，或 ID 读不出来 → 按策略：全自动线 Hold 等人工/MES；手动模式可人工核对后放行（要留痕、要权限）。
- 校验不仅比 CarrierID，先进 FAB 还会联动核对：CarrierType（盒类型对不对）、LotID、工艺路线/目标设备、SlotMap 与 MES 预期是否一致（E90 配合）。

### 4. 防错料闭环（Reservation-based interlock）
```
Host派工 → 给LP1预约预期ID=FOUP-A
天车送盒 → E84 Deposit → 在位ON → 读实际ID
   ├─实际==FOUP-A → 校验通过 → Host授权 → LOADED → 可加工
   ├─实际==FOUP-B → 不匹配 → Hold+报警 → 禁止开门取片 → 等处理(取走/改派)
   └─读不到ID    → 读失败 → Hold/人工确认 → 不自动加工
```
- 核心思想：**"预期（MES 计划）"与"现实（物理读到）"在设备末端强制对齐**，不一致就物理上禁止访问盒内晶圆，把错误挡在加工之前。

### 5. 多口并行与优先级
- 一台设备多个 LoadPort 各自独立状态机、独立预约，可同时处于不同阶段（LP1 LOADED 加工中、LP2 EMPTY 已预约、LP3 INSTALLED 待授权）。
- Host 决定口预约与加工优先级；设备要保证状态上报准确、不串口（CarrierID 必须和正确的 LoadPortID 绑定上报，张冠李戴是严重 bug）。
- 口被预约但盒未到时，调度不会让别的盒占用该口；盒到错口（送到没预约/预约别的 ID 的口）即触发不匹配。
