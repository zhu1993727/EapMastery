## 二、背景知识（先读，30 分钟）

### 1. 对象建模（复用 W09/W10）
- 对象类型：`LoadPort`（属性 LPID、LPState、ReservationID、CurrentCarrier）、`Carrier`（属性 CarrierID、CarrierState、CarrierType、LotID、LoadPortID、VerifyState；方法 Reserve/AuthorizeLoad/Unload/CancelReservation；事件 Installed/Loaded/Unloaded/Removed）。
- OBJSPEC：`LoadPort:LP1`、`Carrier:FOUP-A`，Carrier 用属性 LoadPortID 关联到口（或对象树挂口下，按实现）。

### 2. OSS 完整时序（主线，教学时序）
```
【0 预约（盒未到）】
Host→设备 S15F9 对 LoadPort:LP1 调方法 Reserve(ExpectedCarrierID=FOUP-A, LotID=LOT1)
设备→Host S15F10 ACKC=0（方法被接受；异步执行）
设备内部 LP1 置 RESERVED；（可选）S16F1 LoadPort:LP1 事件"已预约"

【1 物理就位（E84 Deposit 完成）】
(硬件)在位传感器ON → 设备读RFID得 FOUP-A → 创建/更新 Carrier:FOUP-A
设备→Host S16F1：Carrier:FOUP-A 事件 Installed（快照:CarrierID,LoadPortID=LP1,CarrierState=INSTALLED）
Host→设备 S16F2 确认

【2 Host 校验 + 授权】
Host 侧比对预约(LP1预期FOUP-A)与上报实际ID → 一致
Host→设备 S15F9 对 Carrier:FOUP-A 调 AuthorizeLoad()
设备→Host S15F10 ACKC=0（接受）
设备内部校验守卫(预约匹配∧校验通过∧口正常)通过 → Carrier: INSTALLED→LOADED
设备→Host S16F1 事件 Loaded（CarrierState=LOADED）← 真正"可加工"以这条事件为准
Host→设备 S16F2

【3 加工访问（LOADED 期间，W16+ 详讲）】
Host 建 ProcessJob 取放片加工（E40/E94），Carrier 保持 LOADED

【4 卸载（加工完）】
Host→设备 S15F9 对 Carrier:FOUP-A 调 Unload()
设备→Host S15F10 ACKC=0
设备守卫:所有PJ结束∧片归位∧门已关 → LOADED→UNLOADED
设备→Host S16F1 事件 Unloaded（CarrierState=UNLOADED）

【5 物理移除（E84 Pickup 完成）】
(硬件)在位OFF → Carrier: UNLOADED→NOT_INSTALLED，释放LP1
设备→Host S16F1 事件 Removed（LP1 已空），随后可删除/归档 Carrier 实例
Host→设备 S16F2
```

### 3. 异步完成模型（关键，复用 W07/W09 结论）
- S15F10 ACKC=0 只表示"方法请求被接受、参数合法"，**不代表状态已经迁移完成**；真正完成以随后的 S16F1 状态事件为准。
- 若守卫不满足（如预约不匹配），S15F10 直接回非 0 错误码（如 8 状态非法），或接受后异步拒绝并发异常事件，两种实现都要认识。
- 这与 GEM 的 S2F42 ACKC10=0 后靠 S6F11 报完成是同一异步思想。

### 4. 传统 GEM 等价表达（老设备要能看懂）
| 语义 | OSS（主线） | 传统 GEM |
|---|---|---|
| 预约某口 | S15F9 LoadPort.Reserve | S2F41 RCMD="ReserveCarrier"，CP=LoadPortID,CarrierID |
| 载具安装上报 | S16F1 Carrier.Installed | S6F11 CEID=载具安装，报告含 CarrierID/LPID（先 S2F33/35 定义） |
| 授权装载 | S15F9 Carrier.AuthorizeLoad | S2F41 RCMD="LoadCarrier"/"Access"，CP=CarrierID,AccessMode |
| 装载完成上报 | S16F1 Loaded | S6F11 CEID=载具Loaded |
| 卸载 | S15F9 Unload | S2F41 RCMD="UnloadCarrier" |
| 移除上报 | S16F1 Removed | S6F11 CEID=载具Removed |
| 查询状态 | S15F5 读属性 | S1F3/S1F4 读 SVID |
- GEM 方式事件要先用 S2F33 定义报告、S2F35 关联 CEID，远程命令回 S2F42 ACKC10。

### 5. 双向协同的本质
- **设备主动报"物理事实"**（就位/移除等传感器驱动事件，S16F1/S6F11）。
- **Host 主动下"逻辑决策"**（预约/授权/卸载，S15F9/S2F41）。
- 状态迁移 = 物理事实 + Host 决策 + 内部守卫 三者齐备。设备不能没授权自说自话 LOADED，Host 也不能在物理没就位时空授权——这就是软件层的"双边互锁"，和 E84 硬互锁思想对应。

### 6. 断线与重发（复用 W08 Spool）
- Installed/Loaded/Unloaded/Removed 都是关键状态事件，通信中断时进 Spool 缓存，恢复后按序重发、Host 确认后删除，防止 Host 漏失载具状态导致账实不符。
- Host 重连后可用 S15F5/S1F3 主动全量查询各口当前 Carrier 状态做对账（reconciliation）。
