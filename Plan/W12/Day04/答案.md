# W12 · Day04 答案

## 一、自测题标准答案
1. **完整 OSS 消息序列（上料→加工→下料）**：
   - 阶段0 预约（盒未到）：Host→设备 S15F9 对 `LoadPort:LP1` 调 Reserve(ExpectedCarrierID=FOUP-A,LotID)；设备 S15F10 ACKC=0 接受，口置 RESERVED。
   - 阶段1 物理就位：E84 Deposit→在位 ON→读 RFID→设备 S16F1 上报 `Carrier:FOUP-A` Installed（快照 CarrierID/LoadPortID=LP1/State=INSTALLED）；Host S16F2 确认。
   - 阶段2 校验授权：Host 比对预约与实际 ID 一致→S15F9 对 Carrier 调 AuthorizeLoad；S15F10 ACKC=0；设备守卫通过，INSTALLED→LOADED；S16F1 上报 Loaded（State=LOADED）。
   - 阶段3 加工：LOADED 期间 Host 建 ProcessJob/ControlJob 取放片加工，载具保持 LOADED。
   - 阶段4 卸载：加工完 Host S15F9 调 Unload；S15F10=0；守卫（PJ 全结束、片归位、门关）通过，LOADED→UNLOADED；S16F1 上报 Unloaded。
   - 阶段5 移除：E84 Pickup→在位 OFF→UNLOADED→NOT_INSTALLED、释放 LP1；S16F1 上报 Removed；Host 确认，设备归档 Carrier 实例。

2. **S15F10 ACKC=0 与 S16F1 Loaded 的区别 / 为何分两条**：S15F10 ACKC=0 是对方法调用的**同步应答**，只表示"请求收到了、方法存在、参数类型合法、当前允许尝试"，属于接受层；它在状态真正改变之前就返回。S16F1 Loaded 是**状态迁移完成后的异步事件**，表示内部状态机经过守卫校验、已经实际从 INSTALLED 迁到 LOADED、开放了访问。分两条是因为"接受请求"和"完成状态迁移"在时间和因果上是两件事：接受后还要执行内部校验和动作（可能失败、可能需要机械动作时间），Host 必须以 Loaded 事件作为"真正可加工"的唯一权威依据，不能收到 ACKC=0 就以为可加工，否则会在还没 LOADED 时下发取片任务被拒/出错。这与 GEM 的 S2F42 ACKC10=0 后靠 S6F11 报完成是同一异步模型。

3. **Installed 触发源 / AuthorizeLoad 前提**：Installed 由**物理事件**触发——E84 Deposit 硬握手完成、LoadPort 在位传感器稳定 ON、RFID 读到 CarrierID，设备据此创建/更新 Carrier 对象并发 Installed 事件（不是 Host 让它安装的）。AuthorizeLoad 的前提检查（守卫）：①该 Carrier 处于 INSTALLED（物理在位、已上报）；②其所在 LoadPort 有预约且预约期望 ID==实际 CarrierID（校验通过，VerifyState=通过）；③CarrierType/Lot 等联动信息一致；④LoadPort 无故障、处于可用；⑤访问模式允许自动访问。任一不满足则拒绝授权（S15F10 非 0 或异步失败事件），停留 INSTALLED/Hold。

4. **传统 GEM 等价表达**：
   - 预约：S2F41 RCMD="ReserveCarrier"，CPNAME/CPVALUE 带 LoadPortID、预期 CarrierID；设备回 S2F42 ACKC10。
   - 安装上报：S6F11 载具安装 CEID，其报告（需先 S2F33 定义、S2F35 关联）含 CarrierID、LoadPortID 等 VID。
   - 授权装载：S2F41 RCMD="LoadCarrier"/"SetAccess"，CP 带 CarrierID、AccessMode=自动。
   - 装载完成：S6F11 载具 Loaded CEID。
   - 卸载：S2F41 RCMD="UnloadCarrier"；卸载完成 S6F11 Unloaded CEID。
   - 移除：S6F11 Removed CEID。
   - 查询状态：S1F3 请求 SVID、S1F4 返回（替代 S15F5 读属性）。
   区别：OSS 以对象为中心、自描述、可订阅；GEM 以预定义事件报告/远程命令为中心，要先配置报告事件链路，两套语义等价都要能读懂。

5. **软件层双边互锁 / 设备能否自己 LOADED**：E87 的每次关键状态迁移都需要两侧各出一半条件：设备掌握"物理事实"（传感器在位、读到 ID）并主动上报，Host 掌握"逻辑决策"（预约、工艺计划、授权）并主动下发，再加设备内部守卫，三者齐备才迁移。设备**不能**自己检测到盒子就直接进 LOADED——它只能到 INSTALLED 并上报，必须等 Host 的 AuthorizeLoad，因为"该不该加工这个盒"是 MES 计划决策，设备无权自行决定；反过来 Host 也不能对物理没就位的口空授权（没有 Carrier 对象/不在 INSTALDED，守卫拒绝）。这种"物理由设备、决策在 Host、互相等待确认"就是软件层双边互锁，和 E84 硬线"双方信号都满足才动作"同构，只是从电平搬到了消息。

6. **断线不丢 / 重连对账**：载具四态事件（Installed/Loaded/Unloaded/Removed）是影响 MES 账目的关键事件，通信中断时按 W08 Spool 机制落盘缓存，恢复 HSMS 后按时间顺序重发，Host 逐条回 S16F2（或 GEM 的 S6F12）确认后才删除，保证 Host 不漏任何一次载具状态变化、顺序不乱。重连后为防止缓存期间状态判断偏差，Host 可主动用 S15F5（或 S1F3/S1F4）全量查询每个 LoadPort 当前 CarrierID、CarrierState、VerifyState 做一次对账（reconciliation），以设备当前真实状态为准刷新 Host 侧镜像，发现不一致（Host 以为 LOADED、实际已被取走）立即纠正并告警。关键状态事件可靠重发 + 重连全量对账，双保险保证账实一致。

7. **对没就位的口发 AuthorizeLoad 怎么响应**：设备在方法执行时查守卫——该 LoadPort 在位传感器 OFF、没有处于 INSTALLED 的 Carrier 对象（物理没就位），不满足"必须先 INSTALLED"的前置条件，应拒绝：S15F10 回非 0 ACKC（如状态非法/实例不存在），不做任何状态迁移、不创建虚假 LOADED，并可上报告警"对未就位载具授权"。这体现状态机非法迁移零副作用（W10 通用 FSM 原则）和双边互锁——Host 决策必须建立在设备真实物理状态之上，不能凭空授权。设备也可在拒绝应答里带回口当前状态，帮助 Host 重新同步。

## 三、OSS ↔ GEM 等价对照（参考答案）

| 预约口 | S15F9 LoadPort.Reserve | S2F41 ReserveCarrier | S15F10 / S2F42 | 状态/事件 |
| 安装上报 | S16F1 Installed | S6F11 安装CEID | S16F2 / S6F12 | 事件本身 |

| 查状态 | S15F5 读属性 | S1F3/F4 读 SVID | — | 返回值 |

## 四、今日易错点
1. 把 S15F10 ACKC=0 当成已 LOADED（接受≠完成，以 S16F1 Loaded 为准）。
2. 设备检测到盒就自己 LOADED（必须到 INSTALLED 并等 Host 授权）。
3. Host 对没就位的口授权（守卫拒绝，非法迁移零副作用）。
4. 混淆物理触发（设备报）与逻辑决策（Host 下）的方向。
5. 只懂 OSS 看不懂 GEM 的 S6F11+S2F41 等价表达（事件还需 S2F33/35 预定义）。
6. 关键载具事件不走 Spool（断线丢事件会导致 Host 账目错误）。
7. 重连不做全量对账（缓存/错位期间可能状态偏差，需 S15F5/S1F3 对账）。
8. Unload 不看 PJ 是否结束就迁 UNLOADED（在途片会丢，必须守卫）。
9. 事件快照不带 LoadPortID（多口会串行，必须口位+ID 绑定）。
