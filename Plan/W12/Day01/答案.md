# W12 · Day01 答案

## 一、自测题标准答案
1. **E87 解决什么 / 5 类核心对象**：E87（CMS 载具管理标准）解决载具（FOUP/光罩盒）在设备 Load Port 上的逻辑生命周期与准入控制——哪个口有没有盒、盒子是谁、是否被预约授权、处于什么可操作状态、盒内载料情况，从而防错料、防未授权加工、保证物料流与 MES 账实一致、支撑全自动上料。五类核心对象：①**Carrier**（载具本身，含 CarrierID/类型/所在口/状态）；②**LoadPort**（装载口工位，含口状态/当前载具/预约）；③**CarrierID**（载具唯一标识，RFID/条码读出，绑定 Lot/配方/路线）；④**Reservation**（预约，Host 预先指定某口预期的 CarrierID）；⑤**SlotMap**（槽位图，与 E90 配合，记录 25 槽占用）；外加 Access State（访问/操作权限）作为行为约束。

2. **预约作用 / 没预约就上料**：预约是 Host 提前下发的"某 LoadPort 预期将上某 CarrierID"的保留关系，是全自动产线防错料的闸门。实际物理上料（E84 Deposit）后设备读到实际 CarrierID，与该口预约的预期 ID 比对：一致才继续授权装载（迁 LOADED、允许加工）；没有预约（该口 Host 没排过任务）或实际 ID 与预约不符（上错盒/上错口）时，设备不授权加工，把载具置为未授权/Hold 状态、报警并上报 Host 等待人工或 MES 处理，绝不能默认开门取片加工。这样从执行末端杜绝混批、错料、跑错工艺。

3. **E84/E87/E90 边界（手/盒/片）**：
   - **E84 管"手"（物理动作）**：并行硬线，负责 FOUP 在 LoadPort 与天车之间放/取的实时安全互锁，不关心盒子 ID、逻辑状态、盒内晶圆。
   - **E87 管"盒"（载具账本与准入）**：SECS 软件层，负责 Carrier 整体的逻辑状态、CarrierID 绑定、预约授权、能不能开门取片/能不能卸载。
   - **E90 管"片"（盒里货位）**：SECS 软件层，负责盒内每片基板在哪个 Slot、基板 ID、来源/目标槽位（W14）。
   - 再往后 E40/E94 管"活"（怎么加工这些片）。四层物理→载具→基板→任务逐级细化，互不越界：E84 不传 ID，E87 不跟踪每片晶圆位置（交给 E90），E90 不负责物理交接安全。

4. **CarrierID 来源/读取时机/绑定**：CarrierID 是载具的唯一身份标识，物理上通常写在 FOUP 上的 RFID 电子标签（也有条码/人工输入）。读取时机：E84 Deposit 完成、Load Port 检测到 FOUP 物理就位（INSTALLED）之后，由 Load Port 的 RFID 读写器/扫码读取（此时盒子已稳定坐实在口上）。绑定：CarrierID 上送到 Host，与 MES 中的批次 Lot、工艺路线、目标设备、配方 PPID、槽位安排绑定——MES 正是靠 CarrierID 知道"这盒货是什么、该去哪、怎么加工"，E87 上料校验就是把物理盒子和 MES 计划对应起来的关键一步。

5. **为何用 OSS / 传统 GEM 怎么表达**：Carrier 和 LoadPort 天然是对象——有类型、属性（ID/状态/口位）、方法（授权装载/卸载/预约）、事件（就位/装载/卸载/移除），与 E39 OSS 六概念一一对应，用 S14 可发现类型定义、S15 做实例创建/属性设置/方法调用（Host 授权、下预约）、S16 上报对象状态事件，模型清晰、可自描述、可订阅，所以 E87 主要建立在 OSS 上，直接复用 W09/W10 的对象框架。传统/老设备不用 OSS 时，用 GEM 数据采集和远程命令表达等价语义：用 S6F11 事件报告上报"载具安装/装载/卸载"等 CEID（报告里带 CarrierID、LoadPortID 等 VID），用 S2F41 远程命令下发"授权装载/卸载/预约"（RCMD+CP 参数），用 S1F3/S1F4 查载具状态变量。两种语义等价，先进 FAB 以 OSS 为主，读懂两套是专家基本功。

6. **数据流 / E87 物理触发源**：①E84 Deposit 硬握手把 FOUP 物理放稳、Load Port 在位传感器 ON——这个"物理就位硬件事件"是 E87 状态机从 NOT_INSTALLED 迁到 INSTALLED 的触发源；②设备读 CarrierID，经 SECS（S16/S6F11）上报就位+ID；③Host 比对预约/工艺计划后下发授权（S15 方法/S2F41）；④E87 迁 LOADED 并上报；⑤E90 读 SlotMap/基板位置上报；⑥Host 建 E40 ProcessJob/E94 ControlJob 加工；⑦加工完 Host 下卸载，E87 迁 UNLOADED；⑧E84 Pickup 硬握手取走、在位变空，E87 回 NOT_INSTALLED 并上报移除。E87 每次物理状态迁移的源头都是 E84/传感器的物理事件，再叠加 Host 授权共同推进（物理触发 + 软件授权双驱动）。

7. **为何预约驱动强校验 / 防什么事故**：全自动产线无人值守，天车按调度把成百上千个 FOUP 在设备间搬运，一旦上错设备、上错口、盒身份对不上就会"用错误配方加工错误批次"，造成整批晶圆报废、工艺污染、设备污染，且无人现场及时发现，代价极大。预约驱动+强校验在物料进入设备的第一关就做三重核对（口对不对、盒 ID 对不对、工艺授权有没有），把 MES 的计划和物理实物强绑定，任何不一致立即 Hold 报警、拒绝加工，从源头杜绝混料/错料/跑错工艺/未授权加工，保证整厂物料流和数据流严格一致、全程可追溯。这是先进 FAB 零缺陷和全自动运行的必要条件。

## 三、E84→E87→E90→任务层 数据流图（手绘参考）
```
天车 ──E84 Deposit硬握手──► LoadPort在位ON [物理触发]
                              │ 读RFID得CarrierID
                              ▼
              E87: NOT_INSTALLED→INSTALLED→(Host预约校验+授权)→LOADED
                              │ 授权后可访问
                              ▼
              E90: 读SlotMap/基板ID/源目槽位
                              │
                              ▼
        Host: 建 E40 ProcessJob / E94 ControlJob → 加工
                              │ 加工完成
                              ▼
              E87: LOADED→UNLOADED(Host卸载授权)
                              │
天车 ◄──E84 Pickup硬握手─── LoadPort在位OFF → E87→NOT_INSTALLED(移除上报)
层次: E84手 / E87盒 / E90片 / E40·E94活
```

## 四、费曼讲解稿（3 分钟参考）
"一个 FOUP 被天车送过来，分四段：第一段 E84 是'手'，天车和装载口靠一束硬线信号握手，安全地把盒子放稳，这一段不管盒子是谁、里面是什么；盒子一就位触发第二段 E87'管盒'，设备读 RFID 得到 CarrierID，报给 Host，Host 查预约——这个口是不是等这个盒、这盒货是不是该来这台机，核对一致才授权装载，盒子状态变成 LOADED 可以开门；第三段 E90'管片'，读盒里 25 个槽哪些有晶圆、每片 ID 和来源目标槽；最后 Host 掌握了盒子和片子，才建 ProcessJob、ControlJob 去真正加工，这是'管活'。加工完反过来，E87 先变 UNLOADED，E84 再硬握手把盒取走。记住口诀：E84 管手、E87 管盒、E90 管片、E40/E94 管活，物理触发加 Host 授权双驱动，任何 ID 对不上都 Hold，绝不能糊里糊涂加工。"

## 五、今日易错点
1. 把 E84 的物理就位当成 E87 的 LOADED（中间还要读 ID、预约校验、Host 授权，先到 INSTALLED）。
2. 以为 E87 跟踪每片晶圆位置（那是 E90，E87 只管载具整体）。
3. 忽略预约，以为盒子放上来就能加工（先进 FAB 必须预约强校验，否则 Hold）。
4. CarrierID 时机记错（物理就位后才读 RFID，不是天车在空中时读）。
5. 以为 E87 是设备单方面说了算（物理触发+Host 授权双驱动）。
6. 只知道 OSS 实现，看不懂老设备 S6F11+S2F41 的等价表达。
7. 混淆 LoadPort 状态和 Carrier 状态（口是工位、盒是载具，一个口当前最多一个盒）。
8. 手动上料（E84 Bypass）不在 E87 补登记（账实会脱节，必须补登留痕）。
