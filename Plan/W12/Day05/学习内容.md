## 二、背景知识（先读，30 分钟）

### 1. 六类异常逐一拆解
#### 异常A：CarrierID 不匹配（Mismatch）
- 场景：口预约期望 A，实际读到 B（送错盒/送错口/预约下错）。
- 拦截点：INSTALLED 后、AuthorizeLoad 校验时。
- 状态：停留 INSTALLED，VerifyState=失败，禁止迁 LOADED、禁止开门取片。
- 处置：报警+上报告警事件（带期望 ID/实际 ID/口位），通知 Host/AMHS；恢复=取走错盒（回 NOT_INSTALLED）后重上正确盒，或 Host 走严格变更流程改预约（需权限留痕，不建议常态）。

#### 异常B：CarrierID 读不到（Unreadable）
- 场景：RFID 标签损坏、读写器故障、盒放置偏移、干扰，多次重试失败。
- 拦截点：INSTALLED 后读 ID 环节。
- 状态：停留 INSTALLED（或"待识别"子态），无 ID 不进入校验授权。
- 处置：自动重试 N 次→提示重新放置/换口重读→仍失败 Hold 上报；手动模式有权限人员对照实物/MES 人工输入 ID 并留痕后可继续。读写器硬件故障则报修。

#### 异常C：无预约上料（No Reservation）
- 场景：口 UNRESERVED 却来了盒（计划外上料、手动放、调度错）。
- 拦截点：授权前查预约。
- 状态：INSTALLED 停留、不授权。
- 处置：全自动线 Hold 等 Host；Host 核对后可①让 AMHS 转运到正确口、②按规则补建预约再校验授权（需审批留痕）；手动模式人工确认。

#### 异常D：载具/批次被 Hold（扣留）
- 多层 Hold：
  - **Carrier Hold（载具扣留）**：该载具因质量/工程/异常被 Host 或设备扣留，即使 LOADED 也禁止加工取片。
  - **Lot Hold（批次扣留，MES 层）**：载具内 Lot 在 MES 被 hold（质量问题/工程 hold），EAP 收到后对相关载具/任务拦截。
  - **Equipment/Process Hold（设备/工艺 Hold）**：设备状态不允许（故障/工艺条件不满足）。
- Hold 期间禁止：自动取放片、ProcessJob 启动/继续、卸载放行（按 Hold 级别，有的允许工程操作）。
- 解除：只能由下发 Hold 的一方（Host/MES/授权工程师）解除，设备不能自行解除；解除后恢复正常状态迁移。

#### 异常E：LoadPort 故障（Port Fault）
- 场景：升降/开门/夹持/RFID 读写器/传感器故障。
- 状态：LoadPort→LP_FAULT，冻结其上 Carrier 状态推进，禁止 E84 自动交接。
- 处置：报警上报、停止该口一切自动动作、安全保持；维修复位口后，重新对账物理与逻辑状态再恢复。若盒在故障口上，需人工评估取出。

#### 异常F：非正常移除（Unexpected Removal）
- 场景：LOADED/INSTALLED 时在位传感器突然变 OFF（被手动取走/天车误取/传感器断线）。
- 拦截点：任意占用态检测到在位 OFF 且未经正常 Unload 流程。
- 状态：强制回 NOT_INSTALLED，但标记"非正常移除"，LOADED 下尤其严重（可能有片在设备内）。
- 处置：高级报警、中止相关 PJ、冻结取放、触发账实核对（哪些基板不在盒内、在哪），人工/Host 清理后才恢复。

### 2. 异常分类原则
- **准入类（A/B/C）**：错误挡在 LOADED 之前，盒内还没被动，风险可控，主要是"不授权+等纠正"。
- **过程类（D/E/F）**：发生在已装载/加工中，可能涉及在途基板，风险高，需要停任务、账实核对、人工介入。
- 判据：盒内基板是否已被访问/在途——未访问是准入问题（低危），已访问是过程问题（高危）。

### 3. 告警与上报（复用 W07 报警体系）
- 设备产生对应 Alarm（S5F1/GEM 或 OSS 事件），带：LoadPortID、期望/实际 CarrierID、异常码、当前状态、时间戳。
- 区分报警级别：准入不匹配（中，阻止上料）、非正常移除/口故障（高，可能丢片/停机）。
- 报警需要使能（S5F3）、恢复时发清除；状态事件（S16F1/S6F11）与告警（S5F1）配合：事件说"状态变成什么"，告警说"出了什么问题"。

### 4. 恢复策略总表（谁有权、恢复到哪）
| 异常 | 恢复动作 | 权限方 | 恢复后状态 |
|---|---|---|---|
| ID 不匹配 | 取走重上/严格改预约 | AMHS+Host（改预约需审批） | 重新 INSTALLED→校验 |
| ID 读不到 | 重试/重放/换口/人工输入 | 设备重试/工程师人工 | 识别成功继续 |
| 无预约 | 转运/补预约 | Host（补预约留痕） | 校验后 LOADED |
| Hold | 解除 Hold | Hold 下发方 | 回到原状态继续 |
| 口故障 | 维修+复位+对账 | 维修+工程师 | 口 ENABLED 后对账恢复 |
| 非正常移除 | 停 PJ+账实核对+清理 | Host+人工 | 确认后回 EMPTY |

### 5. 与 E84 异常的协同
- E84 硬线异常（Day05 W11）导致物理交接没完成，E87 就不会收到正常就位事件；反之 E84 放好了但 E87 校验失败，盒子物理在口上但逻辑不授权，需要 AMHS 配合取走。物理层（E84）和逻辑层（E87）异常要联动看，不能各自为政。
