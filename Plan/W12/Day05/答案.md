# W12 · Day05 答案

## 一、自测题标准答案
1. **六类异常拦截点 / 准入 vs 过程**：
   - A **ID 不匹配**：INSTALLED 后、AuthorizeLoad 校验时拦截（期望≠实际）。
   - B **ID 读不到**：INSTALLED 后读 ID 环节拦截（无 ID 无法校验）。
   - C **无预约上料**：授权前查预约时拦截（口 UNRESERVED）。
   - D **Hold 扣留**：可发生在 LOADED 加工期间（载具/Lot/设备被 hold），拦截取片和任务推进。
   - E **LoadPort 故障**：任意阶段口硬件故障，冻结该口状态推进。
   - F **非正常移除**：占用态（INSTALLED/LOADED/UNLOADED）检测到在位 OFF 且未走正常卸载流程。
   - **准入类（A/B/C）**：都挡在 LOADED 之前，盒内基板未被访问、风险可控，策略是"不授权+等纠正"；**过程类（D/E/F）**：发生在已装载/加工中，可能有在途基板、风险高，需要停任务、账实核对、人工介入。判据是盒内基板是否已被访问或在途。

2. **ID 不匹配的状态/禁止/恢复**：停留在 INSTALLED（物理在位但不授权），VerifyState=失败；禁止迁 LOADED、禁止开门、禁止机械手取片加工；发中等级别告警和不匹配事件（带期望 ID、实际 ID、LoadPortID），通知 Host/AMHS。恢复：①常规是把错盒取走（E84 Pickup 后回 NOT_INSTALLED），重新上正确盒再走校验；②或由 Host 走严格变更流程修改预约（需有权限、审批留痕，不建议常态，因为预约来自 MES 计划，随意改等于绕过防错）。不会自动"将错就错"授权。

3. **读不到 ID 的原因 / 重试失败后处理**：原因——RFID 标签损坏/未写或脱落、读写器硬件故障、FOUP 放置偏移导致没对准天线、电磁干扰、通信线缆问题。处理阶梯：①设备自动重试若干次（如 3 次，可伴随要求重新对位）；②仍失败则提示重新放置或换口重读；③还失败则停留 INSTALLED、置 ID_UNREADABLE、Hold 并上报，等待人工；④手动/维护模式下，有权限人员对照实物标签和 MES 人工核对、手动输入 CarrierID，留痕（操作人/时间/依据/原因）后继续校验流程；⑤若判定读写器硬件故障则报修并可把该口置故障。核心：身份不明绝不自动加工。

4. **三种 Hold 区别 / 设备能否自解**：
   - **Carrier Hold（载具级）**：针对这个 FOUP，因质量、工程验证、异常被扣留，即使物理 LOADED 也禁止对它取片加工/放行。
   - **Lot Hold（批次级，MES）**：扣留对象是盒内的生产批次 Lot（质量 hold、工程 hold、客户 hold 等），MES 决定并下达到 EAP，影响该 Lot 关联的所有载具和任务。
   - **Equipment/Process Hold（设备/工艺级）**：设备自身故障或工艺条件不满足（参数越限、互锁未满足）导致不能继续加工。
   设备**不能自行解除 Hold**——Hold 是一种显式管控决策，只能由下发它的一方（Host/MES/授权工艺或质量工程师）解除，设备只能执行和如实上报状态；这保证扣留的权威性和可追溯，防止现场设备擅自放行有问题的货。解除后设备按当前状态恢复被冻结的迁移/动作。

5. **LOADED 非正常移除为何高危 / 设备动作**：LOADED 意味着盒已被授权访问、可能正有 ProcessJob 从中取片，盒内晶圆可能有若干片被取到机械手/腔体/在途，此刻盒子物理消失（被误取/手动拿走/传感器断线）会造成"晶圆在设备里、盒子不见了"的严重账实不符，继续动作会撞片、丢片、混片。设备动作：①立即检测在位 OFF 且未经正常 Unload，中止所有访问该 Carrier 的 ProcessJob/运动、冻结取放；②强制 Carrier 状态回 NOT_INSTALLED 但标记"非正常移除"，LoadPort 回 EMPTY；③发高级别告警 + 非正常移除事件（口位、原 CarrierID、当时 PJ、已取片清单）；④触发账实核对：清点哪些基板不在盒内、当前在设备什么位置，由 Host/人工决定这些片如何归位/处置；⑤在核对清理完成前禁止该口上新任务；若是传感器断线（盒其实还在）还要先甄别真伪，避免误判。

6. **状态事件 vs 告警的分工**：**状态事件（S16F1 对象事件 / S6F11 GEM 事件）回答"状态变成了什么"**——客观陈述状态迁移（Installed/Loaded/Hold/Removed 等），驱动 Host 侧状态镜像和流程推进，是"账本流水"。**告警（S5F1）回答"出了什么问题、多严重"**——携带异常码、期望/实际值、级别，触发操作员注意和声光提示、报警管理（需 S5F3 使能，恢复时发报警清除）。二者配合：例如 ID 不匹配，既发 S16F1 说明载具停在 INSTALLED+VerifyState 失败（状态事实），又发 S5F1 中/高级告警提示"ID 不匹配需处理"（问题与级别）；只发事件不报警可能无人及时处理，只报警不发状态事件 Host 账目无法更新，专家级实现两者都不缺且语义不混。

7. **E84 异常与 E87 异常联动**：两层是一条链的上下游，必须联动判断。①若 **E84 物理交接异常**（T_compt 超时、VALID 丢、ESTOP、没放稳），物理上盒没成功就位，E87 就不应收到"在位 ON 稳定"事件、不会进 INSTALLED——E87 的物理触发源被 E84 拦住，避免逻辑层对一个没放好的盒建账。②若 **E84 成功放好、但 E87 校验异常**（ID 不符/无预约），盒物理在口上但逻辑不授权，E87 Hold 的同时需要反向通知调度/AMHS 来把盒取走（再走一次 E84 Pickup），物理和逻辑协同清场。③E84 取走动作（Pickup）也必须在 E87 状态允许时进行（LOADED 正常要先 Unload 到 UNLOADED 才取，异常移除则两边都报警）。原则：物理层管"盒有没有被安全放/取"，逻辑层管"盒该不该被接受/加工"，任一层异常都要把状态同步给另一层和 Host，不能物理放了逻辑不知道、或逻辑拒绝了物理却没人把盒搬走。

## 二、带异常分支的 Carrier 状态机（手绘参考）
```
 NOT_INSTALLED ──在位ON/读ID──► INSTALLED ──预约匹配∧校验通过∧Host授权──► LOADED
      ▲                          │││                                      │
      │                          ││├─ID不匹配─► Hold(停留INSTALLED,告警)──取走/改预约
      │                          ││├─ID读不到─► 重试/人工输入(留痕)
      │                          ││└─无预约───► Hold,转运/补预约(审批)
      │                          ││                                         │
      │                          ││              Hold(载具/Lot/设备)─冻结取片─Hold下发方解除
      │                          ││                                         │ Host卸载(PJ全结束)
      │                          ││                                         ▼
      │                          └──────────────────────────────────► UNLOADED
      │                                                                   │
      └────────────────────在位OFF正常取走───────────────────────────────┘
 异常边(任意占用态):
   在位OFF且未正常Unload ──► 非正常移除: 停PJ+高警报+账实核对+强制NOT_INSTALLED
   LoadPort故障 ──► LP_FAULT: 冻结推进/禁自动交接,维修复位+对账
```

## 三、六类异常处置矩阵（参考答案）
| 异常 | 拦截点 | 停留/迁移状态 | 告警级别 | 恢复动作 | 权限方 |
|---|---|---|---|---|---|
| ID 不匹配 | 授权校验 | INSTALLED+Verify失败 | 中 | 取走重上/严格改预约 | AMHS+Host(审批) |
| ID 读不到 | 读 ID | INSTALLED(待识别) | 中 | 重试/重放/换口/人工输入留痕 | 设备/工程师 |
| 无预约 | 查预约 | INSTALLED 不授权 | 中 | 转运/补预约 | Host(留痕) |
| Hold | LOADED 过程 | 冻结取片/任务 | 按来源 | 解除 Hold | Hold 下发方 |
| 口故障 | 任意 | LP_FAULT 冻结 | 高 | 维修+复位+对账 | 维修/工程师 |
| 非正常移除 | 占用态在位OFF | 强制 NOT_INSTALLED+标记 | 高 | 停PJ+账实核对+清理 | Host+人工 |

## 四、两个高危推演（参考答案）
### 推演1：LOADED 加工中盒被误取走
1. PJ 已从盒取出 3 片在设备内加工，在位传感器突然 OFF 且没有正常 Unload 流程。
2. 立即中止该 Carrier 相关 PJ 和机械手运动、冻结取放，防止在无盒状态继续归位动作撞机。
3. 判非正常移除：Carrier 强制回 NOT_INSTALLED、口回 EMPTY，高级报警+事件（口位、ID、PJ、已取 3 片清单）。
4. 账实核对：这 3 片不在盒里，逐一确认在腔体/机械手/暂存位，由 Host 决定继续加工完再人工归位到替代盒，还是中止取出；期间锁口。
5. 排查移除原因（天车误取/手动/传感器断线），处理完、实物与账目对齐后才解锁恢复。
### 推演2：Lot 被 MES Hold 时设备正准备取下一片
1. 设备在 LOADED 加工中收到 MES/Host 的 Lot Hold（该 Lot 质量/工程扣留）。
2. EAP 立即对该 Lot 关联载具置 Hold 标志，状态机拦截下一次取片：当前在加工的片按安全策略做完当前步或安全暂停（不在中途硬切造成片损伤），但**不再从盒里取新片**、不启动新 PJ。
3. 上报 Hold 状态与当前进度，载具保持在口上、物理不卸载，等待处置。
4. 只有 MES/质量或工艺工程师解除 Lot Hold，设备收到解除后才恢复取片/任务；设备无权自行解除。

## 五、今日易错点
1. 把准入类异常（未访问盒内）和过程类异常（有在途片）同等对待（过程类高危，要停 PJ+核对）。
2. ID 不符自动改预约授权（必须取走重上或严格审批，不能默认放行）。
3. ID 读不到就跳过校验加工（身份不明绝不加工）。
4. 以为设备能自己解除 Hold（只能 Hold 下发方解除）。
5. LOADED 非正常移除只当普通移除（必须停 PJ、高警报、账实核对在途片）。
6. 只发状态事件不发告警，或反之（事件记状态、告警提问题，二者配合）。
7. E84 没放稳 E87 就建账（物理触发源必须先确认在位稳定）。
8. 口故障复位后直接恢复（要先物理/逻辑对账再恢复）。
9. 手动放行/补预约不留痕（例外操作必须可追溯）。
