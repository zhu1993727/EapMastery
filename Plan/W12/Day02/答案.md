# W12 · Day02 答案

> 状态名称/迁移条件以 SEMI E87 原文为准，本计划用业界通用四态主线讲清机制。

## 一、自测题标准答案
1. **为何多个正交状态机 / 四个维度**：载具的情况本来就由多个相互独立、同时变化的维度组成，硬塞进一个状态会产生笛卡尔积爆炸且语义混乱（例如"已装载但没预约""物理在位但校验失败"无法用单一主状态清晰表达）。E87 用正交（并行）状态机，每个维度只描述一件事，组合起来才是完整态势：①**Carrier 管理状态**（物理+逻辑总体生命周期：NOT_INSTALLED/INSTALLED/LOADED/UNLOADED）；②**预约状态**（该口/盒有无 Host 预约：UNRESERVED/RESERVED）；③**校验状态**（实际 CarrierID 与期望是否一致：未校验/通过/失败）；④**访问状态**（能否自动/手动访问盒内：自动/手动/禁止）。主状态走到哪一步要由预约、校验这些正交维度做守卫，访问维度决定能不能真正动手取片。

2. **四态含义 / 是否允许自动取片**：
   - **NOT_INSTALLED**：口上无盒、在位 OFF，空闲基线；不涉及取片（无片可取）；可被预约、可接受 Deposit。
   - **INSTALLED**：物理在位、已读/在读 ID 并上报、等 Host 授权；**禁止自动取片**（还没核验授权）。
   - **LOADED**：Host 校验授权完成；**唯一允许自动开门、机械手取放片、ProcessJob 加工访问**的状态。
   - **UNLOADED**：访问/加工结束、已卸载待物理取走；**禁止自动取片**，只等 Pickup。
   一句话：只有 LOADED 能自动取片，INSTALLED/UNLOADED 都不能。

3. **物理在位≠可加工 / INSTALLED 与 LOADED 本质区别**：在位传感器 ON 只证明盒子物理坐到口上了（E84 层面事实），但此时系统还不知道/没确认"这个盒是不是该来的盒、里面是不是对的货、Host 有没有排它的工艺、能不能安全开门"。INSTALLED 就是这个"货到了但没被系统授权"的状态；必须读 ID、Host 比对预约和工艺计划、校验通过并显式授权后才进 LOADED。本质区别：**INSTALLED 是物理事实（设备自己能感知），LOADED 是逻辑授权（必须 Host 确认）**。这道间隔正是防错料、防未授权加工的闸门——绝不能检测到盒子就直接开门加工。

4. **四条主迁移触发源与守卫**：
   - NOT_INSTALLED→INSTALLED：触发=物理（在位传感器 ON，E84 Deposit 完成）；守卫=信号稳定去抖、口可用；动作=读 CarrierID、发"载具安装"对象事件/CE（带 ID、LoadPortID）。
   - INSTALLED→LOADED：触发=软件（Host 装载授权）；守卫=口已预约且实际 ID==预期 ID（校验通过）、口无故障、访问权限为自动；动作=迁 LOADED 发事件、开放取片访问。
   - LOADED→UNLOADED：触发=软件（Host 卸载指令）；守卫=所有访问该 Carrier 的 ProcessJob 已结束、机械手已归位、盒门已关；动作=迁 UNLOADED 发事件、停止访问、等待取走。
   - UNLOADED→NOT_INSTALLED：触发=物理（在位传感器 OFF，E84 Pickup 完成）；守卫=信号稳定、盒确实离开；动作=发"载具移除"事件、释放 LoadPort、按策略清预约。

5. **预约+校验如何门控 INSTALLED→LOADED**：盒子进 INSTALLED 读到实际 CarrierID 后，先看预约状态：①口为 RESERVED 且携带预期 ID，实际 ID 与预期 ID 一致→校验状态置"通过"，具备授权前提，Host 下装载授权后才迁 LOADED；②口 RESERVED 但实际 ID≠预期→校验"失败"，拒绝授权、停留 INSTALLED 并 Hold 报警；③口 UNRESERVED 无预约→按产线策略，全自动线通常拒绝/Hold（防止计划外盒子被加工），手动/维护模式可经人工确认后放行。即"预约匹配 + 校验通过"是 INSTALLED→LOADED 的必要守卫，Host 授权是触发，三者缺一不可，正交维度在这里共同门控主状态。

6. **LOADED→UNLOADED 前提 / PJ 没结束为何不能卸载**：前提是所有正在访问该 Carrier 的 ProcessJob/ControlJob 都已到达终态（完成或中止）、机械手已把取放的片归位、载具门关闭、没有对盒内基板的未完成操作，再由 Host 下卸载指令才迁移。PJ 没结束不能卸载，是因为 ProcessJob 正在从盒里取片/加工，盒内晶圆可能有被取到设备腔体/机械手上、还没放回槽位的在途状态，此时卸载甚至让天车把盒取走，会造成"晶圆在设备里、盒子被搬走"的严重物料不一致、丢片撞片。必须等所有访问结束、基板全部归位、账实一致，才能结束访问转 UNLOADED，这和 E40/E94 任务状态是联动的（W16+ 会看到任务对载具的占用）。

7. **INSTALLED 被突然取走 / LOADED 异常取走**：
   - INSTALLED 未授权就被取走：本来就没开始访问、盒内没被动过，检测到在位 OFF 直接回 NOT_INSTALLED，撤销"待授权"请求、清理本次安装记录并上报"载具在授权前移除"（一般是调度变更/放错又取走，风险较低，但要留痕）。
   - LOADED 状态被异常取走：这是非正常移除——可能盒内晶圆已被取走若干、正在加工，物理盒子却被搬走，属于严重异常。设备应立即检测在位 OFF、中止相关 ProcessJob、报警（高级别）、状态强制回 NOT_INSTALLED 并上报"已装载载具非正常移除"，触发账实核对（哪些片不在盒里、在设备什么位置），必须人工/Host 介入清理，不能当作正常下料。区别核心：是否已开始访问盒内基板——未访问（INSTALLED）移除是低风险撤销，已访问（LOADED）移除是可能丢片的严重事故。

## 二、Carrier 正交状态机（手绘参考）
```
═══ 管理状态主线（Carrier Management State）═══
 NOT_INSTALLED ──在位ON/读ID/上报──► INSTALLED
      ▲                              │Host授权[预约匹配 ∧ 校验通过 ∧ 口正常]
      │在位OFF(正常取走)             ▼
      │                          LOADED ◄── 唯一允许自动取片/PJ访问
      │                              │Host卸载[所有PJ结束∧门已关∧片归位]
      │                              ▼
      └──────── UNLOADED ◄───────────┘
异常边: INSTALLED未授权被取→直接回NOT_INSTALLED(撤销,低危)
       LOADED被异常取→中止PJ+高级报警+强制回NOT_INSTALLED(账实核对)
═══ 正交维度（门控主线）═══
 预约: UNRESERVED ◄─Host预约(带预期ID)─► RESERVED ─Host取消─► UNRESERVED
 校验: 未校验 ─读ID比对─► 通过(放行) / 失败(Hold,停留INSTALLED)
 访问: 禁止(INSTALLED/UNLOADED) | 自动(LOADED) | 手动(维护)
```

## 三、状态 × 允许动作矩阵（参考答案）
| 动作 \ 状态 | NOT_INSTALLED | INSTALLED | LOADED | UNLOADED |
|---|---|---|---|---|
| 接受 Host 预约 | 可以 | 已带预约则校验 | 一般不再改 | 不再预约 |
| 读 CarrierID | 无盒 | 进行/完成 | 已完成 | 已完成 |
| 开盒门/访问内部 | 否 | 否 | 是（自动/手动按权限） | 否 |
| 自动取放片(PJ) | 否 | 否 | **是** | 否 |
| Host 授权装载 | 否 | 是（校验通过后） | 已授权 | 否 |
| Host 卸载 | 否 | 否 | 是（PJ 全结束） | 已卸载 |
| 天车 Pickup 取走 | 无盒可取 | 可（撤销，低危） | 异常（高危报警） | 正常取走 |
| 加工/被 PJ 占用 | 否 | 否 | 是 | 否 |

## 四、逐边讲解稿（参考）
1. "盒子还没来是 NOT_INSTALLED，这时 Host 可以先预约这个口、告诉设备预期 ID。"
2. "E84 把盒放稳、在位传感器 ON，设备读 RFID、上报安装事件，进入 INSTALLED——注意，只是物理到了，还不能碰。"
3. "Host 拿实际 ID 对预约：对上=校验通过，Host 授权装载，才进 LOADED，这时候才允许开门、机械手取片、PJ 加工。"
4. "加工时所有取放片都只在 LOADED；等所有 PJ 结束、片全归位、门关好，Host 下卸载，进 UNLOADED，停止访问等天车。"
5. "E84 把盒取走、在位 OFF，回 NOT_INSTALLED 并报移除，释放口。"
6. "异常：没授权就拿走，低危撤销；已经 LOADED 在加工却被拿走，立即停 PJ、高警报、账实核对。"

## 五、今日易错点
1. 用单一状态表达所有维度（E87 是管理/预约/校验/访问正交状态机）。
2. 检测到在位 ON 就直接 LOADED 开工（必须经 INSTALLED→读 ID→校验→Host 授权）。
3. 混淆 INSTALLED（物理事实）和 LOADED（逻辑授权）。
4. 以为预约是上料后才做（先进 FAB 先预约后上料，上料即校验）。
5. PJ 没结束就允许卸载（在途基板会丢片，必须访问结束、片归位）。
6. 混淆 Carrier 状态和 LoadPort 状态（盒 vs 工位，1:1 但不同对象）。
7. LOADED 被异常取走当正常移除（已访问过盒内，属高危，要停 PJ+报警+核对）。
8. 记成 UNLOADED 还能取片（UNLOADED 已结束访问，禁止取片，只等取走）。
