## 二、背景知识（先读，35 分钟）

### 1. E87 是"多个正交状态机"，不是单一状态
E87 对一个 Load Port 上的载具，用几组相互正交（各管一个维度、组合起来才完整）的状态描述：
- **Carrier Management State（载具管理状态，主线）**：载具物理+逻辑的总体生命周期。
- **Reservation State（预约状态）**：该口/载具有没有被 Host 预约（UNRESERVED/RESERVED）。
- **Verification State（校验状态）**：实际读到的 CarrierID 与预约/期望是否一致（未校验/验证通过/验证失败）。
- **Access State（访问状态）**：当前能否自动/手动访问载具内部（开门、取放片）。
- 正交含义：管理状态走到哪一步，同时要看预约和校验是否放行；不能只用一个状态字段表达全部。下面以管理状态为主线，其余作为迁移守卫。

### 2. Carrier 管理状态主线（四态，精确语义以 E87 原文为准）
```
                物理就位(E84 Deposit/在位传感器ON)
 NOT_INSTALLED ───────────────────────────────► INSTALLED
 (口上无盒)     读CarrierID, 上报Host, 等授权      (物理在位,待确认/授权)
      ▲                                            │ Host授权(预约校验通过)
      │ 物理移除(E84 Pickup/在位OFF)                ▼
      │                                        LOADED
      │                                     (已装载,可访问:开门/取放片/加工)
      │                                            │ Host卸载指令 + 访问结束
      │                                            ▼
      └─────────────────────────────── UNLOADED (已卸载,访问结束,待物理取走)
```
#### 状态逐一拆解
- **NOT_INSTALLED（未安装/口上无盒）**：Load Port 上没有 Carrier，在位传感器 OFF。这是空闲基线态。允许：接受 Host 预约（口变 RESERVED 但仍无盒）、天车来 Deposit。
- **INSTALLED（已安装/物理在位待授权）**：在位传感器 ON，盒子物理坐实，设备已读到（或正在读）CarrierID 并上报 Host，但**尚未获得 Host 装载授权，不允许开门取片加工**。这是"货到了、等核验授权"的中间态。关键：物理在位≠可加工。
- **LOADED（已装载/授权可访问）**：Host 完成预约与 ID 校验、下发装载授权后进入。此态才允许开门、机械手取放片、ProcessJob 访问盒内基板。这是唯一允许加工访问的状态。
- **UNLOADED（已卸载/访问结束待取走）**：加工/访问完成，Host 下发卸载，设备结束对载具的访问（关门、准备交接），等待天车 Pickup。此态不再允许取片，只等物理移除。
- 物理取走（在位 OFF）后回到 NOT_INSTALLED。

### 3. 每条迁移的触发源与守卫（重点）
| 迁移 | 触发源 | 守卫/条件 | 设备动作与上报 |
|---|---|---|---|
| NOT_INSTALLED→INSTALLED | 物理：在位传感器 ON（E84 Deposit 完成） | 传感器稳定去抖 | 读 CarrierID，发"载具安装"事件(带 ID/口位) |
| INSTALLED→LOADED | 软件：Host 装载授权 | 预约匹配且 ID 校验通过、口无故障 | 迁 LOADED 并发事件，允许访问 |
| LOADED→UNLOADED | 软件：Host 卸载指令 | 所有访问该盒的 PJ 已结束、门已关 | 迁 UNLOADED 发事件，等待取走 |
| UNLOADED→NOT_INSTALLED | 物理：在位传感器 OFF（E84 Pickup 完成） | 传感器稳定、盒确实离开 | 发"载具移除"事件，释放口 |
- 反向/异常迁移：INSTALLED 未授权就被物理取走→直接回 NOT_INSTALLED（取消待授权）；LOADED 异常被取走→报警并回 NOT_INSTALLED（非正常移除，账实核对）；校验失败→不进 LOADED，停在 INSTALLED 并 Hold（Day05）。

### 4. 预约状态如何门控
- 口在 NOT_INSTALLED 时就可被 Host 预约：UNRESERVED→RESERVED（携带预期 CarrierID）。
- 盒子 INSTALLED 读到实际 ID 后：若口 RESERVED 且实际 ID==预期 ID→校验通过，Host 可授权进 LOADED；若 RESERVED 但 ID 不符→校验失败，拒绝授权；若口 UNRESERVED（无预约）→按产线策略，全自动线一般拒绝/Hold，手动模式可人工确认放行。
- 预约可被 Host 取消（RESERVED→UNRESERVED），载具移除后预约按策略释放。

### 5. 校验状态（Verification）三态
- 未校验（NOT_VERIFIED）：刚 INSTALLED，还没比对。
- 通过（VERIFIED/ID_OK）：实际 ID 与预约期望一致。
- 失败（MISMATCH/ID_FAIL）：不一致或读不到 ID。只有"通过"才放行到 LOADED；失败进异常流程（Day05）。

### 6. 访问状态（Access）与 LOADED 的关系
- LOADED 本质是"Host 授权自动访问"。访问维度区分：自动访问（Host/EAP 控制机械手取放）、手动访问（操作员开门）、禁止访问。
- 只有 LOADED + 自动访问允许才允许 ProcessJob 取片；INSTALLED/UNLOADED 都禁止自动取片。这把"状态"和"能不能动手"绑定，防止在未授权态碰盒内晶圆。

### 7. Load Port 自身状态（与 Carrier 状态区分）
- Load Port 是工位，有独立状态：可用/不可用（故障/维护/禁用）、当前有无 Carrier、是否被预约。
- 一个 Load Port 同一时刻最多一个 Carrier；Carrier 状态描述"盒"，Load Port 状态描述"口"，两者 1:1 关联但不同对象。口故障会阻止对应 Carrier 状态推进。
