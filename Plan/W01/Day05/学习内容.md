# W01 · Day05（周五）二进制长度帧 + 粘包/半包 + 抓包

> 建议时长：80 分钟。目标：把昨天的文本帧升级为 **4 字节大端长度头 + payload**（HSMS 帧雏形），写对累积缓冲切帧，并用 Wireshark 亲眼看到自己发的字节。

## 一、今日目标
1. 定义统一帧格式：`[4 字节大端长度 N][N 字节 payload]`，N 只统计 payload（HSMS 里 N=10 字节头+体）。
2. 写一个 `FrameReader`：喂入任意分片的字节流，都能正确切出完整帧（解决粘包/半包）。
3. 双端互发 byte[] 并 hex dump；Wireshark 抓 loopback，逐字节对上。

## 二、背景知识（先读，10 分钟）
- **大端（Big-Endian）**：高位字节在前，SECS/HSMS、网络字节序都是大端。C# 用 `BinaryPrimitives.WriteUInt32BigEndian`。
- **HSMS 真实帧**：`4B length + 10B header + body`；length 的值 = header+body 的字节数（**不含这 4 字节自己**）。今天先用 `4B length + 任意 payload`，W2 把 10B header 补上。
- **切帧状态机思路**：维护内部残留缓冲；每次新字节到来先追加，再循环"够 4 字节读长度→够整条就切出→不够就等更多字节"。
- **抓 loopback**：Windows 抓 127.0.0.1 回环流量需要 Npcap，并选 "Adapter for loopback traffic capture / Npcap Loopback Adapter"。

## 三、今日任务（65 分钟）
### 任务1（30min）：实现 FrameWriter / FrameReader（先自己写，再对答案）
- FrameWriter：`byte[] Build(byte[] payload)` → 4B 大端长度 + payload。
- FrameReader：`IEnumerable<byte[]> Push(byte[] chunk)` 或回调式 `OnFrame`，正确处理：一帧分多次到、一次到多帧、半条长度头。
- 用 xUnit 写用例：单帧、3 帧粘一起、1 帧切成 1+3+剩余字节三种喂法，结果必须一致。

### 任务2（20min）：双端换成二进制帧
- EquipSim/HostSim 用 FrameReader 收、FrameWriter 发；payload 先用 UTF8 文本，收到后 hex dump 原始字节再解码。
- 连发 3 帧验证不再粘连。

### 任务3（15min）：Wireshark 抓包
- 选 loopback 网卡，过滤 `tcp.port == 5000`；看三次握手（SYN/SYN-ACK/ACK）、PSH/ACK 数据段。
- 在数据段里找到自己发的 4 字节长度头与 payload，截图；写 200 字笔记《长度头解决了什么问题》。
