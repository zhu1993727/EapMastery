# W01 · Day05 答案与参考实现

## 一、自测题标准答案
1. **length 是否含自身 / 字节序**：不含。HSMS 的 4 字节长度 = 其后消息（10B 头 + body）的字节数；**大端（网络字节序，高位在前）**。
2. **"完整帧A + 帧B前半截"怎么处理**：先切出完整的 A 交付；把帧 B 的前半截**留在内部残留缓冲**，等下次字节到来继续拼，绝不用不足一帧的数据硬解析。
3. **为什么切帧必须有状态**：因为到达分片与消息边界无关，解析器必须"记住"上次没拼完的字节。无状态逐包解析会在半包时越界/报错、在粘包时把多条当一条，最终解析错乱。
4. **握手 vs 数据 / PSH**：三次握手是 SYN、SYN-ACK、ACK（不带应用数据）；之后 PSH/ACK 段承载应用数据。PSH 标志提示接收方"尽快把缓冲数据交给应用"，但**不能**用 PSH 当消息边界（它与应用帧无关）。
5. **离真正 HSMS 帧还差**：payload 要换成 **10 字节 HSMS/SECS-II 消息头**（SessionID、W+Stream、Function、PType、SType、SystemBytes）+ 可选 SECS-II 数据体；并区分控制消息(Select/Linktest/Separate)与数据消息，配套 T 超时与状态机（W2 全部补齐）。

## 二、参考实现（net8.0，放 EapLab.Transport/Framing/）

### FrameWriter.cs
```csharp
using System.Buffers.Binary;
namespace EapLab.Transport.Framing;

public static class FrameWriter
{
    /// <summary>HSMS 风格帧：4B 大端长度(=payload字节数) + payload。</summary>
    public static byte[] Build(byte[] payload)
    {
        var frame = new byte[4 + payload.Length];
        BinaryPrimitives.WriteUInt32BigEndian(frame.AsSpan(0, 4), (uint)payload.Length);
        Buffer.BlockCopy(payload, 0, frame, 4, payload.Length);
        return frame;
    }
}
```

### FrameReader.cs（有状态累积缓冲，正确处理粘包/半包）
```csharp
using System.Buffers.Binary;
namespace EapLab.Transport.Framing;

/// <summary>喂任意分片，吐出完整帧。线程模型：每个连接一个实例。</summary>
public sealed class FrameReader
{
    private readonly MemoryStream _buffer = new();
    private const int HeaderLen = 4;
    private const int MaxFrame = 16 * 1024 * 1024; // 上限，防异常长度撑爆内存

    public IEnumerable<byte[]> Push(byte[] chunk, int count)
    {
        _buffer.Write(chunk, 0, count);
        var data = _buffer.GetBuffer();
        int total = (int)_buffer.Length;
        int consumed = 0;

        while (total - consumed >= HeaderLen)
        {
            uint len = BinaryPrimitives.ReadUInt32BigEndian(data.AsSpan(consumed, HeaderLen));
            if (len > MaxFrame) throw new InvalidDataException($"帧长度异常: {len}");
            if (total - consumed - HeaderLen < (int)len) break; // 半包，等更多字节

            var frame = new byte[len];
            Buffer.BlockCopy(data, consumed + HeaderLen, frame, 0, (int)len);
            consumed += HeaderLen + (int)len;
            yield return frame;
        }

        // 把未消费的残留(可能是半帧)移到缓冲开头
        if (consumed > 0)
        {
            int remain = total - consumed;
            Buffer.BlockCopy(data, consumed, data, 0, remain);
            _buffer.SetLength(remain);
        }
    }
}
```

### xUnit 用例（EapLab.Tests）
```csharp
public class FrameReaderTests
{
    [Fact]
    public void 三帧粘一起_切出三帧()
    {
        var r = new FrameReader();
        var all = FrameWriter.Build(new byte[]{1}).Concat(
                  FrameWriter.Build(new byte[]{2})).Concat(
                  FrameWriter.Build(new byte[]{3})).ToArray();
        var frames = r.Push(all, all.Length).ToList();
        Assert.Equal(3, frames.Count);
        Assert.Equal(new byte[]{1}, frames[0]);
    }

    [Fact]
    public void 一帧分三次喂_最终得到一帧()
    {
        var r = new FrameReader();
        var one = FrameWriter.Build(new byte[]{9,8,7});
        Assert.Empty(r.Push(one.Take(2).ToArray(), 2));
        Assert.Empty(r.Push(one.Skip(2).Take(3).ToArray(), 3));
        var last = r.Push(one.Skip(5).ToArray(), one.Length-5).ToList();
        Assert.Single(last);
        Assert.Equal(new byte[]{9,8,7}, last[0]);
    }
}
```

## 三、Wireshark 操作要点
1. 装 Wireshark 时勾选 Npcap 与 loopback 支持；接口选 **Npcap Loopback Adapter**。
2. 过滤栏：`tcp.port == 5000`；先看到 SYN/SYN-ACK/ACK 三次握手，再看到 PSH/ACK 数据。
3. 点开数据段 → Data 字段，逐字节对照：前 4 字节是大端长度（如 payload 5 字节即 `00 00 00 05`），后面是 payload。
4. 右键 Follow → TCP Stream 可看整条会话字节流。

- 两个 xUnit 用例通过；故意半包/粘包都能正确还原。
- 抓包能指出长度头与 payload；理解 PSH 不能当帧边界。

## 五、易错点
1. 长度头用了小端（SECS/HSMS 是大端）。
2. length 把自身 4 字节也算进去（错位 4 字节，全部解析崩）。
3. 半包时直接报"长度不足"丢弃残留（应保留等下次）。
4. 不设最大帧长，遇到脏数据 length 巨量导致 OOM。
