## 一、今日目标

## 二、背景知识（先读，10 分钟）
- **TCP 是可靠、有序、面向字节流**的协议：它只保证字节按序到达，**不保留消息边界**。一次 Send 可能被拆成多次 Receive（半包），多次 Send 也可能合并成一次 Receive（粘包）。所以任何应用协议都必须自己定义"帧边界"——HSMS 的做法是"**4 字节大端长度头 + 消息体**"（Day05 实现）。
- **Passive/Active**：Passive 监听(Bind/Listen/Accept)，Active 连接(Connect)；连接建立后双方全双工对等收发。HSMS-SS 在此之上还要 Active 发 Select.req 完成"选通"（W2）。
- HSMS 常用端口 5000（可配）；真实 FAB 设备 IP/端口/会话号由配置决定。

- EquipSim：后台 Accept 循环，接入后起一个收包循环（NetworkStream.Read），收到 UTF8 文本打印 `[RX]`，并可回显。
- HostSim：Connect 后，循环读键盘输入并发送，打印 `[TX]`；同时后台收包打印。
- 用 Day03 的 ILogSink 统一日志。

### 任务2（20min）：观察粘包/半包
- 连续快速发送 3 条短消息（不 Sleep），观察接收端是否一次读到多条（粘包）。
- 发送一条很长消息，观察是否分多次到达（半包）。
- 在笔记里写下：为什么"按 Read 一次=一条消息"的写法是错的，正确思路是什么（留到 Day05 实现）。

### 任务3（15min）：连接生命周期观察
- 先不开 EquipSim，HostSim 去连，观察异常（ConnectionRefused）。
- 连上后强制关掉一端，观察另一端 Read 返回 0 / 异常，理解"断链检测"是 W2 T8/Linktest 要解决的问题。
