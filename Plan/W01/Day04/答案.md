# W01 · Day04 答案与参考实现

## 一、自测题标准答案
1. **为什么 TCP 之上还要帧 / HSMS 外层格式**：TCP 是无边界字节流，不切分就无法知道一条消息从哪到哪结束。HSMS 外层帧 = **4 字节大端无符号长度头（=后续字节数）+ 消息体（10 字节 HSMS/SECS 头 + 可选数据）**。接收方先读满 4 字节得到长度 N，再精确读满 N 字节才交付一条完整消息。
2. **Passive/Active 与 Select**：TCP 阶段 Passive 做 Bind/Listen/Accept，Active 做 Connect，三次握手后只是"传输连通"。HSMS 还要 Select 是因为要在 TCP 之上确认"**双方都是 HSMS 实体、协商/确认会话(Session)、单会话排他选通**"——TCP 连通 ≠ HSMS 选通(Selected)，这就是 W2 控制状态机里 NotSelected→Selected 的那一步。
3. **Read 返回 0 / 断链发现**：Read 返回 0 表示对端正常关闭(FIN)；但对端**断电/网线掉**时不会发 FIN，本端可能长时间无感知（半开连接）。HSMS 用 **T8 无活动超时 + Linktest 心跳**主动探测：空闲到点发 Linktest.req，收不到 rsp 就判链路失效。
4. **接收端要缓存什么**：要维护一个**接收累积缓冲区**，把每次 Read 的字节追加进去，循环判断"是否已凑够 长度头→再凑够整条体"，凑够一条切一条，剩余字节留着拼下一条（处理粘包/半包）。按"Read 一次=一条消息"必然在高并发/分片时解析错乱。
5. **设备为何 Passive**：设备固定在位、7×24 监听；主机侧可冗余、可主动调度与重连，由 Active 方掌控连接节奏，多主机/主备切换时策略更清晰。

## 二、参考实现（net8.0，先自己写再对照）

### EquipSim/Program.cs（Passive）
```csharp
using System.Net;
using System.Net.Sockets;
using System.Text;
using EapLab.Transport.Logging;

var log = new ConsoleLogSink();
var listener = new TcpListener(IPAddress.Loopback, 5000);
listener.Start();
log.Log(LogDir.EVT, "Equip Passive listening 127.0.0.1:5000");

while (true)
{
    var client = await listener.AcceptTcpClientAsync();
    log.Log(LogDir.EVT, $"Host connected: {client.Client.RemoteEndPoint}");
    _ = Task.Run(() => ServeClient(client, log)); // 简化：单连接演示
}

async Task ServeClient(TcpClient client, ILogSink log)
{
    var stream = client.GetStream();
    var buf = new byte[4096];
    try
    {
        while (true)
        {
            int n = await stream.ReadAsync(buf);
            if (n == 0) { log.Log(LogDir.EVT, "Host closed(FIN)"); break; }
            var text = Encoding.UTF8.GetString(buf, 0, n);
            log.Log(LogDir.RX, $"raw {n}B: {text}");   // 注意：这里一次 Read 不等于一条消息
            var echo = Encoding.UTF8.GetBytes("ACK:" + text);
            await stream.WriteAsync(echo);
            log.Log(LogDir.TX, $"echo {echo.Length}B");
        }
    }
    catch (Exception ex) { log.Log(LogDir.ERR, ex.Message); }
    finally { client.Dispose(); }
}
```

### HostSim/Program.cs（Active）
```csharp
using System.Net.Sockets;
using System.Text;
using EapLab.Transport.Logging;

var log = new ConsoleLogSink();
using var client = new TcpClient();
try { await client.ConnectAsync("127.0.0.1", 5000); }
catch (SocketException ex) { log.Log(LogDir.ERR, $"连接被拒绝: {ex.SocketErrorCode}"); return; }
log.Log(LogDir.EVT, "Active connected");
var stream = client.GetStream();

_ = Task.Run(async () => // 后台收包
{
    var buf = new byte[4096];
    while (true)
    {
        int n = await stream.ReadAsync(buf);
        if (n == 0) break;
        log.Log(LogDir.RX, Encoding.UTF8.GetString(buf, 0, n));
    }
});

while (true) // 主线程键盘发送
{
    var line = Console.ReadLine();
    if (string.IsNullOrEmpty(line)) continue;
    var data = Encoding.UTF8.GetBytes(line);
    await stream.WriteAsync(data);
    log.Log(LogDir.TX, $"sent {data.Length}B: {line}");
}
```

### 触发粘包的小实验（HostSim 里临时替换发送段）
```csharp
// 不 Sleep 连发三条，观察 Equip 端是否一次 Read 到多条
for (int i = 0; i < 3; i++)
    await stream.WriteAsync(Encoding.UTF8.GetBytes($"MSG{i}"));
```
现象：Equip 端可能一次 RX 就打印 `MSG0MSG1MSG2`——这就是粘包，证明必须靠长度帧切分（Day05 解决）。

## 四、易错点
1. 把一次 Read 当一条消息（W3 编解码会因此解析崩）。
2. 以为 TCP 连通就等于 HSMS 选通（中间还差 Select）。
3. 只处理 FIN（Read=0）不处理半开连接（要靠心跳/T8）。
4. Accept 后不开并发任务，导致第二个连接被阻塞（今天单连接演示即可，W2 再做会话管理）。
