## 二、背景知识（先读，10 分钟）
### 为什么必须分层、且依赖只能向下
真实设备软件就是"传输→编解码→GEM 行为→GEM300 业务"的栈。分层后：
- 下层不认识上层（Transport 绝不引用 Gem），可独立单测；
- 上层复用下层（Gem 用 Secs2 的编解码、Secs2 用 Transport 的帧）；
- 以后加 EDA 第二通道时，新增 Eda 项目复用同一数据源，不污染 SECS 栈。

### 项目划分（与 26 周阶段一一对应）
| 项目 | 类型 | 职责 | 第几周填 |
|---|---|---|---|
| EapLab.Transport | classlib | TCP/HSMS 帧、连接状态 | W2 |
| EapLab.Secs2 | classlib | E5 消息/数据项编解码 | W3-4 |
| EapLab.Gem | classlib | E30 状态机/采集/报警/RCMD | W5-8 |
| EapLab.Gem300 | classlib | E39/E87/E90/E40/E94 | W9-23 |
| EapLab.EquipSim | console | 设备端(Passive)模拟器 | 持续 |
| EapLab.HostSim | console | 主机端(Active)模拟器 | 持续 |
| EapLab.Tests | xunit | 编解码/状态机单测 | 持续 |

引用关系（只允许这些箭头）：
```
EquipSim/HostSim → Gem300 → Gem → Secs2 → Transport
Tests → 全部
```
