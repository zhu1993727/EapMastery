# W18 · Day01 答案与参考实现

## 一、自测题标准答案
1. **四类资源/容量 / 瓶颈**：①存放类——LoadPort 载具槽、Buffer 暂存位（每槽位容量 1）；②搬运类——EFEM 大气机械手、真空机械手（多为双臂，每臂容量 1，一次持一片）；③过渡类——LoadLock（容量 1 或 2，连接大气/真空，有抽破真空时间）、Aligner 对准器（容量 1）；④工艺类——Process Chamber C1/C2/C3（单片腔容量 1，有工艺时长）。真空臂常是瓶颈，因为真空侧所有腔的上下片都要经过唯一的真空臂，它要串行服务多个腔；LoadLock 常是瓶颈，因为跨大气/真空必须经它，且抽真空/破真空耗时长、一次基本只服务一个方向，两侧的并行都要在锁这里排队。
2. **边的含义 / 可达性来源**：拓扑的边代表片可以在两个资源之间**直接搬运**（存在机械臂可达路径/可交接），如 EFEM 臂↔Aligner、EFEM 臂↔LoadLock、真空臂↔各腔。Route 校验的"路径连通"（W16）就从拓扑计算：一个工艺路线相邻 Step 所在模块之间，必须能在拓扑上找到一条由"边"连成的路径（通常还要经指定类型的臂/锁），找不到即 NotReachable，工艺路线物理上不可执行。
3. **LoadLock 互锁 / 作用**：工艺腔要真空、载具端是大气，片不能直接进出，LoadLock 是中间过渡舱：对内关阀抽真空后才能把片交给真空侧，对外破真空回大气才能交给 EFEM，一次只能处于一个方向流程、内部容量有限，且抽/破真空期间不能被另一侧同时使用，因此是互锁资源（同一时刻只允许一个方向/一组占用）。作用是隔离大气与真空环境，让片在两种压力环境间安全过渡，调度必须安排它的方向切换、占用时序，避免两侧争用死锁。
4. **瓶颈资源 / 产能由它决定**：瓶颈资源是整条流水线中单位时间处理能力最小、最易堆积等待的资源（工艺时间最长、或唯一共享资源如单真空臂/LoadLock）。根据约束理论（TOC），系统产出速率不可能超过瓶颈的产出速率，非瓶颈再快也只能等待，所以稳态产能由瓶颈决定。提升产能要优先优化瓶颈：给工艺步骤增加同型并行腔、用双臂交换减少真空臂空程、重叠抽真空与加工等。
5. **三腔并行 60s 稳态产能**：忽略搬运，三片可同时分别在 C1/C2/C3 加工，每腔 60s 出一片，三腔合计每 60s 出 3 片，即稳态约 3 片/60s=**每小时 180 片**（单腔 60 片/小时×3）。注意这是理想上限，实际要扣除搬运、LoadLock、上下片时间，且若真空臂/锁来不及供片，真实瓶颈会转移到搬运资源，产能低于此值。
6. **为何逻辑时钟**：并发调度要验证"不冲突、不死锁、可复现"。真线程的调度时序不确定，同一方案可能这次不碰撞、下次碰撞，难以测试和定位。逻辑时钟用离散时间步推进，每个动作声明占用资源与时间区间 [start,end)，调度器确定性地排布与裁决，结果每次一致、可断言"某时刻某资源被谁占"、易复现死锁与竞争，也方便直接计算完工时间和产能（W11/W15 同一方法）。
7. **InternalLocation 与资源节点关系**：E90 的 InternalLocation（Robot:R1、Aligner、LoadLock、Chamber 等）是从"片位置/不变式"角度建模——每个位置有容量、守唯一/守恒；今天的资源节点是从"调度/占用时间"角度建模——同一物理单元还要带占用时长、能力、可达边、调度状态。二者一一对应、是同一物理实体的两个视图：E90 保证"任一时刻片在资源上的占用不超容量、位置唯一守恒"，资源拓扑/调度决定"片什么时候、以什么顺序占用该资源多久"；调度结果最终仍要经 E90 位置层执行并校验。

## 二、参考实现（net8.0）

### 资源与拓扑
```csharp
namespace EapLab.E40.Sched;
public enum ResKind { Port, AtmosphericRobot, Aligner, LoadLock, VacuumRobot, Chamber, Buffer }
public sealed class Resource
{
    public string Id { get; } public ResKind Kind { get; } public int Capacity { get; }
    public int Occupancy { get; private set; }
    public int ProcSeconds { get; }                       // 一次占用时长(工艺/动作)
    public string ModuleType { get; }                     // 工艺类: 同型腔同类型
    public HashSet<string> Capabilities { get; }
    public bool Faulted { get; set; }
    public Resource(string id,ResKind kind,int cap,int seconds=0,string moduleType="",IEnumerable<string>? caps=null)
    { Id=id;Kind=kind;Capacity=cap;ProcSeconds=seconds;ModuleType=moduleType;Capabilities=new(caps??Array.Empty<string>()); }
    public bool Free => !Faulted && Occupancy<Capacity;
    public bool TryAcquire(){ if(!Free)return false; Occupancy++; return true; }
    public void Release(){ if(Occupancy>0)Occupancy--; }
}
public sealed class ResourceTopology
{
    public Dictionary<string,Resource> Nodes { get; }=new();
    private readonly Dictionary<string,HashSet<string>> _edges=new();
    public ResourceTopology Add(Resource r){Nodes[r.Id]=r;_edges[r.Id]=new();return this;}
    public ResourceTopology Connect(string a,string b)
    { Edge(a,b);Edge(b,a); return this; }
    void Edge(string a,string b){ if(!_edges.ContainsKey(a))_edges[a]=new(); _edges[a].Add(b); }

    public bool Reachable(string from,string to)   // BFS 可达
    { if(from==to)return true; var seen=new HashSet<string>{from}; var q=new Queue<string>(new[]{from});
      while(q.Count>0){ var x=q.Dequeue(); foreach(var y in _edges.GetValueOrDefault(x,new()))
        if(seen.Add(y)){ if(y==to)return true; q.Enqueue(y);} } return false; }
    public IEnumerable<Resource> ByModuleType(string t)=>Nodes.Values.Where(r=>r.ModuleType==t);
    public Resource? Bottleneck(IEnumerable<string> routeModuleTypes)
    { // 教学: 同型并行越多越不瓶颈; 取 (ProcSeconds / 同型可用数) 最大者, 再考虑共享资源
        return Nodes.Values.Where(r=>r.Kind!=ResKind.Port)
            .OrderByDescending(r=> (double)r.ProcSeconds/Math.Max(1,CountSameType(r))).FirstOrDefault();
    }
    int CountSameType(Resource r)=> r.Kind==ResKind.Chamber ? ByModuleType(r.ModuleType).Count() : 1;
}
```

### 集群机拓扑搭建
```csharp
public static class ClusterTool
{
    public static ResourceTopology Build()
    {
        var t=new ResourceTopology()
        .Add(new Resource("LP1",ResKind.Port,25)).Add(new Resource("LP2",ResKind.Port,25))
        .Add(new Resource("EFEM",ResKind.AtmosphericRobot,2,seconds:4))
        .Add(new Resource("AL",ResKind.Aligner,1,seconds:5))
        .Add(new Resource("LL1",ResKind.LoadLock,1,seconds:12))
        .Add(new Resource("VR",ResKind.VacuumRobot,2,seconds:4))
        .Add(new Resource("C1",ResKind.Chamber,1,60,"ETCH"))
        .Add(new Resource("C2",ResKind.Chamber,1,60,"ETCH"))
        .Add(new Resource("C3",ResKind.Chamber,1,60,"ETCH"));
        t.Connect("LP1","EFEM").Connect("LP2","EFEM").Connect("EFEM","AL").Connect("EFEM","LL1")
         .Connect("LL1","VR").Connect("VR","C1").Connect("VR","C2").Connect("VR","C3");
        return t;
    }
}
```

### 产能估算（逻辑时钟，忽略/含搬运对比）
```csharp
public sealed class ThroughputEstimator
{
    // n片, m个同型腔各proc秒, 稳态吞吐(片/小时); 理想忽略搬运
    public static double ParallelChamberWph(int m,int procSec)=> Math.Round(3600.0*m/procSec,1);
    // 完工时间: 首片(m步启动)后, 瓶颈节拍出片(教学模型)
    public static int Makespan(int n,int m,int procSec,int bottleneckBeatSec)
    { int first=procSec; int rest=(n-1)*bottleneckBeatSec; return first+rest; }
}
```

## 四、今日易错点
1. 只建工艺腔、忽略臂/锁也是有限容量资源（真空臂、LoadLock 往往才是瓶颈）。
2. 不区分大气侧/真空侧（跨侧必须经 LoadLock，且有抽破真空时间与方向互锁）。
3. 以为腔越多线性提速（真实产能受真空臂/锁节拍限制，瓶颈会转移）。
4. 拓扑不建"边"，无法计算工艺路线可达性。
5. 用真线程模拟并发占用（逻辑时钟确定性、可算完工时间、可复现）。
6. 把 E90 位置视图和资源调度视图混为一谈（同一物理实体两视图，位置守不变式、调度排时间）。
7. 忽略资源能力标签（异型腔不能跑任意工艺，同型才可替换并行）。
8. 容量只看腔（双臂/锁/对准器容量也要建模，双臂每臂仍容量 1）。
