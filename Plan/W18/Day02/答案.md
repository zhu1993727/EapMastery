# W18 · Day02 答案与参考实现

## 一、自测题标准答案
1. **调度器/执行器/E90 分工 / 为何分开**：调度器只做"计划"——根据资源容量、拓扑、前驱关系，用逻辑时钟算出每个动作在什么时间占用哪些资源、冲突时何时开始，产出确定性调度表，不真正动硬件；执行器（PJ 状态机驱动）按调度表在真实时序下发动作、推进片/步状态；E90 位置层是唯一真正改片位置的地方，执行器的取放都经它并校验不变式。分开是职责分离：调度是可离线重算、可测试的纯规划（错了重排即可，无物理后果），执行涉及真实时序与反馈，位置层负责物理一致性；这样调度算法可独立单测、可在故障后重排，而物理安全始终由 E90 兜底，避免"规划逻辑"和"物理改动"耦合出错。
2. **时间区间互斥 / 最早开始**：容量 1 资源维护已占用区间集合，新动作请求时长 d、期望 t 开始时，把 [t,t+d) 与已有区间逐一比较，若与某 [s,e) 重叠（t<e 且 s<t+d），则最早可开始时间至少为 e（该冲突区间结束），再用新区间继续检查后续区间，直到找到一段长度≥d 的空隙，其起点即最早可行开始。容量 c 资源则允许同一时刻最多 c 个重叠区间，超过 c 才顺延。本质是把"资源一次只能被一个动作占用"转化为时间轴上区间不重叠的可计算约束，无需真线程锁。
3. **死锁四条件 / 打破哪条**：①互斥（资源一次一用）；②持有并等待（持 A 等 B）；③不可剥夺（只能占用者释放，不能强抢加工中的腔）；④循环等待（动作-资源等待成环）。设备上前三条由物理特性决定难以消除（腔不能同时两片、不能从正在加工的动作手里抢），工程上主要打破第④条循环等待：用全局固定资源申请顺序让等待关系不可能成环，再辅以资源分配图找环检测、等待超时、Buffer 打破位置占用环（W15 单臂交换）。
4. **固定顺序为何消除循环等待**：给所有资源一个全局全序（如按资源 ID 排序），规定任何动作需要多个资源时，只能按这个顺序从小到大申请、逆序释放。于是一个动作只有在拿到排序更靠前的资源后才会去等更靠后的资源，它不可能"持有靠后资源去等靠前资源"；等待边在全局序上永远只从低序指向高序，不可能形成首尾相接的环，循环等待条件不成立，死锁从结构上被消除。
5. **all-or-nothing 解决什么**：解决"持有并等待"造成的部分占用阻塞——动作需要 A、B 两个资源，若先锁住 A 再等 B，会占着 A 阻塞别人、自己也卡住，易促成死锁。all-or-nothing 预留：先检查所需资源是否此刻都能满足，能则一次性原子拿齐，不能则一个都不占、整体进入等待（不留下部分持有），等到可满足再原子分配。这样等待中的动作不持有任何资源，消除"持有并等待"，配合固定顺序进一步杜绝死锁。
6. **防饥饿**：纯优先级调度会让高优先级动作不断插队、低优先级永远排不上。用"优先级 + 到达次序 + 老化（aging）"：资源释放时从等待队列选优先级最高者，同优先级严格 FIFO（先到先得），并让等待越久的动作有效优先级逐渐提升（老化），保证任何动作等待时间有上界、最终都会被服务，从而无饥饿；同时 tie-break 规则固定，保证调度确定、可复现。
7. **超时/故障重调度**：调度表是基于预估时间的计划，实际动作超时或资源故障时，①冻结/中止受影响动作（经状态机与 E90 保证片到安全点）；②把故障资源标记不可用、把已完成动作和已确定位置作为既定事实锁定（不重排已发生的）；③对未开始/被阻塞动作，基于当前时刻与最新资源状态重新计算时间区间（reschedule），把原计划改派到可用同型资源或顺延；④若涉及在途片，先按 E90 确认其实际位置再重排。即"已发生的不回退、未发生的按新现实重算"。

## 二、参考实现（net8.0）

### 资源日程表（时间区间互斥）
```csharp
namespace EapLab.E40.Sched;
public sealed record Interval(int Start,int End);
public sealed class ResourceCalendar
{
    public string ResourceId { get; } public int Capacity { get; }
    private readonly List<Interval> _booked=new();
    public ResourceCalendar(string id,int cap){ResourceId=id;Capacity=cap;}
    public IReadOnlyList<Interval> Booked=>_booked;

    // 期望from开始, 时长dur, 返回最早可行开始(容量约束: 同时重叠<=Capacity)
    public int EarliestStart(int from,int dur)
    {
        int t=from; bool moved;
        do{ moved=false;
            foreach(var iv in _booked.OrderBy(x=>x.Start))
            { int overlap=OverlapCount(t,t+dur);
              if(overlap>=Capacity && t<iv.End && iv.Start<t+dur){ t=iv.End; moved=true; break; } }
        }while(moved);
        return t;
    }
    int OverlapCount(int s,int e)=>_booked.Count(iv=>s<iv.End && iv.Start<e);
    public void Book(int s,int e)=>_booked.Add(new Interval(s,e));
}
```

### 动作与调度器
```csharp
public sealed class SchedAction
{
    public string Id=""; public List<string> Needs=new(); public int Duration; public int ReadyAt;
    public int Priority; public int Arrival; public int? Start; public int? End;
}
public sealed class GlobalScheduler
{
    private readonly Dictionary<string,ResourceCalendar> _cal=new();
    private readonly Dictionary<string,string> _holder=new();   // 资源->动作(分配图)
    private readonly Dictionary<string,HashSet<string>> _waits=new(); // 动作->等待的资源
    public GlobalScheduler(IEnumerable<Resource> rs){foreach(var r in rs)_cal[r.Id]=new(r.Id,r.Capacity);}

    // all-or-nothing + 固定顺序申请: 资源按ID全序, 要么一次拿齐, 要么不持有
    public bool TryAcquireAll(SchedAction a,int now)
    {
        var ordered=a.Needs.OrderBy(x=>x,StringComparer.Ordinal).ToList(); // 全局固定顺序
        var proposed=new List<(string,int)>();
        int start=Math.Max(a.ReadyAt,now);
        foreach(var r in ordered)
        { var cal=_cal[r]; int s=cal.EarliestStart(start,a.Duration); proposed.Add((r,s)); start=s; }
        // 任一日程起点晚于"立即可用"则视为现在拿不齐 -> 不部分持有, 进入等待
        bool allNow = proposed.All(p=>p.Item2==Math.Max(a.ReadyAt,now));
        if(!allNow){ foreach(var r in ordered)_waits.GetOrAdd(a.Id).Add(r); return false; }
        foreach(var (r,s) in proposed){ _cal[r].Book(s,s+a.Duration); _holder[r]=a.Id; }
        a.Start=now; a.End=now+a.Duration; _waits.Remove(a.Id); return true;
    }

    // 资源分配图找环(循环等待检测)
    public bool HasCycle()
    { var graph=new Dictionary<string,string>();           // 动作等待资源, 资源被动作持有 -> 动作->持有动作
      foreach(var (a,rs) in _waits)
        foreach(var r in rs) if(_holder.TryGetValue(r,out var owner) && owner!=a)
            graph[a]=owner;
      var seen=new HashSet<string>();
      foreach(var n in graph.Keys){ var path=new HashSet<string>(); string? x=n;
        while(x is not null){ if(!path.Add(x))return true; if(!graph.TryGetValue(x,out x))break; } }
      return false;
    }
}
static class DictExt{ public static HashSet<string> GetOrAdd(this Dictionary<string,HashSet<string>> d,string k)
  { if(!d.ContainsKey(k))d[k]=new(); return d[k]; } }
```

### 公平等待队列（优先级+FIFO+老化）
```csharp
public sealed class WaitQueue
{
    public sealed class Waiter{ public string Id=""; public int Priority,Arrival; public int Age; }
    private readonly List<Waiter> _q=new();
    public void Enqueue(string id,int pri,int now)=>_q.Add(new(){Id=Id,Priority=pri,Arrival=now});
    public void Tick(){ foreach(var w in _q)w.Age++; }      // 老化
    public string? Dequeue()
    { if(_q.Count==0)return null;
      var pick=_q.OrderByDescending(w=>w.Priority+w.Age/5) // 老化提升有效优先级
                 .ThenBy(w=>w.Arrival).First();            // 同优先级FIFO
      _q.Remove(pick); return pick.Id; }
}
```

### xUnit
```csharp
public class SchedulerTests
{
    static List<Resource> Res()=>new(){new("C1",ResKind.Chamber,1,60),new("C2",ResKind.Chamber,1,60),
        new("VR",ResKind.VacuumRobot,2,4)};
    [Fact] public void 容量1区间冲突_顺延到结束()
    { var cal=new ResourceCalendar("C1",1); cal.Book(0,60);
      Assert.Equal(60,cal.EarliestStart(0,60));             // 0-60占用, 最早60
      Assert.Equal(0,cal.EarliestStart(60,60)); }
    [Fact] public void 固定顺序拿不齐_不部分持有()
    { var s=new GlobalScheduler(Res());
      var a=new SchedAction{Id="A",Needs=new(){"VR","C1"},Duration:60};
      Assert.True(s.TryAcquireAll(a,0));                    // 首次拿齐
      var b=new SchedAction{Id="B",Needs=new(){"C1","VR"},Duration:60}; // 故意逆序, 内部仍排序
      Assert.False(s.TryAcquireAll(b,0));                   // C1忙, 现在拿不齐->等待, 不持有VR
      Assert.False(s.HasCycle()); }
    [Fact] public void 同型两腔_可并行不同腔()
    { var s=new GlobalScheduler(Res());
      var a=new SchedAction{Id="A",Needs=new(){"C1"},Duration:60};
      var b=new SchedAction{Id="B",Needs=new(){"C2"},Duration:60};
      Assert.True(s.TryAcquireAll(a,0)); Assert.True(s.TryAcquireAll(b,0));
      Assert.Equal(0,a.Start); Assert.Equal(0,b.Start); }
    [Fact] public void 等待队列_同优先级FIFO_老化提升()
    { var q=new WaitQueue(); q.Enqueue("lo",1,0); q.Enqueue("hi",2,0);
      Assert.Equal("hi",q.Dequeue());
      for(int i=0;i<20;i++)q.Tick();                        // lo老化
      q.Enqueue("hi2",2,20);
      Assert.Equal("lo",q.Dequeue()); }                     // 老化后lo被服务, 不饥饿
}
```

## 三、死锁规避要点（手绘参考）
```
潜在死锁: 甲持VR等C1, 乙持C1等VR → 等待环
打破(固定全序申请, 如按ID): C1 < VR
  任何动作先申请C1再申请VR, 不可能"持VR等C1" → 无环
再加 all-or-nothing: 拿不齐就一个不占, 等待中不持有资源
运行期: 资源分配图找环兜底 + 等待超时 + Buffer打破位置环(W15)
公平: 优先级+同级FIFO+老化, 等待有上界不饥饿
```

## 四、今日易错点
1. 调度器直接改片位置（只排计划，真正改位置经 E90）。
2. 用真线程锁表达互斥（用时间区间，确定性、可算完工时间）。
3. 容量 1 资源区间重叠仍安排（必须顺延到不重叠空隙）。
4. 多资源不按固定顺序申请（制造循环等待死锁）。
5. 拿不齐资源还部分持有（持有并等待，应 all-or-nothing 全释放等待）。
6. 纯优先级导致饥饿（同级 FIFO + 老化保证上界）。
7. 故障重排时把已完成动作也重排（已发生锁定，只重算未发生）。
8. tie-break 不固定导致调度不可复现（固定排序规则）。
