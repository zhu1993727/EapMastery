# W18 · Day02（周二）全局资源调度器：互斥、时间区间与死锁规避

> 建议时长：95 分钟。在资源拓扑之上做一个全局调度器：为每个动作分配资源与时间区间，保证互斥不冲突、可等待排队，并从原理上规避死锁。这是多腔并发正确运行的核心。

## 一、今日目标
1. 实现全局资源调度器：资源预约（reserve）、占用（acquire）、释放（release）与时间区间。
2. 用时间区间保证互斥：同一资源的占用区间不重叠（容量>1 按容量）。
3. 掌握死锁四必要条件与规避：固定资源申请顺序、资源分配图找环、超时与回退。
4. 实现动作等待队列与公平调度（防饥饿）。
5. xUnit 覆盖区间冲突、固定顺序无死锁、环检测、公平等待。

## 二、背景知识（先读，30 分钟）

### 1. 调度器职责
- 输入：一系列待执行动作（每片每步的取/转/加工），每个动作声明所需资源集合、占用时长、前驱约束。
- 输出：为每个动作安排开始/结束时间（逻辑时钟），满足：资源容量互斥、前驱先后、拓扑可达，且尽量并行、无死锁、无饥饿。
- 它不真正搬片（执行器经 E90 做），只决定"谁在什么时候能用哪些资源"。

### 2. 时间区间互斥
- 资源 r 在时间轴上维护占用区间列表 [s,e)；新动作请求 [t,t+d) 时，检查与已有区间是否重叠，重叠则最早可开始时间顺延到冲突区间结束。
- 容量 c 的资源允许至多 c 个重叠区间（腔容量 1 严格不重叠；双臂资源容量 2）。
- 由此可算出每个动作的最早可行开始时间，形成确定性调度表（Schedule）。

### 3. 死锁四必要条件（经典）
1. 互斥：资源一次只能被一个动作占用（腔/臂天然如此）。
2. 持有并等待：动作持有资源 A 同时等待资源 B。
3. 不可剥夺：资源只能由占用者主动释放（不能强抢正在加工的腔）。
4. 循环等待：存在动作-资源等待环。
- 前三条在设备上难以消除，工程上主要打破第 4 条**循环等待**：规定所有动作按全局固定顺序申请资源（如按资源 ID 排序加锁），等待关系不成环。
- 辅以：资源分配图实时找环检测、等待超时、Buffer 打破位置占用环（W15）。

### 4. 固定顺序申请（重点）
- 任意动作需要多个资源时，按资源 ID 的全局全序排序后依次申请，逆序释放。
- 这样不会出现"甲持 A 等 B、乙持 B 等 A"的环（后申请者不会持有排序靠后的资源去等靠前的）。
- 结合"申请要么一次拿齐、拿不齐就全部释放重排"（all-or-nothing 预留），避免持有并等待造成的阻塞。

### 5. 等待队列与公平
- 资源忙时动作进入该资源等待队列，按优先级+到达顺序（FIFO）服务，防止某动作永远被插队（饥饿）。
- 调度确定性：相同输入产出相同调度表（逻辑时钟 + 固定 tie-break 规则）。

### 6. 调度与状态机/位置层关系
- 调度器产出"计划时间区间"；执行时 PJ 状态机驱动、E90 位置层真正迁移；若实际偏离（动作超时/故障），重新调度（reschedule），已完成的不重排。
- Pause/Abort 时释放或冻结相关资源预约（Day06 并发演练）。
