# W18 · Day06 答案与参考实现

## 一、自测题标准答案
1. **并发 Pause 为何不能立即整体停 / 等哪些单元**：暂停请求时刻，多个并发单元可能处于不可立即停止的状态（腔内化学反应中、臂在两位置间运动、锁在抽真空半程），立即"冻结"会让片停在非安全点、工艺中断在不可续位置、甚至机械/压力不安全。必须等**所有正在执行的并发单元**都到各自安全点：在腔片跑完当前不可中断 Step 到步骤/片边界、在臂片完成当前取放到稳定位、锁里的片完成当前抽/破真空到稳定状态、干涉区动作结束。当且仅当全部并发单元安全、资源可保持、账目一致，才整体 Paused（一个 Job 只有一个 Paused，不是每片各停各的）。
2. **腔中片与臂上片的安全点**：腔内化学反应中的片不能在反应中途停，要让当前工艺 Step 完整跑到结束（或工艺允许的安全中止边界），片处于"该步完成、可续/可重做、腔状态稳定"的边界才算安全点，期间任务保持 Pausing；臂上的片要完成当前这次取/放动作，把片放到确定稳定位置（目标槽/锁/腔/稳定持片位），不能停在两位置间的运动半程。即工艺片等工艺边界、运动片等运动到位，二者都安全后整体才 Paused。
3. **并发 Abort 并行三分类 / 释放顺序**：先立即停止调度新片/新步；对当前所有并发单元，先让不可中断单元到安全点（同 Pause），然后并行分类：已完成归位片保持不动（登记成果）；在途片（在腔/臂/锁）各自经 E90 退到源槽或安全 Buffer/稳定位，逐片记实际位置；未开始片留在源槽不动。资源释放顺序：先让在途片离开工艺/搬运资源到稳定位（释放腔、臂、锁的占用），再释放这些资源的预约；需要保持的（如真空压力）按设备能力保留；最后锁相关载具。释放必须在片安全离开资源之后，不能先释放资源导致片"悬在"已释放资源上，全程每拍守恒。
4. **在腔片 vs 等待片为何根本不同**：等待片还没进入故障腔、仍在源/锁/臂或队列中，它与故障腔没有物理耦合，只需调度层把目标腔从 C2 改派到健康同型腔即可，是纯计划变更、无损失；在腔片已经在故障腔内、工艺被物理中断，它的工艺完整性可能受损（反应到一半），必须走故障处置——判断该步完成/需返工/报废、安全撤出或保持、发 Alarm/Fault、记录中断点，不能简单"换个腔继续"（半成品工艺状态未知）。一个是未发生可改派，一个是已中断要善后，本质区别。
5. **重调度如何不重做已完成片**：重调度只作用于"未开始/被阻塞"的动作，已完成片的完成事实（WaferState.Completed、实际位置、经过的 Step/腔）作为既定事实锁定，不进入重调度集合；调度器以当前时刻为起点、只对未完成片重新排时间区间和选腔，续跑 PJ/计划显式排除 Completed 片（W17 Day04 BuildResumePj 同法）。即"已发生的不回退、未发生的按新现实重算"，从输入集合上保证已完成片不会被再次加工。
6. **并行/串行 Makespan 差异 / 加速上限**：串行 6 片只有 C1 工作，每片走完整流程且互不重叠，Makespan≈6×单片全流程；并行时三腔同时加工、EFEM/VR/锁流水线重叠，工艺时间被三腔分摊、搬运与加工重叠，Makespan≈首片全流程+(6-1)×瓶颈节拍。差异来自"同型腔并行"和"搬运加工重叠"。加速比上限由瓶颈决定：若工艺是瓶颈且有 3 同型腔，工艺段最多加速近 3 倍；但真空臂/LoadLock 若供片不及，瓶颈转移到搬运资源，实际加速比低于腔数——非瓶颈环节再快也无法突破瓶颈节拍。
7. **哪些机制共同保证并行不出物理错**：①资源建模与时间区间互斥（同资源不重叠、容量约束，Day02）；②固定顺序申请+all-or-nothing+找环（无死锁，Day02）；③选腔只在健康可用同型腔、资源不相交才并行（Day03）；④双臂 Swap/锁压力互锁保证交接安全（Day04）；⑤所有位置迁移只经 E90 原子 Move、每拍断言唯一/容量/守恒（Day05、W14）；⑥Job 单一状态机+逐片独立进度+严格完成守卫（W17）；⑦故障/暂停/中止都先到安全点、已发生不回退。规划层防冲突、位置层守物理、状态层守任务，三层叠加才让"高并行"与"物理绝对正确"同时成立。

## 二、参考实现（net8.0，综合实验骨架）

### 并发安全点栅栏（所有并发单元到安全点才整体 Paused）
```csharp
namespace EapLab.E40.Runtime;
public sealed class ConcurrentPauseBarrier
{
    private readonly HashSet<string> _activeUnits;   // 当前在执行的并发单元(片:阶段)
    public ConcurrentPauseBarrier(IEnumerable<string> units){_activeUnits=new(units);}
    public void ReachSafe(string unit){ _activeUnits.Remove(unit); }
    public bool AllSafe => _activeUnits.Count==0;    // 全部到安全点
}
```

### 并发 Abort 分类处置
```csharp
public sealed class ConcurrentAbort
{
    private readonly SubstrateTracker _t; public ConcurrentAbort(SubstrateTracker t){_t=t;}
    public AbortSnapshot Run(ProcessJob job,Func<string,bool> canReturnToSource)
    {
        var snap=new AbortSnapshot();
        foreach(var wp in job.Wafers.Values)
        { var loc=_t.LocationOf(wp.WaferId).Key;
          switch(wp.State)
          { case WaferState.Completed: snap.Wafers.Add((wp.WaferId,WaferClassAtAbort.Completed,loc,wp.CurStepNo)); break;
            case WaferState.Waiting:   snap.Wafers.Add((wp.WaferId,WaferClassAtAbort.NotStarted,loc,wp.CurStepNo)); break;
            default: // 在途: 能退源则经E90退, 否则安全保持
              if(canReturnToSource(wp.WaferId) && loc.StartsWith("Internal"))
                 _t.ReturnToSource(wp.WaferId);   // 教学辅助: 经位置层安全退回
              snap.Wafers.Add((wp.WaferId,WaferClassAtAbort.InFlight,_t.LocationOf(wp.WaferId).Key,wp.CurStepNo)); break; }
        }
        _t.AssertInvariants(); return snap;
    }
}
```

### 腔故障重调度
```csharp
public sealed class FailureRescheduler
{
    private readonly ChamberSelector _sel; public FailureRescheduler(ChamberSelector s){_sel=s;}
    // 受影响(在故障腔)片走故障处置; 等待片改派; 已完成锁定不动
    public Dictionary<string,string> Reassign(string faultedChamber,
        List<(string wafer,string assigned,bool entered,bool done)> inflight,
        Func<string,List<ChamberCandidate>> candidatesOf)
    {
        var reassigned=new Dictionary<string,string>();
        foreach(var (w,ass,entered,done) in inflight)
        {
            if(done) continue;                                  // 已完成: 锁定不重排
            if(entered && ass==faultedChamber)
                throw new FaultedWaferNeedsHandling(w);          // 在腔片: 走故障处置, 不改派了事
            if(ass==faultedChamber || !entered)                 // 未进片: 排除故障腔改派
            { var cs=candidatesOf(w).Where(c=>c.Id!=faultedChamber).ToList();
              var(id,_)=_sel.Choose("", "",cs); reassigned[w]=id; }
        }
        return reassigned;
    }
}
public sealed class FaultedWaferNeedsHandling : Exception{ public FaultedWaferNeedsHandling(string w):base($"{w}在故障腔,需故障处置"){} }
```

### 实验编排（剧本断言）
```csharp
public class ClusterLabTests
{
    [Fact] public void 实验1_并行快于串行_全程守恒()
    { var par=RunSixWafers(parallel:true); var ser=RunSixWafers(parallel:false);
      Assert.True(par.Makespan < ser.Makespan);
      par.Tracker.AssertInvariants(); Assert.Equal(6,par.Tracker.TotalInside+par.Tracker.InCarriers);
    }
    [Fact] public void 实验2_并发Pause_全部安全点才Paused_恢复不重不漏()
    { var run=RunSixWafers(parallel:true);
      run.RequestPauseAt(20);                                   // 一在腔一在臂一在锁
      var barrier=run.PauseBarrier!;
      Assert.False(barrier.AllSafe);                            // 还有单元没到安全点 -> Pausing
      run.AdvanceUntilAllSafe();
      Assert.True(barrier.AllSafe); Assert.Equal(JState.Paused,run.JobState);
      var before=run.WaferLocations();
      run.Resume(); run.AdvanceToEnd();
      Assert.Equal(before.OrderBy(x=>x.Key), run.WaferLocations().OrderBy(x=>x.Key)); // 最终一致
    }
    [Fact] public void 实验3_并发Abort_三分类_终态不Resume()
    { var run=RunSixWafers(parallel:true); run.AdvanceTo(40);  // 2完成2在途2未开始
      var snap=run.Abort();
      Assert.Equal(2,snap.Wafers.Count(x=>x.Class==WaferClassAtAbort.Completed));
      Assert.Equal(2,snap.Wafers.Count(x=>x.Class==WaferClassAtAbort.InFlight));
      Assert.Equal(2,snap.Wafers.Count(x=>x.Class==WaferClassAtAbort.NotStarted));
      run.Tracker.AssertInvariants();
      Assert.Throws<InvalidOperationException>(()=>run.Resume());
    }
    [Fact] public void 实验4_C2故障_在腔片处置_等待片改派_完工守恒()
    { var run=RunSixWafers(parallel:true); run.AdvanceTo(15);
      var ex=Record.Exception(()=>run.FaultChamber("C2"));     // 在C2的片需处置
      Assert.Null(ex?? ((ex is FaultedWaferNeedsHandling)?null:ex));
      run.HandleFaultedWaferThenReschedule("C2");
      run.AdvanceToEnd(); run.Tracker.AssertInvariants();
      Assert.DoesNotContain(run.NewAssign.Values,x=>x=="C2");  // 未进片不再派C2
    }
    // RunSixWafers: 组装 ClusterTool拓扑+Planner+Selector+ConcurrentExecutor+Tracker+JobFsm 的实验台(整合本周代码)
}
```

## 三、四实验时间线（手绘参考）
```
实验1: 甘特行 EFEM/LL1/LL2/VR/C1/C2/C3; 看C行铺满=瓶颈; Makespan=首片+5*beat
实验2: t=20 Pause -> Pausing; 各单元到安全点(腔到步边界/臂到位/锁稳定)
       -> 栅栏AllSafe -> Paused(含全部并发片Token) -> Resume -> 结果同基线
实验3: Abort -> 停调度 -> 完成片不动/在途退源或保持/未开始留源 -> 释放资源锁载具
       -> Aborted(不Resume) -> 续跑PJ只含未完成片,源=实际位置
实验4: C2故障 -> 在C2片: 中断步+撤出/保持+Alarm; 等待片: 排除C2改派C1/C3
       -> 已完成锁定 -> 剩余完工守恒
```

## 四、实验报告要点（结论参考）
- 实验1：三腔并行+流水线，工艺段近 3 倍加速；真实 Makespan 受 VR/LL 节拍限制，加速比<腔数；全程守恒=6。
- 实验2：Paused 时刻晚于请求时刻（等最慢并发单元到安全点）；Resume 后最终每片位置与无暂停基线完全一致，证明不重不漏。
- 实验3：三分类数量与剧本一致（2/2/2），在途片退源或安全保持后守恒；Aborted 拒绝 Resume，续跑 PJ 只含 4 片未完成。
- 实验4：C2 在腔片走故障处置（不直接改派），其余等待片改派健康腔，已完成片不重做，重调度后守恒完工。

## 五、今日易错点
1. 并发 Pause 一请求就整体 Paused（必须栅栏等所有并发单元到安全点）。
2. 反应中途的片被立即冻结（跑到工艺边界才算安全点）。
3. 并发 Abort 先释放资源再撤片（必须片先安全离开资源再释放）。
4. 把故障腔里的半成品片直接改派别的腔（工艺状态未知，走故障处置）。
5. 重调度把已完成片也重新排（已完成锁定，只重排未完成）。
6. 以为腔数=加速比（瓶颈在臂/锁时加速比受节拍限制）。
7. 并行路径上省略逐拍不变式断言（并发更要每拍查唯一/容量/守恒）。
8. 每个并发片各设一个 Job Paused（一个 Job 一个整体状态，栅栏汇聚）。
