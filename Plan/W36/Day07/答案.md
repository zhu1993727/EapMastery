# W36 · Day07 答案（最终综合答辩卷 + 收官）

## 一、最终综合答辩卷（7 题）参考答案

**1. 一片晶圆从派工到良率（5 分钟白板）**
MES 建工单/释放 Lot→dispatch 派工并预约（能力/资格/状态/配方硬约束）→AMHS 经 E84 搬 Carrier 到设备→E87 装载绑定 Carrier↔Lot→E90 SlotMap 对片三不变式→RMS 确认 PPID 版本 hash 一致→S2F41 建 E40 PJ/E94 CJ→PP-Select 回读、五门全过 Start（S6F11 JobStarted 生效）→加工中 EDA 高频 trace 进 EDC、实时流给 FDC 保安全，GEM S6F11 做 Step/作业分段，上一 run 量测/VM 经 R2R 算 overlay 由 RMS→GEM 只调 knob→逐片终态、PJ/CJ Completed，EAP 聚合片/批结果与质量门、数据在 EDC 就绪→质量判定后 MES Move 过账、扣消耗、写谱系，AMHS 搬往下工序→逐道工序重复→量测/缺陷/良率汇入 YMS 与过程数据关联。控制流一条竖线（MES→EAP→GEM→设备，EDA 只读），数据流两股（高频 EDA→EDC、稀疏事件 GEM→EAP→MES）。全程以设备 FSM 为物理事实源、MES 为业务事实源、RMS 为配方事实源、EDC 为数据事实源。

**2. 为何同时要 GEM 和 EDA、如何共享又隔离**
GEM(HSMS/SECS) 是一对一、面向控制与稀疏作业/报警事件的通道，保证单一受控授权、命令握手与状态机一致；EDA/Interface-A 是多客户端订阅、10Hz–1kHz 高频连续只读通道，服务 FDC/VM 等多方数据消费。二者共享同一设备数据总线这一事实源，但暴露不同视图：GEM 侧拿可写 `IDataBus`，EDA 侧只拿 `IReadOnlyDataBus`（编译期无写方法），并用架构约束测试保证分析层不引用控制命名空间。隔离体现在：EDA 高频拥塞/某客户端慢不阻塞 GEM 控制，GEM 重连不影响 EDA 订阅恢复机制，故障域分开；下行控制永远只走 GEM，EDA 即使多客户端也无法写设备，兼顾数据开放与控制安全。

**3. E87/E90/E40/E94 分工与衔接、多腔跨 FOUP**
E87 管 Carrier 生命周期（NotInstalled→Installed→Loaded→Unloaded，Loaded 唯一自动取片）与 Carrier↔Lot 绑定；E90 管片在槽的位置（SlotMap 三态、三不变式、25 槽 1-based/MSB-first）；E40 管加工作业 PJ（哪些槽用什么 recipe 在哪些腔怎么加工，三正交、Queued/Received→Started→Executing⇄Pausing⇄Paused→Completed/Cancelled/Aborted/Failed）；E94 管调度控制 CJ（组织 PJ 顺序、CJ→PJ→Wafer/Step 级联两层栅栏、幂等 Resume）。衔接：E87 装载→E90 对片→E40/E94 才允许建作业启动，片的身份由 E90 提供、作业由 E40/E94 消费。多腔/跨 FOUP：每腔独立作业与故障域，跨 Carrier 片按 SlotMap 精确指定 source/destination slot，全序 all-or-nothing（任一必要片/腔失败整作业不部分生效），级联栅栏保证 CJ 未放行 PJ 不动、PJ 未到点 Wafer 不动，谁设 Hold 谁解，谱系精确到腔/片。

**4. R2R 闭环与安全机制**
量测融合（inline/offline 实测优先、高置信 VM 补盲，低置信/OOD 不进控制）→EWMA/dEWMA 在量测可靠时更新状态（坏量测不更新、hold-last-good）→控制律算 overlay（只含增量 Δ、带作用域=腔/Lot/片/有效期与 ReqId、只动授权 knob）→安全约束：步长限幅（单次最大调整）、死区（小偏差不动作防抖）、控制限（撞限冻结转人工）、多层优先级（片>Lot>腔>基线）、绑配方版本（主档升级旧 overlay 失效）、all-or-nothing→经 RMS→GEM 下发，握手 Idle→Sent→Accepted(ACK 仅受理)→Loaded→Effective(回读一致+S6F11)，幂等重发不叠加、失败回滚→多腔各腔独立 EWMA/overlay、C2O 各腔对目标、C2C 腔间对齐、量测按片归属依赖 E90/E40/E94 谱系、单腔故障隔离、保养换件重置该腔；连续无有效量测即停自动。R2R 不改主档（永久变更走 ECN）。

**5. FDC/VM/SPC/EDC 协作与降级**
EDC 统一接入 EDA 高频与 GEM 事件，做 canonical/WKN 归一、谱系绑定、源时间对齐（水位线）、质量码治理（只降不升）、分层存储与实时/历史服务；FDC 订阅实时流，Good 才按 Step 分段做规则/PCA 检测、秒级保安全；VM 用历史/实时 trace 按 Step 提特征出片级预测+置信区间+OOD；SPC 用聚合数据跨批判稳与 Cpk。一次质量判定：FDC 管 run 内有无异常、VM 补未量测片的预测、SPC 判断批次是否受控/对中，结论与量测共同决定放行/Hold。数据差时优雅降级：Bad/Gap 不判工艺且跨缺口重置、VM 关键特征非全 Good 则降置信或不出预测、R2R 无可靠量测不更新并 hold-last-good、SPC 坏点不入图，长期 Bad 报"监控失明"告警并评估失明期产品——宁可少动作/不出结论，也不基于坏数据决策，且每次不动作都留数据质量事件。

**6. 断线+疑似串批+配方版本不符同时出现的处置顺序**
按"安全与正确性优先、先止损后查因、控制收敛到设备事实"排序：①立即停止/冻结一切下行新指令与该设备相关 Lot 的过账流转（防脑裂、防错误扩大）；②以设备 FSM 为准取现场真相——E87/E90 实物与绑定、当前 PPID+hash、作业状态，先判定串批：若 Carrier↔Lot 或 SlotMap 与 MES 期望不符，拒一切开工/继续、保持安全态、锁现场核对实物（串批是最高严重度，绝不带疑生产）；③配方版本不符则不允许用本地版本将就，走 RMS 受控分发/回正确版本并回读一致，期间不得加工；④通信恢复后按 W22 重连对账（HSMS→E87→E90→E40/E94→Spool），再与 MES WIP 对齐，用 EDC 源时间重建时间线，判断断线期实际加工了哪些片；⑤where-used 圈定所有可能受串批/错配方影响的片并隔离复检；⑥三类问题分别闭环（通信/对账、身份/流程根因、配方管控），受影响片按质量规则放行/返工/报废；⑦横向预防（绑定校验门、配方写保护与审计、对账前置）。理由：身份错误（串批）和配方错误会直接产出废片且污染谱系，优先级高于通信恢复；先冻结再核对，避免在真相未明时用过期/错误状态做动作。

**7. 新产线 EAP/EDA/APC 分阶段上线与验收**
- 阶段0 标准与规格：确定 SEMI 标准版本（E5/E30/E37/E87/E90/E40/E94/E116/E10、EDA E120/E125/E132/E134/E164 Freeze 版本）、客户/厂内 ICD、点表与数据契约、CIM 接口矩阵。
- 阶段1 单设备打通：HSMS/GEM 连接、控制状态机、采集三层、远程命令、Spool；用仿真器+抓包验证报文与状态迁移。
- 阶段2 GEM300：E84 握手、E87 装载、E90 SlotMap、E40/E94 作业全状态机与异常分支，门控与对账，逐场景故障注入。
- 阶段3 EDA/EDC：CEM 建模、DCM 采集计划、认证多客户端会话、Freeze 编码、双通道只读隔离，按需求反推频率、跑完整率/延迟 P95/P99/质量码 SLA。
- 阶段4 APC/RMS：RMS 分发一致性与 PP-Select、FDC 规则与报警生命周期、R2R 闭环（先 shadow 模式只建议不控、观察后再投自动）、VM/SPC。
- 阶段5 MES 端到端：派工→全链路 12 阶段→过账谱系、三方对账、断线/串批/错配方演练。
- 阶段6 验收：全量 build/test+架构约束测试、SAT 场景清单（正常+异常+性能+长稳）、SLA 与 OEE 度量、文档与培训、灰度放量。每阶段设准出闸门（功能、异常、性能、可追溯），上一阶段不达标不进下一阶段。

## 二、费曼总讲三问参考
- **EAP 是什么/为何缺它不可**：FAB 里 MES 等业务系统说的是"工单、批次、良率"的语言，设备说的是 SECS/GEM、状态机、寄存器和毫秒时序的"方言"，而且要 7×24 安全可控地跑。EAP 就是站在每台设备旁的"翻译兼工头"：把上层指令翻译成设备能执行的时序动作并做一道道安全门控，把设备的细粒度事件翻译成上层能记账的制造事务，还负责断线对账、异常 Hold、配方与数据把关。没有它，业务系统无法驱动异构设备、自动化生产和全程追溯就无从谈起。
- **控制一条线、数据两股**：整个 FAB 自动化可以浓缩成两句话——控制是"一条竖线"：任何想改变设备状态的动作（建作业、选配方、启动、Hold）都只能 MES/APC→EAP→GEM→设备这一条受控路径，EDA 只读、谁设谁解、受理不等于生效；数据是"两股上行"：高频连续波形走 EDA 到 EDC 供各种分析系统订阅，稀疏作业/报警事件走 GEM 经 EAP 进 MES 记账。一条线保证安全可控、不脑裂，两股保证数据既实时又全量，这就是架构之美。
- **专家与熟手之别**：熟手能处理见过的报警、背得固定流程，遇到没见过的问题就卡壳；专家掌握的是底层不变量（状态机、事实源、读写隔离、幂等对账、可追溯），能现场推导出没见过的问题该怎么断、怎么恢复，更能在设计阶段就用门控、只读隔离、架构测试、对账机制让一类问题根本无法发生。熟手被动救火，专家主动防火并能把能力沉淀成系统和团队规范。

## 四、36 周核心易错点总清单（压箱底，按六条主线归并）
- **状态机**：漏非法迁移拒绝；漏 Pausing 过渡态/终态；E87 唯一自动取片 Loaded；谁设 Hold 谁解。
- **受理≠生效**：把 ACKC10=0/S7F4=0 当完成；不回读、不等 S6F11 迁移事件就记账。
- **决策≠执行**：把 FDC/Alarm 当执行方（执行永远设备 FSM）；让分析系统/MES 绕过 EAP/GEM 直接写设备；EDA 承担下行控制。
- **事实源/读写隔离**：以 MES 账反推设备物理状态；分析层拿到可写 Bus；配方不看 RMS hash；同名不看版本。
- **幂等/事务/对账**：跨消息下发无事务、失败不回滚；重发无 ReqId 重复建作业/叠加；重连不先对账就下发（脑裂）；账领先物理不冲正；未授权本地作业被补派工洗白；回告不去重/不补报。
- **可追溯/数据**：缺 Lot/Wafer/Step/腔谱系键；用到达时间非源时间；质量码被聚合洗白；实时回改已发结论、历史不可重算；高频原始全量永久或全删；无血缘/版本 hash 无法重放；片不符仍开工（串批）、配方不符将就加工。
- **控制算法**：R2R run 内调节/坏量测也更新/不设限幅死区控制限/直接改主档；VM 低置信 OOD 仍进控制；SPC 用规格限当控制限、对普通原因 tampering；Cpk/Cp 混淆。
