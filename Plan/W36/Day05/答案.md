# W36 · Day05 答案与参考实现

## 一、自测题标准答案
1. **四类框架/通用顺序**：架构设计=分层定位（在 CIM 哪层、事实源）→控制流/数据流白板图→状态机与门控→异常恢复→扩展；异常处置=先止损/安全（containment、设备 FSM 执行 Hold、谁设谁解）→保证据（EDC/日志/Spool）→三分根因方向（设备真异常/数据质量/控制副作用）→对账回滚重放恢复→预防；技术选型=目标与硬约束（实时/吞吐/读写/离线/可维护）→候选与代价→推荐与理由→风险与回退；事故复盘=现象影响→源时间时间线→5Why 根因→决策链审查→纠正预防+横向展开→验证闭环。通用表达顺序：先一句结论，再结构化分点（分层/分阶段），再下钻关键细节与异常分支，最后给权衡与风险；能白板先画图。
2. **架构题先讲事实源/控制通道**：因为这两点决定了整个系统的正确性边界。事实源决定"冲突时听谁的"（物理听设备 FSM、业务听 MES、配方听 RMS、数据听 EDC），控制通道决定"谁有权力改设备状态"（唯一下行走 GEM、EDA 只读）。先立这两条，后面的模块划分、读写隔离、对账与恢复才有一致依据；若一上来就讲报文/类设计，会陷入细节且无法自证架构是否安全、会不会脑裂或越权写设备。
3. **止损先于根因**：根因分析需要时间，而生产在持续、可能继续产出或流出更多可疑片/让异常扩大。异常处置第一优先级是把风险切断——设备 FSM 安全 Hold、冻结相关 Lot 的 WIP/过账、圈定并隔离可疑片（containment），同时保全证据；在风险不再扩大的前提下再从容查因。先查因而不止损，等于带着已知不确定性继续生产，违背质量与安全底线；这也是"谁设谁解、决策≠执行"在应急中的体现（建议方报警，设备执行安全态，业务方冻结流转）。
4. **选型不脱离约束**：技术没有绝对优劣，只有在具体约束下的适配。EDA Freeze III、protobuf、本地模型、EWMA vs dEWMA 的好坏都取决于实时性要求、数据量、读写模型、FAB 内网离线、团队维护能力、成本与合规。脱离约束谈"哪个更先进"会做出过度设计或不可运维的方案；正确姿势是先把硬约束和评估维度列清楚（必要时量化：频率、点数、延迟 P99、内存/CPU、断网可用），再对候选加权比较，给出推荐和代价、以及不适用时的回退方案。
5. **审查决策链而非只看物理根因**：自动化 FAB 的事故往往不是单一物理故障，而是"物理异常出现时，系统为什么没拦住/为何误判"。只查物理根因能修设备，却无法回答 FDC 为何没报警、VM 低置信为何仍进了 R2R、质量门为何放行、对账为何没发现账实不符。审查决策链（当时用了什么数据、质量码与置信度如何、规则/模型/门控为何这样判、版本是否正确）才能堵住系统性漏洞，避免同类问题以别的形式复发；物理根因回答"哪里坏了"，决策链审查回答"为什么自动化没兜住"。
6. **四题要点**：
- **A1 新设备接口分层**：设备内分 Domain（FSM/Bus 事实源）+协议层（HSMS/SECS/GEM、E87/E90/E40/E94）+双通道（GEM 可写一对一控；EDA 只读多客户端高频，IReadOnlyDataBus 编译期隔离）；对上 EAP 暴露制造语义（派工/开工/进度/完工/异常）而非裸报文；MES 控制与作业事件走 GEM，FDC/VM 高频走 EDA→EDC；门控（通信/物料/配方/作业/状态）、受理≠生效、重连对账齐备；故障域隔离（EDA 拥塞不堵 GEM）。白板：双通道+CIM 矩阵。
- **B1 断线 3 分钟**：期间设备本地继续加工，上位不做任何基于旧状态的下行（防脑裂）；恢复先 W22 对账（HSMS→E87→E90→E40/E94→Spool 补报），再与 MES WIP 对齐：用 EDC 源时间数据与作业终态确认期间完成了哪些片/Step，补聚合完工或置 Hold，数据缺口标 Gap/质量码、必要时该段降置信/复检；全部对齐前冻结下行，之后恢复；评估失明期产品。
- **C1 Freeze III vs GEM 事件**：GEM 面向一对一控制与稀疏事件，不适合 10Hz–1kHz×多点×多客户端的海量连续数据（报文冗余、连接模型不匹配）；Freeze III 用 Protocol Buffers 二进制编码 + 订阅/服务端流，体积小、效率高、契合多客户端高频只读，且与控制通道隔离更安全。代价：技术栈新（proto/gRPC 类）、设备/客户端都要支持 Freeze III、运维与工具链要补齐；过渡期可 Freeze II(XML) 兼容，控制仍走 GEM 不变。
- **D1 Cpk 下滑**：先用 SPC 判稳确认是特殊原因（判异规则）还是本征波动；按腔/产品/recipe 分层定位集中点；拉该时段 EDC 过程数据+VM+量测+R2R overlay 记录+FDC 报警，源时间重建时间线；where-used 圈定同腔/同配方版本/同时间窗受影响片并隔离复检；5Why 区分设备劣化/配方/来料/R2R 整定（看 Δu、残差趋势）/数据问题；纠正（保养/重整定/重训/ECN）后验证 Cpk 恢复并横向展开同型号设备。
7. **表达自查**：常见被追问垮的点——只讲"是什么"讲不清"为什么/异常时怎么办"；状态机漏终态与非法迁移；把受理当生效；说不清只读隔离如何落地；给不出量化指标（频率/延迟/保留）；方案没有回退。补法：每个结论后强制补一句"异常分支/代价/以谁为准"，并配一张小图；用今天的 DesignReview 清单逐条自检，录音回听找口头语与跳步。

## 二、12 题答辩提纲（要点速查）
- A2 R2R 闭环安全：量测融合（实测优先/VM 看置信）→EWMA/dEWMA 只在可靠时更新→overlay 只含 Δ、带作用域/ReqId/有效期、knob 限幅死区控制限、多层优先级、绑配方版本→经 RMS→GEM 下发，Idle→Sent→Accepted(仅受理)→Loaded→Effective(回读+事件)，幂等不叠加、失败回滚、连续无有效量测停自动、多腔独立故障域。
- A3 EDC 双满意：实时层内存流+水位线不回溯给 FDC；历史层全量落盘热温冷/TSDB+数据湖给 AI；统一 canonical/WKN/谱系键/源时间/质量码；需求反推采集、数据契约；血缘可重放。
- B2 SlotMap 不符：拒开工、保持安全态、核对实物与绑定，防串批；现场再催也不带疑生产，走异常流程记录。
- B3 表显正常但 FDC HH：看多源一致性/冗余传感器、质量码（是否 Stale/Bad 传感器冻结）、EDA 原始曲线与校准；数据问题报数据质量并评估失明，物理嫌疑则安全确认后再放行，不凭单一指示表否定 FDC。
- C2 内网离线分析选型：本地部署（C# AOT+SQLite FTS5/时序库、本地 RAG/llama.cpp 思路），只读导入 EDC 导出数据，无外网依赖；轻量全文检索+规则+本地模型分层，代价是模型能力与运维，回退纯规则/检索。
- C3 EWMA vs dEWMA：一阶 EWMA 补恒定偏移足够、参数少稳健；存在线性漂移用 dEWMA 加第二 EWMA 估斜率；更复杂模型需数据量与可解释性支撑；撞控制限/残差异常/低置信/连续无效量测即停自动转人工。
- D2 面板私改：同名 hash 变立即联锁、Hold 设备与在制、取证（谁何时改、影响片 where-used）、按 ECN 受控恢复、机群盘点与权限/审计/写保护预防。
- D3 MES 完工但设备剩两片：账领先物理，冲正过账、WIP 退回实际工序、重建作业视图，未完成片续做或异常处置后按完工判定重新过账；预防=预期片销账+终态双条件+重连对账。

## 三、参考实现（net8.0）：设计评审检查器

```csharp
namespace EapLab.Arch;
public sealed class DesignCheck(string Name,bool Ok,string Why);
public sealed class DesignReview
{
    readonly List<DesignCheck> _c=new();
    public DesignReview Require(bool ok,string name,string why){_c.Add(new(name,ok,why));return this;}
    public IEnumerable<DesignCheck> Failed=>_c.Where(x=>!x.Ok);
    public bool Approved=>!Failed.Any();
    // 专家级 EAP/双通道方案的硬性评审项
    public static DesignReview ReviewEap(bool controlViaGemOnly,bool edaReadonly,bool acceptedVsEffective,
        bool hasReconcile,bool sourceOfTruthClear,bool failureIsolated)
    =>new DesignReview()
        .Require(controlViaGemOnly,"下行控制只走GEM","EDA只读, 唯一受控控制通道")
        .Require(edaReadonly,"EDA编译期只读","IReadOnlyDataBus无写方法")
        .Require(acceptedVsEffective,"受理≠生效","以FSM迁移+事件+回读为准")
        .Require(hasReconcile,"重连对账","W22+MES WIP对齐, 防脑裂")
        .Require(sourceOfTruthClear,"事实源清晰","物理听设备/业务听MES/配方听RMS")
        .Require(failureIsolated,"故障域隔离","EDA拥塞不堵GEM, 多腔隔离");
}
```

## 五、今日易错点
1. 一上来讲报文/代码细节，不先定位分层与事实源。
2. 异常题先查因不止损，可疑片继续流出。
3. 选型脱离约束谈"先进性"，无量化、无回退。
4. 复盘只追物理故障，不审查自动化决策链。
5. 把受理当生效、建议方当执行方。
6. 方案讲不出异常分支和故障隔离。
7. 只背标准答案，不会按约束现场权衡。
8. 不录音回看，口头语、跳步、被追问即卡壳不自知。
