# W36 · Day02 答案与参考实现

## 一、自测题标准答案
1. **三类追溯**：正向追溯（forward）从原材料/Lot/工单出发沿工艺路线向前，回答"这批/这片去了哪些工序设备、被怎么加工、最终变成什么、流到哪个成品/客户批次"，用于跟踪去向与交付；反向追溯（backward）从一片问题片或一个异常结果往回查，回答"它经历了哪些设备/腔/配方/控制/量测/报警"，用于定位根因；where-used/反向圈定（containment）从已知问题源（某台设备/某个腔/某版配方/某个时间窗）反查所有经过它的 Lot/wafer，回答"还有哪些片可能受影响"，用于快速隔离止损。三者方向不同：正向跟产品走向、反向查单片历史、圈定按问题源扩散范围。
2. **8 类问题/来源**：①身份——wafer id/slot、Lot/工单/产品/路线（MES+E87/E90）；②路径——每工序设备/腔、起止时间、PJ/CJ、Carrier 变迁（EAP/E40/E94/E87）；③配方——每步 PPID+版本+hash、overlay 的 Δ/作用域/ReqId/来源（RMS+R2R，W33/31）；④过程数据——EDC 各 Step trace 引用、关键统计、采集计划版本与质量码（EDA/EDC，W34）；⑤控制调整——R2R 每次依据哪条量测/VM、控制律输出、限幅（W31）；⑥量测质量——inline/offline/VM 结果与置信区间、SPC 点、OOS/OOC、Cpk（W32/量测）；⑦报警干预——FDC 报警、Hold/Release 谁设谁解及原因、Alarm、人工操作、ECN（W30/W33/W35）；⑧结果去向——单片/批良率、缺陷与 YMS 关联、返工/报废、成品/客户批次（YMS/MES）。
3. **数据指纹/为何带版本 hash**：数据指纹是对一个加工段"用什么、采了什么、怎么算的"的唯一摘要——EDC 数据区间引用（Lot/Wafer/Job/源时间窗/采集计划版本）、配方 PPID+版本+hash、VM 模型/R2R 控制器/SPC 方案版本、数据质量码。配方/模型/采集计划必须带版本与 hash，是因为同名内容可能被修改（面板私改、模型重训、采集点变更），只有版本+内容 hash 才能确认"当时用的到底是不是那份、有没有被改过"，保证追溯到的过程与当时完全一致、结论可复现、责任可界定；否则同名不同内容会让追溯失真（W33 同名 hash 变=疑似私改）。
4. **圈定处置**：以问题源为条件做 where-used 查询——设备/腔 ID + 异常时间窗（用源时间），在谱系中检索所有在该时间窗经过该腔的 PJ/CJ→Lot/wafer，叠加配方版本/overlay 条件（是否同版/同控制段）进一步精确；圈出清单后先 containment 止损：对在制片立即 Hold/暂停流转、对已流入下游的片标记冻结待复检、对已入库/出货的评估是否召回；随后逐片调取过程/量测数据确认是否真受影响（区分经过≠受损），按结果分级放行/返工/报废，并横向排查同型号设备/同配方段（Day 复盘框架）。
5. **复盘步骤/containment 第一**：①现象描述（什么异常、何时、如何发现、指标表现）；②containment 紧急圈定与隔离（先止损，防止继续产出/流出更多可疑片）；③时间线重建（用 EDC 源时间戳+GEM 事件还原经过，而非记忆）；④根因分析（5Why/鱼骨：设备硬件/配方/控制/数据/操作/来料）；⑤决策链审查（当时 FDC/R2R/VM/SPC/质量门为何这样判，置信度、质量码、门控是否生效，是否监控失明）；⑥纠正预防（ECN 改主档、重训 VM、重整定 R2R、加 FDC 规则、强化门控/对账）；⑦验证闭环与横向展开（同设备/同配方/同产品全面排查）。containment 排第一是因为根因分析需要时间，而生产在继续，必须先切断可疑扩散、控制质量风险，再慢慢查因，符合质量管理"先止血后治病"。
6. **区分三类问题**：设备真异常——多个独立量/冗余传感器一致显示偏离、过程数据质量 Good、伴随物理现象/报警，换设备/腔后消失，FDC 规则与 SPC 同向异常；数据质量问题——单点异常但冗余/相邻点不支持、质量码为 Bad/Uncertain/Stale/Gap、通信/采集链路有丢点或时钟异常，此时不能判工艺坏，应报数据质量问题、监控可能失明（W34 Day04）；R2R 控制副作用——异常与 overlay 调整在时间/方向上相关（Δu 单调后残差同向变化、撞限），回退 overlay/重置 EWMA 后恢复，属控制器整定/模型问题而非设备本征漂移（W31/32 SPC 监控 Δu/残差）。用"多源一致性、质量码、控制动作相关性"三把尺子区分。
7. **可重放/前提**：可重放指保存当时的原始数据与全部版本化资产后，能在事后用相同算法/模型/控制器版本重新计算特征、VM 预测、SPC 统计、R2R 输出，复现并验证当时系统给出的结论，或用修正后算法对比差异。前提：原始高频数据按保留策略未被降采样删除（关键段长期留存，W34 Day05）、谱系键与源时间完整、配方/模型/控制器/采集计划都有版本与 hash、算法代码可回溯到对应版本、数据质量信息保留。缺原始数据或缺版本，结果就只能复算不能真正重放。

## 二、参考实现（net8.0）：谱系与正反向/圈定查询

```csharp
namespace EapLab.CimMap.Gene;
public sealed record Segment(string Op,string Equipment,string Chamber,DateTime Start,DateTime End,
    string Ppid,string PpHesh,string? OverlayReq,string EdcRef,string? Alarm,string? Measure,string Result);
public sealed class WaferGene
{ public string Wafer{get;}public string Lot{get;}public string WorkOrder{get;}
    public List<Segment> Segs{get;}=new();
    public WaferGene(string w,string lot,string wo){Wafer=w;Lot=lot;WorkOrder=wo;}
    public void Add(Segment s){Segs.Add(s);}
    // 反向追溯: 单片在某设备/腔的全部加工段
    public IEnumerable<Segment> Backward(string? eq=null,string? chamber=null)
    =>Segs.Where(s=>(eq==null||s.Equipment==eq)&&(chamber==null||s.Chamber==chamber))
          .OrderBy(s=>s.Start);
    public bool UsedRecipe(string ppid,string hash)=>Segs.Any(s=>s.Ppid==ppid&&s.PpHesh==hash);
}
public sealed class GenealogyBook
{ readonly List<WaferGene> _w=new();
    public void Register(WaferGene g)=>_w.Add(g);
    public WaferGene Registered(string wafer)=>_w.First(g=>g.Wafer==wafer);
    // where-used: 某腔在时间窗内加工过的所有片(圈定)
    public List<string> WhereUsed(string chamber,DateTime from,DateTime to)
    =>_w.Where(g=>g.Segs.Any(s=>s.Chamber==chamber&&s.Start>=from&&s.Start<to))
        .Select(g=>g.Wafer).ToList();
    // 某版配方影响的片
    public List<string> AffectedByRecipe(string ppid,string hash)
    =>_w.Where(g=>g.UsedRecipe(ppid,hash)).Select(g=>g.Wafer).ToList();
    // 正向: 片最终结果链
    public IEnumerable<string> Forward(string wafer)
    =>_w.First(g=>g.Wafer==wafer).Segs.Select(s=>$"{s.Op}@{s.Equipment}/{s.Chamber}:{s.Result}");
}
```

## 三、单片追溯时间轴（手绘参考）
```
Wafer(slot) ─Lot─ WorkOrder
 │ 按工序时间轴(源时间)
 ├─Op Etch @EQ1/C1 [08:00-08:10] PPID=ETCH_v3#h1 ─ EDC:edc://a(采集计划v/质量Good) ─ 结果Pass
 ├─Op Film @EQ2/A  [09:00-09:20] PPID=FILM_v2#h9 + overlay OV#7(R2R依据量测M3,Δu,ReqId)
 │        └ EDC:edc://b ─ FDC报警tempHH ─ Hold(张设/张解,原因) ─ VM:ok(PI/置信) ─ SPC点 ─ 结果Hold→Release
 └─...→ 量测/缺陷 → YMS良率 → 成品/客户批次
三查询: 正向(片→去向) / 反向(问题片→历史根因) / where-used(腔·配方·时间窗→受影响片清单→containment隔离)
证据链= 数据指纹(EDC区间+采集版本) + 配方/模型/控制器版本hash + ReqId + 源时间 + 质量码 → 可重放
复盘: 现象→圈定止损→源时间时间线→根因(设备/配方/控制/数据/操作)→决策链审查→纠正预防ECN/重训/重整定→验证+横向展开
三把尺: 多源一致性(真异常) / 质量码(数据问题) / 与overlay动作相关性(控制副作用)
```

## 四、今日易错点
1. 只有正向流程记录，做不了反向追溯和 where-used 圈定。
2. 谱系缺腔/Step/版本/ReqId，只能查到设备级、查不到根因粒度。
3. 只记 PPID 不记版本/hash，同名内容被改后追溯失真。
4. 用到达时间而非源时间，跨设备时间线对不齐。
5. 出问题先查因而不先 containment，可疑片继续流出。
6. 把数据质量问题误判成工艺异常，或忽略监控失明期产品。
7. 不审查当时决策链（置信度/质量门为何放行），只看物理原因。
8. 关键高频段被降采样删除、模型/算法无版本，事后无法重放验证。
