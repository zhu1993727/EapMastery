# W36 · Day01 答案与参考实现

## 一、自测题标准答案
1. **各子系统单一职责**：设备=执行加工的物理实体，FSM 是物理事实源；设备端 EAP/SECS-GEM 接口=设备上的被管接口（你的位置），FAB 端 EAP/Host=管理一组设备的工厂侧系统，设备端只与 FAB EAP 直连；MES=制造执行（工单/Lot/工艺路线/派工/WIP/谱系，业务事实源）；RMS=配方全生命周期与机群一致性（配方事实源）；FDC=实时故障检测与分类（安全监控、建议方）；R2R=逐批反馈/前馈补偿（只产 overlay 建议）；VM=用 trace 预测片级结果+置信度（只预测不控制）；SPC=跨批统计判稳与过程能力（不控制单批）；EDC=设备数据汇聚治理平台（数据底座），EDA/Interface-A=设备标准高频只读出口；YMS=良率管理与长周期过程关联；AMHS=自动搬运（E84 硬线）。每个系统职责单一、不越界，是架构可维护的前提。
2. **关键交互对**：MES↔EAP——派工/预约/Hold/取消下行，作业/片/完工/异常上行，走工厂级异步制造事务；EAP↔设备——GEM(HSMS/SECS) 一对一承担控制与作业事件（S2F41/S6F11/S5F1/S7），EDA 多客户端承担高频只读订阅，E84 硬线对 AMHS；RMS↔EAP/设备——S7 分发上传删除、S2F41 PP-Select、hash 一致性校验，R2R overlay 也必须经 RMS→GEM 下行；FDC↔EDC/设备——订阅 EDA 实时流做检测，报警/建议上行（不直接写设备）；R2R↔设备——不直连，取量测/VM/设定算 overlay 后交 RMS/EAP 经 GEM 下发 knob；VM/SPC/YMS 都从 EDC 取数、结果回 EDC/MES，不直控设备。
3. **下行只走 GEM/EDA 只读/编译期保证**：GEM(HSMS) 是单一、受控、带连接管理与命令握手/状态机保证的一对一控制通道，能保证"谁在控制、命令是否受理生效、如何回滚"；EDA/Interface-A 面向多客户端高频只读订阅，若允许写则多个客户端可同时改设备、无单一控制授权、极不安全。因此架构上把数据总线拆成两个视图：GEM 侧拿可写视图（ICommandBus），EDA 侧只暴露 `IReadOnlyDataBus`（只读接口，编译期就没有任何写方法，W29），分析类系统依赖只读抽象，类型系统层面封死"EDA 写控制"的可能；再辅以代码评审/依赖方向检查（分析层不得引用控制层）。
4. **同步 vs 异步**：同步请求-应答用于"必须立刻知道结果"——S1F13/14 建立通信、变量查询 S1F3/4·S2F33/报告读取、S7F1/2 Inquire、PP-Select 后立即回读当前 PPID、HSMS Linktest；异步事件用于"发生即推、不等待请求"——S6F11 事件报告（Job/Step/片完成）、S5F1 报警上报、作业状态迁移、EDA 周期/异常数据流、FDC 告警。同步保证关键握手确定，异步保证实时与解耦；控制命令是"同步拿受理 + 异步等生效事件"两段式（受理≠生效）。
5. **时间尺度/是否直控**：FDC 秒/亚秒级实时监控，检出异常给建议/联锁信号，执行 Hold 的是设备 FSM（FDC 不直接控）；R2R 逐片/逐批（run 间）补偿，产出 overlay 建议经 RMS/GEM 下发，run 内不调；VM 逐片出预测（片结束即可），只预测不控制，低置信不进 R2R；SPC 小时~月跨批判稳/Cpk，不控制单批，异常驱动工程动作（重整定/保养）；YMS 天~月长周期良率关联分析，纯离线。即越靠左越实时但都不绕过 EAP/GEM 直接写设备，控制执行永远收敛到设备 FSM 与 GEM 通道。
6. **事实源/冲突裁决**：物理与作业状态（片在不在、作业跑到哪、当前 PPID）事实源=设备 FSM；制造业务（Lot 在哪工序、是否放行/完工、WIP）事实源=MES；配方主档事实源=RMS golden 副本；过程原始数据事实源=EDC（其源头是设备）；良率/量测事实源=量测/YMS。冲突按权威边界裁：物理类争议以设备为准（业务账不得领先或违背物理事实，W35 Day05），业务裁决类（合格/放行/报废/路线）以 MES 规则与工程决策为准，配方一致性以 RMS hash 为准，数据争议回 EDC 用源时间/质量码/血缘重算（W34）。EAP 负责发现并对齐差异，不替任一方拍板。
7. **交互矩阵（见下 ASCII）**：节点按"决策层 MES/YMS—使能层 EAP/RMS/APC—数据层 EDC—执行层设备/AMHS"分层摆放，连线标注内容/通道/方向/控制(C)或数据(D)/同步异步。核心形状：下行控制一条竖线（MES→EAP→GEM→设备），上行数据分两股（EDA→EDC→分析系统；GEM 事件→EAP→MES），RMS 挂在控制线上管配方，FDC/R2R/VM/SPC 围绕 EDC 只读消费、其动作回到控制线经 EAP 落地，AMHS 经 E84 与设备/MES 协同。

## 二、参考实现（net8.0）：交互矩阵与违规校验

```csharp
namespace EapLab.CimMap;
public enum Kind{ Control,Data,Both }
public enum Mode{ Sync,Async,Publish }
public sealed record Link(string From,string To,string Via,Kind Kind,Mode Mode,string Note);
public sealed class InteractionMatrix
{
    public List<Link> Links{get;}=new();public InteractionMatrix Add(Link l){Links.Add(l);return this;}
    static readonly string[] Analyzers={"FDC","R2R","VM","SPC","YMS"};
    // 架构铁律校验
    public List<string> Violations()
    { var v=new List<string>();
        foreach(var l in Links)
        { // 1) EDA通道不允许承载控制
          if(l.Via=="EDA"&&l.Kind!=Kind.Data)v.Add($"EDA must be read-only: {l.From}->{l.To}");
          // 2) 分析系统不得直接控制设备(必须经EAP/GEM)
          if(Analyzers.Contains(l.From)&&l.To=="Equipment"&&l.Kind!=Kind.Data)
              v.Add($"analyzer {l.From} must not control equipment directly");
          // 3) 任何到设备的控制必须走GEM且经EAP
          if(l.To=="Equipment"&&l.Kind is Kind.Control or Kind.Both&&l.Via!="GEM")
              v.Add($"control to equipment must go via EAP/GEM: {l.From}->{l.To} via {l.Via}"); }
        return v; }
    public IEnumerable<Link> To(string t)=>Links.Where(l=>l.To==t);
    public IEnumerable<Link> From(string f)=>Links.Where(l=>l.From==f);
}
```

### xUnit
```csharp
public class MatrixTests
{
    [Fact] public void 合规矩阵无违规()
    { var m=new InteractionMatrix()
        .Add(new("MES","EAP","svc",Kind.Control,Mode.Async,"dispatch/hold"))
        .Add(new("EAP","Equipment","GEM",Kind.Control,Mode.Sync,"S2F41/select/start"))
        .Add(new("Equipment","EDC","EDA",Kind.Data,Mode.Publish,"high-freq trace"))
        .Add(new("Equipment","EAP","GEM",Kind.Data,Mode.Async,"S6F11 events"))
        .Add(new("FDC","EDC","sub",Kind.Data,Mode.Publish,"read only"));
        Assert.Empty(m.Violations()); }
    [Fact] public void EDA承载控制被拦()
    { var m=new InteractionMatrix().Add(new("X","Equipment","EDA",Kind.Control,Mode.Sync,"bad"));
      Assert.Contains(m.Violations(),x=>x.Contains("read-only")); }
    [Fact] public void 分析系统直控设备被拦()
    { var m=new InteractionMatrix().Add(new("R2R","Equipment","HTTP",Kind.Control,Mode.Sync,"bad"));
      Assert.NotEmpty(m.Violations()); }
    [Fact] public void 到设备控制不走GEM被拦()
    { var m=new InteractionMatrix().Add(new("MES","Equipment","HTTP",Kind.Control,Mode.Sync,"bypass EAP"));
      Assert.Contains(m.Violations(),x=>x.Contains("via EAP/GEM")); }
}
```

## 四、今日易错点
1. 职责重叠或遗漏（尤其 EDC 数据底座与 EDA 出口、设备端 vs FAB 端 EAP）。
2. 让分析系统（FDC/R2R/VM/SPC）绕过 EAP 直接写设备。
3. 用 EDA 通道下发控制（EDA 必须只读，应用 IReadOnlyDataBus 编译期封死）。
4. 混淆同步握手与异步生效，把受理当完成。
5. 分不清三时间尺度，用 SPC 去做实时控制或让 R2R 在 run 内调节。
6. 多事实源冲突时拍脑袋，不按权威边界裁决。
7. 认为 RMS 只存配方，忽略它也是 overlay 下发与机群一致性的受控关口。
8. 画图不分控制流与数据流、不标方向/通道，别人看不出系统怎么协作。
