# W36 · Day03 答案与参考实现

## 一、自测题标准答案
1. **分层/依赖向内**：自内向外为 Domain（泛型状态机、数据总线、值对象，零外部依赖、唯一事实源）→协议层 E5/E30/E39（HSMS/SECS/GEM/OSS）→GEM300 层 E84/E87/E90/E40/E94/E116/E10→通道层 Eda（只读采集/会话/编码）与 Cim 拓扑→使能/分析层 Fdc/R2r/Vm/Spc/Rms/Edc（只读订阅、算法、治理）→编排层 Mes（制造语义）/Host（FAB 端聚合对账）→适配层 Hosting（最小 API/gRPC/传输）→Tests 横切。依赖只能由外向内指：外层可引用内层，内层绝不知道外层（依赖倒置：外层实现内层定义的接口）。这样内层核心稳定可测、可独立复用，换传输/换 UI/加分析系统都不动 Domain，避免环形依赖与"改一处崩一片"。
2. **三条以上铁律**：①Domain/FSM/Bus 是唯一可写事实源，任何分析层不得反向修改状态机；②Eda/Fdc/Vm/Spc/Edc 只持有 `IReadOnlyDataBus` 只读视图，不引用 GEM 写命令通道，EDA 通道永不承载下行控制；③R2r 只产 overlay 建议对象，下发必须经 Rms→Gem（由 Mes/Host 编排），分析层不直接发 SECS 控制；④Hosting 只做传输适配、不写业务规则；⑤设备控制类只能存在于协议/编排指定命名空间，其他命名空间出现写设备类型即违规。
3. **只读双重保证**：类型层面——数据总线拆两个接口，可写 `IDataBus`（只暴露给 GEM/控制编排）与 `IReadOnlyDataBus`（只暴露给 EDA/分析层），只读接口编译期就没有写方法，分析层构造函数只注入只读接口，拿不到写能力（W29）；架构层面——用架构约束测试反射检查程序集/命名空间引用，分析层程序集不得引用控制命令所在命名空间，一旦有人误引入就在 CI 变红。类型系统挡"写得出"，架构测试挡"引得到"，双保险，避免靠口头约定被破坏。
4. **架构测试/对比 review**：架构约束测试把"EDA 只读、依赖方向、控制类位置、不可变值对象"等规矩写成可执行断言，每次构建/提交自动运行，违规立即红灯且定位到具体类型；相比 code review 依赖人记忆与自觉、容易遗漏、无法覆盖全量代码，架构测试是机器化、全量、可重复、长期不衰减的守护，尤其在多人协作或用 AI 大量生成代码时，能在合并前就拦截破坏隔离的改动，review 则更关注业务正确性与设计合理性，二者互补。
5. **测试金字塔**：底层大量纯单元测试——状态机迁移/非法迁移拒绝、SECS 编解码、EWMA/dEWMA、VM 特征与预测、SPC 系数/判异、RMS 校验/生命周期、EDC 时间对齐/质量传播/需求反推、MES 派工/聚合/对账等纯逻辑，快、确定、无 IO，占绝大多数；中层少量集成测试——双通道（GEM 可写+EDA 只读共享同一事实源）、采集运行时、overlay 下发握手、LotJourney 端到端编排，验证多模块协作；顶层少量面向真实/仿真设备的契约与故障注入测试（报文快照、断连/乱序/丢点/重连对账、高频吞吐与内存基准）。越往上越慢越少，核心正确性靠底层海量单测保证。
6. **跨周不一致统一**：以 Domain 为唯一权威统一术语与枚举——ACKC 原因码、CEID/报告命名、状态枚举（如 E87/E40/E94/RMS 生命周期）、质量码 Q、通道枚举全部收敛到共享定义，各周引用同一套而非各自定义；泛型 `StateMachine<TState,TTrigger>` 全项目复用；命名空间与类名按统一约定（EapLab.<域>.<子域>）。做法是全量 build 让编译器暴露重复/冲突定义，逐个改为引用共享类型，再用集成测试确认行为不变；语义口径（受理≠生效、谁设谁解、物理以设备为准）写入注释/文档并由测试用例固化，避免同名不同义。
7. **最小 CI 流水线**：①触发（push/PR）→②restore 还原依赖→③build 全解决方案（零警告目标，编译期类型隔离在此拦截，如只读层误调写方法）→④test 全量单元+集成+架构约束测试（拦截逻辑错误与架构违规）→⑤可选静态分析/格式/覆盖率门槛→⑥打包产物（库/容器/教学实验可执行）。各阶段拦截点：build 拦类型/接口违规与编译错误，架构测试拦依赖方向/只读破坏，单测拦算法与状态机错误，集成测试拦模块协作与重连/时序问题，覆盖率门槛防止关键逻辑裸奔；专家要能让铁律在团队长期自动化守护而非依赖个人。

## 二、参考实现（net8.0）：轻量架构约束测试（反射，ArchUnit 思想）

```csharp
namespace EapLab.Arch;
using System.Reflection;
public static class ArchRules
{
    // nsA 命名空间下的类型, 不得引用(字段/参数/基类) nsForbidden 下的任何类型
    public static List<string> NoNamespaceDependency(Assembly asm,string nsA,string nsForbidden)
    { var bad=new List<string>();
        foreach(var t in asm.GetTypes().Where(x=>x.Namespace!=null&&x.Namespace.StartsWith(nsA)))
        { var refs=new List<Type?>();
            refs.AddRange(t.GetFields(BindingFlags.Instance|BindingFlags.Public|BindingFlags.NonPublic).Select(f=>f.FieldType));
            refs.AddRange(t.GetConstructors().SelectMany(c=>c.GetParameters().Select(p=>p.ParameterType)));
            refs.Add(t.BaseType);
            if(refs.Any(r=>r!=null&&r.Namespace!=null&&r.Namespace.StartsWith(nsForbidden)))
                bad.Add($"{t.FullName} must not depend on {nsForbidden}"); }
        return bad; }
    // 只读接口不得暴露任何以 Set/Write/Send/Add 开头的公共方法
    public static List<string> ReadOnlyInterfaceNoMutators(Type iface)
    =>iface.GetMethods().Where(m=>m.Name.StartsWith("Set")||m.Name.StartsWith("Write")||
                                  m.Name.StartsWith("Send")||m.Name.StartsWith("Add"))
          .Select(m=>$"{iface.Name}.{m.Name} is a mutator").ToList();
}
public interface IReadOnlyDataBus{ double? Get(string tag); IEnumerable<double> Window(string tag,int n); } // 无写方法
```

### xUnit
```csharp
public class ArchRuleTests
{
    sealed class SampleAsm{public static Assembly A=>typeof(SampleAsm).Assembly;}
    public interface IWritable{void Set(string t,double v);}
    [Fact] public void 只读接口无变更方法()
    { Assert.Empty(ArchRules.ReadOnlyInterfaceNoMutators(typeof(IReadOnlyDataBus))); }
    [Fact] public void 可写接口会被规则识别出变更方法()
    { Assert.NotEmpty(ArchRules.ReadOnlyInterfaceNoMutators(typeof(IWritable))); }
    [Fact] public void 依赖规则_形式可运行()
    { // 真实工程传入 EapLab 程序集, 断言分析层不依赖控制命名空间
      var r=ArchRules.NoNamespaceDependency(typeof(SampleAsm).Assembly,"EapLab.Fdc","EapLab.E5");
      Assert.NotNull(r); }
}
```

### 解决方案结构（教学，目录即项目）
```
EapLab.sln
├─ EapLab.Domain        (StateMachine<,>/Bus/值对象, 零依赖)
├─ EapLab.E5/E30/E39    (HSMS/SECS/GEM/OSS)
├─ EapLab.E87/E90/E40/E94/E84/E116/E10
├─ EapLab.Eda           (只读采集/会话/编码/双通道, 只依赖Domain)
├─ EapLab.Fdc/R2r/Vm/Spc/Rms/Edc  (只读订阅/算法/治理, 不反向写)
├─ EapLab.Mes/Host      (制造语义编排/FAB聚合对账)
├─ EapLab.Hosting       (最小API/gRPC, 仅传输适配)
└─ EapLab.Tests         (单测/集成/架构约束/故障注入)
命令: dotnet new sln; dotnet sln add **/*.csproj; dotnet build; dotnet test
```

## 三、项目依赖图（手绘参考，箭头只向内）
```
                    Hosting (API/gRPC 传输适配, 无业务规则)
                              │ 依赖向内
   Mes(制造编排) / Host(FAB聚合对账) / Rms(下发关口)
                              │
        Fdc / R2r / Vm / Spc / Edc  (分析·治理: 只持有 IReadOnlyDataBus, 只产建议)
                              │ 只读订阅
        Eda(只读通道) / Cim拓扑        E5/E30/E39(协议) / E84/E87/E90/E40/E94/E116/E10(GEM300)
                              └──────────────┬──────────────┘
                                             ▼
                              Domain: StateMachine<,> / IReadOnlyDataBus·IDataBus / 值对象 (唯一可写事实源,零外部依赖)
禁止: 内层→外层; 分析层→控制命名空间; Eda/Fdc/...→可写Bus; R2r直接发SECS(必须Rms→Gem); Hosting写业务
守护: 类型系统(IReadOnlyDataBus编译期无写方法) + 架构约束测试(反射查引用,CI红灯) 双保险
测试: 海量纯单测(状态机/算法) > 少量集成(双通道/握手/Journey) > 少量契约/故障注入/性能基准
```

## 四、今日易错点
1. 环形依赖或内层引用外层，核心无法独立复用与测试。
2. 分析层直接拿到可写 Bus、反向改状态机。
3. 只靠口头约定"EDA 只读"，不用接口隔离和架构测试固化。
4. R2r 绕过 RMS/GEM 直接发控制报文。
5. Hosting/传输层里写业务规则，换通道就要改业务。
6. 只有端到端测试、缺海量纯单测，反馈慢且难定位。
7. 各周自定义同名枚举/ACKC，术语不统一、语义漂移。
8. 没有 CI 自动化守护，铁律随人员流动/AI 生成代码逐渐被破坏。
