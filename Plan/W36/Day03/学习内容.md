# W36 · Day03（周三）收官三：全代码资产集成回归与架构约束测试

> 建议时长：105 分钟。36 周积累了 EapLab 一整套资产，今天把它们组织成一个解决方案、统一依赖方向、跑全量 build/test，并用"架构约束测试"把铁律（EDA 只读、分析层不反向写状态机、控制只经 GEM/RMS）固化成 CI 能自动拦截的规则。这是从"会写片段"到"能交付可维护系统"的关键一步。

## 一、今日目标
1. 把各周项目组织成分层解决方案（Domain/协议/GEM300/EDA/APC/RMS/EDC/MES/Hosting/Tests）。
2. 明确并可视化项目依赖方向（谁能引用谁、谁绝不能引用谁）。
3. 全量 `dotnet build` + `dotnet test` 回归，处理跨周命名/版本冲突。
4. 编写架构约束测试（ArchUnit 思想，用反射实现轻量版）：只读隔离、依赖方向、命名规范。
5. 建立 CI 最小流水线（build→test→架构测试）概念；xUnit。

## 二、背景知识（先读，40 分钟）

### 1. 分层与项目组织
- Domain（状态机/总线/值对象，唯一事实源，零外部依赖）；E5/E30/E39（SECS/HSMS/GEM/OSS）；E84/E87/E90/E40/E94/E116/E10（GEM300）；Eda（只读通道/采集/会话/编码）；Cim 拓扑；Fdc/R2r/Vm/Spc/Rms/Edc（分析与使能，只读订阅）；Mes（制造语义编排）；Host（FAB 端聚合/对账）；Hosting（传输适配：最小 API/gRPC）；Tests。
- 依赖只能由外向内指向 Domain，内层不知道外层。

### 2. 依赖方向铁律（固化为代码）
- Domain 不引用任何分析/服务层；FSM/Bus 是唯一可写事实源。
- Eda/Fdc/Vm/Spc/Edc 只持有只读数据视图，不引用 GEM 写命令、不反向改 FSM。
- R2r 只产 overlay 建议；真正下发经 Rms→Gem（Mes/Host 编排），分析层不直接发控制。
- Hosting 只适配传输，不写业务规则。
- 若出现 Fdc→E5 控制命令、Eda→可写 Bus 这类引用，架构测试直接失败。

### 3. 全量回归
- 解决方案级 `dotnet build` 零警告目标（TreatWarningsAsErrors 逐步开启）；`dotnet test` 全绿。
- 跨周复用命名一致性（ACKC、CEID、状态枚举、同一 StateMachine<TState,TTrigger>），统一冲突。
- 测试金字塔：大量领域纯逻辑单测（状态机/算法/校验）+ 少量集成测试（双通道、端到端 LotJourney）。

### 4. 架构约束测试（把规矩变成测试）
- 用反射枚举程序集类型/引用关系，断言：某命名空间不得引用另一命名空间；实现某接口的类不得暴露写方法；控制类必须在指定命名空间。
- 价值：新人/AI 生成代码一旦破坏隔离，CI 立刻红灯，比 code review 更可靠。

### 5. CI 最小流水线概念
- 提交触发：restore→build→test（含架构测试）→产物；可加格式检查、覆盖率门槛。专家要能说清"如何让这些约束在团队里长期不被破坏"。

### 6. 与工程现实对接
- 真实项目还会有接口契约测试（SECS 报文快照）、与仿真设备/PLC 的集成测试环境、故障注入（断连/乱序/丢点）、性能基准（高频采集吞吐、内存池，呼应你关注的 OOM/内存池）。
