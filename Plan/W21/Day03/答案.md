# W21 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何不能一律全停或一律继续**：一律全停会把与故障无关的健康分支也停掉，造成不必要的产能损失（独立并行分支、可改派同型资源本可继续），不符合高可用；一律局部继续则可能让依赖故障输出的下游 PJ 等不到输入而空转/卡死、让上游继续向已故障路径供片导致片堆积、或在共用安全系统故障时带险运行。正确做法是按依赖图精确计算影响范围，能隔离的隔离继续、在关键路径的才级联停、可短暂恢复的挂起等待，使影响最小同时绝不失控。
2. **上下游/无关判定**：在依赖图上以故障 PJ 为起点，沿"谁需要它"的出边（B 需要 A，则 A→B）正向遍历得到**下游集合**（直接/间接消费故障输出者）；沿入边反向遍历得到**上游集合**（直接/间接给它供片者）；既不在上游也不在下游、与故障点无依赖连通路径的 PJ 为**无关**（独立并行分支），可继续。判定基于控制依赖与片流依赖合成的有向图，用可达性（BFS/DFS）求闭包。
3. **局部隔离前提 / CJ 标记**：前提=①故障 PJ 可被替代（同型资源/其他 PJ 改派、可安全重试）或属于可降级的独立分支；②其他继续的 PJ 不依赖它的输出（不在其下游闭包）；③不涉及共用安全系统、无共同安全风险；④隔离动作本身安全（故障资源释放、在故障 PJ 内的片已三分类到安全位置）。满足则隔离故障 PJ、健康 PJ 继续，CJ 保持 Executing 并标记 Degraded（带故障子作业与受影响片记录），最终若缺片无法全完成则走授权的 Partial，绝不静默 Completed。
4. **关键路径级联停的上下游动作**：故障 PJ 不可替代且其输出被依赖时——下游：停止启动新步骤，已在加工的走到安全点后停（Hold/Abort），已从故障路径取到的在制片安全保护，因输入缺失无法继续；上游：停止向故障路径供片（不再把片送入会断的链路），已产出的半成品在交接位/Buffer 安全保持，若有其他合法去向可改道；故障 PJ 自身三分类处置片；已完成 PJ 保持。全部相关单元到安全态后 CJ 转 Failed/Aborted 并冻结现场，供后续新建 CJ 续跑。
5. **Propagate Hold vs Cascade Stop / 转换**：Propagate Hold 用于故障**预计可快速恢复**（如资源短暂不可用、可重试的通信/机构问题）：下游不判失败而是挂起等待、上游暂缓供片，现场安全保持，设一个等待超时；若在超时内故障恢复，被挂起 PJ 从安全点继续，CJ 不失败。Cascade Stop 用于故障不可替代/不可恢复或等待超时：把挂起的下游正式级联停、上游停供，CJ 转 Failed/Aborted。转换条件=Hold 超时或确认故障不可恢复，即"先给恢复机会、超时再升级为停止"，避免短暂抖动就整批失败，也避免无限等待。
6. **菱形 B 故障 / C 与 D / C 片不丢**：D 需要 B、C 两路汇合，B 故障导致 D 缺一路无法完成。C 与 B 是并行分支、不依赖 B，因此 C 可继续加工完（局部隔离），但其产出到达汇合点时 D 无法汇合，需要把 C 的片安全保存在汇合等待位/Buffer，并在汇合状态里记录"C 路已到、缺 B 路"；等 B 恢复/改道补齐后再汇合 D，若 B 不可恢复则按策略把 C 的片也转入对应结局（Partial/改道/人工）。C 的片不能丢，因为它已合格加工、是有效在制品，丢了既破坏守恒也浪费产能，必须有确定等待位置并计入守恒。
7. **已完成 PJ / 原因**：已 Completed 的 PJ 保持终态不动、其产出片保持在交接/输出位置并登记为有效成果，不因其他 PJ 故障而回退或重做。因为它的加工已完整结束、质量有效，回退是无意义的额外搬运与风险；在最终恢复/新建续跑 CJ 时，这些已完成 PJ 的成果直接作为既成事实被继承（只对未完成部分续跑），这与 W17"已完成片不重做"在 PJ 层一致。

## 二、参考实现（net8.0）

### 依赖图与影响集合
```csharp
namespace EapLab.E94.Cascade;
public sealed class PjDepGraph
{   // edge A->B : B 依赖 A 的输出
    private readonly Dictionary<string,HashSet<string>> _down=new();
    private readonly Dictionary<string,HashSet<string>> _up=new();
    public PjDepGraph Edge(string a,string b){ Add(_down,a,b); Add(_up,b,a); return this; }
    static void Add(Dictionary<string,HashSet<string>> m,string k,string v)
    { if(!m.ContainsKey(k))m[k]=new(); m[k].Add(v); }
    public HashSet<string> Downstream(string x)=>Closure(x,_down);
    public HashSet<string> Upstream(string x)=>Closure(x,_up);
    static HashSet<string> Closure(string x,Dictionary<string,HashSet<string>> g)
    { var r=new HashSet<string>(); var q=new Queue<string>(new[]{x});
      while(q.Count>0){var n=q.Dequeue();foreach(var m in g.GetValueOrDefault(n,new()))if(r.Add(m))q.Enqueue(m);}
      return r; }
    public HashSet<string> Unaffected(string fault,HashSet<string> all)
    { var aff=Downstream(fault); aff.UnionWith(Upstream(fault)); aff.Add(fault);
      return new HashSet<string>(all.Except(aff)); }
}
```

### 故障级联策略
```csharp
public enum FaultAction { Continue, Isolate, Hold, Stop }
public enum FaultMode { Recoverable, Irrecoverable, Replaceable }
public sealed record FaultDecision(string Pj,FaultAction Action,string Reason);
public sealed class FaultPropagation
{
    private readonly PjDepGraph _g; private readonly int _holdTimeout;
    public FaultPropagation(PjDepGraph g,int holdTimeout=30){_g=g;_holdTimeout=g==null?0:holdTimeout;}
    public FaultPropagation(PjDepGraph g):this(g,30){}

    public List<FaultDecision> Analyze(string fault,FaultMode mode,
        HashSet<string> all,Func<string,bool> canReplace,bool allowPartial,int waited=0)
    {
        var res=new List<FaultDecision>{new(fault,FaultAction.Isolate,"隔离故障PJ")};
        var down=_g.Downstream(fault); var up=_g.Upstream(fault);
        foreach(var u in _g.Unaffected(fault,all))res.Add(new(u,FaultAction.Continue,"无关分支继续"));
        foreach(var d in down)
        {
            if(mode==FaultMode.Replaceable && canReplace(d)) res.Add(new(d,FaultAction.Continue,"改派替代继续"));
            else if(mode==FaultMode.Recoverable && waited<_holdTimeout) res.Add(new(d,FaultAction.Hold,"挂起等故障恢复"));
            else res.Add(new(d,FaultAction.Stop,"输入缺失,级联停"));
        }
        foreach(var u in up) res.Add(new(u,FaultAction.Hold,"停止向故障路径供片,半成品安全保持"));
        return res;
    }
    public CjState CjTarget(List<FaultDecision> d,FaultMode mode,bool allowPartial)
    { if(d.All(x=>x.Action is FaultAction.Continue or FaultAction.Isolate))
        return CjState.Executing;                 // 局部隔离, CJ继续(标Degraded)
      if(d.Any(x=>x.Action==FaultAction.Stop))return CjState.Failed;
      return CjState.Executing; }                 // Hold中仍维持, 超时再升级
}
```

### 汇合点等待
```csharp
public sealed class JoinBarrier
{
    private readonly HashSet<string> _branches; private readonly HashSet<string> _arrived=new();
    public JoinBarrier(IEnumerable<string> branches){_branches=new(branches);}
    public void Arrive(string b,string wafer){_arrived.Add(b);}
    public bool AllArrived=>_branches.IsSubsetOf(_arrived);
    public IEnumerable<string> Missing=>_branches.Except(_arrived);
    public bool CanJoin=>AllArrived;   // 缺路则等待, 已到分支片安全保存
}
```

public class FaultPropagationTests

    // A->B->C 顺序链
    [Fact] public void 顺序链_B故障_A上游Hold_C下游停_无无关()

## 三、故障级联决策（手绘参考）
```
故障PJ → 依赖图求闭包: 下游(消费者)/上游(供片)/无关
可替代/独立分支 → 隔离+继续(CJ Degraded, 最终可能Partial)
关键路径不可替 → 下游到安全点Stop + 上游停供Hold半成品 + 故障PJ三分类 → CJ Failed
可短暂恢复 → 下游Hold等待(超时) → 恢复则续 / 超时升级Stop
菱形汇合: 健康分支继续, 产出在JoinBarrier等缺失路(已到不丢), 补齐再汇合
已完成PJ: 保持终态成果不重做
```

## 四、今日易错点
1. 故障一律全停（无关健康分支被误伤，应按依赖闭包精确隔离）。
2. 故障一律继续（下游等不到输入空转、上游继续供片堆积）。
3. 不区分上游/下游（上游停供、下游挂起/停，动作方向相反）。
4. 可恢复故障直接判失败（应先 Hold 带超时，超时再升级）。
5. 菱形缺路时把健康分支的片丢弃或让汇合点假完成（已到分支安全等待、记录缺路）。
6. 已完成 PJ 被回退/重做（成果保持，续跑只针对未完成）。
7. 局部隔离不标 Degraded、最后静默 Completed（必须显式标记、Partial 需授权）。
8. 不考虑共用安全系统（真空/安全门故障属于全局，不能当局部隔离）。
9. 故障 PJ 内片不做三分类就级联（仍需 W17 完成/在途/未开始处置并守恒）。
