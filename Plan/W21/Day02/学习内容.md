## 一、今日目标
1. 实现 CjCommandCascade：Start/Pause/Resume/Cancel/Abort 分别如何作用到不同状态的子 PJ。
2. 掌握"按子状态分类下发"：已完成/执行中/未启动的 PJ 对同一命令反应不同。

## 二、背景知识（先读，30 分钟）

### 1. 级联的本质
- CJ 是容器，真正执行的是子 PJ；CJ 命令必须"翻译"成对一组 PJ 的命令集合。
- 但不能无脑广播：不同 PJ 处于不同状态（Completed/Executing/Queued/Paused），同一命令对它们的合法性不同，要按状态分类。

### 2. 五类命令的级联规则
- **Start(CJ)**：只启动当前可启动（依赖就绪、片就位、资源可用）的 PJ；未就绪的登记、等其依赖完成再启动（W20 Day03 已做，今天纳入统一级联器）。
- **Pause(CJ)**：对 Executing/Pausing 的 PJ 下发 Pause（让其到安全点）；Completed 的不动；Queued 的标记"暂停挂起"（依赖满足也不启动，直到 Resume）。
- **Resume(CJ)**：对被级联 Paused 的 PJ 下发 Resume（现场校验后续跑）；解除 Queued PJ 的"暂停挂起"标记；Completed 不动。
- **Cancel(CJ)**：仅当所有 PJ 都未动工（无片离源）才整体 Cancel；只要有 PJ 已动工，Cancel 拒绝、应走 Abort（与单 PJ 的 NothingTouched 一致，范围扩到全部子 PJ）。
- **Abort(CJ)**：对所有活动 PJ（Executing/Pausing/Paused）下发 Abort，各自三分类处置片；Completed 保持；Queued 取消。CJ 汇总现场。

### 3. 按子状态分类（以 Pause 为例）
```
子PJ状态 Completed → 不动(保持终态)
         Executing → 下发Pause, 该PJ进Pausing
         Pausing   → 幂等(已在暂停中, 不重复下)
         Paused    → 幂等
         Queued    → 标记SuspendPending(依赖满足也不启动)
```
- 命令要幂等：对已经处于目标过程/状态的 PJ 重复下发不产生副作用。

### 4. 级联结果聚合与 CJ 迁移
- 级联器收集每个 PJ 的结果（Accepted/Rejected/Ignored）。
- Pause：全部活动 PJ 都到 Paused（AllChildrenPaused）才驱动 CJ-FSM 到 Paused（Day01 栅栏）。
- Abort：全部活动 PJ 都进入终态（Aborted/Completed）后 CJ 才到 Aborted。
- Resume：被暂停 PJ 成功恢复、挂起标记解除后 CJ 回 Executing。
- 任一关键 PJ 拒绝且导致命令目标无法达成：CJ 不迁移、记录原因、按异常处理（不能"部分暂停却宣称 Paused"）。

### 5. 部分受理的一致性
- 级联不是分布式事务，但要有确定策略：
  - 先做可执行性预判（哪些 PJ 能接受该命令），若命令要求"全部到某态"而存在不可达的 PJ，提前判定整体不可行、不做半吊子下发（all-or-nothing 思路）。
  - 允许渐进的（Pause 本来就要等安全点）：先下发，靠栅栏汇聚，未到齐前 CJ 处于 Pausing。
- 级联动作与 CJ-FSM 迁移分离：级联负责"对子 PJ 下命令"，CJ-FSM 负责"自己何时迁移"，靠聚合事件连接（Day01）。

### 6. 与 W18 并发/资源的关系
- 级联 Pause/Abort 时，多 PJ 可能在多腔并行，沿用 W18 安全点栅栏与资源释放：所有相关并发单元安全后才算子 PJ Paused/Aborted。
