# W27 · Day06 答案与参考实现

## 一、自测题标准答案
1. **E164 解决什么/WKN 能力**：E164 定义跨标准、跨厂商的公共元数据表示与语义约定（标准命名、单位量纲、数据类型、枚举语义、公共结构），并在 Freeze III 集中定义公共 protobuf 元素以保证互操作。其中 Well-Known Names 给通用物理量/状态规定标准路径与语义；设备把厂商私有变量映射到对应 WKN 后，客户端不必关心各厂商私有命名，用同一个标准名就能在不同品牌/型号设备上取到同语义的量（如都用"腔体温度 WKN"取温度），从而写出跨设备通用的 FDC/SPC 规则与看板，这是自描述（结构互通）之上的语义互通。
2. **为何冻结/II 与 III 差异与不变**：各标准独立演进、版本错配会破坏互操作（设备与客户端按不同版本解析出错），Freeze 把相互配套的一组标准版本锁定成套件、声明互操作基线。Freeze II（0710）用 SOAP/XML over HTTP，成熟、存量主流；Freeze III 改用 Protocol Buffers（近 gRPC 高效传输）。**根本差异在编码与传输层**（冗长文本 XML→紧凑二进制 protobuf、SOAP→高效 RPC/流）；**不变的是模型语义**——E120 CEM 对象树、E125 自描述、E132 授权会话、E134 三触发采集计划、E164 WKN 语义全部延续。学新不学旧逻辑，换的是序列化与传输。
3. **SOAP/XML 优缺点/为何转 protobuf**：优点——人可读、自解释、HTTP 防火墙友好、Schema/工具链成熟、早期互操作易落地；缺点——XML 标签冗余、报文大，SOAP 封装重，XML 解析耗 CPU，在 10Hz–1kHz、多客户端、海量 trace 下带宽与 CPU 成为瓶颈。protobuf：二进制紧凑（报文显著变小）、强类型 .proto schema、编译期代码生成、序列化/反序列化快、天然跨语言、适合流式与 AI 数据管道，因此 Freeze III 转向它以支撑高吞吐大数据。
4. **设备端服务类别/数据回传**：教学归纳四类——①元数据/自描述服务（返回 EqSD 模型）；②会话与授权服务（登录认证、权限、会话保活/关闭，E132）；③采集计划管理服务（创建/激活/暂停/删除计划，E134）；④数据回报（按计划把数据包发回客户端）。SOAP 架构下客户端也可暴露一个回调 Web Service，设备主动调用把数据 POST 回去（双向服务）；Freeze III 下更接近服务端流（gRPC streaming）推送。即设备不只是被动应答，还作为数据提供方主动推送。
5. **辅助标准性质**：E128/E138 是 XML Semiconductor Common Components，属 Freeze II 的**辅助规范**——定义用 XML 表达时的公共组件/Schema 构件，保证各标准 XML 一致；E179 是 Freeze 套件的支撑性辅助标准（具体条目以 SEMI 原文为准）；E147 是 **Guide 指南**（非强制），给实施方法与最佳实践。五大主标准（E120/E125/E132/E134/E164）定义强制接口与模型，辅助件提供公共构件，指南给方法建议，三者性质不同。
6. **内核与编码传输分离的原因**：模型语义（对象树、三触发采集、授权、WKN）是长期稳定的业务内核，而编码传输（SOAP/XML vs protobuf/gRPC）是会随 Freeze 版本与技术演进而替换的外层。若耦合，换 Freeze III 就要重写采集逻辑、风险大；分离后采集引擎产出与传输无关的中性数据模型（Packet/样本），编码器可插拔（XmlEncoder/ProtoEncoder），同一内核既支持存量 Freeze II 又能平滑加 Freeze III，便于测试（对同一模型比较两种编码的语义等价）与演进。这和你 EapLab 里"域模型与通信层分离、换传输不动域"是同一架构原则。
7. **WKN 统一取数**：设备在自描述（E125）里为每个变量标注其对应的 E164 WKN（私有路径→标准语义映射）；客户端先取自描述建立"私有路径↔WKN"映射，之后统一按 WKN 查询/订阅——A 厂 `/PM1/Temp/Act` 与 B 厂 `/ChamberA/TempC` 都标注为"腔体温度 WKN"，客户端规则只认 WKN，运行时由映射层翻译成各设备私有路径取值。新增设备只要正确标注 WKN，上层 FDC/SPC 逻辑零改动，实现跨厂商语义统一。

## 二、参考实现（net8.0）：WKN 映射 + 可插拔双编码

```csharp
namespace EapLab.Eda.Meta;
// 私有路径 <-> 标准WKN 语义映射
public sealed class WknMapper
{
    private readonly Dictionary<string,string> _privToWkn=new();
    public void Bind(string privatePath,string wkn){_privToWkn[privatePath]=wkn;}
    public string? ToWkn(string priv)=>_privToWkn.GetValueOrDefault(priv);
    // 客户端按WKN取: 找到该设备上对应私有路径
    public string? ToPrivate(string wkn)=>_privToWkn.FirstOrDefault(kv=>kv.Value==wkn).Key;
}

// 与编码无关的中性数据模型
public sealed record NeutralSample(double At,string Path,double Value,Quality Q,string? Wkn);
public interface IPacketEncoder{ string Format{get;} string Encode(IEnumerable<NeutralSample> rows); }

// Freeze II 风格: XML
public sealed class XmlPacketEncoder:IPacketEncoder
{ public string Format=>"XML";
  public string Encode(IEnumerable<NeutralSample> rows)=>
    "<Packet>"+string.Join("",rows.Select(r=>$"<s t='{r.At}' p='{r.Path}' wkn='{r.Wkn}' q='{r.Q}'>{r.Value}</s>"))+"</Packet>"; }

// Freeze III 风格: 紧凑二进制(tag=varint编号, 教学模拟protobuf的字段编号+定长, 不引库)
public sealed class ProtoLikeEncoder:IPacketEncoder
{ public string Format=>"PB";
  public string Encode(IEnumerable<NeutralSample> rows)=>"PB["+string.Join("|",rows.Select(r=>$"{r.At};{r.Path};{r.Value};{r.Q};{r.Wkn}"))+"]"; }

public sealed class EncodeService{
    readonly WknMapper _wkn;public EncodeService(WknMapper w){_wkn=w;}
    public List<NeutralSample> Project(IEnumerable<(double at,string path,double val,Quality q)> raw)
    =>raw.Select(x=>new NeutralSample(x.at,x.path,x.val,x.q,_wkn.ToWkn(x.path))).ToList();
    public string Send(IEnumerable<NeutralSample> s,IPacketEncoder enc)=>enc.Encode(s);
}
```

## 三、内核-编码分层（手绘参考）
```
┌─────────────────── 稳定内核(与Freeze版本无关) ───────────────────┐
│ CEM对象树(E120) 自描述(E125) 授权会话(E132) 三触发采集(E134) WKN(E164)│
│            采集引擎产出中性模型 NeutralSample/Packet              │
└───────────────┬───────────────────────────────┬────────────────┘
        Freeze II 编码层                  Freeze III 编码层
   SOAP/XML(E128/E138构件)            Protocol Buffers(.proto,E164公共元素)/gRPC流
   人可读/成熟/存量主流               紧凑快/高吞吐/AI; 可插拔, 语义零改动
服务: 元数据 | 会话授权 | 采集计划管理 | 数据回报(SOAP回调 / PB流推送)
对照: GEM=HSMS+SECS2+SxFy(控制); EDA=HTTP+XML/PB(只读采集); 端口隔离/数据源共享
```

## 四、今日易错点
1. 以为 Freeze III 改了对象/采集模型（只改编码传输，语义延续）。
2. 混淆自描述（结构互通）与 WKN（语义互通），缺 WKN 仍无法跨厂商通用规则。
3. 把 E147 指南当强制接口规范。
4. 认为 EDA 只用客户端拉取（设备也主动回报/推流）。
5. 采集逻辑与 XML 编码耦合，导致升级 Freeze III 要重写内核。
6. 记混 E138（XML 公共组件）与 E134（采集计划）。
7. 忽视单位/量纲统一（E164 语义的一部分，Pa/mTorr 不统一 WKN 也白搭）。
8. 认为 protobuf 人可读、可像 XML 一样裸读（二进制，靠 .proto/schema 解析）。
