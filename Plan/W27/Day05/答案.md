# W27 · Day05 答案与参考实现

## 一、自测题标准答案
1. **采集计划要素**：至少声明——绑定会话；采集的变量集合（CEM 路径，区分 SVDV/ECV/EXV）；采集触发方式与采样率（周期 Hz，或绑定的事件/异常）；上报触发条件（定时 flush 间隔 / 累计点数 / 事件即报）；数据格式（是否带时间戳、质量码）；计划状态（创建/激活/暂停/删除）。计划与会话绑定，会话结束自动撤销。
2. **三种采集/用途**：周期采集对应 SVDV（简单值变量），按固定频率连续采，形成时间序列/trace 波形，供 FDC 实时检测、SPC、VM；事件采集对应 ECV，在指定 CEM 事件（如 Step 切换、作业开始）发生时采一组上下文快照，用于把数据对齐到工艺节点；异常采集对应 EXV，在异常置位/清除时采相关变量，用于故障/报警归因。三类触发器独立，可在同一计划混合但语义分清：连续量靠周期、过程节点靠事件、故障现场靠异常。
3. **采样/上报解耦原因/耦合后果**：采样是"多久从数据源读一次并打时间戳"，上报是"多久把攒下的数据打包发一次"，二者频率诉求不同（内部要高频保证波形不失真，网络发送要批量以减少 HTTP 开销与连接压力）。解耦后可 100Hz 内部采、1s 批量报，事件/异常还能插队即报，慢网络不影响内部采样节奏。若耦合（采一次发一次），100Hz 就是每秒上百次 HTTP 调用，开销巨大、网络一抖就丢采样节奏、慢客户端会反压采样线程，实时性与稳定性都崩。
4. **100Hz/1s 数据包结构**：1 秒采 100 点，一个数据包含：会话/计划 ID、时间窗（本包起止时间戳）、变量路径列表（如 N 个 SVDV）、100 行采样（每行=单调时间戳 + N 个变量值 + 各值质量码），可能含丢点/不连续标记；若期间发生事件/异常，附 ECV/EXV 快照段。即"一个时间窗 × 一组变量 × 多行带时间戳与质量的采样"的二维表结构。
5. **质量码取值/为何依赖**：常见 Good（正常可信）、Bad（传感器故障/值不可用/超量程）、Uncertain（可疑、保持/估算/通信抖动）、以及丢点/不连续标记。FDC 规则与 VM 模型把数据当输入做判定/预测，若把坏点当真值会误报警或预测失真；质量码让上层区分"值真的异常"与"采集本身坏了"，坏点应剔除/插补而非触发工艺误判，是数据可信的前提。
6. **慢客户端丢点如何体现**：不能静默丢。Day04 背压丢最旧点时，要在后续数据报告里显式标注——记录该计划时间窗内丢弃点数/间断区间，数据点/包头打"不连续/有丢失"质量标记与丢失区间时间戳，让客户端知道这段 trace 不完整、不能当连续波形用。即"允许为保实时而丢，但必须如实告知丢了哪段"，区别于 GEM 事务的不丢。
7. **DCM vs GEM 采集/数据源**：相同——都是"定义要什么→在恰当时机取数→打包上报"，且都从设备同一权威数据源只读取值（同源，数值一致）。不同——GEM 用 S2F33 定义报告、S2F35 关联 CEID、S6F11 在事件时对单一 Host 发稀疏快照（一对一、控制面、事件驱动）；E134 DCM 由多客户端各自建采集计划，支持高频周期 trace + 事件 + 异常、批量上报、带质量码、会话隔离（一对多、采集面）。GEM 重"事件时刻的状态快照与控制联动"，DCM 重"连续时间序列给多方分析"。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Eda.Dcm;
public enum Trigger{ Periodic,OnEvent,OnException }
public enum Quality{ Good,Bad,Uncertain,Gap }
public sealed record Sample(double At,double Value,Quality Q);

public sealed class CollectionPlan
{
    public string PlanId{get;}public List<string> Tags{get;}public Trigger Trigger{get;}
    public double SampleHz{get;}public double FlushEverySec{get;}public int FlushEveryN{get;}
    public string? BindEvent{get;}
    private readonly List<Dictionary<string,Sample>> _buf=new();
    public CollectionPlan(string id,IEnumerable<string> tags,Trigger t,double hz=10,double flushSec=1,int flushN=1000,string? ev=null)
    {PlanId=id;Tags=tags.ToList();Trigger=t;SampleHz=hz;FlushEverySec=flushSec;FlushEveryN=flushN;BindEvent=ev;}
    public void AddRow(Dictionary<string,Sample> row)=>_buf.Add(row);
    public bool Due(double now,int buffered){return Trigger==Trigger.Periodic &&
        (buffered>=FlushEveryN);} // 定时判定由调度器结合时间
    public List<Dictionary<string,Sample>> Drain(){var x=new List<Dictionary<string,Sample>>(_buf);_buf.Clear();return x;}
    public int Buffered=>_buf.Count;
}

public sealed class DataCollector
{
    readonly EquipmentDataBus _bus;public DataCollector(EquipmentDataBus bus){_bus=bus;}
    public Dictionary<string,CollectionPlan> Plans{get;}=new();
    readonly Dictionary<string,double> _lastFlush=new();
    public void Add(CollectionPlan p){Plans[p.PlanId]=p;_lastFlush[p.PlanId]=0;}

    // 周期采样tick: 从唯一数据源读值+质量码, 写入计划缓冲
    public void SampleTick(string planId,double now,Func<string,Quality> qualityOf)
    { var p=Plans[planId];if(p.Trigger!=Trigger.Periodic)return;
        var row=p.Tags.ToDictionary(t=>t,t=>new Sample(now,_bus.Read(t),qualityOf(t)));p.AddRow(row); }

    // 事件/异常触发: 立即采一组ECV/EXV快照
    public Dictionary<string,Sample> SnapshotOn(string planId,double at,string ev,Func<string,Quality> q)
    { var p=Plans[planId];
        return p.Tags.ToDictionary(t=>t,t=>new Sample(at,_bus.Read(t),q(t))); }

    // 上报触发: 定时或凑点 -> 打包(教学: 返回数据包, 实际序列化XML/protobuf)
    public record Packet(string PlanId,double From,double To,List<Dictionary<string,Sample>> Rows,int Dropped);
    public Packet? MaybeFlush(string planId,double now,int dropped=0)
    { var p=Plans[planId];if(p.Buffered==0)return null;
        bool time=now-_lastFlush[planId]>=p.FlushEverySec; bool cnt=p.Buffered>=p.FlushEveryN;
        if(!(time||cnt))return null;
        var rows=p.Drain();_lastFlush[planId]=now;
        return new Packet(planId,rows.First().First().Value.At,now,rows,dropped); }
}
```

## 三、采样→上报数据流（手绘参考）
```
唯一数据源 ──读值+单调时间戳+质量码──▶ 各会话采集计划缓冲(独立)
周期: SampleTick按Hz写SVDV行 ; 事件: 事件发生采ECV快照(插队) ; 异常: 采EXV
采样(高频内部) ⟂ 上报(定时flush/凑N点/事件即报) → 数据包=时间窗×变量×多行(ts,值,质量)
慢客户端: 缓冲有界, 丢旧点且包头标GAP/丢点区间(不静默丢); 坏点标Bad/Uncertain
编码: FreezeII=XML, FreezeIII=protobuf; 计划绑会话, 会话亡计划撤
同源: 与GEM S6F11、E116时间账读同一数据源、同一时钟, 可跨通道对齐
```

## 四、今日易错点
1. 采样频率和上报频率混为一谈（必须解耦，高频采、批量报）。
2. 三类变量触发方式错配（SVDV 周期/ECV 事件/EXV 异常）。
3. 每计划开独立高频定时器线程（应集中调度，避免线程爆炸）。
4. 数据点不带时间戳/质量码，上层无法对齐与判可信。
5. 慢客户端丢点不标记，客户端把不连续 trace 当完整波形。
6. 事件快照塞进周期缓冲（应即时插队、独立结构）。
7. 计划不绑会话，会话结束不撤销（僵尸计划空耗采样）。
8. EDA 采集另建数据源、与 GEM/E116 数值或时钟对不齐（必须同源同戳）。
