## 二、背景知识（先读，35 分钟）

### 1. 采集计划 Collection Plan（DCM 核心）
- 客户端在会话内创建采集计划，声明：
  - 采集哪些变量（CEM 路径/SVDV/ECV/EXV）；
  - **采集触发方式与频率**（周期多少 Hz；或绑定哪个事件/异常）；
  - **上报触发条件**（每隔多少 ms、累计多少点、或某事件时立即报）；
  - 数据格式/是否带时间戳与质量码。
- 计划可创建、激活、暂停、删除；绑定到会话，会话结束计划撤销（Day04）。

### 2. 三种采集方式（对应三类变量）
- **周期采集 Periodic（SVDV）**：按固定采样率持续采（如 10/50/100Hz），形成时间序列/trace，是 FDC 主力。
- **事件采集 On Event（ECV）**：当指定 CEM 事件发生时，采一组该事件声明的上下文变量（如 Step 开始时采 stepId/recipe/wafer），不连续采。
- **异常采集 On Exception（EXV）**：异常置位/清除时采相关变量快照（如报警时的压力/互锁），用于故障归因。
- 一个计划可混合，但实现上三类触发器独立。

### 3. 采样与上报解耦（关键设计）
- **采样**：设备内部按采样率从唯一数据源读值、打单调时间戳、写入该计划的缓冲。
- **上报**：按上报触发（定时 flush / 凑够 N 点 / 事件即报）把缓冲打包成一个数据报告发送。
- 解耦好处：内部可高频采样，网络发送可批量（减少 HTTP 调用），事件/异常可即时插队上报；慢客户端只影响自己的缓冲（Day04 背压）。

### 4. 数据报告结构（教学模型）
- 一个数据包含：会话/计划 ID、报告时间窗（起止时间戳）、变量路径集合、按时间排列的采样行（时间戳+各变量值+质量码），事件/异常报告含触发对象与 ECV/EXV 快照。
- Freeze II 用 XML 结构表达，Freeze III 用 protobuf 高效编码（Day06/W29）。

### 5. 数据质量码（Data Quality）
- 每个采样点可带质量：Good（正常）、Bad（传感器故障/不可用）、Uncertain（可疑/估算）、以及丢点/不连续标记（Day04 慢客户端丢旧点要标）。
- FDC/VM 依赖质量码判断数据是否可用于模型，坏点不能当真实值喂模型。

### 6. 与 GEM 采集（S2F33/35、S6F11）对照
- GEM：Host 定义报告、事件触发稀疏快照、一对一；DCM：客户端自定义采集计划、支持高频周期 trace + 事件/异常、多客户端各自独立计划。底层都从同一数据源读（同源）。

### 7. 资源与确定性
- 高频周期采集是 CPU/内存敏感操作：采样任务集中调度、避免每计划独立定时器线程；按授权频率上限裁剪（Day04）；时间戳用同一单调时钟，保证与 E116 时间账、作业事件可对齐（W24 同源同戳）。
