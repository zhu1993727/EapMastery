# W27 · Day03 答案与参考实现

## 一、自测题标准答案
1. **解决的痛点/零硬编码原理**：GEM 里 VID/CEID/ALID 与报告要 Host 事先配置（S2F33/35），换机型、加变量、改厂商都要改主机配置，应用和设备型号强耦合。EqSD 让设备把完整模型作为元数据"自己说出来"，客户端连上后先取这份自描述，运行时动态得知对象树、变量/事件/异常及其类型单位语义，再据此动态构建订阅，无需为每种设备预置点表，从而做到通用采集客户端零硬编码、跨厂商即插即用。
2. **元数据内容/缺字段后果**：至少含对象层次（类/实例/父子/物理逻辑类型）；变量的路径名、数据类型、单位量纲、取值范围 min/max、枚举字典、读写性、可否周期采样、描述；事件的 ID/触发时机/携带 ECV 列表；异常的 ID/置位清除语义/EXV/严重级；设备型号/软件与模型版本。缺单位→数值无法解释（如 Pa vs mTorr、℃ vs ℉）；缺范围/枚举→无法做合法性校验、无法把状态码翻译成人可读含义；缺类型→无法正确反序列化；缺 ECV/EXV 清单→不知道事件/异常该带哪些上下文；缺版本→升级后无法判断模型是否变化。
3. **连接到订阅步骤**：①建立 HTTP(S) 连接；②经 E132 完成客户端身份认证与授权（Day04，确认能访问哪些对象）；③调用自描述服务（GetSelf-Description/GetMetadata，可整树或按子树）；④设备返回 EqSD 元数据文档；⑤客户端解析并在本地构建对象/成员模型（可结合 E164 WKN 映射到标准语义）；⑥据此向 E134 DCM 提交采集计划（订阅哪些路径、周期还是事件触发、打包/上报方式）；⑦开始接收数据流。设备模型版本变化时回到③重新获取。
4. **Freeze II/III 异同**：相同——元数据语义完全一致（对象树、变量/事件/异常定义、类型单位范围、ECV/EXV、版本），客户端理解的"设备模型"不变。不同——编码与传输：Freeze II 用 XML（遵循 E138 公共组件 Schema，人可读、工具成熟但冗长、解析/带宽开销大），Freeze III 用 Protocol Buffers（.proto 定义、E164 放公共 protobuf 元素，紧凑、序列化快、适合大数据/AI）。即"同一份语义、两种序列化形态"，学习要抓语义、再分别落地两种编码。
5. **E164 WKN/关系**：自描述让客户端"读得懂结构"，但若厂商对同一物理量命名各异（ChamberTemp/TempC/ProcTemp），跨设备仍无法用统一逻辑取数。E164 定义一批标准 Well-Known Names（标准路径/名称、单位、类型、语义），设备把通用量标注其对应 WKN，客户端用 WKN 就能跨厂商取到同语义量（如所有设备的"腔体压力"用同一标准名）。关系：EqSD 描述"设备有什么、怎么解析"，E164 提供"通用语义命名约定"，自描述里每个成员可挂其 WKN，二者结合才实现真正跨厂商通用。
6. **为何 S2F29/31 不够**：S2F29 读 ECID 名称、S2F31 设 EC 等只是针对扁平 ID 的零散名称/参数查询，返回的是名字字符串，缺少层级化对象树、单位/量纲、取值范围/枚举、事件携带变量、异常语义、模型版本等完整元信息，且面向单一 Host 的配置式交互，不支持多客户端运行时动态发现整棵模型。EqSD 是层级化、语义完备、版本化、面向多客户端只读发现的完整模型文档，通用化能力不是一个量级。
7. **升级新增变量/客户端处理**：EqSD 带模型版本（型号/软件/模型 revision）。设备升级后模型版本变化，客户端在重连或检测到版本变更时重新获取自描述，与本地缓存模型 diff：新增成员→可纳入订阅/展示；删除/改名→标记旧订阅失效并降级（不崩溃）；类型/单位变化→按新元数据解析；在重新同步前对未知成员安全忽略而非报错。核心：客户端永远以设备当前自描述为准、缓存可失效重建，不假设模型静态不变。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Eda.Meta;
public enum DType{ Boolean,Int32,Int64,Double,String,Struct,Array }
public sealed record VarMeta(string Path,DType Type,string Unit,double? Min,double? Max,
    IReadOnlyDictionary<int,string>? Enum,bool Periodic,string? WellKnown,string Desc);
public sealed record EventMeta(string Path,string Trigger,IReadOnlyList<string> EcvPaths);
public sealed record ExcMeta(string Path,string Severity,IReadOnlyList<string> ExvPaths);
public sealed record ModelMeta(string Model,string Software,string Revision,
    List<VarMeta> Vars,List<EventMeta> Events,List<ExcMeta> Exceptions);

public sealed class MetaGenerator
{
    public ModelMeta From(CemObject root)
    { var vars=new List<VarMeta>();
        foreach(var(p,m) in root.AllMembers())
        { var path=$"{p}/{m.Name}";
            if(m.Kind is MemberKind.SVDV or MemberKind.ECV or MemberKind.EXV)
                vars.Add(new VarMeta(path, Parse(m.DataType),m.Unit,null,null,null,m.Kind==MemberKind.SVDV,WknOf(path),m.Name));
        }
        return new ModelMeta("MultiChamberTool","fw-9.1","2026.09",vars,new(),new()); }
    static DType Parse(string t)=>t switch{"int"=>DType.Int32,"bool"=>DType.Boolean,"string"=>DType.String,_=>DType.Double};
    static string? WknOf(string p)=>p.Contains("ActualTemp")?"WKN.Chamber.Temperature":
        p.Contains("Power")?"WKN.RF.ForwardPower":null;
    public VarMeta? Find(ModelMeta m,string path)=>m.Vars.FirstOrDefault(v=>v.Path==path);
    // Freeze II 风格: 序列化为XML(教学, 用System.Text.Json演示结构化; XML同理按E138)
    public string ToXmlLike(ModelMeta m)=>
        "<Model name='"+m.Model+"' rev='"+m.Revision+"'>"+
        string.Join("",m.Vars.Select(v=>$"<Var path='{v.Path}' type='{v.Type}' unit='{v.Unit}' wkn='{v.WellKnown}'/>"))+"</Model>";
}
```

## 三、连接→自描述→订阅时序（手绘参考）
```
FDC客户端                 设备EDA Server
  │── HTTPS connect ───────────▶│
  │── E132 认证/授权(token) ───▶│ ──授权通过, 限定可见子树
  │── GetSelfDescription ─────▶│
  │◀─ EqSD元数据(对象树/变量类型单位范围枚举/事件ECV/异常EXV/版本, 挂E164 WKN)
  │ 本地构建模型(零硬编码, 按WKN映射标准语义)
  │── E134 提交采集计划(路径,周期/事件,打包) ─▶│
  │◀════ 数据流(SVDV周期 / ECV随事件 / EXV随异常) ════
  │ 检测模型版本变化 → 重新GetSelfDescription → diff(新增/失效/类型变)
编码: FreezeII=XML(E138 Schema) ; FreezeIII=Protobuf(.proto,E164公共元素); 语义不变
```

## 四、今日易错点
1. 以为 EDA 也要像 GEM 一样在 Host 侧预配点表（EqSD 运行时自发现）。
2. 元数据漏单位/范围/枚举/版本，导致无法解析、校验、感知升级。
3. 分不清"结构自描述(E125)"与"标准命名(E164 WKN)"，以为有结构就能跨厂商通用。
4. 以为 Freeze III 换了对象模型（只是 XML→protobuf 编码，语义不变）。
5. 拿 S2F29/31 等同 EqSD（前者零散名称、后者完备层级模型）。
6. 客户端把模型当静态、设备升级后不重新获取/不做 diff 与失效降级。
7. ECV/EXV 也当周期变量采（它们由事件/异常触发，非周期）。
8. 自描述里不标只读/可周期，客户端误尝试写或订不可周期量。
