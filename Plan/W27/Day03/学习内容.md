# W27 · Day03（周三）E125 EqSD 设备自描述：让客户端自己"读懂"设备

> 建议时长：90 分钟。CEM 给了对象树骨架，E125 Equipment Self-Description 让设备能把"我是谁、我有哪些对象/变量/事件/异常、各自类型单位枚举范围是什么"完整描述给任意客户端，无需事先拿手册。今天学自描述的内容、获取流程、元数据字段，以及 Freeze II XML 与 Freeze III Protobuf 两种表达。

## 一、今日目标
1. 理解自描述（Self-Description）价值：客户端零预置配置即可发现设备模型。
2. 掌握 EqSD 描述的元数据内容：对象层次、成员定义（类型/单位/取值范围/枚举/访问性/描述）、事件/异常定义。
3. 掌握客户端获取自描述的流程（连接→取元数据→据此动态建订阅）。
4. 了解 Freeze II（XML/Schema，E138 公共组件）与 Freeze III（Protobuf）在自描述表达上的差异，E164 Well-Known Names 的作用。
5. 用 C# 为 Day02 的 CEM 树生成自描述元数据并支持按路径查询；xUnit 验证。

## 二、背景知识（先读，35 分钟）

### 1. 什么是自描述、为什么关键
- 传统 GEM：Host 要事先知道 VID/CEID/ALID 定义（S2F33 由 Host 配报告），换设备/加变量要改配置。
- EDA EqSD：设备**主动提供一份完整模型描述**（元数据），客户端连上后先"读说明书"，动态得知有哪些对象与成员、怎么解析，从而通用化、零硬编码——这是多客户端、跨厂商通用采集工具的基础。

### 2. EqSD 元数据包含什么
- **对象层次**：CEM 树（类名、实例名、父子包含、对象类型物理/逻辑）。
- **变量定义**：每个数据变量的名称/路径、数据类型（int/double/string/bool/数组/结构化）、单位、量纲、取值范围(min/max)、枚举值、读写性（EDA 基本只读）、采样可行性（能否周期采）、描述文本。
- **事件定义**：事件 ID/名称、触发时机、它携带哪些 ECV。
- **异常定义**：异常 ID/名称、置位/清除语义、携带哪些 EXV、严重级别分类。
- **版本信息**：设备型号、软件版本、模型版本（变更后客户端可感知）。

### 3. 客户端获取自描述的流程
1. 建立 HTTP(S) 连接，经 E132 认证授权（Day04）。
2. 请求自描述（EqSD/Metadata 服务，如 GetSelfDescription / GetMetadata）。
3. 设备返回完整（或按子树过滤的）元数据文档。
4. 客户端解析、构建本地模型，据此向 E134（Day05）发起采集计划订阅（订哪些路径、多快、事件还是周期）。
5. 模型版本变化时重新获取（设备改型/版本升级）。

### 4. Freeze II XML 与 Freeze III Protobuf
- **Freeze II**：自描述用 XML，遵循 E138（XML Semiconductor Common Components）定义的公共组件/Schema，结构清晰、人可读、工具链成熟，是存量主流；缺点是 XML 冗长、解析与带宽开销大。
- **Freeze III**：改用 **Protocol Buffers** 描述与编码（.proto 模型、E164 集中放跨标准公共 protobuf 元素），更紧凑、序列化快、适合大数据/AI；模型语义（对象/变量/事件/异常）不变，变的是表达与编码。
- 学习策略：先吃透"元数据语义"（与编码无关），再分别看 XML 与 protobuf 两种序列化形态。

### 5. E164 Well-Known Names（先建立印象，Day06 细讲）
- 若每家厂商对"腔体温度"命名不同，自描述仍难横向通用。E164 定义一批**公共知名名称/元数据约定**（标准路径名、单位、类型、语义），设备把通用量映射到 Well-Known Name，客户端就能跨设备用同一名字取"同一语义"的量。EqSD 描述里会标注某变量对应的 Well-Known Name。

### 6. 与 GEM S2F29/31（ECID/VID 名称）对照
- GEM 也有 S2F29（ECID 名称）、S2F31（设 EC）等"读名称"能力，但只是零散名称查询；EqSD 是完整、层级化、带类型单位范围语义的模型文档，完备度远高，且面向多客户端只读发现。
