# W27 · Day01 答案与参考实现

## 一、自测题标准答案
1. **一句话定位/分工**：EDA(Interface-A) 是设备侧**高带宽、多客户端、订阅式的只读数据采集通道**，把设备参数/状态/事件/异常以高频时间序列持续供给 FDC、YMS、R2R、VM 等分析应用；GEM(SECS/HSMS) 是**一对一的控制与事务通道**，负责派工、远程命令、状态机、报警控制、配方与 GEM300 物料流程。一个解决"海量数据给多方用"，一个解决"可靠地控设备、走业务流程"，二者并存、分工不重叠。
2. **为何不能用 S6F11 扛高频（≥3 点）**：①连接模型——GEM 一对一，只有一个 Host 接收，而 FDC/YMS/R2R 多消费方要各取所需，S6F11 无法多客户端独立订阅；②带宽/时序——S6F11 是带事务语义的事件消息，10Hz–1kHz 连续 trace 会形成消息风暴，序列化/确认开销大、且会挤占控制命令与时序，高频下发可能拖慢甚至阻塞控制面；③模型不匹配——GEM 采集是"事件发生时拍一份 VID 快照"（稀疏、离散），FDC 要的是固定周期连续波形、带精确采样时间戳与数据质量码，需要专门的采集计划（DCM）与缓冲/背压；④耦合风险——把大数据流和控制放一条 HSMS 连接，数据拥堵会影响派工/报警等安全相关事务，违背控制与采集隔离原则。
3. **传输栈/与 HSMS 关系**：EDA **不走 HSMS/SECS-II**，它基于 Web Services：Freeze I/II 用 SOAP/XML over HTTP/HTTPS，Freeze III 改用 Protocol Buffers（更高压缩/吞吐，面向大数据与 AI）。它和 HSMS 是同一台设备上**相互独立的两套服务/端口**，没有承载关系；SECS-II 的类型体系也不用于 EDA（EDA 用 CEM 对象模型 + XML/protobuf 表达）。这是最关键的区分：不要把 EDA 当成"HSMS 上多发点数据"。
4. **谁是服务端/客户端/数量**：EDA 里**设备是服务端**（EDA Server，暴露自描述模型与采集服务，监听 HTTP(S)），FDC、YMS、R2R、工程师诊断工具等是**客户端**；客户端数量是**多个并发**（一对多），每个客户端独立认证（E132）、独立建立会话、独立订阅自己关心的变量与频率，互不影响，一个客户端断开不影响其他客户端与 GEM。
5. **共享数据源/通道隔离各解决什么**：共享数据源——设备内部参数/状态/事件只有一个权威来源，GEM 报告与 EDA 流都从它只读取数，保证两条通道看到的数值一致、不出现"两本账"（接同源原则），也避免重复采样；通道隔离——GEM 与 EDA 用独立连接/端口/缓冲/线程，EDA 高频流量再大、某客户端再慢，也不会阻塞或拖垮 GEM 控制事务（控制安全优先），反之 GEM 忙也不丢 EDA 采集（各自缓冲）。一个保证"数据一致"，一个保证"互不影响、控制优先"。
6. **EDA 能否控制/正确路径**：**不能**。EDA 是只读采集通道，定义上不承担控制，客户端只能订阅/读取数据，不能经 EDA 下发 Hold、改参数、启停作业。原因：控制需要严格的状态机、授权、命令-应答-生效语义与安全联锁，这些属于 GEM/控制面；若允许数据分析方直接经数据通道控设备，会绕过状态机与权限造成安全事故。正确路径：FDC/APC 做出判定或决策 → 经控制通道（GEM S2F41 远程命令，或 APC/R2R→RMS→EAP 下发参数 overlay）→ 设备状态机合法迁移执行，EDA 只负责把执行前后的数据继续采上来（决策方与执行方分离，接前面 Alarm/Hold 结论）。
7. **标准族/Freeze 差别**：E120 CEM 公共设备模型（对象层次）；E125 EqSD 设备自描述（客户端发现"设备有什么"）；E132 客户端认证授权与会话（多客户端、谁能订什么）；E134 DCM 采集计划管理（订哪些变量、周期/事件触发、打包）；E164 EDA 公共元数据（Well-Known Names 与跨标准公共元素）；辅助 E128/E138（XML 公共组件）、E179，E147 是指南。Freeze II（0710）用 SOAP/XML over HTTP，是存量 Fab 主流、互操作成熟；Freeze III 改用 Protocol Buffers、面向高吞吐与 AI，是新方向。落地先掌握 Freeze II 的模型与服务流程，再理解 Freeze III 在编码层的演进（模型语义不变、传输编码变）。

## 二、参考实现（net8.0）：单一数据源、双通道出口概念模型

```csharp
namespace EapLab.Eda;
// 设备内部唯一权威数据源(只读采样接口), GEM与EDA都从这里取值, 不各自维护
public sealed class EquipmentDataBus
{
    private readonly Dictionary<string,double> _v=new();
    private readonly object _lk=new();
    public void Publish(string tag,double value){lock(_lk)_v[tag]=value;}
    public double Read(string tag){lock(_lk)return _v.GetValueOrDefault(tag);}
    public IReadOnlyDictionary<string,double> Snapshot(IEnumerable<string> tags)
    {lock(_lk)return tags.ToDictionary(t=>t,t=>_v.GetValueOrDefault(t));}
}

// GEM出口: 事件驱动稀疏快照(控制面), 与EDA独立队列, 互不阻塞
public sealed class GemOutlet{
    private readonly EquipmentDataBus _bus;public GemOutlet(EquipmentDataBus b){_bus=b;}
    public Dictionary<string,double> OnEvent(int ceid,IEnumerable<string> vids)
    =>new(){{"CEID",ceid}}.Concat(_bus.Snapshot(vids)).ToDictionary(k=>k.Key,k=>k.Value);}

// EDA出口: 一个客户端的订阅(周期/变量集), 高频取数; 多客户端各一份, 慢客户端只影响自己
public sealed class EdaSubscription{
    public string Client{get;}public HashSet<string> Tags{get;}public double IntervalSec{get;}
    private double _next;
    public EdaSubscription(string c,IEnumerable<string> tags,double hz){Client=c;Tags=tags.ToHashSet();IntervalSec=1.0/hz;}
    public bool Due(double now){if(now>=_next){_next=now+IntervalSec;return true;}return false;}}

public sealed class EdaOutlet{
    private readonly EquipmentDataBus _bus;public EdaOutlet(EquipmentDataBus b){_bus=b;}
    private readonly List<EdaSubscription> _subs=new();
    public void Subscribe(EdaSubscription s)=>_subs.Add(s);
    // 每个采样节拍: 只给到期的客户端推各自订阅; 某客户端慢用独立缓冲, 不影响他人与GEM
    public List<(string client,IReadOnlyDictionary<string,double> sample,double at)> Tick(double now)
    =>_subs.Where(s=>s.Due(now)).Select(s=>(s.Client,_bus.Snapshot(s.Tags),now)).ToList();}
```

## 三、双通道架构（手绘参考）
```
                 ┌──────────── 设备内部唯一权威数据源(传感器/FSM/作业状态) ───────────┐
                 │  只读采样, 不允许通道反向写; 同一时钟/同一数值(同源)              │
                 └───────┬───────────────────────────────────────┬──────────────┘
            控制面(稀疏/可靠) │                                       │ 采集面(高频/只读)
                 ┌────────▼─────────┐                     ┌─────────▼──────────┐
   FAB EAP ◀──▶  │ GEM: HSMS+SECS2  │                     │ EDA Server: HTTP(S)│ ◀── FDC
   一对一        │ S2F41/S6F11/S16  │                     │ SOAP/XML | protobuf│ ◀── YMS
   命令/状态/流程 │ 受理≠生效/Spool  │                     │ 多客户端订阅(DCM)   │ ◀── R2R
                 └──────────────────┘                     └────────────────────┘ ◀── 工具
            独立端口/线程/缓冲, 一条堵不影响另一条; EDA只读, 控制决策回GEM/APC下发
```

## 四、今日易错点
1. 以为 EDA 是 HSMS/SECS-II 上多发数据（实为独立 HTTP Web Services 栈）。
2. 以为 EDA 一对一（实为一对多、设备做服务端、多客户端并发订阅）。
3. 用 S6F11 硬扛 10Hz+ 波形（消息风暴、挤占控制、无法多客户端）。
4. 两条通道各采各样、数值对不上（必须共享唯一数据源、只读取数）。
5. 让 EDA 通道直接 Hold/控设备（只读不控，决策回控制面，决策方≠执行方）。
6. 记混标准职责（E120 模型/E125 自描述/E132 授权会话/E134 采集计划/E164 元数据）。
7. 以为 Freeze 是可选协议版本（是配套标准锁定版本，II=SOAP/XML 主流，III=protobuf 新方向）。
8. 忽视隔离：高频客户端变慢拖死控制面（必须独立缓冲/线程、控制优先）。
