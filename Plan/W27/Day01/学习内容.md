## 二、背景知识（先读，35 分钟）

### 1. GEM 通道解决什么、不解决什么
- 你已掌握的 SECS/GEM（E5/E37 HSMS + E5 SECS-II + E30 GEM + GEM300）是**控制与事务通道**：一对一（一台设备对一个 Host/EAP）、请求-应答为主、事件驱动稀疏上报（S6F11/S5F1/S16F1）、典型 1–10Hz 以下、消息要保证控制语义（受理/生效/Spool）。
- 它不擅长：FDC 要 10Hz–1kHz 连续波形/参数流、多个消费方（FDC、YMS、R2R、工程师工具）同时各取所需、海量 trace 数据不挤占控制事务。硬用 S6F11 高频推会造成消息风暴、拖慢控制、且只有一个接收方。

### 2. EDA/Interface-A 是什么
- EDA（Equipment Data Acquisition，设备数据采集），又称 **Interface A**，是 SEMI 定义的一套**设备数据采集标准族**，专门提供高带宽、多客户端、订阅式数据通道，服务 FDC/YMS/R2R/VM 等大数据与先进控制应用。
- 角色反转：GEM 里设备基本被动应答 Host；EDA 里**设备是服务端（EDA Server）**，FDC/YMS/R2R 等是**多个客户端**，客户端来订阅、设备按订阅计划持续推数据。
- 传输栈与 GEM 不同：**不跑 HSMS/SECS-II**，而是 Web Services——Freeze I/II 用 SOAP/XML over HTTP/HTTPS；Freeze III 改用 Protocol Buffers（更高效，面向大数据/AI）。这是本阶段最容易搞错、也最关键的一点。

### 3. 五维度对比（必须能默写）
| 维度 | GEM/SECS（Interface 你已学） | EDA/Interface-A |
|---|---|---|
| 连接模型 | 一对一（设备↔单一 Host） | 一对多（设备↔FDC/YMS/R2R 多客户端并发） |
| 传输/编码 | HSMS(TCP)+SECS-II | HTTP(S) Web Services：SOAP/XML(FzI/II) 或 Protobuf(FzIII) |
| 触发/频率 | 事件驱动、稀疏，1–10Hz 以下 | 订阅式连续流，10Hz–1kHz，trace/波形 |
| 数据方向/语义 | 控制+事务+稀疏上报，重命令与状态 | 只读数据采集，重带宽/时间序列/数据质量 |
| 典型用途 | 派工、状态机、报警控制、配方、GEM300 | FDC 检测分类、VM、SPC、良率/工艺分析、AI |
| 是否能控设备 | 能（远程命令/派工） | 不做控制（只读采集，控制仍走 GEM） |

### 4. 双通道架构（核心心智模型）
- 一台先进设备同时提供：**GEM 接口**（HSMS 端口，对 FAB EAP，控制）+ **EDA 接口**（HTTP/HTTPS 端口，对多客户端，采集）。两条通道进程/连接隔离，一条堵了不影响另一条（高频 EDA 不能拖死控制 GEM）。
- **数据源共享**：设备内部的参数、状态、事件只有一个权威来源（你的 Domain/各 FSM/传感器采样层），GEM 报告与 EDA 流都从这里只读取数；绝不为两条通道各维护一本账（接 W22/W24 同源原则）。
- 决策与执行分离依旧成立：FDC 经 EDA 看到数据、做判定，但要 Hold/改参数仍通过 GEM（S2F41）或 APC 通道下发，**EDA 本身只读不控**。

### 5. EDA 标准族地图（本周逐个展开）
- **E120 CEM**（Common Equipment Model）：公共设备模型，规定对象层次（Equipment→Module/Subsystem→组件）。
- **E125 EqSD**（Equipment Self Description）：设备自描述，客户端能"读出设备有哪些对象/参数/事件/异常"。
- **E132**：客户端认证与授权（谁能连、能订什么）+ 会话管理（多客户端）。
- **E134 DCM**（Data Collection Management）：采集计划管理——订什么变量、多久采、事件触发还是周期、打包格式。
- **E164**：EDA 公共元数据（Well-Known Names、跨标准公共元素，Freeze3 里集中放 protobuf 公共元素）。
- 辅助：**E128/E138**（XML 公共组件，Freeze II）、**E179**；**E147** 是 EDA 指南（Guide，非强制）。
- **Freeze**：为避免各标准独立演进导致互操作问题，SEMI 发布"冻结版本"锁定配套：Freeze I、Freeze II（0710，SOAP/XML，存量 Fab 主流）、Freeze III（Protocol Buffers，新方向，面向 AI/大数据）。

### 6. 与你现有 EapLab 的关系（先有个印象，W29 落地）
- 不重写 GEM：E5/E30/E39/GEM300/E94 全部保留，是控制面。
- 新增 EapLab.Eda：HTTP(S) 服务端、自描述模型、会话/授权、采集计划与高频采样引擎；它**只读订阅** Domain 数据源，不反向写状态机（依赖方向同 Ept/Ram/Oee）。
