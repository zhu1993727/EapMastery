# W27 · Day02 答案与参考实现

## 一、自测题标准答案
1. **CEM 解决什么/没有会怎样**：CEM(E120) 给所有厂商设备规定一棵统一的对象层次与成员组织方式，让 FDC/YMS/R2R 等多客户端用同一套路径与语义找到"设备→模块→子系统→部件→变量/事件/异常"。没有它，每家设备命名/结构各异，每个分析应用都要为每种设备写专用解析与映射，N 个应用×M 种设备的适配爆炸、无法跨机台横向比较、换厂商就要重做，自描述和通用采集工具也无从谈起。
2. **层次/举例**：Equipment（整台多腔设备）→Module（大功能单元，如 ProcessModule 工艺腔模块、TransferModule 传输模块，另 LoadPort 模块、LoadLock 模块）→Subsystem（模块内子系统，如真空子系统、RF 射频子系统、温控子系统、气路 MFC 子系统）→Component（具体部件，如 1 区加热灯/热电偶、某 MFC、某节流阀、某伺服轴）。例：ProcessModule[2]/Temperature/Zone1/ActualTemp；TransferModule/Arm/AxisY/Position。
3. **物理 vs 逻辑归类**：物理对象对应可指认的硬件/空间——加热区、机械臂、腔体、MFC 都是物理对象；逻辑对象是功能/管理抽象、无单一硬件实体——ProcessJob（作业）、设备汇总状态、调度器、Recipe 管理单元是逻辑对象。判断法：能不能用手指到一个具体硬件，能=物理，只是软件概念/跨部件汇总=逻辑。
4. **SVDV/ECV/EXV/采集时机**：SVDV（Simple Value Data Variable 简单值变量，如温度/压力/功率/流量）可按采集计划**周期采样**（10Hz 连续流的主力）；ECV（Event Collection Variable 事件采集变量）在**特定事件发生那一刻**随事件一起采一组上下文快照（如"步骤开始"时采当时 recipe、step id、片 id）；EXV（Exception Variable 异常变量）在**异常发生/清除时**采与该异常相关的上下文（如报警时的压力、互锁状态）。即 SVDV 靠周期、ECV 靠事件、EXV 靠异常触发。
5. **CEM 事件/异常 vs GEM CEID/Alarm**：对应关系——CEM Event≈GEM CEID（某事发生带上下文），CEM Exception≈GEM Alarm（S5 报警条件，置位/清除）。区别：①定位不同——CEM 成员挂在对象树具体子系统/部件路径下，能直接知道是哪个腔哪个部件的事件/异常；GEM 的 CEID/ALID 是扁平 ID 空间，需要靠 VID/约定关联位置；②用途/通道不同——CEM 事件异常经 EDA 供多客户端高频分析，GEM CEID/Alarm 经 HSMS 对单一 Host 做事务/控制相关通知；③同源——底层是同一批领域事件/报警，分别投影到 CEM 与 GEM（Day01 同源）。
6. **CEM vs OSS/共用底层**：两者都用对象（类/实例/属性/方法/事件）思想。定位差异：E39 OSS 面向 **GEM 控制面**，Host 用 S14 查元数据、S15 增删改查调对象（建 PJ/CJ、设属性、调方法）、S16 收执行事件，强调"可操作/可控"；E120 CEM 面向 **EDA 采集面**，多客户端主要只读浏览对象树、订阅数据，强调"跨厂商统一拓扑 + 自描述 + 高带宽读"。共用方式：设备内部维护一套统一领域模型（硬件拓扑+作业+状态作为唯一事实源），向上做两个投影——OSS 视图暴露控制操作给 GEM，CEM 视图暴露标准化只读层次给 EDA，两视图数据同源、职责不混。
7. **为何不解析 GEM 事件也能拿到当前 Step/片**：因为 CEM 树里在 ProcessModule 下建了承载作业语义的**逻辑对象与 SVDV**（如 `/ProcessModule[1]/Job/CurrentStepId`、`.../Processing/WaferId`、`.../Job/State`），这些变量由同一权威作业 FSM（E40/E94）实时更新，EDA 客户端按标准路径**周期订阅**这些 SVDV 即可直接读到当前 Step/片/状态，不需要去解码 GEM 的 S6F11 事件流、也不依赖事件是否恰好到达——这正是 CEM 把"作业状态"也标准化成可订阅数据变量的价值。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Eda.Cem;
public enum CemKind{ Equipment,Module,Subsystem,Component,Logical }
public enum MemberKind{ SVDV,ECV,EXV,Event,Exception }
public sealed record Member(string Name,MemberKind Kind,string DataType,string Unit="",bool Writable=false);

public sealed class CemObject
{
    public string Name{get;}public CemKind Kind{get;}public CemObject? Parent{get;private set;}
    private readonly List<CemObject> _children=new(); private readonly Dictionary<string,Member> _members=new();
    public CemObject(string name,CemKind kind){Name=name;Kind=kind;}
    public CemObject Add(CemObject child){child.Parent=this;_children.Add(child);return this;}
    public CemObject With(Member m){_members[m.Name]=m;return this;}
    public string Path=>Parent is null?$"/{Name}":$"{Parent.Path}/{Name}";
    public IReadOnlyList<CemObject> Children=>_children;
    public IEnumerable<Member> Members=>_members.Values;
    public CemObject? FindByPath(string path) // /Eq/ProcessModule[1]/RF/Power
    { if(Path==path)return this; return _children.Select(c=>c.FindByPath(path)).FirstOrDefault(x=>x!=null); }
    public IEnumerable<CemObject> Flatten(){ yield return this; foreach(var c in _children)foreach(var x in c.Flatten())yield return x; }
    public IEnumerable<(string objPath,Member m)> AllMembers()
    =>Flatten().SelectMany(o=>o._members.Values.Select(m=>(o.Path,m)));
}

public static class TypicalToolTree
{
    public static CemObject Build()
    { var eq=new CemObject("Equipment",CemKind.Equipment);
        for(int i=1;i<=2;i++)
        { var pm=new CemObject($"ProcessModule[{i}]",CemKind.Module);
            var temp=new CemObject("Temperature",CemKind.Subsystem)
                .With(new Member("ActualTemp",MemberKind.SVDV,"double","C"))
                .With(new Member("Zone1Setpoint",MemberKind.SVDV,"double","C"));
            var rf=new CemObject("RF",CemKind.Subsystem)
                .With(new Member("Power",MemberKind.SVDV,"double","W"))
                .With(new Member("MatchFault",MemberKind.Exception,"bool"));
            var job=new CemObject("Job",CemKind.Logical)
                .With(new Member("CurrentStepId",MemberKind.SVDV,"int"))
                .With(new Member("WaferId",MemberKind.SVDV,"string"))
                .With(new Member("StepChanged",MemberKind.Event,""))
                .With(new Member("StepAtChange",MemberKind.ECV,"int"));
            pm.Add(temp).Add(rf).Add(job); eq.Add(pm);
        }
        var tm=new CemObject("TransferModule",CemKind.Module)
            .Add(new CemObject("Arm",CemKind.Subsystem).With(new Member("AxisY_Position",MemberKind.SVDV,"double","mm")));
        eq.Add(tm);
        return eq; }
}
```

### xUnit
```csharp
public class CemTreeTests
{
    [Fact] public void 路径唯一定位()
    { var t=TypicalToolTree.Build();
      var o=t.FindByPath("/Equipment/ProcessModule[1]/RF");Assert.NotNull(o);
      Assert.Contains(o.Members,m=>m.Name=="Power"); }
    [Fact] public void 物理与逻辑对象共存且可区分()
    { var t=TypicalToolTree.Build();
      Assert.Equal(CemKind.Logical,t.FindByPath("/Equipment/ProcessModule[1]/Job")!.Kind);
      Assert.Equal(CemKind.Subsystem,t.FindByPath("/Equipment/ProcessModule[1]/RF")!.Kind); }
    [Fact] public void 三类变量与事件异常都可枚举()
    { var all=t=TypicalToolTree.Build().AllMembers().Select(x=>x.m.Kind).ToHashSet();
      Assert.Contains(MemberKind.SVDV,all);Assert.Contains(MemberKind.ECV,all);
      Assert.Contains(MemberKind.Event,all);Assert.Contains(MemberKind.Exception,all); }
    [Fact] public void 不解析GEM也能订阅当前Step逻辑变量()
    { var job=TypicalToolTree.Build().FindByPath("/Equipment/ProcessModule[2]/Job");
      Assert.Contains(job!.Members,m=>m.Name=="CurrentStepId"&&m.Kind==MemberKind.SVDV); }
    [Fact] public void 树展开节点数确定()
    { var t=TypicalToolTree.Build();
      // Eq + 2*(PM+Temp+RF+Job) + (TM+Arm) =1+8+2=11
      Assert.Equal(11,t.Flatten().Count()); }
}
```

## 三、多腔设备 CEM 树（手绘参考）
```
/Equipment
├ ProcessModule[1] (Module,物理)
│  ├ Temperature(Subsystem): SVDV ActualTemp/Zone1Setpoint
│  ├ RF(Subsystem): SVDV Power ; EXC MatchFault
│  └ Job(Logical): SVDV CurrentStepId/WaferId ; EVT StepChanged ; ECV StepAtChange
├ ProcessModule[2] ...(同构)
├ LoadLock[1..2](Module) ├ Vacuum(Subsystem: SVDV Pressure, EXC DoorInterlock)
├ TransferModule(Module) └ Arm(Subsystem: SVDV AxisY_Position)
└ LoadPort[1..2](Module) └ Carrier(Logical: SVDV CarrierId/State ←E87)
路径=包含关系唯一定位; 物理按硬件拓扑稳定, 逻辑承载作业/汇总
同源投影: 领域模型 → OSS视图(GEM控制,S14/15/16) + CEM视图(EDA只读订阅)
```

## 四、今日易错点
1. 把 CEM 当厂商私有模型（它正是为跨厂商统一而生）。
2. 层次混乱（Module/Subsystem/Component 边界不清，路径无法稳定）。
3. 物理/逻辑对象不分，把 ProcessJob 当硬件。
4. SVDV/ECV/EXV 触发时机混（周期/事件/异常）。
5. 把 CEM 事件异常和 GEM CEID/Alarm 当两套无关数据（应同源投影）。
6. 混淆 E120 CEM（EDA 只读模型）与 E39 OSS（GEM 可控对象服务）。
7. 不给成员单位/类型/路径，客户端无法正确解析与横向比较。
8. 作业状态只走 GEM 事件、不在 CEM 建逻辑 SVDV，导致 EDA 拿不到当前 Step/片。
