# W27 · Day02（周二）E120 CEM 公共设备模型：EDA 客户端看到的对象树

> 建议时长：90 分钟。EDA 多客户端要"读懂"任意厂商设备，靠的是一套标准化对象层次。今天学 SEMI E120 Common Equipment Model（CEM）：设备如何被组织成统一的对象树、对象/属性/异常/事件如何挂在树上，以及它和你学过的 E39 OSS 对象模型的异同。

## 一、今日目标
1. 掌握 CEM 标准化层次：Equipment→Module/Subsystem→Component 的对象树组织。
2. 区分物理对象（Physical）与逻辑对象（Logical），理解模块、子系统、部件的划分原则。
3. 掌握对象上挂载的三类成员：数据变量、事件、异常，以及命名/标识规则。
4. 说清 CEM（E120，面向 EDA 多客户端的标准化模型）与 OSS（E39，GEM 控制对象服务）的关系与区别。
5. 用 C# 构建一棵可遍历的 CEM 对象树并按路径定位成员；xUnit 验证。

## 二、背景知识（先读，35 分钟）

### 1. 为什么需要 CEM
- 没有统一模型，每家设备厂商对"腔体、机械臂、气路"的命名和组织都不同，FDC/YMS 客户端要为每种设备定制解析，成本极高。
- E120 规定一棵**标准化对象树**：无论哪家设备，客户端都按同样层次找到"设备→某模块→某子系统→某参数"，实现跨厂商一致访问（配合 E164 Well-Known Names）。

### 2. CEM 层次结构
- 根 = **Equipment**（整台设备），其下按层级组织：
  - **Module（模块）**：相对独立的功能大单元，如工艺模块 ProcessModule（腔 Chamber）、传输模块 TransferModule（机械手/大气侧）、LoadPort 模块、LoadLock 模块。
  - **Subsystem（子系统）**：模块内功能子系统，如真空、温控、气路 MFC、射频 RF、运动控制。
  - **Component（部件/实例）**：具体到传感器、执行器、单个加热区、单个 MFC、单个阀。
- 树是**包含（containment）层次**：父对象包含子对象，对象有唯一路径（类似 `/Equipment/ProcessModule[1]/RF/Match/Power`），客户端按路径唯一定位。

### 3. 物理对象 vs 逻辑对象
- **Physical Object**：对应真实硬件/空间位置（一个腔、一个臂、一个 MFC、一个加热区），可在物理上指认。
- **Logical Object**：为功能/管理抽象出的对象（一个 ProcessJob、一个 Recipe 管理单元、整设备汇总状态、调度器），没有单一物理实体。
- 建模原则：物理树按硬件拓扑、稳定少变；逻辑对象承载作业/汇总/管理语义。两者都挂在同一棵 CEM 树上但用类型区分。

### 4. 对象上的三类成员（EDA 采集的基本单元）
- **数据变量（Data Variable）**：可被采集的值，E134 进一步分：
  - SVDV（Simple Value Data Variable，简单值变量，可周期采样，如温度/压力/功率）；
  - ECV（Event Collection Variable，事件发生时随事件采集的上下文变量）；
  - EXV（Exception Variable，异常发生时的相关变量）。
- **事件（Event）**：状态/过程发生的事（如加工开始、步骤切换、作业完成），事件触发时带一组 ECV 快照（类比 GEM CEID，但在 CEM 对象上）。
- **异常（Exception）**：错误/告警条件（类比 GEM Alarm，但在对象树上定位到具体子系统），异常发生/清除带 EXV。
- 每个成员有唯一 ID/路径、数据类型、单位、访问性、描述（元数据，E125/E164 细化）。

### 5. CEM(E120) 与 OSS(E39) 的关系（易混，重点）
- 相同：都是对象模型（类/实例/属性/方法/事件思想），都把设备抽象成对象树。
- 不同定位：**E39 OSS 服务 GEM 控制面**——对象被 Host 用 S14/S15/S16 增删改查调、服务于派工与控制；**E120 CEM 服务 EDA 采集面**——对象树主要被多客户端只读浏览/订阅、服务于数据分析，强调跨厂商统一拓扑与自描述。
- 实践关系：设备内部可以有一个统一领域模型，分别投影成 OSS 视图（给 GEM）和 CEM 视图（给 EDA），底层仍是同一权威数据源（Day01 同源原则）。

### 6. 与 GEM300 的对应（帮你建立映射）
- E87 载具、E90 片位置、E40/E94 作业在 CEM 里都有对应的逻辑对象/变量（如 LoadPort 模块下的 Carrier 对象、ProcessModule 下的 Job/Step 对象），EDA 客户端因此能直接订阅"某腔当前加工片、当前 Step、某载具状态"等，而不必解析 GEM 事件。
