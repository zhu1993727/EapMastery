## 三、本周知识地图（先默写再对照）
```
EDA=Interface-A 设备数据采集(只读/高频/多客户端), 与GEM(控制/一对一/HSMS)双通道并存
定位对比: 连接模型/传输栈/频率/方向语义/用途/能否控制(五维)
  设备=EDA服务端; 客户端=FDC/YMS/R2R/工具; 共享唯一数据源, 端口线程隔离, EDA只读不控
标准族:
 E120 CEM 公共设备模型(Equipment→Module→Subsystem→Component; 物理/逻辑;
   成员=SVDV周期/ECV事件/EXV异常 + Event/Exception)
 E125 EqSD 自描述(类型/单位/范围/枚举/访问性/ECV-EXV/版本; 客户端零硬编码发现)
 E132 认证(是谁)+授权(看哪/多快/只读); 会话生命周期; 多会话隔离/配额/有界背压/空闲回收
 E134 DCM 采集计划; 三触发(周期/事件/异常); 采样⟂上报(高频采批量报); 质量码/丢点标记
 E164 公共元数据+Well-Known Names(语义跨厂商统一); FreezeIII公共protobuf元素
 辅助 E128/E138 XML公共组件, E179; E147指南
Freeze: 锁配套版本互操作; II=SOAP/XML(存量主流); III=Protocol Buffers(高吞吐AI)
  变的是编码传输, 不变的是模型语义 → 采集内核与编码层解耦, 编码器可插拔
```

## 四、W28 预热：CEM 建模实操与高频采集引擎（25 分钟）
### 1. W28 七天预告
- Day01 建模方法学：从设备硬件拓扑+作业模型系统梳理 CEM 对象树（物理树稳定、逻辑对象承载 E87/E90/E40/E94 语义）。
- Day02 Well-Known Names 落地：私有变量到 E164 WKN 的映射规范、单位量纲、命名评审。
- Day03 高频采样引擎：统一采样调度（非每计划一线程）、时间戳、环形缓冲、零分配/低 GC。
- Day04 采集计划运行时：多客户端多计划调度、周期/事件/异常混合、批量打包、背压与质量码。
- Day05 数据上报服务：FreezeII XML 回报 + FreezeIII protobuf-like 编码、客户端回调/流。
- Day06 综合实验：一台多腔设备完整 EDA 服务（建模→自描述→授权→多客户端订阅→高频流→慢客户端保护）。
- Day07 复盘 + W29 双通道实战预热。

### 2. 技术准备
- .NET 侧：ASP.NET Core 最小 Web API（承载 HTTP 服务）、System.Text.Xml / protobuf-net（或手写编码抽象）、Channel/环形缓冲做生产消费、定时器集中调度。
- 复用：W27 的 CemObject/MetaGenerator/EdaSessionManager/DataCollector/WknMapper/双编码器。

### 3. 思考题（带进 W28）
1. 你的设备有上千个可采点，如何决定哪些进 CEM、标什么 WKN、给什么默认频率上限。
2. 100Hz×多客户端时，如何做到低延迟且不把 CPU 打满、不影响 GEM 控制。
3. 自描述模型如何随软件版本演进且让旧客户端不崩。
