# W27 · Day04 答案与参考实现

## 一、自测题标准答案
1. **认证 vs 授权/为何都要**：认证（Authentication）回答"你是谁"——校验客户端身份凭证（账号令牌/证书）是否合法，建立可信身份；授权（Authorization）回答"你能做什么、看什么"——在认证通过后，按该身份的角色决定可见对象子树、可订阅变量类别、最高采样频率与操作集。两者都要：只认证不授权，则任何合法登录者都能读全部工艺/敏感数据、订任意高频，无最小权限约束；只授权不认证，则身份可伪造、权限无从绑定。先认证建立身份、再按身份授权限定范围，是安全两道门。
2. **会话生命周期**：Connect 建立 HTTP(S) 连接→Authenticate 提交凭证认证→Authorize 获得可见域/配额→GetSelfDescription 取（被授权裁剪后的）自描述→建立采集会话并提交订阅(E134)→按计划传输数据→心跳/续约保活（空闲超时则回收）→客户端主动 Close 或异常断线→会话失效、级联撤销其订阅、释放缓冲/线程等资源。每会话有唯一 ID、身份上下文、创建/最后活动时间与订阅集合。
3. **会话结束为何级联撤订阅/不撤后果**：订阅是挂在会话下的资源（采样配额、发送缓冲、数据拷贝、调度槽）。会话已断却不撤订阅，会形成"僵尸订阅"：设备仍按其频率采样、组包、往失效连接写，持续白耗 CPU/内存/带宽，累积多个会拖垮 EDA 服务甚至影响设备；还可能造成配额被死会话占用、新客户端订不上。因此会话终止（正常/超时/异常）必须原子撤销其全部订阅并释放资源。
4. **1kHz 全量如何保护**：按授权配额层层限制——①该客户端有最高频率上限（授权时给定），请求超过上限直接降频到允许值或拒绝该采集计划；②单会话订阅变量数/总采样点有上限；③设备有全局采样/发送总预算（CPU/网络），所有会话之和不能超，超出按公平/优先级策略拒绝或降级；④发送队列长度上限+背压。即"频率、点数、总量、队列"四道闸，任何单一客户端都不能独占设备资源，保证多客户端与控制面稳定。
5. **慢客户端/与 Spool 区别**：实时流不无限缓存——发送队列堆积到上限时，对实时 SVDV 采用丢弃最旧（或覆盖最新、按策略）并在数据上打**数据质量码**（标记该段有丢点/不连续），保证设备不被慢消费者拖垮、内存有界。与 GEM Spool 本质不同：GEM Spool 缓存的是**控制/事件事务**（S6F11/S5F1/S16F1），要求可靠、按序、确认后删、不丢（业务正确性）；EDA 是**实时时间序列**，更看重"实时、有界、不拖垮设备"，宁可丢旧点并标注质量，也不无限堆积（实时性优先于逐条可靠）。
6. **为何只读/控制走哪**：EDA 定位是只读数据采集面，面向多客户端、高频、数据分析；若允许经它写参数/Hold/启停，就绕过了 GEM 控制状态机、命令授权与安全联锁，且数据分析方众多、难以保证控制安全与确定性。因此 EDA 不开放控制操作（最小权限、读写分离）；所有控制走控制面——GEM 远程命令 S2F41/OSS S15，或 APC(R2R)→RMS→EAP 的受控参数下发，经设备状态机合法迁移执行（决策方≠执行方）。
7. **FDC 看工艺不看配方/机制**：靠**授权可见域（Authorization Scope）**——为 FDC 角色授予 ProcessModule 下工艺参数子树（温度/压力/功率等 SVDV）的读与订阅权，而把 Recipe/敏感参数对象子树排除在其可见范围外；自描述服务对它只返回授权可见部分，它提交越界路径订阅时直接拒绝。即按角色配置"可见对象路径白名单 + 变量类别 + 频率上限"，在认证身份绑定角色、授权裁剪可见域，实现同设备不同客户端看到不同子集。

## 二、参考实现（net8.0）

```csharp
namespace EapLab.Eda.Session;
public sealed record ClientCred(string ClientId,string Token,string Role);
public sealed class Grant // 授权结果: 可见子树白名单 + 频率/点数上限 + 只读
{
    public HashSet<string> VisiblePrefix{get;}=new();public double MaxHz{get;init;}=100;
    public int MaxTags{get;init;}=10000;public bool ReadOnly=>true;
    public bool CanSee(string path)=>VisiblePrefix.Any(p=>path.StartsWith(p));
}
public enum SessState{ Connected,Authed,Active,Closing,Gone }
public sealed class EdaSession{
    public string Id{get;}public ClientCred Client{get;}public Grant Grant{get;}
    public SessState State{get;set;}public double LastActive{get;set;}
    public HashSet<string> Subs{get;}=new();public Queue<double[]> SendQ{get;}=new();
    public EdaSession(string id,ClientCred c,Grant g,double now){Id=id;Client=c;Grant=g;State=SessState.Active;LastActive=now;}
}

public sealed class EdaSessionManager
{
    readonly Dictionary<string,EdaSession> _s=new(); readonly int _maxSessions; readonly int _qCap;
    public EdaSessionManager(int maxSessions=8,int queueCap=10000){_maxSessions=maxSessions;_qCap=queueCap;}
    // 认证+授权一步返回会话; 角色→可见域(教学内置)
    public (bool ok,EdaSession? s,string err) Open(ClientCred cred,Func<string,Grant> roleGrant,double now)
    { if(!AuthTable.Verify(cred))return(false,null,"auth fail");
      if(_s.Count>=_maxSessions)return(false,null,"session limit");
      var g=roleGrant(cred.Role);
      var s=new EdaSession(Guid.NewGuid().ToString("N")[..8],cred,g,now);_s[s.Id]=s;return(true,s,""); }

    public string? Subscribe(string sid,IEnumerable<string> paths,double hz)
    { if(!_s.TryGetValue(sid,out var s))return"no session";
      var ps=paths.ToList();
      if(ps.Any(p=>!s.Grant.CanSee(p)))return"out of scope";       // 可见域
      if(hz>s.Grant.MaxHz)return"hz over grant";                   // 频率上限
      if(ps.Count>s.Grant.MaxTags)return"tag over grant";          // 点数上限
      foreach(var p in ps)s.Subs.Add(p);return null; }

    // 慢客户端: 有界队列, 满则丢最旧并标记(实时流不无限缓存)
    public int Dropped{get;private set;}
    public void Enqueue(string sid,double[] frame)
    { if(!_s.TryGetValue(sid,out var s))return;s.LastActive=frame[0];
      while(s.SendQ.Count>=_qCap){s.SendQ.Dequeue();Dropped++;} s.SendQ.Enqueue(frame); }

    public void Heartbeat(string sid,double now){if(_s.TryGetValue(sid,out var s))s.LastActive=now;}
    // 空闲/断线回收: 级联清订阅与队列
    public List<string> ReapIdle(double now,double idleTimeout)
    { var dead=_s.Values.Where(x=>now-x.LastActive>idleTimeout).Select(x=>x.Id).ToList();
      dead.ForEach(Close);return dead; }
    public void Close(string sid){_s.Remove(sid);} // 订阅/队列随对象释放
    public int Count=>_s.Count;public IEnumerable<string> SubsOf(string sid)=>_s[sid].Subs;
}
public static class AuthTable{ static readonly HashSet<string> _ok=new(){"tok-fdc","tok-yms","tok-eng"};
    public static bool Verify(ClientCred c)=>_ok.Contains(c.Token); }
```

## 三、多客户端会话（手绘参考）
```
 FDC ─┐                         ┌ 会话S1: 授权(工艺子树,≤50Hz) 订阅集A 独立队列
 YMS ─┼─ HTTPS connect+认证 ──▶ EDA Server 会话表
 R2R ─┤  (E132)                ├ 会话S2: 授权(...) 订阅集B 独立队列
 ENG ─┘                         └ 会话S3 ... ; 全局配额(总会话/总采样/带宽)
认证(是谁)→授权(看哪/多快/只读)→自描述(裁剪可见)→订阅(E134)→数据流→心跳→关闭级联清订阅
保护: 越权路径拒 / 超频拒或降 / 队列有界丢旧点打质量码 / 空闲回收僵尸会话
EDA只读不控; 控制一律走GEM(S2F41/S15)或APC→RMS; 端口独立, 可单独关停
```

## 四、今日易错点
1. 认证授权混为一谈（先认身份、再按角色限可见域与配额）。
2. 不做可见域裁剪，任何客户端读全模型（违反最小权限、泄露配方）。
3. 不限制频率/点数/总会话，一个订阅拖垮设备。
4. 会话断了不级联撤订阅，僵尸订阅持续耗资源。
5. 慢客户端用 GEM Spool 式无限可靠缓存（实时流应有界、丢旧点+质量码）。
6. 在 EDA 开放写/控制（读写不分，绕过状态机与联锁）。
7. 无心跳/空闲回收，断线连接堆积。
8. EDA 与 GEM 端口/进程不隔离，EDA 故障波及控制面。
