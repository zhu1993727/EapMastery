## 二、背景知识（先读，35 分钟）

### 1. PJ 完整状态集（教学口径，精确名称以 E40 原文为准）
- **Queued/Received（已接收排队）**：Host 经 S15 创建成功，设备已接收但未 Start，等待调度/资源/启动命令。
- **Started（已启动）**：收到 Start 且通过开工校验，任务进入可执行（很短的过渡态，随即进入 Executing）。
- **Executing（执行中）**：正在按 WaferOrder/Route 逐片逐 Step 加工，是主要工作态。
- **Pausing/Paused（暂停中/已暂停）**：收到 Pause，Pausing 表示在走到安全点的过程中，到达安全点后 Paused（区分请求与生效，关键）。
- **Completed（完成，终态）**：所有片完成全部 Step、归位、终验通过，正常结束。
- **Cancelled（取消，终态）**：未真正加工前由 Host 取消，现场等同未执行，无片受影响。
- **Aborted（中止，终态）**：执行中被 Host 中止或设备因不可继续而中止，可能有在途/在腔片，需恢复处置。
- **Failed（失败，终态）**：因故障/校验失败无法继续而失败，带错误码与现场；与 Aborted 的区别：Aborted 多为主动中止，Failed 多为异常导致（实现中可合并管理，语义要分清）。
- 终态（Completed/Cancelled/Aborted/Failed）无出边，不可再迁移（W10 终态原则）。

### 2. 合法迁移总图
```
Queued ─Start(校验通过)→ Started ─→ Executing
Queued ─Cancel(未加工)→ Cancelled(终)
Executing ─Pause→ Pausing ─(到达安全点)→ Paused
Paused ─Resume→ Executing
Executing/Paused ─Abort→ Aborted(终)
Executing ─故障/校验失败→ Failed(终)
Executing ─(全片完成+归位+终验,守卫)→ Completed(终)
非法示例(必须拒绝): Queued→Completed; Paused→Completed; Completed→*; Cancelled→*; Executing未全完成→Completed
```

### 3. 每条迁移的三要素
- **触发方**：Host 命令（Start/Pause/Resume/Cancel/Abort 经 S15 方法）、设备自发（故障→Failed、全片完成→Completed）、条件守卫（全片完成且终验通过才允许 Completed）。
- **前置条件（Guard）**：如 Start 需开工双校验通过、Completed 需聚合守卫、Cancel 需无片受影响。
- **副作用 + 事件**：迁移时更新状态、记录时间戳、发对应 S16 CEID；非法迁移零副作用并回 IllegalState ACKC。

### 4. 受理 vs 生效（关键易错点）
- S15F10 ACKC=0 只表示"方法请求被受理"，状态真正迁移在前置条件满足、动作执行后；Paused/Completed 这类尤其明显（Pause 受理后还要走到安全点才 Paused；完成要等最后一片归位终验）。
- 状态以 S16 状态事件为权威，Host 不能拿命令应答当最终状态。

### 5. 任务级 vs 片级/步骤级状态映射
- Job=Executing 时，片可 Waiting/InProcess/StepDone/Completed；Job 是否可 Completed 由片聚合决定。
- Pausing 安全点通常选"片间"或"步骤边界"（W16 Day05），片级状态决定任务级何时真正 Paused。
- 一片 Failed：片级 Failed 驱动 Job 级 Failed/Aborted（策略：单片失败是否中止整 Job 可配置，但默认安全中止）。

### 6. 与 W10 泛型状态机衔接
- 用 StateMachine<JobState,JobMethod/JobEvent> 配置：命令触发用方法、设备自发/守卫用内部事件；PermitIf 表达聚合守卫；终态无出边；非法 Fire 零副作用。本周后续天逐步加 Pause/Cancel/Abort/恢复细节。
