# W17 · Day01 答案

## 一、自测题标准答案
1. **全部状态/终态/Started 与 Executing**：状态集=Queued(Received 已接收排队)、Started(已启动过渡)、Executing(执行中)、Pausing(暂停中过渡)、Paused(已暂停)，以及四个终态 Completed(正常完成)、Cancelled(未加工取消)、Aborted(执行中主动中止)、Failed(故障失败)。终态是 Completed/Cancelled/Aborted/Failed，无出边、不可再迁移。Started 与 Executing：Start 命令通过开工校验后先进入 Started（表示任务已启动、正在做执行前的最后调度），随即进入 Executing（真正逐片逐 Step 加工）；Started 是很短的过渡态，区分"已下令启动"和"正在执行"，让状态语义精确、事件可追踪，实现中也可合并但要能区分启动瞬间与稳定执行态。
2. **为何要 Pausing**：收到 Pause 命令时设备可能正在运动/某片在腔加工到一半，物理过程不能瞬间冻结，立即标 Paused 会造成"状态说暂停、实际还在动/在加工"的不一致，且无法确定恢复点。Pausing 表示"已接受暂停请求、正在走到最近安全点"（片间或步骤边界），等当前不可中断动作走到可安全停止的边界、片处于确定稳定位置后才进入 Paused。区分 Pausing（请求生效中）与 Paused（已安全停下）准确描述了暂停的异步过程，Resume 也才能从明确安全边界续跑。这与"受理≠生效"一致。
3. **Cancel/Abort 可迁移状态与前提**：Cancel 只能从**尚未真正加工**的状态（Queued/Received，或 Started 但还没有任何片被取动/加工）迁移到 Cancelled，前提是没有片受到影响、现场等同未下发、无在途片，是干净撤回。Abort 可从 **Executing/Pausing/Paused**（执行相关态）迁移到 Aborted，用于执行中主动中止，前提不要求无片受影响（恰恰可能已有在途/在腔片），中止后必须保留现场并处置这些片。二者不能混用：已加工后不能 Cancel（物理已改变回不到未执行），未启动也无需 Abort（直接 Cancel 即可）。
4. **Completed 聚合守卫**：进入 Completed 必须同时满足：①所有 WaferProcess 都到 Completed（每片走完所有 Step）；②每片都归位——E90 位置在其声明目标槽（无 LeftInside/在途残留，设备内位置全空）；③跨盒/源目终验通过（逐片目标槽 ID 对、全局守恒、无丢重错位）；④无未处理失败/告警阻断；⑤（需要时）结果数据/采集完整。用状态机 PermitIf 聚合守卫表达，任一不满足则保持 Executing（或挂起），杜绝"工艺走完但片没归位也标完成"。
5. **受理到真正迁移之间发生什么 / 以何为准**：S15F10 ACKC=0 后到状态真正迁移之间，设备要做前置条件校验、资源调度、等待安全点、等最后片完成与终验——例如 Start 受理后可能因资源未就绪稍后才 Executing，Pause 受理后要走到安全点才 Paused，完成命令/自发完成要等最后一片归位终验才 Completed，期间也可能校验失败转 Failed。因此 Host 必须以**状态迁移后发出的 S16 状态事件**为权威状态，命令应答只代表请求被接收，不能据此断定最终状态；订阅状态事件才能得到真实生命周期。
6. **三条非法迁移及拒绝方式**：①Queued→Completed（没 Start、没加工不能完成）；②Paused→Completed（暂停态不能直接完成，必须先 Resume 回 Executing 且满足聚合守卫）；③Completed→任意（终态无出边）；还如 Executing 未全片完成→Completed、Cancelled→Resume。拒绝方式：由 W10 泛型状态机——只为合法（状态,触发）配置出边，未配置的 Fire 直接抛非法迁移、**零副作用**（状态不变、不发事件、不动片），S15 方法层把它映射为 IllegalState（ACKC=8）应答返回 Host；带守卫的迁移（如 Completed）在守卫为假时同样拒绝，保证任何非法命令都不能推动状态。
7. **Executing 时片级状态 / 单片 Failed 影响**：Job=Executing 时片级可分别为 Waiting（等待）、InProcess（正在某 Step 加工）、StepDone（某步完成待下一步）、Completed（全部完成归位）。一片 Failed：默认安全策略是该片置 Failed、驱动 Job 进入 Failed/Aborted、**立即停止后续片调度**并保留 Partial 现场（W16 Day05）；是否"单片失败不影响其他片继续"可按工艺策略配置（例如该片隔离、其余继续，Job 最终带部分失败标记），但默认对半导体加工采取保守中止，防止异常状态下扩大影响，具体策略要在 PJ 定义中显式声明、不能隐式继续。

## 二、PJ 状态机总图（手绘参考，含触发方）
```
                       Host S15 Create
                            │
                         Queued/Received
              Start(Host,开工双校验过)      Cancel(Host,无片受影响)
                            ▼                                  ▼
                         Started ───────────────────────► Cancelled(终)
                            │
                            ▼
              ┌──────► Executing ◄────Resume(Host)──────┐
              │        │  │  │                          │
              │   Pause│  │  │Abort(Host)/故障          │ Paused
              │        ▼  │  ▼                          ▲
              │     Pausing│ Aborted(终)/Failed(终)      │(到安全点)
              │        │  │                             │
              │   到安全点│  │全片完成+归位+终验(守卫)    │
              │        ▼  ▼                              │
              │     Paused ────────────────────────────┘
              │        │Abort→Aborted
              │        ▼
              │   (终态) 
         Completed(终)◄─ 仅当聚合守卫满足, 从 Executing 进入
   终态 Completed/Cancelled/Aborted/Failed 均无出边
   每条边: 触发方(Host命令/设备自发/守卫) + 前置Guard + 副作用(时间戳/S16事件)
   S15F10=受理; 真实状态以迁移后的S16事件为准
```

## 三、迁移三要素表（参考）
| 迁移 | 触发方 | 前置 Guard | 副作用/事件 |
|---|---|---|---|
| Queued→Started | Host Start | 映射/路线双校验通过、资源可满足 | 记开始时间、5101 前置 |
| Started→Executing | 设备 | 调度就绪、首片可执行 | 5101 Started |
| Executing→Pausing | Host Pause | 任务执行中 | 标记等待安全点 |
| Pausing→Paused | 设备(到安全点) | 当前片/步到可停边界、片位置确定 | 5105 Paused |
| Paused→Executing | Host Resume | 现场仍一致、资源可用 | 续跑、状态事件 |
| Executing→Completed | 设备+守卫 | 全片完成+归位+终验通过 | 5104 JobDone |
| Queued→Cancelled | Host Cancel | 无片受影响 | 释放预留、取消事件 |
| Executing/Paused→Aborted | Host/设备 | — | 5106、保留 Partial 现场 |
| Executing→Failed | 设备自发 | 故障/校验失败不可续 | 5106、错误码+现场 |

## 四、费曼讲解稿（参考）
"PJ 状态机描述一个加工任务从接收到结束的全部合法生命周期。Host 创建后是 Queued 排队；发 Start、设备校验通过才 Started 然后 Executing 真正加工。注意两个异步细节：第一，暂停不是一令即停——设备可能正在搬片或片在腔里，只能先进入 Pausing 走到片间或步骤边界这个安全点，才真正 Paused，恢复时从这个确定边界续；第二，Host 收到方法应答只代表设备受理了请求，状态真正改变要等条件满足、并以状态事件为准。结束有四个终态：没动工可以 Cancel 干净撤回；一旦开始加工就只能 Abort 中止，且要处理在途片；故障走 Failed；只有所有片加工完、都放回目标槽、终验守恒通过，才允许 Completed——这个'全片完成且归位'是硬守卫，没到齐就算流程跑完也不能标完成。所有终态不可再变，任何没配置的状态跳转都会被状态机零副作用拒绝并回非法状态，保证任务状态永远真实可信。"

## 五、今日易错点
1. 收到 Pause 立刻 Paused（必须经 Pausing 到安全点才生效）。
2. 把 S15F10 受理当状态生效（以 S16 状态事件为准）。
3. Cancel/Abort 混用（已加工不能 Cancel，Cancel 要求无片受影响）。
4. 缺 Completed 聚合守卫，片没归位也标完成。
5. 终态留了出边（Completed/Cancelled/Aborted/Failed 不可再迁移）。
6. 非法迁移改了状态才报错（状态机先判定、非法零副作用、回 ACKC8）。
7. 混淆 Started 过渡态与 Executing 稳定执行态。
8. 不区分任务级与片级状态，无法表达 Executing 下各片不同进度。
9. 单片失败默认继续（半导体默认保守中止并保留现场，策略须显式）。
