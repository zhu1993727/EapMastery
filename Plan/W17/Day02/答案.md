# W17 · Day02 答案与参考实现

## 一、自测题标准答案
1. **为何分外部命令/内部事件 / Pause 例**：外部命令是 Host"要求"状态改变（Start/Pause/...，经 S15 方法），表达意图，能否生效取决于设备当下条件；内部事件是设备/执行器"某事实已发生"（到安全点、全片完成、故障），是状态真正推进的依据。二者分离才能表达异步生效。以 Pause：Host 发 Pause 是外部命令，设备受理后不能立刻 Paused（片可能在腔加工中途），先迁到 Pausing；等执行器真的把当前动作走到安全点、产生 ReachedSafePoint 内部事件，状态机才据此刻迁到 Paused。若只用一个命令触发直接 Paused，就会"状态已暂停、物理还在动"的不一致。命令表达请求、事件确认事实，是严谨状态机的通用做法。
2. **Queued→Completed 迁移链与触发类型**：Queued —Start（外部命令，开工 Guard 通过）→ Started —ReadyToExecute（内部事件，调度就绪）→ Executing —（逐片加工，内部片/步事件推进，任务态保持 Executing）—WaferAllDone（内部事件，聚合 Guard：全片完成+归位+终验通过）→ Completed（终态）。其中 Start 是唯一由 Host 命令推动进入执行链路的一步，之后进入 Executing、最终 Completed 都由内部事实事件推动；中途 Pause/Resume 由命令、到安全点由事件配合。
3. **WaferAllDone Guard 检查 / 为假表现**：检查①所有 WaferProcess 状态=Completed（每片走完所有 Step）；②每片 E90 位置在其声明目标槽（归位），设备内位置/Buffer 全空（无 LeftInside）；③跨盒终验通过（源目逐片 ID 对、全局守恒、无丢重错位）；④无未处理 Failed 片/阻断告警。Guard 为假时，即使执行器发了 WaferAllDone 事件，状态机也**拒绝迁移到 Completed**，Job 保持 Executing（或进入挂起），不发 JobDone 事件、零副作用，并回报/记录"未满足完成条件"及缺什么（如还有片在 C2、某槽 ID 不符），提示继续处理或异常，防止假完成。
4. **Accept 返回 ACKC 后状态一定变吗**：不一定。ACKC=0 只表"请求被受理"（对象/方法存在、格式合法），状态是否、何时改变取决于 Guard 和内部事件：Start 可能因资源未就绪稍后才 Executing；Pause 受理后进 Pausing、到安全点才 Paused；若随后 Guard 始终不满足或发生故障，可能停在过渡态甚至转 Failed。也存在同步拒绝：命令在当前状态非法（如对 Completed 发 Start）直接回 ACKC=8 IllegalState、不受理也无副作用。所以受理层与状态层解耦，最终状态一律以迁移后的 S16 事件为准。
5. **先迁移再发事件 / 反过来**：事件是"某状态事实已经发生"的对外通知，必须先让状态机成功完成迁移（Guard 通过、状态确实改变、副作用落定），再发携带新状态的 S16 事件，保证事件内容与真实状态一致、订阅方不会收到"声称进入 Paused 实际迁移失败"的假事件。反过来先事件后迁移，若迁移被 Guard 拒绝或抛错，外部已经收到状态变更通知，形成"通知了但没发生"的不一致，Host 会据此误判。原则同 W16：事件是事实发生后的回报，不是意图广播；迁移失败则不发该事件、改发失败/保持。
6. **Cancel Guard / 有片 InProcess 的结果**：Cancel Guard=没有任何片受到加工影响——所有 WaferProcess 仍 Waiting、没有片离开源槽、未占用工艺模块（现场等同未下发）。已有一片 InProcess 时说明物理世界已改变（片被取走/在加工），不满足 Cancel 前提，状态机拒绝 Cancel（回 IllegalState），Job 保持 Executing/Pausing；此时若 Host 想停下，应走 Abort（执行中中止并处置在途片），而不是 Cancel。这从机制上杜绝"已加工却当没发生取消"导致的账实不符和无主片。
7. **执行器为何不能自改 Job 状态**：Job 状态必须有**单一写入口**（状态机），所有迁移都经统一的合法表、Guard、副作用与审计。执行器负责推进物理加工并产生事实事件，但它若自行直接改 Job 状态，就可能绕过状态合法表和聚合守卫（例如自判完成、跳过 Pausing 直接 Paused），造成非法状态、漏发事件、多处写状态互相冲突、无法保证一致与可追溯。正确做法：执行器只"上报事实事件"，状态机集中裁决能否迁移、如何迁移并发事件，职责分离（执行器做、状态机裁决），与"位置变更唯一经 E90 位置层"是同一种单一权威设计。

## 二、参考实现（net8.0）

### 命令与内部事件
```csharp
namespace EapLab.E40.Fsm;
public enum JobCommand { Start,Pause,Resume,Cancel,Abort }
public enum JobEvent { ReadyToExecute, ReachedSafePoint, WaferAllDone, Fault }
public enum JState { Queued,Started,Executing,Pausing,Paused,Completed,Cancelled,Aborted,Failed }
```

### 完整状态机（复用 W10 泛型 StateMachine）
```csharp
public sealed class JobStateMachine
{
    private readonly StateMachine<JState,object> _sm;   // object=command或event
    public JState State { get; private set; }=JState.Queued;
    public List<string> Audit { get; }=new();
    public event Action<JState,JState,object>? Changed;
    // 可注入的聚合/前提
    public Func<bool> StartGuard=()=>true;
    public Func<bool> AllDoneGuard=()=>true;
    public Func<bool> NothingTouched=()=>true;
    public List<int> Events { get; }=new();

    public JobStateMachine()
    {
        _sm=new StateMachine<JState,object>(JState.Queued);
        _sm.Configure(JState.Queued)
           .PermitIf((object)JobCommand.Start,JState.Started,_=>StartGuard())
           .PermitIf((object)JobCommand.Cancel,JState.Cancelled,_=>NothingTouched());
        _sm.Configure(JState.Started)
           .Permit((object)JobEvent.ReadyToExecute,JState.Executing)
           .PermitIf((object)JobCommand.Cancel,JState.Cancelled,_=>NothingTouched());
        _sm.Configure(JState.Executing)
           .Permit((object)JobCommand.Pause,JState.Pausing)
           .PermitIf((object)JobEvent.WaferAllDone,JState.Completed,_=>AllDoneGuard())
           .Permit((object)JobCommand.Abort,JState.Aborted)
           .Permit((object)JobEvent.Fault,JState.Failed);
        _sm.Configure(JState.Pausing)
           .Permit((object)JobEvent.ReachedSafePoint,JState.Paused)
           .Permit((object)JobCommand.Abort,JState.Aborted)
           .Permit((object)JobEvent.Fault,JState.Failed);
        _sm.Configure(JState.Paused)
           .Permit((object)JobCommand.Resume,JState.Executing)
           .Permit((object)JobCommand.Abort,JState.Aborted);
        // 终态 Completed/Cancelled/Aborted/Failed 不配置出边
        _sm.StateChanged+=(f,t,trig)=>{ State=t; Audit.Add($"{f}->{t} by {trig}"); Changed?.Invoke(f,t,trig); };
    }
    public bool Try(object trigger)
    { try{ _sm.Fire(trigger); return true; }
      catch(InvalidOperationException){ return false; } } // 非法/Guard假: 零副作用拒绝
}
```
> 泛型状态机触发器用 object 统一承载命令与事件；也可用共同接口/结构体区分类型，实现等价。Permit/PermitIf、终态无出边、非法零副作用沿用 W10。

### 命令受理层（受理≠生效）
```csharp
public sealed class JobCommandHandler
{
    private readonly JobStateMachine _fsm;
    public JobCommandHandler(JobStateMachine fsm){_fsm=fsm;}
    public Ackc Accept(JobCommand cmd)   // S15方法调用的同步受理
    {
        return _fsm.Try(cmd) ? Ackc.Ok : Ackc.IllegalState;
        // Pause 返回Ok只表受理进Pausing; 真正Paused由ReachedSafePoint事件, 并以S16通知
    }
    public void OnInternal(JobEvent ev)=>_fsm.Try(ev); // 执行器事实事件
}
```

### xUnit
```csharp
public class JobFsmTests
{
    [Fact] public void 正常链_Queued到Completed()
    { var f=new JobStateMachine(); f.AllDoneGuard=()=>true; f.StartGuard=()=>true;
      var h=new JobCommandHandler(f);
      Assert.Equal(Ackc.Ok,h.Accept(JobCommand.Start));
      f.Try(JobEvent.ReadyToExecute); Assert.Equal(JState.Executing,f.State);
      f.Try(JobEvent.WaferAllDone); Assert.Equal(JState.Completed,f.State);
      Assert.False(f.Try(JobCommand.Start)); // 终态无出边
    }
    [Fact] public void Pause异步生效_受理后到安全点才Paused()
    { var f=new JobStateMachine(); var h=new JobCommandHandler(f);
      h.Accept(JobCommand.Start); f.Try(JobEvent.ReadyToExecute);
      Assert.Equal(Ackc.Ok,h.Accept(JobCommand.Pause));
      Assert.Equal(JState.Pausing,f.State);          // 还没Paused
      f.Try(JobEvent.ReachedSafePoint);
      Assert.Equal(JState.Paused,f.State);           // 事实到安全点才生效
      Assert.Equal(Ackc.Ok,h.Accept(JobCommand.Resume));
      Assert.Equal(JState.Executing,f.State);
    }
    [Fact] public void 聚合Guard为假_不得Completed()
    { var f=new JobStateMachine(); f.AllDoneGuard=()=>false; // 还有片没归位
      h(f); f.Try(JobEvent.WaferAllDone);
      Assert.NotEqual(JState.Completed,f.State); }
    static void h(JobStateMachine f){f.Try(JobCommand.Start);f.Try(JobEvent.ReadyToExecute);}
    [Fact] public void 已加工_Cancel被拒_应走Abort()
    { var f=new JobStateMachine(); f.NothingTouched=()=>false; // 有片InProcess
      h(f);
      Assert.Equal(Ackc.IllegalState,new JobCommandHandler(f).Accept(JobCommand.Cancel));
      Assert.Equal(JState.Executing,f.State);
      Assert.True(f.Try(JobCommand.Abort)); Assert.Equal(JState.Aborted,f.State);
    }
    [Fact] public void 终态无出边()
    { var f=new JobStateMachine(); f.NothingTouched=()=>true;
      Assert.True(f.Try(JobCommand.Cancel)); Assert.Equal(JState.Cancelled,f.State);
      Assert.False(f.Try(JobCommand.Start)); Assert.False(f.Try(JobCommand.Resume));
    }
}
```

## 三、迁移时序（手绘参考）
```
Host命令 ──Accept──► ACKC(受理,可能仅进过渡态)
执行器事实 ──Internal Event──► 状态机Guard裁决 ──通过──► 迁移(OnEntry:时间戳/资源/审计) ──► 迁移后发S16
                                          └─拒绝─► 状态不变/零副作用/IllegalState
Pause: 命令→Pausing →(走到安全点事件)→ Paused(5105)
完成: Executing →(WaferAllDone+聚合Guard)→ Completed(5104)
```

## 四、今日易错点
1. 命令直接改最终状态，不区分受理与内部事实事件（Pause 必须经 Pausing 到安全点）。
2. Guard 为假还迁移（必须拒绝、零副作用、回 IllegalState）。
3. 先广播事件再迁移（迁移失败会造成"通知了没发生"，必须先迁移后事件）。
4. 已加工还允许 Cancel（Cancel 要求无片受影响，否则只能 Abort）。
5. 终态配置出边（Completed/Cancelled/Aborted/Failed 不可再迁）。
6. 执行器自改 Job 状态（单一状态写入口=状态机，执行器只报事实事件）。
7. 完成只看流程走完不看归位/终验（聚合 Guard 必须含 E90 归位与守恒）。
8. 迁移不留审计轨迹（from/to/trigger/时间/原因是追溯依据）。
