# W17 · Day05（周五）完成条件严格性与部分完成（Partial）表达

> 建议时长：85 分钟。今天聚焦"什么才算真正完成"：Completed 的严格聚合条件、完成度统计、部分完成（Partial Complete）的精确表达与处置，以及"全部成功/部分成功/全部失败"的结果模型。杜绝"流程跑完=任务完成"的误判。

## 一、今日目标
1. 严格定义 PJ Completed 的充要条件（片、位置、终验、数据）。
2. 实现完成度统计：总片/完成/在途/失败、步骤完成率、结果汇总。

## 二、背景知识（先读，30 分钟）

### 1. Completed 的充要条件（严格）
一个 PJ 能进 Completed，必须**同时**满足：
1. 片进度：WaferMap 中**每一片**都 WaferState.Completed（走完所有 Step）。
2. 物理归位：每片 E90 位置==其声明目标槽（AtDestination），设备内/Buffer 全空（无 LeftInside）。
3. 终验通过：跨盒/源目逐片 ID 正确、全局守恒、无 Missing/Double/Misplaced/WrongId。
4. 无未决异常：无 Failed 片、无未确认 Alarm/阻断 Hold。
5. 数据完整（按 FAB 要求）：每片每步事件/采集数据齐全、配方版本记录完整（供 YMS/R2R）。
任一不满足，Job 不得 Completed（保持 Executing 挂起，或按结局转 Partial/Aborted）。

### 2. "流程跑完"不等于"任务完成"
- 执行循环把所有片"处理了一遍"只是动作走完；若一片没归位、数据缺失、终验不过，仍不是 Completed。
- 完成判定以聚合守卫为准（Day02 WaferAllDone Guard），不以"循环结束"为准。

### 3. 完成度统计（Progress）
- Wafer 维度：Total/Completed/InProcess/Waiting/Failed 计数与百分比。
- Step 维度：总步骤实例数（片×步）、完成数、完成率。
- 位置维度：在目标槽数、设备内数、源槽未动数。
- 实时对外可查（S15F5 读属性/S16 进度事件），供 Host 看板与调度。

### 4. 部分完成 Partial 的表达
- 当策略允许"部分片成功、任务带结果结束"（或异常中止时），必须结构化表达：
  - CompletedList：成功片及其最终目标槽（有效成果）。
  - Pending/InFlightList：未完成片及**实际位置**、当前 Step（待续/待处置）。
  - FailedList：失败片、错误码、实际位置。
  - 守恒核对：完成+在途+未开始+失败=总数。
- Partial 不是正常 Completed：状态上应是 Aborted/Failed 带 Partial 结果，或专门的"部分完成"终态（按标准/实现），**绝不能标 Completed 却在结果里藏失败片**。

### 5. 三种结局模型
- **AllCompleted**：全部满足严格条件→Completed（正常终态）。
- **PartialCompleted**：策略允许部分交付时，任务以"部分完成"结束并显式列出未完成部分（需要 Host 明确策略授权，默认不允许静默部分完成）。
- **Aborted/Failed**：中止/故障结束，带完整现场与 Partial 明细，供新建 PJ/Rollback/人工。
- 结局判定集中在一处（结果评估器），避免散落判断导致口径不一。

### 6. 与 Host/MES 的结果对接
- 完成/部分完成结果经 S16 事件与对象属性回报，MES 据此更新批次：哪些片完工可下流、哪些要返工/隔离。
- 部分完成必须让 MES 明确知道缺口，防止 MES 误判整批完工。
