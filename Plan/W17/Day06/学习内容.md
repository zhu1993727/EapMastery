# W17 · Day06（周六）PJ 状态持久化与断电/重启恢复

> 建议时长：105 分钟。真实设备会断电、重启、断连。今天解决"重启后如何依据物理现实重建 PJ 状态"：Job/片/步状态与位置的持久化、事件溯源快照、重启恢复流程（物理优先重建逻辑），把本周状态机做成可恢复的工业级实现。

## 一、今日目标
1. 设计 PJ 状态持久化：Job 状态、逐片进度、恢复点、位置快照的落盘/快照机制。
2. 掌握事件溯源（Event Sourcing）思路：状态由有序事件重建，结合快照加速。
3. 实现重启恢复流程：E87 确认载具→E90 重建物理位置→比对持久化进度→恢复/对账/人工。
4. 处理恢复三分支：一致→恢复到可续状态；不一致→对账重建；存疑→安全保持人工。
5. xUnit 覆盖快照重建、一致恢复、位置不符拦截、终态不恢复。

## 二、背景知识（先读，30 分钟）

### 1. 为什么需要持久化
- 设备重启后内存状态丢失，但物理片位置、载具、已完成工艺是客观事实；若不持久化进度，就不知道哪些片做过、做到哪步，可能整片重做（工艺不可重复）或漏做。
- 需要把"逻辑进度"可靠保存，重启后与"物理现实"对齐。

### 2. 持久化内容
- Job：JobId、定义（源目映射/路线）、Job 状态、时间戳。
- 每片：WaferState、当前 StepNo、步骤完成集合、实际位置、实际经过腔体。
- 恢复点 ResumeToken（Day03）、载具绑定与 SlotMap 快照、守恒基线。
- 有序状态/进度事件（用于事件溯源重建）。

### 3. 事件溯源 + 快照
- **事件溯源**：只追加不可变事件（Started/StepEnter/StepDone/WaferDone/Paused/Aborted…），状态=从初始态顺序回放事件的结果；天然有完整审计、可重建任意时刻状态。
- **快照 Snapshot**：定期/在安全点保存聚合当前状态，重启时"最近快照 + 其后少量事件"快速恢复，避免从头回放全部。
- 持久化要在**状态迁移成功后、动作不可逆点**落盘（WAL 思想：先写日志再改/与改原子），保证重启不丢已完成事实。

### 4. 重启恢复流程（核心：物理优先）
```
1 加载持久化: 最近快照 + 后续事件 → 重建 Job 逻辑状态与预期进度
2 E87: 重新扫描 LoadPort, 确认各载具身份/状态(是否还是那些盒)
3 E90: 用传感器/Mapper/读码重建物理位置空间(每片实际在哪)
4 三方比对:
   - 片: 逻辑进度位置 vs 物理实际位置; 载具: 绑定 vs 实际; 守恒
   一致 → 按逻辑状态恢复:
        Completed→终态(不重跑); Paused→Paused待Resume; Executing→安全挂起待续(从恢复点)
   不一致但可自动对账 → 以物理为准刷新逻辑(限有无/位置类,身份存疑不改)
   身份/归属存疑 → 安全保持+人工(同W13 P/L-H原则)
5 恢复后重新校验配方/模块/资源, 由Host确认后续跑/退/停
```

### 5. 恢复的状态映射
- 重启前 Completed：恢复为 Completed（成果保留，不重做）。
- 重启前 Paused：恢复 Paused（恢复点仍有效前提是现场一致）。
- 重启前 Executing：片可能停在任意位置，**不能直接恢复 Executing 自动跑**，先进入"恢复挂起"安全态，确认每片位置与安全边界后，由 Resume 从安全点续。
- 重启前终态 Aborted/Failed/Cancelled：保持终态，不自动复活。

### 6. 与 Spool/对账的关系
- 通信层 Spool（W08）保证上报事件不丢；状态持久化保证任务进度不丢；重连用全量对账（W13）校正 Host 镜像。三者互补：Spool 管报文、快照管任务、对账管 Host 视图一致。

### 7. 工业级要点
- 写入原子性/落盘时机、快照与事件一致性、恢复幂等（多次恢复结果相同）、恢复全过程审计留痕。
