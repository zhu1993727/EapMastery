## 三、三条报文的标准结构（构造依据）

### S1F2（Are You There Response）
```
L,2
  A <MDLN>    设备型号，如 "EAP-SIM-01"
  A <SOFTREV> 软件版本，如 "1.0.0"
```
S1F1 是空 body（无 Item）。

### S6F11（Event Report Send，雏形）
```
L,3
  U4 <DATAID>          数据 ID
  U2 <CEID>            事件 ID
  L,n                   报告列表
    L,2
      U2 <RPTID>       报告 ID
      L,m               变量值列表
        <V1> <V2> ...  各变量值（类型由报告定义决定）
```

### S2F41（Host Command Send，雏形）
```
L,2
  A <RCMD>              远程命令名，如 "START"
  L,n                   参数列表
    L,2
      A <CPNAME>        参数名，如 "LOTID"
      <CPVALUE>         参数值（任意类型）
```

## 四、今日任务（按时间块执行，每条报文必做四步）
对每条报文：①用 Secs 工厂构造 Item 树 → ②Encode 得 hex → ③手算独立推导 hex → ④两者逐字节对比，不一致就定位到是哪个 Item 编码错了。

### 异常注入 5 例（必做，记录"输入→预期异常→实际"）
1. 截断：`20 02 A4 01`（L,2 但只有一个子项且不完整）
2. 未知格式码：`08 00`（code=2，保留未用）
3. 长度越界：`A4 FF`（U1 声明 255 元素但无值区）
4. 嵌套超限：构造 33 层 L（超过 MaxDepth=32）
5. 原子长度非宽度整数倍：`A8 03 00 01 00`（U2 声明 3 元素但只有 3 字节值区）
