# W03 · Day06 答案与综合实验参考

## 一、自测题标准答案
1. **S1F1 空 body**：它的意图"你在吗"完全由消息头的 Stream=1/Function=1 表达，不需要额外数据；对端回 S1F2 带身份信息。空 body 是合法且常见的（很多请求类 primary 都如此）。
2. **DATAID vs CEID**：DATAID 是"数据收集定义的 ID"，标识这套报告-变量关联关系是哪次 S2F33 定义的，范围大、可能很多，用 U4；CEID 是"集合事件 ID"，标识触发本次上报的具体设备事件，数量相对有限，常用 U2（部分设备用 U4）。两者配合：DATAID 说"按哪套定义报"，CEID 说"什么事件触发的"。
3. **CPVALUE 任意类型**：远程命令的参数值由命令定义决定，可能是字符串(LOTID)、数值(数量)、布尔(开关)等，所以标准不固定类型，解码器必须能按实际格式字节还原任意类型——这正是 E5 自描述格式的价值（每个 Item 自带类型码，不需要外部 schema）。
4. **往返一致能证明/不能证明**：能证明编码器和解码器在格式字节、长度、值编码、嵌套结构上**自洽**（编出来的能解回去，解出来的能再编一样）；不能证明**与标准/对端兼容**（比如双方对某类型宽度理解不同、或对某消息结构约定不同，往返自洽但互操作失败）。所以还要手算对拍 + 真实对端/抓包验证。
5. **异常注入为何重要**：现场报文不总是完美的——网络截断、对端 bug、版本差异都会产生坏报文。只测正常报文会漏掉"解码器遇到坏报文时崩溃/死循环/读出垃圾"的风险，而这在 FAB 现场是致命的（一个坏包导致 EAP 进程挂掉）。异常注入确保解码器健壮降级。
6. **抓包区分头和 body**：HSMS 帧 = 4B 长度 + 10B 头 + body。body 从**第 15 个字节**（offset 14，0 基）开始；前 4 是长度，5-14 是 10B 头（其中第 10 字节 offset9 是 SType，SType=0 才是数据消息有 body）。

## 二、三条报文构造代码与手算 hex

### 1. S1F2（L,2[A MDLN, A SOFTREV]）
```csharp
var s1f2 = Secs.L(Secs.A("EAP-SIM-01"), Secs.A("1.0.0"));
```
手算：
- A"EAP-SIM-01" = 10 字符 → `40 0A` + 10 字节 ASCII = 12B
- A"1.0.0" = 5 字符 → `40 05` + 5 字节 = 7B
- 外层 L,2 → `20 02` + 12 + 7 = 21B
完整：`20 02 40 0A 45 41 50 2D 53 49 4D 2D 30 31 40 05 31 2E 30 2E 30`
（验证：E=45,A=41,P=50,-=2D,S=53,I=49,M=4D,-=2D,0=30,1=31；1.0.0 = 31 2E 30 2E 30 ✓）

### 2. S6F11 雏形（2 个报告）
```csharp
var s6f11 = Secs.L(
    Secs.U4(1),                                    // DATAID
    Secs.U2(2001),                                 // CEID
    Secs.L(                                         // 报告列表 L,2
        Secs.L(Secs.U2(1), Secs.L(Secs.U1(100), Secs.A("RUN"))),  // 报告1
        Secs.L(Secs.U2(2), Secs.L(Secs.F4(1.5), Secs.Boolean(true))) // 报告2
    )
);
```
手算（自底向上）：
- 报告1变量：U1=100=`A4 01 64`(3B)，A"RUN"=`40 03 52 55 4E`(5B) → L,2=`20 02`+3+5=10B
- 报告1：U2=1=`A8 01 00 01`(4B) + 变量L(10B) → L,2=`20 02`+4+10=16B
- 报告2变量：F4=1.5=`84 01 3F C0 00 00`(6B)，Boolean=true=`28 01 01`(3B) → L,2=`20 02`+6+3=11B
- 报告2：U2=2=`A8 01 00 02`(4B) + 变量L(11B) → L,2=`20 02`+4+11=17B
- 报告列表：L,2=`20 02`+16+17=35B
- 最外：U4=1=`AC 01 00 00 00 01`(6B)，U2=2001=`A8 01 07 D1`(4B)，报告列表(35B) → L,3=`20 03`+6+4+35=47B

### 3. S2F41 雏形（START 命令，2 个参数）
```csharp
var s2f41 = Secs.L(
    Secs.A("START"),
    Secs.L(
        Secs.L(Secs.A("LOTID"), Secs.A("LOT001")),
        Secs.L(Secs.A("RECIPE"), Secs.A("RCP_A"))
    )
);
```
手算：
- 参数1：A"LOTID"=`40 05 4C 4F 54 49 44`(7B)，A"LOT001"=`40 06 4C 4F 54 30 30 31`(8B) → L,2=`20 02`+7+8=17B
- 参数2：A"RECIPE"=`40 06 52 45 43 49 50 45`(8B)，A"RCP_A"=`40 05 52 43 50 5F 41`(7B) → L,2=`20 02`+8+7=17B
- 参数列表：L,2=`20 02`+17+17=36B
- A"START"=`40 05 53 54 41 52 54`(7B)
- 最外：L,2=`20 02`+7+36=45B

## 三、异常注入 5 例预期
| 例 | 输入 | 预期异常/行为 |
|---|---|---|
| 1 截断 | `20 02 A4 01` | FormatException "值区截断"（L,2 只读到一个不完整子项）|
| 2 未知码 | `08 00` | FormatException "未知/不支持的格式码 code=2" |
| 3 长度越界 | `A4 FF` | FormatException "U1 值区截断"（声明 255 元素但无值）|
| 4 嵌套超限 | 33 层 L | FormatException "嵌套深度超过 32" |
| 5 非整数倍 | `A8 03 00 01 00` | FormatException "U2 长度 3 不是宽度 2 的整数倍" |

## 四、SECS-II 编解码全链路图（参考画法）
```
应用层(GEM业务)
  │ 构造/消费
  ▼
SecsItem 树（不可变对象模型）
  │ Encode()          ▲ Decode()
  ▼                   │
字节流（格式字节+长度+值，DFS 线性化）
  │ 交给 HSMS         ▲ 从 HSMS 收到
  ▼                   │
HSMS 帧（4B长度+10B头 SType=0 + body）
  │                   │
  ▼                   ▼
TCP → IP → 网线 → 对端
```
编码方向自顶向下，解码方向自底向上；每层只关心自己的边界，不跨层解析。

## 五、今日验收（DoD）
- 3 条报文代码 hex 与手算 hex 逐字节一致（可写 Assert 自动对拍）。
- HSMS 双端真实传输：发端 Encode、收端 Decode、SML 打印与构造树一致。
- 抓包 body 字节与本地 Encode 输出完全相同。
- 异常注入 5 例全部按预期抛明确异常，进程不崩溃。

## 六、易错点
1. 手算时外层总长算错（没自底向上累加）。
2. F4 浮点 hex 记错（1.5=3F C0 00 00，不是 3F 80）。
3. S6F11 报告列表嵌套层数少一层（报告列表→单个报告→报告ID+变量列表→变量值，共 4 层 L）。
4. 异常测试只断言"抛异常"不校验异常类型/消息，导致坏报文被错误类型吞掉。
5. 抓包时把 HSMS 头的字节当 body 对比（body 从 offset 14 开始）。
