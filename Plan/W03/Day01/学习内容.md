## 二、背景知识（先读，20 分钟）

### 1. 分层边界（一句话各归位）
- **E37 HSMS**：管"怎么送到、连接状态、控制事务"，不关心 body 内容。
- **E5 SECS-II**：定义 body 的**数据结构与编码**（把结构化数据编码成字节树），并定义 SxFy 的消息族框架与语义约定。
- **E30 GEM**：规定"哪些 SxFy 用来做什么、数据项里放什么业务含义"（W5）。
- 关系：GEM 用 SECS-II 的消息表达业务，SECS-II 借 HSMS 传输。

### 2. 一条 SECS-II 消息的组成
```
HSMS: [4B长度][10B头(SType=0, S/F, W, SystemBytes)][SECS-II body]
SECS-II body = 0 或 1 棵"数据项树"（最外层通常是一个 List）
```
- body 可以为空（如 S1F1 只要 S1F2，无数据）。
- 有 body 时，最外层通常是一个 L（List），里面嵌套若干 Item。

### 3. Item 三段式（本周核心模型，必背）
```
┌──────────────┬────────────────┬──────────────┐
│ Format Byte  │ Length(1~3B)   │ Value Bytes  │
│ 高6位类型码   │ 元素个数/字节数 │ 具体数据/子项 │
│ 低2位长度字节数-1│ 大端          │ (List时是子Item)│
└──────────────┴────────────────┴──────────────┘
```
- 格式字节 = `(类型码 << 2) | (长度所占字节数 - 1)`；长度最多 3 字节（低 2 位最大 3-1=2）。
- 对原子类型，Length = 值占用的**字节数**；对 List，Length = **子元素个数**（不是字节数！）。
- Value 对 List 而言是"依次排列的子 Item"，所以能无限递归成树。

### 4. Stream/Function 与 primary/reply
- **Stream(S)**：消息大类（S1 通信、S2 设备控制、S5 报警、S6 事件报告、S7 配方…）；**Function(F)**：类内编号。
- **primary（主消息）**：发起方，F 为奇数（S1F1、S6F11）；**reply（回复）**：对应 F+1 偶数（S1F2、S6F12）。
- **W 位**：primary 的 W=1 表示"我要求你回 reply"；W=0 表示不需要回复。reply 自身 W 位为 0。
- 一条 primary 和它的 reply 用 HSMS SystemBytes 关联（W2 已实现配对机制）。

### 5. 先看一个熟例子（本周要彻底吃透）
`L,2[ A"OK", U1=7 ]` 的 body hex：`20 02  40 02 4F 4B  A4 01 07`
- `20 02`：L，2 个元素；`40 02 4F 4B`：A，2 字节="OK"；`A4 01 07`：U1，1 个元素=7。今天先眼熟，Day02/03 逐位拆。
