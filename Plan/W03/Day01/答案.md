# W03 · Day01 答案与参考

## 一、自测题标准答案
1. **三者分工**：HSMS(E37) 管传输与会话（连不连、选通、心跳、超时）；SECS-II(E5) 管 body 的**数据结构怎么编码成字节、SxFy 消息框架**；GEM(E30) 管**业务语义**（哪条消息做什么、数据代表什么设备行为）。E5 不负责送达，因为它是表示层，只产出/消费字节树，把字节交给下层 HSMS 是分层解耦——同一套 SECS-II 在 HSMS 或老的 SECS-I(E4) 上都能跑。
2. **Item 三段式 / 格式字节**：格式字节 + 长度(1~3B) + 值。格式字节**高 6 位=类型码**（L/A/U1…），**低 2 位=长度字节数-1**（0→1B长度，1→2B长度，2→3B长度）。
3. **List 的 Length 单位**：List 的 Length = **直接子元素的个数**（计数，不是字节数）；ASCII 的 Length = 字符串**字节数**；数值数组的 Length = 元素个数（总字节还要乘单元素宽度）。这是最易错点。
4. **长度为何 1~3B / 低 2 位编码**：小数据用 1 字节长度最省，超大 List/长字符串需要 2~3 字节才能表示长度；低 2 位写"长度字节数-1"：用 1B→00、2B→01、3B→10，解析时先读格式字节低 2 位就知道还要读几个长度字节。
5. **S6F11/S6F12 与 W**：S6F11 是 primary（F 奇数，事件报告上报），S6F12 是 reply（F+1 偶数，回执）。W 位只出现在 primary：S6F11 若要求 Host 回 S6F12，则其头字节2 的 W=1；reply S6F12 的 W=0。
6. **body 是否可空**：可以为空（0 个 Item）。典型 **S1F1（Are You There Request）**无 body，对方回 S1F2 带设备标识文本；很多"请求类"primary 只靠头表达意图，body 为空。

## 二、熟例子初步拆解（Day03 完整推导）
`20 02 40 02 4F 4B A4 01 07`
- `20`：0x20 高6位=8=L，低2位=0→长度1字节；`02`=2 个子元素。
- `40`：高6位=16=A(ASCII)，低2位=0；`02`=2字节；`4F 4B`="OK"。
- `A4`：高6位=41=U1，低2位=0；`01`=1个元素；`07`=值7。
（类型码全集 Day02 背，编码规则 Day03 手算。）

## 三、参考占位（EapLab.Secs2）

### SecsFormat.cs（Day02 补全数值）
```csharp
namespace EapLab.Secs2;
public enum SecsFormat : byte
{
    List = 8, Binary = 9, Boolean = 10,
    Ascii = 16, Jis8 = 17,
    I8 = 24, I1 = 25, I2 = 26, I4 = 27,
    F8 = 32, F4 = 33,
    U8 = 40, U1 = 41, U2 = 42, U4 = 43
}
```
> 注意：枚举值是**线上 6 位类型码**（=格式字节>>2），不是 0 起的顺序号；这正是 `L=8→0x20、A=16→0x40、U1=41→0xA4` 的来源。

### SecsItem.cs（抽象，Day04/05 实现 Encode/Decode）
```csharp
namespace EapLab.Secs2;

public abstract class SecsItem
{
    public abstract SecsFormat Format { get; }
    public abstract int Count { get; }                 // List=子项数；原子=元素个数
    public abstract byte[] Encode();                   // Day04
    public static SecsItem Decode(byte[] data, out int used) =>
        SecsDecoder.Read(data, 0, out used);           // Day05
}
```

## 五、今日易错点
1. 把 List 的 Length 当字节数（应是子元素个数）。
2. 类型码从 0 顺序编号（线上码 L=8/A=16/U1=41，别写错）。
3. 给 reply 也置 W=1（reply 的 W=0）。
4. 以为每条消息必有 body（S1F1 等可为空）。
5. 混淆"格式字节低 2 位"和"长度本身"（低 2 位只说长度占几字节）。
