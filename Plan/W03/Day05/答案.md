# W03 · Day05 答案与参考实现

## 一、自测题标准答案
1. **Item 边界如何确定**：先读格式字节→低 2 位得到长度字节数→读长度→对原子类型直接算出值区字节数（length×宽度），对 List 则递归读完 length 个子项；**本 Item 总消耗 = 1(格式)+长度字节数+值区字节数**，offset 推进这个量就是下一个 Item 起点。关键是"长度"在 List 是子项数、在原子是元素数/字节数，不能混用。
2. **0xA5 解码**：高 6 位 = 0xA5>>2 = 41 = **U1**；低 2 位 = 1 → 长度占 **2 字节**；随后两字节大端合成整数（如 `01 2C` = 300）。
3. **为何递归/栈而非平铺**：List 的值区是"依次排列的子 Item"，子 Item 又可能是 List，结构天然是树；平铺一层循环无法表达嵌套，也无法正确推进 offset（子项长度要等子项解码完才知道）。递归/显式栈是唯一自然解法。
4. **used 与 body.Length 关系**：used < body.Length → body 末尾有多余脏字节（可能粘了下一条、或对端多写），应告警；used > body.Length → 不可能，说明解码越界（声明长度超过实际字节，是截断/坏报文）。正常必须 used == body.Length。
5. **未知 typeCode 处理**：不应崩溃。正确做法：抛明确的"未知格式码"异常（含 offset 与字节值），上层按 S9 错误回执或记日志告警；绝不能把未知码当某类型硬解，否则会读出垃圾并污染 offset。
6. **SML 为何有用**：hex 对人不友好，SML 用缩进和类型名把树结构可视化，能一眼看出嵌套层级、元素个数、值；排障时对照标准消息结构（如 S6F11 的 L,3 骨架），立刻能发现"少了一层/类型错了/值越界"；给同事讲解时也不用翻 hex。

## 二、参考实现（EapLab.Secs2/Coding/）

### SecsDecoder.cs
```csharp
using System.Buffers.Binary;
using EapLab.Secs2.Items;

namespace EapLab.Secs2.Coding;

public sealed class SecsDecoder
{
    private const int MaxDepth = 32; // 防递归炸弹

    public static SecsItem Read(byte[] data, int offset, out int used)
        => Read(data, offset, 0, out used);

    private static SecsItem Read(byte[] data, int offset, int depth, out int used)
    {
        if (depth > MaxDepth) throw new FormatException($"嵌套深度超过 {MaxDepth}，疑似坏报文");
        if (offset >= data.Length) throw new FormatException("offset 越界，报文截断");

        byte fb = data[offset];
        var format = (SecsFormat)(fb >> 2);
        int lenBytes = (fb & 0x03) + 1;
        if (offset + 1 + lenBytes > data.Length)
            throw new FormatException($"长度字段截断 @{offset}");

        int length = ReadLength(data, offset + 1, lenBytes);
        int pos = offset + 1 + lenBytes;

        SecsItem item;
        if (format == SecsFormat.List)
        {
            var children = new SecsItem[length];
            for (int i = 0; i < length; i++)
                children[i] = Read(data, pos, depth + 1, out int childUsed), pos += childUsed;
            item = new SecsList(children);
        }
        else
        {
            int width = format.AtomWidth();
            int valueBytes = (format == SecsFormat.Ascii || format == SecsFormat.Binary)
                ? length : length * width;
            if (pos + valueBytes > data.Length)
                throw new FormatException($"{format} 值区截断 @{pos}");
            if (width > 1 && length * width != valueBytes)
                throw new FormatException($"{format} 长度 {length} 不是宽度 {width} 的整数倍");
            var raw = new byte[valueBytes];
            Buffer.BlockCopy(data, pos, raw, 0, valueBytes);
            item = BuildAtom(format, length, raw);
            pos += valueBytes;
        }
        used = pos - offset;
        return item;
    }

    private static int ReadLength(byte[] d, int off, int n)
    {
        int v = 0;
        for (int i = 0; i < n; i++) v = (v << 8) | d[off + i];
        return v;
    }

    private static SecsItem BuildAtom(SecsFormat f, int count, byte[] raw)
    {
        switch (f)
        {
            case SecsFormat.Ascii:   return new SecsAscii(System.Text.Encoding.ASCII.GetString(raw));
            case SecsFormat.Binary:  return new SecsBytes(raw);
            case SecsFormat.Boolean: return new SecsBoolean(raw.Select(b => b != 0).ToArray());
            default:
                // 数值：按宽度大端还原成 long[]（F4/F8 单独处理）
                if (f == SecsFormat.F4 || f == SecsFormat.F8)
                {
                    var vals = new double[count];
                    for (int i = 0; i < count; i++)
                        vals[i] = f == SecsFormat.F4
                            ? BinaryPrimitives.ReadSingleBigEndian(raw.AsSpan(i * 4))
                            : BinaryPrimitives.ReadDoubleBigEndian(raw.AsSpan(i * 8));
                    return new SecsNumber(f, vals);
                }
                var ints = new long[count];
                int w = f.AtomWidth();
                bool signed = f is SecsFormat.I1 or SecsFormat.I2 or SecsFormat.I4 or SecsFormat.I8;
                for (int i = 0; i < count; i++)
                {
                    long v = 0;
                    for (int j = 0; j < w; j++) v = (v << 8) | raw[i * w + j];
                    if (signed)
                    {   // 符号扩展
                        int shift = 64 - w * 8;
                        v = (v << shift) >> shift;
                    }
                    ints[i] = v;
                }
                return new SecsNumber(f, ints);
        }
    }
}
```

### SML 打印（SecsItem 扩展）
```csharp
public static class SecsSml
{
    public static string ToSml(this SecsItem item, int indent = 0)
    {
        var pad = new string(' ', indent * 2);
        switch (item)
        {
            case SecsList l:
                var sb = new System.Text.StringBuilder();
                sb.AppendLine($"{pad}L,{l.Count}");
                foreach (var c in ((IEnumerable<SecsItem>)typeof(SecsList)
                    .GetField("_items", System.Reflection.BindingFlags.NonPublic | System.Reflection.BindingFlags.Instance)!
                    .GetValue(l)!))
                    sb.Append(c.ToSml(indent + 1));
                return sb.ToString();
            case SecsAscii a:
                return $"{pad}A \"{a.Value()}\"\n";   // Value() 见下方取值方法
            case SecsNumber n:
                return $"{pad}{n.Format} {string.Join(" ", n.Values())}\n";
            default:
                return $"{pad}{item.Format} ...\n";
        }
    }
}
```
> 实际工程中建议在 SecsItem 上暴露 `Value()`/`Values()` 取值方法，避免反射；上面仅示意 SML 输出形态。

### 接通 HSMS（W2 HsmsConnection 的 OnDataMessage）
```csharp
conn.OnDataMessage += (h, body) =>
{
    if (body.Length == 0)
    {
        _log.Log(LogDir.RX, $"{h.SxFy} (空 body)");
        return;
    }
    var root = SecsItem.Decode(body, out int used);   // 调 SecsDecoder.Read
    if (used != body.Length)
        _log.Log(LogDir.ERR, $"{h.SxFy} body 末尾有 {body.Length - used} 字节脏数据");
    _log.Log(LogDir.RX, $"{h.SxFy} W={h.W} sys={h.SystemBytes}\n{root.ToSml()}");
};
```

### xUnit（往返 + 异常）
```csharp
[Fact]
public void 例3往返一致()
{
    var src = Secs.L(Secs.U4(1), Secs.U2(2001),
        Secs.L(Secs.L(Secs.U2(1), Secs.L(Secs.U1(1)))));
    var bytes = src.Encode();
    var back = SecsItem.Decode(bytes, out int used);
    Assert.Equal(bytes.Length, used);
    Assert.Equal(src.ToHex(), back.ToHex());
}
[Fact]
public void 截断报文抛异常()
    => Assert.Throws<FormatException>(() => SecsItem.Decode(new byte[]{0x20,0x02,0xA4}, out _));
[Fact]
public void 未知格式码抛异常()
    => Assert.Throws<FormatException>(() => SecsItem.Decode(new byte[]{0x08,0x00}, out _)); // code=2 保留
```

## 三、今日验收
- 例1/2/3 编码→解码→再编码 hex 完全一致（往返不变）。
- 截断、未知码、长度越界、深度超限四类坏报文都抛明确异常且不崩。
- 双端 S6F11 雏形：Equip 发、Host 解出树并打印 SML，层级与值正确。

## 四、易错点
1. 把 List 的 length 当字节数读值区（应递归读 length 个子项）。
2. 原子值区长度没乘宽度（U2 长度=3 时只取 3 字节，实际应 6 字节并判对齐异常）。
3. 有符号整数还原没做符号扩展（I1=0xFF 还原成 255 而不是 -1）。
4. 不校验 used==body.Length，放过尾部脏字节。
5. 递归不限深，遇到畸形长度可栈溢出。
