# W22 · Day03 答案与参考实现

## 一、自测题标准答案
1. **请求-应答 / 主动上报举例**：请求-应答（Host 发、设备回，主从成对）——S2F41 远程命令/S2F42 应答、S15F1 创建对象/S15F2、S2F33 定义报告/S2F34、S7F1 下载配方请求/S7F2（或 S1F1/2  Are You There）。设备主动上报（设备→Host，异步）——S6F11 事件报告、S16F1 OSS 对象事件、S5F1 报警上报（另有 S9 错误上报）。区别：前者由 Host 发起、设备同步回一个对应应答；后者由设备状态/现场变化触发、不等 Host 请求。
2. **ACKC=0 的含义/不表示**：S2F42 的 ACKC10=0、S15F2 的 ACKC=0 只表示设备**同步受理**——消息格式正确、对象/命令可识别、基本前置通过、"我收到并接受这次请求"。它不表示命令已经执行完成、对象已进入目标状态（Start 受理≠CJ 已 Executing、Load 受理≠已 Loaded）。真正生效要看状态机迁移成功后设备主动发的异步事件 S16F1/S6F11；若受理后 Guard 失败，不会迁移，要回失败结果/事件，Host 不能拿 ACKC=0 当成功。
3. **PJ 完成的 S16F1 与 S6F11 / 为何同源**：PJ 完成时，OSS 通道发 S16F1（OBJSPEC=该 PJ、CEID=PJ 完成、携带该 PJ 属性快照），GEM 采集通道发 S6F11（对应完成 CEID + 关联 RPT/VID 快照）。它们是同一事实（PJ 进入 Completed）在两套服务里的表达。必须同源：迁移成功后从同一个权威 PJ 状态对象、在同一时刻取同一批数据（状态、完成时间、进度、片数等）由统一出口生成两份报文。否则两通道各查各的缓存/拼装时刻不同，可能出现"OSS 报 Completed、GEM 还报 Executing"或进度数字不一致，Host 不同子系统收到矛盾信息。
4. **E84 为何不在 SECS 链 / 走什么**：E84 是 LoadPort 与 AMHS（OHT 小车）之间的**本地并行硬线接口（Local Parallel Transfer Interface）**，走的是独立于 TCP/IP/SECS 消息的数字 I/O 电平信号（CS/SS/VALID/HO/COMPT 等），由硬件握手保证交接安全，不经过 HSMS 连接，也不封装成 SECS 流/功能消息。它与 SECS/GEM 是两条并行通道：E84 管"盒子物理交接动作安全"，交接结果（在位）再由 E87 经 SECS（S16/S6F11）上报。
5. **Start 的消息时序 / 何时算生效**：Host→设备 S15F9（Start 方法调用），设备先同步回 S15F10（受理，ACKC=0 表示接受请求）；设备随后执行开工校验与状态迁移（LayerGate 前提、CJ-FSM Queued→Started→Executing、级联起首批 PJ）；迁移成功后设备主动发 S16F1（CJ Started/Executing、PJ Started）以及对应 S6F11。Host 只有收到这个与目标状态一致的异步事件，才能认为 Start 真正生效；只收到 S15F10 ACKC0 只能认为"设备答应去做"。
6. **不同源典型故障 / 架构避免**：典型故障：同一 PJ 完成，S16F1 用刚迁移的新状态（Completed）、S6F11 用迁移前缓存快照（Executing），Host 的 OSS 侧和采集侧看到矛盾状态；或两条链时间戳/进度数字对不上，良率/派工系统误判。架构上避免：状态迁移与上报分离为"先迁移成功→对权威状态拍一次快照→由统一事件出口 UnifyEmitter 基于这同一份快照同时组装 S16F1 和 S6F11"，任何通道都不自行另查缓存拼装，从结构上保证一次事实、一份快照、多通道一致。
7. **Spool 哪类 / 命令为何不简单重发**：进 Spool 的是设备主动上报类——S6F11、S5F1、S16F1（这些是"已发生事实的通知"，断线时缓存、按序重发、对端按序号去重、ACK 后删，至少一次且有序）。命令类（S2F41、S15F9 等）不能断线后简单重发，因为命令是"要求执行动作"，断线期间设备可能已经执行过（只是应答丢了），盲目重发会导致重复创建对象/重复启动/重复加工；应在重连后先做状态对账（权威状态为准），确认目标状态未达成才决定是否重下，且命令要幂等。

## 二、参考实现（net8.0）

### 消息与链路追踪
```csharp
namespace EapLab.Cell.Msg;
public enum Dir{ H2E, E2H, Hardwire }
public sealed record Msg(string Name,Dir Dir,bool Async,string? Pair=null,string Note="");
public sealed class MessageTracer
{
    private readonly List<Msg> _chain=new(); public IReadOnlyList<Msg> Chain=>_chain;
    public void Emit(Msg m){_chain.Add(m);}
    // 校验: 每个H2E请求应答对都已出现, 且请求先于应答
    public List<string> ValidatePairs()
    { var err=new List<string>();
      foreach(var req in _chain.Where(m=>m.Dir==Dir.H2E && m.Pair!=null))
      { var idx=_chain.IndexOf(req); var rep=_chain.Skip(idx+1).FirstOrDefault(m=>m.Name==req.Pair);
        if(rep==null)err.Add($"{req.Name} 缺少应答 {req.Pair}"); }
      return err; }
    public void OnDeposit(){Emit(new("E84 Deposit",Dir.Hardwire,false,Note:"四相握手非SECS"));}
    public void OnInstalled(){Emit(new("S16F1 CarrierInstalled",Dir.E2H,true));}
    public void OnLoad(){Emit(new("S15F9 Load",Dir.H2E,false,"S15F10"));Emit(new("S15F10 ACKC",Dir.E2H,false));
                         Emit(new("S16F1 Loaded",Dir.E2H,true));}
    public void OnStartCj(){Emit(new("S15F9 Start",Dir.H2E,false,"S15F10"));Emit(new("S15F10 ACKC",Dir.E2H,false));
                            Emit(new("S16F1 CjStarted",Dir.E2H,true));Emit(new("S6F11 CEID",Dir.E2H,true));}
}
```

### 同源统一事件出口
```csharp
public sealed record StateSnapshot(string ObjId,string State,DateTime At,IReadOnlyDictionary<string,object> Attrs);
public sealed record SecsMessage(string Kind,StateSnapshot Snap);
public sealed class UnifiedEventEmitter
{
    public List<SecsMessage> Outbox{get;}=new();
    // 迁移成功后调用: 对同一权威快照同时生成 S16F1 与 S6F11
    public void EmitStateChanged(StateSnapshot snap)
    { Outbox.Add(new SecsMessage("S16F1",snap)); Outbox.Add(new SecsMessage("S6F11",snap)); } // 同一份snap
    public bool SameSourceConsistent()=>Outbox.Chunk(2).All(p=>ReferenceEquals(p[0].Snap,p[1].Snap));
}
```

### xUnit
```csharp
public class MsgChainTests
{
    [Fact] public void Start链_先受理后异步生效()
    { var t=new MessageTracer(); t.OnStartCj();
      var names=t.Chain.Select(m=>m.Name).ToList();
      Assert.Equal(new[]{"S15F9 Start","S15F10 ACKC","S16F1 CjStarted","S6F11 CEID"},names);
      Assert.Empty(t.ValidatePairs()); }
    [Fact] public void 缺应答被检出()
    { var t=new MessageTracer(); t.Emit(new("S15F1 Create",Dir.H2E,false,"S15F2"));
      Assert.Contains(t.ValidatePairs(),e=>e.Contains("S15F2")); }
    [Fact] public void S16与S6F11同源同快照()
    { var e=new UnifiedEventEmitter();
      var snap=new StateSnapshot("PJ1","Completed",DateTime.UtcNow,new Dictionary<string,object>{{"done",6}});
      e.EmitStateChanged(snap);
      Assert.True(e.SameSourceConsistent());
      Assert.Equal("Completed",e.Outbox[0].Snap.State); Assert.Same(e.Outbox[0].Snap,e.Outbox[1].Snap); }
    [Fact] public void E84走硬线不走SECS()
    { var t=new MessageTracer(); t.OnDeposit();
      Assert.Equal(Dir.Hardwire,t.Chain[0].Dir); }
    [Fact] public void 受理ACKC不等于生效_生效看异步事件()
    { var t=new MessageTracer();
      t.Emit(new("S15F9 Start",Dir.H2E,false,"S15F10")); t.Emit(new("S15F10 ACKC",Dir.E2H,false));
      bool effective=t.Chain.Any(m=>m.Dir==Dir.E2H&&m.Async&&m.Name.StartsWith("S16"));
      Assert.False(effective);   // 只有受理, 还没S16, 未生效
      t.Emit(new("S16F1 CjStarted",Dir.E2H,true)); Assert.True(true); }
}
```

## 三、消息纵贯（手绘参考）
```
上线: HSMS Select → S1F13/14 → S1F17/18
送盒: E84硬线(非SECS) → Installed: E→H S16F1/S6F11
授权: H→E S15F1/F2建对象 → S15F9 Load/F10受理 → E→H S16F1 Loaded
派工: H→E S15F1 CJ/F2 → S15F9 Start/F10(受理) → 迁移后 E→H S16F1 CJ/PJ Started + S6F11
加工: E→H S6F11(CEID+VID/RPT快照); 报警E→H S5F1; 命令H→E S2F41/F42
完成: 迁移成功→同一权威快照→统一出口同时出 S16F1(PJ/CJ Completed)+S6F11
下料: S15F9 Unload/F10 → S16F1 Unloaded → E84 Pickup硬线
铁律: ACKC=受理(同步); 生效=迁移后异步事件; S16与S6F11同一份快照同源
可靠: 上报类断线Spool按序重发去重; 命令类重连对账后幂等决定, 不盲目重发
```

## 四、今日易错点
1. 把 ACKC=0 当执行完成（受理≠生效，生效看迁移后 S16/S6F11）。
2. S16F1 和 S6F11 各查各的缓存拼装（必须同一权威快照、统一出口）。
3. 把 E84 当 SECS 消息（它是独立并行硬线数字 I/O）。
4. 分不清主从请求应答对与设备异步上报。
5. 迁移还没成功就发"完成"事件（必须先迁移、后对新状态拍快照上报）。
6. 受理后 Guard 失败却不补发失败结果，Host 误以为生效。
7. 断线后盲目重发命令导致重复创建/启动（应先对账、命令幂等）。
8. Spool 不按序/不去重，重连后事件乱序或重复。
