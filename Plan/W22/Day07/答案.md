# W22 · Day07 答案

## 一、排障推演参考
1. **Host 说 CJ 已完成、设备不让下料**：分三层查。状态层：调 LayerGate.CanUnload 看哪条不过——常见是 CJ 实际没到 Completed（Host 可能把 S15 Start 的 ACKC 受理误当完成，或收到了不一致的上报），逐个查子 PJ 是否真 Completed；物理层（最常见）：E90 是否有片没回输出盒（LeftInside 在臂/腔/Buffer）、机械手是否 Home、LoadPort 门是否关、是否有 CarrierHold/EquipmentHold 未解除；消息层：核对 S16F1 CJ Completed 是否真的发出且数据来自完成后的权威快照（可能 Host 侧状态超前、设备侧 CompleteGuard 因片未归位没过）。顺序：先让设备给出 UnloadGuard 不满足的具体条件→查 E90 每片实际位置与设备机构状态→再核对 Host 为何认为完成（消息是否同源、是否把受理当生效）。根因多为"账面完成、物理有片滞留"。
2. **重连后收到两条相同 PJ Started**：可能原因①命令重发——断线时 Host 没收到 S15 应答，重连后又下了一次 Start，而设备其实已启动，若命令不幂等就重复创建/启动并各发一次 Started；②Spool 与实时重复——断线期间 PJ Started 事件入了 Spool，重连实时又发了一次同一事件，对端没按序号/幂等键去重；③S16 与 S6F11 被 Host 同一消费者当成两个不同"Started"（没识别它们是同一事实的两通道表达）。正确机制：命令幂等（同一 CJ/PJ 的 Start 带幂等键，重复调用只返回当前态、不二次启动）；Spool 事件带单调序号，重连按序补发、对端按序号去重，且补发前先对账权威状态、已确认的不重发；明确 S16F1 与 S6F11 是同一权威快照的两通道、Host 侧按对象+状态+事件序号去重。

## 二、全栈综合自测卷（8 题）参考答案
1. **十阶段口述要点**：0 通信上线（E5 HSMS SELECTED、E30 S1F13/14、S1F17 ONLINE REMOTE）；1 E84 硬线 Deposit 送盒；2 E87 Installed（去抖在位、读盒 ID）；3 预约匹配+Load→Loaded（逻辑授权、S15/S16）；4 E90 读盒建 SourceMap 基线；5 E94 S15 Create CJ 过六不变量；6 Start 级联起首批 E40 PJ（门控+选腔）；7 多腔并发加工、位置唯一走 E90、跨 PJ 交接，全程 S6F11/S16F1/S5F1/S2F41；8 PJ 严格完成、CJ 聚合完成（片到输出、终验）；9 UnloadGuard 五条件→Unloaded→E84 Pickup。每段门控=物理事实→逻辑授权→任务编排。
2. **五层唯一权威 / 跨层只读**：E30 控制态归 GEM 控制模块（整机）、E87 载具态归 CarrierManager（盒）、E90 片位置归 SubstrateTracker（片，唯一改位入口）、E40 PJ 态归 JobStateMachine、E94 CJ 态归 CjStateMachine（子 PJ 聚合）。跨层不复制可写副本，只调对方公开方法实时查询，或订阅事件维护只读投影（以权威方为准）；LayerGate 作为只读协调者集中做前置判定、不改任何层状态。
3. **受理≠生效 / 同源**：S2F42 ACKC10=0、S15F2/F10 ACKC=0 都只是同步受理（收到、可识别、基本前置过），生效以状态迁移成功后的异步 S16F1/S6F11 为准；受理后 Guard 不过则不迁移并回失败。同源解决"同一事实在 OSS 通道(S16F1)和 GEM 采集通道(S6F11)报出不一致状态/数据"的问题：迁移成功后对同一权威状态拍一份快照，由统一出口同时生成两报文，保证状态、时间戳、关键属性完全一致。
4. **上料链路与异常**：E84 Deposit（四相握手、在位）→去抖确认 E87 Installed（读 CarrierID）→预约匹配+无 Hold 才 Load→Loaded（唯一可自动取片）→逐槽读片建 SourceMap/SlotMap 并与 Loaded 载具绑口、冻结基线。异常：在位抖动/握手中断不确认、等重交；读不到盒 ID 挂起；预约不符拒 Load 并 Hold（防错料）；Missing/Double/Misplaced/UnknownId 如实标 Abnormal、Double 等严重异常 Hold；多口管线独立、片账全局统一。
5. **加工链路三边界**：Start CJ→级联起依赖就绪 PJ→选腔并发→逐片 E90 原子 Move（源→臂→锁→腔），Process 只改工艺状态不改位置，加工完 Move 到 PJ 目标→PJ 严格完成→跨 PJ 幂等交接→后继启动→CJ 聚合完成。三边界：编排不改位置（CJ/PJ 只下指令，位置唯一由 E90 Move 改）；加工不改位置（Process 只推进工艺状态）；状态只向上聚合（片→PJ→CJ，上层不自称完成）。
6. **UnloadGuard 五条件/下料时序**：所有作业完成、所有片回输出载具、机械手 Home、LoadPort 门关闭、无相关 Hold。时序：先逻辑 Unload（Loaded→Unloaded、解除占用，S15 受理→迁移后 S16 生效），再 E84 Pickup 四相握手让 OHT 物理取盒、在位 OFF；归属不确定禁自动重试、fail-safe 转人工。
7. **重连对账顺序 / Spool 补不补**：HSMS Select→S1F13/14、S1F17 恢复 ONLINE；E87 三对账（物理在位/设备账/Host 镜像）；E90 用实际 SlotMap 重建片账（P→L 收敛）；E40/E94 事件溯源+快照重建并与物理核对（L→H）；权威确定后 Spool 按序补发。Spool 只补"已发生未确认的上报"（S6F11/S5F1/S16F1，带序号、对端去重、ACK 后删）；命令类不重发，重连对账后按权威状态幂等决定是否补下，防重复启动。
8. **三条红线如何杜绝假完成/丢片/非法迁移**：物理红线——任何异常下 E90 唯一位置/容量/守恒成立，异常处理本身不制造重片丢片；状态红线——只走合法迁移、Guard 不过不迁移、终态无出边，不存在账面与物理脱节；事实红线——完成必须物理归位+守恒，恢复后输出集合等于基线，达不到就显式 Partial（授权+片明细）或安全保持转人工。三条分别守住物理、状态、结果，使设备在正常与异常路径都不可能"说完成却没做完、把片弄丢、跳到非法状态"。

## 三、W23 预热思考题参考
1. **两 CJ 争唯一腔 / 防饥饿**：调度器依据确定性规则排序——优先级（Host 指定/批次紧急度）→同级按就绪时间 FIFO→老化（等待越久优先级动态提升，aging）→配方切换代价/亲和。用设备级全局资源日历为该腔预留时间区间，先满足者得、后到者排到最早空隙。防无限推迟：给每个等待 PJ/CJ 记录等待时长并做老化提升，设置最大等待/饥饿阈值，超过则强制提权，并保证规则可解释（能说明"为什么先做它、还要等多久"），避免低优先级饿死与优先级反转（W18 全序申请、all-or-nothing 预留同样适用）。
2. **前批未下料后批已 Loaded / 全局台账**：E90 台账以**全局唯一片 ID** 为主键，每片带所属 CJ/Lot 标记与当前位置，不按载具/CJ 混账；两个载具各自走 E87 状态（前批输出载具待 Unload、后批输入载具 Loaded），全局集合守恒按"所有载具+设备内"整体计算，同时按 CJ 分别统计子集（前批片集合、后批片集合各自守恒、交集为空）。这样即使物理上同机并存，也能区分某片属于哪个 CJ、在哪个位置，跨 CJ 不串片、总量与分量都守恒。
3. **多 CJ 并发断线重连不串批**：重建以对象身份为准而非时间顺序——通信恢复后先 E87/E90 重建物理与片账（每片带 CJ 归属），再逐个 CJ 用各自的事件溯源/快照重建：按 CjId 恢复其 PJ 集合、依赖图、各自进度与状态，再与 E90 实际片位置交叉核对（这片属于哪个 CJ、应在哪个 PJ），Spool 补发的事件带 CjId/PjId 与序号，Host 按对象身份归位。关键是所有状态与事件都携带 CJ/PJ 身份键，重建按身份分别收敛，物理片账提供"片属于哪批"的裁决，从而多 CJ 各自回到正确状态、不串批。

## 五、W22 全周易错点总清单
1. 跳过阶段/把 Installed 当 Loaded/跳过 E90 基线。
2. 设备端直连 MES；E84 误当 SECS 消息。
3. 跨层复制可写状态（单一事实源被破坏）。
4. 起 CJ/起 PJ/取片/完成/Unload 门控条件遗漏（集中 LayerGate）。
5. 三类 Hold 范围混淆、以为设备能自解。
6. 把 ACKC 受理当生效；S16 与 S6F11 不同源。
7. 上料预约不符将错就错；读片异常不如实标 Abnormal。
8. 加工段编排/Process 越权改位置（唯一 E90 Move）。
9. 最后 PJ 完成即 CJ 完成（必须片到输出、设备空、守恒）。
10. 并行汇合一支先到就汇合（分支齐才 Join、先到安全等）。
11. 下料不满足五条件、账面与物理取盒时序颠倒、归属不确定自动重试。
12. 断线停本地不可中断工艺；重连不按 E87→E90→PJ/CJ 顺序对账。
13. 命令类进 Spool 重发导致重复启动；上报不按序/不去重。
14. 异常处理破坏守恒、非法迁移、静默假完成（三红线）。
