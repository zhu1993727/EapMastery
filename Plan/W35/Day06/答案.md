# W35 · Day06 答案与参考实现

## 一、自测题标准答案
1. **12 阶段（标准/系统）**：①建单建批——MES 工单/Lot、WIP Released；②排程派工——scheduling/dispatch、设备能力资格+派工规则、预约（Day02）；③搬运上料——AMHS、E84 并行 I/O 握手（W11）；④装载绑定——E87 Installed→Loaded、Carrier↔Lot（W12-13）；⑤对片——E90 SlotMap 三不变式（W14-15）；⑥配方就绪——RMS golden 一致性、缺则 S7 分发回读 hash（W33）；⑦建作业——S2F41、E40 PJ+E94 CJ（W16-23）；⑧选配方启动——PP-Select 回读、五门、Start、S6F11 JobStarted 生效（Day03）；⑨加工监控——recipe Step、EDA trace→EDC→FDC、GEM S6F11 分段（W27-34/W30）；⑩逐批控制——量测/VM→R2R overlay 经 RMS/GEM、VM/SPC（W31-32）；⑪完工聚合——片终态→PJ/CJ Completed、片/批结果与质量门、EDC 数据就绪（Day04）；⑫过账流转——Move、扣消耗、写谱系、AMHS 搬走、刷新派工、YMS 关联（Day02/04）。
2. **通道分工**：GEM(HSMS/SECS) 走稀疏作业与控制/事件——E87/E90 状态、S2F41 远程命令建 PJ/CJ、PP-Select、Start、S6F11 Job/Step/片事件、S5F1 报警、S7 配方、Hold/Release，以及所有下行控制；EDA/EDC 走高频连续只读数据——10Hz–1kHz 过程 trace、异常 EXV，经 EDC 实时流给 FDC、历史给 VM/SPC/YMS（W27-34）。下行控制只走 GEM，是因为 EDA/Interface-A 被设计为多客户端只读订阅通道（编译期 IReadOnlyDataBus 封死写方法，W29），没有控制语义与单一控制授权；控制必须经唯一、受控、带握手与状态机保证的 GEM 通道，避免多客户端同时写设备造成冲突与安全事故。
3. **生效判据**：阶段8 以设备状态机真正迁移到 Started/Executing 并主动发出 S6F11 JobStarted（且回读当前作业/PPID 与指令一致）为生效；S2F42/命令 ACKC10=0 只是"收到且格式合法、愿意受理"，此刻可能尚未建作业/未选配方/未启动。若把 ACK 当生效，设备随后拒绝或延迟时上位会误判已开工，造成账实脱节（W05/W22/W31/W35 Day03 一以贯之的"受理≠生效"）。
4. **overlay 路径/不改主档**：R2R 依据上一 run 量测/VM 用 EWMA/dEWMA 算出只含增量 Δ 的 overlay（作用域=腔/Lot/片/有效期、带 ReqId、只调被授权的 control knob），经"R2r 建议→RMS 受控→GEM 下行（S2F41/参数设定）→设备回读一致+S6F11 生效"的握手作用到设备（W31）。不直接改 recipe 主档，是因为主档是经 ECN 批准的 golden 基线（W33），永久/结构性变更必须走 ECN；overlay 是小幅、可撤、带作用域的临时补偿，二者分离才能既自动补偿慢漂移又保持基线受控可审计，主档升级旧 overlay 自动失效。
5. **片不符拒开工/不变式**：E90 三不变式要求 MES 期望片集合、Carrier 实际片、设备 SlotMap 三者一致（W14-15）。出现缺片/错片/位置不符时必须拒绝建作业/开工并保持安全态、核对实物，因为一旦开工就会把 A Lot/错槽的片按 B Lot 工艺加工，造成串批、片级张冠李戴、谱系与良率全错，属不可接受的质量事故；宁可停机核对也不带疑生产（与 Day03 物料门一致）。
6. **分支B 各方职责**：FDC（检测/建议方）基于 EDA 实时流检出越限/异常模式，发出报警与"建议 Hold"信号并分级，但它不是执行方；设备 FSM（唯一执行方）按联锁/指令真正进入 Hold 状态、暂停加工（谁设谁解，决策≠执行）；MES（业务方）收到 S5F1/S6F11 后冻结该 Lot 的 WIP、暂停过账与流转；工程师（处置/决策方）查因、处置后执行 Release（解除方与设置方对应），设备恢复续做；全过程数据入 EDC、完工结果带质量状态与报警记录（W30/W34/Day03/05）。FDC 不直接停设备、MES 也不绕过 EAP 直接控设备。
7. **分支C 先对账/顺序**：断线期间设备可能本地继续加工，上位停留在旧状态形成脑裂，若直接下发会重复 Start/建 Job/抢占片腔，故重连后必须先对账、对账完成前冻结下行。顺序沿用 W22 并上延到 MES：先 HSMS 重新 Select/Linktest→读 E87 Loadport/Carrier→读 E90 SlotMap→读 E40/E94 作业队列与各 Job 状态→Spool 补报断线期上报类事件（设备侧重连对账）；再与 MES WIP 账逐 Lot/Job 比对，按设备真相做幂等补偿（补完工/置 Hold/冲正提前过账/清幽灵作业），判不准的冻结升级人工（Day05）；全部对齐后才恢复正常下行控制。

## 二、参考实现（net8.0）：端到端编排（教学级，串联各周概念）

```csharp
namespace EapLab.Mes.E2E;
public enum Stage{ Created,Dispatched,Moved,Loaded,SlotsChecked,RecipeReady,JobBuilt,Started,
                   Monitoring,Controlled,CompletedAggregated,MovedOut,Blocked }
public sealed class LotJourney
{
    public Stage S{get;private set;}=Stage.Created;public List<string> Log{get;}=new();
    bool _slotOk,_recipeOk,_reconciled=true;
    public void Dispatch(){S=Stage.Dispatched;Log.Add("dispatch+reserve");}
    public void LoadAndCheckSlots(bool slotMatch)
    { S=Stage.Moved;Log.Add("E84 AMHS handoff");S=Stage.Loaded;Log.Add("E87 bind carrier-lot");
      _slotOk=slotMatch;S=slotMatch?Stage.SlotsChecked:Stage.Blocked;
      if(!slotMatch)Log.Add("E90 mismatch -> REJECT, no job (anti mix-lot)"); }
    public void ReadyRecipe(bool ok){_recipeOk=ok;if(ok&&_slotOk){S=Stage.RecipeReady;Log.Add("RMS golden hash ok");}}
    public void BuildAndStart(bool fiveGates)
    { if(!_slotOk||!_recipeOk){S=Stage.Blocked;Log.Add("gates fail -> block");return;}
      S=Stage.JobBuilt;Log.Add("S2F41 build E40 PJ / E94 CJ");
      if(fiveGates){S=Stage.Started;Log.Add("ACKC10=0 accepted; S6F11 JobStarted = effective");} }
    public void Process(bool fdcAlarm)
    { S=Stage.Monitoring;Log.Add("EDA trace->EDC->FDC; GEM S6F11 step markers");
      if(fdcAlarm){S=Stage.Blocked;Log.Add("FDC signal -> equipment FSM Hold(who-set-who-clear), MES freeze WIP");} }
    public void Control(){if(S==Stage.Monitoring){S=Stage.Controlled;Log.Add("VM/R2R overlay via RMS->GEM knob only");}}
    public void AggregateComplete(bool dataReady,bool qualityDecided)
    { if(S is Stage.Monitoring or Stage.Controlled&&dataReady&&qualityDecided)
      {S=Stage.CompletedAggregated;Log.Add("wafer/job aggregate + quality gate + EDC ready");} }
    public void MoveOut(){if(S==Stage.CompletedAggregated){S=Stage.MovedOut;Log.Add("MES move + consumption + genealogy + AMHS out");}}
    public void ReconnectThenResume(System.Action recon)
    { if(!_reconciled){recon();_reconciled=true;Log.Add("W22 HSMS>E87>E90>E40/E94>Spool then align MES WIP; downlink frozen until done");} }
}
```

public class JourneyTests

    { var j=new LotJourney();j.Dispatch();j.LoadAndCheckSlots(true);j.ReadyRecipe(true);

## 二、五泳道全链路（手绘参考）
```
MES:        建单建批 → 排程派工/预约 ──────────────────────────────── 冻结/放行 → 质量判定→Move/扣账/谱系 → YMS
EAP:           │ 派工  ├ E84搬 →E87绑定→E90对片 →RMS就绪→建PJ/CJ→选配方Start(五门)  聚合片/批结果/质量门 → 过账
设备:           ▼       └Loadport 装载/对片  S7配方 S2F41建作业 S6F11生效 按Step加工(FSM Hold执行方) PJ/CJ Completed
RMS:                         golden一致/S7分发/PP-Select ◀── overlay只调knob(R2R) ── VM/SPC/FDC
EDC(EDA):                                 高频trace→实时流FDC / 历史VM·SPC / 数据引用回MES ; 时间·上下文·质量治理
AMHS:       E84搬进 ───────────────────────────────────────────────────────────── E84搬出到下一工序
控制流(下行,只走GEM): MES→EAP→设备 ; 数据流(上行): 高频EDA→EDC, 作业/事件GEM→EAP→MES
异常: A片不符(E90拒开工) / B FDC信号→设备Hold·MES冻结·工程师Release / C 断线先W22+MES对账再下行(防脑裂)
```

## 三、今日易错点
1. 全链路漏阶段（尤其对片、配方就绪、生效判据、数据齐备再过账）。
2. 把高频 trace 走 GEM 或让 EDA 承担下行控制。
3. 把 ACK 当开工生效。
4. R2R 直接改 recipe 主档而非经 RMS 下发 knob overlay。
5. 片不符仍开工，破坏 E90 不变式导致串批。
6. 混淆 FDC（建议）、设备 FSM（执行 Hold）、MES（冻结 WIP）、工程师（处置 Release）。
7. 断线重连不先对账就下发，脑裂期重复作业。
8. 过账不写谱系/不扣消耗/不关联 EDC 数据引用，后续无法追溯与良率分析。
