# W35 · Day02 答案与参考实现

## 一、自测题标准答案
1. **scheduling vs dispatch/对接谁**：scheduling（排程）是基于订单交期、产能与工艺路线的较长期（班/日级）计划，决定每个 Lot 大致何时到哪道工序、目标顺序与资源安排；dispatch（派工）是现场实时决策——当某台设备空闲时，从当前等待的 WIP 里按规则选出下一个加工哪个 Lot、上哪台/哪个腔，并驱动搬运上料。排程面向未来产能与交期，派工面向当下这一次选择；设备端 EAP 主要对接 dispatch 的结果（派给我哪个 Lot、哪版 PPID、哪些片槽、优先级），并把设备实时状态回传给上层支撑排程/派工。
2. **候选条件**：①能力匹配——设备/腔硬件支持该 Operation/产品/recipe；②资格有效——设备当前通过该工艺认证（保养/换件后重新 qualification、工程片验证合格），未认证不能做；③状态可用——按 E10 处于可生产状态、非 Down/Hold/Off、无安全联锁（W25）；④配方就绪——指定 PPID 版本已分发且一致性校验通过、可选择（W33）；⑤资源满足——有空腔/Loadport/配套资源，批处理还要满足凑批条件；⑥工艺路线与 WIP 状态允许（Lot 确实流到该工序、未被 Hold）。全部满足才是合法候选，缺一不可派。
3. **派工规则（≥4）**：FIFO 按到达先后，简单公平、易预测；优先级/EDD 按紧急度/最早交期优先保交付；Setup/换型最小化，让同 recipe/同气体/同产品连续加工，减少换型停机；批处理凑批（炉管类攒够片数或等到时限开炉）；瓶颈优先（TOC，优先喂饱瓶颈设备避免整线受限）；还可结合 WIP 平衡、就近搬运（AMHS 路径短）、客户/质量状态等多因子加权打分，生成 dispatch list 排序，同时始终受工艺路线、资格、在制状态硬约束（硬约束先过滤，软规则再排序）。
4. **凑批/权衡**：炉管/CVD 等批处理设备一次加工一整批（多个 Lot/盒或多片），单批数量越大单位产能越高、均摊成本越低，但凑批需要等待更多 Lot 到达，等待会拉长在制周期（cycle time）、增加 WIP、可能拖慢交期。权衡是设"目标批量+最大等待时限"双阈值：片数凑够即开，或虽没凑够但等到时限也开（避免无限等），在设备利用率（大 batch）与交付周期（少等待）之间取平衡；瓶颈批设备通常偏向保利用率，非瓶颈偏向少等待。
5. **预约-搬运-上料-队列串联**：派工/调度先为 Lot 预约（reserve）目标设备/腔的时段或位置→下发搬运请求给 AMHS，把对应 Carrier 从存储/上游搬到该设备 Loadport（E84 并行 I/O 握手，W11）→Carrier 到位后 E87 Load、扫码绑定 CarrierID↔Lot（Installed→Loaded）→E90 校验 SlotMap/片（W14-15）→EAP 按派工创建 E40 PJ/E94 CJ 进入设备作业队列（Queued），设备空闲时 Received→Started 执行（W16-23）。取消/改派时要反向同步：撤搬运、卸载或更新作业队列状态，保证预约、实物位置、作业队列三者一致。
6. **Move 防错/拦截**：过账 Move 前校验：①工艺路线顺序——Lot 当前工序与目标工序相邻且正确，拦截跳站/错序回流；②设备匹配——加工设备具备该工序能力与资格（防上错机台）；③身份一致——Lot↔Carrier↔SlotMap 一致（防串批/张冠李戴，Day01/E87/E90）；④状态合法——作业确已完工、未被 Hold、结果/量测满足过站条件（防未完工过站）；⑤唯一性——同一 Lot 同一工序不能重复过账（防重复加工/重复计数）。任一不过拒绝 Move 并提示，异常走返工/报废/工程流程，保证 WIP 账实一致与谱系正确。
7. **区分异常流**：正常生产按标准路线增值加工；返工（rework）是片有问题需按专门返工路线重复某工序（可能影响性能、有次数限制、需批准）；报废（scrap）是片退出生产；工程 Lot/工程作业是为调试/验证设备而非客户产品。它们在 MES 中必须区分：走不同路线与审批、单独统计产能/良率（工程片不应计入产品良率，W25 OEE 也要区分）、谱系上明确标注，否则会污染交付数量、良率/OEE 统计、工艺数据（VM/SPC 不能把工程片当产品片）与成本核算。

## 二、参考实现（net8.0）：派工器

```csharp
namespace EapLab.Mes.Dispatch;
using EapLab.Mes;
public sealed class EqInfo
{ public string Id{get;init;}="";public HashSet<string> Capable{get;init;}=new();public bool Qualified=true;
    public bool Available=true;public bool RecipeReady=true;public bool IsBottleneck=false;public int Queued; }
public sealed class WipLot
{ public string Id{get;init;}="";public string Op{get;init;}="";public string Ppid{get;init;}="";
    public int Priority;public DateTime Arrive;public int WaferCount;public bool OnHold;public int DueInHours; }
public sealed class Dispatcher
{
    // 硬约束过滤: 能力/资格/状态/配方/未Hold
    public IEnumerable<EqInfo> Candidates(string op,WipLot lot,IEnumerable<EqInfo> eqs)
    =>eqs.Where(e=>e.Capable.Contains(op)&&e.Qualified&&e.Available&&e.RecipeReady&&!lot.OnHold);
    // 打分: 瓶颈保护 + 交期紧迫 + 优先级 + 少换型(同PPID排队少) + 早到(FIFO)
    public WipLot? Pick(string op,string currentPpid,IEnumerable<WipLot> waiting)
    { var q=waiting.Where(l=>l.Op==op&&!l.OnHold).ToList();if(q.Count==0)return null;
        return q.OrderByDescending(l=>Score(l,currentPpid)).First(); }
    static double Score(WipLot l,string cur){double s=0;
        s+=(72-l.DueInHours)*2; s+=l.Priority*10; s+=l.Ppid==cur?5:0; s-=l.Arrive.Ticks/TimeSpan.TicksPerMinute*0.001;return s; }
    // 批处理: 凑够目标数 或 等到最大等待时限
    public bool CanStartBatch(IEnumerable<WipLot> lots,int targetCount,TimeSpan maxWait,DateTime now)
    { int wafers=lots.Sum(l=>l.WaferCount);var oldest=lots.Min(l=>l.Arrive);
        return wafers>=targetCount||now-oldest>=maxWait; }
    // Move防错
    public string? ValidateMove(Lot lot,EqInfo eq,string targetOp,bool jobDone)
    { if(lot.OnHold==false?false:lot.State==LotState.OnHold)return "lot on hold";
        if(!eq.Capable.Contains(targetOp)||!eq.Qualified)return "equipment not capable/qualified";
        int next=lot.OpIndex+1;
        if(next>=lot.Route.Count||lot.Route[next]!=targetOp)return "wrong route/skip station";
        if(!jobDone)return "job not finished";return null; }
}
```

```csharp
public class DispatcherTests
{
    EqInfo E(string id,string op,bool q=true,bool a=true,bool r=true,bool bn=false)=>
        new(){Id=id,Capable=new(){op},Qualified=q,Available=a,RecipeReady=r,IsBottleneck=bn};

      Assert.Single(d.Candidates("Etch",lot,list)); }
    [Fact] public void 交期紧急优先()
    { var d=new Dispatcher();
      var lots=new[]{new WipLot{Id="A",Op="Etch",DueInHours=48,Arrive=DateTime.Now},
                      new WipLot{Id="B",Op="Etch",DueInHours=4,Arrive=DateTime.Now.AddMinutes(1)}};

    { var d=new Dispatcher();
      var lots=new[]{new WipLot{Id="A",Op="E",Ppid="X",DueInHours=24,Arrive=DateTime.Now},
                      new WipLot{Id="B",Op="E",Ppid="Y",DueInHours=24,Arrive=DateTime.Now.AddMinutes(-10)}};

      Assert.NotNull(d.ValidateMove(lot,E("E","Cmp"),"Cmp",true)); }
}
```

## 三、派工到 Move（手绘参考）
```
Scheduling(班/日排程,交期产能) ──▶ Dispatch(设备空闲时实时选Lot)
 硬约束先过滤: 能力capable + 资格qualified + E10可用 + 配方就绪(W33) + 资源 + Lot未Hold
 软规则打分: 交期EDD/优先级 + 换型最小(同PPID) + 瓶颈TOC + FIFO + 就近AMHS + 批凑批(数量/等待双阈值)
   ▼ 选中Lot
预约设备/腔 → AMHS搬Carrier到Loadport(E84握手) → E87 Load绑定Lot → E90校验SlotMap
   → 建E40 PJ/E94 CJ入作业队列Queued → 空闲Received→Started加工
   ▼ 完工
Move过账防错: 路线顺序(防跳站)+设备资格+Lot/Carrier一致(防串批)+完工且未Hold+唯一(防重复)
   → 过账下一工序更新WIP ; 异常分流: 返工rework/报废scrap/工程lot(单独统计,不污染良率OEE)
改派/取消: 同步撤搬运/卸载/作业队列, 保证预约·实物·队列三一致
```

## 四、今日易错点
1. 混淆排程（长期）与派工（实时）。
2. 派工不做硬约束过滤，给无资格/Down/配方未就绪设备派活。
3. 只按 FIFO，不考虑交期/换型/瓶颈/凑批。
4. 批处理只凑数量不设等待时限（无限等拖周期），或只看等待不看批量。
5. 预约、AMHS 实物位置、E40 作业队列三者不同步。
6. Move 不校验路线顺序/身份/完工，导致跳站、串批、重复加工。
7. 返工/工程片混入正常产品统计，污染良率/OEE/VM-SPC。
8. 改派/取消不同步设备作业队列，产生幽灵作业。
