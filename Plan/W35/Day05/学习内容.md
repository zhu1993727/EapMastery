# W35 · Day05（周五）三方状态对账：MES 账、EAP、设备实际的一致性与重连恢复

> 建议时长：100 分钟。断线、重启、丢事件、人工干预都会让 MES 以为的状态与设备实际不一致。今天讲三方状态模型（MES WIP 账 / EAP 作业视图 / 设备 FSM 实际）、对账（reconciliation）触发与流程、以谁为准、补偿与纠正、重连恢复（W22 的上位延伸）、幂等与防脑裂。代码实现 StateReconciler。

## 一、今日目标

5. 用 C# 实现 StateReconciler；xUnit。

## 二、背景知识（先读，40 分钟）

### 1. 三方状态模型与权威范围
- 设备 FSM：物理世界真相的来源——片到底在不在、作业到底跑到哪（E40/E94/E87/E90/E10 状态）。
- EAP 作业视图：设备状态的实时映射与下发编排，是 MES 与设备之间的缓冲/翻译层（W35 Day03/04）。
- MES WIP 账：制造业务账——Lot 在哪个工序、是否开工/完工、数量与质量结果。
- 权威原则：**物理/作业状态以设备实际为准**（设备真做了就是做了），业务决策（放行/Hold/报废/改路线）以 MES 规则为准；EAP 负责把二者对齐，不能凭空替任何一方改业务结论。

### 2. 对账触发时机
- 通信重连后（HSMS 重选、EAP/MES 服务重启）——必做（W22 重连对账链的上位延伸）。
- 周期性心跳对账（防静默漂移）。
- 关键边界前后（开工、完工、Move、换 Carrier）。
- 人工本地面板操作后（操作员在设备上手动动作，MES 不知道）。
- 收到异常/矛盾事件（如 MES 说在加工、设备报无作业）。

### 3. 对账流程（自底向上）
1. 取设备真相：当前控制/通信状态、E87 Loadport 与 Carrier、E90 SlotMap、E40/E94 作业队列与各 Job 状态、当前 PPID、E10 状态、报警/Hold。
2. 校正 EAP 视图：与缓存比对，补齐/修正作业进度、清除幽灵作业、标记本地手动变更。
3. 与 MES 账比对：逐 Lot/Job 找差异（开工未记账、完工未过账、账在加工实际已停等）。
4. 补偿：按规则生成补偿事务（补开工/补完工、撤幽灵派工、上 Hold、回退错误过账），幂等提交 MES；无法自动判定的差异升级人工并冻结相关 Lot（不猜）。

### 4. 典型不一致与纠正
- MES 以为加工中、设备已完工且丢了完工事件→补聚合完工回告（用 EDC 数据/作业终态佐证）再过账。
- MES 以为加工中、设备已 Abort/Hold→补异常状态、Lot 置 Hold 待处理，不自动续做。
- 设备有作业但 MES 无派工（本地手动/幽灵）→识别为未授权作业，Hold 并核查，不默默补派工。
- MES 已过账但设备实际未全片完成→冲销/纠正过账（账不能领先于物理事实）。
- 重复完工/过账→幂等去重（Day04）。

### 5. 防脑裂与人工干预
- 脑裂：通信中断期间设备继续加工、MES/EAP 无法观测，恢复前不要基于过期状态下发新指令（避免双份指令/重复开工）；先对账再决策。
- 人工在设备本地操作必须被对账发现并记录（本地/Remote、手动选配方、手动取放片），评估是否偏离工单，必要时质量冻结。
- 对账结果全程留痕（差异、依据、补偿动作、操作/自动），供审计与谱系。

### 6. 与前序衔接
- 设备侧重连对账顺序沿用 W22（HSMS→E87→E90→E40/E94→Spool）；今天是在其之上加"与 MES WIP 账对齐"这一层；EDC（W34）为对账提供过程数据/时间线佐证，RMS（W33）提供配方版本真相。
