# W35 · Day05 答案与参考实现

## 一、自测题标准答案
1. **三方/权威**：设备 FSM 是物理世界真相来源——片在不在、Carrier 装载、E40/E94 作业跑到哪、当前 PPID、E10/报警/Hold 状态都以设备实际为准；EAP 作业视图是设备状态的实时映射加下发编排，是 MES 与设备之间的翻译/缓冲层；MES WIP 账是业务账——Lot 在哪道工序、开工/完工、数量与质量结果、是否放行。权威分工：物理与作业状态以设备 FSM 为准（真做了就是做了，业务账不能领先或违背物理事实），业务决策（放行、Hold、报废、改路线、返工）以 MES 质量/业务规则为准；EAP 负责发现并对齐二者差异，不凭空替设备改事实、也不替 MES 下业务结论。
2. **对账触发**：①通信重连后（HSMS 重选成功、EAP 或 MES 服务重启）必做；②周期性心跳对账，防静默漂移；③关键边界前后（开工、完工、Move、Carrier 装载/卸载）；④人工在设备本地面板操作之后（手动选配方/取放片/启停，上位不知情）；⑤收到矛盾事件（MES 说在加工、设备报无作业，或事件顺序冲突）；⑥异常终态（Abort/Fail/异常断连恢复）。原则是"任何可能让三方各自演进的节点之后都要重新对齐"。
3. **自底向上四步**：①取设备真相——读取通信/控制状态、E87 Loadport/Carrier、E90 SlotMap、E40/E94 作业队列与各 Job 状态、当前 PPID 版本、E10 与报警/Hold（顺序沿用 W22：HSMS→E87→E90→E40/E94→Spool）；②校正 EAP 视图——与自身缓存比对，补全/修正作业进度、清除幽灵作业、标记本地手动变更；③与 MES 账逐 Lot/Job 比对找差异（开工未记账、完工未过账、账在加工实际已停、账实数量不符）；④补偿——按规则生成幂等补偿事务（补开工/补完工、撤幽灵派工、置 Hold、冲正错误过账）提交 MES，无法自动判定的差异冻结相关 Lot 并升级人工，绝不猜测性改账。
4. **在加工实际已完工/丢完工**：不能直接信 MES 的"加工中"，也不能凭单事件改。先从设备取真相确认作业确已到 Completed 终态、预期片全部终态（Day04 完工判定），再用 EDC 过程数据时间线/Spool 补报佐证确有完整加工，然后由 EAP 补做事件聚合、生成幂等"补完工"事务回 MES（带数据引用与质量状态），MES 据此完成过账；若发现片有失败/OOS 则按部分成功/质量 Hold 处理。关键是用设备终态+过程数据双重佐证后补偿，而不是简单把账改成完成。
5. **未派工的本地作业/不默默补**：设备上存在 MES 无派工记录的作业，意味着操作员本地手动加工、未授权配方或状态错乱，属于"未授权作业"。正确处理是立即识别、Hold 相关 Lot/设备、保留现场与证据（谁、何时、用什么 PPID、加工了哪些片）、核查这些片属于哪个 Lot、是否符合工艺，再按质量规则决定放行/返工/报废并补记合规记录。不能默默"补一张派工单"让账实看起来一致，因为那会把一次可能的串批/跑错配方/违规操作洗白成正常生产，掩盖质量与合规事故，谱系也会造假。
6. **脑裂/先对账**：脑裂指通信中断期间设备仍在本地继续加工，而 MES/EAP 因收不到事件停留在旧状态，两侧各自演进、对当前世界认知分裂。此时若上位基于过期状态下发新指令（重复 Start、再建 Job、改派），恢复后就会出现重复加工、双份作业、抢占腔/片等严重问题。因此重连后必须先完成自底向上对账、把三方状态对齐到设备真相、清理/补偿完差异，再允许下发新的控制指令；对账完成前对该设备/相关 Lot 的下行控制应处于保守冻结态（只读观测、不新增指令）。
7. **账领先物理事实**：MES 已过账（记为工序完工/已流到下工序）但设备实际没把预期片全部做完，属于业务账领先物理事实，必须冲正（reverse/correct）该过账：把 Lot WIP 退回到实际所处工序与状态，按设备真实进度重建作业视图，查明为何提前过账（误判完工/事件错乱/重复），未完成片继续加工或按异常处置后，待真正满足完工判定（Day04）再重新过账。绝不允许"账已走完、片还在设备上"，否则后续工序会对未完工片操作、谱系与数量全错。

## 二、参考实现（net8.0）：三方状态对账器

```csharp
namespace EapLab.Mes.Recon;
public enum Fact{ Idle,Processing,Completed,Aborted,Unauthorized }
public sealed record DeviceView(Fact Fact,bool LocalManual,List<string> TerminatedSlots);
public sealed record MesView(string State); // Processing/Completed/Queued
public sealed record Diff(string Kind,string Action,bool NeedHuman);
public sealed class StateReconciler
{
    public List<Diff> Reconcile(string lot,DeviceView dev,MesView mes)
    { var d=new List<Diff>();
        if(dev.Fact==Fact.Unauthorized||dev.LocalManual)
        { d.Add(new("unauthorized-job","HOLD lot/eq + investigate, NEVER auto-create dispatch",true));return d; }
        switch(dev.Fact,mes.State)
        { case (Fact.Completed,"Processing"): // 丢完工: 终态+片佐证后补完工
              d.Add(new("missing-completion","emit idempotent completion(verify slots+EDC) then move",false));break;
          case (Fact.Aborted,"Processing"):
              d.Add(new("aborted-not-known","report abort + HOLD lot pending disposition",true));break;
          case (Fact.Processing,"Completed"): // 账领先物理: 冲正过账
              d.Add(new("premium-move","reverse move, roll WIP back to actual op",false));break;
          case (Fact.Idle,"Processing"):
              d.Add(new("ghost-processing","clear EAP view, check missing events",true));break;
          default: break; }
        return d; }
    bool _downlinkAllowed;
    public bool MaySendDownlink(bool reconDone){_downlinkAllowed=reconDone;return reconDone;} // 未对账禁下行
}
```

public class ReconTests
{ readonly StateReconciler _r=new();
    [Fact] public void 设备已完成_MES以为加工_补完工()

    { Assert.False(_r.MaySendDownlink(false));Assert.True(_r.MaySendDownlink(true)); }
}

## 三、对账时序（手绘参考）
```
触发: 重连/重启, 周期心跳, 开完工/Move/装卸边界, 本地手动后, 矛盾事件, 异常终态
  │ 自底向上
  ├─1 取设备真相: HSMS→E87 Carrier→E90 SlotMap→E40/E94作业队列/状态→当前PPID(W33)→E10/Alarm/Hold (EDC时间线佐证)
  ├─2 校正EAP视图: 补进度/清幽灵作业/标记本地手动
  ├─3 与MES WIP账逐Lot/Job比对差异
  └─4 幂等补偿: 补开工/补完工 / 撤幽灵派工 / 置Hold / 冲正提前过账 ; 判不准→冻结+升级人工(不猜)
权威: 物理作业状态以设备FSM为准 ; 业务放行/Hold/报废以MES规则为准 ; EAP只对齐不替决
典型: 丢完工→终态+EDC佐证补完工 ; 未授权本地作业→Hold核查绝不补派工洗白 ; 账领先→冲正 ; Abort→Hold
防脑裂: 断连期设备继续跑, 重连先对账对齐, 对账完成前冻结下行(不重复Start/建Job), 全程留痕可审计
```

## 四、今日易错点
1. 以 MES 账为准反推设备（物理状态必须以设备 FSM 为准）。
2. 重连后不先对账就直接下发，脑裂期重复开工。
3. 丢完工只改状态，不用设备终态+EDC 过程数据佐证。
4. 对本地未授权作业默默补派工，洗白违规/串批。
5. 账领先物理事实不冲正，导致未完工片流入下工序。
6. 设备 Abort 却自动续做（应 Hold 待处置）。
7. 幽灵作业不清、EAP 视图长期与设备漂移。
8. 补偿事务不幂等，对账重跑造成重复过账；差异处理不留痕、不可审计。
