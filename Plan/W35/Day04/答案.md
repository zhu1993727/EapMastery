# W35 · Day04 答案与参考实现

## 一、自测题标准答案
1. **聚合层次/不逐 Step 上报**：自底向上为 Step 事件/单片进出腔/EDA trace（最细）→Wafer 单片完成→E40 Process Job 完成→E94 Control Job 完成→整个 Lot 在本工序加工完成。EAP 用 Lot/Wafer/Job/Step/腔谱系键把同一作业的细粒度事件归并、累计进度（已完成片数/总片数、当前 Step/片），只在片完成、作业完成、工序完工等关键边界向 MES 发制造事务。不逐 Step 上报，是因为 Step/trace 量极大且是设备内部细节，MES 只关心制造对象（Lot/片/工序）的状态与结果；逐 Step 上报会淹没 MES、制造大量无业务意义流量，细粒度过程数据应由 EDA→EDC 承载（W34），需要时按引用查询，做到"过程数据在 EDC、制造事务进 MES"。
2. **完工判定**：以派工时确定、并经 E90 SlotMap 核实的"预期片清单"为基准，逐片跟踪终态（Processed 成功/Failed/Skipped/Aborted）。只有所有预期片都到达明确终态，且 PJ/CJ 状态机走到 Completed 终态（E40/E94，W16-23），才判作业/工序完工。不能只凭一个"完成事件"就算完，因为单个事件可能丢失、重复、只代表某个腔/某个 PJ 完成而非整作业，或设备在还有片未加工时异常退出；以预期片清单逐片销账 + 作业终态双条件，才能防止"事件说完成但实际漏片"。
3. **部分成功回告/处置**：逐片给出结果——N 片 Processed、M 片 Failed/Skipped/Aborted，标明失败片的 slot、所在腔、失败阶段、FDC/Alarm 原因与过程数据引用，批级汇总合格率与异常清单，绝不用一个"整体完成"掩盖个别废片。处置上：成功片可继续流转，失败片按质量规则 Hold，走返工（rework 专门路线）或报废（scrap），并在 MES 记录（Day02）；只有全部预期片都有明确终态与处置，作业才闭环，Lot 是否过账/部分过账由 MES 质量规则决定，EAP 如实回告不擅自放行。
4. **片级/批级结果/质量门**：片级含单片状态、加工时长、所在腔、recipe 与 overlay 版本、过程数据在 EDC 的引用（指纹/时间区间）、量测结果（inline/VM）、合格判定；批级含合格率/良率、FDC 报警与处置记录、R2R 调整记录、SPC 判定、异常清单。质量门：存在未清除的关键 FDC 报警/Hold、关键量测 OOS（超规格）、数据质量失明（W34 长期 Bad）时，完工事务必须带相应质量状态（Hold/待检/可疑），MES 据此决定放行、Hold 待检还是返工——EAP/设备负责如实回告与执行 Hold，放行决策由质量规则/MES 做出（决策≠执行，谁设谁解）。
5. **Move 做什么/触发下游**：完工过账把 Lot 从当前工序移动到下一工序（或待检/入库），更新 WIP 账（位置、状态、数量），写入工序历史与完整谱系（设备、腔、起止时间、recipe/overlay 版本、自动/手动、操作与结果）；同时扣减物料/资源消耗（气体/靶材/光阻、工时，供成本与库存，E116/E10）。触发下游：量测站/抽检或 SPC、AMHS 经 E84 把 Carrier 搬往下一工序、EDC/YMS 关联过程量测与良率、派工系统刷新该设备的下一个候选 Lot（Day02）。
6. **放引用/时序**：高频 trace 体量巨大且属过程数据，应存 EDC（热温冷分层，W34 Day05），MES 回告只放"数据引用/批次指纹"（Lot/Wafer/Job/时间区间/采集计划版本/数据可用状态），需要细节时按引用查 EDC，避免把海量波形塞进制造事务、拖慢过账并造成冗余。时序上遵循"加工完工→过程与量测数据在 EDC 就绪并完成质量判定→再过账 Move"，即先确认数据齐备（含必要量测/VM、质量门结论）再过账，防止先过账后才发现 OOS/数据缺失导致账已流走、难以追回；必要时设"完工待检"中间态，数据/判定齐了再放行过账。
7. **不重不漏**：不重——事件/事务带唯一 Job/Wafer/事务 ID，消费端去重，重发幂等（同一完工事务重复到达只生效一次，W31/W35 Day03 同思想）；不漏——以预期片清单逐片销账、作业终态双条件判完工，断线期间事件靠 Spool/EDC 补报（第一阶段 Spool 只补上报类、W22 重连对账），重连后按作业状态对账补齐缺失回告；顺序——按 Lot/Job/片有序归并，乱序迟到事件用缓冲/状态机校正（W34 Day03）；并在 EAP 侧维护作业进度表作为权威聚合状态，保证 MES 最终收到且只收到一次完整、与现场一致的完工回告。

## 二、参考实现（net8.0）：事件聚合与完工报告

```csharp
namespace EapLab.Mes.Report;
public enum Wf{ Pending,Processed,Failed,Skipped }
public sealed class WaferOutcome{public int Slot;public Wf State;public string? DataRef;public bool InSpec;}
public sealed class JobProgress
{ public int Expected;public List<WaferOutcome> Rows{get;}=new();
    public void Add(WaferOutcome o){if(Rows.Any(x=>x.Slot==o.Slot))return;Rows.Add(o);} // 幂等去重
    public bool AllTerminal=>Rows.Count==Expected&&Rows.All(r=>r.State!=Wf.Pending);
    public int Ok=>Rows.Count(r=>r.State==Wf.Processed&&r.InSpec); }
public sealed record CompletionReport(string LotId,string JobId,int OkCount,int BadCount,bool AllDone,bool QualityHold,string? DataRef);
public sealed class EventAggregator
{
    public CompletionReport? Complete(string lot,string job,JobProgress p,bool criticalAlarmOrOos)
    { if(!p.AllTerminal)return null; // 预期片未全部终态 → 不算完工
        int bad=p.Rows.Count(r=>!r.InSpec||r.State==Wf.Failed);
        var refKey=$"edc://{lot}/{job}";
        return new CompletionReport(lot,job,p.Ok,bad,AllDone:true,QualityHold:criticalAlarmOros(criticalAlarmOrOos),refKey); }
    static bool criticalAlarmOros(bool x)=>x;
    // 过账前置: 数据齐备且质量判定完成
    public bool CanMove(CompletionReport? r,bool dataReady,bool qualityDecided)
    =>r is{AllDone:true}&&dataReady&&qualityDecided;
}
```

### xUnit
```csharp
public class AggregatorTests
{ static JobProgress Prog(int n){var p=new JobProgress{Expected=n};return p;}
    [Fact] public void 预期片未全终态_不完工()
    { var p=Prog(3);p.Add(new(){Slot=1,State=Wf.Processed,InSpec=true});
      Assert.Null(new EventAggregator().Complete("L","J",p,false)); }
    [Fact] public void 全部终态才完工_部分废片如实统计()
    { var p=Prog(3);p.Add(new(){Slot=1,State=Wf.Processed,InSpec=true});
      p.Add(new(){Slot=2,State=Wf.Processed,InSpec=false});
      p.Add(new(){Slot=3,State=Wf.Failed,InSpec=false});
      var r=new EventAggregator().Complete("L","J",p,false)!;
      Assert.True(r.AllDone);Assert.Equal(1,r.OkCount);Assert.Equal(2,r.BadCount); }
    [Fact] public void 重复片事件去重()
    { var p=Prog(2);p.Add(new(){Slot=1,State=Wf.Processed,InSpec=true});
      p.Add(new(){Slot=1,State=Wf.Processed,InSpec=true});Assert.Single(p.Rows); }
    [Fact] public void 关键报警OOS_完工带质量Hold()
    { var p=Prog(1);p.Add(new(){Slot=1,State=Wf.Processed,InSpec=true});
      Assert.True(new EventAggregator().Complete("L","J",p,true)!.QualityHold); }
    [Fact] public void 数据未齐不允许过账()
    { var p=Prog(1);p.Add(new(){Slot=1,State=Wf.Processed,InSpec=true});
      var r=new EventAggregator().Complete("L","J",p,false);
      Assert.False(new EventAggregator().CanMove(r,dataReady:false,qualityDecided:true));
      Assert.True(new EventAggregator().CanMove(r,dataReady:true,qualityDecided:true)); }
}
```

## 三、细事件到 Move（手绘参考）
```
设备: Step事件/单片进出腔/EDA trace ──归并(键:Lot/Wafer/Job/Step/腔)──▶ Wafer完成
   → E40 PJ终态 → E94 CJ终态 → Lot本工序
完工判定= 预期片清单(E90核实)逐片销账(Processed/Failed/Skipped) + 作业终态, 双条件; 单"完成事件"不足
结果: 片级(状态/腔/时长/recipe+overlay版本/EDC引用/量测/InSpec) + 批级(合格率/FDC/R2R/SPC/异常)
   关键报警未清/OOS/数据失明 → 完工带质量Hold(决策在质量规则/MES, EAP如实回告, 谁设谁解)
时序: 加工完工 → 过程+量测在EDC就绪+质量判定 → 才允许Move过账(否则停"完工待检")
Move: 更新WIP+写工序历史/谱系 + 扣消耗(E116/E10) → 触发量测/SPC/AMHS(E84)下工序/刷新派工
不重不漏: 唯一事务ID幂等去重 + 预期片销账 + Spool/重连对账补报 + 乱序缓冲 ; MES收且只收一次一致回告
原则: 海量trace留EDC, MES只收制造事务+数据引用(指纹/区间/版本/可用状态)
```

## 四、今日易错点
1. 把每个 Step/trace 事件都上报 MES（应聚合，细数据留 EDC）。
2. 只收到一个完成事件就判完工，漏片未发现。
3. 不按预期片清单逐片销账、不区分部分成功。
4. 用"整体完成"掩盖个别废片。
5. 关键报警/OOS/数据失明仍直接放行、不带质量 Hold。
6. 先过账后发现 OOS/数据缺失，账已流走难追回。
7. MES 事务里塞海量 trace 而非 EDC 数据引用。
8. 回告不去重/不补报，断线后 MES 缺完工或重复过账。
