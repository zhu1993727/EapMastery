# W35 · Day03 答案与参考实现

## 一、自测题标准答案
1. **下行时序（默写）**：①MES 派工——指定 Lot、目标工序、PPID/版本、片槽范围、优先级；②物料到位与身份校验——E84 上料握手、E87 Load 绑定 Carrier↔Lot（Installed→Loaded）、E90 SlotMap 与 MES 期望逐片核对；③配方就绪——RMS 确认设备上该 PPID/版本存在且 hash 一致，不一致先 S7 分发并回读校验（W33）；④建作业——EAP 经 S2F41 远程命令按 E40 创建 Process Job（槽/PPID/腔/顺序正交），按 E94 建 Control Job 组织调度（W16-23）；⑤PP-Select——在安全点远程选配方并回读当前 PPID/版本一致；⑥Start——五门全过后启动 CJ/PJ，设备迁移 Started/Executing 并发 S6F11 事件，EAP 回告 MES 已开工。
2. **五类门控/复用标准**：通信门——HSMS SELECTED、设备在线且 Remote（W02/W05）；物料门——E87 Loaded、E90 SlotMap 三不变式与 MES 期望一致、无错片缺片（W12-15）；配方门——PPID/版本合工单、设备副本 hash 一致、PP-Select 回读一致（W33）；作业门——E40 PJ 三正交合法、E94 CJ 栅栏/顺序/幂等正确（W16-23）；状态门——E10 可生产、非 Hold/Down、处于非加工安全点、无未解除联锁（W25）。任一不过即停、不进入下一步并返回原因，已建部分回滚。
3. **受理≠生效/怎样算生效**：S2F42/远程命令 ACKC10=0、S7F4=0、E40 命令 ACK 只表示设备"收到、格式合法、愿意受理"，是传输/语法层确认，此刻作业可能还没建、配方还没选、设备还没动。真正生效必须等设备状态机实际迁移到目标状态，并由设备主动发出对应 S6F11 事件（JobSelected/JobStarted/StepStarted）且回读当前状态/PPID 与指令一致——以"迁移后事件+回读一致"为生效判据（W05/W22/W31 一致口径）。把受理当生效会在设备拒绝/延迟时误以为已开工，造成 MES 账与现场脱节。
4. **事务/幂等/回滚**：一次派工开工跨多条消息，必须具备事务性——要么完整走到开工，要么干净回到未开始/可重试态，不留"建了一半的 Job、占着预约却没加工"的脏状态。幂等指每条命令带唯一 ReqId/JobId，网络重发同一指令时设备/EAP 识别为重复请求，返回原结果而不重复建 PJ/CJ、不叠加 overlay（W31）。Start 失败回滚：取消已建 PJ/CJ、释放设备/腔预约、必要时卸载或复位、回告 MES"派工未执行+原因"，且配方下发/选择失败时绝不能用设备本地旧版或近似配方将就开工（否则跑错工艺）。
5. **回告四层**：受理层——命令 ACK（收到/格式合法）；生效层——状态迁移 S6F11 + 回读一致（真正开工/选中/完成）；进度层——CJ/PJ 状态、当前片/Step、加工进度、消耗与 E10/E116 过程数据实时上行；完工层——JobCompleted、片级结果、触发量测，EAP 聚合成 Lot/工序完工事务回 MES（Day04）；异常层——Hold/Alarm/Abort/Failed 即时上行，MES 据此冻结 WIP、暂停派工（谁设谁解、设备 FSM 是执行方）。四层逐级从"收到"到"做成"，MES 只应依据生效层及以后更新制造账。
6. **不符处理/不将就**：上料片与 MES 期望不符（Carrier↔Lot 绑定错、SlotMap 缺片/错片/位置不符）→拒绝建作业/开工，保持安全态、上报告警并核对实物，因为继续会串批、片级张冠李戴、谱系全错，是严重质量事故；配方版本不符（设备 PPID 版本≠工单/RMS golden 版本、hash 不一致）→先走 RMS 受控分发并回读一致，分发/选择失败则不得开工。不能"将就加工"，因为半导体工艺对配方极敏感，用错版本或错片会直接产出废片且污染数据，事后难追溯，宁可停机核对也不带病生产。
7. **屏蔽设备差异**：不同机台厂商/型号的 SECS 实现、消息细节、状态命名差异很大，MES 是面向制造对象（Lot/工序/WIP）的业务系统，不应也无法为每种设备写协议逻辑。EAP 处在中间，把异构设备的 SECS/GEM/EDA/E87/E90/E40/E94 细节封装起来，对上（MES）呈现稳定的制造语义——"派工、开工、进度、完工、Hold、异常"，对下翻译为具体设备时序。这样 MES 与设备解耦、可独立演进，新增机台只改 EAP 适配层；若让 MES 面对裸报文，业务系统会被设备协议细节淹没且极难维护。

## 二、参考实现（net8.0）：下发编排状态机

```csharp
namespace EapLab.Mes.Flow;
public enum Flow{ Idle,MaterialChecked,RecipeReady,JobBuilt,Selected,Started,Failed,RolledBack }
public enum Gate{ Comm,Material,Recipe,Job,State }
public sealed class DispatchFlow
{
    public Flow S{get;private set;}=Flow.Idle;public List<string> Events{get;}=new();
    readonly HashSet<string> _seenReq=new();
    bool Gate(Dictionary<Gate,bool> g,Gate k)
    { if(g.TryGetValue(k,out bool ok)&&ok)return true;S=Flow.Failed;Events.Add($"gate-fail:{k}");return false; }
    // 返回是否开工; reqId 幂等: 重复请求不重复建作业
    public bool Start(string reqId,Dictionary<Gate,bool> gates,Action? rollbackBuilt=null)
    { if(_seenReq.Contains(reqId)){Events.Add("duplicate-ignored");return S==Flow.Started;}
        _seenReq.Add(reqId);
        if(!Gate(gates,Gate.Comm))return Rollback(rollbackBuilt);
        if(!Gate(gates,Gate.Material))return Rollback(rollbackBuilt);
        if(!Gate(gates,Gate.Recipe))return Rollback(rollbackBuilt);
        S=Flow.RecipeReady;Events.Add("recipe-ready");
        if(!Gate(gates,Gate.Job))return Rollback(rollbackBuilt);
        S=Flow.JobBuilt;Events.Add("pj-cj-built");
        S=Flow.Selected;Events.Add("pp-selected(readback ok)");
        if(!Gate(gates,Gate.State))return Rollback(rollbackBuilt);
        S=Flow.Started;Events.Add("S6F11 JobStarted=effective");return true;
    }
    bool Rollback(Action? rb){rb?.Invoke();S=Flow.RolledBack;Events.Add("rolled-back");return false;}
    // 受理≠生效: ACK 只是受理
    public static bool AcceptedOnly(int ackc10)=>ackc10==0;
}
```

### xUnit
```csharp
public class FlowTests
{ static Dictionary<Gate,bool> AllOk()=>new()
    {{Gate.Comm,true},{Gate.Material,true},{Gate.Recipe,true},{Gate.Job,true},{Gate.State,true}};
    [Fact] public void 五门全过才开工_以事件为生效()
    { var f=new DispatchFlow();Assert.True(f.Start("R1",AllOk()));Assert.Equal(Flow.Started,f.S);
      Assert.Contains(f.Events,e=>e.Contains("JobStarted")); }
    [Fact] public void 物料门失败_不建作业并回滚()
    { var g=AllOk();g[Gate.Material]=false;bool rolled=false;
      var f=new DispatchFlow();Assert.False(f.Start("R1",g,()=>rolled=true));
      Assert.Equal(Flow.RolledBack,f.S);Assert.True(rolled); }
    [Fact] public void 配方门失败_不将就加工()
    { var g=AllOk();g[Gate.Recipe]=false;var f=new DispatchFlow();
      Assert.False(f.Start("R1",g));Assert.NotEqual(Flow.Started,f.S); }
    [Fact] public void 幂等_重发同ReqId不重复建()
    { var f=new DispatchFlow();f.Start("R1",AllOk());f.Start("R1",AllOk());
      Assert.Equal(1,f.Events.Count(e=>e=="pj-cj-built"));Assert.Contains(f.Events,e=>e=="duplicate-ignored"); }
    [Fact] public void ACKC10为0仅是受理()
    { Assert.True(DispatchFlow.AcceptedOnly(0)); }
}
```

## 三、下行时序（手绘参考）
```
MES 派工(Lot/工序/PPID版本/槽/优先级)
  │ EAP编排
  ├─[通信门] HSMS SELECTED + Remote
  ├─[物料门] E84上料→E87 Load绑定Carrier↔Lot→E90 SlotMap对MES期望(三不变式)
  ├─[配方门] RMS: PPID/版本存在+hash一致(否则S7分发回读) → PP-Select回读一致
  ├─[作业门] S2F41建 E40 PJ(槽/腔/recipe正交)+E94 CJ(栅栏/顺序)
  ├─[状态门] E10可生产/非Hold/安全点/无联锁
  └─ Start → 设备迁移Started/Executing
回告: 受理(ACKC10=0仅收到) → 生效(S6F11 JobStarted+回读一致) → 进度(CJ/PJ/片Step/E10/E116)
      → 完工(JobCompleted/片结果→Lot工序完工回MES) ; 异常(Hold/Alarm/Abort即时上行,谁设谁解)
事务: 任一门失败→停+回滚已建作业/释放预约+回告原因 ; ReqId幂等重发不叠加 ; 版本/片不符绝不将就
EAP对上呈现制造语义(派工/开工/完工/异常), 对下翻译异构SECS时序, MES只见稳定语义不见裸报文
```

## 四、今日易错点
1. 把 ACKC10=0/S7F4=0 当成已生效（只是受理，生效看迁移事件+回读）。
2. 跳门控直接 Start（物料/配方/作业/状态门缺一不可）。
3. 配方版本不符用本地旧版将就加工。
4. 上料片与 MES 期望不符仍开工，导致串批。
5. 跨消息下发无事务性，留下半截 Job 和占用预约。
6. 重发命令无 ReqId 幂等，重复建作业/叠加。
7. Start 失败不回滚作业与预约，也不回告 MES。
8. 让 MES 直接处理裸 SECS 报文，业务系统与设备协议强耦合。
