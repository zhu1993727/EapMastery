## 二、综合实验（50 分钟）

### 实验场景：多类型多实例对象管理
搭建一个模拟设备，注册 3 种对象类型：
- **ProcessJob**：属性 ProcessState(U1,只读)、LotID(A,读写,必填)、WaferCount(U2,只读,默认0)、Priority(U1,读写,默认5)；方法 Start/Abort；事件 Started(4101)/Completed(4102)/Aborted(4103)。
- **Carrier**：属性 CarrierState(U1,只读)、CarrierID(A,读写,必填)、SlotCount(U1,只读,默认25)；方法 Load/Unload；事件 Loaded(4201)/Unloaded(4202)。
- **Chamber**：属性 ChamberState(U1,只读)、Temp(F4,只读)、Pressure(F4,只读)；无方法；事件 StateChanged(4301)。

### 实验步骤（每步记录请求/响应 Item 树）
```
1. 设备启动：ObjectRegistry 注册 3 个类型（含属性/方法/事件定义）
2. S14F1 → S14F2：查询类型列表，应返回 3 个类型
3. S14F3(ProcessJob) → S14F4：查询属性，应返回 4 个属性
4. S14F5(ProcessJob) → S14F6：查询方法，应返回 Start/Abort 及允许状态
5. S14F7(ProcessJob) → S14F8：查询事件，应返回 4101/4102/4103
6. S15F1 创建 ProcessJob:PJ001（LotID=LOT_A, Priority=3）
7. S15F1 创建 ProcessJob:PJ002（LotID=LOT_B）
8. S15F1 创建 Carrier:CAR01（CarrierID=FOUP01, SlotCount=25）
9. S15F11 批量存在性查询 [PJ001, PJ002, PJ999] → 前两个 true，PJ999 false
10. S15F5 查询 PJ001 全部属性 → 验证默认值（WaferCount=0, Priority=3）
11. S15F7 设置 PJ001.Priority=1（整批原子）
12. S15F7 尝试设置 PJ001.ProcessState=3（只读）→ ACKC=5，且 Priority 不受影响
13. S15F9 对 PJ001 调 Start → S15F10 ACKC=0；状态转 EXECUTING；收到 S16F1(4101 Started)
14. S15F9 对执行中的 PJ001 再调 Start → ACKC=8（状态非法）
15. S15F3 尝试删除执行中的 PJ001 → ACKC=8
16. S15F9 对 PJ001 调 Abort → 状态转 ABORTED；收到 S16F1(4103 Aborted)
17. S15F3 删除 PJ001（终态允许）→ ACKC=0；验证事件订阅已取消
18. S15F5 查询已删除的 PJ001 → ACKC=2（实例不存在）
19. 对 PJ002 走 Start→Completed 正常流程，收到 4101/4102
20. 清理：删除 PJ002、CAR01；验证 InstanceStore 清空、无残留订阅（内存泄漏检查）
```

### 2. 关键预告：对象树（先建立印象）
真实 GEM300 中对象不是平铺的，而是一棵树：
```
ControlJob:CJ001
  ├─ ProcessJob:PJ001
  │    ├─ Substrate:W01 (Slot 1)
  │    └─ Substrate:W02 (Slot 2)
  └─ ProcessJob:PJ002
       └─ Substrate:W03
Carrier:CAR01
  └─ Substrate:W01..W25（槽位映射，E90 详解）
```
- 嵌套 OBJSPEC 用路径表达（如 "ControlJob:CJ001/ProcessJob:PJ001"），具体语法以 E39/E94 标准为准。
- 父对象状态会聚合子对象状态（如所有 PJ 完成，CJ 才完成）——这是 W20-W23 E94 的核心，W10 先搭框架。

### 3. 关键预告：事件订阅模型
- 不是所有对象事件 Host 都需要，S16 支持订阅过滤：按对象类型、对象实例、CEID 订阅。
- Host 订阅后设备才发（或设备全发、Host 过滤，两种策略 W10 对比）。
- 订阅信息在重连后需要重新建立（和 S2F35 事件关联一样，易失性）。
