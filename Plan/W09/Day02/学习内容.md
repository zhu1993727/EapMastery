## 二、背景知识（先读，20 分钟）

### 1. 类型定义 vs 实例数据（分清两层）
OSS 模型分两层，代码也要分两层：
- **元数据层（Type Layer，静态）**：ObjectType 及其 AttributeDefinition/MethodDefinition/EventDefinition，描述"这类对象长什么样"。设备启动时注册一次，运行期间基本不变，S14 查询的就是这一层。
- **实例层（Instance Layer，动态）**：ObjectInstance，描述"具体某个对象现在是什么状态"。运行期间动态创建/删除，S15 操作、S16 上报的是这一层。
- 类比 C#：元数据层 = Type 类（typeof(ProcessJob)）+ PropertyInfo/MethodInfo/EventInfo；实例层 = new 出来的对象。S14 = 反射查 Type，S15 = 操作实例。

### 2. 属性定义的关键要素
一个属性定义（AttributeDefinition）包含：
- ATTRID：属性 ID（字符串或数字，E39 常用字符串名，如 "ProcessState"；具体以标准为准）
- Name：属性名（可读名）
- DataType：SECS-II 数据类型（A/U1/U2/U4/I4/F4/F8/Boolean/B/List）
- AccessMode：访问模式——ReadOnly（只读，Host 只能查）、ReadWrite（可读写）、WriteOnly（少见）
- Required：创建对象时是否必须提供初始值
- DefaultValue：默认值
- 枚举值约束（如 ProcessState 只能取特定几个状态值）

### 3. 方法定义的关键要素
一个方法定义（MethodDefinition）包含：
- METHODID：方法 ID（如 "Start"、"Abort"）
- Name：方法名
- InputParameters：输入参数定义列表（参数名+类型+是否必填）
- OutputParameters：输出参数定义列表（返回值）
- RequiredState：允许调用的前置状态（如 Start 只允许在 READY/PAUSED 状态调用，EXECUTING 时调用非法）
- 执行委托：实际执行逻辑（设备端实现，Func<输入参数, 输出结果>）

### 4. 事件定义的关键要素
一个事件定义（EventDefinition）包含：
- CEID：事件 ID（数字，如 4101=ProcessJob Started）
- Name：事件名（如 "Started"）
- LinkedAttributes：事件触发时快照哪些属性值（类似 GEM 事件关联报告）
- 触发时机：对象状态转换到哪个状态时触发（如状态机转到 EXECUTING 时触发 Started 事件）

### 5. ObjectInstance 的设计
- OBJSPEC：唯一标识（"Type:ID"）
- TypeName：所属类型名
- Attributes：当前属性值字典（ATTRID → SecsItem 值）
- StateMachine：对象自己的状态机（如 ProcessJob 的状态机，W17/W21 会详细实现，今天先留接口）
- 方法：SetAttribute/GetAttribute/InvokeMethod/RaiseEvent
- 事件：OnEventRaised（事件触发时通知上层，上层发 S16F1）
- 线程安全：多线程访问（Host 操作线程 + 设备内部状态线程），用锁或 ConcurrentDictionary。

### 6. ObjectRegistry 的设计
- TypeRegistry：类型名 → ObjectType（设备启动时注册所有支持的类型）
- InstanceStore：OBJSPEC → ObjectInstance（运行期间动态增删）
- 方法：
  - RegisterType(ObjectType)：注册类型
  - CreateInstance(typeName, id, initialAttributes)：创建实例，校验类型存在、必填属性、ID 不重复，返回 OBJSPEC
  - DeleteInstance(objSpec)：删除实例
  - GetInstance(objSpec)：查找实例（不存在返回 null 或抛异常）
  - ListInstances(typeName?)：列出实例（可按类型过滤）
  - GetType(typeName)：查类型定义
  - ListTypes()：列出所有类型名（给 S14F1 用）
