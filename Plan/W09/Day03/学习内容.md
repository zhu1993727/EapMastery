## 二、背景知识（先读，30 分钟）

### 1. S14 在 OSS 中的位置
- S14 是**元数据查询**：查询的是 ObjectType（类型定义），不是 ObjectInstance（实例数据）。
- 即使设备当前一个对象实例都没有创建，Host 也能用 S14 查询"你支持哪些类型、每种类型长什么样"。
- 类比：C# 反射——`assembly.GetTypes()` 拿类型列表 ≈ S14F1；`type.GetProperties()` 拿属性 ≈ S14F3；`type.GetMethods()` 拿方法 ≈ S14F5；`type.GetEvents()` 拿事件 ≈ S14F7。
- S14 全部是 Host 发 primary（奇数 F）、设备回 reply（偶数 F），W=1。

### 2. S14F1/F2 GetObjTypes（对象类型列表查询）
- **S14F1（Host→设备）**：请求对象类型列表。
  - body 可以为空（查询全部类型），或带过滤条件（简化实现按空处理，查询全部）。
- **S14F2（设备→Host）**：返回对象类型列表。
  - body 结构（简化、教学用，字段顺序以 E39 标准原文为准）：
    ```
    L,2
      [0] U1 ACKC            // 0=成功，非0=失败
      [1] L,n                // 类型列表，n 个类型
            [i] L,3
                  [0] A ObjType    // 类型名，如 "ProcessJob"
                  [1] U1 AttrCount // 属性数量（便于 Host 预判）
                  [2] A Comment    // 类型说明（可空字符串）
    ```
  - 示例：设备支持 ProcessJob、ControlJob、Carrier 三种类型，返回 L,2[U1 0, L,3[ L,3[A"ProcessJob",U1 5,A"加工任务"], L,3[A"ControlJob",...], L,3[A"Carrier",...] ]]。

### 3. S14F3/F4 GetAttrs（指定类型的属性定义查询）
- **S14F3（Host→设备）**：指定类型名，请求其属性定义列表。
  - body：`L,1[A ObjType]`，如 L,1[A "ProcessJob"]。
  - 也可以带 ATTRID 列表只查指定属性（简化实现按查全部处理）。
- **S14F4（设备→Host）**：返回属性定义列表。
  - body 结构：
    ```
    L,2
      [0] U1 ACKC
      [1] L,n                        // n 个属性定义
            [i] L,5
                  [0] A AttrId       // 属性 ID，如 "ProcessState"
                  [1] U1 DataType    // SECS-II 类型码（如 U1/U2/A/F4...）
                  [2] U1 AccessMode  // 0=ReadOnly 1=ReadWrite 2=WriteOnly
                  [3] Boolean Required
                  [4] A AttrName     // 可读名/说明
    ```
  - 示例：ProcessJob 有 ProcessState(U1,只读)、LotID(A,读写,必填)、WaferCount(U2,只读) 三个属性。

### 4. S14F5/F6 GetMethods（指定类型的方法定义查询）
- **S14F5（Host→设备）**：`L,1[A ObjType]`。
- **S14F6（设备→Host）**：返回方法定义列表。
  - body 结构：
    ```
    L,2
      [0] U1 ACKC
      [1] L,n
            [i] L,4
                  [0] A MethodId      // 方法 ID，如 "Start"
                  [1] L,k             // 输入参数定义列表
                        [j] L,3
                              [0] A ParamName
                              [1] U1 DataType
                              [2] Boolean Required
                  [2] L,m             // 输出参数定义列表（结构同上）
                  [3] L,p [A State]   // 允许调用的前置状态列表 RequiredStates
    ```
  - 示例：ProcessJob.Start 方法，输入 Mode(U1,可选)，无输出，允许状态 QUEUED/PAUSED。

### 5. S14F7/F8 GetEvents（指定类型的事件定义查询）
- **S14F7（Host→设备）**：`L,1[A ObjType]`。
- **S14F8（设备→Host）**：返回事件定义列表。
  - body 结构：
    ```
    L,2
      [0] U1 ACKC
      [1] L,n
            [i] L,4
                  [0] U4 CEID         // 事件 ID，如 4101
                  [1] A EventName     // 事件名，如 "Started"
                  [2] L,q [A AttrId]  // 事件快照的属性列表
                  [3] A TriggerState  // 触发状态（可空）
    ```
  - 示例：ProcessJob.Started(CEID=4101)，快照 ProcessState/LotID，转到 EXECUTING 时触发。

### 6. Host 首次连接的类型发现流程（必背时序）
```
1. HSMS Select → S1F13 建链 → S1F17 在线（GEM 基础，W5）
2. S14F1（查类型列表）→ S14F2：得到 [ProcessJob, ControlJob, Carrier, Substrate...]
3. 对每个类型循环：
   3.1 S14F3(ProcessJob) → S14F4：得到属性定义
   3.2 S14F5(ProcessJob) → S14F6：得到方法定义
   3.3 S14F7(ProcessJob) → S14F8：得到事件定义
4. Host 在本地构建设备对象模型缓存（类型→属性/方法/事件字典）
5. 之后 S15 操作实例、S16 收事件时，用本地缓存解析 ATTRID/METHODID/CEID
6. （可选）订阅 S16 事件，或用 S15F1 创建对象实例
```
- 为什么要先发现再操作：S15/S16 消息里只有 ATTRID/METHODID/CEID，Host 必须知道它们的类型和语义才能正确编码/解析，这些信息来自 S14。
- 类型发现结果通常在 Host 端缓存（同一型号设备类型定义相同），不必每次连接都全量查询；但设备软件版本升级（SOFTREV 变化）后应重新发现。

### 7. 错误处理
- S14F2/F4/F6/F8 的 ACKC：0=成功；非 0 表示失败（如类型不存在、内部错误）。
- 查询不存在的类型：S14F4/F6/F8 回 ACKC 非 0 + 空列表，而不是崩溃。
- 属性/方法/事件列表为空是合法的（某些简单类型可能没有方法或事件）。
