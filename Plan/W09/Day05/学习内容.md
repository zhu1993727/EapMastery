## 二、背景知识（先读，30 分钟）

### 1. S15 总览：所有操作都围绕 OBJSPEC
| 消息对 | 操作 | 关键输入 | 返回 |
|---|---|---|---|
| S15F1/F2 | 创建对象 Create | ObjType + ID + 初始属性 | ACKC + OBJSPEC |
| S15F3/F4 | 删除对象 Delete | OBJSPEC | ACKC |
| S15F5/F6 | 查询属性 Get | OBJSPEC + ATTRID 列表 | ACKC + 属性值列表 |
| S15F7/F8 | 设置属性 Set | OBJSPEC + 属性值列表 | ACKC |
| S15F9/F10 | 调用方法 Invoke | OBJSPEC + METHODID + 输入参数 | ACKC + 输出参数 |
| S15F11/F12 | 存在性查询 Exist | OBJSPEC 列表 | 每个对象是否存在 |

### 2. S15F1/F2 创建对象
- **S15F1（Host→设备）body 结构（教学约定，字段顺序以 E39 原文为准）**：
  ```
  L,3
    [0] A ObjType            // 要创建的类型，如 "ProcessJob"
    [1] A ObjectID           // 实例 ID，如 "PJ001"（设备分配时可空）
    [2] L,n                  // 初始属性列表
          [i] L,2
                [0] A AttrId
                [1] <值>     // 按属性类型编码（LotID→A, WaferCount→U2）
  ```
- **S15F2（设备→Host）**：
  ```
  L,2
    [0] U1 ACKC              // 0=创建成功；非0=失败（类型不存在/缺必填/重复/类型错）
    [1] A OBJSPEC            // 成功时返回完整 "ProcessJob:PJ001"
  ```
- 创建时的校验（对照 Day02 CreateInstance）：类型存在→ID 不重复→必填属性齐全→属性都已定义→类型匹配→数量上限。

### 3. S15F3/F4 删除对象
- **S15F3**：`L,1[A OBJSPEC]`，如 L,1[A "ProcessJob:PJ001"]。
- **S15F4**：`L,1[U1 ACKC]`，0=删除成功；对象不存在回非 0。
- 删除语义：删除前通常要求对象处于可删除状态（如 COMPLETED/ABORTED 终态；EXECUTING 中的 Job 不允许直接删，必须先 Abort），这属于业务校验。

### 4. S15F5/F6 查询属性值
- **S15F5**：
  ```
  L,2
    [0] A OBJSPEC
    [1] L,n [A AttrId]       // 要查哪些属性；空列表表示查全部属性
  ```
- **S15F6**：
  ```
  L,2
    [0] U1 ACKC
    [1] L,n                  // 属性值列表，顺序与请求的 AttrId 一一对应
          [i] L,2
                [0] A AttrId
                [1] <值或空> // 属性值；属性不存在时该项带错误标记
  ```
- 关键：请求列表和返回列表**顺序对应**，Host 按下标匹配，不依赖返回里重复 AttrId（但教学实现保留 AttrId 便于调试）。

### 5. S15F7/F8 设置属性值
- **S15F7**：
  ```
  L,2
    [0] A OBJSPEC
    [1] L,n                  // 要设置的属性
          [i] L,2
                [0] A AttrId
                [1] <新值>
  ```
- **S15F8**：`L,1[U1 ACKC]`（或 L,2[ACKC, 每个属性的设置结果]，教学用整体 ACKC + 逐项结果）。
- 设置校验：对象存在→属性存在→AccessMode 允许写（ReadOnly 拒绝）→当前对象状态允许写（执行中锁定配置属性）→类型匹配。
- 部分成功策略：一批属性中某个非法，是整批拒绝（原子，推荐）还是跳过非法项设置其余（非原子），要在设备规范中明确。**专家建议整批原子**——要么全设置成功，要么全不变，避免对象处于半更新的不一致状态。

### 6. S15F9/F10 调用方法（重点：异步模型）
- **S15F9**：
  ```
  L,3
    [0] A OBJSPEC
    [1] A METHODID           // 如 "Start"
    [2] L,n                  // 输入参数
          [i] L,2
                [0] A ParamName
                [1] <值>
  ```
- **S15F10**：
  ```
  L,2
    [0] U1 ACKC              // 0=方法已接受（不是已执行完成！）
    [1] L,m                  // 即时输出参数（如无则 L,0）
  ```
- **异步模型（和 GEM S2F41 完全一致的思想）**：
  - ACKC=0 只表示"方法请求合法、已被接受排队/开始"，**不表示方法逻辑执行完成**。
  - 方法执行导致对象状态转换，转换触发 S16 事件（如 Start→EXECUTING→S16F1 Started；执行结束→COMPLETED→S16F1 Completed）。
  - Host 判断方法真正完成，靠 S16F1 事件，不靠 S15F10。
  - 错误状态调用（RequiredState 不满足）→ S15F10 ACKC 非 0，方法不执行、状态不变。

### 7. S15F11/F12 存在性查询（批量）
- **S15F11**：`L,n[A OBJSPEC]`（一次查多个对象）。
- **S15F12**：`L,n[L,2[A OBJSPEC, Boolean Exists]]`，逐个返回是否存在。
- 用途：Host 重连后批量确认自己缓存的对象实例在设备端是否还存在（状态同步），避免操作已被删除的对象。

### 8. S15 ACKC 错误码体系（教学项目统一）
| 值 | 含义 | 典型场景 |
|---|---|---|
| 0 | 成功 | 操作完成/接受 |
| 1 | 对象类型不存在 | S15F1 传了未注册类型 |
| 2 | 对象实例不存在 | 操作的 OBJSPEC 找不到 |
| 3 | 对象已存在 | 重复创建同 OBJSPEC |
| 4 | 属性不存在 | ATTRID 未定义 |
| 5 | 只读属性拒绝写 | 对 ReadOnly 属性 S15F7 |
| 6 | 缺少必填属性 | 创建时必填项缺失 |
| 7 | 数据类型不匹配 | 传值类型与定义不符 |
| 8 | 状态非法 | 当前对象状态不允许该操作 |
| 9 | 方法不存在 | METHODID 未定义 |
| 10 | 参数错误 | 缺必填参数/参数非法 |
| 99 | 内部错误 | 设备内部异常 |

### 9. 完整示例：创建并启动一个 ProcessJob
```
① S15F1 创建：
L,3
  A "ProcessJob"
  A "PJ001"
  L,2
    L,2[A "LotID", A "LOT20260901"]
    L,2[A "WaferCount", U2 25]
→ S15F2: L,2[U1 0, A "ProcessJob:PJ001"]   // 创建成功，对象处于 QUEUED

② S15F9 调用 Start：
L,3
  A "ProcessJob:PJ001"
  A "Start"
  L,1[ L,2[A "Mode", U1 1] ]
→ S15F10: L,2[U1 0, L,0]                    // 方法被接受

③ 设备内部状态机 QUEUED→EXECUTING，触发 Started 事件：
→ S16F1: [OBJSPEC="ProcessJob:PJ001", CEID=4101, 快照{ProcessState, LotID}]
Host 回 S16F2 确认

④ 加工完成，状态机 EXECUTING→COMPLETED：
→ S16F1: [CEID=4102 Completed, 快照{ProcessState,LotID,WaferCount=25}]

⑤ S15F3 删除：
L,1[A "ProcessJob:PJ001"]
→ S15F4: L,1[U1 0]
```
