# W09 · Day06 答案与参考实现

## 一、自测题标准答案
1. **统一处理模式 / 为什么抽 SafeHandle**：模式=解析请求 body→调用 Registry/Instance→成功组装 reply(ACKC=0+数据)→捕获 OssException 映射为 ACKC 非0+空数据→捕获未知异常回 ACKC=99 并记日志（绝不崩溃断连）。抽 SafeHandle 的原因：六个处理器的异常处理骨架完全相同，重复写六遍既冗余又容易不一致（某个处理器漏 catch 就会把异常抛到消息分发层导致断连）。抽成统一辅助方法后，处理器只写"成功路径"的业务逻辑，异常映射集中一处，错误码策略变更只改一处；同时保证所有 S15 reply 结构一致（L,?[ACKC,...]），Host 解析逻辑统一。
2. **OssException 为什么带错误码 / 文本匹配的问题**：在异常上携带结构化错误码字段（OssException(code,message)），抛出点（Registry/Instance 校验处）最清楚是哪类错误，直接带上精确码，处理器 catch 后读取 ex.Code 即可。靠异常消息文本匹配（如判断 message.Contains("not found")）的问题：①脆弱——改一句错误文案，匹配逻辑就失效；②无法本地化/多语言；③文本可能含动态内容（OBJSPEC），匹配不可靠；④性能差（字符串比较）；⑤不同错误可能文案相近导致误判。结构化错误码是机器可读的稳定契约，文本只给人看日志。
3. **S15F7 两阶段 / 为什么校验阶段不能写入**：第一阶段"校验"——遍历整批属性，只检查不修改：属性是否存在、是否只读、当前状态是否允许写、类型是否匹配，收集第一个错误；第二阶段"提交"——只有全部校验通过，才循环真正 SetAttribute 写入。校验阶段不能写入的原因：如果边校验边写，当校验到第 3 个属性失败时，前 2 个已经写入，无法自动回滚（除非额外实现事务回滚），对象就处于"部分属性是新值、部分是旧值"的半更新不一致状态，且属性间有耦合时会产生非法组合。先全量校验、后一次性提交，天然实现 all-or-nothing 原子性，无需回滚机制。
4. **S15F10 和 S16F1 的时机和含义**：S15F10 在设备**同步接受方法请求时立即发出**（毫秒级）——即完成"对象存在、方法存在、状态允许、参数合法、投递执行"这些检查后立刻回复，ACKC=0 只表示"请求被接受、即将/开始执行"。S16F1 在方法驱动的**对象状态机实际发生转换时发出**（可能是立即，也可能是数分钟/数小时后工艺走到某个状态）——Start 方法的执行委托调用 TransitionTo("EXECUTING")，转换成功的瞬间触发 Started 事件，ObjectEventService 发 S16F1(CEID=4101)；工艺结束转到 COMPLETED 时再发 S16F1(CEID=4102)。含义区别：F10="我收到并同意做"，S16F1="我做到了哪一步/做完了"。Host 不能靠 F10 判断业务完成，必须等终态 S16F1。
5. **何时订阅/取消订阅 / 不取消的后果**：订阅时机——对象实例创建成功后（S15F1 成功路径，或设备内部创建对象处），ObjectEventService.Subscribe(instance)，挂接 instance.EventRaised。取消时机——对象删除前（S15F3 从 InstanceStore 移除前/后），Unsubscribe，用 -= 摘掉委托。不取消的后果：事件委托持有 ObjectInstance 引用，即使对象从 Registry 删除，GC 仍因委托引用无法回收该实例（典型托管堆内存泄漏）；长期运行下创建/删除大量对象会让内存持续增长；更严重的是已"删除"的对象若内部仍触发事件，会通过残留订阅发出幽灵 S16F1（Host 收到已删除对象的事件，状态错乱）。这正是 W8 Day04 内存泄漏排查中的"事件订阅未取消"模式。
6. **S16F1 通信中断怎么不丢 / 如何接 Spool**：S16F1 和 GEM 的 S6F11 性质相同——都是设备主动上报、需要 Host 确认的事件消息，因此复用 W8 的 SpoolManager：ObjectEventService 不直接 SendPrimaryAsync，而是调用 spoolManager.SendOrSpool(16,1,body)。通信 ON-LINE 且 Normal 模式时直接发送并进入待确认队列；通信 OFF-LINE 时自动入队缓存；通信恢复后 SpoolManager 按时间顺序重发，Host 回 S16F2 确认后从待确认/缓存删除，超时有限次重发。这样对象事件在断连期间不丢失、重连后补收，与 S6F11/S5F1 走同一套可靠机制，不需要为 S16 单独造缓存。
7. **Host 如何知道 ProcessJob 从创建到完成全过程 / 消息序列**：
   ①S14F1/F2、F3/F4、F5/F6、F7/F8：先发现 ProcessJob 类型定义（属性/方法/事件），Host 本地建模；
   ②S15F1/F2：Host 创建 PJ001（带 LotID/WaferCount 初始值），设备回 OBJSPEC，Host 记录"PJ001 存在，状态 QUEUED"；
   ③S15F9/F10：Host 调 Start，设备回 ACKC=0 接受，Host 标记"PJ001 启动中"；
   ④S16F1(Started,CEID=4101)：状态转 EXECUTING，Host 标记"PJ001 执行中"，快照记录当时属性；
   ⑤（执行中）S15F5/F6：Host 可随时查询进度属性（已加工片数等）；
   ⑥S16F1(Completed,CEID=4102)：状态转 COMPLETED，Host 标记"PJ001 完成"，从快取得最终 WaferCount；
   ⑦S15F11/F12：Host 确认对象仍存在（可选对账）；
   ⑧S15F3/F4：Host 删除 PJ001，设备回 ACKC=0，Host 从本地实例缓存移除。
   全程 Host 通过"创建应答+事件流+主动查询"三种信息源精确重建对象生命周期状态，这就是对象级可观测性，比 GEM 扁平事件推断更可靠。

### OssErrorCode 与带码异常（补充 Day02 的 OssException）
```csharp
namespace EapLab.Oss.ObjectModel;

public enum OssErrorCode
{
    Ok = 0, UnknownType = 1, ObjectNotFound = 2, ObjectExists = 3,
    AttrNotFound = 4, ReadOnlyAttr = 5, MissingRequired = 6,
    TypeMismatch = 7, IllegalState = 8, MethodNotFound = 9, BadParameter = 10,
    InternalError = 99
}

public sealed class OssCodedException : Exception
{
    public OssErrorCode Code { get; }
    public OssCodedException(OssErrorCode code, string msg) : base(msg) => Code = code;
}

/// <summary>统一安全执行：成功返回 reply，异常映射为错误 ACKC。</summary>
public static class SafeHandler
{
    public static SecsItem Run(Func<SecsItem> success, Func<OssErrorCode, SecsItem> errorReply)
    {
        try { return success(); }
        catch (OssCodedException ex) { return errorReply(ex.Code); }
        catch (Exception ex)
        {
            Console.WriteLine($"[S15] internal error: {ex}");
            return errorReply(OssErrorCode.InternalError);
        }
    }
}
```

### S15 处理器（节选核心四个，Delete/Exists 同构）
```csharp
using EapLab.Oss.ObjectModel;
using EapLab.Secs2;

namespace EapLab.Oss.S15;

/// <summary>S15F1/F2 创建对象。</summary>
public sealed class S15F1Handler
{
    private readonly ObjectRegistry _registry;
    private readonly ObjectEventService _events;
    public S15F1Handler(ObjectRegistry registry, ObjectEventService events)
    { _registry = registry; _events = events; }

    public SecsItem Handle(SecsItem? body) => SafeHandler.Run(() =>
    {
        if (body is not SecsList l || l.Items.Count < 3)
            throw new OssCodedException(OssErrorCode.BadParameter, "expect L,3");
        string typeName = ((SecsAscii)l.Items[0]).Value;
        string id = ((SecsAscii)l.Items[1]).Value;
        var initValues = ParseAttrValues((SecsList)l.Items[2]);

        var instance = _registry.CreateInstance(typeName, id, initValues, "QUEUED");
        _events.Subscribe(instance);                 // 创建后订阅事件
        return SecsItem.L(SecsItem.U1(0), SecsItem.A(instance.ObjSpec));
    },
    code => SecsItem.L(SecsItem.U1((byte)code), SecsItem.A("")));

    internal static Dictionary<string, SecsItem> ParseAttrValues(SecsList list)
    {
        var dict = new Dictionary<string, SecsItem>();
        foreach (var item in list.Items)
        {
            var pair = (SecsList)item;
            dict[((SecsAscii)pair.Items[0]).Value] = pair.Items[1];
        }
        return dict;
    }
}

/// <summary>S15F5/F6 查询属性（严格按请求顺序返回）。</summary>
public sealed class S15F5Handler
{
    private readonly ObjectRegistry _registry;
    public S15F5Handler(ObjectRegistry registry) => _registry = registry;

    public SecsItem Handle(SecsItem? body) => SafeHandler.Run(() =>
    {
        var (spec, attrIds) = ParseSpecAndAttrs(body);
        var inst = _registry.GetInstance(spec);

        var resultItems = new List<SecsItem>();
        if (attrIds.Count == 0) // 空列表=查全部，按类型注册顺序
        {
            foreach (var def in inst.Type.Attributes)
                resultItems.Add(SecsItem.L(SecsItem.A(def.AttrId),
                    inst.GetAttribute(def.AttrId) ?? SecsItem.L(Array.Empty<SecsItem>())));
        }
        else // 严格按请求顺序
        {
            foreach (var attrId in attrIds)
            {
                if (inst.Type.GetAttribute(attrId) == null)
                    throw new OssCodedException(OssErrorCode.AttrNotFound, attrId);
                resultItems.Add(SecsItem.L(SecsItem.A(attrId),
                    inst.GetAttribute(attrId) ?? SecsItem.L(Array.Empty<SecsItem>())));
            }
        }
        return SecsItem.L(SecsItem.U1(0), SecsItem.L(resultItems.ToArray()));
    },
    code => SecsItem.L(SecsItem.U1((byte)code), SecsItem.L(Array.Empty<SecsItem>())));

    internal static (string spec, List<string> attrIds) ParseSpecAndAttrs(SecsItem? body)
    {
        if (body is not SecsList l || l.Items.Count < 2)
            throw new OssCodedException(OssErrorCode.BadParameter, "expect L,2");
        string spec = ((SecsAscii)l.Items[0]).Value;
        var ids = ((SecsList)l.Items[1]).Items
            .Select(i => ((SecsAscii)i).Value).ToList();
        return (spec, ids);
    }
}

/// <summary>S15F7/F8 设置属性（两阶段原子）。</summary>
public sealed class S15F7Handler
{
    private readonly ObjectRegistry _registry;
    public S15F7Handler(ObjectRegistry registry) => _registry = registry;

    public SecsItem Handle(SecsItem? body) => SafeHandler.Run(() =>
    {
        if (body is not SecsList l || l.Items.Count < 2)
            throw new OssCodedException(OssErrorCode.BadParameter, "expect L,2");
        string spec = ((SecsAscii)l.Items[0]).Value;
        var updates = S15F1Handler.ParseAttrValues((SecsList)l.Items[1]);
        var inst = _registry.GetInstance(spec);

        // 阶段1：全量校验（不写入）
        foreach (var kv in updates)
        {
            var def = inst.Type.GetAttribute(kv.Key)
                ?? throw new OssCodedException(OssErrorCode.AttrNotFound, kv.Key);
            if (def.Access == AccessMode.ReadOnly)
                throw new OssCodedException(OssErrorCode.ReadOnlyAttr, kv.Key);
            // 状态允许写、类型匹配校验略（IllegalState / TypeMismatch）
        }
        // 阶段2：全部通过才提交
        foreach (var kv in updates) inst.SetAttribute(kv.Key, kv.Value);

        return SecsItem.L(SecsItem.U1(0));
    },
    code => SecsItem.L(SecsItem.U1((byte)code)));
}

/// <summary>S15F9/F10 调用方法（异步：立即回接受，状态转换发 S16）。</summary>
public sealed class S15F9Handler
{
    private readonly ObjectRegistry _registry;
    private readonly Dictionary<string, Func<ObjectInstance, Dictionary<string, SecsItem>, Dictionary<string, SecsItem>>> _executors;
    public S15F9Handler(ObjectRegistry registry,
        Dictionary<string, Func<ObjectInstance, Dictionary<string, SecsItem>, Dictionary<string, SecsItem>>> executors)
    { _registry = registry; _executors = executors; }

    public SecsItem Handle(SecsItem? body) => SafeHandler.Run(() =>
    {
        if (body is not SecsList l || l.Items.Count < 3)
            throw new OssCodedException(OssErrorCode.BadParameter, "expect L,3");
        string spec = ((SecsAscii)l.Items[0]).Value;
        string methodId = ((SecsAscii)l.Items[1]).Value;
        var inputs = S15F1Handler.ParseAttrValues((SecsList)l.Items[2]);
        var inst = _registry.GetInstance(spec);

        if (!_executors.TryGetValue(methodId, out var executor))
            throw new OssCodedException(OssErrorCode.MethodNotFound, methodId);

        // InvokeMethod 内部校验 RequiredState（非法状态抛 IllegalState）
        var outputs = inst.InvokeMethod(methodId, inputs, executor);
        var outItems = outputs.Select(kv => SecsItem.L(SecsItem.A(kv.Key), kv.Value)).ToArray();
        return SecsItem.L(SecsItem.U1(0), SecsItem.L(outItems)); // 立即回：已接受
    },
    code => SecsItem.L(SecsItem.U1((byte)code), SecsItem.L(Array.Empty<SecsItem>())));
}

// S15F11Handler 存在性：遍历 OBJSPEC 列表，回 L,n[L,2[A spec,Boolean exists]]
```

### ObjectEventService（S16）
```csharp
using EapLab.Oss.ObjectModel;
using EapLab.Secs2;
using EapLab.Gem.Spool;
using EapLab.Transport.Connection;

namespace EapLab.Oss.S16;

/// <summary>对象事件服务：订阅实例事件 → 组 S16F1 → 发送(走 Spool)。</summary>
public sealed class ObjectEventService
{
    private readonly HsmsConnection _conn;
    private readonly SpoolManager _spool;
    // 显式保存委托引用，取消订阅时才能精确摘除
    private readonly Dictionary<string, Action<string, uint, Dictionary<string, SecsItem>>> _handlers = new();
    private readonly object _lock = new();

    public ObjectEventService(HsmsConnection conn, SpoolManager spool)
    { _conn = conn; _spool = spool; }

    public void Subscribe(ObjectInstance instance)
    {
        lock (_lock)
        {
            if (_handlers.ContainsKey(instance.ObjSpec)) return;
            Action<string, uint, Dictionary<string, SecsItem>> handler = OnObjectEvent;
            _handlers[instance.ObjSpec] = handler;
            instance.EventRaised += handler;
        }
    }

    public void Unsubscribe(ObjectInstance instance)
    {
        lock (_lock)
        {
            if (_handlers.Remove(instance.ObjSpec, out var handler))
                instance.EventRaised -= handler; // 精确摘除，防泄漏/幽灵事件
        }
    }

    private void OnObjectEvent(string objSpec, uint ceid, Dictionary<string, SecsItem> snapshot)
    {
        var snapItems = snapshot.Select(kv => SecsItem.L(SecsItem.A(kv.Key), kv.Value)).ToArray();
        var body = SecsItem.L(
            SecsItem.A(objSpec),
            SecsItem.U4(ceid),
            SecsItem.L(snapItems));

        // 走 Spool：在线直发+待确认，离线缓存，恢复补发（与 S6F11 同机制）
        _spool.SendOrSpool(16, 1, body);
    }

    /// <summary>处理 Host 回的 S16F2 确认（转交 Spool 做待确认删除）。</summary>
    public void OnS16F2(SecsItem? body) => _spool.OnAckReceived(16, 2, body!);
}
```

## 三、今日易错点
1. 每个处理器各写一套 try/catch（应抽 SafeHandler，统一错误映射，防止漏 catch 断连）。
2. OssException 不带错误码、靠消息文本判断（应结构化错误码，稳定可维护）。
3. S15F7 边校验边写（应两阶段，先全量校验后统一提交，保证原子）。
4. S15F5 返回顺序用字典枚举（字典无序，必须按请求列表顺序）。
5. 把 S15F10 当完成信号（它只是接受，完成看 S16F1 终态事件）。
6. 创建对象后不订阅事件、删除对象后不取消订阅（内存泄漏 + 幽灵事件）。
7. S16F1 直接发送不走 Spool（断连丢失，应复用 SpoolManager.SendOrSpool）。
8. 方法执行器里直接改状态字符串而不走 TransitionTo（绕过状态机，事件不会触发、非法转换不拦截）。
9. 删除执行中的对象不做终态校验（应 ACKC=8 拒绝，先 Abort）。
10. S16F1 快照在异步发送时才取值（应在状态转换瞬间快照，避免取到变化后的值，Day02 的 RaiseEvent 已在锁内快照）。
