## 二、背景知识（先读，15 分钟）

### 1. S14 处理器在架构中的位置
```
HsmsConnection 收到 S14Fx 消息
  → MessageDispatcher 按 Stream=14 路由到 S14Router
    → S14Router 按 Function 分发：
        F1 → S14F1Handler（不需要 ObjType，查全部类型）
        F3 → S14F3Handler（解析 ObjType，查属性）
        F5 → S14F5Handler（解析 ObjType，查方法）
        F7 → S14F7Handler（解析 ObjType，查事件）
  → Handler 从 ObjectRegistry 取 ObjectType
  → 序列化为 S14F2/F4/F6/F8 body
  → HsmsConnection 回 reply
```

### 2. 数据类型映射
AttributeDefinition.DataType（枚举 SecsDataType）要映射成 SECS-II 消息中的类型码（U1）。定义一张映射表：
```
A→对应类型码, Boolean→对应类型码, U1/U2/U4/U8, I1/I2/I4/I8, F4/F8, B, List
```
Host 端拿到类型码后知道该属性值用什么 SECS-II 类型编解码。

### 3. 请求解析要点
- S14F1 body 可为空（查全部）。
- S14F3/F5/F7 body = L,1[A ObjType]，解析时校验：body 必须是 List、第 0 项必须是 A（ASCII）、非空字符串。
- 解析失败（格式错）回 ACKC 非 0 + 空列表，不抛异常（W8 Day05 的异常处理原则）。

### 4. 序列化要点（对照 Day03 的 Item 树）
- BuildTypesReply：遍历 ObjectRegistry.ListTypes()，每个类型生成 L,3[A TypeName, U1 属性数, A 说明]。
- BuildAttrsReply：遍历 type.Attributes，每个生成 L,5[A AttrId, U1 类型码, U1 AccessMode, Boolean Required, A Name]。
- BuildMethodsReply：遍历 type.Methods，每个生成 L,4[A MethodId, L,k 输入参数, L,m 输出参数, L,p 允许状态]；参数生成 L,3[A Name,U1 类型码,Boolean Required]。
- BuildEventsReply：遍历 type.Events，每个生成 L,4[U4 CEID, A Name, L,q 快照属性, A TriggerState]。
- 空集合生成 L,0（空 List），合法。

### 5. ACKC 约定（本教学项目统一）
- 0 = 成功
- 1 = 类型不存在
- 2 = 请求消息格式错误
- 3 = 内部错误
（具体数值以 E39 标准和项目约定为准，重点是设备和 Host 一致。）
