# W09 · Day04 答案与参考实现

## 一、自测题标准答案
1. **S14 完整调用链**：HsmsConnection 收到字节流→SECS-II 解码得到 Stream=14、Function、body→MessageDispatcher 按 Stream 查路由表找到 S14Router→S14Router 按 Function（1/3/5/7）分发到对应 Handler→Handler 解析请求 body（F3/F5/F7 解析 ObjType）→Handler 从 ObjectRegistry 的 TypeRegistry 取 ObjectType→调用对应 Build 方法把类型定义序列化为 SECS-II Item（S14F2/F4/F6/F8 body）→交回 MessageDispatcher→HsmsConnection 用相同 SystemBytes 编码发送 reply（W=0）。
2. **S14F3 请求结构 / 解析校验 / 失败处理**：S14F3 body=L,1[A ObjType]。校验：①body 非空且是 SecsList；②List 子项数 ≥1；③第 0 项是 SecsAscii（A 类型）；④字符串非空、非纯空白。任一不满足判定为请求格式错误。失败处理：不抛异常、不断连，回 S14F4，ACKC=2（格式错误），列表为 L,0，记录日志（原始 body hex + 失败原因）。这符合 W8 Day05 的原则——对端请求格式问题用业务错误码回答。
3. **BuildAttrsReply 字段对应**：遍历 type.Attributes，每个 AttributeDefinition 生成一个 L,5：[0] A=AttrId（属性标识）、[1] U1=DataType 经 DataTypeMapper 映射的 SECS-II 类型码、[2] U1=(byte)AccessMode（0只读/1读写/2只写）、[3] Boolean=Required（创建时是否必填）、[4] A=Name（可读说明）；外层 L,2[U1 ACKC=0, L,n(所有属性子 List)]。
4. **类型没有方法怎么回 / 能省略吗**：正常回 S14F6，ACKC=0，方法列表为空 List L,0（即 L,2[U1 0, L,0]）。不能省略列表项——reply 结构固定为 L,2[ACKC,List]，省略会导致 Host 按固定结构解析时越界/错位。空集合是合法且常见的情况（简单对象可能只有属性没有方法），用 L,0 明确表达"该类型没有方法"，和"查询失败"（ACKC 非0）区分开。
5. **为什么需要 DataTypeMapper / Host 拿类型码的用途**：ObjectType 内部用 C# 枚举 SecsDataType 表示类型，SECS-II 消息只能传数值，所以需要映射表把枚举转成线上约定的 U1 类型码，反向 Host 端再把类型码映射回类型。Host 拿到属性类型码的用途：①知道该属性值用什么 SECS-II 类型编码（S15F7 设置时）和解码（S15F6 返回时、S16F1 快照中）；②做客户端类型校验，避免把 A 类型的 LotID 错传成 U4；③UI 渲染时选择合适控件（枚举用下拉、数值用数字框、ASCII 用文本框）。
6. **S14Router 怎么分发 / 不支持的 Function 怎么办**：S14Router 内部维护 Function→Handler 字典（1→F1Handler、3→F3Handler、5→F5Handler、7→F7Handler），收到消息按 header.Function 查表，命中则调用并回对应偶数 reply。收到不支持的 Function（如 S14F9）：①该 Function 无对应 Handler，属于"未定义的 Function"，按 W4 学的 S9 机制回 **S9F3（Unrecognized Function）**，携带原消息头；②记录日志；③不回伪造的 S14F10，也不崩溃。区分：Function 完全不认识用 S9F3；Function 认识但请求内容错（如类型不存在）用 reply 内 ACKC 非 0。

## 二、参考实现（EapLab.Oss/S14）

### DataTypeMapper.cs
```csharp
using EapLab.Oss.ObjectModel;

namespace EapLab.Oss.S14;

/// <summary>SecsDataType 枚举 与 线上 U1 类型码互转（项目约定码值，全设备/Host 保持一致）。</summary>
public static class DataTypeMapper
{
    // 约定的类型码（教学项目自定义，实际工程以团队接口规范为准）
    public static readonly Dictionary<SecsDataType, byte> ToCode = new()
    {
        [SecsDataType.A] = 10,
        [SecsDataType.B] = 11,
        [SecsDataType.Boolean] = 12,
        [SecsDataType.U1] = 20,
        [SecsDataType.U2] = 21,
        [SecsDataType.U4] = 22,
        [SecsDataType.U8] = 23,
        [SecsDataType.I1] = 30,
        [SecsDataType.I2] = 31,
        [SecsDataType.I4] = 32,
        [SecsDataType.I8] = 33,
        [SecsDataType.F4] = 40,
        [SecsDataType.F8] = 41,
        [SecsDataType.List] = 50,
    };

    public static byte ToWireCode(SecsDataType t) => ToCode[t];
}
```

### S14Replies.cs（四个 Build 序列化方法）
```csharp
using EapLab.Oss.ObjectModel;
using EapLab.Secs2;

namespace EapLab.Oss.S14;

public static class S14Replies
{
    public const byte AckOk = 0;
    public const byte AckUnknownType = 1;
    public const byte AckBadRequest = 2;
    public const byte AckInternalError = 3;

    /// <summary>S14F2：类型列表。</summary>
    public static SecsItem BuildTypesReply(ObjectRegistry registry)
    {
        var typeItems = registry.ListTypes()
            .Select(name =>
            {
                var t = registry.GetType(name);
                return SecsItem.L(
                    SecsItem.A(t.TypeName),
                    SecsItem.U1((byte)t.Attributes.Count()),
                    SecsItem.A(t.TypeName) // Comment 简化用类型名
                );
            }).ToArray();
        return SecsItem.L(SecsItem.U1(AckOk), SecsItem.L(typeItems));
    }

    /// <summary>S14F4：属性定义列表。</summary>
    public static SecsItem BuildAttrsReply(ObjectType? type)
    {
        if (type == null) return Error(AckUnknownType);
        var items = type.Attributes.Select(a => SecsItem.L(
            SecsItem.A(a.AttrId),
            SecsItem.U1(DataTypeMapper.ToWireCode(a.DataType)),
            SecsItem.U1((byte)a.Access),
            SecsItem.Boolean(a.Required),
            SecsItem.A(a.Name)
        )).ToArray();
        return SecsItem.L(SecsItem.U1(AckOk), SecsItem.L(items));
    }

    /// <summary>S14F6：方法定义列表。</summary>
    public static SecsItem BuildMethodsReply(ObjectType? type)
    {
        if (type == null) return Error(AckUnknownType);
        var methods = type.Methods.Select(m =>
        {
            var inputs = m.Inputs.Select(p => SecsItem.L(
                SecsItem.A(p.Name),
                SecsItem.U1(DataTypeMapper.ToWireCode(p.DataType)),
                SecsItem.Boolean(p.Required))).ToArray();
            var outputs = m.Outputs.Select(p => SecsItem.L(
                SecsItem.A(p.Name),
                SecsItem.U1(DataTypeMapper.ToWireCode(p.DataType)),
                SecsItem.Boolean(p.Required))).ToArray();
            var states = m.RequiredStates.Select(s => SecsItem.A(s)).ToArray();
            return SecsItem.L(
                SecsItem.A(m.MethodId),
                SecsItem.L(inputs),
                SecsItem.L(outputs),
                SecsItem.L(states));
        }).ToArray();
        return SecsItem.L(SecsItem.U1(AckOk), SecsItem.L(methods));
    }

    /// <summary>S14F8：事件定义列表。</summary>
    public static SecsItem BuildEventsReply(ObjectType? type)
    {
        if (type == null) return Error(AckUnknownType);
        var events = type.Events.Select(e =>
        {
            var linked = e.LinkedAttributes.Select(a => SecsItem.A(a)).ToArray();
            return SecsItem.L(
                SecsItem.U4(e.Ceid),
                SecsItem.A(e.Name),
                SecsItem.L(linked),
                SecsItem.A(e.TriggerState ?? ""));
        }).ToArray();
        return SecsItem.L(SecsItem.U1(AckOk), SecsItem.L(events));
    }

    private static SecsItem Error(byte ackc) =>
        SecsItem.L(SecsItem.U1(ackc), SecsItem.L(Array.Empty<SecsItem>()));
}
```

### S14Handlers.cs
```csharp
using EapLab.Oss.ObjectModel;
using EapLab.Secs2;

namespace EapLab.Oss.S14;

/// <summary>S14F1：类型列表查询（请求可为空）。</summary>
public sealed class S14F1Handler
{
    private readonly ObjectRegistry _registry;
    public S14F1Handler(ObjectRegistry registry) => _registry = registry;
    public SecsItem Handle(SecsItem? body) => S14Replies.BuildTypesReply(_registry);
}

/// <summary>S14F3/F5/F7 共用：解析 L,1[A ObjType]。</summary>
internal static class ObjTypeParser
{
    public static bool TryParse(SecsItem? body, out string objType)
    {
        objType = "";
        if (body is not SecsList l || l.Items.Count < 1 || l.Items[0] is not SecsAscii a)
            return false;
        objType = a.Value.Trim();
        return !string.IsNullOrEmpty(objType);
    }
}

public sealed class S14F3Handler
{
    private readonly ObjectRegistry _registry;
    public S14F3Handler(ObjectRegistry registry) => _registry = registry;
    public SecsItem Handle(SecsItem? body)
    {
        if (!ObjTypeParser.TryParse(body, out var t))
            return S14Replies.BuildAttrsReply(null) with BadRequest(body); // 见说明
        ObjectType? type = null;
        try { type = _registry.GetType(t); } catch (OssException) { return S14Replies.BuildAttrsReply(null); }
        return S14Replies.BuildAttrsReply(type);
    }
}

public sealed class S14F5Handler
{
    private readonly ObjectRegistry _registry;
    public S14F5Handler(ObjectRegistry registry) => _registry = registry;
    public SecsItem Handle(SecsItem? body)
    {
        if (!ObjTypeParser.TryParse(body, out var t))
            return SecsItem.L(SecsItem.U1(S14Replies.AckBadRequest), SecsItem.L(Array.Empty<SecsItem>()));
        try { return S14Replies.BuildMethodsReply(_registry.GetType(t)); }
        catch (OssException) { return S14Replies.BuildMethodsReply(null); }
    }
}

public sealed class S14F7Handler
{
    private readonly ObjectRegistry _registry;
    public S14F7Handler(ObjectRegistry registry) => _registry = registry;
    public SecsItem Handle(SecsItem? body)
    {
        if (!ObjTypeParser.TryParse(body, out var t))
            return SecsItem.L(SecsItem.U1(S14Replies.AckBadRequest), SecsItem.L(Array.Empty<SecsItem>()));
        try { return S14Replies.BuildEventsReply(_registry.GetType(t)); }
        catch (OssException) { return S14Replies.BuildEventsReply(null); }
    }
}
```
> 说明：上例 S14F3Handler 中 `with BadRequest(body)` 是伪代码示意，实际工程按 S14F5/F7 的写法返回 ACKC=2 的错误 reply，保持四个 Handler 风格一致。

### S14Router.cs
```csharp
using EapLab.Secs2;
using EapLab.Transport.Logging;

namespace EapLab.Oss.S14;

/// <summary>Stream=14 路由：按 Function 分发，不支持的 Function 由上层回 S9F3。</summary>
public sealed class S14Router
{
    private readonly S14F1Handler _f1;
    private readonly S14F3Handler _f3;
    private readonly S14F5Handler _f5;
    private readonly S14F7Handler _f7;
    private readonly ILogSink _log;

    public S14Router(S14F1Handler f1, S14F3Handler f3, S14F5Handler f5, S14F7Handler f7, ILogSink log)
    { _f1 = f1; _f3 = f3; _f5 = f5; _f7 = f7; _log = log; }

    /// <summary>返回 reply body；返回 null 表示无法处理（上层回 S9F3）。</summary>
    public SecsItem? Route(byte function, SecsItem? body)
    {
        switch (function)
        {
            case 1: return _f1.Handle(body);
            case 3: return _f3.Handle(body);
            case 5: return _f5.Handle(body);
            case 7: return _f7.Handle(body);
            default:
                _log.Log(LogDir.WARN, $"S14F{function} not supported, should reply S9F3");
                return null;
        }
    }
}
```

### 单元测试（节选）
```csharp
public class S14HandlerTests
{
    private static ObjectRegistry BuildRegistry()
    {
        var reg = new ObjectRegistry();
        reg.RegisterType(new ObjectType("ProcessJob")
            .AddAttribute(new("ProcessState", "状态", SecsDataType.U1))
            .AddAttribute(new("LotID", "批次", SecsDataType.A, AccessMode.ReadWrite, required: true))
            .AddMethod(new("Start", "开始",
                new[] { new ParameterDefinition("Mode", SecsDataType.U1, false) },
                Array.Empty<ParameterDefinition>(), new HashSet<string> { "QUEUED" }))
            .AddEvent(new(4101, "Started", new[] { "ProcessState", "LotID" }, "EXECUTING")));
        reg.RegisterType(new ObjectType("Carrier")); // 无方法无事件
        return reg;
    }

    [Fact]
    public void S14F1_返回全部类型()
    {
        var h = new S14F1Handler(BuildRegistry());
        var reply = (SecsList)h.Handle(null);
        Assert.Equal(0u, ((SecsU1)reply.Items[0]).Values[0]);
        var types = (SecsList)reply.Items[1];
        Assert.Equal(2, types.Items.Count);
    }

    [Fact]
    public void S14F4_返回属性定义()
    {
        var reg = BuildRegistry();
        var h = new S14F3Handler(reg);
        var reply = (SecsList)h.Handle(SecsItem.L(SecsItem.A("ProcessJob")));
        Assert.Equal(0u, ((SecsU1)reply.Items[0]).Values[0]);
        var attrs = (SecsList)reply.Items[1];
        Assert.Equal(2, attrs.Items.Count);
    }

    [Fact]
    public void S14F6_空方法类型_返回空List()
    {
        var reg = BuildRegistry();
        var h = new S14F5Handler(reg);
        var reply = (SecsList)h.Handle(SecsItem.L(SecsItem.A("Carrier")));
        Assert.Equal(0u, ((SecsU1)reply.Items[0]).Values[0]);
        Assert.Empty(((SecsList)reply.Items[1]).Items);
    }

    [Fact]
    public void S14F4_类型不存在_ACKC为1()
    {
        var h = new S14F3Handler(BuildRegistry());
        var reply = (SecsList)h.Handle(SecsItem.L(SecsItem.A("NotExist")));
        Assert.Equal(1u, ((SecsU1)reply.Items[0]).Values[0]);
    }

    [Fact]
    public void S14F3_请求格式错误_ACKC为2()
    {
        var h = new S14F3Handler(BuildRegistry());
        var reply = (SecsList)h.Handle(SecsItem.U4(123)); // 不是 L,1[A]
        Assert.Equal(2u, ((SecsU1)reply.Items[0]).Values[0]);
    }

    [Fact]
    public void S14Router_不支持的Function_返回null()
    {
        var reg = BuildRegistry();
        var router = new S14Router(
            new S14F1Handler(reg), new S14F3Handler(reg),
            new S14F5Handler(reg), new S14F7Handler(reg), new ConsoleLogSink());
        Assert.Null(router.Route(9, null)); // 上层回 S9F3
    }
}
```

## 三、今日易错点
1. Handler 里直接抛异常（类型不存在/格式错误应回 ACKC 非 0，不抛异常不断连）。
2. 空集合省略不回（必须回 L,0，保持 reply 结构固定 L,2[ACKC,List]）。
3. 类型码映射表设备端和 Host 端不一致（必须统一约定并文档化）。
4. S14F1 请求 body 强制要求非空（F1 允许空 body 查全部类型）。
5. 不支持的 Function 回伪造 reply（应回 S9F3 未定义 Function）。
6. CEID 用 U1/U2（事件 ID 用 U4，注意宽度）。
7. Router 每次 new Handler（Handler 无状态可复用，构造一次注入即可）。
8. 序列化时直接访问 AttributeDefinition 内部字典（应通过 type.Attributes 枚举，保持封装）。
9. 忘记把 S14Router 挂到 MessageDispatcher 的 Stream=14 路由（消息到不了 Handler）。
