# W20 · Day06 答案与参考实现

## 一、自测题标准答案
1. **顺序链后继为何不立即启动 / 何时启动**：PJ_CLEAN 依赖 PJ_ETCH（控制依赖）且其输入片来自 ETCH 输出（片流依赖），Start CJ 时只有无依赖的首批 PJ（PJ_ETCH）满足"依赖就绪+片就位+资源可用"，PJ_CLEAN 的输入片还没被 ETCH 加工出来、无片可取，因此不启动。它在 PJ_ETCH 完成、产出片到达约定交接位置（中间位/输出载具）、交接校验通过、且自身资源可用时，才由 CJ 编排器级联 Create+Start。这样保证后继不会对尚不存在的"半成品"操作，也不提前空占资源。
2. **交接核对 / 不符处理**：核对①交接清单——ETCH 输出片集合==CLEAN 期望输入集合（顺序链是同一批 6 片）；②逐片读码身份=预期 ID；③片在约定交接稳定位置、位置可用未 Hold；④交接前后全局片 ID 集合守恒。任一不符：停止级联，不启动后继，冻结现场（记录哪片缺/多/身份错/位置错），按异常处理——缺片查 E90 轨迹与守恒、身份错按错料隔离人工、位置不稳等到位；绝不在清单不一致时"先启动后边找"，否则片会丢在两个 PJ 的责任缝隙。
3. **并行汇合不重不漏证明**：以唯一片 ID 集合做两次核对——不重：X 输出集合与 Y 输出集合交集为空（分支选择条件互斥，同一片不会同时走两路），输出槽唯一（两片不写同槽）；不漏：X 输出∪Y 输出==CJ 输入 6 片集合（SetEquals，基数 6、ID 全对）。再叠加 E90 全局守恒（Σ输出载具+设备内=基线 6）。数量对、ID 对、交集空、并集全等，即证明汇合既没重复也没遗漏（6 片不会被算成 12）。
4. **一分支先完成 CJ 态 / 为何不完成**：CJ 仍 Executing。因为聚合规则要求**所有** PJ Completed 且全部片到输出才 Completed；一个并行 PJ 先完成只是该分支结束，另一分支还在加工，整批料尚未全部走完，属于"部分子完成、整体执行中"的正常混合态。先完成的 PJ 保持 Completed 终态，CJ 等另一分支完成并汇合、全部片到输出后才聚合为 Completed。
5. **顺序链计数**：CJ 总片数按唯一片 ID=6（同一片经两个 PJ 不翻倍）；PJ 加工次数（片-步骤实例）=6 片×2 PJ=12 次 PJ 加工（这个维度可累加，用于设备工作量/利用率统计）；CJ 完成片数以最终到输出 B 为准=6。区分两个口径：在制片数（唯一实体）用 6，加工工作量（流经次数）用 12，不能混用。
6. **CJ 事件少、PJ 事件多**：PJ 层每步/每片/每次状态变化都发细粒度事件（高频，供工艺监控与数据采集）；CJ 层每次子变化只触发重新聚合，**仅当 CJ 自身状态/当前活动 PJ/跨越进度阈值变化时才发一个 CJ 事件**。顺序链里 CJ 从 Queued→Executing 一次、最终→Completed 一次，中间 PJ_ETCH 完成、PJ_CLEAN 启动虽有子事件，但若 CJ 始终是 Executing 就不重复发 CJ 事件。这样 Host 看 CJ 事件得到简洁的批次主线，需要细节再下钻 PJ 事件，避免高频刷屏。
7. **中间 PJ 失败的前后处置**：前序已完成片（PJ_ETCH 已加工、停在交接位/中间载具）保持不动、登记为"已完成前道、待后续"的中间在制品，位置与工艺进度记录清楚，不回退（成果有效）；失败的 PJ 内片按 W17 故障处置（判返工/报废、撤到安全位/保持、Alarm）；未开始的后继 PJ_CLEAN 不启动（其输入依赖失败环节，级联阻断）。CJ 按策略：关键顺序链断裂→整体 Failed/Aborted 并带每片分类与实际位置，待故障处理后，可基于现场为未完成片新建 CJ/PJ 续跑（源=当前实际位置），前序合格片不重做。全程守恒、锁相关载具。

## 二、参考实现（net8.0，两剧本总装）

### E94 总装
```csharp
namespace EapLab.E94;
public sealed class CjCell
{
    public CjHostService Host{get;} public MapCompiler Compiler{get;}=new();
    public CjStateAggregator Agg{get;}=new(); public SubstrateTracker Tracker{get;}
    private readonly Dictionary<string,ControlJobRuntime> _rt=new();
    public CjCell(CarrierManager c,SubstrateTracker t,PjFactory f){Tracker=t;Host=new CjHostService(c,f);}

    public CjRunResult RunSequential(ControlJobDefinition def,FlowGraph g)
    { var ev=new List<CjState>();
      Host.Create(def); Host.OnCjS16+=(id,_)=>ev.Add(StateOf(id));
      Host.Start(def.CjId);                                  // 只起PJ_ETCH
      // 模拟PJ_ETCH执行完成 -> 交接 -> 级联PJ_CLEAN -> 完成
      Host.DrivePjToDone(def.CjId,"PJ_ETCH",HandoverOk);
      Host.DrivePjToDone(def.CjId,"PJ_CLEAN",HandoverOk);
      return new CjRunResult(StateOf(def.CjId),Tracker.AssertSafe(),ev); }
    bool HandoverOk(string a,string b,List<string> wafers)=>true;
    public CjState StateOf(string id)=>Host.StateOf(id);
}
public sealed record CjRunResult(CjState Final,bool Conserved,List<CjState> CjEventStates);
```

public class SequentialCjTests

    [Fact] public void 蚀刻完才起清洗_全完CJ完成_守恒()

public class ParallelCjTests

    [Fact] public void 两分支并行_汇合不重不漏_全完才完成()

## 三、两剧本流程（手绘参考）
```
顺序链: A→[PJ_ETCH]→交接(清单=读码=位置=守恒)→[PJ_CLEAN]→B
        Start只起ETCH; ETCH完级联CLEAN; 全到B才CJ Completed
并行:   A ┬W1-3→[PJ_X]→┐
          └W4-6→[PJ_Y]→┴→B(槽唯一); 两支并行, 先完一支CJ仍Executing
汇合: X∩Y=空(不重), X∪Y=输入6(不漏); 唯一片6, PJ加工12次
事件: PJ高频; CJ仅状态变才发(Queued→Executing→Completed)
失败: 前序片保留/失败片处置/后继阻断, 关键链CJ Failed带分类, 续跑新建
```

## 四、实验报告结论参考
- 顺序链：级联时点正确（ETCH 完成并交接成功才起 CLEAN），交接四校验拦截构造的清单不符，最终 6 片到 B、设备内空、集合守恒，CJ 事件仅 Executing/Completed。
- 并行汇合：两 PJ Start 时并行，一支先完 CJ 仍 Executing，汇合后 X∩Y 空、X∪Y=6、输出槽无冲突，唯一计数 6（加工次数 12），全完才 Completed；分支失败不假完成。

## 五、今日易错点
1. Start CJ 把所有 PJ 一起启动（后继等前驱完成+片就位+资源）。
2. PJ 交接不做清单/读码/守恒（责任缝隙丢片串片）。
3. 并行汇合按 PJ 加工次数计片（同一片流经多 PJ，CJ 按唯一 ID=6）。
4. 一个并行分支完成就 CJ Completed（要所有 PJ 完成且片全到输出）。
5. 分支选择条件不互斥导致同片走两路（交集必须空）。
6. 两片写同一输出槽（输出槽唯一，编译期/放置前拦截）。
7. 子 PJ 高频事件都转发成 CJ 事件（仅 CJ 层状态变化才发）。
8. 中间 PJ 失败还启动后继、或回退已完成前序片（前序保留、失败处置、后继阻断、续跑新建）。
