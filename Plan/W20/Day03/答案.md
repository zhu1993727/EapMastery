# W20 · Day03 答案与参考实现

## 一、自测题标准答案
1. **只读/必填举例**：只读（设备执行时计算、Host 不可写）——State（CJ 当前状态）、Progress（整体进度）、CurrentPJ（当前活动 PJ）、完成/失败计数、开始/完成时间戳、最终结果；创建必填（Host 下发）——CjId、输入/输出载具及其角色、PJ 编排（有序 PJ 与依赖）、ControlJobMap（片流），LotId/优先级按 FAB 要求。只读属性被 S15F7 改写回 ACKC5，创建缺必填回 ACKC6、类型不符回 ACKC7、CjId 重复回 ACKC3。
2. **Create(CJ) 额外校验**：除 OSS 通用校验（对象类存在、属性存在、类型、必填、ID 不重复）外，必须过 Day02 的 CjDefinitionValidator 六不变量——至少一个 PJ、PJ 顺序唯一、依赖 DAG 无环、每片有完整输入到输出路径无断头、片不重复分配且输出槽唯一、片集合守恒、载具角色合法、后继来源合法。因为 CJ 是编排对象，其合法性核心在跨 PJ 片流与依赖自洽，通用属性校验查不出"断头/成环/串片"，必须做结构校验，不通过则拒绝创建（对应类型/参数类 ACKC），不进入 Queued。
3. **Start(CJ) 内部级联链**：ACKC 受理后，先做开工校验（输入/输出载具都已 E87 Loaded、绑定口与载具 ID 一致、各 PJ 定义与配方版本齐、所需资源可用、无阻断 Hold/Alarm）；通过后 CJ 状态 Queued→Started→Executing；随后按编排依赖图，把**当前可启动的 PJ**（无未满足依赖者，通常是首个 PJ 或并行分支的首批 PJ）逐个用 E40 机制 Create+Start（复用 ProcessJobController/状态机/多腔调度），并建立 CJ→PJ 的运行时关联；后继 PJ 先不启动，等其依赖的前驱 PJ 完成、输出片就位再级联启动。即 Start 一个 CJ，内部会"派生"出若干真正干活的 PJ。
4. **CJ 事件与 PJ 事件关系 / Host 用法**：两层事件都发、各司其职。子 PJ 的 S16 事件（PJ Started/StepEnter/WaferDone/PJ Done 等，E40 层）照常发，描述细粒度执行；CJ 订阅其所有子 PJ 事件，据此更新聚合状态（进度、当前 PJ、计数）并在 CJ 层状态变化时发 CJ 事件（CJ Started/PJ 切换/进度/Paused/Completed/Aborted）。Host 做精细监控/工艺数据时用 PJ/片级事件，做批次整体追踪与派工管理时主要看 CJ 事件即可；二者通过 CJ id/PJ id 关联，数据同源、序号单调。
5. **ACKC0 不代表 Executing**：S15F9/F10 的 ACKC0 是同步受理应答，只表示方法合法、被接受；Start 之后还要异步完成开工校验、状态迁移、级联创建并启动首个 PJ，这些可能失败（载具没 Loaded、资源忙、Hold）或需要时间。真正进入 Executing 以状态迁移成功后的 S16 CJ Started（及首个 PJ Started）事件为准。若 Host 拿 ACKC0 当已执行，可能在 CJ 还停在 Queued（校验失败）时误判已开工。校验失败时回非 0、CJ 停留 Queued、零副作用。
6. **后继 PJ 何时创建/启动**：后继 PJ 的启动条件=其依赖的前驱 PJ 已完成（DependsOn 满足）**且**前驱产出的片已到达它所需的输入位置（在中间载具/Buffer、身份核对一致）**且**开工所需资源可用。满足时由 CJ 编排器级联 Create+Start；前驱未完成或输出片未就位时后继保持等待（不提前创建为运行态，避免占用资源、避免对还不存在的片操作）。并行分支里无依赖关系的 PJ 可在 CJ Start 时同批启动。本质是"依赖就绪+片就位+资源可用"三者齐备。
7. **完整派工步骤**：①载具就绪——E84 上料去抖在位→E87 Installed→预约核对→Loaded，E90 注册 SlotMap 与基线；②Host 经 S14 知晓 CJ/PJ 对象定义；③S15 Create CJ（载具/PJ 编排/Map）过静态六校验，ACKC0，Queued；④（可选）查询确认 CJ 属性；⑤S15 Start CJ，ACKC0 受理，开工校验通过后 Executing 并级联启动首批 PJ；⑥执行中 PJ 事件→CJ 聚合发 CJ 事件，按依赖级联启动后继 PJ，多腔并发、片在层间流动、每拍守恒；⑦所有 PJ Completed、片到输出载具声明槽、终验守恒→CJ Completed 事件；⑧UnloadGuard 放行→E87 Unload→E84 Pickup 下料。异常时 Pause/Resume/Abort 作用于 CJ 并级联活动 PJ（W21）。

### CJ S15 服务（Create/方法 + 级联起 PJ）
```csharp
namespace EapLab.E94;
public sealed class CjHostService
{
    private readonly Dictionary<string,ControlJobRuntime> _cjs=new();
    private readonly CjDefinitionValidator _val=new();
    private readonly CarrierManager _carriers; private readonly PjFactory _pjf;
    public event Action<string,CjEvent>? OnCjS16;
    public CjHostService(CarrierManager c,PjFactory f){_carriers=c;_pjf=f;}

    public Ackc Create(ControlJobDefinition def)
    { if(_cjs.ContainsKey(def.CjId))return Ackc.AlreadyExists;
      var issues=_val.Validate(def);
      if(issues.Any(i=>i.Code==CjIssueCode.NoPj))return Ackc.BadParam;
      if(issues.Any())return Ackc.TypeMismatch;
      _cjs[def.CjId]=new ControlJobRuntime(def); return Ackc.Ok; }

    public Ackc Start(string cjId)   // 受理; 生效以S16为准
    { if(!_cjs.TryGetValue(cjId,out var cj))return Ackc.NoInstance;
      if(cj.State!=CjState.Queued)return Ackc.IllegalState;
      if(!ReadyToStart(cj))return Ackc.IllegalState;     // 载具Loaded/绑口/资源/Hold
      cj.State=CjState.Executing;
      foreach(var link in StartablePjs(cj))             // 级联创建并启动首批PJ
      { var pj=_pjf.Create(link.Def); cj.PjRuntime[link.PjId]=pj; _pjf.Start(pj); }
      Raise(cjId,new CjEvent(CjCeid.Started,cjId)); return Ackc.Ok; }

    // 依赖就绪+片就位+资源可用 才启动后继
    public void OnPjDone(string cjId,string pjId)
    { var cj=_cjs[cjId];
      foreach(var link in StartableAfter(cj,pjId)){ var pj=_pjf.Create(link.Def); cj.PjRuntime[link.PjId]=pj; _pjf.Start(pj);}
      if(cj.PjRuntime.Values.All(p=>p.State==JState.Completed)) TryComplete(cjId); }

    bool ReadyToStart(ControlJobRuntime cj)=>
        cj.Def.Carriers.All(c=>_carriers.IsLoaded(c.CarrierId));   // 载具Loaded(并核口/ID, 略)
    static IEnumerable<PjLink> StartablePjs(ControlJobRuntime cj)=>cj.Def.Pjs.Where(p=>p.DependsOn.Count==0);
    IEnumerable<PjLink> StartableAfter(ControlJobRuntime cj,string done)=>cj.Def.Pjs
        .Where(p=>!cj.PjRuntime.ContainsKey(p.PjId) && p.DependsOn.All(d=>cj.PjRuntime.TryGetValue(d,out var x)&&x.State==JState.Completed));
    void TryComplete(string id){ var cj=_cjs[id]; cj.State=CjState.Completed; Raise(id,new CjEvent(CjCeid.Completed,id)); }
    void Raise(string id,CjEvent e){OnCjS16?.Invoke(id,e);}
}
public enum CjCeid{Started=6101,PjEnter=6102,Progress=6103,Paused=6105,Completed=6104,Aborted=6106}
public sealed record CjEvent(CjCeid Ceid,string CjId);
public interface PjFactory{ ProcessJob Create(ProcessJobDefinition d); void Start(ProcessJob p); }
```

public class CjOssTests

## 三、Host 派工时序（手绘参考）
```
E84→E87 Loaded; E90注册
 S14取CJ/PJ定义 → S15 Create CJ(过六不变量)→ACKC0/Queued
 S15 Start CJ → ACKC0(受理) → 开工校验(载具Loaded/绑口/配方/资源/Hold)
   → CJ Executing → 级联Create+Start首批无依赖PJ(E40全套)
 PJ事件 → CJ聚合(进度/当前PJ)发CJ事件; 前驱完成+片就位+资源→级联后继
 全部PJ Completed + 片到输出载具 + 终验守恒 → CJ Completed(6104)
 UnloadGuard → Unload → Pickup
铁律: ACKC=受理, S16=生效; 事件迁移后发/同源/序号; 后继=依赖+片就位+资源
```

## 四、今日易错点
1. Create CJ 只做通用属性校验（必须过跨 PJ 六不变量，查断头/成环/串片）。
2. 把 Start 的 ACKC0 当 Executing（受理而已，以 S16 Started 为准）。
3. CJ Start 时一次性把所有后继 PJ 都启动（后继要等前驱完成+片就位+资源）。
4. CJ 直接操作硬件/位置（级联 PJ，由 PJ→E90 改位置，CJ 只编排）。
5. 只读 State 允许 S15F7 改（回 ACKC5，状态只由状态机迁移）。
6. 开工校验失败还迁移状态（回非 0、停留 Queued、零副作用）。
7. CJ 事件与 PJ 事件混为一层、数据两份（PJ 发细粒度、CJ 聚合，同源关联）。
8. 事件在状态迁移前发（必须迁移成功后发、序号单调）。
9. 忽略载具必须 Loaded 且绑口/ID 核对才允许 CJ Start。
