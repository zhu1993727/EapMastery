# W20 · Day04 答案与参考实现

## 一、自测题标准答案
1. **两类依赖 / 例子**：控制依赖回答"PJ 什么时候能启动"（B DependsOn A，A 到某阶段/完成后 B 才启动）；片流依赖回答"B 加工的片从哪来、是谁"（B 的输入片集合由 A 的输出提供）。有控制依赖但无片流交接的例子：PJ-A 是腔体清洗/调机作业，必须先完成（控制上 B 要等 A），但 A 不产出工件片，PJ-B 直接从输入载具取生产片加工——B 等 A 启动，却不接收 A 的片。反过来也可能有片流而启动时机由资源决定，二者是两条正交的约束，建模时要分别表达，不能混为一谈。
2. **四结构示意**：
```
顺序: Source→PJ_A→PJ_B→PJ_C→Sink
并行: Source→┬PJ_A→┐
             └PJ_B→┴→(汇合)→Sink
汇合: PJ_A─┐
          ├→PJ_C→Sink ; PJ_B─┘   (A/B输出合给C或同一输出载具)
回流: Source→PJ_A→(判定)─合格→Sink
                    └不合格(第k轮,k<N)→回到PJ_A重做
```
3. **交接四校验 / 为何危险**：①交接清单一致——前驱输出片集合与后继输入片集合相等（分支/汇合时是显式约定的子集，不能多不能少）；②身份核对——交接取片时读码，片 ID 与交接清单预期一致（防串片）；③位置确定可用——片在约定的中间载具/Buffer 槽、该位置 Loaded/可用、未 Hold；④全局守恒——交接前后片总数与 ID 集合不变。跨 PJ 边界和跨载具一样危险，因为这里是"两个执行单元的责任交接面"：前驱认为已交出、后继若没正确接收，片就会掉在缝隙里（无主、重复或丢失），且 PJ 各自记账，最易出现"两边都以为对方管"的真空，所以必须像跨盒一样做显式清单+读码+守恒核对。
4. **编译器产出 / 编译期错误**：为每片产出①工艺路径（有序经过的 PJ 序列与各自 Step）、②物理路径（从哪个输入槽、经哪些中间位置、到哪个输出槽），同时为每个 PJ 算出期望输入/输出片集合。编译期可查出：到不了 Sink 的片（断头）、没有任何片流经的空 PJ、输入声明了但图里没有来源的片、两片竞争同一输出槽（汇合冲突）、引用不存在节点、片集合不守恒（某些片既不流向输出也不进入合法回流）、分支条件未覆盖导致某片无路径。这些都是静态结构错误，应在 Create/编译阶段拒绝，而不是运行到一半才发现。
5. **回流为何允许 / 避免死循环**：DAG 无环约束的是"PJ 节点的控制依赖图"（启动关系不能成环），而回流是**同一批片对同一个 PJ 的新一轮加工实例**，不是让控制依赖图成环——用"轮次/实例号"区分第 1 次、第 2 次进 PJ_A，逻辑上是 PJ_A 的不同执行实例沿时间推进，仍有向出口。避免死循环：定义时显式给出最大返工次数 N 和退出条件（合格即出、达到 N 次强制出到隔离/报废分支），运行时记录每片当前轮次，超过 N 不再回流，保证每片最终必达某个 Sink（成品或隔离），不会无限循环。
6. **分支条件定义期保证**：运行时按量测结果才确定某片走哪条边，但定义期必须保证：①候选分支闭合——所有可能的结果都有对应边（Good/Recheck/Reject 全覆盖，含 else/默认分支），不会出现某结果无路可走；②目标节点都已定义存在；③各分支的输出槽/汇合点不冲突；④无论走哪条分支，片最终都能到 Sink（每条候选路径都完整、守恒）。即"运行时选择、定义时穷举"，把不确定性限制在已闭合的候选集合内。
7. **中间堆积管理**：前驱快、后继慢时，片在中间 Buffer/中间载具排队，靠 W18 的资源容量与调度约束：每个中间位置容量有限（槽/Buffer 位容量 1），全局资源日历统一安排前驱"放入"与后继"取走"的时间区间，放不下时前驱等待（背压 back-pressure），不超容量、不叠片；同时全局守恒始终包含这些在制片（WIP），交接清单记录哪些片在中间等待。本质是把 PJ 间交接点也建模成有限容量资源，纳入同一调度与守恒体系。

## 二、参考实现（net8.0）

### 片流图
```csharp
namespace EapLab.E94.Flow;
public sealed record FlowEdge(string From,string To,Func<string,bool>? Select=null,string Label="");
public sealed class FlowGraph
{
    public HashSet<string> Nodes{get;}=new();
    public List<FlowEdge> Edges{get;}=new();
    public FlowGraph Node(string n){Nodes.Add(n);return this;}
    public FlowGraph Edge(string f,string t,Func<string,bool>? sel=null,string lab=""){Nodes.Add(f);Nodes.Add(t);Edges.Add(new(f,t,sel,lab));return this;}
    public IEnumerable<string> Out(string n)=>Edges.Where(e=>e.From==n).Select(e=>e.To);
    // 每片从source到sink的路径(运行时按选择条件; 定义期要求候选闭合)
    public List<string> PathOf(string wafer,string source,string sink)
    { var path=new List<string>{source}; var cur=source; var guard=new HashSet<string>{source};
      while(cur!=sink)
      { var next=Edges.FirstOrDefault(e=>e.From==cur&&(e.Select is null||e.Select(wafer)));
        if(next is null)throw new InvalidOperationException($"{wafer}在{cur}断头(无候选边)");
        if(!guard.Add(next.To) && !next.To.Contains("Rework"))throw new InvalidOperationException("片流成环");
        cur=next.To; path.Add(cur); if(path.Count>1000)throw new InvalidOperationException("路径异常超长(疑似死循环)"); }
      return path; }
}
```

### PJ 间交接
```csharp
public sealed record Handover(string FromPj,string ToPj,List<string> ExpectedWafers,string AtLocation);
public sealed class PjHandover
{
    private readonly SubstrateTracker _t; public PjHandover(SubstrateTracker t){_t=t;}
    public void Verify(Handover h,HashSet<string> produced,HashSet<string> consumed)
    { if(!new HashSet<string>(produced).SetEquals(consumed))           // ①清单一致
        throw new InvalidOperationException($"交接清单不一致 {h.FromPj}->{h.ToPj}");
      foreach(var w in h.ExpectedWafers)
      { var actual=_t.ReadIdAt(h.AtLocation,w);                       // ②读码身份核对
        if(actual!=w)throw new InvalidOperationException($"交接身份不符 期望{w} 实读{actual}");
        if(!_t.IsStable(h.AtLocation))throw new InvalidOperationException("交接位置不稳定/不可用"); }
      _t.AssertInvariants(); }                                        // ④守恒
}
```

### ControlJobMap 编译器
```csharp
public sealed record WaferRoute(string Wafer,List<string> PjSequence,SlotRef Src,SlotRef Dst);
public sealed class MapCompiler
{
    public List<WaferRoute> Compile(FlowGraph g,ControlJobDefinition d,string sink)
    { var routes=new List<WaferRoute>();
      foreach(var w in d.InputWaferIds)
      { var path=g.PathOf(w,SourceOf(d,w),sink);
        var pjs=path.Where(n=>n.StartsWith("PJ_")).ToList();
        if(pjs.Count==0)throw new InvalidOperationException($"{w}无PJ可加工");
        routes.Add(new WaferRoute(w,pjs,SlotOf(d,w),DstOf(d,w,path))); }
      // 每个PJ期望输入/输出集合 + 守恒
      var touched=routes.SelectMany(r=>r.PjSequence).ToHashSet();
      foreach(var p in d.Pjs)if(!touched.Contains(p.PjId))throw new InvalidOperationException($"{p.PjId}无片流经(空PJ)");
      var all=routes.Select(r=>r.Wafer).ToHashSet();
      if(!all.SetEquals(d.InputWaferIds))throw new InvalidOperationException("片集合不守恒");
      var dstDup=routes.GroupBy(r=>r.Dst.ToString()).FirstOrDefault(g=>g.Count()>1);
      if(dstDup is not null)throw new InvalidOperationException($"输出槽冲突{dstDup.Key}");
      return routes; }
    static string SourceOf(ControlJobDefinition d,string w)=>"SRC";   // 教学简化
    static SlotRef SlotOf(ControlJobDefinition d,string w)=>new("A",1);
    static SlotRef DstOf(ControlJobDefinition d,string w,List<string> path)=>new("B",1);
}
```

## 三、片流编排（手绘参考）
```
控制依赖(DAG,启动先后) ‖ 片流依赖(谁的片给谁) —— 两条正交
顺序 A→B→C / 并行Fork / 汇合Join / 回流(同PJ新实例+轮次上限N+退出条件)
编译器: 片流图+输入清单 → 每片[工艺路径PJ序列 + 物理路径Src→Sink] + 每PJ期望输入输出
  编译期拒绝: 断头/空PJ/来源缺失/输出槽冲突/集合不守恒/分支未闭合
PJ间交接(跨责任面): 清单一致→读码身份→位置可用→全局守恒 (同跨载具级别危险)
背压: 中间Buffer有限容量, 进全局资源日历, 放不下前驱等待, WIP计入守恒
```

## 四、今日易错点
1. 把控制依赖和片流依赖当一回事（一个管启动时机、一个管片给谁，正交）。
2. PJ 间交接不做清单/读码/守恒（责任缝隙最易丢片串片）。
3. 片流图有断头/空 PJ/输出槽冲突却到运行时才暴露（编译期静态拒绝）。
4. 回流让控制依赖成环、无返工上限（用 PJ 实例+轮次+最大次数+退出条件）。
5. 分支条件运行时选、定义期不穷举（候选路径必须闭合、每条都到 Sink）。
6. 中间堆积不建容量/背压（交接点是有限资源，纳入全局调度与守恒）。
7. 在 CJ 层重复实现 PJ 内部路线（CJ 只管跨 PJ 的边，内部归 E40/E90）。
8. 跨 PJ 守恒按单个 PJ 比对（要以整个 CJ 为范围做片 ID 集合守恒）。
