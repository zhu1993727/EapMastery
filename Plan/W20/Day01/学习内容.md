## 二、背景知识（先读，40 分钟）

### 1. 为什么需要 E94（从问题出发）
- E40 ProcessJob 描述"一组片走一条工艺路线"，但一批料的完整生产往往：跨多个源/目标载具、包含多个工艺段（不同路线/配方）、PJ 之间有先后或依赖。
- 若 Host 直接逐个下发 PJ，就要自己维护：用哪些载具、PJ 谁先谁后、上一个 PJ 产出如何成为下一个输入、整体成败与进度——复杂且易不一致。
- E94 ControlJob 提供一个**上层容器与编排对象**：一次描述"从哪些源载具、经过哪些 ProcessJob、产出到哪些目标载具"，Host 以 CJ 为单位派工，设备负责拆成 PJ 执行并汇总状态。

### 2. 三层作业模型（核心，务必能默写）
```
ControlJob (E94)          业务/批次层: 派工单位, 跨载具, 编排多个PJ
   ├ ProcessJob (E40)     加工层: 一条工艺路线, 一组片, 在一组模块上加工
   │    └ Wafer/Step      片/步骤层: 每片逐Step加工(E90管其物理位置)
   ├ ProcessJob
   └ ProcessJob
载具(E87/E90): CJ 声明源载具(Input)与目标载具(Output), 片在其中流动
```
- **CJ（控制作业）**：回答"这批料从哪几个盒来、经过哪些加工、到哪几个盒去、整体到什么状态"。面向 Host/MES 的派工与批次追踪。
- **PJ（过程作业，E40）**：回答"某组片按哪条路线、什么配方、在哪些模块加工"。面向设备调度执行（W16-W19 已精通）。
- **Wafer/Step**：回答"每一片现在哪个 Step、在哪个物理位置、什么工艺状态"，物理位置由 E90 唯一管理。

### 3. 层间数据流
- CJ 持有 ControlJobMap：声明输入载具槽位的片如何分配到各 PJ、各 PJ 产出如何汇到输出载具（本质是跨 PJ 的片流向规划，W15 CrossMap/W19 多 PJ 的标准化）。
- CJ 启动时按编排依次/并行创建并启动其 PJ（复用 E40 全套机制）；PJ 执行结果与片位置向上汇聚成 CJ 进度与状态。
- 片在物理上始终由 E90 位置层管理，CJ/PJ 都不直接改位置，只编排与记录（单一事实源不变）。

### 4. E94 与其他标准的依赖（为什么 E94 放最后学）
- 依赖 **E39 OSS**：CJ/PJ 都是 OSS 对象，S14 定义、S15 创建/方法、S16 事件（W09/W10）。
- 依赖 **E40 PJ**：CJ 编排的执行单元是 PJ，没有 E40 就没有可编排对象（W16-W19）。
- 依赖 **E90 基板跟踪**：片在跨 PJ、跨载具流动时的位置与守恒（W14/W15）。
- 依赖 **E87 载具管理**：CJ 的输入/输出载具必须 Loaded、授权、绑定正确（W12/W13）。
- 依赖 **E30 GEM/E5**：状态、事件、远程命令、通信底座（W02-W08）。
- 结论：E94 是"集大成"的上层，硬啃 E94 而不懂下层只会是黑盒；你现在已具备全部下层基础。

### 5. CJ 的典型形态（先进 FAB）
- 单 CJ 单 PJ：最简单（一批片一条路线），CJ 退化为 PJ 的薄封装。
- 单 CJ 多顺序 PJ：蚀刻 PJ→清洗 PJ→沉积 PJ，前一个输出是后一个输入。
- 单 CJ 多并行 PJ：不同片分组并行走不同路线后汇合。
- 多载具：多输入盒合批、分档到多输出盒（W19 复杂布局在 CJ 层的正式表达）。

### 6. CJ 生命周期骨架（W21 展开状态机）
- 定义/创建（S14/S15）→校验（载具/PJ/片流自洽）→Queued→Start→依次/并行驱动 PJ→全部 PJ 完成且片到输出载具→Completed；支持 Pause/Resume/Cancel/Abort，状态由子 PJ 聚合（级联是 W21 重点）。
