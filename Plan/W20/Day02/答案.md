# W20 · Day02 答案与参考实现

## 一、自测题标准答案
1. **七类属性 / 举例**：①标识类——CJ ID、LotId、优先级、创建时间；②状态类——CJ 状态、整体进度百分比、当前活动 PJ；③载具类——输入载具列表、输出载具列表及角色（Input/Output/InOut）与口绑定；④片流类——ControlJobMap（输入槽→PJ→输出槽的映射、片路径）；⑤PJ 编排类——有序 PJ 列表、PJ 间依赖（顺序/并行/DAG）、各 PJ 路线引用；⑥进度结果类——总片数/完成/在制/失败计数、每片当前 PJ/Step/位置、All/Partial 结果；⑦时间审计类——创建/开始/完成时间、配方版本、操作者、事件轨迹。
2. **Definition/Runtime 分离原因**：Definition 是 Host 下发的纯数据计划（源目载具、PJ 编排、片流），可序列化、可静态校验、与当前设备是否在位无关；Runtime 是设备执行时的活状态（状态机、进度、载具实际绑定口、片实际位置/经过腔体）。分离后：同一定义可校验后再实例化、重启时可用持久化的 Definition+运行事件重建 Runtime（W17 思路）、静态计划不被运行态污染、便于测试（拿固定 Definition 重复跑）。若混在一起，计划数据和易变状态耦合，无法独立校验、难以重建与复现。
3. **ControlJobMap / 与 WaferMap、CrossMap 关系**：ControlJobMap 描述片在**整个 CJ 层**的流动：输入载具槽的片分给哪个 PJ、PJ 产出再流向哪个后继 PJ、最终落到哪个输出载具槽，即跨 PJ、跨载具的片路径。它是 E40 WaferMap（单个 PJ 内源→目标）和 W15 CrossMap（交叉取放的源目槽映射）的**上层组合与一般化**：一个 PJ 内部用 WaferMap 描述该段源目，跨 PJ/跨盒衔接用 CrossMap 思想描述自由指定的源目，ControlJobMap 把这些段串成全流程路径。下层机制（守恒、六道校验）不变，CJ 层增加跨 PJ 的路径完整性校验。
4. **六不变量**：①CJ 至少 1 个 PJ，PJ 标识/顺序唯一；②片流引用一致，每片恰有一条输入到输出的完整路径，PJ 依赖 DAG 无环；③片不重复分配（输入槽不被两条互斥路径共用、输出槽唯一不冲突）；④片集合守恒（所有 PJ 处理片集合==输入集合==输出集合，跨 PJ 不丢不增）；⑤载具角色合法（输入片只来自声明 Input/InOut 的载具，输出只写入声明 Output/InOut）；⑥依赖合法（后继 PJ 的输入由前驱 PJ 输出或输入载具提供，不能引用不存在的来源）。
5. **完整路径校验 / 断头环**：把 PJ 当节点、片流/依赖当有向边，从每个输入槽的片出发沿"输入载具→首个 PJ→后继 PJ→输出载具"遍历：必须最终到达某个输出槽（完整路径）。断头=某片流经某个 PJ 后没有后继边也没连到输出载具（片"断"在中间，无去向）；环=PJ 依赖或片流形成闭合回路（A 输出给 B、B 又输出给 A 且无出口，DAG 成环，无法确定起始、会死循环）。用拓扑排序/可达遍历检测：有输入片到不了输出即断头，拓扑排序排不完即有环。
6. **后继 PJ 输入的两种合法来源**：①来自前驱 PJ 的输出（前道加工完的片作为后道输入，顺序/依赖衔接，如蚀刻 PJ 输出→清洗 PJ 输入）；②直接来自 CJ 输入载具（该 PJ 不从其他 PJ 取片，而是从源载具取原始片，常见于并行分支各自从输入取片）。除此之外引用了既非前驱输出、又非输入载具的来源即非法（来源不存在，违反不变量⑥）。
7. **双向导航用途**：向下（CJ→PJ→Wafer→Step/位置）用于执行编排与进度汇总——CJ 启动时找到要创建的 PJ、PJ 找到要加工的片，统计整体完成度；向上（Wafer→PJ→CJ）用于追溯与状态聚合——某片出问题时快速定位它属于哪个 PJ、哪个 CJ（批次），某 PJ 状态变化时通知所属 CJ 重新聚合整体状态，片级报警/良率数据向上关联到批次。载具导航则用于把逻辑片流绑定到 E87 实际载具与 E90 槽位。

### 六不变量校验器
```csharp
public enum CjIssueCode{NoPj,DuplicatePjOrder,DanglingFlow,CyclicDep,
    DuplicateInputAssign,DuplicateOutputSlot,SetNotConserved,BadCarrierRole,UnknownSource}
public sealed record CjIssue(CjIssueCode Code,string Detail);
public sealed class CjDefinitionValidator
{
    public List<CjIssue> Validate(ControlJobDefinition d)
    {
        var iss=new List<CjIssue>();
        if(d.Pjs.Count==0)iss.Add(new(CjIssueCode.NoPj,"CJ至少一个PJ"));
        var orders=d.Pjs.Select(p=>p.Order).ToList();
        if(orders.Distinct().Count()!=orders.Count)iss.Add(new(CjIssueCode.DuplicatePjOrder,"PJ顺序号重复"));

        var pjIds=d.Pjs.Select(p=>p.PjId).ToHashSet();
        // 依赖有环(DAG拓扑)
        if(HasCycle(d.Pjs))iss.Add(new(CjIssueCode.CyclicDep,"PJ依赖成环"));

        // 片流: 输入分配唯一 / 输出槽唯一 / 来源合法 / 每片可达输出(断头)
        var inAssign=new HashSet<string>(); var outSlot=new HashSet<string>();
        var carriers=d.Carriers.ToDictionary(c=>c.CarrierId,c=>c.Role);
        foreach(var f in d.Map.Flows)
        {
            if(IsCarrierSlot(f.From)){ if(!inAssign.Add(f.From))iss.Add(new(CjIssueCode.DuplicateInputAssign,f.From));
                var c=f.From.Split(':')[0]; if(carriers.GetValueOrDefault(c)==CarrierRole.Output)iss.Add(new(CjIssueCode.BadCarrierRole,f.From)); }
            else if(!pjIds.Contains(f.From))iss.Add(new(CjIssueCode.UnknownSource,f.From)); // 来源须是输入槽或已知PJ
            if(IsCarrierSlot(f.To)){ if(!outSlot.Add(f.To))iss.Add(new(CjIssueCode.DuplicateOutputSlot,f.To));
                var c=f.To.Split(':')[0]; if(carriers.GetValueOrDefault(c)==CarrierRole.Input)iss.Add(new(CjIssueCode.BadCarrierRole,f.To)); }
            else if(!pjIds.Contains(f.To))iss.Add(new(CjIssueCode.DanglingFlow,f.To));
            if(!pjIds.Contains(f.PjId))iss.Add(new(CjIssueCode.UnknownSource,f.PjId));
        }
        // 可达性: 每个输入片最终到输出槽(断头检测, 简化: 从From做流图遍历)
        foreach(var w in d.InputWaferIds) if(!ReachesOutput(d,w))iss.Add(new(CjIssueCode.DanglingFlow,w));
        // 集合守恒: 所有PJ处理集合 == 输入集合 (教学: 由Map统计)
        var pjSet=new HashSet<string>(); foreach(var f in d.Map.Flows) if(IsCarrierSlot(f.From)) pjSet.UnionWith(ExtractWafers(f.From));
        if(!pjSet.SetEquals(d.InputWaferIds))iss.Add(new(CjIssueCode.SetNotConserved,"PJ处理集合≠输入集合"));
        return iss;
    }
    static bool IsCarrierSlot(string x)=>x.Contains(':');
    static IEnumerable<string> ExtractWafers(string s)=>new[]{s.Split(':')[1]};
    bool HasCycle(List<PjLink> pjs)
    { var g=pjs.ToDictionary(p=>p.PjId,p=>p.DependsOn); var color=new Dictionary<string,int>();
      bool dfs(string n){ color[n]=1; foreach(var m in g.GetValueOrDefault(n,new()))
        { if(color.GetValueOrDefault(m)==1)return true; if(color.GetValueOrDefault(m)==0&&dfs(m))return true; }
        color[n]=2; return false; }
      return pjs.Any(p=>color.GetValueOrDefault(p.PjId)==0&&dfs(p.PjId)); }
    bool ReachesOutput(ControlJobDefinition d,string w)=> /* 沿FlowNode遍历到carrier:slot, 教学略 */ true;
}
```

public class CjModelTests

    static ControlJobDefinition Good()=>new CjBuilder("CJ1")

## 三、CJ 对象树（手绘参考）
```
ControlJobDefinition(计划, 可序列化/静态校验)
 ├ Carriers: A(Input,LP1) B(Output,LP2)
 ├ Pjs[PjLink]: PJ_ETCH(order1) → PJ_CLEAN(order2,depends ETCH)  [DAG无环]
 └ Map.Flows: A:S1 →ETCH→ CLEAN → B:S1 (每片一条完整路径, 输出槽唯一)
ControlJobRuntime(运行): 状态机 + 各PJ Runtime + 实际绑口/实际位置
   向下: CJ→PJ→Wafer/Step(执行/汇总); 向上: Wafer→PJ→CJ(追溯/聚合)
校验六不变量: 有PJ/路径完整无环/不重复分配/集合守恒/载具角色/来源合法
复用: E40 ProcessJobDefinition/Validator, E90位置, E87载具
```

## 四、今日易错点
1. CJ 定义与运行状态混在一起（Definition 纯数据、Runtime 持状态，分离才好校验/重建）。
2. 只建 PJ 列表不建跨 PJ 片流（ControlJobMap 才是 CJ 的核心编排信息）。
3. 不校验 PJ 依赖成环/片流断头（DAG 拓扑+可达遍历必须做）。
4. 允许两片写同一输出槽或同一输入片被两条互斥路径分配。
5. 跨 PJ 不做片集合守恒（所有 PJ 处理集合必须==输入==输出）。
6. 载具角色不校验（从 Output 取片、往 Input 写片都是非法）。
7. 后继 PJ 引用既非前驱输出也非输入载具的来源。
8. 在 CJ 层重写一套 PJ/位置模型（复用 E40/E90，CJ 只加跨 PJ 校验与编排）。
