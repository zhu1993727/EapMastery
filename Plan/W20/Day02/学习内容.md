# W20 · Day02（周二）ControlJob 对象模型：属性、载具关联与对象关系树

> 建议时长：90 分钟。今天把 ControlJob 作为标准 OSS 对象建模：它有哪些关键属性、如何关联输入/输出载具与 ProcessJob、CJ-PJ-Wafer 对象树如何组织，并用 C# 建成可校验的对象模型。精确属性名以 SEMI E94 原文为准，这里用业界通用语义讲清机制。

## 一、今日目标
1. 掌握 ControlJob 的关键属性类别：标识、状态、载具、片流、进度、时间、结果。
2. 建立 CJ 与输入/输出载具、PJ、片（Wafer）的对象关联与导航关系。
3. 实现 ControlJob 对象树与基本不变量（CJ 至少一个 PJ、载具被引用一致、片不重复分配）。
4. 区分定义（Definition）与运行实例（Runtime）两层对象。
5. xUnit 覆盖对象树构建、关联一致性、非法组合拒绝。

## 二、背景知识（先读，35 分钟）

### 1. 对象建模思路（沿用 E39/E40）
- 与 PJ 一样，CJ 分**定义**（静态：源目载具、PJ 编排、片流映射，来自 Host）与**运行实例**（动态：状态、进度、每片结果，设备执行时产生）。
- CJ 是 OSS 对象：有 ObjectClass、属性集合、方法（Start/Pause/...）、事件（W20 Day03、W21）。

### 2. ControlJob 关键属性类别（语义级）
- **标识类**：CJ ID（唯一）、Lot/批次关联、优先级、创建者/时间。
- **状态类**：CJ 状态（Queued/Executing/...，W21）、整体进度、当前活动 PJ。
- **载具类**：输入载具列表（源，含口绑定/预约）、输出载具列表（目标）；每个载具的角色（Input/Output/InOut）。
- **片流类（核心）**：ControlJobMap——输入载具槽位的片如何分配给各 PJ、PJ 产出如何到输出载具槽（跨 PJ/跨载具映射，W15/W19 的上层表达）。
- **PJ 编排类**：有序 PJ 列表 + 依赖关系（顺序/并行/DAG）、每 PJ 的工艺路线引用。
- **进度/结果类**：总片数、完成/在制/失败计数、每片当前 PJ/Step/位置、结果（All/Partial）。
- **时间/审计类**：创建/开始/完成时间、配方版本、操作者、事件轨迹。

### 3. 对象关系树（导航）
```
ControlJob
 ├ InputCarriers[] ── Carrier(E87) ── Slot/Wafer(E90)
 ├ OutputCarriers[]── Carrier ── Slot/Wafer
 ├ ProcessJobs[] (有序, 带依赖)
 │    └ ProcessJob(E40) ├ WaferMap/Route ├ Wafers[] └ Steps/Modules
 └ ControlJobMap: 输入槽→PJ→...→PJ→输出槽 的片流路径
```
- 向上导航：片→所属 PJ→所属 CJ；向下：CJ→PJ→片。载具被 CJ 引用并与 E87 实际载具绑定。
- 一片在 CJ 内有确定的"工艺路径"（经过哪些 PJ 的哪些 Step）和"物理路径"（从哪个输入槽到哪个输出槽）。

### 4. CJ 对象基本不变量（定义校验，今天实现）
1. CJ 至少含 1 个 PJ；每个 PJ 有唯一顺序号/标识。
2. 输入/输出载具被片流引用一致：每片有且仅有一条从输入到输出的完整路径，不断头、不环（PJ 依赖 DAG 无环）。
3. 片不重复分配：同一输入槽/片不会被分给两条互斥路径；输出槽唯一（不两片写同一目标槽）。
4. 片集合守恒：所有 PJ 处理的片集合==输入片集合==输出片集合（跨 PJ 不丢不增）。
5. 载具角色合法：被当输入的载具确实声明为 Input，输出同理，InOut 两用要显式。
6. 依赖合法：后继 PJ 引用的输入必须由前驱 PJ 输出或输入载具提供。

### 5. 定义 vs 运行实例
- Definition 可序列化（Host 下发）、纯数据、可静态校验、不含运行状态；Runtime 持有状态机、进度、实际载具绑定口、实际经过腔体。
- 运行时把 Definition + 当前载具/资源实例化，二者分离便于重启重建（W17 思路在 CJ 层复用）。

### 6. 与 PJ 对象模型的复用
- 直接复用 E40 的 ProcessJobDefinition/ProcessJob、PjMapValidator；CJ 校验器在其之上增加"跨 PJ 片流与依赖"校验，不重复造轮子。
