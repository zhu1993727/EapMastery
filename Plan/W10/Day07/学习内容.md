## 四、W11 预热：E84 LPT 并口交接（30 分钟）

### 1. E84 是什么 / 解决什么问题
- E84 = SEMI E84，**Local Parallel Transfer Interface（本地并行传输接口，LPT）**，规范"载具（FOUP/FOUP/Reticle Pod）在设备 Load Port（装载口）与 AMHS（天车/OHT/AGV 物料搬运系统）之间自动交接"时的**硬件握手信号**。
- 之前 W1-W10 学的 HSMS/SECS-II/GEM/OSS 都是**串行消息通道**（TCP/网口，软件报文）；E84 是另一套完全独立的通道——**并行硬线数字 I/O 信号**（一束信号线，每根线一个电平信号，同时并行传输），用于毫秒级、高可靠的物理动作互锁（Interlock）。
- 场景：天车把 FOUP 放到 Load Port、或从 Load Port 取走 FOUP 的过程中，双方通过 E84 信号确认"可以放/可以取/已放好/已取走/急停"，防止物理碰撞、掉落。

### 2. 为什么物理交接不用 TCP 消息而用硬线
- **确定性实时**：物理动作（天车移动、Load Port 开门/升降）是硬实时的，要求信号延迟确定（毫秒级），TCP 报文有调度/重传不确定性。
- **安全互锁**：交接安全不能依赖软件栈是否崩溃/网络是否通畅，硬线信号直达 PLC/安全回路，断电、死机也能保持安全态（故障安全 fail-safe）。
- **简单可靠**：并行 I/O 每根线语义固定，电平即状态，不经过协议栈解析，工业现场抗干扰、易诊断（示波器/万用表可量）。
- 因此：**E84 管"物理交接动作的硬握手"，SECS/GEM（E87）管"载具逻辑状态和信息管理"**，两者配合，W13 会做 E84+E87 自动上料综合。

### 3. E84 信号全貌（先建立框架，W11 逐类精讲）
E84 用两组方向相反的并行信号：
- **设备→搬运系统（Equipment→AMHS，"输出"信号）**：如 CS（Carrier System Ready/设备交接就绪）、ES（Equipment Ready to Transfer）、HO_0/HO_1（Hand-off，设备侧交接请求/确认）、TR_READY 等。
- **搬运系统→设备（AMHS→Equipment，"输入"信号）**：如 SS（Storage System Ready/搬运系统就绪）、VR（Vehicle Ready，小车就绪）、TR_REQ（Transfer Request，搬运请求）、BUSY、COMPT（Transfer Complete，交接完成）等。
- 还有双方共用的安全/互锁信号：VALID（信号有效）、ESTOP（急停）、BYPS（Bypass 旁路模式）等。
- 交接分两个方向：**Deposit（放货/上料，AMHS→设备放 FOUP）** 和 **Pickup（取货/下料，设备→AMHS 取走 FOUP）**，各自有一套握手时序（W11 Day03/Day04 分别精讲并手绘时序图）。

### 4. E84 与 E87/E90 的关系地图
```
物理层：E84 LPT 并口硬线 —— 负责 FOUP 在 Load Port 与天车之间的"放/取"硬握手
逻辑层：E87 Carrier Management —— 载具状态机（ID 绑定、预约、Load/Unload 逻辑状态），走 SECS
位置层：E90 Substrate Tracking —— FOUP 内晶圆槽位 SlotMap、基板位置跟踪
```
- 一次自动上料：天车到→E84 Deposit 握手放 FOUP→Load Port 就位→E87 载具状态转 LOADED 并上报 Host（S16/S6F11）→E90 读取 SlotMap→Host 建 ProcessJob。W13 把这条链完整串起来。
