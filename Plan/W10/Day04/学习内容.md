## 二、背景知识（先读，25 分钟）

### 1. FSM 五要素
- **State（状态）**：对象在某一时刻的稳定情形，如 QUEUED/EXECUTING/PAUSED/COMPLETED/ABORTED。
- **Trigger（触发/事件）**：引起状态变化的输入，如 Start/Pause/Resume/Abort/Complete，来自方法调用或内部工艺回调。
- **Transition（转换/边）**：(源状态, Trigger) → 目标状态，一条合法边。
- **Guard（守卫条件）**：转换前的布尔判断，条件不满足即使有合法边也不转换（如"只有片数>0 才能 Complete"）。
- **Action（动作）**：转换时执行的副作用——退出动作（离开源状态）、转换动作、进入动作（进入目标状态），如发 S16 事件、写日志、通知工艺执行器。

### 2. 状态机的标准画法（手绘规范，专家必备）
- 节点=状态（圆角框），初始态用实心圆箭头指出，终态用双圈。
- 边=转换，标注格式：`Trigger [Guard] / Action`（触发 [守卫] / 动作）。
- 每条边必须能回答：什么触发、什么条件下允许、转换时做什么、转到哪个状态、是否发事件。
- 非法组合（如 COMPLETED + Start）不画边，Fire 时拦截。

### 3. 通用状态机 API 设计
```
Configure(state)
   .OnEntry(action)            // 进入该状态动作
   .OnExit(action)             // 离开该状态动作
   .Permit(trigger, target)    // 无条件合法边
   .PermitIf(trigger,target,guard) // 带守卫的边
   .OnEntryRaiseEvent(ceid)    // 进入该状态自动触发 OSS 事件
Fire(trigger)                  // 尝试转换（非法抛异常/返回 false）
CanFire(trigger)               // 预判是否可转换
CurrentState / TransitionHistory
```
- 线程安全：Fire 加锁，状态转换是原子的。
- 转换流程（Fire 内部）：查边→查守卫→执行源状态 OnExit→改 CurrentState→执行目标 OnEntry（含 RaiseEvent）→记历史→触发 OnTransitioned 回调。

### 4. 状态机与 OSS 对象的关系（关键集成）
- ObjectInstance 持有一个 StateMachine（不再用裸字符串 TransitionTo）。
- 方法执行器（S15F9 的 executor）调用 stateMachine.Fire(trigger)，而不是直接改状态。
- OnEntryRaiseEvent 绑定 CEID：进入 EXECUTING 自动 RaiseEvent(4101 Started)，进入 COMPLETED 自动 RaiseEvent(4102)。
- 守卫里可读取对象属性/子对象状态（如 E94 父状态机的守卫检查子 PJ 状态，W21 用）。
- 这样状态合法性、事件触发、副作用全部收敛到状态机，业务代码只发 Trigger，不直接碰状态。

### 5. ProcessJob 迷你状态机（今天的样板）
```
状态：QUEUED(初始) / EXECUTING / PAUSED / COMPLETED(终) / ABORTED(终)
边：
  QUEUED    --Start-->   EXECUTING   [进入发 4101 Started]
  EXECUTING --Pause-->   PAUSED
  PAUSED    --Resume-->  EXECUTING
  EXECUTING --Complete--> COMPLETED [守卫:已加工片数==计划片数; 进入发 4102]
  PAUSED    --Abort-->   ABORTED    [进入发 4103]
  EXECUTING --Abort-->   ABORTED    [进入发 4103]
  QUEUED    --Abort-->   ABORTED
非法：COMPLETED/ABORTED 上任何 Trigger；EXECUTING 上 Start/Resume；QUEUED 上 Pause/Resume/Complete
```
