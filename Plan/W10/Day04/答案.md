# W10 · Day04 答案与参考实现

## 一、自测题标准答案
1. **FSM 五要素 / 边标注含义**：五要素——State 状态（对象某时刻的稳定情形）、Trigger 触发（引起变化的输入，来自方法调用或内部回调）、Transition 转换边（源状态+触发→目标状态）、Guard 守卫（转换前布尔条件，不满足则不转）、Action 动作（转换副作用：OnExit 退出动作、转换动作、OnEntry 进入动作，如发事件/写日志/驱动执行器）。边标注 `Trigger [Guard]/Action`：Trigger 是触发这条边的输入；[Guard] 是该边成立还需满足的条件（可省略表示无条件）；/Action 是走这条边时执行的副作用。专家看图时每条边都要能回答：什么触发、什么条件允许、做什么动作、转到哪、是否发事件。
2. **Fire 内部流程 / 非法转换拦截点**：①加锁（转换原子）；②根据 CurrentState+Trigger 查配置的转换表，找不到边→非法转换，抛异常或返回 false（拦截点1：无合法边）；③找到边，若有 Guard 则求值，Guard 返回 false→守卫不满足，拒绝转换（拦截点2：条件不满足）；④执行源状态 OnExit 动作；⑤更新 CurrentState=目标状态；⑥执行目标状态 OnEntry 动作（含 OnEntryRaiseEvent 自动触发事件）；⑦记录转换历史（源、触发、目标、时间）；⑧触发 OnTransitioned 全局回调；⑨解锁。非法转换在"查边"和"守卫"两个拦截点被挡住，状态保持不变，不产生任何副作用（OnExit/OnEntry 都不执行）。
3. **Permit vs PermitIf / 守卫不满足怎么办**：Permit(trigger,target) 声明无条件合法边——只要当前是源状态、收到该 trigger 就转换；PermitIf(trigger,target,guard) 声明带守卫的边——除了状态匹配，还要 guard() 返回 true 才转换，guard 是一个可读取对象属性/子状态的委托（如"已加工片数==计划片数才允许 Complete"）。同一 (state,trigger) 可配置多条 PermitIf（不同守卫到不同目标）+ 一条兜底 Permit，按配置顺序求值第一个守卫满足的边。守卫不满足时：状态机拒绝转换、CurrentState 不变、不执行任何动作/事件，Fire 返回 false 或抛 GuardNotSatisfied 异常（项目统一），由调用方决定如何应答 Host（通常回 ACKC=8 状态非法/条件不满足）。
4. **为什么业务只发 Trigger 不直接改状态**：①合法性集中保证——所有转换都经过状态机查边和守卫，业务代码无法绕过，杜绝非法状态（如 COMPLETED 又回 EXECUTING）；②副作用自动且一致——进入/退出动作、事件触发、历史记录由状态机统一执行，业务直接改字符串会漏掉发 S16 事件、漏日志，导致 Host 状态不同步；③可测试、可讲解——状态图即代码，所有合法/非法路径可枚举单测，对着状态机图就能给人讲清行为；④易扩展——新增状态/边只改配置，业务调用方不变；⑤并发安全——Fire 内部加锁原子转换，业务散改字符串无法保证原子。直接改状态等于绕过状态机这个"唯一状态管理者"（W5/W8 反复强调的原则）。
5. **OnEntryRaiseEvent 自动发事件 / 与 W09 RaiseEvent 关系**：配置状态时声明该状态绑定的 CEID（Configure(state).OnEntryRaiseEvent(ceid)），状态机在 Fire 流程第⑥步执行目标状态 OnEntry 时，调用持有它的 ObjectInstance.RaiseEvent(ceid)，由 W09 的事件机制按 EventDefinition.LinkedAttributes 快照属性、触发 EventRaised C# 事件→ObjectEventService 组 S16F1→（过订阅过滤）→Spool 发送。关系：状态机负责"什么时候该发哪个事件"（进入某状态即发对应 CEID），W09 的 RaiseEvent/ObjectEventService 负责"怎么采集快照并把事件发出去"，两者分工——状态机是事件的触发源，OSS 事件服务是事件的发送通道。这样业务无需在每个方法里手写"转状态+发事件"，转换即事件，不会漏发。
6. **终态为什么拦截所有 Trigger / 不拦截后果**：COMPLETED/ABORTED 是终态，对象生命周期已结束，语义上不应再发生任何状态变化。拦截所有后续 Trigger 的原因：①防止已完成/已中止的 Job 被意外 Start/Pause/Resume，产生"死而复生"的非法对象；②保证终态不可变，Host 一旦收到终态事件就能确定该对象不再变化，可安全做统计、清理、删除；③防止资源和状态混乱（已 Abort 的工艺若再 Complete，会重复上报、错误计数）。不拦截的后果：状态机进入未定义路径（没有配置的边）或被错误地转回工作态，Host 收到矛盾的事件序列（先 Completed 又 Started），状态机不变式被破坏，可能引发重复加工、重复上报、对象无法删除等严重问题。实现上终态不配置任何出边，任何 Trigger 都在查边环节被拦截。
7. **ProcessJob 迷你状态机（手绘标准图，文字版）**：
   ```
         Start                Pause
   QUEUED ───────► EXECUTING ◄───────┐
     │  ▲            │  ▲            │
     │  │ Resume     │  └──────────► PAUSED
     │  └────────────┘                  │
     │ Abort         │ Complete[片数达标]│ Abort
     │               ▼                   │
     │            COMPLETED(终)          │
     ▼                                   ▼
                 ABORTED(终)
   进入 EXECUTING→RaiseEvent(4101 Started)
   进入 COMPLETED→RaiseEvent(4102 Completed)
   进入 ABORTED  →RaiseEvent(4103 Aborted)
   边：QUEUED-Start→EXECUTING；EXECUTING-Pause→PAUSED；PAUSED-Resume→EXECUTING；
       EXECUTING-Complete(guard 片数达标)→COMPLETED；
       QUEUED/EXECUTING/PAUSED-Abort→ABORTED
   非法：终态任何 trigger；EXECUTING 的 Start/Resume；QUEUED 的 Pause/Resume/Complete
   ```

## 二、参考实现（EapLab.Oss.Fsm）

### StateMachine.cs（泛型通用框架）
```csharp
using System.Diagnostics;

namespace EapLab.Oss.Fsm;

public sealed class TransitionRecord<TState, TTrigger>
{
    public TState From { get; init; } = default!;
    public TState To { get; init; } = default!;
    public TTrigger Trigger { get; init; } = default!;
    public DateTime At { get; init; }
}

internal sealed class Transition<TState, TTrigger>
{
    public TTrigger Trigger { get; }
    public TState Target { get; }
    public Func<bool>? Guard { get; }
    public Transition(TTrigger trigger, TState target, Func<bool>? guard)
    { Trigger = trigger; Target = target; Guard = guard; }
}

public sealed class StateConfiguration<TState, TTrigger>
{
    public TState State { get; }
    internal readonly List<Transition<TState, TTrigger>> Transitions = new();
    internal readonly List<Action> EntryActions = new();
    internal readonly List<Action> ExitActions = new();
    public StateConfiguration(TState state) => State = state;

    public StateConfiguration<TState, TTrigger> Permit(TTrigger trigger, TState target)
    { Transitions.Add(new Transition<TState, TTrigger>(trigger, target, null)); return this; }

    public StateConfiguration<TState, TTrigger> PermitIf(TTrigger trigger, TState target, Func<bool> guard)
    { Transitions.Add(new Transition<TState, TTrigger>(trigger, target, guard)); return this; }

    public StateConfiguration<TState, TTrigger> OnEntry(Action action)
    { EntryActions.Add(action); return this; }

    public StateConfiguration<TState, TTrigger> OnExit(Action action)
    { ExitActions.Add(action); return this; }
}

public sealed class StateMachine<TState, TTrigger> where TState : notnull where TTrigger : notnull
{
    private readonly Dictionary<TState, StateConfiguration<TState, TTrigger>> _configs = new();
    private readonly object _lock = new();
    private readonly List<TransitionRecord<TState, TTrigger>> _history = new();

    public TState CurrentState { get; private set; }
    public event Action<TransitionRecord<TState, TTrigger>>? Transitioned;

    public StateMachine(TState initial) => CurrentState = initial;

    public StateConfiguration<TState, TTrigger> Configure(TState state)
    {
        if (!_configs.TryGetValue(state, out var cfg))
            _configs[state] = cfg = new StateConfiguration<TState, TTrigger>(state);
        return cfg;
    }

    public bool CanFire(TTrigger trigger)
    {
        lock (_lock) return FindTransition(trigger, out _);
    }

    public void Fire(TTrigger trigger)
    {
        lock (_lock)
        {
            if (!FindTransition(trigger, out var trans) || trans == null)
                throw new InvalidOperationException(
                    $"Illegal transition: state={CurrentState}, trigger={trigger}");

            var from = CurrentState;
            // 源状态 OnExit
            if (_configs.TryGetValue(from, out var fromCfg))
                foreach (var a in fromCfg.ExitActions) a();
            // 改状态
            CurrentState = trans.Target;
            // 目标状态 OnEntry
            if (_configs.TryGetValue(trans.Target, out var toCfg))
                foreach (var a in toCfg.EntryActions) a();
            // 历史
            var rec = new TransitionRecord<TState, TTrigger>
            { From = from, To = trans.Target, Trigger = trigger, At = DateTime.Now };
            _history.Add(rec);
            Transitioned?.Invoke(rec);
        }
    }

    private bool FindTransition(TTrigger trigger, out Transition<TState, TTrigger>? found)
    {
        found = null;
        if (!_configs.TryGetValue(CurrentState, out var cfg)) return false;
        foreach (var t in cfg.Transitions)
        {
            if (!EqualityComparer<TTrigger>.Default.Equals(t.Trigger, trigger)) continue;
            if (t.Guard == null || t.Guard()) { found = t; return true; }
        }
        return false; // 有 trigger 但守卫都不满足 / 无此边
    }

    public IReadOnlyList<TransitionRecord<TState, TTrigger>> History
    { get { lock (_lock) return _history.ToList(); } }
}
```

### 用框架搭 ProcessJob 状态机
```csharp
public enum PjState { Queued, Executing, Paused, Completed, Aborted }
public enum PjTrigger { Start, Pause, Resume, Complete, Abort }

public sealed class ProcessJobFsm : ObjectInstance
{
    public StateMachine<PjState, PjTrigger> Fsm { get; }
    public int PlannedCount { get; }
    public int ProcessedCount { get; private set; }

    public ProcessJobFsm(ObjectType type, string id, int planned)
        : base(type, id, "QUEUED", new())
    {
        PlannedCount = planned;
        var fsm = new StateMachine<PjState, PjTrigger>(PjState.Queued);

        fsm.Configure(PjState.Queued)
           .Permit(PjTrigger.Start, PjState.Executing)
           .Permit(PjTrigger.Abort, PjState.Aborted);

        fsm.Configure(PjState.Executing)
           .OnEntry(() => RaiseEvent(4101))                 // Started
           .Permit(PjTrigger.Pause, PjState.Paused)
           .PermitIf(PjTrigger.Complete, PjState.Completed, () => ProcessedCount == PlannedCount)
           .Permit(PjTrigger.Abort, PjState.Aborted);

        fsm.Configure(PjState.Paused)
           .Permit(PjTrigger.Resume, PjState.Executing)
           .Permit(PjTrigger.Abort, PjState.Aborted);

        fsm.Configure(PjState.Completed).OnEntry(() => RaiseEvent(4102));
        fsm.Configure(PjState.Aborted).OnEntry(() => RaiseEvent(4103));
        Fsm = fsm;
    }

    public void IncrementProcessed() => ProcessedCount++;
}
```

## 三、今日易错点
1. 业务代码直接改状态字符串绕过 FSM（必须 Fire(trigger)，状态机是唯一管理者）。
2. 非法转换时已经执行了 OnExit（应先查边+守卫，全部通过才执行动作，失败零副作用）。
3. 守卫写在 Fire 之外判断（应 PermitIf 声明在状态机内，集中可测）。
4. 进入状态忘记绑定事件（用 OnEntryRaiseEvent/OnEntry(RaiseEvent)，转换即事件，防漏发 S16）。
5. 终态配了出边导致"死而复生"（终态不出边，任何 trigger 拦截）。
6. Fire 不加锁（多线程并发触发导致状态错乱，转换必须原子）。
7. 同一 (state,trigger) 多条 PermitIf 不注意求值顺序（按配置顺序取第一个守卫满足的）。
8. 状态机不记历史（历史是排查"对象怎么走到这个状态"的关键审计线索）。
9. 手绘状态机边不标注 Guard/Action（专家图必须标注完整，能讲清每条边）。
