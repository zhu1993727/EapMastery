## 二、背景知识（先读，20 分钟）

### 1. 为什么需要列举
- **重连同步**：Host 重连后不知道设备当前有哪些 Job/Carrier，需要列举重建本地实例缓存。
- **界面刷新**：EAP 界面显示设备当前所有任务及状态。
- **调度决策**：MES 派工前列举现有 ProcessJob，判断设备忙闲、槽位占用。
- W09 的 S15F11 只判断"给定对象是否存在"，列举是反向的——"设备上到底有哪些对象"。

### 2. 列举的几种粒度
- 按类型列举：ListInstances("ProcessJob") → 所有 PJ。
- 全量列举：不带类型 → 所有对象（慎用，量大）。
- 按子树列举：给定父 OBJSPEC，列出其所有子孙（配合 W10 Day01 对象树）。
- 带过滤列举：按状态过滤（如只列 EXECUTING 的 PJ）、按属性条件过滤。

### 3. 分页（Pagination）
- 对象可能很多（如一台设备几百片 Substrate），一次返回会撑爆消息（受最大消息长度限制），需要分页。
- 分页参数：起始游标/索引（StartIndex）、每页数量（Count，如每页 50）。
- 返回：本页实例列表 + 是否还有下一页（HasMore/NextCursor）+ 总数（TotalCount，可选）。
- Host 循环翻页直到 HasMore=false。

### 4. 批量查询的矩阵结构
- 一次请求 N 个对象 × M 个属性，返回 N×M 矩阵：
  ```
  请求：L,2
    [0] L,n [A OBJSPEC]          // N 个对象
    [1] L,m [A AttrId]           // M 个属性（对所有对象统一）
  返回：L,2
    [0] U1 ACKC
    [1] L,n                      // 每个对象一行
          [i] L,2
                [0] A OBJSPEC
                [1] L,m [ <值> ] // 与请求属性同序的 M 个值
  ```
- 某个对象不存在/某属性取不到：该位置放错误标记或空值，不影响其他对象（批量查询允许部分失败，因为查询无副作用）。

### 5. 批量写操作的原子性边界
- **批量查询（读）**：无副作用，允许部分成功，逐项返回结果。
- **批量创建/批量设置（写）**：有副作用，推荐"请求内原子"——同一批要么全成功要么全失败；跨对象的强一致（如同时创建 CJ 和其 PJ）用事务边界或要求按依赖顺序创建。
- 批量删除：逐个校验终态，任一非终态可选择整批拒绝或删除能删的并返回逐项结果（推荐整批拒绝，避免删一半）。

### 6. 教学项目新增 S15 消息（在 W09 六操作基础上扩展）
- S15F13/F14：列举实例（List Instances），请求带类型/父路径/分页，返回实例 OBJSPEC 列表（可带摘要属性）。
- S15F15/F16：批量查询属性（Batch Get）。
- 批量创建/设置复用 S15F1/F7 的 List 嵌套（请求体支持多个对象），不新增 Function（具体 Function 号以 E39 标准/项目规范为准，教学编号便于讲解）。
