# W10 · Day03 答案与参考实现

## 一、自测题标准答案
1. **三个订阅粒度 / 组合优先级**：①按类型订阅（Type-level）——订阅某类型所有实例事件，如"ProcessJob 全部事件"；②按实例订阅（Instance-level）——订阅具体 OBJSPEC，如"ProcessJob:PJ001 的事件"；③按事件订阅（CEID-level）——订阅特定 CEID，如"只要 4102 Completed"。一条订阅=(类型或实例范围)+CEID 白名单（空=该范围全部 CEID）。匹配优先级：**实例级优先于类型级**（实例订阅更具体、更明确，先判定）；同一层级内 CEID 白名单为空表示全部 CEID，非空则事件 CEID 必须在集合内才命中；任一订阅命中即发送（订阅是"或"关系，不是"与"）。
2. **ShouldEmit 流程 / 空订阅两种约定**：流程：事件发生（objSpec,typeName,ceid）→先查是否存在实例级订阅且 OBJSPEC 完全匹配、CEID 命中（白名单空或含该 CEID）→命中则发；否则查类型级订阅（typeName 匹配、CEID 命中）→命中则发；都不命中则抑制。两种空订阅约定：①"空订阅=全发"——没有任何订阅时设备发送全部事件（向后兼容，Host 不订阅也能收到，行为和 W09 一致，一旦建立订阅则切换为白名单过滤）；②"空订阅=不发"——必须显式订阅才发，默认静默（最省流、最可控，但 Host 忘记订阅会完全收不到事件）。选型：控制通道（SECS/GEM）为兼容老 Host 常用"空=全发"；高频数据通道（EDA/Interface-A）用"空=不发"的显式订阅。教学采用"空=全发，有订阅按白名单"。
3. **设备端 vs Host 端过滤 / EDA 为何强制订阅**：设备端过滤（订阅表在设备，设备匹配后只发订阅事件）优点是网络流量小、Host 负担轻、天然支持多 Host 各自独立订阅，缺点是设备要维护订阅表、实现复杂；Host 端过滤（设备全发、Host 自己挑）优点是设备实现简单、Host 过滤逻辑灵活可变、不依赖设备订阅能力，缺点是网络流量大、Host CPU 负担重、无关事件占带宽。EDA（Interface-A，后续 M7）面向 FDC/YMS 等高频数据消费，参数采样可达毫秒~秒级、数据量巨大（一台设备成百上千参数持续上报），若全发会直接占满内网带宽、压垮消费方，因此 EDA 强制订阅模型（Data Collection Plan，Host 精确订阅需要的参数/事件/异常和采样周期），从源头只产生和传输被订阅的数据。控制通道事件量小，两种策略都可行。
4. **S16F3 Action / 退订精确移除**：Action：1=订阅 Add（新增一条订阅）、2=退订 Remove（移除指定订阅）、3=清空 Clear（移除该 Host 的全部订阅）。精确移除方式：①订阅时返回 SubscriptionId，退订时带 SubscriptionId 精确删除这一条；②或按 Scope 退订——移除某类型/某实例范围下的全部订阅；③按 Scope+CEID 组合退订——只移除该范围下特定 CEID 的订阅。实现上订阅表用 (Scope,ScopeKind,CeidSet) 作为条目，Remove 时按匹配条件定位删除；Clear 直接清空当前连接（当前 Host）的所有条目。注意多 Host 场景订阅表要按连接隔离，退订只影响发起请求的 Host。
5. **重连为何重建订阅 / 不重建后果**：订阅表是易失配置，存在设备内存中，连接断开（HSMS Deselect/TCP 断）或设备重启后订阅表清空，和 S2F33/S2F35 报告事件关联、S5F3 报警使能性质相同。Host 重连并重新建链（S1F13/S1F17）后必须重新下发 S16F3 订阅。不重建的后果取决于空订阅约定：若"空=全发"，Host 会突然收到全部事件（包括不想要的，流量和处理量暴涨，行为与断连前不一致）；若"空=不发"，Host 完全收不到对象事件，状态停滞、误以为设备没动作，造成严重的状态不一致。因此 Host 应把订阅集持久化在本地，重连流程固定为"建链→类型发现(S14)→重建数据采集配置→重建订阅(S16F3)→恢复操作"，并在 SOFTREV 变化后校验 CEID 是否仍有效。
6. **实例订阅与类型订阅 CEID 白名单不同怎么判定**：按"实例优先、命中即发（或关系）"。例：类型订阅=ProcessJob 全部 CEID（白名单空），实例订阅=ProcessJob:PJ001 只要 CEID=4102。对 PJ001 的 4101 事件：先查实例级——实例订阅白名单 {4102} 不含 4101，实例级不命中；再查类型级——类型订阅白名单空（全部），类型名 ProcessJob 匹配，命中→发送。对 PJ002（无实例订阅）的 4101：实例级无匹配，类型级命中→发送。若想"PJ001 只收 4102、其他 PJ 全收"，这种"实例白名单收窄但类型白名单更宽"的组合会因为类型级兜底而让 PJ001 仍收到全部事件——要真正收窄，需要订阅模型支持"实例级抑制/排除"或让类型订阅也显式列出 CEID。设计时要明确：订阅是纯"正向白名单的并集"，不支持"订阅全部但排除某实例"，排除需求用更细的白名单表达。这是订阅语义的常见坑。

## 二、参考实现

### SubscriptionTable.cs
```csharp
using EapLab.Secs2;

namespace EapLab.Oss.S16;

public enum ScopeKind { Type = 1, Instance = 2 }

public sealed class Subscription
{
    public uint SubId { get; }
    public string Scope { get; }            // 类型名 或 OBJSPEC
    public ScopeKind Kind { get; }
    public HashSet<uint> CeidSet { get; }   // 空=全部 CEID
    public Subscription(uint id, string scope, ScopeKind kind, HashSet<uint> ceids)
    { SubId = id; Scope = scope; Kind = kind; CeidSet = ceids; }
}

public sealed class SubscriptionTable
{
    private readonly List<Subscription> _subs = new();
    private readonly object _lock = new();
    private uint _nextId = 1;
    /// <summary>空订阅是否全发（教学=true）。</summary>
    public bool EmitAllWhenEmpty { get; set; } = true;

    public uint Add(string scope, ScopeKind kind, HashSet<uint> ceids)
    {
        lock (_lock)
        {
            var sub = new Subscription(_nextId++, scope, kind, ceids);
            _subs.Add(sub);
            return sub.SubId;
        }
    }

    public int Remove(uint? subId, string? scope)
    {
        lock (_lock)
        {
            int n = _subs.RemoveAll(s =>
                (subId.HasValue && s.SubId == subId.Value) ||
                (scope != null && s.Scope == scope));
            return n;
        }
    }

    public void Clear() { lock (_lock) _subs.Clear(); }

    /// <summary>判定事件是否应发送。</summary>
    public bool ShouldEmit(string objSpec, string typeName, uint ceid)
    {
        lock (_lock)
        {
            if (_subs.Count == 0) return EmitAllWhenEmpty;

            // 1) 实例级优先
            foreach (var s in _subs)
                if (s.Kind == ScopeKind.Instance && s.Scope == objSpec && CeidMatch(s, ceid))
                    return true;
            // 2) 类型级
            foreach (var s in _subs)
                if (s.Kind == ScopeKind.Type && s.Scope == typeName && CeidMatch(s, ceid))
                    return true;
            return false;
        }
    }

    private static bool CeidMatch(Subscription s, uint ceid)
        => s.CeidSet.Count == 0 || s.CeidSet.Contains(ceid);

    public IReadOnlyList<Subscription> Snapshot() { lock (_lock) return _subs.ToList(); }
}
```

### ObjectEventService 接入过滤（改造 W09 版本）
```csharp
public sealed class ObjectEventService2
{
    private readonly HsmsConnection _conn;
    private readonly SpoolManager _spool;
    private readonly SubscriptionTable _table;
    public long SuppressedCount { get; private set; }
    private readonly Dictionary<string, Action<string, uint, Dictionary<string, SecsItem>>> _handlers = new();
    private readonly object _lock = new();

    public ObjectEventService2(HsmsConnection conn, SpoolManager spool, SubscriptionTable table)
    { _conn = conn; _spool = spool; _table = table; }

    public void Subscribe(ObjectInstance i)
    {
        lock (_lock)
        {
            if (_handlers.ContainsKey(i.ObjSpec)) return;
            Action<string, uint, Dictionary<string, SecsItem>> h = OnEvent;
            _handlers[i.ObjSpec] = h;
            i.EventRaised += h;
        }
    }
    public void Unsubscribe(ObjectInstance i)
    {
        lock (_lock)
            if (_handlers.Remove(i.ObjSpec, out var h)) i.EventRaised -= h;
    }

    private void OnEvent(string objSpec, uint ceid, Dictionary<string, SecsItem> snapshot)
    {
        // 先取类型名（Resolve 实例），过订阅过滤
        string typeName = objSpec.Split(':')[0];
        if (!_table.ShouldEmit(objSpec, typeName, ceid))
        {
            SuppressedCount++;   // 被订阅抑制，计数不发送
            return;
        }
        var body = SecsItem.L(
            SecsItem.A(objSpec), SecsItem.U4(ceid),
            SecsItem.L(snapshot.Select(kv => SecsItem.L(SecsItem.A(kv.Key), kv.Value)).ToArray()));
        _spool.SendOrSpool(16, 1, body);
    }
}
```

### S16F3Handler（订阅/退订/清空）
```csharp
public sealed class S16F3Handler
{
    private readonly SubscriptionTable _table;
    public S16F3Handler(SubscriptionTable table) => _table = table;

    public SecsItem Handle(SecsItem? body) => SafeHandler.Run(() =>
    {
        var l = (SecsList)body!;
        byte action = ((SecsU1)l.Items[0]).Values[0];
        byte kind = ((SecsU1)l.Items[1]).Values[0];
        var targets = (SecsList)l.Items[2];

        var active = new List<SecsItem>();
        switch (action)
        {
            case 1: // Add
                foreach (SecsList t in targets.Items)
                {
                    string scope = ((SecsAscii)t.Items[0]).Value;
                    var ceids = ((SecsList)t.Items[1]).Items
                        .Cast<SecsU4>().Select(x => x.Values[0]).ToHashSet();
                    uint id = _table.Add(scope, (ScopeKind)kind, ceids);
                    active.Add(SecsItem.U4(id));
                }
                break;
            case 2: // Remove（按 scope）
                foreach (SecsList t in targets.Items)
                    _table.Remove(null, ((SecsAscii)t.Items[0]).Value);
                break;
            case 3: // Clear all
                _table.Clear();
                break;
            default:
                throw new OssCodedException(OssErrorCode.BadParameter, "bad action");
        }
        return SecsItem.L(SecsItem.U1(0), SecsItem.L(active.ToArray()));
    },
    code => SecsItem.L(SecsItem.U1((byte)code), SecsItem.L(Array.Empty<SecsItem>())));
}
```

### 单元测试（节选）
```csharp
public class SubscriptionTests
{
    [Fact]
    public void 空订阅_默认全发()
    {
        var t = new SubscriptionTable();
        Assert.True(t.ShouldEmit("ProcessJob:P1", "ProcessJob", 4101));
    }

    [Fact]
    public void 类型订阅_白名单外被抑制()
    {
        var t = new SubscriptionTable { EmitAllWhenEmpty = true };
        t.Add("ProcessJob", ScopeKind.Type, new() { 4102 }); // 只要 Completed
        Assert.False(t.ShouldEmit("ProcessJob:P1", "ProcessJob", 4101));
        Assert.True(t.ShouldEmit("ProcessJob:P1", "ProcessJob", 4102));
        // 未订阅的类型也被抑制（一旦有订阅即按白名单）
        Assert.False(t.ShouldEmit("Chamber:C1", "Chamber", 4301));
    }

    [Fact]
    public void 实例订阅_只影响该实例()
    {
        var t = new SubscriptionTable();
        t.Add("ProcessJob:P1", ScopeKind.Instance, new HashSet<uint>()); // P1 全部
        Assert.True(t.ShouldEmit("ProcessJob:P1", "ProcessJob", 4101));
        Assert.False(t.ShouldEmit("ProcessJob:P2", "ProcessJob", 4101)); // P2 未订阅
    }

    [Fact]
    public void 退订后_恢复抑制()
    {
        var t = new SubscriptionTable();
        uint id = t.Add("ProcessJob", ScopeKind.Type, new HashSet<uint>());
        Assert.True(t.ShouldEmit("ProcessJob:P1", "ProcessJob", 4101));
        t.Remove(id, null);
        Assert.True(t.ShouldEmit("ProcessJob:P1", "ProcessJob", 4101)); // 清空后空订阅=全发
    }
}
```

## 三、今日易错点
1. 订阅是"正向白名单并集"，不支持"订阅全部但排除某实例"，收窄要用更细白名单。
2. 实例级和类型级优先级不清（实例先判，任一命中即发）。
3. CEID 白名单空的语义搞错（空=该范围全部 CEID，不是不收）。
4. 一旦建立订阅还按全发处理（有订阅即切换白名单模式，未订阅类型/实例应抑制）。
5. 多 Host 共用一张订阅表（应按连接隔离，退订只影响发起 Host）。
6. 重连后不重建订阅，导致全发泛滥或完全静默。
7. 被抑制事件不计数（应统计 SuppressedCount 便于诊断"为什么没收到事件"）。
8. 退订只按 Scope 却想精确删某 CEID（应支持 Scope+CEID 或 SubscriptionId 精确移除）。
