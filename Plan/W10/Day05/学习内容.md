# W10 · Day05（周五）OSS 与 GEM 共存：单一状态源、双出口

> 建议时长：75 分钟。真实设备要同时服务老 Host（只懂 GEM S2F41/S6F11）和新 Host（用 OSS S15/S16）。今天解决"同一份设备状态如何同时支撑两套接口"，核心原则：单一状态源（Single Source of Truth）+ 两个上报出口，绝不能维护两份会漂移的状态。

## 一、今日目标
1. 理解为什么设备要同时支持 GEM 和 OSS，以及"双份状态"的危害。
2. 掌握单一状态源架构：内部领域模型唯一，GEM 适配器和 OSS 适配器都是只读投影。
3. 实现 GEM SV ↔ OSS Attribute 的映射层。
4. 实现同一状态变化同时产出 S6F11（GEM 事件）和 S16F1（OSS 对象事件）。
5. 理解命令双通道：S2F41 远程命令与 S15F9 方法调用最终驱动同一内部状态机。

## 二、背景知识（先读，20 分钟）

### 1. 为什么要共存
- 老产线/MES 只实现了 GEM（E30）：用 S1F3 查 SV、S2F33/35 配报告、S6F11 收事件、S2F41 发命令。
- 先进 FAB 的 GEM300（E40/E87/E90/E94）走 OSS：S14/S15/S16。
- 一台设备可能同时对接：MES（GEM 通道）、EAP/Cell Controller（OSS 通道）、EDA 客户端（Interface-A，后续）。
- 设备不能因为对接方式不同就实现两套业务逻辑，必须共存。

### 2. 最大陷阱：双份状态漂移
错误做法：GEM 模块维护一份状态变量（SV 字典），OSS 模块又维护一份对象属性，各自被不同消息更新。后果：
- S1F11 查到的温度和 S15F5 查到的 Temperature 不一致；
- S6F11 说命令完成、S16F1 说还在 EXECUTING；
- 两个 Host 看到矛盾的世界，调度错乱。
根因：状态有多个权威来源。正确做法：**内部领域模型（Domain Model）是唯一状态源**，GEM 和 OSS 都只是它的"视图/适配器"。

### 3. 单一状态源 + 适配器架构
```
              内部领域模型（唯一状态源）
        ProcessJobDomain / ChamberDomain / AlarmDomain
        （状态机、真实工艺数据、权威状态）
          ▲ 写：只有内部工艺逻辑/统一命令入口能改
          │
   ┌──────┴───────────────────┐
   │ 投影/适配层（只读）        │
 GEM 适配器                 OSS 适配器
 SV←属性映射                Attribute←属性映射
 S6F11 事件                 S16F1 事件
 S2F41 命令→统一入口        S15F9 方法→统一入口
```
- 领域模型变化时发布"领域事件"（DomainEvent），GEM/OSS 适配器订阅后各自翻译成 S6F11/S16F1。
- 任何通道都不直接改状态，都调用统一命令入口，由领域模型状态机裁决。

### 4. GEM SV ↔ OSS Attribute 映射
- 建立映射表：同一内部量映射到 GEM 的 VID 和 OSS 的 (ObjType,AttrId)。
  | 内部量 | GEM SV(VID) | OSS 属性 |
  |---|---|---|
  | 任务状态 | 1001 | ProcessJob.ProcessState |
  | 温度 | 100 | Chamber.Temp |
  | 已加工片数 | 1002 | ProcessJob.WaferCount |
- GEM S1F11 查询时，适配器从领域模型读值并按 VID 编码；OSS S15F5 查询时按 AttrId 读同一值。值来自同一处，必然一致。
- 映射方向：内部模型 →（投影）→ 两种线上表示，避免反向同步。

### 5. 事件双出口
- 领域模型状态转换发布 DomainEvent（如 JobStateChanged(old,new,jobId,snapshot)）。
- GemEventAdapter：按 S2F35 关联配置，把相关 SV 组成 Report，发 S6F11（CEID 用 GEM 编号，如 3001）。
- OssEventAdapter：按 S14 事件定义，快照 LinkedAttributes，发 S16F1（CEID 用 OSS 编号，如 4101），过订阅过滤、走 Spool。
- 两个适配器独立订阅、互不影响：一个发送失败/未配置不影响另一个。
- 注意 CEID 编号空间：GEM CEID 和 OSS CEID 是两套编号，映射表关联到同一领域事件。

### 6. 命令双通道归一
- S2F41（RCMD=START）和 S15F9（ProcessJob.Start）最终都调用同一个内部应用服务 JobAppService.Start(jobId)。
- AppService 内部调用领域状态机 Fire(Start)，由状态机决定接受/拒绝。
- 两个通道只是不同的"接入协议"，业务裁决唯一。拒绝时 S2F42 回 ACKC10 非 0、S15F10 回对应 ACKC，语义一致。
