# W10 · Day05 答案与参考实现

## 一、自测题标准答案
1. **为什么不能各维护一份状态 / 问题**：GEM 模块维护一份 SV 字典、OSS 模块维护一份对象属性，两者被不同消息、不同线程、不同代码路径更新，必然出现更新时机/逻辑不一致，导致状态漂移：①同一物理量两个通道读到不同值（S1F11 温度≠S15F5 Temperature）；②事件矛盾（S6F11 已报命令完成、S16F1 仍显示 EXECUTING），两个 Host 看到互相矛盾的世界；③一处修 bug 另一处漏改，长期维护中偏差累积；④并发更新产生竞态，谁后写谁覆盖。根本原因是"状态有多个权威来源"，违反单一事实源原则。正确做法是内部领域模型唯一持有状态，GEM/OSS 都是它的只读投影，从根上消除漂移可能。
2. **单一状态源+双适配器架构 / 谁能写谁只读**：最底层是内部领域模型（Domain Model：JobDomain/ChamberDomain/AlarmDomain，持有状态机和真实工艺数据），它是唯一能被写的——只有内部工艺逻辑回调和统一命令入口（AppService）能改变它；领域模型状态变化时发布领域事件（DomainEvent）。其上是两个只读适配器：GEM 适配器把领域状态投影成 SV、把领域事件翻译成 S6F11、把 S2F41 命令转给统一入口；OSS 适配器把领域状态投影成 Object Attribute、把领域事件翻译成 S16F1、把 S15F9 方法调用转给统一入口。适配器对领域模型**只读不写**（写只能通过调用 AppService 命令，由领域状态机裁决）。这样无论哪个通道读到的都是同一份事实。
3. **SV 和 Attribute 怎么保证同值 / 映射方向**：建立一张中央映射表，把每个内部量同时映射到 GEM VID 和 OSS（ObjType,AttrId）（如内部 JobState↔SV 1001↔ProcessJob.ProcessState）。GEM 的 S1F11 处理器和 OSS 的 S15F5 处理器都不持有数据，而是拿标识去映射表找到内部量名，再从同一个领域模型实时读值，分别按 SECS-II 类型编码返回——值来自同一处同一时刻，必然一致。映射方向必须是"内部模型→线上表示"的单向投影：内部模型不关心也不依赖 GEM/OSS 格式，适配器负责翻译；若反向（让 GEM 状态和 OSS 状态互相同步）就又回到双份状态、需要双向一致性维护的老路，且形成循环依赖。单向依赖（适配器依赖领域，领域不依赖适配器）是干净可测的架构。
4. **一次转换如何同时产生 S6F11 和 S16F1 / 互相影响吗**：领域模型状态机 Fire 转换时发布一个领域事件 JobStateChanged（含 jobId、old、new、属性快照）到内部事件总线；GemEventAdapter 和 OssEventAdapter 都订阅该总线：GEM 适配器按 S2F35 的事件-报告关联，取出相关 SV 值组成报告，编码 S6F11（GEM CEID，如 3001）发送；OSS 适配器按 S14 事件定义快照 LinkedAttributes，编码 S16F1（OSS CEID，如 4101），过订阅过滤后走 Spool 发送。两者是**独立订阅者，互不影响**：各自 try/catch，一个适配器未配置报告、发送失败或抛异常，不阻断另一个，也不影响领域模型（发布事件用独立错误隔离，必要时异步队列解耦）。这是发布-订阅模式的天然优势——一个事件源，N 个独立投影出口。
5. **S2F41 与 S15F9 如何归一 / 拒绝时回什么**：两个通道都不直接操作状态机，而是解析各自协议后调用同一个应用服务方法 JobAppService.Start(jobId, params)，AppService 定位领域对象、调用其状态机 Fire(Start)，由状态机统一裁决（查边、守卫），成功则状态转换并发布领域事件（适配器再各自上报），失败抛业务异常。拒绝时：GEM 通道 S2F41 处理器捕获异常，回 S2F42 ACKC10 非 0（如 4=离线/8=状态非法，按 GEM 错误码）；OSS 通道 S15F9 处理器捕获同一异常，回 S15F10 对应 ACKC（如 8=状态非法），两个错误码通过同一业务异常映射到各自协议的错误码表，语义一致（都是"当前状态不允许 Start"）。这样命令裁决逻辑只有一份，不会出现 GEM 允许、OSS 拒绝的矛盾。
6. **GEM CEID 和 OSS CEID 是否同一套 / 怎么关联**：不是同一套编号，是两个独立编号空间——GEM 事件用 S2F35 关联的设备级 CEID（如 3001=LotStart），OSS 事件用对象类型事件定义里的 CEID（如 4101=ProcessJob.Started），数值可以不同、语义粒度也可能不同（GEM 偏设备/批次级，OSS 精确到对象实例）。关联方式：在领域事件映射表中，把同一个内部领域事件（JobStateChanged→Started）同时映射到 GEM CEID=3001 和 OSS CEID=4101，两个适配器订阅同一领域事件后各取各的编号上报。映射表是"一个领域事件→N 个协议事件编号"的一对多关系，保证语义同源、编号独立。SOFTREV 升级时两套编号都要重新核对。

```csharp
namespace EapLab.Domain;

public sealed record DomainSnapshot(string Key, object Value);
public sealed class JobStateChangedEvent
{
    public string JobId { get; init; } = "";
    public string OldState { get; init; } = "";
    public string NewState { get; init; } = "";
    public Dictionary<string, object> Snapshot { get; init; } = new();
}

/// <summary>任务领域模型：唯一状态源，持有状态机和真实数据。</summary>
public sealed class JobDomain
{
    public string JobId { get; }
    public PjState State => Fsm.CurrentState;
    public StateMachine<PjState, PjTrigger> Fsm { get; }
    public string LotId { get; private set; }
    public int ProcessedCount { get; private set; }
    public int PlannedCount { get; }

    public JobDomain(string jobId, string lotId, int planned)
    {
        JobId = jobId; LotId = lotId; PlannedCount = planned;
        Fsm = new StateMachine<PjState, PjTrigger>(PjState.Queued);
        ConfigureFsm();
    }
    private void ConfigureFsm()
    {
        Fsm.Configure(PjState.Queued).Permit(PjTrigger.Start, PjState.Executing)
           .Permit(PjTrigger.Abort, PjState.Aborted);
        Fsm.Configure(PjState.Executing)
           .Permit(PjTrigger.Pause, PjState.Paused)
           .PermitIf(PjTrigger.Complete, PjState.Completed, () => ProcessedCount == PlannedCount)
           .Permit(PjTrigger.Abort, PjState.Aborted);
        Fsm.Configure(PjState.Paused).Permit(PjTrigger.Resume, PjState.Executing)
           .Permit(PjTrigger.Abort, PjState.Aborted);
    }
    public void Increment() => ProcessedCount++;
}

/// <summary>极简进程内事件总线（发布领域事件，适配器订阅）。</summary>
public sealed class DomainEventBus
{
    private readonly List<Action<JobStateChangedEvent>> _handlers = new();
    private readonly object _lock = new();
    public void Subscribe(Action<JobStateChangedEvent> h) { lock (_lock) _handlers.Add(h); }
    public void Publish(JobStateChangedEvent e)
    {
        List<Action<JobStateChangedEvent>> copy;
        lock (_lock) copy = _handlers.ToList();
        foreach (var h in copy)
            try { h(e); } catch (Exception ex) { Console.WriteLine($"adapter error isolated: {ex.Message}"); }
    }
}
```

### 统一命令入口 AppService
```csharp
namespace EapLab.Domain;

public sealed class JobAppService
{
    private readonly Dictionary<string, JobDomain> _jobs = new();
    private readonly DomainEventBus _bus;
    public JobAppService(DomainEventBus bus) => _bus = bus;

    public JobDomain Create(string jobId, string lotId, int planned)
    {
        var j = new JobDomain(jobId, lotId, planned);
        j.Fsm.Transitioned += rec => _bus.Publish(new JobStateChangedEvent
        {
            JobId = jobId, OldState = rec.From.ToString(), NewState = rec.To.ToString(),
            Snapshot = new() { ["State"] = rec.To.ToString(), ["LotID"] = lotId }
        });
        _jobs[jobId] = j;
        return j;
    }

    /// <summary>唯一命令入口：S2F41 和 S15F9 都调这里。</summary>
    public void Start(string jobId) => Get(jobId).Fsm.Fire(PjTrigger.Start);
    public void Pause(string jobId) => Get(jobId).Fsm.Fire(PjTrigger.Pause);
    public void Resume(string jobId) => Get(jobId).Fsm.Fire(PjTrigger.Resume);
    public void Abort(string jobId) => Get(jobId).Fsm.Fire(PjTrigger.Abort);
    public void Complete(string jobId) => Get(jobId).Fsm.Fire(PjTrigger.Complete);
    public JobDomain Get(string id) => _jobs.GetValueOrDefault(id) ?? throw new KeyNotFoundException(id);
    public object ReadInternal(string jobId, string internalKey) => internalKey switch
    {
        "State" => Get(jobId).State.ToString(),
        "LotID" => Get(jobId).LotId,
        "WaferCount" => Get(jobId).ProcessedCount,
        _ => throw new KeyNotFoundException(internalKey)
    };
}
```

### 两个只读适配器
```csharp
/// <summary>GEM 适配器：领域事件→S6F11；查询→SV。</summary>
public sealed class GemEventAdapter
{
    private readonly JobAppService _svc; private readonly HsmsConnection _conn;
    private static readonly Dictionary<string, uint> DomainToGemCeid = new()
    { ["Executing"] = 3001u, ["Completed"] = 3004u, ["Aborted"] = 3005u };

    public GemEventAdapter(JobAppService svc, HsmsConnection conn, DomainEventBus bus)
    { _svc = svc; _conn = conn; bus.Subscribe(OnDomain); }

    private void OnDomain(JobStateChangedEvent e)
    {
        if (!DomainToGemCeid.TryGetValue(e.NewState, out var ceid)) return;
        // 按 S2F35 关联报告组装（简化），发 S6F11
        var body = SecsItem.L(SecsItem.U4(1), SecsItem.U2(ceid), SecsItem.L(Array.Empty<SecsItem>()));
        _conn.SendPrimaryAsync(6, 11, body);
    }
    public SecsItem ReadSv(uint vid, string jobId)
    {
        var map = AttributeMap.ByVid(vid)!;
        object v = _svc.ReadInternal(jobId, map.InternalKey);
        return Encode(v, map.Type);
    }
    private static SecsItem Encode(object v, SecsDataType t) => t switch
    {
        SecsDataType.A => SecsItem.A((string)v),
        SecsDataType.U2 => SecsItem.U2((ushort)(int)v),
        _ => SecsItem.U1(0)
    };
}

/// <summary>OSS 适配器：领域事件→S16F1；查询→Attribute。</summary>
public sealed class OssEventAdapter
{
    private readonly JobAppService _svc; private readonly ObjectEventService2 _ossEvents;
    private static readonly Dictionary<string, uint> DomainToOssCeid = new()
    { ["Executing"] = 4101u, ["Completed"] = 4102u, ["Aborted"] = 4103u };

    public OssEventAdapter(JobAppService svc, ObjectEventService2 ossEvents, DomainEventBus bus)
    { _svc = svc; _ossEvents = ossEvents; bus.Subscribe(OnDomain); }

    private void OnDomain(JobStateChangedEvent e)
    {
        if (!DomainToOssCeid.TryGetValue(e.NewState, out var ceid)) return;
        var snap = new Dictionary<string, SecsItem>
        { ["ProcessState"] = SecsItem.U1((byte)e.NewState.Length), ["LotID"] = SecsItem.A((string)e.Snapshot["LotID"]!) };
        // 直接复用对象事件发送通道（过订阅过滤+Spool）
        _ossEvents.SendDirect($"ProcessJob:{e.JobId}", ceid, snap);
    }
}
```

### 单元测试（一致性）
```csharp
public class DualChannelTests
{
    [Fact]
    public void 一次状态转换_两通道都收到事件且查询一致()
    {
        var bus = new DomainEventBus();
        var svc = new JobAppService(bus);
        svc.Create("PJ001", "LOT1", 2);
        int gemCount = 0, ossCount = 0;
        bus.Subscribe(e => { if (e.NewState == "Executing") gemCount++; }); // 模拟两适配器
        bus.Subscribe(e => { if (e.NewState == "Executing") ossCount++; });

        svc.Start("PJ001"); // 唯一入口

        Assert.Equal(1, gemCount); Assert.Equal(1, ossCount);
        Assert.Equal("Executing", svc.ReadInternal("PJ001", "State")); // 单一事实
    }

    [Fact]
    public void 双通道命令_驱动同一状态机()
    {
        var bus = new DomainEventBus(); var svc = new JobAppService(bus);
        svc.Create("PJ001", "L1", 1);
        svc.Start("PJ001");                 // 无论来自 S2F41 还是 S15F9
        Assert.Throws<InvalidOperationException>(() => svc.Start("PJ001")); // 重复 Start 被同一 FSM 拒绝
    }
}
```

## 三、今日易错点
1. GEM/OSS 各存一份状态（必须单一领域模型，适配器只读投影）。
2. 适配器直接写领域状态（写只能走 AppService 命令，由状态机裁决）。
3. 让 GEM 状态和 OSS 状态互相反向同步（应单向：内部→线上，禁止双向）。
4. 一个适配器抛异常阻断另一个（发布事件要隔离每个订阅者的异常）。
5. 以为 GEM CEID 和 OSS CEID 是同一编号（两套编号空间，靠领域事件映射表一对多关联）。
6. S2F41 和 S15F9 各写一套业务裁决（必须归一到同一 AppService+状态机）。
7. 查询时适配器返回自己缓存的值（应实时从领域模型读，保证一致）。
8. 领域模型依赖 SECS/GEM 类型（依赖方向反了：领域不依赖协议，协议适配器依赖领域）。
