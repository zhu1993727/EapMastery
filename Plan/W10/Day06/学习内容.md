## 二、迷你 GEM300 对象模型定义（先读，20 分钟）

### 1. 四类对象骨架（属性/方法/事件）
#### ControlJob（E94 雏形）
- 属性：CJState(U1 只读)、ControlJobID(A 必填)、Priority(U1 读写默认5)、ProcessJobList(L 只读，子 PJ 列表)
- 方法：Create/Start/Abort/Pause/Resume
- 事件：Created(5101)、Started(5102)、Completed(5103)、Aborted(5104)
- 状态：QUEUED→EXECUTING→(PAUSED)→COMPLETED/ABORTED，由子 PJ 聚合

#### ProcessJob（E40 雏形）
- 属性：PJState(U1 只读)、ProcessJobID(A 必填)、LotID(A 读写必填)、RecipeID(A 读写必填)、SourceCarrier(A 关联)、TargetCarrier(A 关联)、ProcessedCount(U2 只读)、PlannedCount(U2 必填)
- 方法：Start/Pause/Resume/Abort/Complete
- 事件：Started(4101)、Paused(4104)、Resumed(4105)、Completed(4102)、Aborted(4103)
- 状态：Day04 的 PJ FSM

#### Carrier（E87 雏形，W12 详细学）
- 属性：CarrierState(U1 只读)、CarrierID(A 必填)、SlotMap(B/List 只读，25 槽占用)、LoadPortID(A 读写)
- 方法：Load/Unload/Reserve/Unreserve
- 事件：Loaded(4201)、Unloaded(4202)
- 状态：NOT_INSTALLED→INSTALLED→(RESERVED)→LOADED→UNLOADED（W12 详解，今天用简化 3 态：ABSENT/LOADED/UNLOADED）

#### Substrate（E90 雏形，W14 详细学）
- 属性：SubState(U1 只读)、SubstrateID(A 必填)、SourceSlot(U1)、TargetSlot(U1)、Location(A，当前位置)
- 方法：无（被动对象，状态由流程驱动）
- 事件：Moved(4401)、Processed(4402)
- 状态：NOT_LOADED→ON_CARRIER→IN_PROCESS→PROCESSED→BACK_ON_CARRIER

### 2. 对象树装配规则
- CompositionRule：ControlJob→ProcessJob、ProcessJob→Substrate（加工归属）、Carrier→Substrate（槽位归属）。
- 注意 Substrate 同时被 PJ（加工视角）和 Carrier（物理位置视角）引用：加工归属用包含树，物理位置用关联属性 Location/SlotMap，避免一个子两个父。今天统一：**包含树走 CJ→PJ；Substrate 由 Carrier 包含（物理），PJ 通过 SourceSlot/SubstrateID 关联**，这是真实 GEM300 的建模方式（Substrate 物理上属于 Carrier，加工上被 PJ 引用）。

### 3. 完整业务流程（实验剧本，22 步）
```
【上料阶段】
1. S15F1 创建 Carrier:CAR01（CarrierID=FOUP01, LoadPort=LP1）
2. S15F9 对 CAR01 调 Load → 状态 LOADED，S16 收到 4201
3. 批量创建 Substrate W01..W05，挂到 CAR01（槽位 1-5），填 SlotMap
【建任务阶段】
4. S15F1 创建 ControlJob:CJ001（ControlJobID=CJ001, Priority=2）
5. S15F1 创建 ProcessJob:PJ001（LotID=LOT_A, Recipe=RCP_A, Source=CAR01, Planned=5）
6. 把 PJ001 挂到 CJ001（对象树 AddChild）
7. PJ001 关联 W01..W05（按槽位）
8. S14 系列查询：发现 4 类对象、CJ/PJ/Carrier/Substrate 的属性方法事件
9. S15F13 列举 CJ001 子树，应含 PJ001
【加工阶段】
10. S16F3 订阅：只订阅 ProcessJob 的 4102/4103 和 ControlJob 全部事件
11. S15F9 CJ001.Start → CJ 驱动 PJ001.Start
12. PJ001 转 EXECUTING（S16 4101，但未订阅被抑制）；CJ 聚合为 EXECUTING（S16 5102）
13. 逐片：W01 IN_PROCESS→PROCESSED→BACK_ON_CARRIER，ProcessedCount+1（S16 4402 未订阅抑制）
14. S15F9 PJ001.Pause → PAUSED（4104 抑制）；CJ 聚合为 PAUSED
15. S15F9 PJ001.Resume → EXECUTING；CJ 回 EXECUTING
16. 5 片完成，守卫满足，PJ001.Complete → COMPLETED（S16 4102，订阅命中，发送）
17. CJ 聚合：唯一子 PJ COMPLETED → CJ COMPLETED（S16 5103）
【异常对照分支（可重跑第二个 CJ 演示）】
18. 新建 CJ002/PJ002，Start 后执行中 Abort
19. PJ002 ABORTED（4103 订阅命中）；CJ002 聚合为 ABORTED（5104）
【下料清理阶段】
20. S15F9 CAR01.Unload → UNLOADED（4202）
21. 级联删除 CJ001 子树（先 Substrate 关联解除、删 PJ、删 CJ）
22. S15F13 全量列举，验证对象树清空、订阅计数、无幽灵事件
```

### 4. CJ 驱动 PJ 与状态聚合实现要点
- CJ.Start 方法执行器内部：遍历子 PJ，逐个调用 PJ 的 Start（父驱动子）。
- 子 PJ 状态变化（Transitioned 事件）冒泡到 CJ，用 Day01 的 StateAggregator 重算 CJ 状态并 Fire 对应 trigger。
- 守卫：CJ.Complete 不允许外部直接调，只能由"全部子 PJ COMPLETED"聚合触发。
