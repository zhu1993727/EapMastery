# W10 · Day01 答案与参考实现

## 一、自测题标准答案
1. **对象树关系图**：
   ```
   【包含关系 Composition，强生命周期】
   ControlJob(CJ,E94) ──1:N──► ProcessJob(PJ,E40) ──1:N──► Substrate(基板,E90)
   Carrier(载具,E87) ──1:N──► Substrate（按 Slot 槽位，E90 SlotMap）
   【关联关系 Association，弱引用】
   ProcessJob ──引用──► Carrier（SourceCarrier 源载具 / TargetCarrier 目标载具）
   ProcessJob ──引用──► Recipe（RMS 配方）
   ControlJob ──编排──► ProcessJob（加工顺序）
   ```
   一个 CJ 是一次完整加工指令，含多个 PJ（多腔体/多工序）；一个 PJ 加工多片 Substrate；Carrier 用槽位装 Substrate；PJ 通过属性引用从哪个 Carrier 取片、放回到哪个 Carrier，但不拥有 Carrier 生命周期。

2. **包含 vs 关联 / 代码表达**：包含（Composition）是强生命周期关系——父"拥有"子，子不能脱离父独立存在，父删除时子必须级联删除或先转移，代码上用 ObjectTree 维护 parent→children 映射和 CompositionRule 类型规则，子对象的创建/挂载/删除都经过树容器。关联（Association）是弱引用关系——两者生命周期独立，只是互相引用，代码上在对象属性里存对方的 OBJSPEC 字符串（如 ProcessJob 的 SourceCarrier 属性值=A "Carrier:CAR01"），不进父子树，一方删除时另一方的引用变为悬空引用（查询时校验目标是否还存在）。区分意义：级联删除只沿包含边传播，不沿关联边传播（删 PJ 不能把它引用的 Carrier 也删了）。

3. **嵌套路径逐级解析 / 每级校验**：路径 `ControlJob:CJ001/ProcessJob:PJ001/Substrate:W01`：①按 `/` 分成三段；②每段按第一个 `:` 拆出 Type 和 ID；③从根开始，第 1 段在 InstanceStore 定位 ControlJob:CJ001，校验存在、类型确为 ControlJob；④第 2 段通过 ObjectTree.GetChildren(CJ001) 校验 ProcessJob:PJ001 确实是 CJ001 的子（且类型符合 CompositionRule：CJ 可包含 PJ）；⑤第 3 段校验 Substrate:W01 是 PJ001 的子（PJ 可包含 Substrate）；⑥任一级"对象不存在/类型不符/不是直接父子"都返回路径解析失败（对应 ACKC=2 实例不存在或 ACKC=8 层级非法）。这样保证路径真实反映对象树，不能靠拼字符串伪造归属。

4. **删除 CJ 时子对象怎么处理 / 两种策略**：策略一**级联删除（递归删除）**——先递归删除所有子孙（先删 Substrate，再删 PJ，最后删 CJ），即后序遍历删除整棵子树，适合"取消整个任务、清理一切"的场景；删除前仍要校验每个对象处于可删除终态（执行中的先 Abort）。策略二**安全拒绝（存在性检查）**——删除前检查该 CJ 下是否还有未终态的 PJ/Substrate，有则拒绝删除（ACKC=8），要求 Host 先逐个处理子对象（Abort/完成/删除）后才能删父，适合"防止误删、严格管控"的场景。专家实践：默认安全拒绝（保护数据和工艺安全），提供显式的"级联删除/强制取消"方法（如 CJ.Abort 递归中止所有 PJ 后再删），不做隐式级联。无论哪种，都只沿包含边级联，不删关联对象（Carrier/Recipe）。

5. **父状态聚合举例**：设 CJ001 含 PJ001、PJ002。规则：任一子 EXECUTING→父 EXECUTING；全部 QUEUED→父 QUEUED；全部 COMPLETED→父 COMPLETED；任一 FAILED/ABORTED 且其他未完成→父 PAUSED 或 FAILED（按策略）。过程：初始两 PJ 都 QUEUED→CJ=QUEUED；PJ001 开始转 EXECUTING，聚合重算：有一个 EXECUTING→CJ=EXECUTING；PJ001 COMPLETED、PJ002 仍 QUEUED→既非全完成也非执行中，CJ 保持 EXECUTING（或 PARTIAL，部分完成）；PJ002 也 EXECUTING→CJ 仍 EXECUTING；PJ002 COMPLETED→两个都 COMPLETED→CJ=COMPLETED。实现：每个子状态变化事件向上冒泡到父，父遍历直接子状态按聚合函数重算自己的状态，父状态若变化再向祖父冒泡（递归到根）。

6. **Substrate 能否直接挂 CJ / 怎么拦截**：不能。CompositionRule 规定 Substrate 的直接父必须是 ProcessJob（或 Carrier，按槽位关系），CJ 的直接子只能是 PJ。拦截点在 ObjectTree.AddChild：挂载前查规则表 `CanContain(parentType, childType)`，CJ 下直接挂 Substrate 时规则表无此边，拒绝挂载并返回层级非法错误（ACKC=8 / 层级关系非法），不建立父子关系。意义：保证对象树结构始终符合 GEM300 标准模型，防止非法层级导致状态聚合、调度、SlotMap 逻辑全部错乱。规则表集中声明合法父子对，新增对象类型时只需扩展规则表。

## 二、参考实现（EapLab.Oss.Tree）

### ObjSpecPath.cs
```csharp
namespace EapLab.Oss.Tree;

/// <summary>嵌套 OBJSPEC 路径：Type:ID 段，用 / 分层。</summary>
public readonly struct SpecSegment
{
    public string Type { get; }
    public string Id { get; }
    public string Full => $"{Type}:{Id}";
    public SpecSegment(string type, string id) { Type = type; Id = id; }

    public static SpecSegment[] Parse(string path)
    {
        return path.Split('/')
            .Select(seg =>
            {
                int idx = seg.IndexOf(':');
                if (idx <= 0 || idx == seg.Length - 1)
                    throw new FormatException($"Bad spec segment: {seg}");
                return new SpecSegment(seg[..idx], seg[(idx + 1)..]);
            }).ToArray();
    }
}
```

### CompositionRule.cs
```csharp
namespace EapLab.Oss.Tree;

/// <summary>合法包含关系规则：父类型 → 允许的子类型集合。</summary>
public sealed class CompositionRule
{
    private readonly Dictionary<string, HashSet<string>> _rules = new();

    public CompositionRule Add(string parentType, params string[] childTypes)
    {
        if (!_rules.TryGetValue(parentType, out var set))
            _rules[parentType] = set = new HashSet<string>();
        foreach (var c in childTypes) set.Add(c);
        return this;
    }

    public bool CanContain(string parentType, string childType)
        => _rules.TryGetValue(parentType, out var set) && set.Contains(childType);
}
```

### ObjectTree.cs
```csharp
using EapLab.Oss.ObjectModel;

namespace EapLab.Oss.Tree;

/// <summary>对象树：在 ObjectRegistry 之上维护父子包含关系、路径解析、级联删除。</summary>
public sealed class ObjectTree
{
    private readonly ObjectRegistry _registry;
    private readonly CompositionRule _rule;
    // childSpec -> parentSpec
    private readonly Dictionary<string, string> _parentOf = new();
    // parentSpec -> 子 spec 集合
    private readonly Dictionary<string, HashSet<string>> _childrenOf = new();
    private readonly object _lock = new();

    public ObjectTree(ObjectRegistry registry, CompositionRule rule)
    { _registry = registry; _rule = rule; }

    public void AddChild(string parentSpec, string childSpec)
    {
        lock (_lock)
        {
            var parent = _registry.GetInstance(parentSpec); // 不存在抛异常
            var child = _registry.GetInstance(childSpec);
            if (!_rule.CanContain(parent.TypeName, child.TypeName))
                throw new OssCodedException(OssErrorCode.IllegalState,
                    $"{parent.TypeName} cannot contain {child.TypeName}");
            if (_parentOf.ContainsKey(childSpec))
                throw new OssCodedException(OssErrorCode.IllegalState,
                    $"{childSpec} already has a parent");

            if (!_childrenOf.TryGetValue(parentSpec, out var set))
                _childrenOf[parentSpec] = set = new HashSet<string>();
            set.Add(childSpec);
            _parentOf[childSpec] = parentSpec;
        }
    }

    public string? GetParent(string childSpec)
    { lock (_lock) return _parentOf.GetValueOrDefault(childSpec); }

    public IReadOnlyList<string> GetChildren(string parentSpec)
    {
        lock (_lock)
            return _childrenOf.TryGetValue(parentSpec, out var set)
                ? set.ToList() : Array.Empty<string>();
    }

    /// <summary>按嵌套路径逐级定位。</summary>
    public ObjectInstance Resolve(string path)
    {
        var segs = SpecSegment.Parse(path);
        string current = segs[0].Full;
        var currentInst = _registry.GetInstance(current); // 根必须存在
        if (currentInst.TypeName != segs[0].Type)
            throw new OssCodedException(OssErrorCode.IllegalState, "root type mismatch");

        for (int i = 1; i < segs.Length; i++)
        {
            string childSpec = segs[i].Full;
            var child = _registry.GetInstance(childSpec);
            if (child.TypeName != segs[i].Type)
                throw new OssCodedException(OssErrorCode.IllegalState, "segment type mismatch");
            lock (_lock)
            {
                if (!_childrenOf.TryGetValue(current, out var kids) || !kids.Contains(childSpec))
                    throw new OssCodedException(OssErrorCode.ObjectNotFound,
                        $"{childSpec} is not a direct child of {current}");
            }
            current = childSpec;
        }
        return _registry.GetInstance(current);
    }

    /// <summary>级联删除（后序：先删子孙，再删自己）。执行中对象应先 Abort。</summary>
    public void DeleteTree(string spec, Action<ObjectInstance> beforeDelete)
    {
        lock (_lock)
        {
            foreach (var child in GetChildren(spec).ToList())
                DeleteTree(child, beforeDelete);   // 递归先删子
            var inst = _registry.GetInstance(spec);
            beforeDelete(inst);
            _registry.DeleteInstance(spec);
            _childrenOf.Remove(spec);
            _parentOf.Remove(spec);
            if (_parentOf.TryGetValue(spec, out var p) && _childrenOf.TryGetValue(p, out var ps))
                ps.Remove(spec);
        }
    }
}
```

### StateAggregator.cs（最简父子状态聚合）
```csharp
using EapLab.Oss.ObjectModel;

namespace EapLab.Oss.Tree;

/// <summary>子状态冒泡，聚合计算父状态（E94 级联状态机雏形）。</summary>
public sealed class StateAggregator
{
    private readonly ObjectRegistry _registry;
    private readonly ObjectTree _tree;
    public StateAggregator(ObjectRegistry registry, ObjectTree tree)
    { _registry = registry; _tree = tree; }

    /// <summary>子状态变化后调用，向上重算父状态直到根。</summary>
    public void BubbleUp(string childSpec, Func<ObjectInstance, string> setState)
    {
        var parentSpec = _tree.GetParent(childSpec);
        while (parentSpec != null)
        {
            var parent = _registry.GetInstance(parentSpec);
            var childStates = _tree.GetChildren(parentSpec)
                .Select(s => _registry.GetInstance(s).State).ToList();
            string aggregated = Aggregate(childStates);
            if (parent.State != aggregated)
                setState(parent); // 由调用方通过状态机转换，触发事件并继续冒泡
            parentSpec = _tree.GetParent(parentSpec);
        }
    }

    /// <summary>聚合规则：任一执行中→EXECUTING；全 QUEUED→QUEUED；
    /// 全 COMPLETED→COMPLETED；任一失败且其余未完→FAILED；否则保持。</summary>
    public static string Aggregate(IList<string> childStates)
    {
        if (childStates.All(s => s == "QUEUED")) return "QUEUED";
        if (childStates.All(s => s == "COMPLETED")) return "COMPLETED";
        if (childStates.Any(s => s is "FAILED" or "ABORTED")
            && childStates.Any(s => s is not "COMPLETED" and not "FAILED" and not "ABORTED"))
            return "FAILED";
        if (childStates.Any(s => s == "EXECUTING")) return "EXECUTING";
        return childStates[0]; // 兜底
    }
}
```

### 单元测试（节选）
```csharp
public class ObjectTreeTests
{
    private static (ObjectRegistry reg, ObjectTree tree) Build()
    {
        var reg = new ObjectRegistry();
        reg.RegisterType(new ObjectType("ControlJob"));
        reg.RegisterType(new ObjectType("ProcessJob"));
        reg.RegisterType(new ObjectType("Substrate"));
        var rule = new CompositionRule()
            .Add("ControlJob", "ProcessJob")
            .Add("ProcessJob", "Substrate");
        return (reg, new ObjectTree(reg, rule));
    }

    [Fact]
    public void 嵌套路径逐级定位()
    {
        var (reg, tree) = Build();
        var cj = reg.CreateInstance("ControlJob", "CJ001", new());
        var pj = reg.CreateInstance("ProcessJob", "PJ001", new());
        var w = reg.CreateInstance("Substrate", "W01", new());
        tree.AddChild(cj.ObjSpec, pj.ObjSpec);
        tree.AddChild(pj.ObjSpec, w.ObjSpec);

        var found = tree.Resolve("ControlJob:CJ001/ProcessJob:PJ001/Substrate:W01");
        Assert.Equal("Substrate:W01", found.ObjSpec);
    }

    [Fact]
    public void 跨级非法挂载_拒绝()
    {
        var (reg, tree) = Build();
        var cj = reg.CreateInstance("ControlJob", "CJ001", new());
        var w = reg.CreateInstance("Substrate", "W01", new());
        Assert.Throws<OssCodedException>(() => tree.AddChild(cj.ObjSpec, w.ObjSpec));
    }

    [Fact]
    public void 伪造路径_不是直接父子_解析失败()
    {
        var (reg, tree) = Build();
        reg.CreateInstance("ControlJob", "CJ001", new());
        reg.CreateInstance("ProcessJob", "PJ001", new());
        // 没有 AddChild，直接拼路径
        Assert.Throws<OssCodedException>(() =>
            tree.Resolve("ControlJob:CJ001/ProcessJob:PJ001"));
    }

    [Fact]
    public void 状态聚合_全部完成父才完成()
    {
        Assert.Equal("QUEUED", StateAggregator.Aggregate(new[] { "QUEUED", "QUEUED" }));
        Assert.Equal("EXECUTING", StateAggregator.Aggregate(new[] { "EXECUTING", "QUEUED" }));
        Assert.Equal("EXECUTING", StateAggregator.Aggregate(new[] { "COMPLETED", "EXECUTING" }));
        Assert.Equal("COMPLETED", StateAggregator.Aggregate(new[] { "COMPLETED", "COMPLETED" }));
        Assert.Equal("FAILED", StateAggregator.Aggregate(new[] { "FAILED", "QUEUED" }));
    }
}
```

## 三、今日易错点
1. 混淆包含边和关联边，删除 PJ 时把关联的 Carrier 也删了（级联只沿包含边）。
2. 嵌套路径只做字符串拼接不校验真实父子关系（必须逐级 Resolve，防伪造归属）。
3. 允许跨级挂载（Substrate 直接挂 CJ），应用 CompositionRule 拦截。
4. 级联删除不按后序（应先删子孙再删父，且执行中对象先 Abort）。
5. 父状态聚合只在直接子变化时算一次（子变化要递归冒泡到根）。
6. 一个子对象挂到多个父下（包含关系中一个子只能有一个直接父，挂载前检查）。
7. 关联引用目标删除后不做悬空检查（通过 OBJSPEC 引用时，使用前校验目标存在）。
8. 聚合规则把"部分完成"误判为 COMPLETED（必须所有子 COMPLETED 父才 COMPLETED）。
