## 二、背景知识（先读，25 分钟）

### 1. 为什么需要对象树
W09 的对象彼此独立，靠 OBJSPEC 平铺管理。但真实生产中对象有明确层级：
- 一个 **ControlJob（CJ，控制任务，E94）** 是 Host 下发的一个完整加工指令，它包含 1~N 个 **ProcessJob（PJ，加工任务，E40）**（多腔体设备每个腔体一个 PJ，或按工序段拆多个 PJ）。
- 每个 ProcessJob 加工 1~N 片 **Substrate（基板/晶圆，E90）**。
- **Carrier（载具/FOUP，E87）** 装载 Substrate，通过 SlotMap（槽位映射，E90）描述每片晶圆在哪个槽位。
- 关系：
  ```
  ControlJob:CJ001
    ├─ ProcessJob:PJ001
    │    ├─ Substrate:W01
    │    └─ Substrate:W02
    └─ ProcessJob:PJ002
         └─ Substrate:W03
  Carrier:CAR01
    └─ Substrate:W01..W25（按 Slot 槽位）
  ```
- 平铺模型无法表达"PJ001 属于哪个 CJ""W01 属于哪个 PJ/CAR"，对象树解决归属、级联、聚合问题。

### 2. 两类关系：包含（Composition）vs 关联（Association）
- **包含（强生命周期）**：父对象包含子对象，父删除则子必须先处理（删除或转移）。如 CJ 包含 PJ，PJ 包含 Substrate 加工记录。
- **关联（弱引用）**：对象之间引用但不拥有生命周期。如 PJ 关联 Carrier（从哪个 FOUP 取片），Carrier 卸载后 PJ 的加工历史仍在。
- 代码上：包含用"父持有子 ID 列表 + 树容器统一管理"，关联用"对象属性存对方 OBJSPEC 字符串"（如 ProcessJob 的 SourceCarrier 属性=Carrier:CAR01）。

### 3. 嵌套 OBJSPEC 路径表达
- 平铺：`ProcessJob:PJ001`
- 嵌套路径：`ControlJob:CJ001/ProcessJob:PJ001`（CJ001 下的 PJ001）
- 更深：`ControlJob:CJ001/ProcessJob:PJ001/Substrate:W01`
- 路径分段：用 `/` 分隔，每段是 `Type:ID`；从左到右逐级定位，每级都校验"父存在、类型匹配、确实包含该子"。
- 注意：路径语法各厂商/标准实现可能不同（有的用数组式 OBJSPEC List 表达层级），**具体以 E39/E94 标准原文和项目接口规范为准**，教学统一用字符串路径，重点是理解逐级定位思想。

### 4. 树容器 ObjectTree 的职责
- 在 ObjectRegistry 之上增加父子关系：
  - AddChild(parentSpec, childSpec)：建立包含关系（校验父子类型合法，如 CJ 下只能挂 PJ）
  - RemoveChild / GetChildren(parentSpec) / GetParent(childSpec)
  - Resolve(path)：按嵌套路径逐级定位到目标实例
  - DeleteTree(spec)：级联删除（先删所有子孙，再删自己），或删除前检查"有活跃子对象则拒绝"
- 类型合法关系表（CompositionRule）：定义哪种类型可包含哪种类型（CJ→PJ、PJ→Substrate、Carrier→Substrate）。

### 5. 父子状态聚合（E94 雏形，先建立直觉）
- 父对象状态由子对象状态聚合：
  - 所有子对象都 QUEUED → 父 QUEUED
  - 任一子对象 EXECUTING → 父 EXECUTING（或 PARTIAL）
  - 所有子对象 COMPLETED → 父 COMPLETED
  - 任一子对象 ABORTED/FAILED → 父受影响（PAUSED/FAILED，取决于策略）
- 子对象状态变化时，重新计算父对象状态（事件向上冒泡），这是 E94 ControlJob 级联状态机的核心，W21 详解，今天只实现最简聚合。
