## 二、背景知识（先读，20 分钟）

### 1. 什么是 SECS-II 事务
- **事务（Transaction）**：一对相关的消息——发起方发 **primary**，接收方回 **reply**，共同完成一次业务交互。
- 不是所有消息都有 reply：primary 的 W 位=0 时，接收方**不应回 reply**，这是"发完即忘"的单向通知。

### 2. primary / reply 编号规则（必背）
- **primary**：Function 为**奇数**（S1F1、S2F33、S6F11、S7F3），由请求/发起方发送。
- **reply**：Function = primary 的 F + 1，为**偶数**（S1F2、S2F34、S6F12、S7F4），由接收方回。
- reply 的 Stream 与 primary 相同，Function 差 1。
- **W 位**：只在 primary 上有意义。W=1 表示"我要求你回 reply"；W=0 表示"不需要回复"。reply 自身的 W 位恒为 0。

### 3. 事务配对靠什么
- **不是靠 S/F**（同一时刻可能有多个相同 S/F 的事务在途，如连续两个 S2F33）。
- **靠 HSMS SystemBytes**：primary 发起方生成唯一 4 字节 sys，reply **原样复制**该 sys；接收方按 sys 在未决事务表中匹配。
- 这就是 W2 实现的 PendingTransactions 机制——W4 把它从控制事务扩展到数据事务。

### 4. 事务生命周期（必背）
```
1. 构造 primary Item 树 → Encode → 加 HSMS 头(S/F, W=1, sys=新生成)
2. 登记未决事务：sys → (primary, 发出时刻, T3超时, 回调)
3. 发送
4. 等待：
   a. 收到 reply(sys 匹配) → 触发回调(成功)，从事务表移除
   b. T3 超时 → 触发回调(超时)，移除，按策略重发/上报/Spool
   c. 收到 S9 错误 → 触发回调(对端无法处理)，移除
5. 事务结束
```
- W=0 的 primary：不登记未决事务，发完即结束，不期待 reply。

### 5. 并发事务
- HSMS 全双工，同一连接上可同时有多个在途事务（如 Host 连发 S2F33 定义报告、S1F13 建立通信）。
- 每个 primary 用不同 sys，未决事务表按 sys 索引，互不干扰。
- 实现上必须用线程安全的字典（ConcurrentDictionary），sys 生成器必须线程安全（Interlocked.Increment）。
