# W04 · Day02 答案与参考实现

## 一、自测题标准答案
1. **为何用 ConcurrentDictionary**：未决事务表被三个线程并发访问——发送线程 Register、接收线程 TryMatch、超时扫描线程 TimeoutScan/Remove。普通 Dictionary 在并发读写下会内部结构损坏（死循环、丢数据、抛异常），ConcurrentDictionary 是线程安全的，且支持原子的 TryRemove/GetOrAdd。
2. **数据/控制事务 sys 分开生成**：虽然标准只要求 sys 在连接上唯一，但分开生成（如数据 0x00000001~0x7FFFFFFF，控制 0x80000000~0xFFFFFFFF）有三个好处：①日志里一眼看出是数据事务还是控制事务；②两张未决事务表各自独立，不会跨表误匹配；③排查"sys 冲突"时范围更清晰。
3. **W=0 时两端行为**：本端（发起方）不登记未决事务，发完即结束，不期待 reply；对端（接收方）处理业务后**不回 reply**（即使有对应的偶数 F 消息定义）。如果对端仍回了，本端按"匹配不上的 reply"告警丢弃。
4. **匹配不上的 reply 原因与处理**：原因可能是：①对端回了 W=0 事务的 reply（对端不合规）；②本端 T3 已超时移除了事务，对端才迟到回 reply；③sys 生成冲突（极罕见）；④对端回错了 sys。正确处理：记 ERR 日志（含 sys、S/F、时间），丢弃该 reply，不触发任何业务回调，不崩溃。
5. **为何共用 Tick 而非每事务 Task.Delay**：①一个统一 Tick（250ms）扫描所有超时，资源占用恒定，不会因为 1000 个在途事务就开 1000 个定时器；②取消/清理简单——事务移除后自然不再被扫描，不需要取消一堆 Task；③时间源统一，避免多个定时器漂移；④和 W2 的 T6/T8 扫描共用同一个循环，代码结构一致。
6. **sys 溢出回绕防冲突**：实践中只要在途事务数远小于 2^32（通常几十到几百），回绕后的新 sys 不会和旧事务冲突——旧事务早已完成移除。极端情况下，如果在途事务极多，可在 Register 时检查 sys 是否已存在，若存在则跳过（+1 再试），保证不覆盖在途事务。

## 二、参考实现（EapLab.Secs2/Transaction/）

### DataSysGenerator.cs
```csharp
namespace EapLab.Secs2.Transaction;

/// <summary>数据事务 sys 生成器：从 1 递增，溢出回绕，跳过 0。</summary>
public sealed class DataSysGenerator
{
    private uint _next = 0;
    public uint Next()
    {
        uint v = Interlocked.Increment(ref _next);
        return v == 0 ? Interlocked.Increment(ref _next) : v; // 跳过 0
    }
}
```

### TransactionManager.cs
```csharp
using System.Collections.Concurrent;
using EapLab.Secs2.Items;

namespace EapLab.Secs2.Transaction;

public sealed class TransactionManager
{
    private readonly ConcurrentDictionary<uint, SecsTransaction> _pending = new();
    private readonly DataSysGenerator _sys = new();
    public TimeSpan T3 { get; init; } = TimeSpan.FromSeconds(45);

    public uint NextSys() => _sys.Next();

    /// <summary>发送 primary 前调用，登记未决事务（W=0 不调用）。</summary>
    public SecsTransaction Register(byte s, byte f, SecsItem? body)
    {
        var tx = new SecsTransaction(_sys.Next(), s, f, true, body, T3);
        while (!_pending.TryAdd(tx.SystemBytes, tx))
        {   // 极罕见 sys 冲突，换一个
            tx = new SecsTransaction(_sys.Next(), s, f, true, body, T3);
        }
        return tx;
    }

    /// <summary>收到 reply 时调用，按 sys 匹配并触发成功回调。</summary>
    public bool TryMatchReply(uint sys, SecsItem? replyBody)
    {
        if (_pending.TryRemove(sys, out var tx))
        {
            tx.CompleteWithReply(replyBody);
            return true;
        }
        return false; // 匹配不上：W=0 的 reply、迟到 reply、或对端错误
    }

    /// <summary>收到 S9 错误时调用。</summary>
    public bool TryMatchError(uint sys, byte[] s9Body)
    {
        if (_pending.TryRemove(sys, out var tx))
        {
            tx.CompleteWithError(s9Body);
            return true;
        }
        return false;
    }

    /// <summary>由统一 Tick 驱动，扫描 T3 超时事务。</summary>
    public void ScanTimeout(DateTime now)
    {
        foreach (var tx in _pending.Values)
        {
            if (tx.IsTimedOut(now))
            {
                if (_pending.TryRemove(tx.SystemBytes, out _))
                    tx.CompleteWithTimeout();
            }
        }
    }

    public int PendingCount => _pending.Count;
}
```

### HsmsConnection 接通（在 W2 基础上扩展）
```csharp
// 发送数据消息：W=1 自动登记，W=0 不登记
public SecsTransaction? SendData(byte s, byte f, bool w, SecsItem? body)
{
    byte[]? data = body?.Encode();
    var sys = _txMgr.NextSys();
    var head = new HsmsHeader { SessionId = _sessionId, W = w, Stream = s, Function = f, SType = HsmsSType.Data, SystemBytes = sys };
    var frame = FrameWriter.Build(head.Encode(data?.Length ?? 0).Concat(data ?? Array.Empty<byte>()).ToArray());
    Send(frame);

    if (!w) return null;          // W=0：发完即忘
    var tx = _txMgr.Register(s, f, body);
    // 注意：Register 内部会再生成一个 sys，这里需要把发送用的 sys 传进去
    // 实际实现应让 Register 接受外部 sys，或先 Register 再用 tx.SystemBytes 发送
    return tx;
}

// 接收侧：reply 自动匹配，primary 触发上层事件
private void DispatchData(HsmsHeader h, byte[] body)
{
    SecsItem? root = body.Length > 0 ? SecsItem.Decode(body, out int used) : null;
    if (h.Function % 2 == 0)   // reply
    {
        if (h.Stream == 9)     // S9 错误回执
            _txMgr.TryMatchError(h.SystemBytes, body);
        else if (!_txMgr.TryMatchReply(h.SystemBytes, root))
            _log.Log(LogDir.ERR, $"收到匹配不上的 reply S{h.Stream}F{h.Function} sys={h.SystemBytes:X8}");
    }
    else                         // primary
    {
        OnPrimaryReceived?.Invoke(h, root);   // 上层决定是否回 reply
    }
}
```
> 注意：上面 SendData 有个 sys 两次生成的示意问题，实际工程中应先 Register 拿到 tx，再用 tx.SystemBytes 构造头发送；或让 Register 接受外部 sys。核心原则：**发送用的 sys 和登记的 sys 必须是同一个**。

### 并发测试参考
```csharp
[Fact]
public void 并发10线程各100条_sys不重复_事务不丢()
{
    var mgr = new TransactionManager();
    var txs = new ConcurrentBag<SecsTransaction>();
    Parallel.For(0, 10, _ => {
        for (int i = 0; i < 100; i++) txs.Add(mgr.Register(6, 11, null));
    });
    Assert.Equal(1000, txs.Count);
    Assert.Equal(1000, txs.Select(t => t.SystemBytes).Distinct().Count());
    Assert.Equal(1000, mgr.PendingCount);
}
[Fact]
public void T3超时触发回调并移除()
{
    var mgr = new TransactionManager { T3 = TimeSpan.FromMilliseconds(50) };
    var tx = mgr.Register(1, 1, null);
    bool timedOut = false;
    tx.Completed += (t, _, _) => timedOut = t.State == SecsTransactionState.TimedOut;
    Thread.Sleep(100);
    mgr.ScanTimeout(DateTime.UtcNow);
    Assert.True(timedOut);
    Assert.Equal(0, mgr.PendingCount);
}
```

## 三、今日易错点
1. 发送用的 sys 和登记的 sys 不是同一个（必须先 Register 再用 tx.SystemBytes 发）。
2. W=0 也登记事务（应不登记）。
3. 收到 reply 不校验 Function 奇偶，把 primary 当 reply 匹配。
4. 超时后不 TryRemove，事务残留内存泄漏。
5. 匹配不上的 reply 直接抛异常（应告警丢弃，不崩溃）。
6. sys 生成器用普通 ++（必须 Interlocked.Increment）。
