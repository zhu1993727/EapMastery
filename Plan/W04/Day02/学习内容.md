## 二、背景知识（先读，20 分钟）

### 1. 未决事务管理器职责
```
SendPrimary(tx) → 登记 sys→tx → 发字节
ReceiveReply(header, body) → 按 header.SystemBytes 查 tx → 触发回调 → 移除
TimeoutScan() → 遍历 Pending，T3 到点的触发超时回调 → 移除
```
- 核心数据结构：`ConcurrentDictionary<uint, SecsTransaction>`。
- 超时扫描由 W2 的统一 Tick 驱动（和 T6/T8 同一个扫描循环，避免多定时器）。

### 2. SystemBytes 生成策略
- **数据事务和控制事务共用 4 字节 sys 空间，但建议分开生成**（如数据事务从 1 开始递增，控制事务从 0x80000000 开始），避免混淆、便于日志排查。
- 递增生成：`Interlocked.Increment(ref _counter)`，线程安全。
- **防复用**：sys 是 4 字节，理论上会溢出循环；实践中事务完成即移除，只要在途事务数远小于 2^32，不会冲突。溢出后从 1 重新开始（跳过 0，0 常被保留）。
- 控制事务的 sys 也必须唯一，不能和数据事务复用（W2 的 PendingTransactions 和 W4 的 TransactionManager 是两张表，各自生成）。

### 3. W=0 语义实现
- 发送 W=0 的 primary：**不登记**未决事务，发完即结束。
- 接收 W=0 的 primary：处理业务后**不回 reply**（即使标准里有对应的 reply 消息，也不应发）。
- 收到一条 sys 匹配不上的 reply：说明对端回了不该回的（或本端已超时移除），记 ERR 日志告警，丢弃。

### 4. 与 HSMS 管线接通点
- 发送侧：`HsmsConnection.SendData(s, f, w, body)` 内部生成 sys、构造头、若 w=1 则登记事务、发送。
- 接收侧：`OnDataMessage(header, body)` 中，若 header 是 reply（F 偶数），按 sys 匹配事务；若 header 是 primary（F 奇数），触发"收到 primary"事件，由上层决定是否回 reply。
