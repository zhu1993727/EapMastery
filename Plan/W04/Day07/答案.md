## 二、闭卷三件套标准图（对照找差距）

### 1. 事务生命周期
```
构造 primary(S/F, W=1, body)
  → Register(生成 sys, 登记 Pending)
  → 编码+发送
  → 等待:
      收到 reply(sys 匹配) → Replied → 返回 body
      T3 超时 → TimedOut → 抛异常(业务层可重发)
      收到 S9 错误 → Error → 抛 Secs9Exception
  → 移除未决事务
```

## 三、现场排障方法论（专家必会，费曼重点）

### "Host 发命令设备没反应，但抓包看到命令发出去了"排查
1. **抓包看完整事务**：S2F41 发出去了，设备有没有回 S2F42？
   - 没回 S2F42 → 设备收到了但没处理，或设备没收到（抓包位置不对）。
2. **看设备端日志**：设备 EAP 有没有收到 S2F41？收到后有没有校验失败？
   - 设备没收到 → 网络/HSMS 层问题（Select 状态、防火墙、端口）。
   - 设备收到但校验失败 → 回 S9F7（非法数据）或 S2F42 ACKC 非 0。
3. **看 S2F42 的 ACKC10**：如果回了但 ACKC 非 0，说明设备拒绝了命令（参数错、设备忙、状态不对）。
4. **看 GEM 状态**：设备是否在 ONLINE？控制状态是否 EQUIPMENT ON-LINE？远程命令要求设备在特定状态。
5. **看 W 位和 sys**：S2F41 W=1 吗？sys 唯一吗？设备回的 S2F42 sys 匹配吗？
6. **超时与重发**：Host T3 超时了吗？超时后重发了吗？重发用新 sys 了吗？

### "设备事件上报偶尔丢失"排查
1. **看设备端 S6F11**：事件发生时设备有没有发 S6F11？
   - 没发 → 事件定义/关联问题（S2F33/S2F35 没配好，或 CEID 不对）。
   - 发了 → 继续。
2. **看 S6F11 的 W 位**：W=1 吗？如果 W=0，设备发完即忘，Host 收没收到设备不知道，可能网络丢了。
3. **看 Host 回 S6F12 吗**：如果 W=1，Host 必须回 S6F12；没回的话设备 T3 超时后可能重发或进入 Spool。
4. **看 Spool**：设备通信不可用时，事件是否进入 Spool 队列？通信恢复后是否上传了？Spool 满了会不会丢？
5. **看网络抖动**：抓包看 S6F11 有没有发出但 Host 没收到（TCP 重传、丢包）。
6. **看事件关联**：S2F35 关联的 CEID 和实际事件的 CEID 是否一致？报告定义的 VID 是否存在？

## 四、费曼参考脚本（对照录音）
"Host 发一条 S2F41 远程命令，先在应用层构造成 Item 树——L,2[A RCMD, L,n 参数]。SECS-II 编码成字节，HSMS 加 10 字节头，W=1 表示要回复，生成唯一 SystemBytes，前面加 4 字节长度，走 TCP 到设备。同时 Host 登记未决事务，sys 映射到这条事务。设备收到后，先校验 Device ID、Stream、Function、数据长度，都通过后 SECS-II 解码，业务层处理远程命令，回 S2F42 带 ACKC10 确认码，sys 原样复制。Host 收到 S2F42，按 sys 匹配未决事务，触发成功回调，返回复用 body。如果设备 T3 时间内没回，Host 事务超时，业务层可以用新 sys 重发。如果设备不支持这条 Stream/Function，回 S9F3/F5，Host 收到后按 sys 匹配事务，触发错误回调抛异常。如果命令 body 太大，分多块传输，每块 sys 相同，Host 拼接后再解码。整个过程的核心是 SystemBytes 配对——它是事务的身份证，所有的成功、超时、错误都靠它找到对应的事务。"

## 五、W5(E30 GEM) 三问思考方向（先自己想，W5 揭晓）
1. **GEM 通信状态机**：主要状态 OFF-LINE / ON-LINE（设备上电默认 OFF-LINE）；Host 通过 S1F17（Request On-line）请求设备进入 ON-LINE，设备回 S1F18 确认；也有设备支持自动 ONLINE。ON-LINE 后 Host 才能发控制命令。
2. **GEM 控制状态 vs HSMS SELECTED**：HSMS SELECTED 是传输层状态（TCP+选通），只说明"能传消息"；GEM 控制状态是业务层状态（OFF-LINE/ON-LINE），说明"设备是否接受 Host 控制"。SELECTED 是 ON-LINE 的前提，但 SELECTED 不等于 ON-LINE——设备可以 SELECTED 但 OFF-LINE，此时只接受有限消息（如 S1F17），不接受控制命令。
3. **S1F13 和 S2F41 的状态要求**：S1F13（建立通信）在 OFF-LINE 也能发，是建立通信身份的第一步；S2F41（远程命令）要求设备在 ON-LINE 且控制状态为 EQUIPMENT ON-LINE，否则设备会拒绝（ACKC 非 0 或不处理）。

## 六、W5 预告
W5 = E30 GEM 通信与控制状态机：GEM 状态机（OFF-LINE/ON-LINE、EQUIPMENT OFF-LINE/ON-LINE）、S1F13/F14 建立通信、S1F15-F18 在线/离线、控制状态切换、远程命令执行流程、GEM 能力列表（S1F1/F2 扩展）、状态与消息允许矩阵。W5 结束后，你就有了"能连、能选通、能编解码、能做事务、能管 GEM 状态"的完整 GEM 通信底座，可以进入 W6 的数据采集体系。
