# W04 · Day05（周五）常见消息族语义速查（S1/S2/S5/S6/S7）

> 建议时长：85 分钟。今天把 SECS-II 最常用的 5 个 Stream 的常见消息过一遍，建立"看到 SxFy 就知道在干什么、body 长什么样"的直觉。这是 W5 GEM 行为层的基础。

## 一、今日目标
1. 掌握 S1/S2/S5/S6/S7 各 Stream 的职责与常见消息。
2. 对每条重点消息，说清方向（谁发谁收）、W 位、body 结构、业务含义。
3. 整理成速查表，后续 W5+ 随时查阅。

## 二、背景知识（先读，25 分钟）

### Stream 总览（一句话职责）
| Stream | 职责 | 典型场景 |
|---|---|---|
| S1 | 通信与身份 | 建立通信、在线/离线、设备身份 |
| S2 | 设备控制与数据 | 远程命令、报告定义、事件关联、时间 |
| S5 | 报警 | 报警上报、报警使能/禁用、报警列表 |
| S6 | 事件报告与数据采集 | 事件上报、跟踪数据、数据收集 |
| S7 | 配方（PP） | 配方下载/上传/删除/校验 |

### S1：通信与身份
| 消息 | 名称 | 方向 | W | body 结构 |
|---|---|---|---|---|
| S1F1 | Are You There Request | Host→设备 | 1 | 空 |
| S1F2 | Are You There Response | 设备→Host | 0 | `L,2[A MDLN, A SOFTREV]` |
| S1F13 | Establish Communications Request | Host→设备 | 1 | `L,2[A MDLN, A SOFTREV]` |
| S1F14 | Establish Communications Response | 设备→Host | 0 | `L,2[A MDLN, A SOFTREV]` |
| S1F15 | Request Off-line | Host→设备 | 1 | 空 |
| S1F16 | Off-line Acknowledge | 设备→Host | 0 | `L,2[U1 ACKC1, A ERRMSG?]` |
| S1F17 | Request On-line | Host→设备 | 1 | 空 |
| S1F18 | On-line Acknowledge | 设备→Host | 0 | `L,2[U1 ACKC1, A ERRMSG?]` |

### S2：设备控制与数据（重点）
| 消息 | 名称 | 方向 | W | body 结构 |
|---|---|---|---|---|
| S2F17 | Date/Time Set Request | Host→设备 | 1 | `A <时间字符串>` |
| S2F18 | Date/Time Set Response | 设备→Host | 0 | `A <时间字符串>` |
| S2F31 | Date/Time Request | Host→设备 | 1 | 空 |
| S2F32 | Date/Time Data | 设备→Host | 0 | `A <时间字符串>` |
| S2F33 | Define Report | Host→设备 | 1 | `L,2[U2 RPTID, L,n[U2 VID...]]` |
| S2F34 | Define Report Acknowledge | 设备→Host | 0 | `U1 ACKC5` |
| S2F35 | Link Event Report | Host→设备 | 1 | `L,2[U2 CEID, L,n[U2 RPTID...]]` |
| S2F36 | Link Event Report Acknowledge | 设备→Host | 0 | `U1 ACKC6` |
| S2F37 | Unlink Event Report | Host→设备 | 1 | `L,2[U2 CEID, L,n[U2 RPTID...]]` |
| S2F38 | Unlink Event Report Ack | 设备→Host | 0 | `U1 ACKC7` |
| S2F41 | Host Command Send | Host→设备 | 1 | `L,2[A RCMD, L,n[L,2[A CPNAME, <CPVALUE>]]]` |

### S5：报警
| 消息 | 名称 | 方向 | W | body 结构 |
|---|---|---|---|---|
| S5F1 | Alarm Report Send | 设备→Host | 1 | `L,3[U1 ALCD, U2 ALID, A ALTXT]` |
| S5F2 | Alarm Report Acknowledge | Host→设备 | 0 | `U2 ALID` |
| S5F3 | Enable/Disable Alarm Report | Host→设备 | 1 | `L,2[U1 ALED, L,n[U2 ALID...]]` |
| S5F4 | Enable/Disable Alarm Ack | 设备→Host | 0 | `U1 ACKC5` |
| S5F5 | List Alarms Request | Host→设备 | 1 | 空 |
| S5F6 | List Alarms Data | 设备→Host | 0 | `L,n[L,3[U1 ALCD, U2 ALID, A ALTXT]...]` |

### S6：事件报告与数据采集（重点）
| 消息 | 名称 | 方向 | W | body 结构 |
|---|---|---|---|---|
| S6F1 | Trace Data Send | 设备→Host | 1 | `L,4[U2 TRID, U2 SMPLN, U2 NSTPC, L,n[...]]` |
| S6F2 | Trace Data Acknowledge | Host→设备 | 0 | `U2 TRID` |
| S6F11 | Event Report Send | 设备→Host | 1 | `L,3[U4 DATAID, U2 CEID, L,n[L,2[U2 RPTID, L,m[变量值...]]]]` |
| S6F12 | Event Report Acknowledge | Host→设备 | 0 | `U4 DATAID` |
| S6F15 | Event Report Request | Host→设备 | 1 | `L,2[U2 CEID, L,n[U2 RPTID...]]` |
| S6F16 | Event Report Request Ack | 设备→Host | 0 | `U1 ACKC6` |

### S7：配方（PP）
| 消息 | 名称 | 方向 | W | body 结构 |
|---|---|---|---|---|
| S7F1 | PP Load Inquire | 设备→Host | 1 | `A PPID` |
| S7F2 | PP Load Grant | Host→设备 | 0 | `L,2[U1 ACKC1, A PPID?]` |
| S7F3 | PP Download | Host→设备 | 1 | `L,3[A PPID, L,n[B 配方数据分块...], U1 LACK?]` |
| S7F4 | PP Download Acknowledge | 设备→Host | 0 | `U1 ACKC5` |
| S7F5 | PP Upload Request | Host→设备 | 1 | `A PPID` |
| S7F6 | PP Upload Data | 设备→Host | 0 | `L,3[A PPID, L,n[B 配方数据分块...], U1 LACK?]` |
| S7F17 | Delete PP Request | Host→设备 | 1 | `L,n[A PPID...]` |
| S7F18 | Delete PP Acknowledge | 设备→Host | 0 | `U1 ACKC5` |

> 以上 body 结构为常见形式，具体以 E5/E30 原文及设备实现为准；ACKCx 是确认码（0=接受，非0=各种拒绝原因）。
