# W06 · Day04（周四）S6F11 事件上报 + S6F12 确认

> 建议时长：80 分钟。今天讲数据采集的"输出"环节——S6F11 Event Report Send。设备事件触发后，采集关联报告的变量，组装成 S6F11 上报给 Host，Host 回 S6F12 确认。这是 GEM 数据采集最核心的消息。

## 一、今日目标
1. 掌握 S6F11 Event Report Send 的 body 结构（DATAID + CEID + 报告列表）。
2. 掌握 S6F12 Event Report Acknowledge 的 body 结构（DATAID）。
3. 理解事件触发→采集→组装→上报→确认的完整流程。
4. 实现 EventReportEngine：事件触发时自动查关联、采集变量、组装 S6F11、发送、等待 S6F12。

## 二、背景知识（先读，25 分钟）

### 1. S6F11 body 结构（必背，重中之重）
```
S6F11 Event Report Send (Equipment → Host, W=1)
body = L,3[
  U4 DATAID,              // 数据收集定义 ID（标识当前配置版本）
  U2 CEID,                // 触发本次上报的事件 ID
  L,n[                    // 报告列表（n 个报告，n = 该事件关联的报告数）
    L,2[                  // 每个报告
      U2 RPTID,           // 报告 ID
      L,m[                // 该报告的变量值列表（m 个，按 S2F33 定义的 VID 顺序）
        <变量值1>,         // 第一个 VID 的值（类型由 VID 定义决定）
        <变量值2>,
        ...
      ]
    ],
    ...
  ]
]
```
- **DATAID**：U4 类型，数据收集定义 ID。Host 每次重新配置（S2F33/S2F35）后 DATAID 递增，设备在 S6F11 中带回当前 DATAID，Host 据此知道报告是按哪套配置采集的。
- **CEID**：U2 类型，触发本次上报的事件 ID。
- **报告列表**：L,n，n 个报告。每个报告是 L,2[U2 RPTID, L,m[变量值...]]。
- **变量值列表**：L,m，m 个变量值，按 S2F33 定义的 VID 顺序排列。变量值的类型由 VID 对应的变量类型决定（如 VID=100 是 F4 温度，则该位置是 F4 类型的值）。
- 注意：S6F11 是设备主动发给 Host 的（W=1，需要 Host 回 S6F12），不是 Host 请求的。

### 2. S6F12 body 结构（必背）
```
S6F12 Event Report Acknowledge (Host → Equipment, W=0)
body = U4 DATAID          // 确认收到的 DATAID
```
- Host 收到 S6F11 后，回 S6F12，body 是 U4 DATAID（与 S6F11 中的 DATAID 相同）。
- S6F12 是确认，不是数据。Host 回 S6F12 表示"我收到了这份事件报告"。
- 如果 Host 不回 S6F12，设备可能重发 S6F11（取决于设备实现和 Spool 配置）。

### 3. 事件触发→上报完整流程（必背）
```
1. 设备内部事件发生（如 Lot Start、状态变化、命令完成）
2. 设备查 EventReportLinkStore：该 CEID 关联了哪些 RPTID？
   ├─ 无关联 → 不上报（事件只在设备内部记录）
   └─ 有关联 → 继续
3. 对每个关联的 RPTID，查 ReportStore：该报告包含哪些 VID？
4. 采集每个 VID 的当前值：
   ├─ SV → 读设备当前状态（如当前温度、当前运行状态）
   └─ DV → 读事件时刻的瞬时值（如事件发生时的计数、结果）
5. 组装 S6F11 body：
   DATAID（当前配置版本）+ CEID + 报告列表（每个报告=RPTID+变量值列表）
6. 设备发送 S6F11（W=1）
7. Host 收到 S6F11，解析 body，提取 DATAID/CEID/报告数据
8. Host 回 S6F12（DATAID）
9. 设备收到 S6F12，确认上报完成
```

### 4. 变量值的类型和顺序
- S6F11 中变量值的**类型**由 VID 对应的变量类型决定：
  - VID=100 定义为 F4（温度）→ S6F11 中该位置是 F4 类型的值
  - VID=101 定义为 U2（计数）→ 该位置是 U2 类型的值
  - VID=102 定义为 A（状态字符串）→ 该位置是 A 类型的值
- Host 解析 S6F11 时，需要知道每个 VID 的类型才能正确解析变量值。Host 通常在 S1F4（SV 列表）中获取 VID 和变量类型的映射。
- 变量值的**顺序**严格按 S2F33 定义报告时的 VID 顺序排列，不能乱序。Host 按位置解析，不按 VID 解析（S6F11 中不带 VID，只带值）。

### 5. DATAID 的管理
- DATAID 是 U4 类型，由设备维护，初始值为 0。
- 每次 Host 重新配置数据采集（S2F33 定义报告、S2F35 关联事件、S2F37 取消关联）后，设备递增 DATAID。
- 设备在 S6F11 中带回当前 DATAID。
- Host 回 S6F12 时带回相同的 DATAID。
- Host 可以通过 DATAID 判断报告是否按最新配置采集——如果 Host 刚改了配置，但收到的 S6F11 还带旧 DATAID，说明设备还没应用新配置（或配置没生效）。

### 6. 无关联事件的处理
- 不是所有事件都会上报 S6F11——只有被 Host 通过 S2F35 关联了报告的事件才会上报。
- 未关联的事件只在设备内部记录（设备日志），不发给 Host。
- 这是为了减少通信量——Host 只关心它关联的事件，其他事件不需要上报。
