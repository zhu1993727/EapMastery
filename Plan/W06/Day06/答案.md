# W06 · Day06 答案与综合实验参考

## 一、自测题标准答案
1. **能力发现 / 配置采集 / 数据上报分别是哪步**：**能力发现**=S1F3（查 SV 列表）、S1F5（查事件列表）、S1F7（查报告列表）——Host 知道设备支持哪些 VID/CEID、已定义哪些报告；**配置采集**=S2F33（定义报告，指定 RPTID+VID 列表）、S2F35（关联事件，指定 CEID+RPTID 列表）——Host 告诉设备"采集什么变量、什么时候采集"；**数据上报**=设备事件触发→采集变量→组装 S6F11→发送→Host 回 S6F12——设备主动把数据发给 Host。三者是"先发现能力、再配置采集、最后数据上报"的顺序。
2. **建链后为何先查 S1F3/S1F5 / 不查直接配置会怎样**：先查 S1F3/S1F5 是为了**知道设备支持哪些 VID 和 CEID**，避免在 S2F33/S2F35 中引用不存在的 VID/CEID。不查直接配置可能导致：①S2F33 引用了不存在的 VID→设备回 ACKC5=3（变量 ID 不存在），报告定义失败；②S2F35 引用了不存在的 CEID→设备回 ACKC6=2（事件 ID 不存在），关联失败；③S2F35 引用了未定义的 RPTID→设备回 ACKC6=3（报告 ID 不存在）。专家实践：建链后必须先做能力发现，再配置数据采集，这是 GEM 初始化的标准流程。
3. **DATAID 作用 / Host 怎么通过 DATAID 判断是否最新配置**：DATAID（Data Collection Definition ID）是数据收集定义 ID，标识当前这套"报告定义+事件关联"的配置版本。Host 每次重新配置（S2F33/S2F35/S2F37）后，设备递增 DATAID。设备在 S6F11 中带回当前 DATAID。Host 通过 DATAID 判断报告是否按最新配置采集：Host 记录自己最后一次配置后期望的 DATAID（或通过 S1F 查询获取当前 DATAID），收到 S6F11 时对比——如果 S6F11 的 DATAID 与 Host 期望的一致，说明报告是按最新配置采集的；如果不一致（S6F11 带旧 DATAID），说明设备还在用旧配置，报告内容可能不符合预期（如缺少新增的变量），Host 可以告警或重新配置。
4. **一个事件关联 2 个报告时 S6F11 报告列表有几个 / 变量值怎么排列**：S6F11 的报告列表（L,n）里有 **2 个报告**，n=2。每个报告是 L,2[U2 RPTID, L,m[变量值...]]，变量值按该报告 S2F33 定义的 VID 顺序排列。2 个报告在 S6F11 中按 S2F35 关联时的 RPTID 顺序排列（Host 发 S2F35 时 RPTID 列表的顺序）。Host 解析时先按报告位置找到 RPTID，再查该报告的 VID 列表，按位置和 VID→类型映射解析每个变量值。
5. **未关联事件触发时会发 S6F11 吗 / 为什么**：**不会**。设备触发事件时先查 EventReportLinkStore，如果该 CEID 没有关联的 RPTID，直接跳过，不组装也不发送 S6F11。这是为了减少通信量——Host 只关心它关联的事件，其他事件不需要上报。未关联的事件只在设备内部记录（设备日志）。这也是为什么 Host 必须先通过 S2F35 关联事件，否则即使事件发生了 Host 也收不到数据。
6. **现场报"Host 收不到 S6F11"排查顺序**：
   1. **通信状态**：设备通信 ON-LINE 吗？控制 ONLINE 吗？（OFF-LINE 时事件可能不上报或缓存）
   2. **事件是否发生**：设备端确认事件真的发生了吗？（看设备日志、状态变化）
   3. **事件是否关联了报告**：S1F7/S1F9 查询报告列表，S2F35 关联了吗？（未关联就不上报）
   4. **报告是否定义了**：S1F7 查询报告列表，RPTID 存在吗？（报告未定义，关联会失败）
   5. **报告是否包含变量**：S1F9 查询报告包含的 VID，VID 列表非空吗？（空报告可能不上报或上报空值）
   6. **S6F11 是否发出**：设备端抓包/日志，看 S6F11 是否发出？（发出了但 Host 没收到=通信问题，没发出=配置问题）
   7. **S6F12 是否回了**：Host 是否回了 S6F12？（不回可能导致设备重发或停止上报）
   8. **Spool 状态**：通信中断时事件是否被 Spool 缓存？（W8 细讲）
   9. **DATAID**：当前 DATAID 是多少？配置是否生效？

## 二、4 个场景的预期结果与日志

### 场景1：正常采集全链路
```
Host:  建链完成（W5 流程）
Host:  TX S1F3 body=L,0（查全部SV）
Equip: RX S1F3 → 回 S1F4 body=L,2[L,2[U2=100,A"Temperature"],L,2[U2=101,A"Pressure"]]
Host:  TX S1F5 body=L,0（查全部事件）
Equip: RX S1F5 → 回 S1F6 body=L,1[L,2[U2=3001,A"LotStart"]]
Host:  TX S1F7 body=L,0（查报告列表）
Equip: RX S1F7 → 回 S1F8 body=L,0（空，重启后无报告）
Host:  TX S2F33 body=L,2[U2=1,L,2[U2=100,U2=101]]
Equip: RX S2F33 → 校验 VID 存在 → 存储报告1 → 回 S2F34 body=L,2[U1=0,U2=1]  ACKC5=0
Equip: DATAID 递增为 1
Host:  TX S2F35 body=L,2[U2=3001,L,1[U2=1]]
Equip: RX S2F35 → 校验 CEID/RPTID 存在 → 关联 → 回 S2F36 body=L,2[U1=0,U2=3001]  ACKC6=0
Equip: 模拟事件发生 CEID=3001
Equip: 查关联→RPTID=[1]→查报告→VID=[100,101]→采集 VID=100(F4=25.5), VID=101(U2=100)
Equip: 组装 S6F11 body=L,3[U4=1,U2=3001,L,1[L,2[U2=1,L,2[F4=25.5,U2=100]]]]]
Equip: TX S6F11 W=1
Host:  RX S6F11 → 解析 DATAID=1, CEID=3001, 报告1=[25.5,100] → 回 S6F12 body=U4=1
Host:  TX S1F11 body=L,2[U2=100,U2=101]（轮询）
Equip: RX S1F11 → 采集当前值 → 回 S1F12 body=L,2[F4=25.6,U2=101]
✓ 场景1通过
```

```

```

## 四、今日验收（DoD）
- 设备端数据采集完整栈可运行（ReportStore + EventReportLinkStore + EventReportEngine + S1QueryHandler + S2F33/S2F35/S2F37 Handler）。
- Host 端数据采集客户端可运行（能力发现 + 定义报告 + 关联事件 + 监听 S6F11 + 轮询 S1F11）。
- 4 个场景全部跑通，每个场景有抓包截图、日志、状态变化记录。
- S6F11 组装和解析正确（DATAID、CEID、报告列表、变量值顺序）。
- DATAID 在配置变更后正确递增。
- 未关联事件不上报。

## 五、易错点
1. 跳过能力发现直接配置（引用不存在的 VID/CEID 导致失败）。
2. S2F35 引用未定义的 RPTID（必须先 S2F33 定义报告，再 S2F35 关联）。
3. S6F11 变量值顺序乱序（必须按 S2F33 定义的 VID 顺序）。
4. 配置变更后没递增 DATAID（每次 S2F33/S2F35/S2F37 后都要递增）。
5. 以为所有事件触发都会发 S6F11（只有关联了报告的事件才发）。
6. Host 不回 S6F12（可能导致设备重发或停止上报）。
7. 混淆 S1F3（查 SV 列表）和 S1F11（查 SV 值）。
8. 以为 S1F4 返回变量类型（只返回名称，类型从文档或 S1F11 推断）。
9. 现场排障不按顺序（先查通信、再查事件是否发生、再查关联/定义、最后查 S6F11 是否发出）。
