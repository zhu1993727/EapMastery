## 二、背景知识（先读，25 分钟）

### 1. S1 系列查询消息总览
S1 Stream 是"设备状态"相关消息，其中与数据采集能力发现相关的有：

| 消息 | 全称 | 方向 | 作用 |
|---|---|---|---|
| S1F1/F2 | Are You There | H→E / E→H | 心跳/身份确认（W2 已学）|
| S1F3/F4 | Status Variable Namelist Request | H→E | 查询设备支持的 SV 列表（VID + 名称）|
| S1F5/F6 | Collection Event Namelist Request | H→E | 查询设备支持的事件列表（CEID + 名称）|
| S1F7/F8 | Report Namelist Request | H→E | 查询已定义的报告列表（RPTID）|
| S1F9/F10 | Report Variable Request | H→E | 查询某个报告包含哪些 VID |
| S1F11/F12 | Status Variable Data Request | H→E | 查询指定 VID 的当前值 |
| S1F13/F14 | Establish Communications | H→E | 建立通信（W5 已学）|
| S1F15-F18 | Off-line/On-line | H→E | 在线/离线（W5 已学）|

### 2. S1F3/F4（查询 SV 列表）
```
S1F3 Status Variable Namelist Request (Host → Equipment, W=1)
body = L,n[                  // 要查询的 VID 列表（n 个，空列表=查询全部）
  U2 VID,
  ...
]

S1F4 Status Variable Namelist (Equipment → Host, W=0)
body = L,n[                  // 返回的 SV 列表（n 个，与请求对应）
  L,2[
    U2 VID,                  // 变量 ID
    A SVNAME                 // 变量名称（如 "Temperature", "RunStatus"）
  ],
  ...
]
```
- Host 发 S1F3，指定要查询的 VID 列表。如果 body 为空列表（L,0），表示查询设备支持的**所有** SV。
- 设备回 S1F4，返回每个 VID 的名称。Host 据此建立 VID→名称映射，也知道设备支持哪些 SV。
- 注意：S1F4 只返回 VID 和名称，**不返回变量类型**。变量类型需要 Host 从设备文档获取，或通过 S1F11 查询值时推断（看返回值的类型）。部分设备在 S1F4 中扩展返回类型，但不是标准要求。

### 3. S1F11/F12（查询 SV 值）
```
S1F11 Status Variable Data Request (Host → Equipment, W=1)
body = L,n[                  // 要查询值的 VID 列表
  U2 VID,
  ...
]

S1F12 Status Variable Data (Equipment → Host, W=0)
body = L,n[                  // 返回的 SV 值列表（与请求对应，顺序一致）
  <变量值1>,                  // 第一个 VID 的当前值（类型由 VID 定义决定）
  <变量值2>,
  ...
]
```
- Host 发 S1F11，指定要查询值的 VID 列表。
- 设备回 S1F12，返回每个 VID 的当前值，按请求顺序排列。值的类型由 VID 对应的变量类型决定。
- S1F11/S1F12 是 Host **主动查询**设备当前状态的方式，和 S6F11（设备主动上报事件数据）互补。
- 常见场景：Host 定期轮询关键 SV（如温度、压力），或在命令执行后查询结果。

### 4. S1F5/F6（查询事件列表）
```
S1F5 Collection Event Namelist Request (Host → Equipment, W=1)
body = L,n[                  // 要查询的 CEID 列表（空=全部）
  U2 CEID, ...
]

S1F6 Collection Event Namelist (Equipment → Host, W=0)
body = L,n[
  L,2[
    U2 CEID,                 // 事件 ID
    A CENAME                 // 事件名称（如 "LotStart", "StateChange"）
  ], ...
]
```
- Host 查询设备支持哪些事件，据此决定要关联哪些事件。

### 5. S1F7/F8（查询报告列表）
```
S1F7 Report Namelist Request (Host → Equipment, W=1)
body = L,n[                  // 要查询的 RPTID 列表（空=全部）
  U2 RPTID, ...
]

S1F8 Report Namelist (Equipment → Host, W=0)
body = L,n[                  // 已定义的 RPTID 列表
  U2 RPTID, ...
]
```
- Host 查询设备上已定义了哪些报告。建链后通常为空（报告定义在重启后丢失），Host 需要重新定义。

### 6. S1F9/F10（查询报告变量列表）
```
S1F9 Report Variable Request (Host → Equipment, W=1)
body = L,n[                  // 要查询的 RPTID 列表
  U2 RPTID, ...
]

S1F10 Report Variable (Equipment → Host, W=0)
body = L,n[                  // 每个报告包含的 VID 列表
  L,2[
    U2 RPTID,
    L,m[U2 VID, ...]         // 该报告包含的 VID 列表
  ], ...
]
```
- Host 查询某个报告包含哪些 VID，用于解析 S6F11（知道报告里每个位置对应哪个 VID）。

### 7. 能力发现完整流程（必背）
```
建链完成后（S1F13/S1F17 之后）：
1. Host 发 S1F3(空) → 设备回 S1F4（所有 SV 的 VID+名称）
   → Host 建立 VID→名称映射，知道设备支持哪些 SV
2. Host 发 S1F5(空) → 设备回 S1F6（所有事件的 CEID+名称）
   → Host 建立 CEID→名称映射，知道设备支持哪些事件
3. Host 发 S1F7(空) → 设备回 S1F8（已定义的 RPTID 列表）
   → 通常为空，Host 需要重新定义报告
4. Host 根据业务需求，选择要采集的 SV/DV 和要监听的事件
5. Host 发 S2F33 定义报告（RPTID + VID 列表）
6. Host 发 S2F35 关联事件（CEID + RPTID 列表）
7. 事件触发 → 设备发 S6F11 → Host 回 S6F12
8. Host 可随时发 S1F11 查询 SV 当前值（主动轮询）
```
