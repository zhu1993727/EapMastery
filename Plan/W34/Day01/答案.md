# W34 · Day01 答案与参考实现

## 一、自测题标准答案
1. **三层各是什么/回答什么**：EDA（Interface-A，含 GEM 报告通道）是**设备侧标准数据出口/通道层**，由设备实现，回答"设备能提供哪些数据、用什么标准接口与格式对外提供"（CEM 自描述、会话授权、DCM 采集执行、WKN 元数据、HTTP/protobuf 或 HSMS）。ADC（Automatic Data Collection）是**采集方法与计划层**，回答"为支撑各应用，应该采哪些点、用什么频率/触发、给谁、什么精度与保留策略"，是对采集行为的规划与治理（决定 EDA 建什么采集计划、GEM 定义哪些报告事件）。EDC（厂内设备数据汇聚子系统）是**工厂级数据平台层**，回答"数据收上来后如何接入、对齐、治质量、建模、存储并服务各消费方"。一句话：EDA 是"出口"，ADC 是"采集清单与规则"，EDC 是"数据底座"。
2. **完整流向与每层动作**：传感器/设备状态→设备内唯一数据总线（同源）→**EDA 出口**按 ADC 计划规定的频率/触发把点打成 Packet（或 GEM 产生 S6F11 事件）→工厂网络→**EDC 接入层**解码协议、校验、打数据质量码、做时钟对齐、贴谱系/上下文标签（设备/腔/Lot/Wafer/Step）→写入时序库/事件库/数据湖→通过实时流订阅或历史查询服务给消费方：FDC 实时规则/模型检测、R2R 取批结果与特征、VM 取 trace 特征、SPC 做聚合控制图、YMS 做过程-良率关联、报表/AI。每层动作：设备层产生与标准化、ADC 决定采什么、EDC 汇聚治理与服务、应用层消费决策。
3. **为何分层/混层后果**：三层关注点与变化频率不同——EDA 随设备/SEMI 标准稳定，ADC 随工艺与算法需求频繁调整，EDC 随数据规模与消费方演进取向；分层后改采集点不动设备固件、换设备不改数据平台、扩消费方不改出口。混层后果：把采集清单写死进设备程序，改一个特征点都要改设备软件、重新验证；EDC 直接耦合各厂商私有协议，换机台就要重写接入；没有 ADC 统一规划会两极化——采不全导致 FDC/VM 缺关键特征，或无节制高频滥采导致网络/存储/处理爆炸且噪声多。分层实现"标准出口、计划可控、平台可扩"。
4. **ADC 计划要素**：点清单（tag/WKN/单位/数据类型/来源 EDA 或 GEM/所属对象路径）；采集模式（周期 SVDV、事件触发 ECV、异常触发 EXV）；周期频率或触发事件；必需上下文 marker（Job/Step/Carrier/Hold/Alarm 等及 Lot/腔/片 ECV）；数据质量要求与质量码；目标消费方（FDC/VM/…）与订阅权限；保留时长/存储等级；SLA（端到端延迟、完整率/丢包上限）；适用范围（设备类型/recipe/产品）与版本、变更记录。计划本身版本化、可审计。
5. **EDC 核心能力**：多协议接入与归一解码（EDA Freeze II/III、GEM、其他）；时钟同步与时间对齐（NTP/PTP、事件与采样对齐，Day03）；数据质量治理（质量码、缺失/Gap/Bad 处理、完整率监控，Day04）；统一元数据/标签模型与谱系键（设备-模块-腔-部件、Lot-Wafer-Step，Day02）；分层存储（实时热存/历史温冷存/数据湖，Day05）；实时流与历史查询两类服务且实时不补、历史不混（Day05）；数据血缘、采集完整率与延迟监控；权限/多租户可见域（对接 E132，FDC/YMS 各取所需）；对外稳定的数据契约/API。
6. **GEM 事件在三层的位置**：在设备/通道层，GEM（HSMS/SECS-II，S6F11 事件、S1F3/4 变量、S5F1 报警）与 EDA 并列，是另一种**出口通道**——稀疏、作业/控制/报警类离散事件与状态变量走 GEM，高频连续量走 EDA（W29 双通道）。ADC 计划层同时规划两类通道各采什么（哪些事件必报、事件带哪些 ECV）；EDC 平台层把 GEM 事件与 EDA 连续量接入后按统一时间轴与谱系键对齐融合（如用 Step 事件给 trace 分段，正是 VM 特征工程的基础）。
7. **设备端职责/源头错全链错**：设备端 EAP 实现并维护 EDA 出口与 GEM 报告、保证设备内数据总线唯一同源（GEM 可写视图、EDA 只读视图，W29）；按 ADC 计划在设备侧正确执行采集（频率/触发/必需 marker 不缺）；保证数据质量码、时钟、上下文（腔/Lot/片/Step）完整准确；配合 EDC 做接入验证（点是否齐、单位/WKN 是否对、延迟与完整率是否达标）。它是整条链的源头：若源头点错、时间戳错、marker 缺失或质量码不标，EDC 再强也只能存下错误数据，FDC 会误报漏报、VM 特征错位、SPC/R2R 被带偏且事后极难追溯，所以数据质量必须在源头保证。

## 二、参考实现（net8.0）：三层数据流骨架

```csharp
namespace EapLab.Edc;
// ADC 采集计划(采什么/模式/频率/触发/消费方/质量要求)
public enum CollectMode{ Periodic,OnEvent,OnException }
public sealed record AdcPoint(string Tag,string Wkn,string Unit,CollectMode Mode,double Hz,string[] Consumers,bool Required);
public sealed class AdcPlan
{ public string Version{get;}List<AdcPoint> Points{get;}=new();
    public AdcPlan(string v){Version=v;}
    public IEnumerable<AdcPoint> For(string consumer)=>Points.Where(p=>p.Consumers.Contains(consumer));
    public bool HasRequiredMarkers(IEnumerable<string> provided)=>Points.Where(p=>p.Required).All(p=>provided.Contains(p.Tag)); }
// EDA出口产出的原始样本(设备侧)
public sealed record RawSample(string Tag,double Value,string Quality,DateTime T,string Chamber,string? Lot,string? Step);
// EDC治理后的记录
public sealed record EdcRecord(RawSample S,bool Aligned,string CanonicalTag,string Consumer);
public sealed class EdcPipeline
{
    readonly Dictionary<string,string> _wknMap; // tag->规范名(WKN)
    public EdcPipeline(Dictionary<string,string> wknMap){_wknMap=wknMap;}
    // 接入: 归一标签 + 质量门 + 时间对齐标记 + 按消费方分发
    public List<EdcRecord> Ingest(IEnumerable<RawSample> s,IEnumerable<string> consumers,bool timeAligned)
    { var outp=new List<EdcRecord>();
        foreach(var x in s)
        { if(!_wknMap.TryGetValue(x.Tag,out var canon))continue;            // 未建模点丢弃/入异常区
          foreach(var c in consumers)outp.Add(new EdcRecord(x,timeAligned&&x.Quality=="Good",canon,c)); }
        return outp; }
    public double Completeness(IEnumerable<EdcRecord> r)=>r.Count()==0?0:r.Count(x=>x.Aligned)/(double)r.Count();
}
```

```csharp
public class ThreeLayerTests
{
    [Fact] public void ADC按消费方筛点()
    { var p=new AdcPlan("v1");p.Points.Add(new AdcPoint("T1","Temperature","C",CollectMode.Periodic,10,new[]{"FDC","VM"},true));
      p.Points.Add(new AdcPoint("T2","Pressure","Pa",CollectMode.OnEvent,0,new[]{"FDC"},false));
      Assert.Single(p.For("VM")); }
    [Fact] public void 必需marker缺失判定不通过()
    { var p=new AdcPlan("v1");p.Points.Add(new AdcPoint("StepChanged","","",CollectMode.OnEvent,0,new[]{"VM"},true));
      Assert.False(p.HasRequiredMarkers(new[]{"JobStart"})); }
    [Fact] public void EDC归一标签并按消费方分发()
    { var pipe=new EdcPipeline(new(){{"T1","Temp.Chamber"}});
      var raw=new[]{new RawSample("T1",100,"Good",DateTime.UtcNow,"C1","L1","Etch")};
      var r=pipe.Ingest(raw,new[]{"FDC","VM"},true);
      Assert.Equal(2,r.Count);Assert.All(r,x=>Assert.Equal("Temp.Chamber",x.CanonicalTag)); }
    [Fact] public void 未建模点被过滤()
    { var pipe=new EdcPipeline(new(){{"T1","Temp"}});
      var r=pipe.Ingest(new[]{new RawSample("XX",1,"Good",DateTime.UtcNow,"C1",null,null)},new[]{"FDC"},true);
      Assert.Empty(r); }
    [Fact] public void 质量差或未对齐_完整率下降()
    { var pipe=new EdcPipeline(new(){{"T1","Temp"}});
      var raw=new[]{new RawSample("T1",1,"Good",DateTime.UtcNow,"C1",null,null),new RawSample("T1",2,"Bad",DateTime.UtcNow,"C1",null,null)};
      var r=pipe.Ingest(raw,new[]{"FDC"},true);
      Assert.Equal(0.5,pipe.Completeness(r)); }
}
```

## 三、三层数据体系（手绘参考）
```
[设备] 传感器/状态 → 唯一数据总线(GEM可写视图/EDA只读视图, 同源)
   │ EDA/Interface-A=标准出口通道(CEM/E132/E134/E164, 高频只读多订阅) ‖ GEM=稀疏作业/控制/报警事件
   ▼
[ADC 采集方法/计划层] 采哪些点(WKN/单位) / 周期SVDV·事件ECV·异常EXV / 频率触发 / 必需marker / 消费方 / SLA / 版本
   │ 计划下发到设备DCM执行, 决定出口实际产出什么
   ▼
[EDC 厂内汇聚平台层] 多协议接入解码 → 质量码治理 → 时钟/事件对齐 → 统一标签谱系建模
   → 分层存储(实时热/历史冷) → 实时流(不补) + 历史查询(不混) → 权限可见域
   ▼
消费方: FDC实时检测 / R2R批结果 / VM trace特征 / SPC聚合 / YMS良率关联 / 报表AI
原则: 标准出口(EDA) · 计划可控(ADC) · 平台可扩(EDC); 改一层不动其他; 源头(设备端)错全链错
```

## 四、今日易错点
1. 把 EDA（通道）、ADC（采集计划）、EDC（数据平台）混为一谈。
2. 以为 EDC 是某一家厂商产品名（它是厂内数据汇聚子系统/平台层的统称）。
3. 把采集点写死在设备程序里，改点要改固件。
4. 没有 ADC 统一规划，采不全或滥采洪水。
5. 忽视 GEM 事件也是出口通道，且要与 EDA 连续量在 EDC 对齐。
6. EDC 直接耦合设备私有协议，换机台大改。
7. 认为数据质量可以在平台端"事后补救"（源头质量码/上下文必须设备端保证）。
8. 采集计划不版本化、不与 recipe/产品关联，变更不可追溯。
