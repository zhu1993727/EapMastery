## 二、背景知识（先读，40 分钟）

### 1. 设备层级模型（定位"数据从哪个物理位置来"）
- ISA-95 层级：Enterprise→Site（厂）→Area（区）→Work Center/Cell（线/单元）→Work Unit/Equipment（设备）→Module/Chamber（模块/腔）→Component（部件）。
- 与 CEM(E120) 对象树对应（W28）：Equipment/Module/Subsystem/Component/Logical，数据变量挂在对象节点上，路径唯一。
- 统一层级后，跨设备的"腔温度"才有相同的位置语义，可聚合、可对比、可按腔分层（SPC/R2R 都要按腔，W31/W32）。

### 2. 规范标签命名与 WKN
- 设备厂商私有 tag 名五花八门（Temp1、T_CH_A、ChamberATemp），EDC 必须映射到**规范名（canonical tag）**：层级路径 + 量名，如 `Site1/EtchLineA/Etcher07/ChamberA/Temperature`。
- WKN（E164 Well-Known Names，W28）给"物理量"标准语义与量纲：Temperature/Pressure/FlowRate/Power…，配合 SI 单位归一（℃/K、Pa/Torr/mTorr、sccm/slm），跨设备同义同名同单位。
- 命名规则：唯一、稳定、结构化、不含随 Lot 变化的动态值；私有 tag→canonical→WKN 的映射表本身受控、版本化。

### 3. 谱系上下文键（Context Key，最关键）
- 光有"哪个点、什么值、什么时间"还不够，工艺分析必须知道这值属于**哪个加工对象**：Lot/Carrier、Wafer(slot)、Job(PJ/CJ id)、Step/Recipe/RecipeVer、Chamber，必要时还有产品/工艺层、批次 run 序号。
- 这些构成上下文键，与数据一起存储，才能回答"这片在 A 腔 Etch 步的温度曲线"，VM 才能按片按 Step 提特征、R2R 才能把量测归属到腔（W31 Day06）、YMS 才能做良率关联。
- 缺上下文键的连续数据几乎不可用于工艺分析（不知道是哪片哪步）。

### 4. 上下文动态绑定（Context Binding）
- 连续 trace 本身不带 Lot/Wafer，靠作业/状态事件动态绑定：CarrierLoaded→Lot、PJ Started/CJ Started→Job、Wafer 进入某腔→Wafer+Chamber、StepChanged→Step/Recipe（E87/E40/E94/GEM S6F11，前序周已学）。
- EDC 维护"当前上下文状态机"，事件推进上下文，期间到达的周期采样继承当前上下文；上下文切换（换片/换 Step）要精确切分，边界时间戳对齐（Day03）。
- 异常：事件缺失/乱序会导致上下文空洞或错贴，需要质量标记与对账（与作业状态重连对账同源，W22）。

### 5. 时序建模：窄表 vs 宽表
- 窄表/长表（EAV：time, tag, value, quality, context…）：灵活、加点不改表、适合海量异测点与时序库；查询需透视。
- 宽表（每点一列、按时间一行）：查询直观、适合固定点集的快速分析，但加点要改 schema。
- FAB 级平台多以时序库窄表 + 按上下文索引为主，分析层再透视成宽表/特征表；教学用记录模型表达。

### 6. 与消费方的关系
- FDC 按设备/腔/Step 取实时序列；VM 按 Wafer+Step 取整段特征；R2R 按腔+run 取结果；SPC 按产品/腔分层聚合；YMS 按 Lot/Wafer 关联良率——全部依赖统一层级、规范名与谱系键。
