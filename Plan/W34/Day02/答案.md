# W34 · Day02 答案与参考实现

## 一、自测题标准答案
1. **层级/与 CEM 关系**：ISA-95 自上而下 Enterprise（企业）→Site（厂区）→Area（车间/区域）→Work Center/Work Cell（产线/单元）→Equipment（设备）→Module/Chamber（模块/工艺腔）→Component（部件）。它给"数据来自哪个物理位置"统一坐标。CEM(E120) 对象树在设备侧用 Equipment/Module/Subsystem/Component/Logical 组织对象，数据变量挂在节点上（W28）；两者对应：ISA-95 的 Equipment/Module/Chamber 与 CEM 树节点一一映射，EDC 用统一层级路径定位每个点，使跨设备的"某腔温度"位置语义一致，可聚合、可对比、可按腔分层（R2R/SPC 都依赖）。
2. **canonical/WKN 必要性**：不同厂商私有 tag 命名各异（Temp1/T_CH_A/ChamberATemp 可能是同一个量），直接存私有名会导致跨设备无法统一查询与建模、同义不同名/同名不同义、单位不一（℃/K、Torr/Pa），每加一种设备应用层就要写一堆适配。canonical tag 用"层级路径+量名"给每个点全局唯一名，WKN(E164) 给物理量标准语义与量纲并做 SI 单位归一，做到同义同名同量纲；私有 tag→canonical→WKN 的映射表受控版本化。这样 FDC/VM 等应用面向统一模型而非厂商私有名。
3. **上下文键**：除 tag/value/quality/timestamp 外，还需 Enterprise/Site/Area/设备/腔（位置键）、Lot/Carrier、Wafer(slot/wafer id)、Job（PJ/CJ id）、Step（步骤名/序号）、Recipe 及其版本、产品/工艺层、run/片序号（必要时工艺腔 pass 次数）。它们回答"这个值是哪台设备哪个腔、在加工哪片哪 Lot 的哪一步、用哪版配方时产生的"。缺了这些键，连续数据只剩"某传感器某时刻的值"，无法归属到加工对象，几乎不能用于工艺分析、控制或良率追溯。
4. **上下文如何加上**：连续周期采样本身只带时间和点，不含 Lot/Wafer；靠离散作业/状态事件动态绑定——CarrierLoaded（E87）建立 Lot/Carrier，PJ/CJ Started（E40/E94）建立 Job，Wafer 进入某腔（移动/加工事件）绑定 Wafer+Chamber，StepChanged（S6F11）绑定 Step/Recipe。EDC 维护一个"当前上下文状态"，事件推进它，事件之间到达的周期采样**继承当前上下文**打上相同键；片离开/Step 结束则切换。本质是用稀疏事件给密集连续流"分段贴标签"，也是 VM 按 Step 提特征的前提。
5. **切换瞬间注意**：必须精确确定边界——以事件时间戳为准把切换前后的采样分别归到旧/新上下文，不能让换片/换 Step 前后的点错贴（Step 末点算旧 Step、首点算新 Step）；要处理事件与采样的时间对齐与微小错位（Day03 时钟/对齐）；事件乱序/丢失会造成上下文空洞或张冠李戴，需质量标记（如 unbound/unknown context）并与作业状态对账补正（W22 重连对账同源）；同一时刻多腔并行要按腔分别维护上下文，不能全局只有一个"当前 Lot/Wafer"。
6. **窄表/宽表/选型**：窄表（长表/EAV：每行 time+tag+value+quality+上下文）优点是灵活、新增点不改 schema、适合海量异测点和时序库压缩，缺点是多变量分析要透视/join；宽表（每个 tag 一列、一时间一行）优点是查询直观、多变量同列对比方便，缺点是加点要改表结构、稀疏点浪费、设备型号多则 schema 爆炸。FAB 级平台通常用时序库**窄表 + 上下文索引**做统一存储（灵活可扩），在分析/特征层按 Wafer/Step 透视成宽表或特征表给 VM/SPC 用，兼顾扩展性与分析便利。
7. **缺失/错贴影响**：VM——按 Wafer+Step 取 trace 提特征，上下文错会把别的片/别的 Step 波形当训练/推理样本，特征错位、模型预测失准甚至学坏；R2R——要把量测归属到产生它的腔和 run（W31 Day06），上下文错等于用 B 腔结果调 A 腔，越调越乱；YMS——良率关联按 Lot/Wafer 追溯过程，键错会把问题原因归到错误设备/步骤，误导根因分析；SPC——分层错误把不同腔/产品混层，制造假信号或掩盖真异常（W32）。所以谱系键是数据可用的前提，错误的上下文比缺失更危险（缺失可标记，错贴会误导决策）。

## 二、参考实现（net8.0）：规范标签 + 上下文绑定器

```csharp
namespace EapLab.Edc.Model;
public sealed record CanonicalTag(string Path,string Wkn,string SiUnit);
public sealed record Ctx(string? Lot,string? Wafer,string? Job,string? Step,string? RecipeVer,string Chamber);
public sealed record BoundSample(string Canon,double Value,string Quality,DateTime T,Ctx C);

public sealed class ContextBinder
{
    readonly Dictionary<string,CanonicalTag> _map; Ctx _cur;
    public ContextBinder(Dictionary<string,CanonicalTag> map,string chamber){_map=map;_cur=new Ctx(null,null,null,null,null,chamber);}
    // 事件推进当前上下文(作业/片/Step)
    public void OnEvent(string ev,(string? lot,string? wafer,string? job,string? step,string? ver)? d=null)
    { _cur=ev switch
      { "CarrierLoaded" =>_cur with{Lot=d!.Value.lot},
        "JobStarted"    =>_cur with{Job=d!.Value.job,Lot=d.Value.lot??_cur.Lot},
        "WaferEnter"    =>_cur with{Wafer=d!.Value.wafer},
        "StepChanged"   =>_cur with{Step=d!.Value.step,RecipeVer=d.Value.ver??_cur.RecipeVer},
        "WaferExit"     =>_cur with{Wafer=null,Step=null},
        "CarrierUnloaded"=>_cur with{Lot=null,Job=null,Wafer=null,Step=null},
        _=>_cur }; }
    // 周期采样继承当前上下文; 无Wafer/Step则标Unbound(不硬贴)
    public BoundSample? Bind(string rawTag,double value,string quality,DateTime t)
    { if(!_map.TryGetValue(rawTag,out var ct))return null;
      if(_cur.Wafer is null||_cur.Step is null)
        return new BoundSample(ct.Path,value,"Unbound",t,_cur);
      return new BoundSample(ct.Path,value,quality,t,_cur); }
    public bool FullyBound(BoundSample b)=>b.Quality!="Unbound"&&b.C.Wafer is not null&&b.C.Step is not null;
}
```

public class ContextBinderTests

## 三、层级-命名-上下文（手绘参考）
```
ISA-95: Enterprise/Site/Area/Cell/Equipment/Module-Chamber/Component  ←对应→ CEM(E120)对象树
私有tag(Temp1) ──映射(受控版本)──▶ canonical: Site1/LineA/EQ7/ChA/Temperature + WKN(Temperature)+SI单位(K)
上下文状态机(稀疏事件推进):
 CarrierLoaded→Lot  JobStarted→Job  WaferEnter→Wafer+Chamber  StepChanged→Step+RecipeVer  WaferExit→清
   期间密集周期采样继承当前上下文 → (canon,value,quality,time, Lot/Wafer/Job/Step/Recipe/Chamber)
切换边界以事件时间戳切分; 乱序/缺失→Unbound标记+作业对账, 不硬贴; 多腔各维护上下文
存储: 时序库窄表(time,tag,value,quality,上下文键)+索引 → 分析层按Wafer/Step透视宽表/特征表
铁律: 缺上下文的trace不可用于工艺分析; 错贴比缺失更危险(误导VM/R2R/YMS/SPC)
```

## 四、今日易错点
1. 直接存厂商私有 tag，跨设备同义不同名、单位不一。
2. 有值和时间却缺 Lot/Wafer/Step 谱系键，数据无法用于分析。
3. 以为连续采样自带上下文（实际靠作业事件动态绑定）。
4. 换片/换 Step 边界不按事件时间戳切分，前后错贴。
5. 事件乱序/丢失时硬贴上下文而不是标 Unbound 并对账。
6. 多腔共用一个全局当前上下文（应按腔独立）。
7. 私有→规范名映射不受控、不版本化。
8. 宽表 schema 随设备型号爆炸，或窄表不留上下文索引导致无法按片检索。
