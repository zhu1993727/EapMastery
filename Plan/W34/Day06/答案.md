# W34 · Day06 答案与参考实现

## 一、自测题标准答案
1. **五方需求对比**：FDC——关键过程量高频连续序列（采样≥异常时间尺度 5–10 倍）、Step/状态事件分段、Good 才判、亚秒~秒延迟、要腔/Step 上下文；R2R——run/片结果量测（实测/VM）、生效设定与 overlay、量测质量、批级延迟、要腔/Lot/片/run 且量测对回当时设定；VM——每 Step 较全的高频 trace（含相关性通道）、完整 Step marker、片/腔/recipe 版本上下文、片结束即可、可离线精确对齐；SPC——聚合后的关键特性（片/批统计）、分层维度（腔/产品/recipe）、分钟~小时、长期完整；YMS——片级过程特征+量测+良率、完整 Lot/Wafer/Step 谱系、长周期、历史完整优先。核心差异：FDC 求实时高频、R2R 求批结果对齐、VM 求全特征、SPC 求分层聚合、YMS 求全谱系长历史。
2. **频率怎么定/为什么**：同一点被多方需要时，采集频率取各方要求的**最大值（最严）**，质量要求取最高、上下文取并集、延迟 SLA 取最紧、保留取最长。因为一次采集可同时供给多方，按最严要求采能满足所有消费方（高频数据可在 EDC 降频/聚合给低频方，反之低频无法还原高频）；若按最低需求采，FDC/VM 会缺关键信息。但要结合设备/网络容量校验（见第 6 题），在满足最严需求前提下避免无消费方的滥采。
3. **EDA vs GEM 选点**：看数据性质与用途——高频、连续、过程波形类（温度/压力/功率/流量 trace，10Hz–1kHz、多客户端只读消费）走 EDA 周期 SVDV/异常 EXV；稀疏、离散、作业与控制/报警类事件（JobStart/Complete、StepChanged、CarrierLoaded、HoldChanged、AlarmChanged、批结果、远程命令回告）走 GEM S6F11（其权威控制语义在 GEM），事件发生时刻的上下文值可作 ECV 随 EDA 计划采。下行控制只走 GEM、EDA 只读（W29 铁律）。判据：连续高频量→EDA，作业/控制/报警事件→GEM。
4. **契约要素/会签受控**：要素含 canonical 路径、WKN 与 SI 单位/量纲、数据类型、采集模式（周期/事件/异常）与频率/触发、质量要求、必需上下文（Lot/Wafer/Job/Step/腔/recipe 版本）、通道（EDA/GEM）、端到端延迟与完整率 SLA、保留等级、消费方清单、版本与审批。三方（设备端 EAP、EDC 平台、应用消费方）会签是因为契约是共同接口基线：设备要知道采什么、平台要知道怎么收怎么治、应用要知道能拿到什么，任何一方私改都会导致缺点/错单位/对不齐。变更要走受控流程评估对**所有**消费方影响（类似配方 ECN、FDC ICD），版本化留痕。
5. **无消费方点不采**：不采（或默认不进高频采集计划）。采集有真实成本：设备采样/打包负载、EDA 会话频率与点数配额（W29 MaxHz/MaxTags）、网络带宽、EDC 存储与治理成本，无主数据还制造噪声、拖慢排查。正确做法是需求驱动——每个点都要能指认消费方与用途，按 ADC 计划采；确有潜在价值的可低频归档或待提出需求再纳入计划（版本更新），而不是默认"先全采了再说"导致数据洪水。
6. **超设备/会话配额**：不能硬采导致丢点或影响控制通道。处理顺序：①核对是否真都需最高频，按消费方实际时间尺度优化（FDC 异常最快、其他可较低），同点分时复用、不同点分级频率；②利用 EDA 多客户端共享同一次采集（一份数据多订阅，而非每客户端各采一遍，W29 Hub fan-out）；③仍超则与应用协商降级（部分点降频/改事件触发/只在关键 Step 高频），或增加会话/提升设备与网络能力；④对无法满足的 SLA 明确记录限制与风险，不假装满足。本质是在设备能力边界内做最优化资源分配并把约束显性化。
7. **端到端流程**：①应用方（FDC/VM/…）提数据需求（点/频率/触发/延迟/质量/上下文/保留）；②ADC 汇总反推：同点取最严频率/最高质量/并集上下文/最紧 SLA/最长保留，剔除无消费方点，形成采集计划；③通道规划：连续高频走 EDA、作业事件走 GEM；④形成数据契约并由设备端/EDC/应用三方会签、版本化；⑤设备端 EAP 据此配置 EDA DCM 采集计划与 GEM 报告/事件（S2F33/S2F35），保证点表/频率/marker/质量码一致；⑥EDC 配置接入、标签映射、上下文绑定、时间同步、质量治理、分层存储与实时/历史服务；⑦上线用完整率、端到端 P95/P99 延迟、乱序/Gap/Bad 率等 SLA 验收（Day03/04），不达标回到计划/通道优化；⑧需求变更走契约新版本。

## 二、参考实现（net8.0）：需求反推采集规划器

```csharp
namespace EapLab.Edc.Plan;
public enum Chan{ Eda,Gem }
public sealed record Need(string Consumer,string Tag,double Hz,Chan Chan,string MinQuality,string[] Context,string Retain,double MaxLatencySec);
public sealed record Planned(string Tag,double Hz,Chan Chan,string Quality,string[] Context,string Retain,double LatencySec,List<string> Consumers);
public sealed class CollectionPlanner
{
    static int RankQ(string q)=>q switch{"Good"=>2,"Uncertain"=>1,_=>0};
    static string BetterQ(string a,string b)=>RankQ(a)>=RankQ(b)?a:b;
    static string Longer(string a,string b)=>RetainRank(a)>=RetainRank(b)?a:b;
    static int RetainRank(string r)=>r switch{"cold-year"=>3,"warm-month"=>2,"hot-day"=>1,_=>0};
    public List<Planned> Build(IEnumerable<Need> needs,double deviceMaxHz)
    { return needs.GroupBy(n=>n.Tag).Select(g=>
        { var l=g.ToList();
          // 通道: 任一要求EDA连续即EDA; 频率取最大; 质量最高; 上下文并集; SLA最紧; 保留最长
          var chan=l.Any(x=>x.Chan==Chan.Eda&&x.Hz>0)?Chan.Eda:Chan.Gem;
          double hz=l.Max(x=>x.Hz);
          if(hz>deviceMaxHz)throw new InvalidOperationException($"{g.Key} {hz}Hz > device {deviceMaxHz}Hz, negotiate");
          string q=l.Select(x=>x.MinQuality).Aggregate(BetterQ);
          var ctx=l.SelectMany(x=>x.Context).Distinct().OrderBy(x=>x).ToArray();
          string retain=l.Select(x=>x.Retain).Aggregate(Longer);
          double lat=l.Min(x=>x.MaxLatencySec);
          return new Planned(g.Key,hz,chan,q,ctx,retain,lat,l.Select(x=>x.Consumer).Distinct().ToList());
        }).OrderBy(p=>p.Tag).ToList(); }
    public bool Covers(List<Planned> plan,IEnumerable<Need> needs) // 下游需求一个不缺
    =>needs.All(n=>plan.Any(p=>p.Tag==n.Tag&&p.Hz>=n.Hz&&p.Context.Intersect(n.Context).Count()==n.Context.Length));
}
```

### xUnit（综合案例）
```csharp
public class PlannerTests
{
    List<Need> Needs()=>new()
    { new("FDC","ChA.Power",10,Chan.Eda,"Good",new[]{"Step","Chamber"},"hot-day",1),
      new("VM","ChA.Power",5,Chan.Eda,"Good",new[]{"Step","Chamber","Wafer","RecipeVer"},"warm-month",5),
      new("SPC","ChA.Power",1,Chan.Eda,"Uncertain",new[]{"Chamber"},"cold-year",60),
      new("FDC","StepChanged",0,Chan.Gem,"Good",new[]{"Job","Step"},"warm-month",1) };
    [Fact] public void 同点取最严频率最高质量并集上下文最长保留()
    { var p=new CollectionPlanner().Build(Needs(),deviceMaxHz:20);var power=p.Single(x=>x.Tag=="ChA.Power");
      Assert.Equal(10,power.Hz);Assert.Equal("Good",power.Quality);Assert.Equal(1,power.LatencySec);
      Assert.Equal("cold-year",power.Retain);Assert.Contains("Wafer",power.Context);Assert.Equal(3,power.Consumers.Count); }
    [Fact] public void 连续高频走EDA_事件走GEM()
    { var p=new CollectionPlanner().Build(Needs(),20);
      Assert.Equal(Chan.Eda,p.Single(x=>x.Tag=="ChA.Power").Chan);
      Assert.Equal(Chan.Gem,p.Single(x=>x.Tag=="StepChanged").Chan); }
    [Fact] public void 需求全覆盖()
    { var n=Needs();var p=new CollectionPlanner().Build(n,20);Assert.True(new CollectionPlanner().Covers(p,n)); }
    [Fact] public void 超设备配额抛错要求协商()
    { var n=new List<Need>{new("FDC","X",100,Chan.Eda,"Good",Array.Empty<string>(),"hot-day",1)};
      Assert.Throws<InvalidOperationException>(()=>new CollectionPlanner().Build(n,deviceMaxHz:50)); }
    [Fact] public void 无消费方点不进计划()
    { var p=new CollectionPlanner().Build(new List<Need>{new("FDC","A",1,Chan.Eda,"Good",new[]{"S"},"hot-day",1)},20);
      Assert.Single(p);Assert.DoesNotContain(p,x=>x.Tag=="B"); }
}
```

## 三、需求反推到服务（手绘参考）
```
消费需求: FDC(高频实时/Good/Step,腔) R2R(批结果/对当时设定) VM(全trace/完整marker/片) SPC(分层聚合/长期) YMS(全谱系/历史)
   │ 同点合并: 频率取最大, 质量取最高, 上下文取并集, SLA取最紧, 保留取最长; 无消费方不采
   ▼
ADC计划(点/模式/频率/触发/质量/上下文/SLA/保留, 版本化) ──超设备MaxHz?─→分级降频/多客户端共享/协商, 不假装满足
   │ 通道选择: 连续高频trace→EDA(SVDV/EXV,只读多订阅) ; 作业/控制/报警事件→GEM(S6F11) ; 下行只走GEM
   ▼
数据契约(canonical/WKN/单位/上下文/通道/SLA/消费方) 三方(设备·EDC·应用)会签, 变更受控
   ▼
设备端配DCM+S2F33/35 → EDC接入: 命名映射/上下文绑定/时钟对齐/质量治理 → 热温冷存储
   ▼
实时流(水位不回溯)→FDC/R2R/看板 ; 历史(可重算)→VM/SPC/YMS/AI
验收: 完整率/P95P99延迟/Gap/Bad/乱序率达标SLA, 不达标回到计划/通道优化
```

## 四、今日易错点
1. 各消费方各采一遍、重复浪费（应一次采集多方订阅共享）。
2. 同点频率取最低值，导致 FDC/VM 缺信息（应取最严）。
3. 上下文不取并集，VM/YMS 缺 Wafer/Recipe 谱系。
4. 通道选错：高频 trace 走 GEM 或作业事件走 EDA。
5. 无消费方的点也全量高频采，制造数据洪水。
6. 超设备会话配额硬采、丢点，或假装满足 SLA。
7. 数据契约不会签、不版本化，一方私改全链断。
8. 上线不用完整率/延迟 SLA 验收，问题到应用层才暴露。
