# W34 · Day03 答案与参考实现

## 一、自测题标准答案
1. **为何统一时钟/偏差错误**：跨通道、跨设备、跨系统的对齐、因果排序、延迟与时长计算都建立在"同一根时间轴"上。时钟偏差会：把同时/先后顺序判反（如分不清压力与功率谁先变化，FDC 时序指纹错）；Step 边界错位，把过渡段点算进稳态（VM 特征错）；多通道对不齐，相关/积分等特征失真；误算检测延迟、加工时长与 OEE；跨设备协同（多腔/上下游）时序混乱。亚秒级高频场景几百毫秒偏差就足以改变结论，因此必须统一时钟并监控偏差。
2. **NTP/PTP**：NTP 基于网络软件校时，部署简单、无需专用硬件，局域网通常毫秒到几十毫秒精度，满足作业/事件/管理类数据与一般采集；PTP（IEEE 1588）用硬件时间戳与主从同步，可达亚毫秒到微秒级，适合 10Hz–1kHz 高频 EDA、多通道严格波形对齐与跨设备因果分析，但需要网络设备/网卡支持。设备晶振有漂移，即使同步后也会慢慢偏，需周期校时，EDC 记录每台设备相对主时钟的 offset 并监控，超阈告警，接入时可用 t_corrected=t_device−offset 做软件校正。
3. **源端打戳原因**：样本从设备采集到 EDC 可查询，中间经过打包 flush、网络传输、排队、解码，存在不等的延迟与抖动；若用 EDC 到达时间当时间戳，就把这些随机延迟混进了数据时间轴，导致采样间隔失真、周期/积分/检测延迟算错、多通道假性错位。正确做法是在离传感器最近的设备侧打"源时间戳"（sample time），EDC 同时另存"入库时间"用于监控传输延迟；所有工艺对齐、特征计算、因果判断都用源时间。
4. **事件切区间/边界**：以 StepChanged/JobStart/JobComplete 等事件的**源时间戳**为分界，把连续 trace 切成区间，如 Step k 对应 [t_start_k, t_end_k)，落在区间内的采样归属该 Step（Day02 上下文绑定的时间实现）。边界规则全平台统一，常用左闭右开，恰在边界的点明确归新段还是旧段；多通道采样时刻不完全一致时，按统一栅格重采样（W32 归一化）或最近邻/线性插值 join，并记录对齐方法，保证可复现。换片/换腔同理按事件切。
5. **水位线/解决的问题**：流式处理中数据会乱序、迟到，系统既不能在数据没到齐时永远等下去（出不了实时结果），也不能完全不等（结果被乱序反复推翻）。watermark（水位线）=目前已观测到的最大事件时间减去允许的最大迟到量，它声明"早于水位线时间的数据基本到齐了"，据此关闭对应窗口、产出实时结果。它在"结果及时性"和"完整性"之间给出可控折中，允许迟到量按网络 P99 延迟设定。
6. **迟到数据/实时与历史**：窗口未关（数据时间仍在水位线之后）→正常并入窗口参与计算；窗口已关才到：实时结论**不回溯修改**（FDC 实时告警/已做出的控制判断不撤回，保证实时决策确定、及时），但数据写入历史存储，可在 EDC 历史侧触发离线修正/重算特征/标注（如 VM 离线特征、SPC 重算、报表更正）。即"实时不补、历史可修"（Day05 展开）：实时流面向当下决策追求低延迟，历史库面向准确完整可重算，二者职责分开；若迟到量超 SLA 还要计数据质量事件。
7. **时间相关质量指标**：设备时钟相对主时钟的 offset 及漂移、校时成功率；端到端延迟（源时间戳→可查询时间）的均值/P95/P99 与超阈比例；乱序率、迟到率及超水位丢弃/修正数量；采样缺口 Gap（预期点缺失）与完整率；时间戳重复/回跳（时钟异常）数量；多通道/事件对齐误差。这些是 ADC 计划 SLA 的一部分，异常即告警，因为时间质量不合格会让下游所有分析失真。

## 二、参考实现（net8.0）：时钟校正 + 事件分段 + 乱序水位对齐

```csharp
namespace EapLab.Edc.Time;
public readonly record struct Tick(DateTime SrcTime,double V,string Raw="");
public sealed record Segment(string Step,DateTime Start,DateTime End,List<Tick> Ticks);
public sealed class TimeAligner
{
    readonly TimeSpan _clockOffset, _allowedLateness;public TimeAligner(TimeSpan clockOffset,TimeSpan allowed){_clockOffset=clockOffset;_allowedLateness=allowed;}
    public DateTime Correct(DateTime deviceT)=>deviceT-_clockOffset;       // 设备时钟校正

    // 事件时间戳把采样切成Step区间(左闭右开)
    public List<Segment> SegmentByEvents(IEnumerable<Tick> ticks,IReadOnlyList<(string step,DateTime start)> ev)
    { var ordered=ev.OrderBy(e=>e.start).ToList();var segs=ordered.Select(e=>new Segment(e.step,e.start,DateTime.MaxValue,new List<Tick>())).ToList();
        for(int i=0;i<segs.Count-1;i++)segs[i]=segs[i] with{End=segs[i+1].Start};
        foreach(var t in ticks.OrderBy(t=>Correct(t.SrcTime)))
        { var ct=Correct(t.SrcTime);var idx=segs.FindLastIndex(s=>s.Start<=ct&&ct<s.End);
            if(idx>=0)segs[idx].Ticks.Add(t); }
        return segs.Where(s=>s.Ticks.Count>0).ToList(); }
    // 乱序缓冲+水位线: 返回已关闭(到齐)窗口内按源时间排序的点
    DateTime _maxSeen=DateTime.MinValue;readonly List<Tick> _buf=new();
    public List<Tick> Ingest(Tick t)
    { _buf.Add(t);if(Correct(t.SrcTime)>_maxSeen)_maxSeen=Correct(t.SrcTime);
        var wm=_maxSeen-_allowedLateness;
        var ready=_buf.Where(x=>Correct(x.SrcTime)<=wm).OrderBy(x=>Correct(x.SrcTime)).ToList();
        foreach(var r in ready)_buf.Remove(r);return ready; }
    public bool IsLate(DateTime srcTime)=>Correct(srcTime)<_maxSeen-_allowedLateness; // 已关窗=迟到
}
```

## 三、时间对齐（手绘参考）
```
设备时钟(有漂移) ──offset校正──▶ 统一主时钟(NTP毫秒/PTP微秒, 周期校时监控偏差)
时间戳: 源时间(设备采集时刻, 工艺对齐用) + 入库时间(EDC, 监控传输延迟) 双字段
事件(GEM S6F11 源时间) StepChanged ──切区间[start,end)左闭右开──▶ 连续EDA采样归段
多通道: 统一栅格重采样/最近邻·插值join, 记录对齐方法
乱序流: 有序小缓冲(按P99延迟) → watermark=max源时间-允许迟到 → 关窗出实时结果
迟到: 窗未关→并入; 窗已关→实时不回溯(决策确定), 入历史可离线重算修正(实时不补/历史可修)
质量SLA: clock offset, 端到端P95/P99, 乱序率/迟到率, Gap完整率, 时间戳回跳
要求: 对齐误差 << FDC检测时间尺度; VM离线可用历史精确重对齐
```

## 四、今日易错点
1. 用 EDC 到达时间当数据时间（应用设备源时间戳）。
2. 只打一个时间字段，无法监控传输延迟。
3. 忽视设备时钟漂移，不周期校时、不监控 offset。
4. 高频多通道只用 NTP 毫秒级、对齐误差大于检测时间尺度。
5. Step 边界归属规则不统一，前后段错贴。
6. 乱序数据来一点算一点、结果反复跳变（应用水位线/有序缓冲）。
7. 窗口关闭后还回改实时结论（实时不回溯），或丢弃迟到点不入历史（历史应可修）。
8. 不监控乱序率/迟到率/Gap/时间回跳等时间质量指标。
