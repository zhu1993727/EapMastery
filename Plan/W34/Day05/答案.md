# W34 · Day05 答案与参考实现

## 一、自测题标准答案
1. **两类服务差异**：实时流服务面向当下决策（FDC 秒级检测、R2R 片间控制、实时看板告警），要求极低延迟（毫秒~秒）、按水位窗口尽快产出，容忍极少量迟到/缺失，且结论一旦给出就确定、不反复推翻（否则控制与告警抖动）；历史回查服务面向分析与追溯（VM 训练与特征重算、SPC 长周期、YMS 良率关联、AI、合规），要求完整、准确、可按任意时间/上下文范围查询并可重复计算，对延迟不敏感（秒~分钟甚至批量小时级可接受）。一个求"快而及时"，一个求"全而准确"。
2. **为何不能一套**：两条路径的优化方向相反。实时要在内存里做短窗口流处理、近线索引、尽快输出，若为等迟到数据补全而阻塞，延迟飙升、控制不及时；历史要落盘、列存压缩、长保留、全量重算，若要求它毫秒实时则成本极高。一套系统同时满足会互相拖累：要么实时被完整性拖慢，要么历史为快而丢点/不修正导致分析不准。分离后同一份原始数据进两条路径，实时层"快而可略"、历史层"全而可重"，独立伸缩互不阻塞。
3. **热温冷三层**：热层存最近小时~天的高频原始/近线数据，用内存或 SSD 时序库，毫秒~秒级查询，支撑实时检测与即时回看；温层存近期周~月数据，用列式时序库/数据库，秒级查询，支撑日常分析、SPC、报表；冷层存月~年甚至更长，用数据湖/对象存储列存压缩文件（如 Parquet），低成本高压缩，支撑 AI 建模、长周期趋势与合规审计。数据按龄自动迁移（tiering），并对老数据降采样（原始高频留短、聚合值留长）。
4. **TSDB vs 数据湖**：时序库（TSDB）为时间序列优化写入、时间窗查询、降采样、标签/上下文索引，服务在线监控与近线分析，快但通常不存全部多模原始；数据湖存全量原始与多模数据（高频 trace、事件、量测、良率、报警、文本），支持大规模跨域 join、特征工程、AI 训练与长追溯。EDC 通常"TSDB + 数据湖"组合：TSDB 管在线与近线，数据湖管全量与建模，二者通过统一元数据/谱系键打通（Day02）。
5. **实时不补/历史可修/为何不改实时**：实时层按水位线关窗即出结论，之后到达的迟到/补传数据**不回头修改**已发出的实时告警/控制建议，但原始数据照常写入历史层；历史层收到补全/校正数据后可离线重算特征、控制图、报表并标注算法/数据版本，复盘以历史重算为准。实时结论不能反复改，是因为下游（FDC 联锁、R2R 控制、操作员响应）需要确定、及时的一次性信号，若几秒后又撤回/翻转会造成控制振荡、重复动作和信任崩溃；准确性通过历史层重算与复盘兜底（实时近似、批量准确）。
6. **保留策略差异**：高频原始 trace 数据量极大（10Hz–1kHz×大量点×全机台），长期全量保存成本极高，而实时与近期分析用完后价值下降，故原始高频只短期保留（热/温层），过期降采样或归档；聚合值（分钟/片/Step 级均值、特征）、关键事件、量测结果、报警与决策记录数据量小但对质量追溯、SPC、良率分析、合规价值高，需长期甚至永久保留。按"数据价值/体积/合规要求"分级设定保留期、采样率与压缩，兼顾成本与可追溯。
7. **血缘用途/为何 VM/R2R 依赖**：数据血缘记录每条/每批数据来自哪台设备哪个点、哪个采集计划版本、经过哪些处理与算法版本、某特征/预测/控制决策由哪些原始数据算出。VM 依赖它回溯训练样本来源、复现特征、定位模型预测错误是数据问题还是模型问题、在主档/设备变更后界定模型适用范围；R2R 依赖它逐 run 追溯"当时用了哪版主档+哪份 overlay、依据哪条量测（实测/VM）"（W31）。没有血缘，结果不可复现、问题无法根因、审计不通过，出了质量事故无法重建当时的数据与决策链。

## 二、参考实现（net8.0）：实时/历史双服务层

```csharp
namespace EapLab.Edc.Serve;
using EapLab.Edc;
public sealed record Rec(DateTime SrcTime,string Tag,double V,string Quality);
public sealed class RealtimeLayer // 水位关窗即出, 结论不回溯
{
    readonly TimeSpan _wm;DateTime _max=DateTime.MinValue;public List<Rec> Window{get;}=new();
    public List<Rec> Pushed{get;}=new();
    public RealtimeLayer(TimeSpan allowedLateness){_wm=allowedLateness;}
    public List<Rec> Ingest(Rec r)
    { var closed=new List<Rec>();if(r.SrcTime>_max)_max=r.SrcTime;
        var wm=_max-_wm;
        foreach(var x in Window.Where(x=>x.SrcTime<=wm))closed.Add(x);
        foreach(var c in closed)Window.Remove(c);
        if(r.SrcTime<wm){/* 迟到: 不回改已发结论, 仅返回让其落历史 */}else Window.Add(r);
        if(closed.Count>0)Pushed.AddRange(closed);
        return closed; }
}
public sealed class HistoryLayer // 全量落盘, 可补传/重算
{
    public List<Rec> Rows{get;}=new();public List<string> Revisions{get;}=new();
    public void Upsert(Rec r){Rows.Add(r);}
    public void Amend(Rec corrected){Rows.Add(corrected);Revisions.Add($"amend@{corrected.SrcTime:HH:mm:ss}");}
    public double? RecomputeAvg(string tag,DateTime from,DateTime to)
    { var q=Rows.Where(x=>x.Tag==tag&&x.SrcTime>=from&&x.SrcTime<to&&x.Quality=="Good").ToList();
        return q.Count==0?null:q.Average(x=>x.V); } // 历史可随时重算
}
public sealed class DualServingLayer
{
    public RealtimeLayer Rt{get;}public HistoryLayer Hist{get;}=new();
    public DualServingLayer(TimeSpan late){Rt=new RealtimeLayer(late);}
    public List<Rec> Write(Rec r){var closed=Rt.Ingest(r);Hist.Upsert(r);return closed;} // 同一份原始进两层
    public void LateArrival(Rec r){Rt.Ingest(r);Hist.Upsert(r);} // 迟到: 实时不改旧结论, 历史照收
}
```

## 三、两层 + 分层存储架构（手绘参考）
```
                 ┌─ 实时层(内存流/短窗口/水位线): FDC/R2R/告警, 关窗即结论, 迟到不回改(确定及时)
同一份原始数据 ──┤   热: 内存/SSD TSDB(小时~天, 毫秒秒查)
                 │
                 └─ 历史层(落盘/全量/可重算): VM训练/SPC/YMS/AI/审计, 补传校正可重算版本化
                     温: 列式TSDB(周~月, 秒查) → 冷: 数据湖/对象Parquet(月~年, 降采样压缩)
迟到数据: 实时不补(已发信号不翻转) + 历史照收并可重算(实时近似/批量准确)
保留: 高频原始短期(体积大) ; 聚合/特征/事件/量测/决策长期(追溯) ; 迁移tiering+降采样
血缘: 设备/点/采集计划版本/处理算法版本 → 特征/预测/决策可复现可审计(VM/R2R依赖)
补传: GEM Spool补事件进历史归位; 高频trace实时已过, 是否补原始段按ADC计划约定
```

## 四、今日易错点
1. 用一条路径同时服务实时与历史，互相拖累。
2. 为等迟到数据阻塞实时结论（应水位关窗、实时不回溯）。
3. 迟到点翻转已发实时告警/控制，造成抖动。
4. 历史层不存补传/校正、不可重算，复盘无据。
5. 高频原始数据永久全量保存导致成本爆炸，或全删导致无法追溯（应分级+降采样）。
6. 只有时序库没有数据湖，AI/跨域建模缺全量多模数据。
7. 不做数据血缘，VM/R2R 结果不可复现、事故无法重建。
8. 静默覆盖校正数据、不保留版本与更正记录。
