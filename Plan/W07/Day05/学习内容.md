## 二、背景知识（先读，25 分钟）

### 1. 配方（Process Program / PP / Recipe）概念
- 配方是设备执行工艺的参数集合，包含工艺步骤、参数值、时序等。
- 配方由 **PPID**（Process Program ID，配方 ID）唯一标识，A 类型。
- 配方内容可以是任意格式（文本、二进制、JSON、XML 等），由设备定义，Host 不解析内容（只存储和传输）。
- 配方存储在设备端，Host 通过 S7 消息管理配方（上传/下载/删除）。
- 配方和远程命令的关系：Host 发 S2F41 START 命令时，参数中指定 PPID（要执行的配方），设备加载并执行该配方。

### 2. S7 系列消息总览
| 消息 | 全称 | 方向 | 作用 |
|---|---|---|---|
| S7F1/F2 | Process Program Load Inquire / PPID | H→E / E→H | 配方上传请求 / 返回配方内容 |
| S7F3/F4 | Process Program Download / Acknowledge | H→E / E→H | 配方下载 / 确认 |
| S7F5/F6 | Process Program Delete / Acknowledge | H→E / E→H | 删除配方 / 确认（旧版）|
| S7F17/F18 | Delete Process Program / Acknowledge | H→E / E→H | 删除配方 / 确认（新版，推荐）|

### 3. S7F1/F2（配方上传，Host 从设备读取配方）
```
S7F1 Process Program Load Inquire (Host → Equipment, W=1)
body = A PPID                // 要上传的配方 ID

S7F2 Process Program (Equipment → Host, W=0)
body = L,2[
  A PPID,                    // 配方 ID
  B PPBODY                   // 配方内容（二进制，可能很大，用多块消息传输）
]
```
- Host 发 S7F1，指定要上传的 PPID。
- 设备回 S7F2，返回配方内容（PPBODY，B 类型二进制）。
- 如果配方很大，S7F2 可能用**多块消息**（W4 学过多块消息）分片传输，Host 拼接。
- 如果 PPID 不存在，设备可能回 S7F2 带空 body，或回 S9 错误（具体以设备实现为准）。

### 4. S7F3/F4（配方下载，Host 向设备写入配方）
```
S7F3 Process Program Download (Host → Equipment, W=1)
body = L,2[
  A PPID,                    // 配方 ID
  B PPBODY                   // 配方内容（二进制）
]

S7F4 Process Program Acknowledge (Equipment → Host, W=0)
body = L,2[
  U1 ACKC7,                  // 下载结果（0=成功，非0=失败）
  A PPID                     // 配方 ID
]
```
- Host 发 S7F3，指定 PPID 和配方内容。
- 设备校验：PPID 格式合法？配方内容格式正确？设备存储空间足够？
- 设备回 S7F4 ACKC7（0=成功，非0=失败，如 PPID 已存在且不允许覆盖、配方内容格式错误、存储空间不足）。
- 如果 PPID 已存在，S7F3 通常**覆盖**原配方（具体以设备实现为准，部分设备要求先删除再下载）。
- 大配方同样用多块消息分片传输。

### 5. S7F17/F18（删除配方，推荐新版）
```
S7F17 Delete Process Program (Host → Equipment, W=1)
body = L,n[                  // 要删除的配方 ID 列表
  A PPID, ...
]

S7F18 Delete Process Program Acknowledge (Equipment → Host, W=0)
body = L,2[
  U1 ACKC7,                  // 删除结果（0=成功，非0=失败）
  L,n[A PPID, ...]           // 删除的配方 ID 列表
]
```
- Host 发 S7F17，指定要删除的 PPID 列表（可一次删除多个配方）。
- 设备回 S7F18 ACKC7（0=成功，非0=失败，如 PPID 不存在、配方正在使用不能删除）。
- S7F5/F6 是旧版删除消息（一次删一个），S7F17/F18 是新版（一次删多个），推荐用 S7F17/F18。

### 6. 配方校验机制
设备收到 S7F3 下载配方时，通常进行以下校验：
1. **PPID 格式校验**：PPID 长度、字符集是否符合设备要求（如最多 8 字符、只能字母数字）。
2. **配方内容格式校验**：配方内容是否符合设备定义的格式（如特定的文件头、参数结构、校验和）。
3. **存储空间校验**：设备存储空间是否足够存储新配方。
4. **覆盖策略**：如果 PPID 已存在，是否允许覆盖？（部分设备要求先删除再下载，或需要特定权限）
5. **配方完整性校验**：配方内容是否完整（多块消息拼接后长度正确、校验和匹配）。
- 校验失败时，设备回 S7F4 ACKC7 非 0，并可能在 ERRTEXT 中说明失败原因。

### 7. 配方和 R2R 控制的关系（专家级，M7-M9 进阶细讲）
- **基础配方（Base Recipe）**：存储在 RMS（Recipe Management System）和设备端，包含工艺的标准参数（如温度设定值、压力设定值、时间）。
- **R2R 偏移（Run-to-Run Overlay）**：R2R 控制器根据历史批次的量测数据，计算出参数偏移量（如温度 +0.5°C、压力 -0.2 Pa），用于修正基础配方。
- **最终执行参数**：设备执行配方时，最终参数 = 基础配方参数 + R2R 偏移。
  - 例：基础配方温度=200°C，R2R 偏移=+0.5°C，最终执行温度=200.5°C。
- **R2R 不直接修改配方主档**：R2R 偏移是临时的、批次相关的，不修改 RMS 中的基础配方。R2R 偏移通过 EAP 下发给设备（如通过远程命令参数、或特定的 S2F41 参数、或 EDA 接口），设备执行时叠加。
- **版本对齐与审计**：R2R 偏移和基础配方版本需要对齐（确保偏移是针对该版本配方计算的），并记录审计日志（哪个批次用了哪个版本配方 + 哪个偏移）。
- 今天只讲概念，R2R 的具体实现和 EAP 集成在 M7-M9 进阶阶段细讲。
