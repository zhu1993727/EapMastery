# W07 · Day06 答案与综合实验参考

## 一、自测题标准答案
1. **Host 发 START 前需要做哪些准备**：①**建链**（TCP→HSMS Select→S1F13 建立通信→S1F17 请求在线→控制 ONLINE，W5 流程）；②**能力发现**（S1F3 查 SV 列表、S1F5 查事件列表、S5F5 查报警列表、S1F7 查报告列表，W6/W7 流程）；③**使能报警**（S5F3 ALED=1 使能关心的报警，否则报警不上报）；④**下载配方**（S7F3 下载 START 命令要执行的配方，否则配方不存在）；⑤**配置数据采集**（S2F33 定义报告、S2F35 关联事件，包括命令开始/完成/失败事件，否则收不到命令状态变化的 S6F11）。这些准备完成后，Host 才能发 START 命令并正确接收执行结果。
2. **命令执行中触发报警，命令怎么处理 / Host 收到哪些通知**：命令执行中触发严重报警（如温度过高）时，设备通常会**中断命令**——命令从 EXECUTING 进入 FAILED 状态，停止工艺执行，进入安全状态。Host 会收到两类通知：①**S5F1 报警上报**（设备主动发，通知 Host 报警设置，Host 回 S5F2）；②**S6F11 命令失败事件**（命令状态变化到 FAILED，触发"命令失败"事件，通过 S6F11 上报，含失败原因，Host 回 S6F12）。如果配置了报警相关的事件（如"报警设置"事件），Host 还可能收到报警设置的 S6F11。Host 收到这些通知后，应该通知操作员、暂停派工、触发维护流程。
3. **START 指定不存在的配方，什么时候拒绝 / 回什么 ACKC10**：取决于设备实现，有两种可能：①**参数校验时拒绝**（S2F41Handler 在接收命令时校验 RECIPE 参数，如果 PPID 不存在，回 ACKC10=3 参数错误）——这是严格实现，命令不进入队列；②**执行时失败**（S2F41Handler 不校验配方存在性，命令接受并排队，执行时 FakeEquipment 发现配方不存在，命令进入 FAILED 状态，通过 S6F11 命令失败事件通知）——这是宽松实现。专家实践：应该在参数校验时就拒绝（回 ACKC10=3），因为配方不存在是参数错误，不应该让命令进入队列。但部分设备实现可能在执行时才校验，需要看设备手册。今天的综合实验中，FakeEquipment 在 Execute 时校验配方存在性，不存在则返回失败。
4. **报警禁用时触发报警，设备内部状态怎么变 / Host 能收到通知吗**：报警禁用时触发报警，设备内部**仍然记录报警状态**（从 CLEAR→SET），报警状态机正常运行，操作员在设备本地仍然能看到报警。但设备**不发 S5F1**上报 Host（因为报警被禁用了）。Host 收不到 S5F1 通知。当 Host 重新使能该报警时，如果报警当前处于 SET 状态，设备会**立即发一条 S5F1**（通知 Host 当前有报警），这是 AlarmStore.SetEnabled 的实现逻辑（使能时如果报警是 SET，立即触发 OnAlarmChanged）。这是报警使能/禁用机制的设计——禁用只是屏蔽通知，不影响设备内部状态。
5. **命令完成和命令失败都通过 S6F11 通知，Host 怎么区分**：Host 通过 **CEID（事件 ID）** 区分——命令完成触发的是"命令完成"事件（CEID=3102），命令失败触发的是"命令失败"事件（CEID=3103）。Host 在 S2F35 关联事件时，分别把这两个 CEID 关联到对应的报告（报告中可以包含命令名、命令 ID、失败原因等 DV）。收到 S6F11 时，Host 解析 CEID 字段，根据 CEID 判断是命令完成还是命令失败，然后解析报告中的变量值获取详细信息。另外，Host 也可以维护命令 ID→状态的映射表，收到 S6F11 时更新对应命令的状态。
6. **现场报"Host 发 START 后设备没反应"排查顺序**：①**通信状态**：设备通信 ON-LINE？控制 ONLINE？（OFF-LINE 时命令被拒绝，回 ACKC10=4）；②**S2F42 是否回了**：设备回了 S2F42 吗？ACKC10 是多少？（没回=T3 超时，可能设备忙或通信问题；回了非 0=命令被拒绝，看 ACKC10 原因）；③**命令是否在排队**：设备是否忙？队列中是否有其他命令在前面？（查询设备状态 SV）；④**命令是否在执行**：设备是否正在执行该命令？执行时间是否正常？（查询命令状态 SV，或看设备本地显示）；⑤**配方是否存在**：START 指定的 PPID 设备上有吗？（S7F1 上传验证，或 S1F7 查配方列表）；⑥**报警/Hold 状态**：设备有严重报警吗？有 Hold 吗？（报警或 Hold 可能暂停命令执行）；⑦**命令完成事件是否配置**：Host 是否通过 S2F33/S2F35 配置了命令完成/失败事件？（没配置就收不到 S6F11，但命令可能已经完成了）；⑧**S6F11 是否发出**：设备端抓包/日志，看命令完成时是否发了 S6F11？（发出了但 Host 没收到=通信问题，没发出=配置问题）；⑨**主动查询**：Host 发 S1F11 查询命令状态相关的 SV，确认命令当前状态。

## 二、FakeEquipment 参考实现
```csharp
using EapLab.Gem.Alarm;
using EapLab.Gem.Recipe;
using EapLab.Gem.RemoteCommand;
using EapLab.Transport.Logging;

namespace EapLab.Gem.Equipment;

/// <summary>设备业务逻辑模拟器：实现 ICommandExecutor，模拟工艺执行。</summary>
public sealed class FakeEquipment : ICommandExecutor
{
    private readonly RecipeStore _recipeStore;
    private readonly AlarmStore _alarmStore;
    private readonly ILogSink _log;
    private bool _isExecuting;

    // 可配置的报警触发点：执行到第 N 片时触发报警（0=不触发）
    public int AlarmAtWafer { get; set; } = 0;
    public uint AlarmIdToTrigger { get; set; } = 1001;

    // 控制状态（由 GemStateMachine 同步）
    public bool ControlOnline { get; set; } = true;
    // 严重报警状态（有严重报警时拒绝命令）
    public bool HasCriticalAlarm => _alarmStore.Query(Array.Empty<uint>()).Any(a => a.AlCd >= 3 && a.State == AlarmState.Set);

    public bool IsBusy => _isExecuting;
    public bool CanAcceptCommands => ControlOnline && !HasCriticalAlarm;

    public FakeEquipment(RecipeStore recipeStore, AlarmStore alarmStore, ILogSink log)
    {
        _recipeStore = recipeStore;
        _alarmStore = alarmStore;
        _log = log;
    }

    public bool Execute(RemoteCommand command, out string? failureReason)
    {
        failureReason = null;
        _isExecuting = true;

        try
        {
            switch (command.Rcmd)
            {
                case "START":
                    return ExecuteStart(command, out failureReason);
                case "STOP":
                    _log.Log(LogDir.INFO, "STOP command: stopping process");
                    return true; // 简化：STOP 总是成功
                case "PAUSE":
                case "RESUME":
                case "ABORT":
                    return true; // 简化
                default:
                    failureReason = $"Unknown command: {command.Rcmd}";
                    return false;
            }
        }
        finally
        {
            _isExecuting = false;
        }
    }

    private bool ExecuteStart(RemoteCommand command, out string? failureReason)
    {
        failureReason = null;

        // 1. 解析参数
        if (!command.Parameters.TryGetValue("RECIPE", out var recipeItem) || recipeItem is not SecsA recipeId)
        {
            failureReason = "Missing or invalid RECIPE parameter";
            return false;
        }
        int quantity = 25; // 默认
        if (command.Parameters.TryGetValue("QUANTITY", out var qtyItem) && qtyItem is SecsU2 qty)
            quantity = qty.Values[0];

        // 2. 校验配方存在
        if (!_recipeStore.Exists(recipeId.Value))
        {
            failureReason = $"Recipe not found: {recipeId.Value}";
            return false;
        }

        // 3. 加载配方
        var recipeBody = _recipeStore.Upload(recipeId.Value);
        _log.Log(LogDir.INFO, $"Recipe loaded: {recipeId.Value} size={recipeBody?.Length ?? 0}");

        // 4. 模拟工艺执行
        _log.Log(LogDir.INFO, $"Process started: LOT={command.Parameters.GetValueOrDefault("LOTID")}, recipe={recipeId.Value}, qty={quantity}");
        for (int i = 1; i <= quantity; i++)
        {
            Thread.Sleep(50); // 每片 50ms（模拟）

            // 检查是否触发报警
            if (AlarmAtWafer > 0 && i == AlarmAtWafer)
            {
                _log.Log(LogDir.WARN, $"Alarm triggered at wafer {i}: ALID={AlarmIdToTrigger}");
                _alarmStore.Set(AlarmIdToTrigger); // 设置报警（如果使能会发 S5F1）

                // 严重报警中断命令
                var alarm = _alarmStore.Get(AlarmIdToTrigger);
                if (alarm != null && alarm.AlCd >= 2)
                {
                    failureReason = $"Process interrupted by alarm ALID={AlarmIdToTrigger} at wafer {i}";
                    _log.Log(LogDir.ERR, failureReason);
                    return false; // 命令失败
                }
            }
        }

        _log.Log(LogDir.INFO, $"Process completed: {quantity} wafers");
        return true; // 命令成功
    }
}
```

## 五、今日验收（DoD）
- FakeEquipment 实现 ICommandExecutor，支持 START/STOP/PAUSE/RESUME/ABORT。
- W7 三大能力（S5/S2F41/S7）集成到消息管线，Stream 分发正确。
- 4 个场景全部跑通，每个场景有抓包截图、日志、状态变化记录。
- 报警中断命令时，Host 收到 S5F1 和 S6F11 命令失败事件。
- 报警禁用时不发 S5F1，使能时立即发（如果报警是 SET）。
- 命令完成/失败通过不同 CEID 的 S6F11 区分。

## 六、易错点
1. 发 START 前不下载配方（配方不存在，命令失败）。
2. 发 START 前不使能报警（报警触发时 Host 收不到 S5F1）。
3. 不配置命令完成/失败事件（收不到 S6F11，不知道命令执行结果）。
4. 命令执行中触发报警时不中断命令（严重报警应该中断命令，进入 FAILED）。
5. 报警禁用时以为设备内部也不记录状态（禁用只是不通知，内部状态仍记录）。
6. 命令完成和命令失败用同一个 CEID（应该用不同 CEID，Host 靠 CEID 区分）。
7. FakeEquipment 的 CanAcceptCommands 不检查严重报警（有严重报警时应该拒绝命令）。
8. 命令失败时只回 ACKC10 非 0（执行失败是在接受之后，ACKC10 已经回 0 了，失败靠 S6F11 事件）。
