## 三、现场排障方法论（专家必会，费曼重点）

### "Host 发 START 后设备没反应"排查（9 步）
1. **通信状态**：设备通信 ON-LINE？控制 ONLINE？（OFF-LINE 时回 ACKC10=4）
2. **S2F42 是否回了**：设备回了吗？ACKC10 是多少？（没回=T3 超时；回了非 0=被拒绝，看原因）
3. **命令是否在排队**：设备忙吗？队列中有其他命令吗？
4. **命令是否在执行**：设备正在执行吗？执行时间正常吗？（查命令状态 SV）
5. **配方是否存在**：START 指定的 PPID 设备上有吗？（S7F1 上传验证）
6. **报警/Hold 状态**：设备有严重报警吗？有 Hold 吗？（可能暂停或中断命令）
7. **命令完成事件是否配置**：Host 配置了命令完成/失败事件吗？（没配置收不到 S6F11，但命令可能已完成）
8. **S6F11 是否发出**：设备端抓包，命令完成时发 S6F11 了吗？
9. **主动查询**：S1F11 查命令状态相关 SV，确认当前状态。

### "设备触发报警但 Host 收不到 S5F1"排查
1. **报警是否使能**：Host 发 S5F3 使能了吗？（禁用时不上报，最常见原因）
2. **报警是否真的触发**：设备端确认报警状态从 CLEAR→SET 了吗？（看设备本地显示/日志）
3. **S5F1 是否发出**：设备端抓包/日志，报警触发时发 S5F1 了吗？（发出了但 Host 没收到=通信问题，没发出=配置问题）
4. **S5F2 是否回了**：Host 回 S5F2 了吗？（不回可能导致设备重发或状态异常）
5. **通信状态**：设备通信 ON-LINE 吗？（OFF-LINE 时报警可能缓存或丢弃）
6. **Spool 状态**：通信中断时报警是否被 Spool 缓存？（W8 细讲）
7. **报警 ID 是否正确**：Host 使能的 ALID 和设备触发的 ALID 一致吗？

## 四、费曼参考脚本（对照录音）
"Host 发一条 S2F41 START 命令，前提是建链完成、报警使能、配方已下载、命令完成事件已配置。Host 构造 S2F41 body：L,2[A RCMD='START', L,n 参数（LOTID、RECIPE、QUANTITY）]，发出去。设备收到后先过状态闸门（通信/控制 ON-LINE），然后校验命令名（START 支持吗）、参数（CPNAME 认识吗、类型对吗、必填吗）、设备状态（忙/报警/Hold），都通过后回 S2F42 ACKC10=0（命令已接受并排队，PENDING 状态）。注意这只是接受，不是完成。设备从队列取出命令，进入 EXECUTING，触发'命令开始'事件（S6F11）。设备加载配方，模拟工艺执行。如果执行中触发温度过高报警（严重），设备设置报警（ALID=1001，状态 SET），发 S5F1 上报（Host 回 S5F2），同时中断命令（命令进入 FAILED，失败原因='温度过高中断'），触发'命令失败'事件（S6F11，含失败原因）。Host 收到 S5F1 和 S6F11 命令失败事件，回确认，通知操作员。如果没有报警，命令执行完成后进入 COMPLETED，触发'命令完成'事件（S6F11）。如果 Host 发 START 后设备没反应，按 9 步排查：通信→S2F42→排队→执行→配方→报警/Hold→事件配置→S6F11→主动查询。核心是：ACKC10=0 只表示接受，执行结果靠 S6F11 事件；报警是异常通知，需要先使能才能上报。"

## 五、W8(GEM 内核综合实验 + Spool) 三问思考方向（先自己想，W8 揭晓）
1. **Spool 是什么 / 通信中断时怎么处理 / 缓存存在哪里**：Spool（假脱机/缓存）是设备在通信中断（Host OFF-LINE 或 HSMS 断开）时，把事件报告（S6F11）和报警（S5F1）缓存到设备本地存储（内存或 Flash），等通信恢复后再重发给 Host 的机制。Spool 保证通信中断期间的事件/报警不丢失。缓存存在设备的非易失性存储（如 Flash）或内存中（取决于设备实现，非易失性存储更可靠，断电不丢）。Spool 有容量限制，超出后可能丢弃最旧的或拒绝新的（取决于设备配置）。
2. **Spool 触发条件和恢复流程 / 通信恢复后怎么重发**：触发条件：①通信状态从 ON-LINE→OFF-LINE（Host 请求离线或设备主动离线）；②HSMS 连接断开（Select 丢失或 TCP 断开）；③Host 不回确认（S6F12/S5F2 超时，可能导致重发或 Spool）。恢复流程：①通信恢复（ON-LINE + Select 重新建立）；②设备查询 Spool 中是否有缓存的事件/报警；③设备按时间顺序重发缓存的 S6F11/S5F1（每条带原始的时间戳或 DATAID）；④Host 回确认（S6F12/S5F2）；⑤设备收到确认后从 Spool 中删除已发送的记录；⑥全部重发完成后，Spool 清空，恢复正常上报。注意：重发的 S6F11 可能带"Spool 重发"标志（取决于设备实现），Host 可以识别并去重。
3. **S2F43/S2F44 作用 / Host 怎么查询和清空 Spool**：S2F43（Spooling Control Request，Host→设备）用于 Host 控制 Spool 行为——可以查询 Spool 状态（有多少缓存记录、占用多少空间）、清空 Spool（删除所有缓存记录）、启用/禁用 Spool。S2F44（Spooling Control Acknowledge，设备→Host）是确认，返回 Spool 状态或操作结果。Host 建链后通常先查询 Spool 状态（S2F43），如果有缓存记录，等待设备重发或主动请求重发；通信恢复后可以清空 Spool（S2F43）以释放空间。S2F43/S2F44 的具体 body 结构和操作码以 E30 标准和设备实现为准，W8 细讲。
