## 二、背景知识（先读，25 分钟）

### 1. 报警体系核心概念
GEM 定义了设备的报警机制，用于通知 Host 设备的异常状态。核心概念：

| 概念 | 全称 | 含义 |
|---|---|---|
| ALID | Alarm ID | 报警唯一标识，U4 类型 |
| ALCD | Alarm Code | 报警代码，表示报警类型/严重程度，U1 或 U4（具体以设备实现为准）|
| ALTX | Alarm Text | 报警描述文本，A 类型，人类可读的报警说明 |
| SET | 报警已设置 | 报警处于活动状态（异常发生）|
| CLEAR | 报警已清除 | 报警处于非活动状态（异常恢复）|

- 每个报警有唯一的 ALID，设备通过 ALID 标识不同的报警（如 ALID=1001="温度过高"，ALID=1002="压力过低"）。
- ALCD 表示报警的类型或严重程度（如 1=警告，2=严重，3=紧急），具体含义由设备定义。
- ALTX 是报警的文本描述，Host 收到报警后可以直接显示给操作员。

### 2. 报警状态机（必背）
```
CLEAR（非活动）──异常发生──► SET（活动）
    ▲                            │
    └──异常恢复──────────────────┘
```
- 报警有两种状态：**SET**（已设置/活动）和 **CLEAR**（已清除/非活动）。
- 初始状态：CLEAR（设备上电时所有报警默认为 CLEAR，除非有持续异常）。
- 异常发生：报警从 CLEAR→SET，设备发 S5F1 通知 Host（报警设置）。
- 异常恢复：报警从 SET→CLEAR，设备发 S5F1 通知 Host（报警清除）。
- 报警状态变化时，设备**主动**发 S5F1 上报，不需要 Host 请求。

### 3. S5F1/S5F2（报警上报）
```
S5F1 Alarm Report Send (Equipment → Host, W=1)
body = L,2[
  U4 ALID,              // 报警 ID
  A ALTX                // 报警文本（部分设备还包含 ALCD，具体以实现为准）
]
（部分设备扩展为 L,3[U4 ALID, U1 ALCD, A ALTX]，包含报警代码）

S5F2 Alarm Report Acknowledge (Host → Equipment, W=0)
body = U4 ALID          // 确认收到的报警 ID
```
- S5F1 是设备主动发给 Host 的报警上报，W=1，需要 Host 回 S5F2。
- S5F1 可以表示报警**设置**（异常发生）或**清除**（异常恢复），通过 ALCD 或上下文区分（部分设备用 ALCD 的位表示 SET/CLEAR，具体以设备实现为准）。
- Host 收到 S5F1 后回 S5F2（body=U4 ALID），表示确认收到。
- 注意：S5F1 和 S6F11 不同——S5F1 是报警上报，不需要先定义报告/关联事件；S6F11 是事件上报，需要 S2F33/S2F35 配置。

### 4. S5F3/S5F4（使能/禁用报警）
```
S5F3 Enable/Disable Alarm (Host → Equipment, W=1)
body = L,2[
  U1 ALED,              // 报警使能/禁用标志（0=禁用，1=使能）
  L,n[                  // 要使能/禁用的报警 ID 列表（空=全部）
    U4 ALID, ...
  ]
]

S5F4 Enable/Disable Alarm Acknowledge (Equipment → Host, W=0)
body = U1 ACKC5         // 确认结果（0=成功，非0=失败）
```
- Host 通过 S5F3 使能或禁用报警。使能的报警状态变化时才会发 S5F1；禁用的报警即使状态变化也不上报（但设备内部仍记录报警状态）。
- ALED（Alarm Enable/Disable）：0=禁用，1=使能。
- ALID 列表为空（L,0）表示使能/禁用**全部**报警。
- 设备回 S5F4 ACKC5（0=成功，非0=失败，如 ALID 不存在）。
- 常见场景：Host 建链后使能所有关心的报警；维护期间禁用非关键报警避免干扰。

### 5. S5F5/S5F6（查询报警列表）
```
S5F5 List Alarms Request (Host → Equipment, W=1)
body = L,n[                  // 要查询的 ALID 列表（空=全部）
  U4 ALID, ...
]

S5F6 List Alarms (Equipment → Host, W=0)
body = L,n[                  // 报警列表
  L,3[
    U4 ALID,                 // 报警 ID
    U1 ALCD,                 // 报警代码
    A ALTX                   // 报警文本
  ], ...
]
```
- Host 通过 S5F5 查询设备支持的报警列表（ALID+ALCD+ALTX）。
- ALID 列表为空（L,0）表示查询**全部**报警。
- 设备回 S5F6，返回每个报警的 ALID、ALCD、ALTX。
- Host 建链后通常先查 S5F5，知道设备支持哪些报警，再通过 S5F3 使能关心的报警。

### 6. 报警和事件的区别（必背）
| 维度 | 报警（S5F1）| 事件（S6F11）|
|---|---|---|
| 用途 | 设备异常状态通知 | 设备状态变化/操作通知 + 数据采集 |
| 配置 | 不需要定义报告/关联事件，只需使能/禁用（S5F3）| 需要 S2F33 定义报告 + S2F35 关联事件 |
| body | L,2[U4 ALID, A ALTX]（或含 ALCD）| L,3[U4 DATAID, U2 CEID, 报告列表] |
| 触发 | 报警状态变化（SET/CLEAR）| 事件发生（CEID 触发）|
| 数据 | 只带报警 ID 和文本，不带变量数据 | 带报告列表，包含采集的变量值 |
| 确认 | S5F2（U4 ALID）| S6F12（U4 DATAID）|

- 报警是"异常通知"，告诉 Host"设备出问题了"；事件是"数据采集触发器"，告诉 Host"某件事发生了，这是相关数据"。
- 报警和事件可以关联——报警设置/清除时可以触发事件（CEID），通过 S6F11 上报更多数据（如报警发生时的温度、压力）。这是高级用法，需要设备支持。

### 7. 报警在 FAB 中的作用
- 报警是设备异常的第一通知渠道，Host（EAP/MES）收到报警后可以：
  - 通知操作员（声光报警、消息推送）
  - 暂停派工（MES 停止给该设备派 Lot）
  - 触发 FDC 分析（收集报警前后的工艺数据）
  - 触发维护流程（CMMS 创建维修工单）
- 报警的严重程度（ALCD）决定响应级别：警告→记录，严重→暂停派工，紧急→停机。
