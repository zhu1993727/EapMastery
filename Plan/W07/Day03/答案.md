# W07 · Day03 答案与参考实现

## 一、自测题标准答案
1. **远程命令完整生命周期**：①Host 发 S2F41（RCMD + 参数）→ ②设备接收并解析 → ③状态校验（通信/控制 ON-LINE，否则回 ACKC10=4）→ ④命令名校验（RCMD 支持吗，否则 ACKC10=1）→ ⑤参数校验（CPNAME/CPVALUE 正确吗，否则 ACKC10=3）→ ⑥设备状态校验（忙/报警/Hold，否则 ACKC10=2 或 5，或排队）→ ⑦接受（回 S2F42 ACKC10=0，命令进入 PENDING 状态并入队）→ ⑧排队等待（如果设备忙）→ ⑨执行（从队列取出，进入 EXECUTING，执行业务逻辑）→ ⑩完成/失败（成功→COMPLETED，失败→FAILED）→ ⑪事件通知（触发"命令完成"或"命令失败"事件，通过 S6F11 上报 Host，失败时可能同时设置报警 S5F1）。关键：ACKC10=0 只表示接受，执行结果靠 S6F11 事件。
2. **ACKC10=0 是否表示执行成功 / Host 怎么知道结果**：**不是**。ACKC10=0 只表示"命令已被设备接受并排队"，是命令接受的确认，不是命令执行完成的确认。Host 通过 **S6F11 事件上报**知道命令执行结果——设备执行完命令后触发"命令完成"或"命令失败"事件（CEID），通过 S6F11 上报，Host 回 S6F12 确认。事件报告中可以包含命令相关的变量（DV），如命令名、执行结果、失败原因。Host 也可以通过 S1F11 查询状态变量（SV）主动查询命令执行状态，但事件上报是标准方式。
3. **命令执行状态机状态 / 状态变化时怎么通知 Host**：命令执行状态机有 4 种状态：①**PENDING**（已排队，等待执行）；②**EXECUTING**（执行中）；③**COMPLETED**（执行成功完成）；④**FAILED**（执行失败）。可选状态 **CANCELLED**（已取消）。状态变化时设备通过 **S6F11 事件上报**通知 Host——如果 Host 定义并关联了"命令状态变化"事件，设备在状态变化时触发事件，通过 S6F11 上报新状态。常见事件：命令开始执行（PENDING→EXECUTING）、命令完成（EXECUTING→COMPLETED）、命令失败（EXECUTING→FAILED）。Host 需要通过 S2F33/S2F35 配置这些事件才能收到通知。
4. **设备正在执行命令时 Host 又发一条怎么处理**：取决于设备实现和命令类型：①**排队**：如果设备支持命令队列，新命令进入 PENDING 状态排队，等当前命令执行完后再执行（回 ACKC10=0 表示已接受排队）。②**拒绝**：如果设备不支持排队或队列已满，回 ACKC10=5（设备忙），拒绝新命令。③**中断**：如果新命令是高优先级命令（如 STOP/ABORT），可以中断正在执行的命令，立即执行新命令（被中断的命令进入 FAILED 或 CANCELLED 状态）。标准实践：普通命令排队，STOP/ABORT 等控制命令可以中断。Host 应该检查 ACKC10 判断命令是被接受排队还是被拒绝。
5. **命令执行中触发严重报警怎么处理**：命令执行过程中如果触发严重报警（ALCD=3 紧急，如温度失控、气路异常），命令通常会被**中断**——设备进入安全状态，命令从 EXECUTING 进入 FAILED 状态，触发"命令失败"事件（CEID），通过 S6F11 上报 Host（含失败原因=报警中断），同时设置报警（S5F1 上报报警）。Host 收到命令失败事件和报警后，应该通知操作员、暂停派工、触发维护流程。如果是轻微报警（ALCD=1 警告），命令可能继续执行（取决于设备配置和报警严重程度）。
6. **ACKC10=2 vs =5 区别 / 分别在什么情况**：ACKC10=2=**命令不能执行**（设备状态不允许执行该命令，如设备正在运行、维护模式、有严重报警、Hold 状态），表示设备当前状态不适合执行该命令，但命令本身是合法的（RCMD 认识、参数正确）；ACKC10=5=**设备忙**（设备正在执行其他命令，无法接受新命令，或命令队列已满），表示设备当前忙，但空闲后可能可以执行（如果支持排队则回 0 排队，不支持排队则回 5 拒绝）。简单说：=2 是"设备状态不允许执行这个命令"（如维护模式下任何命令都不执行），=5 是"设备现在忙，等一下"（如正在执行 START，又发 START）。两者都表示命令未被接受，但原因不同，Host 的处理方式也不同（=2 可能需要等设备状态变化，=5 可以等当前命令完成后重试）。

```csharp
namespace EapLab.Gem.RemoteCommand;

public enum CommandState { Pending, Executing, Completed, Failed, Cancelled }

/// <summary>远程命令实例。</summary>
public sealed class RemoteCommand
{
    public uint CommandId { get; }            // 命令唯一 ID（设备内部分配）
    public string Rcmd { get; }                // 命令名（如 "START", "STOP"）
    public IReadOnlyDictionary<string, SecsItem> Parameters { get; } // 参数 CPNAME→CPVALUE
    public CommandState State { get; set; } = CommandState.Pending;
    public DateTime CreatedAt { get; }
    public DateTime? StartedAt { get; set; }
    public DateTime? CompletedAt { get; set; }
    public string? FailureReason { get; set; }

    public RemoteCommand(uint commandId, string rcmd, IEnumerable<KeyValuePair<string, SecsItem>> parameters)
    {
        CommandId = commandId;
        Rcmd = rcmd;
        Parameters = new Dictionary<string, SecsItem>(parameters);
        CreatedAt = DateTime.Now;
    }
}
```

### RemoteCommandEngine.cs
```csharp
using System.Collections.Concurrent;
using EapLab.Transport.Logging;

namespace EapLab.Gem.RemoteCommand;

/// <summary>远程命令引擎：命令队列 + 异步执行 + 状态管理。</summary>
public sealed class RemoteCommandEngine
{
    private readonly ConcurrentQueue<RemoteCommand> _queue = new();
    private readonly ICommandExecutor _executor;
    private readonly ILogSink _log;
    private readonly object _executeLock = new();
    private uint _nextCommandId = 1;

    // 命令状态变化事件（上层订阅，用于触发 S6F11）
    public event Action<RemoteCommand, CommandState /*old*/, CommandState /*new*/>? OnCommandStateChanged;

    public int QueueLength => _queue.Count;
    public bool IsExecuting { get; private set; }

    public RemoteCommandEngine(ICommandExecutor executor, ILogSink log)
    {
        _executor = executor;
        _log = log;
    }

    /// <summary>入队命令。返回 ACKC10（0=已接受，非0=拒绝原因）。</summary>
    public byte Enqueue(string rcmd, IEnumerable<KeyValuePair<string, SecsItem>> parameters)
    {
        // 1. 状态校验：设备是否允许接受命令
        if (!_executor.CanAcceptCommands)
            return 4; // ACKC10=4: 设备 OFF-LINE

        // 2. 命令名校验（简化：执行器负责，这里假设已校验）
        // 3. 参数校验（简化：执行器负责）

        // 4. 设备状态校验：忙且不支持排队则拒绝
        // 简化版：支持排队，总是接受（队列长度限制可扩展）
        if (_queue.Count >= 10) // 队列最大 10 条
            return 5; // ACKC10=5: 设备忙/队列满

        // 5. 接受并排队
        var cmd = new RemoteCommand(_nextCommandId++, rcmd, parameters);
        _queue.Enqueue(cmd);
        _log.Log(LogDir.INFO, $"Command enqueued: ID={cmd.CommandId} RCMD={rcmd} state=PENDING");
        OnCommandStateChanged?.Invoke(cmd, CommandState.Pending, CommandState.Pending);

        // 6. 尝试执行（如果设备不忙）
        TryExecuteNext();

        return 0; // ACKC10=0: 已接受
    }

    /// <summary>尝试执行队列中的下一条命令。</summary>
    public void TryExecuteNext()
    {
        lock (_executeLock)
        {
            if (IsExecuting) return; // 正在执行，不并发
            if (!_queue.TryDequeue(out var cmd)) return; // 队列空

            IsExecuting = true;
            cmd.State = CommandState.Executing;
            cmd.StartedAt = DateTime.Now;
            _log.Log(LogDir.INFO, $"Command executing: ID={cmd.CommandId} RCMD={cmd.Rcmd}");
            OnCommandStateChanged?.Invoke(cmd, CommandState.Pending, CommandState.Executing);

            // 异步执行（简化版：同步执行，实际应在后台线程）
            Task.Run(() =>
            {
                try
                {
                    bool success = _executor.Execute(cmd, out var failureReason);
                    cmd.CompletedAt = DateTime.Now;
                    if (success)
                    {
                        cmd.State = CommandState.Completed;
                        _log.Log(LogDir.INFO, $"Command completed: ID={cmd.CommandId} RCMD={cmd.Rcmd}");
                        OnCommandStateChanged?.Invoke(cmd, CommandState.Executing, CommandState.Completed);
                    }
                    else
                    {
                        cmd.State = CommandState.Failed;
                        cmd.FailureReason = failureReason;
                        _log.Log(LogDir.ERR, $"Command failed: ID={cmd.CommandId} RCMD={cmd.Rcmd} reason={failureReason}");
                        OnCommandStateChanged?.Invoke(cmd, CommandState.Executing, CommandState.Failed);
                    }
                }
                finally
                {
                    lock (_executeLock) { IsExecuting = false; }
                    TryExecuteNext(); // 执行下一条
                }
            });
        }
    }

    /// <summary>取消排队中的命令（正在执行的不能取消）。</summary>
    public bool Cancel(uint commandId)
    {
        // 简化版：不支持从队列中间删除，只记录
        _log.Log(LogDir.WARN, $"Command cancel requested: ID={commandId} (not implemented in simplified version)");
        return false;
    }
}
```

### 单测（节选）
```csharp
public class RemoteCommandEngineTests
{
    private class FakeExecutor : ICommandExecutor
    {
        public bool ShouldSucceed { get; set; } = true;
        public string? FailureReason { get; set; }
        public bool IsBusy { get; set; }
        public bool CanAcceptCommands { get; set; } = true;
        public bool Execute(RemoteCommand command, out string? failureReason)
        {
            failureReason = ShouldSucceed ? null : FailureReason;
            return ShouldSucceed;
        }
    }

    [Fact]
    public void 接受命令_状态PENDING()
    {
        var executor = new FakeExecutor();
        var engine = new RemoteCommandEngine(executor, new ConsoleLogSink());
        byte ackc10 = engine.Enqueue("START", new Dictionary<string, SecsItem>());
        Assert.Equal(0, ackc10);
    }

    [Fact]
    public void OFFLINE时拒绝_ACKC10_4()
    {
        var executor = new FakeExecutor { CanAcceptCommands = false };
        var engine = new RemoteCommandEngine(executor, new ConsoleLogSink());
        byte ackc10 = engine.Enqueue("START", new Dictionary<string, SecsItem>());
        Assert.Equal(4, ackc10);
    }

    [Fact]
    public void 执行成功_状态COMPLETED()
    {
        var executor = new FakeExecutor { ShouldSucceed = true };
        var engine = new RemoteCommandEngine(executor, new ConsoleLogSink());
        RemoteCommand? completedCmd = null;
        engine.OnCommandStateChanged += (cmd, old, newState) =>
        {
            if (newState == CommandState.Completed) completedCmd = cmd;
        };

        engine.Enqueue("START", new Dictionary<string, SecsItem>());
        Thread.Sleep(100); // 等待异步执行

        Assert.NotNull(completedCmd);
        Assert.Equal(CommandState.Completed, completedCmd.State);
    }

    [Fact]
    public void 执行失败_状态FAILED()
    {
        var executor = new FakeExecutor { ShouldSucceed = false, FailureReason = "Temperature too high" };
        var engine = new RemoteCommandEngine(executor, new ConsoleLogSink());
        RemoteCommand? failedCmd = null;
        engine.OnCommandStateChanged += (cmd, old, newState) =>
        {
            if (newState == CommandState.Failed) failedCmd = cmd;
        };

        engine.Enqueue("START", new Dictionary<string, SecsItem>());
        Thread.Sleep(100);

        Assert.NotNull(failedCmd);
        Assert.Equal(CommandState.Failed, failedCmd.State);
        Assert.Equal("Temperature too high", failedCmd.FailureReason);
    }

    [Fact]
    public void 队列满时拒绝_ACKC10_5()
    {
        var executor = new FakeExecutor { IsBusy = true }; // 忙，命令排队
        var engine = new RemoteCommandEngine(executor, new ConsoleLogSink());
        // 入队 10 条（队列满）
        for (int i = 0; i < 10; i++)
            engine.Enqueue("START", new Dictionary<string, SecsItem>());
        // 第 11 条应该被拒绝
        byte ackc10 = engine.Enqueue("START", new Dictionary<string, SecsItem>());
        Assert.Equal(5, ackc10);
    }
}
```

## 三、今日易错点
1. 以为 ACKC10=0 表示命令执行成功（只表示已接受排队，执行结果靠 S6F11 事件）。
2. 混淆 ACKC10=2（命令不能执行，设备状态不允许）和 =5（设备忙，队列满）。
3. 以为命令执行是同步的（S2F42 回 ACKC10=0 时命令可能还没开始执行，是异步排队执行）。
4. 命令状态变化时不通知 Host（应通过 S6F11 事件上报，Host 需要先定义并关联事件）。
5. 以为所有命令都可以中断（只有 STOP/ABORT 等高优先级命令可以中断，普通命令排队）。
6. 命令执行失败时只回 ACKC10 非 0（执行失败是在接受之后，ACKC10 已经回 0 了，失败靠 S6F11 事件通知）。
7. 以为设备忙时总是拒绝命令（支持排队的设备会回 ACKC10=0 排队，不支持排队才回 5）。
8. 命令队列没有长度限制（应限制最大长度，超出回 ACKC10=5）。
