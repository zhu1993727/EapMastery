## 二、背景知识（先读，25 分钟）

### 1. 远程命令的完整生命周期（必背）
```
Host 发 S2F41 (RCMD + 参数)
    │
    ▼
1. 接收：设备收到 S2F41，解析 RCMD 和 CPNAME/CPVALUE
    │
    ▼
2. 状态校验：通信 ON-LINE？控制 ON-LINE？（否则回 ACKC10=4）
    │
    ▼
3. 命令名校验：RCMD 设备支持吗？（否则回 ACKC10=2）
    │
    ▼
4. 参数校验：CPNAME 都认识吗？CPVALUE 类型/范围正确吗？（否则回 ACKC10=3）
    │
    ▼
5. 设备状态校验：设备忙吗？有报警吗？有 Hold 吗？（否则回 ACKC10=5 或排队）
    │
    ▼
6. 接受：回 S2F42 ACKC10=0（命令已接受并排队），命令进入 PENDING 状态
    │
    ▼
7. 排队：命令进入命令队列，等待执行（如果设备忙）
    │
    ▼
8. 执行：命令从队列取出，进入 EXECUTING 状态，设备执行业务逻辑
    │
    ├─ 执行成功 → COMPLETED 状态 → 触发"命令完成"事件(CEID) → S6F11 上报
    │
    └─ 执行失败 → FAILED 状态 → 触发"命令失败"事件(CEID) → S6F11 上报（含失败原因）
                → 可能同时设置报警(S5F1)
```

### 2. 命令执行状态机（必背）
```
PENDING（已排队，等待执行）
    │
    ├─ 设备就绪 → EXECUTING（执行中）
    │              │
    │              ├─ 执行成功 → COMPLETED（已完成）
    │              └─ 执行失败 → FAILED（已失败）
    │
    └─ Host 取消 → CANCELLED（已取消，可选）
```
- **PENDING**：命令已接受并排队，等待执行。此时 S2F42 已回 ACKC10=0。
- **EXECUTING**：命令正在执行。设备执行业务逻辑（如 START 命令开始加工）。
- **COMPLETED**：命令执行成功完成。触发"命令完成"事件，通过 S6F11 通知 Host。
- **FAILED**：命令执行失败。触发"命令失败"事件，通过 S6F11 通知 Host（含失败原因），可能同时设置报警。
- **CANCELLED**（可选）：Host 取消命令。部分设备支持取消排队中的命令。
- 命令状态变化时，设备可以通过 S6F11 事件通知 Host（如果定义了相关事件和报告）。

### 3. ACKC10 详解（必背）
S2F42 返回的 ACKC10 表示命令接受/拒绝的原因：

| ACKC10 | 含义 | 说明 |
|---|---|---|
| 0 | 命令已接受 | 命令已接受并排队，将异步执行 |
| 1 | 命令不认识 | RCMD 设备不支持 |
| 2 | 命令不能执行 | 设备状态不允许（如正在运行、维护模式）|
| 3 | 参数错误 | CPNAME 不认识或 CPVALUE 类型/范围错误 |
| 4 | 设备 OFF-LINE | 通信或控制 OFF-LINE，拒绝远程命令 |
| 5 | 设备忙 | 设备正在执行其他命令，无法接受新命令（或排队）|
| 6+ | 设备自定义 | 设备商定义的其他原因 |

- 具体值以设备实现为准，核心是 0=接受，非0=各种拒绝。
- **关键**：ACKC10=0 只表示命令已接受，**不表示执行成功**。执行结果靠 S6F11 事件通知。

### 4. 命令队列机制
- 设备通常维护一个命令队列（FIFO），Host 发的多个命令按顺序排队执行。
- **并发控制**：设备同一时间只能执行一个命令（或有限数量的并发命令，取决于设备能力）。
- **命令优先级**：部分设备支持命令优先级（如 STOP 命令优先级高于 START，可以中断正在执行的命令）。
- **队列长度**：设备通常支持有限的队列长度（如最多排队 10 条命令），超出后回 ACKC10=5（设备忙）。
- **命令取消**：部分设备支持取消排队中的命令（通过特定的远程命令，如 CANCEL），正在执行的命令通常不能取消（或通过 STOP/ABORT 中断）。

### 5. 命令完成/失败的事件通知
- 命令执行完成（COMPLETED）或失败（FAILED）时，设备触发对应的事件（CEID），通过 S6F11 上报给 Host。
- 常见命令相关事件：
  - 命令开始执行（CEID=命令开始）
  - 命令执行完成（CEID=命令完成）
  - 命令执行失败（CEID=命令失败，含失败原因）
  - 命令被取消（CEID=命令取消）
- Host 需要通过 S2F33/S2F35 定义并关联这些事件，才能收到命令执行结果的通知。
- 事件报告中可以包含命令相关的变量（DV），如命令名、命令参数、执行结果、失败原因等。

### 6. 命令和报警/Hold 的关系
- **报警时拒绝命令**：设备有严重报警（ALCD=3 紧急）时，通常拒绝接受远程命令（回 ACKC10=2 或 5），直到报警清除。
- **Hold 时暂停命令**：设备处于 Hold 状态（如 MES 下发的 Lot Hold、FDC 触发的 Process Hold）时，暂停命令执行（排队中的命令不执行，正在执行的命令可能暂停）。Hold 解除后继续执行。
- **命令执行中触发报警**：命令执行过程中如果触发报警，命令可能被中断（进入 FAILED 状态），并通过 S6F11 通知 Host 命令失败。
- **STOP/ABORT 命令**：STOP 命令可以优雅停止正在执行的命令（完成当前加工后停止），ABORT 命令可以立即中断命令（紧急停止）。这些命令通常优先级较高，可以中断正在执行的命令。
